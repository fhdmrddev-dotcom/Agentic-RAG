<measured_facts>
## Read off the installed packages during planning. These are the two facts that shape the fix.

### 1. `nowheel` is load-bearing; `onWheel` stopPropagation alone CANNOT be sufficient.

`@xyflow/system` `createZoomOnScrollHandler` (dist/esm/index.js:2764-2780) short-circuits with
`return null` — no `preventDefault`, so the native scroll proceeds on the scrollable element —
whenever `isWrappedWithClass(event, noWheelClassName)` is true, and that helper is
`(event, className) => event.target.closest('.' + className)` (:2693), i.e. an ANCESTOR WALK from
the event target. `createFilter` (:2861) and `createPanOnScrollHandler` (:2711) check the same
class. `ReactFlow`'s default is `noWheelClassName = 'nowheel'` (@xyflow/react dist/esm/index.js:3728).

React's synthetic `onWheel` is delegated to the ROOT container, so it fires AFTER the native
wheel has already bubbled through `.react-flow`'s d3-zoom listener. `e.stopPropagation()` in a
React handler therefore cannot stop that listener. **Keep the `onWheel` guard (it is cheap and
the constraint requires it) but understand that `nowheel` is the half that actually works.**
`nopan` ships alongside it so dragging the panel's own scrollbar cannot pan the canvas.

### 2. The counter-scale nets to 1 for the panel's content — this is the obvious trap.

The wrapper lives inside `.react-flow__viewport` (`scale(zoom)`) and carries `scale(1/zoom)`.
Net scale on the PANEL'S CONTENT is `zoom * (1/zoom) = 1`, so **one panel CSS px == one screen
px at every zoom, and the height budget needs no zoom conversion.** The wrapper's `translate(...)`
is applied in the wrapper's PARENT space (flow coords) and so IS multiplied by `zoom` — which
means `PICKER_DROP: 22` is 22 FLOW px (11 screen px at zoom 0.5). Existing quirk; keep it, and
pin both spaces in the same test case so a future author cannot collapse them.

A correction expressed in SCREEN px must therefore be appended AFTER `scale(1/zoom)` in the
transform list, where local px == screen px. CSS transforms apply right-to-left, so a trailing
`translate(dxPx, 0) translateY(-100%)` runs in post-scale local space; both are pure translations
and commute.

`translateY(-100%)` resolves against the WRAPPER's own border box, which shrink-wraps the panel —
so the flip needs no height measurement at all.

### 3. The store already gives everything, reactively.

`ReactFlowStore` (`@xyflow/react/dist/esm/types/store.d.ts:5-7`) exposes `width`, `height` and
`transform`. `width`/`height` are the container's, kept current by the library's ResizeObserver;
`transform` changes on every pan/zoom. **Reading them in a selector is the "re-measure on
resize/zoom" requirement, for free and with no oscillation** — nothing is measured off the panel
we are ourselves adjusting, so there is no feedback loop to converge.
</measured_facts>

```ts
// frontend/src/components/workflows/editAffordance.ts  (NEW exports)

/** Breathing room kept between the panel and the container edge, in screen px. */
export const PICKER_MARGIN = 8
/** Never bound the panel below this, in screen px — a 30px menu is not a menu. */
export const PICKER_MIN_HEIGHT = 120

export interface PickerPlacementInput {
  /** Flow y of the `＋` this picker belongs to: `EDIT_AFFORDANCE.INSERT_Y + slant`. */
  anchorFlowY: number
  /** Flow x of the panel's LEFT edge as shipped: `insertPointX(...) - PICKER_WIDTH / 2`. */
  panelFlowX: number
  /** The live viewport transform, `[tx, ty, zoom]` (@xyflow store `transform`). */
  transform: readonly [number, number, number]
  /** `.react-flow`'s own size in screen px (@xyflow store `width` / `height`). */
  container: { width: number; height: number }
}

export interface PickerPlacement {
  /** Which side of the `＋` the panel opens on. */
  side: "below" | "above"
  /** The flow y the wrapper translates to. */
  flowY: number
  /** Screen-px x correction, applied INSIDE the counter-scale. 0 when it already fits. */
  offsetXPx: number
  /** The panel's height budget in its own CSS px (== screen px, net scale 1).
   *  `null` = DO NOT BOUND — the container has not been measured yet (jsdom, first paint). */
  maxHeightPx: number | null
}

export function pickerPlacement(input: PickerPlacementInput): PickerPlacement
```

The arithmetic, stated once so the executor implements it rather than re-derives it:

```
z            = finite(zoom) && zoom > 0 ? zoom : 1          // totality, never NaN
belowFlowY   = anchorFlowY + EDIT_AFFORDANCE.PICKER_DROP
aboveFlowY   = anchorFlowY - EDIT_AFFORDANCE.PICKER_DROP
belowTopPx   = belowFlowY * z + ty                          // px from container top
aboveBotPx   = aboveFlowY * z + ty
spaceBelow   = container.height - belowTopPx - PICKER_MARGIN
spaceAbove   = aboveBotPx - PICKER_MARGIN
side         = spaceAbove > spaceBelow ? "above" : "below"  // prefer BELOW on a tie: the shipped side
flowY        = side === "above" ? aboveFlowY : belowFlowY
maxHeightPx  = max(PICKER_MIN_HEIGHT, side === "above" ? spaceAbove : spaceBelow)

leftPx       = panelFlowX * z + tx
maxLeft      = container.width - EDIT_AFFORDANCE.PICKER_WIDTH - PICKER_MARGIN
offsetXPx    = clamp(leftPx, PICKER_MARGIN, max(PICKER_MARGIN, maxLeft)) - leftPx

// DEGENERATE (container.height <= 0 or width <= 0, or any input non-finite):
//   return { side: "below", flowY: belowFlowY, offsetXPx: 0, maxHeightPx: null }
//   — byte-identical to the shipped geometry, so jsdom and first paint are unchanged.
```

The wrapper transform Task 2 emits (`PlaneEditingLayer.tsx`), for reference:

```
translate(<panelFlowX>px, <placement.flowY>px) scale(<1/zoom>) translate(<offsetXPx>px, 0px)[ translateY(-100%)]
```
with the trailing `translateY(-100%)` present only when `side === "above"`.
