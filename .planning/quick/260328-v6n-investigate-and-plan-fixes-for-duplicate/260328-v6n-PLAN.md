# Investigation + Plan: 9 Issues

## Issue Analysis

### Category A: Quick Fixes (Issues 1-6)

**Issue 1: Duplicate file upload ignores folder context**
- **Root cause:** `backend/app/api/documents.py` line 82-93 — the duplicate check queries by `content_hash` + `user_id` + `status=completed` but does NOT filter by `folder_id`. If the same file exists in folder A, uploading to folder B returns the existing record from folder A instead of creating a new entry.
- **Fix:** Add `.eq("folder_id", folder_id or None)` to the duplicate check query (lines 82-90). This allows the same file content in multiple folders. Alternatively, if the intent is "same content anywhere = skip", then the existing duplicate should be MOVED to the target folder. The simpler fix: check content_hash within the same folder only.
- **Complexity:** Simple (1 line change + test update)

**Issue 2: Tool call loading state UX — no "still processing" indicator after tool results arrive**
- **Root cause:** `frontend/src/components/chat/ToolCallPanel.tsx` — the panel shows `Loader2` spinner only when `allDone` is false (line 340-341, 362-364). When all tool calls are individually `status: "done"` but the LLM is still generating the final response, `allDone` becomes `true` and the spinner disappears. The user sees completed tools but no indication the assistant is still thinking.
- **Fix:** The ToolCallPanel itself correctly shows tools. The issue is that after tools complete and before the assistant text streams in, there is no visible indicator. Need to add a "Generating response..." indicator below the ToolCallPanel when tools are done but assistant content is still empty/streaming. This belongs in the message rendering area (ChatArea/MessageBubble), not in ToolCallPanel.
- **Complexity:** Simple (add conditional indicator in message rendering)

**Issue 3: Tool call layout overflow on expand**
- **Root cause:** `ToolCallPanel.tsx` — the expanded body (line 380-419) has `px-3.5 pb-3 space-y-2` but no width constraint. The inner result renderers (LsResult, TreeResult, etc.) use `max-h-48 overflow-y-auto` for vertical scroll but have no `overflow-x-auto` or `max-w` or `break-words` to prevent horizontal overflow. Long filenames or paths in monospace font can push beyond the parent container.
- **Fix:** Add `overflow-x-hidden` or `overflow-hidden` to the expanded body div, and add `break-all` or `truncate` to the monospace filename spans in each result renderer. Also ensure the outer panel has `max-w-full overflow-hidden`.
- **Complexity:** Simple (CSS adjustments)

**Issue 4: Duplicate folder name prevention**
- **Root cause:** `backend/app/api/folders.py` `create_folder` (line 57-86) — no uniqueness check. It validates parent_id but never checks if a folder with the same name already exists under the same parent for the same user.
- **Fix:** Before inserting, query `folders` table for `name=body.name.strip(), parent_id=body.parent_id, user_id=current_user['id']`. If exists, return 409 Conflict. Also add the same check to `rename_folder`.
- **Complexity:** Simple (add query + 409 response)

**Issue 5: Delete document confirmation**
- **Root cause:** `frontend/src/components/ingestion/DocumentList.tsx` line 155-160 — the delete button calls `onDelete(doc.id)` directly with no confirmation dialog.
- **Fix:** Add an AlertDialog (shadcn/ui) wrapping the delete button. On click, show "Are you sure? This will permanently delete {filename} and all its chunks." with Cancel/Delete buttons.
- **Complexity:** Simple (add AlertDialog component)

**Issue 6: Folder breadcrumb navigation**
- **Root cause:** `frontend/src/pages/IngestionPage.tsx` — when a folder is selected, there is no breadcrumb trail showing the path. The user can only see what folder is selected via the tree highlight. No way to navigate up except clicking in the tree.
- **Fix:** Add a breadcrumb bar above the document list that shows `Root > Parent > Current Folder`. Each segment is clickable to navigate to that folder. Build the path by walking `parent_id` references in the flat `folders` array.
- **Complexity:** Simple (new small component + path builder utility)

### Category B: Larger Features (Issues 7-9)

**Issue 7: Global folder UI toggle**
- **Current state:** `is_global` is a column on the `folders` table. The `create_folder` API accepts `is_global` in the body (`FolderCreate` model). But the frontend `FolderTree` and `FolderCreateInput` components never expose this option. The `useFolders.createFolder` already accepts `isGlobal` as a third param (default false).
- **Sub-question: Do files in a global folder become globally visible?** Looking at the documents table: documents have `user_id` and `folder_id`. RLS on documents filters by `user_id`, not folder visibility. So files in a global folder are NOT automatically visible to other users — only the folder structure is shared, not the documents inside. This needs to be clarified: either (a) document RLS needs a policy that exposes docs in global folders, or (b) global folders are just organizational (visible tree, but each user's own docs).
- **Fix needed:**
  1. Add a toggle/checkbox in folder creation UI for "Make global"
  2. Add a context menu option on existing folders to toggle global status (new PATCH endpoint)
  3. Decide and implement document visibility in global folders (requires new RLS policy if docs should be shared)
- **Complexity:** Medium (UI toggle is simple, but document-in-global-folder visibility is an architectural decision)

**Issue 8: Folder appearance enhancement**
- **Current state:** Folders exist only in the left panel of the IngestionPage. When clicked, the right panel filters the document list to that folder. There is no card-based view, no visual preview of folder contents, no folder-centric navigation outside the tree panel.
- **Fix needed:** This is a UI redesign of the ingestion/documents page. Options:
  1. Keep two-panel layout but enhance folder items to show document count, size, last updated
  2. Add a grid/card view for folders on the main panel, clicking opens folder contents
  3. Add a "folder detail" view when a folder is selected
- **Complexity:** Medium (UI redesign, multiple components affected)

**Issue 9: Chat with specific folder**
- **Current state:** Chat uses `search_documents` which queries all user documents via pgvector RPC. There is no folder scoping in `retrieval_service.search_documents()` or the `match_document_chunks` RPC. Threads have no `folder_id` concept.
- **Fix needed (multi-layer):**
  1. **DB:** Update `match_document_chunks` RPC to accept optional `folder_id` filter, join on `documents.folder_id`
  2. **Backend:** `retrieval_service.search_documents()` accepts `folder_id`, passes to RPC
  3. **Backend:** Thread model or thread metadata stores the associated folder_id
  4. **Backend:** `threads.py` agentic loop passes folder_id to search_documents when set
  5. **Frontend:** UI to select a folder for a conversation (dropdown in chat header or sidebar)
  6. **Frontend:** Visual indicator showing a thread is scoped to a folder
  7. **Frontend:** Folder-scoped tool calls (ls, tree, grep, glob) should also be auto-scoped
- **Complexity:** Complex (touches DB, RPC, backend services, thread model, frontend chat UI)

## Implementation Plan

### Task 1: Quick Fixes — Backend (Issues 1, 4)
**Files:**
- `backend/app/api/documents.py`
- `backend/app/api/folders.py`

**Actions:**
1. **Issue 1 — Folder-aware duplicate check:** In `upload_document()`, modify the duplicate check query (line 82-90) to also filter by `folder_id`. Use `.eq("folder_id", folder_id)` when folder_id is truthy, and `.is_("folder_id", "null")` when folder_id is None/empty. This allows the same file to exist in different folders.
2. **Issue 4 — Duplicate folder name prevention:** In `create_folder()`, before the insert, query: `supabase.table("folders").select("id").eq("name", body.name.strip()).eq("user_id", current_user["id"])` plus `.eq("parent_id", str(body.parent_id))` if parent_id exists, or `.is_("parent_id", "null")` if root-level. If result has data, raise `HTTPException(status_code=409, detail="A folder with this name already exists in this location")`. Apply the same check in `rename_folder()`.

**Verify:**
- Upload same file to two different folders — both should succeed (201 for each)
- Upload same file to same folder — second should return 200 (duplicate)
- Create two folders with same name under same parent — second should return 409
- Rename folder to a name that already exists under same parent — should return 409

### Task 3: Plan for Larger Features (Issues 7, 8, 9) — Design Document

These three issues are interconnected and should be planned as a proper milestone/phase rather than quick fixes.

**Issue 7 (Global folder toggle)** requires an architectural decision about document visibility in global folders before implementation.

**Issue 8 (Folder appearance)** is a UI redesign that should be done after the folder system's behavior (global visibility, scoping) is settled.

**Issue 9 (Chat with folder)** is the most complex, requiring DB migration, RPC changes, backend plumbing, and frontend chat UI changes.

**Recommended approach — new planning phase:**

1. **Decide first:** Does "global folder" mean (a) folder structure visible + each user's own docs, or (b) folder + docs visible to all? This affects RLS, and Issue 9's folder scoping.

2. **Phase structure (suggested 3 plans):**
   - **Plan 1: Global folder toggle + document visibility RLS** (Issue 7)
     - Add PATCH `/folders/{id}/toggle-global` endpoint
     - Add UI toggle in folder context menu
     - Implement chosen RLS policy for docs in global folders
   - **Plan 2: Folder-scoped chat** (Issue 9)
     - DB: Add `folder_id` to threads table (migration)
     - DB: Update `match_document_chunks` RPC to accept folder_id filter
     - Backend: Thread creation accepts folder_id, search_documents passes it through
     - Backend: All tools (ls, tree, grep, glob, read) auto-scope to thread's folder
     - Frontend: Folder picker in chat creation, visual badge on scoped threads
   - **Plan 3: Folder UI redesign** (Issue 8)
     - Enhanced folder cards with doc count, size, last modified
     - Grid view option for folder browsing
     - Folder detail panel when selected
