## Decisions Made

1. **Exact equality, not casefold** — recorded in the plan and now pinned by a test row
   (`"approve and run this step"` must fail). Rationale carried verbatim in the source comment and
   in `_ARMED_NON_APPROVALS`' docblock: a looser rule only ever accepts strings the button cannot
   emit, so it widens the typed path (the attack surface) for zero legitimate benefit; and the two
   errors are asymmetric — a refused approval is recoverable with a click, an accepted one sends the
   email. The engine's own words at `:1123-1127` are quoted as the governing precedent.
2. **`.strip()` is NOT widened.** Trailing whitespace on the exact label still proceeds, exactly as
   it does today. The pre-existing strip is upstream of the new comparison and was left alone.
3. **The fail_run reason gets a distinct suffix** rather than reusing `"— aborted by user"`, so the
   ledger distinguishes "they declined" from "we could not read their answer as consent", and so the
   tests have a discriminator proving which branch fired.
4. **Scope held.** The freshness/generic free-text fall-through was deliberately left unchanged and
   fenced two-sidedly, rather than "fixed while we were in there".

any `response_text`.**

- `frontend/src/components/panel/PendingAskCard.tsx:413-425` — the `<textarea>` renders alongside

Neither is exploitable for the armed path now that the engine is fail-closed, and both were left
alone deliberately: a UI-only change leaves the API open, and the API change is not needed once the
engine refuses. But there is exactly one layer of defence.

**Re-open trigger (concrete):** any phase that adds a **second consumer of `ask_user_prompt`
answers**, or introduces a **checkpoint whose approval is not routed through
`_resolve_failure_with_ask_user`**, must (a) gate the textarea on `options.length === 0` and
(b) validate `response_text` against the prompt's stored `options` server-side. Named likely
triggers: **Phase 186** (approval identity — "someone else approved it"), **Phase 188** (the run
surface, which renders these prompts), **Phase 189** (the external-action node, the named producer
of `armed: false` edges).

**Provenance:** the unconditional textarea is the shipped **085/096 D3 "no-options trap"**, not a
Phase 185 regression. Phase 185 is what made it safety-critical — pre-185 this gate guarded
"continue a retrieval"; post-185 it guards "send the email / file the claim".

**Also still open, unchanged and out of scope (recorded in 185's own deferred items):** the
freshness/generic twin of this fall-through, and the global timeout-advances-silently behaviour in
