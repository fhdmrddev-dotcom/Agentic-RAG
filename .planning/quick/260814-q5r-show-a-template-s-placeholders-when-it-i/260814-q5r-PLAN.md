<decisions>

**D-1 — A dedicated owner-gated route, NOT a widened `template_asset_id` on
`/workflows/grounding-bundle`.** Four reasons, in order of weight: (a) widening that
parameter converts an accidental `UUID` guard into a hand-written ownership fence on a
**service-role** Storage read (finding 2) — the exact shape Phase 190's CR-01 was; (b) the
palette route is `require_canvas()`-gated, so placeholders would be invisible on the **Spine**
view, which is the surface most authors are on and which the page mounts the template prop
unconditionally for (`WorkflowBuilderPage.tsx:2033-2040`); (c) it would refetch the whole
palette — folder tree, skill registry, tool list — to read one document's field names; (d) it
would put a template-read axis onto a response shape `/validate` and NL generate also consume.
**Cost, stated rather than hidden:** `getGroundingBundle`'s `templateAssetId` parameter and the
`GroundingBundle.template_placeholders` field remain **unused by the app** after this plan.
They are left alone, not deleted — deleting a shipped typed seam is not this task's call.

**D-2 — A dedicated leaf hook, NOT a parameter on `useGroundingBundle`.** That hook is the
shared palette read keyed on `enabled` alone; a `templateAssetId` parameter changes the effect
key for every consumer, and its `ready` member types `degraded` as the empty tuple precisely so
that "a partial palette presented as complete" is unconstructable — a template-read failure is a
different honesty axis and would have to be smuggled onto that union. The precedent is recorded
in `TemplateAttachSection.tsx`'s own docblock: *"The `ConnectionPicker.tsx` shape (Phase 190-12):
a leaf that consults the server itself rather than growing three props on its parent."*

**D-3 — Derive from the BOUND `asset_id`, never from the upload response.** This serves BOTH
readings of "when it is attached": (b) a saved draft re-opened months later, because
`WorkflowBuilderPage` already resolves `assets.find(a => a.kind === "template")` on mount; and
(a) a fresh upload in this session, because `onTemplateAttached` writes the descriptor into the
store one statement before `saveNow()` (`WorkflowBuilderPage.tsx:1349-1355`), so the `assetId`
prop changes in the same render. A design keyed off the upload response would satisfy (a) and
silently fail (b) — which is the reading that makes the feature worth having.
⚠ **The corollary that makes (a) work without a race:** the route takes the `asset_id` as a
query parameter and does **not** require it to be bound in the persisted definition. Requiring
the binding would mean the fetch races `saveNow()`'s round trip and answers about the OLD
template, or none. Ownership is proved by the two fences in D-4, not by the binding.

**D-4 — Two fences, and the second one is not decoration.** The route gates on
`_owned_slug_or_404(pool, definition_id, user_id)` — the SAME owner-scoped `created_by` WHERE
the upload/delete/preview routes use, whose 404 is deliberately indistinguishable from
not-found — AND on the asset id itself: it must start with `f"{user_id}/"` and contain no `..`
segment. The `..` check is load-bearing rather than belt-and-braces: `workspace_storage_select_own`
(`supabase/migrations/054_workspace_files.sql:83-89`) keys on `(storage.foldername(name))[1]`,
so `{uid}/../someone/x.docx` **passes the database policy**. Both fences are driven RED.

**D-5 — Read through the USER-JWT client, not the service role.** `get_user_supabase_client`
makes `workspace_storage_select_own` a second, database-enforced boundary underneath the
route's own fence, exactly as the Phase 193 upload route documents for its write. If a live
probe shows Storage refusing the authenticated read, fall back to `get_supabase` and record
the fallback as a decision in the SUMMARY — never silently.

**D-6 — Four readings, four distinct nodes, every sentence an exported identifier.**
`fields` / `none` / `unavailable` / `not-word`. `none` and `unavailable` MUST NOT share a node
or a sentence; that is RED-4. Every string is a module-scope export for the reason this file
already states: *"a sentence living inline inside JSX is a sentence nobody can test for drift."*

**D-7 — The not-a-Word-document sentence is gated on EMPTINESS, which makes it drift-safe by
construction.** It renders only when the server answered `ok` with zero fields AND the filename
does not end `.docx`. If the backend ever learns `.pptx`, the fields render and this sentence
can never appear — so it cannot become a stale second copy of a server predicate (the D-182-06
red line).

**D-8 — No new colour, no chip, no badge.** The amber `REFUSAL_CLASSES` block is reserved for
