# v3.7 Milestone Audit — mid-flight checkpoint

## 0. ⚠ Read this first: the milestone is NOT finished, and this is not a definition-of-done audit

`/gsd:audit-milestone` verifies a milestone *achieved its definition of done*. **v3.7 has not reached
it**: `all_phases_complete: false`, **7 of 18 phases**, and **phases 195–198 have no directories at
all.**

Run as specified, the audit would report seven requirements unsatisfied purely because nobody has
built them yet — which is not information. **So this is deliberately re-framed as a mid-milestone
checkpoint**, and the seven unbuilt requirements are recorded as `not-yet-built` rather than counted
as failures.

**What that leaves is genuinely worth knowing**, because the v3.6 close was gated not by code but by
paperwork — five stale checkboxes, a phase reading `1/13` thirteen days after it shipped `13/13`, and
nine requirements riding on three missing VERIFICATION files. **The same pattern is forming here.**

**Milestone goal:** *an author can find a workflow, understand the door they are walking through,
build it with the right vocabulary, stop it, and see what it produced.*

### 2.1 ⛔ BLOCKER — FOUND AND FIXED DURING THIS AUDIT

**The L-01 terminal guard was applied to `workflow_runs` and not to `workflow_phases`.** Measured:
`git show 9dbd57f5 -- backend/app/db/workflows.py | grep -cE "^\+.*workflow_phases"` → **0**.

⚠ **This was residue of a fix made hours earlier the same day.** On the known L-01 residue (the
far-worker producer keeps running after a Stop), worker A writes `cancel_phase → cancelled` and
worker B writes `complete_phase → completed` over it — so the run would read `cancelled` while its
spine showed that very step **done**, with `runStepCount` counting it toward *"N of M steps"*.
**Making the run row honest while leaving the phase rows unguarded is worse than leaving both
dishonest**, because the surfaces then disagree — the exact defect class 194/194.1 existed to remove.

**Fixed in `e1200576`**, scoped deliberately narrower than the run-level guard: only `cancelled` is
protected, because a retry legitimately re-runs a phase and `failed → completed` may be correct.
Proved on a real row with a control, and retries shown unharmed.

### 2.2 ⛔ BLOCKER — "see what it produced" has no surface

**There is no run history anywhere.** `grep -rn "runHistory|listWorkflowRuns|pastRuns" frontend/src`
→ 0. `backend/app/api/workflow_runs.py` exposes **one** GET route — single-id, and canvas-gated.

The only routes back to a finished run are the chat thread and a panel link that is itself
canvas-gated. **At the shipped flag default both the run page and its one read route are off.** This
is the milestone goal's own last clause, and it is unmet. **Phase 195 is the natural home.**

### 2.3 ⚠ WARNING — a draft can become permanently unpublishable with no in-product remedy

`business_requirement` has **exactly one writer**, and it is canvas-gated
(`WorkflowBuilderPage.tsx:2119`, `requirementAffordance = canvasEnabled ? … : null`). The publish
gate that *requires* the field is not gated. **So at the shipped default, a draft whose model output
omitted the field cannot be published and the product offers no control to fix it and no sentence
explaining why.** Live: **10 of 80 drafts** have no `business_requirement`. Residue of
`BUG-260809-02`, narrowed rather than closed.

### 2.4 ⚠ Other warnings

- **The stopped run line has no recency gate** — it reads the thread's *last* workflow run, so a user
  who stops a run and keeps chatting sees `⊘ Stopped by you` pinned under newer, unrelated content
  indefinitely. Structural; not sighted (all 11 such threads have zero messages after the cancel).
- **193's template mark goes silent on exactly the rows 193.1 produces.** A template-first workflow is
  the one shape guaranteed to show *no* template signal on its card. Live: 1 admits / 35 does-not-admit
  / 120 unknown.
- **`Stop all` in the tray** bypasses `StopControl` — same resolver, so the one-mechanism rule holds,
  but it is the one Stop affordance not covered by 194.1's impossible-to-double-press property.
- **Three stale RUN-01 claims**, one in shipped source — **all three reconciled in `20a0952f`**.
