## 1. Header

v2.6 builds the production-ready substrate the next four milestones depend on. Three workstreams ship in parallel: (1) a **RAG quality lift** that replaces the inconsistent pypdf + pdfplumber + vision-API ingestion path with **Docling** (MIT, IBM-maintained) as the primary extractor and PyMuPDF AGPL behind a new `PdfExtractor` abstraction as a fallback, fixing the production failure mode where the user's reference thesis extracts ~5 tables / 4 images via the PDF path but 50+ tables / 0 images via the DOCX path; (2) a **multi-worker discipline rewrite** that wraps remaining sync `supabase-py` paths via `asyncpg` and lifts `D-v2.5-02`'s single-worker constraint so v3.3 (public API) and v3.4 (automations) can ship safely on top; (3) **polish carry-forwards** that close `SEED-008` / `SEED-009` / `SEED-010` / `SEED-011` plus the still-open code-quality items the v2.5 sweep didn't absorb. As a fourth strand, v2.6 also pre-emptively lifts `SEED-007` (App-level `<StreamsProvider>`) so v3.0's eval-streaming UX lands on a clean substrate (per `D-PRD-06`). Strategically, every milestone after this assumes either retrieval quality is solved or the backend can run with `--workers N`; deferring v2.6 means inheriting the same constraints v2.5 deliberately deferred.

## 5. Architecture & Data Model changes

**Migration numbers claimed:** `039`, `040`, `041`, `042`, `043`, `044`, `045`. Seven of the 11 reserved slots used; 046–049 remain as buffer for unanticipated phase-level discoveries. Matches `MIGRATION-RESERVATIONS.md` row for v2.6 (range `039 – 049`, width 11).

**New tables:**
- `pdf_extraction_runs` — per-document extraction telemetry. Columns: `id uuid pk`, `document_id uuid fk`, `user_id uuid fk`, `engine text` (`'docling' | 'pymupdf' | 'pypdfium2'`), `started_at timestamptz`, `completed_at timestamptz`, `duration_ms int`, `table_count int`, `image_count int`, `error text`. RLS keyed on `user_id` via FK. Migration `039_pdf_extraction_runs.sql`.

**Modified tables:**
- `documents` — add `extractor text` column (nullable, backfilled to `'pypdf-legacy'` for existing rows during one-time re-ingest pass; default `'docling'` on new ingests). Migration `040_documents_extractor_column.sql`.
- `document_images` — add `bbox jsonb` column (spatial coordinates from Docling/PyMuPDF). Migration `041_document_images_bbox.sql`.
- `document_tables` — add `bbox jsonb` and `extractor text` columns (matches `document_images` shape; required for the Q-v2.6-03 calibration to compare extractor lineage). Migration `042_document_tables_bbox_extractor.sql`.
- `documents` — add partial unique index `(user_id, content_hash, folder_id) WHERE status != 'failed'` (closes RECOVERED_Code_Quality_Review §2.C concurrent-upload race per CQ-DEDUP-01). Migration `043_documents_dedup_unique_index.sql`.
- `app_settings` — promote multimodal limits from module constants to admin-tunable settings: `multimodal_max_vision_calls int default 100`, `multimodal_max_b64_bytes_kb int default 4096` (lift defaults from current 20 / 512 KB per RAG-MM-LIFT-01). Migration `044_app_settings_multimodal_limits.sql`. (Note: `app_settings` table is currently dead code per `CONCERNS.md:520-524`; this migration also wires the `models/user_settings.py` reader to actually consult it for these two keys, treating settings_override.json as override only.)

**Schema-only changes for cross-worker safety:**
- `runs` — no schema change required; the table already exists from `035_runs_table.sql` and is cross-worker-safe by virtue of being Postgres-backed (per `D-v2.5-11`).

**Optional/conditional migration:**
- Migration `045_runs_worker_id.sql` — adds `runs.spawned_by_worker text` column for cross-worker debugging. Conditional on Q-v2.6-02 outcome; if atomic rollout chosen, lands in same phase as multi-worker enablement.

**New SDK / library deps:**
- `docling>=2.x` — pinned compatible with whichever httpx-conflict resolution path Q-v2.6-01 selects (likely `docling==2.92` if subprocess-isolated; later if supabase-py upgraded).
- `pymupdf>=1.24` — AGPL-3.0; documented in `D-PRD-07`. Behind subprocess fence (per D-PRD-03 implication: AGPL must not be linkable into open peripherals — see §6 Compatibility row 3).
- `pypdfium2>=4.30` — Apache 2.0; license-safe last-resort fallback (used for cases where both Docling and PyMuPDF fail).
- `asyncpg>=0.29` — async Postgres driver for hot paths (`D-PRD-08`, `WORKER-LIFT-02`).

**Removed/deprecated deps (NOT removed in v2.6, marked):**
- `pdfplumber>=0.11.0` — no longer the primary table extractor; preserved only for v1 fallback paths until v3.0+ confirms no callers remain. Removal deferred.
- `pypdf>=5.0.0` — no longer the primary text extractor; same deferral.

**New env vars:**
- `EXTRACTOR_PRIMARY=docling|pymupdf|pypdfium2` — operator override of the per-document extractor decision.
- `EXTRACTOR_DOCLING_ISOLATION=subprocess|in-process` — escape valve if the Q-v2.6-01 in-process resolution surfaces issues in production.
- `WORKER_COUNT` (int, default 1 in dev / 2 in prod once D-PRD-12 lands) — explicit override of `--workers N`. Documented in supersession ADR.
- `BACKPRESSURE_ADMIN_USER_IDS` (comma-separated UUID list) — gates `GET /admin/backpressure` until v3.1 RBAC ships.

**New Redis key patterns:** none — existing `run:{run_id}` / `runs_by_thread:{thread_id}` / `runs:active` (per `CLAUDE.md` "Run-buffer key conventions") already cover the multi-worker case.

**New SSE event types:**
- `tool_args_progress` (POLISH-TOOL-PROG-01) — payload `{tool_index: int, args_so_far: str (≤5KB chunk), total_args_bytes_so_far: int}`. Wire-shape mirrors existing `code_executing` heartbeat.
- `code_stdout` (SEED-008 §gap2) — payload `{tool_index: int, line: str, captured_at: float}`. Replaces post-completion batched stdout emit.

**New API routes:**
- `GET /threads/{id}/snapshot` — returns `{messages, active_runs, since_cursors}` in one round-trip. Backed by parallel `aexec`-then-asyncpg reads (POLISH-SEED-008-01).
- `GET /admin/backpressure` — read-only JSON dashboard primitive (WORKER-LIFT-04). Admin gate via `BACKPRESSURE_ADMIN_USER_IDS` env var.
- `POST /documents/{id}/reextract` — opt-in re-extraction trigger for the Docling path on a single document (per Q-v2.6-04 recommendation). Queues a single re-ingest task; returns `202`.

**New background processes:** none. The asyncpg adoption is in-process. Multi-worker means N copies of the SAME process under uvicorn supervision — not microservice split.

**Modified hot paths:**
- `backend/app/api/threads.py:158-255` (`_drain_stream_with_close_on_cancel`) — Postgres reads/writes converted from `aexec(supabase.table(...).select(...))` to asyncpg pool calls. Behavior preserved.
- `backend/app/api/threads.py:842` (asyncio.timeout wrap) — unchanged at the timeout layer; only the supabase-py call inside it switches.
- `backend/app/dependencies.py:13-17` (Supabase singleton) — preserved for non-hot endpoints; new asyncpg pool singleton added alongside (`_pg_pool` at `dependencies.py:18-30` per phase-level design). Both shut down via lifespan.

## 10. Surprise-feature check (Gate 5)

**Rejected ideas:**

1. **Idea:** Migrate pgvector index from `ivfflat` to HNSW as part of the Docling re-extraction pass.
   **Why tempting:** Docling re-extraction will re-embed every chunk anyway (one-time cost amortized). HNSW is the modern default for >10k vectors and gives better recall at scale.
   **Why not now:** v2.6's risk surface is already large (Docling spike + asyncpg + multi-worker + `<StreamsProvider>` lift). Adding an index migration on top compounds rollback risk. Pgvector `ivfflat` is "good enough" up to ~100k vectors with proper `lists` tuning; below that threshold, HNSW's gains are marginal.
   **Re-trigger:** Vector search latency p95 > 500ms on a real workload (telemetry observation via the new `pdf_extraction_runs` table makes this cheap to observe), OR document corpus crosses 100k rows. Promote to its own polish phase in v3.0 or v3.1.

2. **Idea:** Adopt **Adobe PDF Services API** as primary extractor instead of Docling.
   **Why tempting:** Adobe's API has the most mature table + figure detection on the market and gives commercial-grade reliability without AGPL friction.
   **Why not now:** Recurring per-page cost is incompatible with the self-host pricing model (`D-PRD-10` 3-tier flat per-named-user — no per-document overage). It also defeats the open-source self-hostable positioning (`D-PRD-03`). Docling MIT closes 80% of the quality gap at zero recurring cost; the remaining 20% can be addressed by PyMuPDF Pro after first paying customer (`D-PRD-07`).
   **Re-trigger:** A specific customer commits to a deployment posture where per-document recurring API cost is acceptable AND Docling+PyMuPDF have failed on their corpus.

3. **Idea:** Migrate vector store off pgvector to a dedicated vector DB (Pinecone / Qdrant / Weaviate).
   **Why tempting:** Dedicated vector DBs have stronger query latency at very large scale + advanced filtering primitives.
   **Why not now:** pgvector is performant enough at projected scale (per `D-PRD-01` mid-large enterprise tier — hundreds to thousands of users per org, NOT millions of vectors per query). One-way migration adds operational complexity (a third stateful service to back up + monitor). The unified-Postgres-with-RLS story is a real moat against multi-tenancy in v3.2 — splitting state across two stores complicates the org-isolation RLS rewrite.
   **Re-trigger:** First customer on a vertical pack with >10M chunks AND pgvector p95 query latency > 500ms even after HNSW migration.

4. **Idea:** Convert all OpenAI calls to the **AsyncOpenAI** client as part of the multi-worker rewrite.
   **Why tempting:** AsyncOpenAI is the "proper" async-native path; eliminates the `_drain_stream_with_close_on_cancel` thread-executor dance entirely; aligns with the asyncpg work.

The Track A drain helper is well-understood and stable post-067.x.

5. **Idea:** Real-time multi-user collaboration on threads (live cursors, simultaneous typing, shared selection).
   **Why tempting:** Strong product differentiator vs ChatGPT / NotebookLM (neither has it); enables team brainstorming flows.

## 14. Competitive positioning paragraph

v2.6 positions Agentic RAG against **Glean** (the primary enterprise-search competitor per `D-PRD-05`) and **NotebookLM** (Google's RAG offering — strong on PDF extraction with Gemini multimodal, but no agent layer or self-hosting). Two differentiators ship in this milestone. **First: multimodal RAG that actually surfaces what's in the document.** Glean is closed SaaS with no self-hosting and no code execution; its PDF table-extraction quality is moderate but its agent layer is a workflow surface, not a skill runtime. NotebookLM is strong on multimodal (Gemini + Google's PDF stack) but has no agent layer and no path to self-host or extend. By replacing pypdf with Docling primary + lifting the multimodal ceiling at `backend/app/services/multimodal_service.py:29-33` and adding the `PdfExtractor` abstraction, v2.6 closes the user-observed 5/4 vs 50+/0 PDF/DOCX inconsistency and stores ≥80% of visible figures by default — table cells and image regions become first-class participants in vector search, with extractor lineage telemetry per document. The abstraction also means *any operator can swap in their preferred backend* (PyMuPDF Pro post-paying-customer, Adobe API for one-off needs, custom extractors for vertical packs) without touching app code. **Second: production-tier scale-out via single-codebase multi-worker, self-hostable.** Lifting `D-v2.5-02`'s single-worker rule and shipping the asyncpg-backed pool means a self-hosted deployment can scale linearly with `--workers N` against a tunable pgbouncer pool — a story neither competitor offers because their architecture is closed and SaaS-only. v2.6's groundwork unlocks the v3.3 Open Platform claim (open-source self-hostable agentic-RAG-as-a-platform with REST + MCP exposure per `D-PRD-03`) by removing the ceiling that kept the v2.5 backend unusable above ~10 concurrent users. The reproducible extraction telemetry per document (`pdf_extraction_runs`) is a third quiet differentiator — buyers can audit RAG quality drift over time without instrumentation work.
