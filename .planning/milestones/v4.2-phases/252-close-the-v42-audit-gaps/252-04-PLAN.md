<objective>
Stop the workspace panel calling a live run finished — on **both** of its run-state surfaces.

Purpose: **SC#5.** `TodosSection.tsx:262-264` derives `isRunLive` from `streamingThreads ∪
loadingThreads` and renders **`Not ticked` on a LIVE run** when that reads false. And
`PhaseCard.tsx:407` derives `isRunning` from the SSE phase status **alone**, so a run that dies
without emitting its phase-terminal event leaves a card spinning forever.

⛔ **`BUG-260915-01`'s stated mechanism is measurably FALSE and this plan corrects it first.**
The report says *"opening a thread triggers no reconcile"*. `StreamsProvider.tsx:1936-1942` shows
`setViewingThread` **does** fire `actions.reconcile(threadId)`. **A fixer following the report ships
a no-op.** The real hole is that `reconcile` never sets any loading signal, so the `||` buys
nothing — and `reconcileInFlightRef` is a **global** boolean, so a dropped reconcile leaves the false
state until the user navigates away and back, which is the persistent symptom the report describes.

⭐ **Hole 2 is nearly free, and the reason is worth stating.** `PhaseTimeline.tsx:250` **already
computes** `runTerminal` from the authoritative fetched frame. `PhaseCard`'s own docblock at `:398`
says *"A local ternary here would be a second derivation and the panel and the run page would
eventually disagree."* So the fix **reuses the shipped derivation** rather than adding one.

Output: a corrected report, one new store slice, a per-thread lock, one optional prop, one
vocabulary row, and three small warnings.
</objective>
