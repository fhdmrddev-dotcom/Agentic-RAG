<threat_model>
### Invariants

1. **The D-05 trap — a cap-paused run must NEVER be marked.** A Deep run that hit the iteration
   cap is **non-terminal and re-attachable**: the user can continue it, and marking its open todos
   *"not completed"* would be a lie about a run that is still going. The current gate spends a
   second clause (`result_sink.get("cap_disposition") != "cap_paused"`) on this. The replacement
   gets it from set membership. ⛔ **That equivalence must be PROVEN by a fence, not argued** —
   this is the one way this plan can ship a regression.

2. **The 8 finalize-ordering invariants are byte-locked.** The reconciler is step 3. Steps 1-7 run
   in exact source order. ⛔ Do not move the block, do not reorder, do not merge it into step 4.

3. **The reconciler may never raise into the finalizer.** The `except BaseException` +
   `logger.exception("RUN-01b reconciler failed for run %s")` wrapper stays exactly as it is.
   ⚠ It is also the thing that would hide a new failure introduced by admitting three more
   statuses, so the fences must assert the CALL, not just the absence of a crash.

4. **More runs now reach the reconciler.** It re-SELECTs the thread's todos and, when something
   changed, calls `replace_todos` (a full-state replace inside a transaction) plus one `emit`.
   On a cancelled or timed-out run the surrounding path is already doing DB work in the same
   finalizer; the added work is one SELECT and, only when an open todo exists, one write.
   ⛔ The no-op path must stay byte-clean (D-14): nothing open ⇒ no `replace_todos`, no emit.
</threat_model>
