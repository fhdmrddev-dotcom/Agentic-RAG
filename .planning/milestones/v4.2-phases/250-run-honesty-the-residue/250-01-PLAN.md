<objective>
**Two ways a run lies about itself, both inside the agent loop, both fixed without a provider branch.**

`HONEST-01` — the trimmer evicts the user's own question while keeping the tool results that
question produced, and the model then apologises for losing a question the person just asked.

`HONEST-02` — a model that produces no visible text gets one sentence for every possible cause:
*"empty response after N iteration(s)"*. It names a count and a workaround and says nothing about
what happened.
</objective>

<threat_model>
### Invariants

1. **Deep Mode byte-identical (D-14).** No call site, signature or parameter changes. The trim
   fast path (`estimate_messages_tokens(messages) <= max_tokens` → return `messages`) is
   untouched, so a conversation that fits is returned as the same object it came in as.

2. **No orphaned tool messages — ever.** `_remove_oldest_atomic`'s whole reason for existing is
   that an assistant message with `tool_calls` and its `tool` results are removed together.
   ⛔ Skipping a user group must not let the scan strand a `tool` result whose parent was removed,
   nor remove a `tool` result whose parent survives. Every candidate the new rule returns must
   still be a **complete atomic group**.

3. **Termination.** The removal loop must still make progress. If the user-last rule ever returns
   "removed 0" while groups remain, the `while trimmable:` loop spins forever inside a request.
   ⛔ The fallback arm (remove a user group when nothing else is left) is what guarantees progress
   and is not optional.

4. **The honest message must not become a second lie.** `full_reasoning_content` is reset inside
   the loop. Reading it at the fallback reports *"the model produced no reasoning"* about a model
   that reasoned on every iteration — i.e. the honesty fix shipping a falsehood, for exactly the
   `gpt-5.6` family `BUG-260722-02` is filed against.

5. **No provider fork.** Both changes read shared state. A provider difference belongs at the
   adapter/sanitizer boundary.
</threat_model>
