<threat_model>
### Reliability Invariants

1. **A broadcast must never turn a successful write into an error.**
   - **Invariant:** both broadcast helpers are documented `NEVER RAISES`, and
     `publish_cache_invalidation` returns 0 on any failure with a 1.0 s timeout — a dead Redis
     degrades to the pre-existing 30 s TTL. **The write is the contract.**
   - The fence must pin the fail-soft arm too, not only the happy path.

2. **⛔ A READ must not broadcast.**
   - **Invariant:** `broadcast_model_overrides_change`'s own docstring: the two
     `invalidate_model_overrides_cache()` calls in `admin.py` that force a fresh read before a guard
     (WR-03) **are reads, not writes, and must NOT broadcast.** Publishing there makes every worker
     re-read the database because one worker wanted to check something.
   - This is a fence in **both directions** — three call sites that must publish, two that must not.

3. **Honest cause (D-02).**
   - **Invariant:** an unhealthy tile carries the **verbatim** provider/arm error, never an
     engine-shaped message. The one synthetic string
     (`"The engine did not complete this arm."`) is a correct **last** resort for a
     terminal-but-failed run with no error, and must never become the first.

4. **A closure may not claim more than it measured.**
   - `BUG-260809-01` was measured on **cloud production**. This phase measured **local `develop`**.
     ⛔ The closure states both sentences or it is not honest.
</threat_model>
