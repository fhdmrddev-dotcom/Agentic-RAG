<objective>
**MODEL-05 — the warning moves to where the choice is made, and it says what will actually happen.**

Today an unregistered model resolves `capability_source = "inferred"`, silently loses `native_tools`,
and produces a run that never calls a tool while nothing says why. The warning for this **already
exists** — an amber `unverified` chip in `ModelPillRow.tsx` — but it is on the Settings page, and
the requirement says *"at pick time"*. **Pick time is the chat composer's model dropdown, which has
no such marker at all.**

Two things ship: the chip lands on the pick-time surface, and its words state the consequence rather
than the mechanism.
</objective>

<threat_model>
### Security & Reliability Invariants

1. **Default-SAFE degradation must survive (D-122-05).**
   - **Invariant:** a registry miss degrades to `emit_tier = "coerce"` and, for a non-native inferred
     provider, `native_tools = False`. That default is **correct** — it never assumes a capability it
     has not verified.
   - ⛔ This plan makes the degradation **visible**. It does not make it **fatal**. No refusal, no
     disabled option, no blocked send. `SEED-135` says so in its own words.

2. **No client mirror of the inference table (RESEARCH §6, Approach b).**
   - **Invariant:** the five inference regex patterns and `_NATIVE_TOOL_PROVIDERS` live in
     `config.py` and are never re-implemented in TypeScript. `inferred_provider_for` exists
     precisely so the frontend substitutes a value it was handed.
   - `inferred_tools_lost` follows the same rule: the **server** decides, the client renders.

3. **A model id is a value, not a secret.**
   - The providers payload already exposes model ids to every signed-in user (`VIS-01` run
     carve-out — ⛔ **do not add `require_visible` to `/settings/providers`**; gating it is a
     self-inflicted end-user outage, and `test_148_carveouts` guards against exactly that).
   - The three new fields carry ids and provider names only. **No key, no base URL, no secret.**

4. **The end-user picker feed must never break.**
   - `load_all_model_overrides()` never raises (it returns the stale/empty cache on a blip). The new
     fields must inherit that property: a failed overrides read degrades to *"everything is
     verified"* — i.e. today's behaviour, no chip — never a 500 on the chat picker.
</threat_model>
