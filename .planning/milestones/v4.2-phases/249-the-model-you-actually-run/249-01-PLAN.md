<objective>
**MODEL-04 + MODEL-07 — the operator's registry surface stops refusing the models they run, and its
controls stop reading as something they are not.**

Two requirements, one surface, one plan: both live in `ModelRegistryTab.tsx` + `admin.py`, and
splitting them would be two plans fighting over the same two files.

- **MODEL-04:** a self-hosted model (Ollama / LM Studio / any OpenAI-compatible endpoint) is added
  from the Model Registry UI, with **no code edit and no deploy**.
- **MODEL-07:** the control that hides a model from the picker is the one the operator reaches
  first — achieved by making the controls explain themselves, **not** by adding a control or
  renaming one.
</objective>

<threat_model>
### Security & Reliability Invariants

1. **⛔ SSRF (T-149-03) — THE LOAD-BEARING ONE.**
   - **Invariant:** `PROVIDER_ENDPOINTS` (`model_discovery_service.py:50`) is the set of URLs the
     server will make an **outbound request** to. It is hardcoded so no caller-supplied URL reaches
     the HTTP client.
   - **This plan widens the list `POST /admin/models` VALIDATES against, and does NOT widen the
     list anything is FETCHED from.** They happen to have been the same list; they were never the
     same concept.
   - **Enforcement:** an explicit test asserts `PROVIDER_ENDPOINTS` has exactly its 8 members and
     that none of `ollama` / `lmstudio` / `custom` is among them. A `git diff --stat` on
     `model_discovery_service.py` must be empty at the plan's close.
   - **Why widening the ROUTING roster is safe:** a self-hosted provider's base URL comes from the
     operator's own `app_settings` column (`_SELF_HOSTED_PROVIDERS`, migration 180), through
     `normalize_self_hosted_base_url`. The server never *discovers* it, so it has no business in a
     discovery allowlist. The egress question for those URLs was already answered by migration 180.

2. **SQL identifier integrity (T-159-02).**
   - **Invariant:** column names reaching `add_model_by_id`'s SET clause come ONLY from
     `_ADD_MODEL_CAP_COLUMNS` + the two fixed columns; values are `$N` binds.
   - This plan changes only the **provider value** guard. ⛔ It must not move, weaken or bypass the
     allowlist-before-touch ordering: a blank id is still 422, a bad type is still 422, a duplicate
     is still a case-folded 409, and **all of it still runs before any DB touch**.

3. **Opt-in-enable (SC#3 / D-149-02).**
   - **Invariant:** `AddModelRequest` has no `enabled` field and the row lands `enabled=false`.
   - Widening the provider roster must not create a path where a self-hosted model arrives enabled.

4. **Honest locks (Control-Room doctrine).**
   - **Invariant:** a control that cannot act is gated **with a tooltip saying why**; a control that
     acts differently than it reads is the same defect wearing better clothes.
   - MODEL-07 applies the doctrine to controls that *do* act: each says what it does at the moment
     of reach.
</threat_model>
