<objective>
**CRED-01: Reject secrets in `custom_client_id` across models and panel, with SEED-239 read-resilience and dual-role query execution.**

Ensure that OAuth client secrets and credentials pasted into the non-secret `custom_client_id` field are refused at model validation time with an explicit 422 naming which field takes a secret, and surfaced inline in `ConnectionFormPanel.tsx`. Protect `list_connections` against SEED-239 outages if legacy rows fail validation by safely degrading the single row. Establish the dual-role database fixture executing actual queries as `authenticated` and `anon`.

FENCE: `backend/app/api/connectors.py` is strictly fenced (0 lines touched).
</objective>

<threat_model>
### Security & Reliability Invariants (ASVS L1)
1. **Plaintext Secret Exposure (TM-248-01 / BUG-260907-02):**
   - Invariant: A value resembling a secret (specifically Entra `<prefix>~<body>`, API key prefixes `sk-`, `ghp_`, `xoxb-`, or >128 chars) must never enter `config` on `connector_connections`.
   - The model validator is the gate; 422 is raised naming which field takes a secret.
2. **BYO MCP Compatibility (RFC 7591):**
   - Invariant: Dynamic client IDs (e.g. `bD78Ksp3xBJew1kL`) continue to succeed without disruption.
3. **Read-Path Outage Prevention (TM-248-05 / SEED-239):**
   - Invariant: If a stored database row fails configuration model validation, `connector_service._to_response` must degrade that single row to `status="error"` with an informative message rather than raising an uncaught `ValidationError` in `list_connections:1116` that turns one bad row into a 503 outage for the entire organization.
4. **Credential Non-Echo in Reporting (TM-248-06):**
   - Invariant: Any query or log that identifies bad stored rows outputs row metadata (`id`, `service_id`, `name`) and rotation instructions, never echoing the plaintext secret.
5. **Real Query Execution as Anon & Authenticated (D-248-04):**
   - Invariant: Test suite executes actual SQL queries under `SET ROLE authenticated` and `SET ROLE anon` to verify that `authenticated` CAN read `config`, CANNOT read `secret_ciphertext`, and `anon` gets zero access.
</threat_model>
