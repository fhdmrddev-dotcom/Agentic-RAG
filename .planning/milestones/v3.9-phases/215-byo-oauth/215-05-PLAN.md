# Plan 215-05: E2E Integration, Threat Model Verification & Closeout

## Tasks

### Task 1: End-to-End Integration Suite
- Create `backend/tests/integration/test_oauth_e2e.py`:
  - `test_oauth_full_authorization_and_token_storage_lifecycle`: End-to-end test simulating authorization URL generation -> callback execution -> token encryption -> retrieval.
  - `test_oauth_claim_refresh_concurrency_two_workers`: Simulates 2 workers attempting refresh simultaneously on an expired token, asserting only 1 worker calls the mock provider while both receive the valid refreshed token.
  - `test_oauth_revocation_on_invalid_grant`: Simulates provider returning `invalid_grant` during refresh and asserting connection status updates to `revoked`.

### Task 2: Security Threat Model Verification & Report
- Create `.planning/phases/215-byo-oauth/215-VERIFICATION.md`:
  - **Threat 1: Token Leaks at Rest** → Proves `access_token` and `refresh_token` are encrypted with `enc:v1:` AES-256-GCM.
  - **Threat 2: CSRF / Code Injection** → Proves PKCE `code_challenge` and HMAC `state` nonces are strictly verified.
  - **Threat 3: Token Refresh Race Conditions** → Proves atomic `refresh_claimed_until` lease prevents duplicate refreshes across workers (`WORKER_COUNT=2`).
  - **Threat 4: SSRF on Token Endpoints** → Proves provider endpoints are validated against fixed HTTPS authority lists via `egress.py`.

### Task 3: Vitest Count Gate & Milestone Progress
- Run `node scripts/vitest-count-gate.cjs` to confirm 171/171 pinned files pass with 0 failures.
- Update `.planning/ROADMAP.md` and `.planning/STATE.md` marking Phase 215 complete.
