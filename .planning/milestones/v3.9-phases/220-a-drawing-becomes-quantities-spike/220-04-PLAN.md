# Plan 220-04: End-to-End Integration, Anti-Regression & Spike Closeout

**Phase:** 220 — A Drawing Becomes Quantities — SPIKE  
**Goal:** Run full end-to-end integration tests on the CAD takeoff flow with real sample data, verify all refusal and anti-ambiguity invariants, execute the vitest count gate, and document spike results in `220-VERIFICATION.md`.

---

## 1. Context & Objectives

- **Success Criteria:** `1..6` in `ROADMAP.md` § Phase 220
- **Negative Controls:**
  - Unitless DXF (`$INSUNITS=0`) is refused and never assumed to be millimeters.
  - Ambiguous matches are escalated with candidates and never silently priced by position.
  - Raw line lengths are never counted as wall volumes or areas.
- **Closeout Deliverables:** `220-VERIFICATION.md`, `220-04-SUMMARY.md`, `STATE.md` update.

---

## 2. Implementation Steps

### Step 1: E2E Integration Suite
- Create `backend/tests/integration/test_takeoff_e2e.py`:
  - Upload sample DXF drawing.
  - Upload sample Excel rate sheet.
  - Execute takeoff matching endpoint.
  - Assert that counted blocks, measured dimensions, and priced lines match ground truth.
  - Assert that ambiguous lines are flagged and resolving them updates the final BOQ total.

### Step 2: Negative Control Tests
- Upload a unitless DXF (`$INSUNITS=0`):
  - Verify that extraction reports `"refused: unitless drawing ($INSUNITS=0)"`.
  - Verify no arbitrary millimeter scaling occurs.
- Verify that a multileader text with 2 candidate rate lines returns `status: "ambiguous"` and includes both candidate codes in `candidate_codes`.

### Step 3: Frontend & Backend Count Gate Verification
- Run `pytest backend/tests/unit/test_dxf_takeoff_extractor.py backend/tests/unit/test_takeoff_matcher.py`.
- Run `npx vitest run src/components/metadata/__tests__/TakeoffSection.test.tsx`.
- Run `node scripts/vitest-count-gate.cjs`.

### Step 4: Verification & Milestone Closeout
- Generate `220-VERIFICATION.md` documenting test results, performance, and commercial viability findings for the spike.
- Update `.planning/ROADMAP.md` and `.planning/STATE.md`.
