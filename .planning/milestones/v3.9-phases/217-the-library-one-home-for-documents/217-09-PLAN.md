<objective>
The Library becomes one home with four tabs, driven by one source of selection truth.

Purpose: this is the composition plan. Every leaf it mounts already exists — the reducer (plan 05),
the dropzone (plan 07), the strip (plan 08), the shipped `ViewsGroup` and the shipped
`ReembedStatusCard`. What is new is the shell, and the shell is exactly what the ledger's named seam
for this file warns about: *"the sidebar, the filter bar and the grid are three independent concerns
in one component. **With a tab shell arriving, extract the shell first and let each tab own its body
— otherwise the tab bar becomes the tenth conditional branch.**"* This plan takes that seam.

Output: a four-tab shell, three new tab-body components, six `useState` calls and five handlers
replaced by one reducer, and a suite proving the tab and the list beneath it can never disagree.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| selection state -> list fetch | the reducer's folder/view id parameterises `resolveView` and the document list; it never authorizes |
| saved-view names and folder names -> DOM | server-stored, user-authored strings rendered as tab-body content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-217-32 | Elevation of privilege | a view id or folder id from client state | mitigate | Every list is resolved server-side by the shipped `POST /document-views/resolve*` and `GET /documents`, both owner-scoped under RLS. The client never filters a view itself — that responsibility is recorded in the phase's Architectural Responsibility Map and is unchanged |
| T-217-33 | Spoofing (UX) | tab and list disagreeing | mitigate | Made unrepresentable by the union, and asserted through the DOM from BOTH mounts in task 3. A disagreement is exactly what SC#5 forbids |
| T-217-34 | Information disclosure | the Indexing tab's coverage numbers | accept | `getReembedProgress` is a shipped, owner-scoped endpoint already reachable from Settings; this tab adds no new data path |
| T-217-35 | Tampering | the positional column-shedding rule | mitigate | Preserved byte-identical and asserted by grep; reordering the columns silently sheds the wrong ones, and the rule lives in a file `DocumentList.tsx` does not import |
| T-217-36 | Denial of service | eager per-view count resolution | mitigate | `ViewsGroup`'s counts are lazy and cached (`resolveView(id, {count_only:true})`); the task forbids adding an eager pass, so mounting the Views tab does not fan out one request per saved view |
| T-217-SC | Tampering | npm/pip/cargo installs | mitigate | No package installed by this plan |
</threat_model>
