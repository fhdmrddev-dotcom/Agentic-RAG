## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-217-10 | Elevation of privilege | the service-role client on `/queries` | mitigate | ⭐ **The application-level `.eq("user_id", current_user["id"])` is the SOLE gate** — RLS is bypassed by construction. It is asserted from `mock_builder.eq.call_args_list`, not by reading the code, and a second source fence asserts no user id is read from the request |
| T-217-11 | Information disclosure | cross-user audit rows | mitigate | Same gate. The `document_id` is a selector only; a caller passing another user's document id gets `[]`, because their own audit rows never reference it |
| T-217-12 | Repudiation | reading, not writing | accept | The route is read-only and parameterized; it adds no writer and no audit event of its own. Recorded so the absence is a decision |
| T-217-13 | Denial of service | `.contains` on `audit_log.metadata` with no GIN index | mitigate | Window-bounded to `WINDOW_DAYS = 30` and user-scoped before containment; the named fallback is the shipped fetch-then-filter shape. Assumption A1 is recorded and the shipped arm is reported in the summary |
| T-217-14 | Information disclosure | `query_text` echoed back | accept | It is the caller's own search text, returned only to them. Rendering is the client's job and must escape as text (plan 11 owns that) |
| T-217-SC | Tampering | npm/pip/cargo installs | mitigate | No package installed by this plan |
