Make an AI-drafted workflow publishable without hand-repair, and prove — once, properly — that a
human can reach a published workflow with a declared input.

deliverable is a test written so that seeding it makes it FAIL.

property, and every shared-registry edit this phase owes.

For every `external_action` phase whose `arg_sources[<property>].source == "ask"`, the key is
`spec.ask_key or <property>` — the rule `backend/app/services/connectors/args.py:303` and `:393`
already resolve and refuse with. Each such key not already present in `definition.inputs[]` becomes:

```python
InputFieldSpec(key=<key>, label=<key>, type="text", required=True)
```

⚠ **`label` IS THE KEY, DELIBERATELY.** `InputFieldSpec.label` is a required `str` and a fabricated
friendly name is exactly the invention the launch renderer's two-arm rule refuses. Plan `214.1-01`
Task 3 makes `label == key` read as an ABSENCE downstream, so the launcher renders the key in the
mono face rather than pretending a human wrote prose. ⛔ Do not title-case, humanise or expand it.

⚠ **A RESERVED key is NEVER declared.** If a step asks under `kickoff_prompt` or `folder_id`, the
derivation adds nothing — the server strips those values at run time, so declaring one would mint a
field whose value silently vanishes.
