## Task 2 — the reachability property, and a trap that has a second floor

### ⭐ The 187-24 trap fired on all four fences at once

**First run: 6 failed / 3 passed — and not one of the six was a real finding.** Every fence went
red **against its own positive control**.

Stripping comments (which the file does, with a controlled stripper) is **not enough**. A control
that PLANTS the forbidden shape as a string literal has written that shape into the very file its
fence scans. The fence reports the file guilty and is at that moment **indistinguishable from a
fence catching a genuine regression**.

> **THE RULE THIS FILE NOW OBEYS: a positive control must never SPELL the shape it tests.**

Every planted string is assembled by `spell(...)`, so the pattern exists at runtime and never in
the bytes on disk. The paragraph recording this sits above the fences with an explicit warning not
to "simplify" a `spell()` call back into a literal — that edit will look like noise, will pass the
moment you also delete the fence it broke, and is exactly what re-opens the hole.

⚠ The dispatch note predicted this shape (*"you will write a lot of prose about mocks while
asserting their absence; that is the highest-risk shape for this trap"*). **The prediction was
right and the guard still fired** — which is the argument for driving fences RED rather than
trusting a careful author.

### The three fences, driven RED against real plants

Three defects planted at once (a `vi.mock("@/lib/api/workflows")`, an `inputs: [...]` literal, a
third `KEY_TO_DECLARE` occurrence), then the file restored and verified **md5-identical**
(`9812bebcbf5bf83fdba4787804e1b20b` before and after).

| fence | claim | RED result | control |
|---|---|---|---|
| 0 | the comment stripper actually strips | (control) | sentinel assembled, not spelled |
| 1 | no store / `@/lib/api` mock; **the enumeration IS the claim** | `expected ['@/lib/supabase', …(1)] to deeply equal ['@/lib/supabase']` | 3 planted specifiers, 2 matching `@/lib/api` |
| 2 | no hand-built `inputs` array | `expected true to be false` | planted literal across a **CRLF** break, and the compact spelling |
| 3 | the constant reaches the DOM and **nothing else** | `expected 3 to be 2` | planted assertion counted once; the DOM-read regex misses a source that dropped the read |

Fence 3's strongest half is a **count, not a pattern**: `KEY_TO_DECLARE` occurs in code **exactly
twice** — its declaration and the single `fireEvent.change` that types it into the input. It is
therefore structurally impossible for any assertion to read it, and the wire assertions compare
against `typed`, the value read back off `field.value`.

**All four positive controls stayed green through every red run.**

### ⭐ A measured correction to the plan: the declaration reaches the wire on the CREATE

The plan says to assert on *"the last `PATCH /workflows/{id}`"*. **For a freshly generated draft
the declaration reaches the wire on the CREATE, not on a PATCH.** The walk ran straight into a
shipped rule: `useDraftPersistence`'s matured debounce returns early on
`if (!store.getState().dirty) return`, whose own comment says *"merely OPENING a draft would PATCH
it"*. A generated draft is not dirty, **no row exists at all**, and the first thing that writes
anything is the author's first edit — which here *is* the declare.

The headline case therefore asserts **both**, in order, and neither alone would have been honest:

1. `expect(definitionWrites()).toHaveLength(0)` — no write has happened yet, asserted rather than
   assumed, so a future change that writes on arrival reddens this and forces a re-measure;
2. the **CREATE** body carries `[typed]` — the write that actually happens first;
3. a **second real edit** (the row's `Required` toggle) so a PATCH exists at all, whose body also
   carries `[typed]` — the plan's literal criterion, **reached by causing it**. Asserting (3)
   without causing (3) is how a criterion passes by never running.

`waitForCreate` asserts **exactly one** create, not "at least one": the create branch is guarded
against re-entry precisely because a second would collide on `UNIQUE(slug, version)` and 500, so a
wait that accepted two would be blind to the defect standing beside it.

### ⭐ The non-vacuity control needed its own non-vacuity

*"The same walk with the declare removed"* writes **nothing at all** (see above), so *"no write
carried `inputs`"* would have been true **because there were no writes** — a control that passes
by not existing. The case instead clicks the shipped `Living Register` toggle: a one-click,
non-declare edit that dirties the store and forces the identical write. **A write happens, it
declares nothing, and `is_stateful: true` is asserted on the body** so the write is not an empty
one carrying no `inputs` for the wrong reason. The affordance is asserted present in both cases,
so the difference between them is the DECLARE and never the ARRIVAL.

  `inputs` is derivable from the emitted definition alone; `is_stateful` is not, because nothing
