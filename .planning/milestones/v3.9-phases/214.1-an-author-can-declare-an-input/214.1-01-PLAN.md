The stored shape, which is `InputFieldSpec` narrowed to what this door writes
(`backend/app/models/harness.py:653-660`, MEASURED at HEAD):

```ts
// declaredInputs.ts
export interface DeclaredInput {
  key: string
  label: string
  /** ALWAYS the literal "text". `InputFieldSpec.type` has NO default and the model is
   *  `extra="forbid"`, so it must be written; D-214.1-02 forbids a type SYSTEM, not the field. */
  type: "text"
  required: boolean
}

export type DeclaredInputRefusal = "reserved" | "duplicate" | "empty"

/** null == acceptable. Never throws; the caller renders the reason. */
export function refuseDeclaredInputKey(
  key: string,
  existing: readonly DeclaredInput[],
): DeclaredInputRefusal | null

/** The ask keys this definition's OWN steps name that nothing declares yet. Pure. */
export function undeclaredAskKeys(def: {
  inputs?: unknown
  phases?: unknown
}): string[]
```

The store action, the SIXTH `meta` writer:

```ts
setDeclaredInputs: (inputs: readonly DeclaredInput[]) => void
```

⚠ **`description` IS NOT ON THIS SHAPE AND MUST NOT BE ADDED.** `InputFieldSpec` is `_StrictBase`
(`extra="forbid"`) and declares no such field, and `selectDefinition` spreads `meta` STRAIGHT into
the autosave PATCH body — so a `description` key would 422 the FIRST autosave and destroy the write.
That is a measured correction to D-214.1-02's wording, recorded rather than silently applied.
