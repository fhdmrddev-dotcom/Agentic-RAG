**Client fns to add to `frontend/src/lib/api/library.ts`** (Plan 09 already created this module for
`getIndexSummary()` — extend it rather than creating a second `checked-queries` client module):
`listCheckedQueries()`, `createCheckedQuery({question, expected_document_id})`,
`triggerCheck(id)`, `triggerCheckAll()`, `deleteCheckedQuery(id)` — one call per Plan 16 route.

**Verdict derivation — pure, client-side, from the row's own two fields:**
- `checked_at === null` → `Not checked yet`
- `last_rank === null` (checked but not found) → a distinct "not found" verdict (state your exact word in
  the summary — the sketch's three named verdicts are `Holding`/`Slipped`/`Not checked yet`; a genuine
  "never found" case needs a fourth honest word, not a forced fit into one of the three)
- `previous_rank === null || last_rank <= previous_rank` → `Holding`
- `last_rank > previous_rank` → `Slipped`

**`was 2, now 6` — a rank-change sentence, not a bare pair.** Render as a sentence with the verb the
sketch draws (`was {previous_rank}, now {last_rank}`), never two numbers with no connective text — this
is the same "numerator alone invites the reader to guess" honesty rule the coverage ring and the Folders
table already apply.

**The tile — replaces Plan 12's honest-unknown placeholder with `listCheckedQueries().length` (or a
dedicated count endpoint if Plan 16's summary records one) — same tile position, same `HealthStatBar`
shape, no new component.**

**`Add a check` — a small form:** question (text) + expected document (a searchable picker — reuse an
existing document-select pattern from the codebase, e.g. the folder/document pickers already built in
this phase, rather than inventing a new typeahead). Submits `createCheckedQuery`, then immediately calls
`triggerCheck(id)` so the row has a rank on first render rather than sitting at `Not checked yet`
indefinitely.
