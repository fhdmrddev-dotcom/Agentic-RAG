<objective>
Replace the shipped six stage-count cards with the sketch's four (`Reading · Splitting · Indexing ·
Labelling`) — a fidelity gap, not an invention (D-217.1-07: screen 008 does draw a stage-card row).
D-217.1-26 (operator-ruled, overriding the literal ledger mapping) folds `extracting_tables` and
`extracting_images` into **Indexing**, not Reading — both stages run *after* `embedding` in the measured
write order (`documents.py:2277, 2315, 2326`), so folding them into card 1 would make an in-flight file
visibly jump backwards, exactly the defect `ingestionStages.ts` was written to fix. The monotonic mapping:
`extracting → Reading` · `chunking → Splitting` · `embedding` + `extracting_tables` + `extracting_images`
→ **Indexing** · `metadata → Labelling`. Also promote the shipped `<ul>` queue to the sketch's
`File · Stage · Folder · Size · Actions` table, and build the `History` sub-tab from `useDocuments`'
already-held completed rows.

Purpose: this is the composition Phase 217 never planned — the exact gap SC#1 exists to catch.
Output: a four-card, monotonic pipeline row; a queue table; a working History sub-tab.
</objective>

**The measured write order (do not re-derive — cited from source this session by RESEARCH):**
`extracting → chunking → embedding → extracting_tables → extracting_images → metadata`
(`documents.py:2069, 2249, 2277, 2315, 2326, 2436`).

**The fold — exact, per D-217.1-26:**
| Backend stage | Card |
|---|---|
| `extracting` | Reading |
| `chunking` | Splitting |
| `embedding` | Indexing |
| `extracting_tables` | Indexing |
| `extracting_images` | Indexing |
| `metadata` | Labelling |

**`pipelineGroups.ts` — build on the shipped stage vocabulary, do not re-derive it:**
`components/ingestion/ingestionStages.ts` (217-08) already exports `INGESTION_STAGES`, `stageIndex`, and
`stageTermKey`. The new leaf is a pure fold: `cardForStage(stage: IngestionStage): "reading" | "splitting"
| "indexing" | "labelling"` per the table above, plus a `PIPELINE_CARDS` ordered array
`["reading","splitting","indexing","labelling"]` that the row renders over. ⚠ **`drive.cjs`'s `A5b` sorts
before comparing, so it will not catch a reorder** — the fold's own test must compare **ordered** arrays
(Shared Pattern D note on the pipeline-fold fence).

**The shipped card component, re-shaped not deleted (D-217.1-07):** `IngestionTab.tsx:32-49`'s
`StageCount` is the analog — re-group its inputs over the four-card fold instead of the six raw stages.

**Queue table analog:** `IngestionTab.tsx:82-104`'s shipped `<ul>` queue promotes to a `<table>` with
`thead` columns `File · Stage · Folder · Size · Actions`, following `DocumentList.tsx:345-360`'s
`<thead>`/`<th className="px-4 py-3">` shape for visual consistency (a NEW table, not a `DocumentList`
mount — the Ingestion queue is a subset view, not the full Documents table).

**History — no new fetch, per `IngestionTab`'s own docblock rule ("IT FETCHES NOTHING"):**
`documents.filter(d => d.status === "completed")`, grouped/sorted by date, from the same `useDocuments`
rows the tab already receives as a prop.
