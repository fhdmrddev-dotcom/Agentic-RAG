## Pattern Assignments — the backend six

### BE-1 · `document_chunks.embedded_at timestamptz`

**Migration analog: `supabase/migrations/121_workflow_phases_timings.sql` — copy it structurally,
not just its DDL.** Six things in it are the pattern:

1. `BEGIN; … COMMIT;` — 115's WR-01 finding: without it, two `ADD COLUMN`s each run in their own
   implicit transaction when pasted into the SQL editor.
2. `ADD COLUMN IF NOT EXISTS` — makes a re-paste safe.
3. ⭐ **No `DEFAULT` clause and NULLABLE, and the file says WHY.** *"A `default now()` would backfill
   every existing row at ALTER time in Postgres 11+, destroying D-06's 'time not recorded' arm before
   it ever existed — a backfill by accident is still a backfill."* **This is BE-1's argument verbatim**:
   a pre-migration chunk must read `never`, never a fabricated timestamp.
4. `COMMENT ON COLUMN` naming **every write site by file and line**.
5. A **negative-control migration test** (`test_migration_121.py`) asserting `is_nullable = 'YES'` and
   the **absence** of a default — *"a test that only proves the columns exist cannot tell a
   no-backfill migration from a backfilled one."*
6. An explicit *"no RLS work is owed, and a reviewer will ask, so it is answered here"* section.
   ⚠ **For `document_chunks` that answer must be checked, not assumed** — mig 107 (`ten04_chunk_embedding_org_id`)
   and mig 118's column-by-column grant precedent mean a new column can be **unreadable by default**
   (see MEMORY: *adding a column to `connector_connections` breaks EVERY read of it*).

**The "column written by two paths" analog — and it is FOUR paths here.** The closest single-site
idiom is `skill_embedding_service.py:262-270`, which already writes a timestamp beside the model tag
in the same dict:

```python
{
    "skill_id": s["id"],
    "user_id": user_id,
    "embedding": vec,
    "embedding_model": current,
    "embedding_dimensions": dims,
    "source_text_hash": h,
    "updated_at": _now_iso(),      # ⭐ the shape `embedded_at` takes
}
```

**The four sites `embedded_at` must join, verbatim as they read today:**

| Site | What it writes into |
|---|---|
| `backend/app/api/documents.py:2302-2303` | the main ingest chunk rows (`chunk_rows` → `.insert()`, `:2308`) |
| `backend/app/services/multimodal_service.py:425-426` | **table**-derived chunks (`.insert(chunk_rows)`, `:432`) |
| `backend/app/services/multimodal_service.py:903-904` | **image**-description chunks (`.insert(chunk_rows)`, `:908`) |

### BE-2 · `GET /library/index-summary`

**Aggregate-endpoint analog: `backend/app/api/knowledge_health.py`** — its `_fetch_overview_metrics`
(`:399-530`) is the closest body: several owner-scoped `count="exact"` reads folded into one response

```python
never_query = (supabase.table("documents").select("id", count="exact")
               .eq("user_id", user_id).eq("is_latest", True))
if all_retrieved:
    never_query = never_query.not_.in_("id", list(all_retrieved))
```

**⚠ Does the service-role fence transfer? NO — and this is the load-bearing answer.**

`knowledge_health.py` is service-role **for one specific reason stated in its docstring and repeated
at eight call sites**: `audit_log` has no `authenticated` SELECT policy, so a user-JWT client would
silently read an EMPTY audit set. **`index-summary` reads `document_chunks` and `documents` — both
of which have working RLS.** Carrying a service-role carve-out into a module that does not need one
would widen the classified exception from two modules to three for no reason.

**So the correct analog is the pair 217-02 shipped, not 217-03's carve-out:**

```python
current_user: dict = Depends(get_current_user),
supabase: Client = Depends(get_user_supabase_client),   # RLS-enforced, D-14 eq(user_id) kept
```

wrapped in `aexec` on every query (`backend/app/utils/db.py:47-58`, D-v2.5-01 — 217-PATTERNS
§ *Shared Pattern A*). ⛔ **Do not copy `skill_test_cases.py`'s inline `.execute()`** — that file
states its own exemption (*"ACCEPTED prevailing tech-debt … tracked as SEED-097; do NOT diverge this
one router"*), and a net-new module has no such licence.

⚠ **The provider is DERIVED, not stored.** `document_chunks.embedding_model` exists; the provider
resolves from the model id — the resolver already exists as
`openai_service.resolve_effective_embedding_provider(user_settings)`, called at
`tool_dispatcher.py:724`. **Reuse it. Do not add a `provider` column.**

⚠ **`GET /settings/reembed-progress` sits behind `require_visible("model_management")`

### BE-3 · folder scope on `POST /settings/reembed`

**"Existing endpoint gains an optional scope" analog:** `knowledge_health.py:608-613` — `stale_days`
