# Requirements: Milestone v4.8 Every Page Has a Link

**Defined:** 2026-10-27 (operator intake + research: `.planning/research/SUMMARY.md`)
**Core value:** The agent acts as an AI colleague — it knows your knowledge base, can run code, and can be taught new behaviours (skills) that persist and can be shared.
**Milestone goal:** Every place in the app has its own URL, and a person is told, with a link, when a run is waiting on them.

Seeds folded at intake: SEED-185, SEED-015, SEED-178, SEED-281 (the run-waiting half), SEED-389, SEED-391, SEED-312.
Bugs folded at intake: BUG-261027-01, -02, -03, -04, -05.

Decided at intake (operator, 2026-10-27):
- Library, Workflows, the thread list and run history follow the active org.
- The "waiting on you" badge counts waiting runs in every org the user belongs to, and each item names its org.
- Notification email goes to the run owner for any waiting run that is still waiting after a delay, plus an in-app notice. The sender is app-owned, not a user's connection.
- Open Platform (`SEED-013`) moves to v4.9.

## v4.8 Requirements

### Links (LINK)

- [x] **LINK-01**: Every top-level view has its own `/app/...` address. Opening it directly, refreshing, or pressing Back/Forward lands on that view. — `SEED-185`
- [x] **LINK-02**: A chat thread, a workflow, a workflow run and an Expert each have their own address, and a refresh returns to the same item. — `SEED-178`, `SEED-015`
- [x] **LINK-03**: A user can copy a link to what they are looking at, and opening it in a new tab or on another signed-in machine opens the same item. Existing links keep working: `?run=`, `?connections=1`, `/admin/spend`, `/setup` and `/invite`.
- [x] **LINK-04**: A link to something that does not exist, or that the user may not open, shows one plain "can't be opened" page. The page is the same in both cases and never silently falls back to chat.
- [x] **LINK-05**: A link to an item in another org the user belongs to asks "This is in <org> — switch?" before switching. Nothing is saved under the wrong org.
- [x] **LINK-06**: After signing in by password, SSO or sign-up, the user lands on the link they first opened. The boot screen cannot hang forever. — `SEED-312`
- [x] **LINK-07**: Leaving a page with unsaved edits by Back/Forward asks before discarding them.
- [x] **LINK-08**: Every address works in local dev, on the cloud app domain and on the self-hosted one-box. An automated check fails if the routing layers disagree.

### Active org (ORG)

- [x] **ORG-01**: Library folders show only the active org's items, and switching org refreshes the list. — `SEED-389`
- [x] **ORG-02**: The Workflows list, both published and drafts, shows only the active org's workflows. — `SEED-389`
- [x] **ORG-03**: The chat thread list shows only the active org's threads.
- [x] **ORG-04**: Workflow run history shows only the active org's runs.
- [x] **ORG-05**: Saving or launching a workflow that points at another org's folder is refused with a worded reason. Scheduled runs, API-key runs and chat retrieval keep working as before.
- [x] **ORG-06**: A user who has items in another org sees an honest count of them rather than a silent gap. Items stamped to the wrong org before Phase 296 can be moved one at a time, and each move is audited. The audit is measured before any filter ships.

### Told when a run waits on you (NOTE)

- [x] **NOTE-01**: When a workflow run starts waiting on a person, its owner sees it in an in-app "waiting on you" list and badge. Waiting means a question or an approval, including on scheduled and API-key runs. The list covers every org the owner belongs to, and each item names its org and links to the run. — `SEED-281`
- [x] **NOTE-02**: If the run is still waiting after a delay, the owner gets one email linking to the run. The delay defaults to 2 minutes and is a Settings knob. Answering in time means no email. A restart, a deploy or the second worker never sends it twice. — `SEED-281`
- [x] **NOTE-03**: The email contains no document content: only the workflow name, the org, how long the run has waited, and the link.
- [x] **NOTE-04**: A user can turn notification email off in their own Settings. The in-app notice stays.
- [x] **NOTE-05**: Once the question is answered or the run ends, its notice leaves the list and the badge.
- [x] **NOTE-06**: The app can send email from a built image: through Resend on cloud and through SMTP on the one-box. The secret lives in env and every other knob in Settings. Invite email uses the same sender, and a failed send is visible rather than only logged.

## Future Requirements (deferred)

- An email when a scheduled run fails.

- Public share links for people outside the org.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Approve or answer from inside the email | Mail scanners open links; the decision stays on the signed-in run page |
| Org name or slug in the URL | IDs are globally unique; the server works out the org from the item |
| Auto-approve or auto-continue when nobody answers | A pause nobody was told about must never resolve itself (`SEED-281`) |
| Scroll position, open panels and other UI state in the URL | The URL carries only which view and which item |
| A full notification history centre | The list shows what is waiting now; history can come later |
| Open Platform: public API, MCP server, webhooks (`SEED-013`) | Moved to v4.9; needs this milestone's links first |
