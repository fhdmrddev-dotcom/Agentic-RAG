# Phase 071.3: Code Review Report

**Reviewed:** 2026-05-16T10:47:18Z

## Summary

Phase 071.3 hard-deletes Docling from the runtime, ships camelot as the default PDF table engine (migration 047), retires the PyMuPDF subprocess fence in favor of in-process `import fitz` (D-PRD-07 AGPL OK), and unpins the httpx upper bound. The core rip is well-executed: the per-aspect dispatcher cleanly excludes Docling adapters, the camelot adapter follows the failure-bubble policy (D-071.3-06), migration 047 is idempotent for re-runs, AGPL disclosure remains in `requirements.txt`, and supabase-py + openai + anthropic + langsmith all support httpx >= 0.28 (D-071.3-10 verified by phase context).

**No critical security or correctness defects found.** All findings are documentation / cleanup debris from the rip — most user-visible is a stale Docling-mentioning API doc-string baked into the FastAPI `Query(description=...)` for `/upload` and `/reextract`, which will appear in the live OpenAPI schema and mislead clients (WR-01). A dead env var (`PYMUPDF_TIMEOUT_S`) survives in `.env.example` and `main.py` (WR-02). Migration 047 silently overwrites any pre-existing `app_settings.global` row value for `extraction_table_engine_pdf` (WR-03) — by design but worth a note in the migration header.

Test coverage for camelot is thin but covers the happy path, shape contract, mime guard, and degenerate empty-PDF case. The failure-bubble policy (D-071.3-06) is **not** directly exercised by a test (no "malformed PDF makes camelot raise → composer captures into `table_extraction_error`" assertion); see IN-04.

## Warnings

### WR-01: Stale `docling` / `docling_tf` example in user-facing API `Query` descriptions

**File:** `backend/app/api/documents.py:344-350` (POST `/upload`) and `backend/app/api/documents.py:725-733` (POST `/reextract`)
**Issue:** The `engines` query-parameter `description=` string still suggests `docling` and `docling_tf` as valid engine names. Because FastAPI surfaces `Query(description=...)` text in `/openapi.json` and the auto-generated `/docs` UI, clients reading the live schema will think they can pass `?engines=text:docling,tables:docling_tf,...`. Submitting these will trigger `KeyError` inside `extract_composable`, which the route catches and reports as a 422 (`/reextract`) or marks the doc as `failed` (`/upload`). That mismatch between documented API and runtime is user-facing.

The Phase 071.3 rip notes explicitly call this out as a flag-worthy concern ("any orphan docstring/import/comment").

**Fix:** Replace both `Query(description=...)` strings (and the matching `_parse_engines_hint` docstring example at `documents.py:30`) with the current valid engine names:
```python
# documents.py:344-351 (and equivalent at 725-733)
engines: str | None = Query(
    default=None,
    description=(
        "Phase 071.2 D-071.2-03 — per-call extraction engine override hint. "
        "Format: 'text:<engine>,tables:<engine>,images:<engine>,equations:<engine>'. "
        "Valid engines: text={legacy,pymupdf}, tables={camelot,pdfplumber}, "
        "images={pdfplumber,pymupdf_full,inline_shapes,zip_xpath}, equations={none}. "
        "Subject to app_settings.extraction_per_call_hints_enabled flag."
    ),
),
```
Mirror the registry shipped by `backend/app/services/extractors/aspects/__init__.py` so the doc and the registry can never drift again.

### WR-02: Dead env var `PYMUPDF_TIMEOUT_S` in `.env.example` + main.py comment

**File:** `backend/.env.example:152-155`, `backend/app/main.py:11-14`
**Issue:** Phase 071.3 Phase G retired the PyMuPDF subprocess fence (D-071.3-11). The `PYMUPDF_TIMEOUT_S` env var was the fence's child-process timeout knob and is no longer read anywhere in the codebase (grep confirms: only appearances are these two doc sites). Setting it now is a no-op, and the `.env.example` entry implies a runtime knob that does not exist. `main.py:11-14`'s `load_dotenv` justification cites `PYMUPDF_TIMEOUT_S` as the canonical "env-only knob downstream of pydantic-settings" — that justification no longer holds for this var (though `load_dotenv` is still useful for any other genuine env-only consumer).

**Fix:** Delete lines 152-155 from `backend/.env.example`. Update `backend/app/main.py:11-14` to drop the `PYMUPDF_TIMEOUT_S` mention — either pick a still-valid example (`os.getenv("REDIS_URL")` etc.) or drop the parenthetical:
```python
# pydantic-settings reads backend/.env into the Settings object, but it does NOT
# populate os.environ. Downstream os.getenv() consumers would otherwise never
# see env-only knobs. load_dotenv() fills os.environ from backend/.env regardless
# of CWD. Must run before any module reads os.getenv() at import time.
load_dotenv(Path(__file__).resolve().parent.parent / ".env")
```

### WR-03: Migration 047 silently clobbers any pre-existing `extraction_table_engine_pdf` value on the singleton `global` row

**File:** `supabase/migrations/047_app_settings_table_engine_default.sql:38-40`
**Issue:** Step 6 unconditionally `UPDATE app_settings SET extraction_table_engine_pdf = 'camelot' WHERE id = 'global'`. If an operator has manually flipped the global default to `pdfplumber` (e.g., to bench camelot vs pdfplumber pre-rip, or to dodge camelot's opencv install during local dev), running 047 will silently overwrite that choice with `camelot`. There is no `WHERE extraction_table_engine_pdf NOT IN ('camelot', 'pdfplumber')` guard, and the migration header (lines 18-19) only notes the intent ("so the live system uses the new default immediately") without flagging the destructive-on-prior-override aspect.

This is by design per the phase narrative (camelot is the chosen winner — D-071.3-05) but is worth either a comment or a guard so a future operator reading the migration cold doesn't get surprised. Severity is Warning rather than Critical because (a) the column is a single global-default setting, not user data, and (b) the prior value was `pdfplumber` in 99% of envs (per migration 046's interim flip), which is one of the two valid post-047 values.

**Fix:** Either (a) only force-update rows whose value is the pre-rip `docling_tf` or no longer in the new constraint set, or (b) document the clobber explicitly. Option (a):
```sql
UPDATE public.app_settings
SET extraction_table_engine_pdf = 'camelot'
WHERE id = 'global'
  AND extraction_table_engine_pdf NOT IN ('camelot', 'pdfplumber');
```
This preserves an operator's deliberate `pdfplumber` pick while still healing any rows still on `docling_tf` (belt-and-suspenders alongside step 2's bulk migrate).

### IN-06: `pymupdf_text` silently maps unknown mimes to `filetype="docx"`

**File:** `backend/app/services/extractors/aspects/text.py:56`
**Issue:** `filetype = "pdf" if mime == PDF_MIME else "docx"` — any non-PDF mime (including `text/plain`, `text/html`, garbage) becomes `"docx"`. The composer only calls this for PDF/DOCX so it's currently safe, but the implicit fallback is a future footgun: if a caller bypasses the composer's mime check, fitz will throw a confusing parser error instead of a clear "unsupported mime" message.

**Fix:** Mirror `legacy_text`'s explicit guard:
```python
def pymupdf_text(raw: bytes, mime: str) -> tuple[str, str | None]:
    import fitz  # noqa: PLC0415 — AGPL in-process per D-PRD-07

    if mime == PDF_MIME:
        filetype = "pdf"
    elif mime == DOCX_MIME:
        filetype = "docx"
    else:
        raise ValueError(f"pymupdf_text: unsupported mime {mime!r}")
    doc = fitz.Document(stream=raw, filetype=filetype)
    ...
```
Pulls `DOCX_MIME` from the existing import on line 18.

### IN-07: Camelot failure-bubble policy (D-071.3-06) is not directly tested

**File:** `backend/tests/unit/test_aspect_engines_tables.py`
**Issue:** The phase context emphasized verifying camelot's "failure-bubble" contract (D-071.3-06): on internal camelot crash, the exception bubbles to `extract_composable`, which captures it in `table_extraction_error` (no silent swallow, no fallback). Current tests cover happy-path shape, mime guard, and the empty-PDF degenerate case (which does **not** raise — camelot treats stray text as a 1x1 table). Nothing exercises the "camelot raises → composer catches" path.

**Fix:** Add one test that patches camelot to raise and asserts the exception bubbles out of `camelot_tables` (not swallowed inside) and is captured by `extract_composable`:
```python
def test_camelot_tables_does_not_swallow_internal_errors(monkeypatch):
    """D-071.3-06: camelot internal exceptions bubble to extract_composable,
    they are NOT caught inside the adapter."""
    from app.services.extractors.aspects.tables import camelot_tables

    def boom(*a, **kw):
        raise RuntimeError("camelot internal failure")

    monkeypatch.setattr("camelot.read_pdf", boom)
    with pytest.raises(RuntimeError, match="camelot internal failure"):
        camelot_tables(b"%PDF-fake", PDF_MIME)


def test_extract_composable_captures_camelot_failure_in_error_field(monkeypatch):
    """Companion: composer's try/except around tables turns the bubbled
    exception into table_extraction_error (does NOT raise)."""
    from app.services.extractors import aspects
    from app.services.extraction_service import extract_composable, PDF_MIME

    monkeypatch.setitem(aspects.TEXT_ENGINES, "legacy", lambda r, m: ("t", None))
    monkeypatch.setitem(aspects.TABLE_ENGINES, "camelot",
                        lambda r, m: (_ for _ in ()).throw(RuntimeError("boom")))
    monkeypatch.setitem(aspects.IMAGE_ENGINES_PDF, "pymupdf_full", lambda r: [])
    monkeypatch.setitem(aspects.EQUATION_ENGINES, "none", lambda r, m: [])

    out = extract_composable(b"%PDF", PDF_MIME, engines={
        "text": "legacy", "tables": "camelot",
        "images": "pymupdf_full", "equations": "none",
    })
    assert out.tables == ()
    assert "boom" in (out.table_extraction_error or "")
```
