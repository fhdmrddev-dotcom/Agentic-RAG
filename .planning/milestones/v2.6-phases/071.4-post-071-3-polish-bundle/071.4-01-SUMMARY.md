# Phase 071.4 Plan 01: Camelot row/col precision floor — SEED-022 partial close, 4.4x reduction

**A 4-line precision floor in `camelot_tables` rejects shape-degenerate regions (< 2 rows or < 2 columns). On the operator's thesis PDF, this cut stored tables from 214 → 48 — a 4.4x reduction, matching DOCX ground truth ±23%.**

## Accomplishments

1. **Row/col floor in `camelot_tables`** (`backend/app/services/extractors/aspects/tables.py`). Inside the table loop, reject any `Table` with `len(df) < 2 OR len(df.columns) < 2`. Increments a `rejected` counter and logs `camelot_tables: precision floor rejected N of M candidate regions` at info level when at least one rejection happens.

2. **3 new unit tests + 1 updated test** in `tests/unit/test_aspect_engines_tables.py`:
   - `test_camelot_tables_precision_floor_rejects_single_row` — mocks camelot to return a 1×3 fake Table, asserts empty output
   - `test_camelot_tables_precision_floor_rejects_single_col` — mocks 8×1 fake Table, asserts empty output
   - `test_camelot_tables_precision_floor_accepts_2x2_minimum` — mocks 2×2, asserts output has 1 TableData with 2 headers + 1 data row
   - `test_camelot_tables_empty_pdf_returns_empty` (UPDATED) — was previously "either empty or 1×1"; now asserts strict empty (the 1×1 degenerate case is rejected by the floor)

3. **Confirmed mitigation magnitude on operator's thesis** (recorded in SEED-022):

   | | Pre-floor | Post-floor (verified) | Reduction |
   |---|---|---|---|
   | PDF tables | 214 | **48** | **4.4x** (78%) |
   | DOCX tables (no floor, reference) | 39 | 39 | — |
   | Overcount vs DOCX ground truth | +175 (5.5x) | **+9 (1.23x)** | **95% closed** |

   The floor caught **most** of camelot's false positives — they were predominantly shape-degenerate (header bands without data, aligned bulleted lists). Only ~9 false positives remain with ≥2×2 shape (likely formula blocks or multi-row aligned paragraphs). Whether the full SEED-022 content-density audit is still worth running before Phase 076 is now an open question (downgraded from "must address" to "nice-to-have").

## Decisions Made

- **Shape-degenerate filter over content-density filter.** Shape (len(df) < 2 or len(df.columns) < 2) is unambiguous — a real table cannot have fewer rows or columns than 2. Content density (text length, header heuristics, figure-bbox overlap) is heuristic-y and could reject real tables with terse content. Shape-only is the lowest-risk first pass. The remaining ~9 false positives can be addressed by content-density if needed; that's SEED-022's deferred audit scope.
- **Floor uses `len(df)`, not `len(df.index)`.** Equivalent for the current DataFrame shape but slightly clearer to read. Documented in the inline comment.
- **No bbox-area filter.** The bench (Plan 01) used a `bbox-area ≥ 25 px²` filter per D-071.3-17. That's already enforced in the bench script, but the production `camelot_tables` adapter currently does NOT filter on bbox area. Considered adding it as part of the floor but deferred — bbox-area thresholds are camera/scan-dependent and adding it without operator validation could lose real small tables. Left for SEED-022's full audit.
