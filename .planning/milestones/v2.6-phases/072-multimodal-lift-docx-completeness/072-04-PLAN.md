Close Gap 2 from `.planning/phases/072-multimodal-lift-docx-completeness/072-VERIFICATION.md`: the
`/reextract?retry_empty_descriptions_only=true` retry helper at
`backend/app/api/documents.py:732+` returns 202 but refills 0 of N empty rows on
production documents because it imports the legacy pre-dispatcher extractors
(`extract_pdf_images`, `extract_docx_images`) from `multimodal_service.py`. These
legacy functions don't match what the active per-aspect dispatcher engines
(`pymupdf_full_images_pdf`, `zip_xpath_docx`) actually populate into
`document_images`. On operator's thesis DOCX (58 floating-shape images, 0
`python-docx inline_shapes`), the helper's `extract_docx_images` returns `[]` →
no UPDATEs → 0/58 refill.

The fix: route through `extract_composable(raw, mime_type, engines={"images":
configured_engine})` using the app_settings engine name, then convert returned
`ImageData` dataclasses to the dict shape the existing composite-key matcher
expects. Keep the matcher logic intact — the bug is the data feeding it, not
the matcher.

The mandatory companion fix: a NON-mocked integration test that asserts UPDATE
side-effects against real supabase-py + real PostgREST + the real dispatcher.
Plan 03's `test_reextract_retry_empty_descriptions_only_branch` mocks
supabase-py and never exercised either the PostgREST layer (Gap 1 root cause)
or the dispatcher call chain (Gap 2 root cause). This plan ships the missing
test as part of the fix.

Purpose: make `/reextract?retry_empty_descriptions_only=true` actually do its
job on dispatcher-era documents (i.e., all current production documents) so
RAG-MM-LIFT-01's cheap-retry half is satisfied (currently PARTIAL per
072-VERIFICATION.md).
