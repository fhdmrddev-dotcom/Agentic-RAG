<objective>
Land the cache substrate + cold-render fix that closes the in-app blank window (BUG-260513-01, original symptom) and gives F5 refresh a pre-painted cache. Three concentric pieces:

1. **localStorage cache layer** — A `streamsCache.ts` helper (read sync, write throttled, LRU evict, quota-exceeded fallback) plus a 15-LOC `throttle.ts` (DIY trailing-edge with `.flush()`). The cache mirrors `bucketsBySurface: Map<SurfaceId, Map<string, Message[]>>` 1:1; the on-disk shape is a single packed JSON blob under `agentic-rag.streams.v1`.

2. **Synchronous hydrate in the Zustand store factory** — Replace the `bucketsBySurface: new Map()` literal at `streamsStore.ts:76` with `bucketsBySurface: readSnapshotSyncOrEmpty()`. This is THE Pitfall 1 / Pitfall 8 closure: without it, the first paint shows the empty Map and the skeleton flashes for one frame, which fails SC#5's <100ms cached-paint gate. Add a new `reconcileError: null` slot for Plan 2's retry banner consumer.

3. **Cold-render fix + skeleton placeholder** — DELETE the unconditional `clearMessages()` call at `ChatArea.tsx:134` (RESEARCH §Finding #5 — branch (a) chosen; bucket survival is structurally safe per Phase 067.3 per-thread keying). Add a `<MessageSkeleton/>` component that renders inside `MessageList` when `messages.length === 0` (D-068.5-11). This handles the genuinely-cold-load case (never-opened thread + no localStorage entry) without re-introducing the blank window.

Also: add a `useEffect #4` inside `StreamsProvider` that wires a Zustand `subscribe(state => state.bucketsBySurface, throttled-write)` for ~500ms trailing-edge persistence, plus a `.flush()` call from inside the `setViewingThread` action body (D-068.5-03 immediate-flush-on-thread-switch). The throttle instance is hoisted to a ref so the action body can call `.flush()` synchronously without re-creating the throttle on every render.

From `frontend/src/lib/throttle.ts` (NEW):
```typescript
export function makeThrottle<T extends (...args: never[]) => void>(
  fn: T,
  waitMs: number,
): T & { flush: () => void }
```
- Trailing-edge: fires at most once per `waitMs` window; if called multiple times in the window, only the LAST args fire on the trailing-edge.
- `.flush()`: cancels pending timer + invokes immediately with the last-captured args.
- No leading-edge fire. No max-wait. No this-binding (Zustand subscribers don't need it).

    ```typescript
    /**
     * Phase 068.5: Trailing-edge throttle with explicit `.flush()` method.
     *
     * Used by <StreamsProvider> (D-068.5-03) to batch writes to localStorage
     * during streaming (~500ms cadence) while still guaranteeing a clean
     * snapshot at terminal events + on thread switch via `.flush()`.
     *
     * No leading-edge fire (would cause N writes per stream burst, defeating
     * the batch). No max-wait (the trailing window is bounded by waitMs).
     * No this-binding (Zustand subscribers don't need it).
     *
     * Canonical reference: 068.5-RESEARCH.md §Pattern 2 lines 304-340.
     */
    export function makeThrottle<T extends (...args: never[]) => void>(
      fn: T,
      waitMs: number,
    ): T & { flush: () => void } {
      let timer: ReturnType<typeof setTimeout> | null = null
      let lastArgs: Parameters<T> | null = null
      const invoke = () => {
        timer = null
        if (lastArgs) {
          fn(...lastArgs)
          lastArgs = null
        }
      }
      const throttled = ((...args: Parameters<T>) => {
        lastArgs = args
        if (timer === null) {
          timer = setTimeout(invoke, waitMs)
        }
      }) as T & { flush: () => void }
      throttled.flush = () => {
        if (timer !== null) {
          clearTimeout(timer)
          invoke()
        }
      }
      return throttled
    }
    ```
