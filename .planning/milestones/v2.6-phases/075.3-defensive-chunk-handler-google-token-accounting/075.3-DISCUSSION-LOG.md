## Accumulator strategy + handler shape

### Q1: How should we lock the Google accumulator strategy?

| Option | Description | Selected |
|---|---|---|
| Live repro probe first | Run a one-shot script, log `chunk[i].usage` raw, pin cumulative-vs-delta from real numbers | ✓ |
| Doc-research only | Researcher reads Google OpenAI-compat docs + community sources | |
| Both — probe + doc cross-check | Probe AND docs; pin only if they agree | |
| Default to overwrite-last-wins | Lock cumulative now based on community consensus + add a fail-loud unit test | |

**User's choice:** Live repro probe first.
**Notes:** Risk of guessing wrong = silently corrupted `runs.input_tokens` / `runs.output_tokens` in DB for every Google run. The captured-chunk evidence from quick-task 260522-gdg showed `has_usage=True` on both content chunks but did not capture the numeric usage values, so cumulative-vs-delta is unproven. Probe ≈5 min + 1 API call.

### Q2: How should `_on_chunk_openai` branch on provider?

| Option | Description | Selected |
|---|---|---|
| Explicit provider arg | Pass `provider` into the closure; `if provider == 'google':` branch | ✓ |
| Shape-detect at runtime | If `chunk.usage` AND `chunk.choices[0].delta.content` are both populated → treat as cumulative shape | |
| Hybrid: provider branch + shape-assert | Explicit branch plus a guard that warns if `+=` path sees content+usage together | |

**User's choice:** Explicit provider arg.
**Notes:** Vibe-coder readability priority. Provider already in scope at line ~1781 via `get_model_capability(_model_id).get("provider")`; one-line extraction.

## Warning-log noisiness

### Q1: How often should the `model_capability_unknown` warning fire?

| Option | Description | Selected |
|---|---|---|
| Once per process per model_id | Module-level `set[str]` dedup; reset on worker restart | ✓ |
| Once per request (via contextvar) | Reset dedup per HTTP request | |
| Every call | Simplest; one log line per `get_model_capability` invocation | |

**User's choice:** Once per process per model_id.
**Notes:** `get_model_capability` is called 3+ times per agent iteration (resolve_max_tokens + resolve_calling_mode + get_per_call_timeout). For a 4-iteration run on an unregistered model that's ~12 lines per request without dedup. Module-level set keeps the log clean — one row per session per unknown model.

## Settings UI badge placement

### Q1: Where should the "unverified — using safe defaults" badge surface?

| Option | Description | Selected |
|---|---|---|
| Inline next to each item in dropdown | Chip rendered in select options + mirrored next to currently-selected label | ✓ |
| Banner under dropdown after selection | Sub-text banner appears only after picking the unregistered model | |

**Notes:** User wants to see status BEFORE saving the change, not after. Banner-after-selection is a "surprise" UX; tooltip-on-hover requires user discovery.
