<objective>
Close the "user added a new model from Settings UI → silent failure" loop
by replacing the `{"provider": "unknown"}` sentinel in `get_model_capability`
with pattern-based provider inference + safe defaults + visible UI signal.

**Three sub-deltas, all wave-orderable:**

1. **Backend inference + warn-once** (Wave 1): `backend/app/config.py` gets
   an ordered `_INFERENCE_PATTERNS` table (5 regex/provider tuples), a
   `_build_inferred_defaults(model_id, provider)` helper with safe-default
   constants per provider, a module-level `_WARNED_UNKNOWN_MODEL_IDS: set[str]`
   dedup, and a rewritten `get_model_capability` that returns either a
   verified registry entry (`capability_source="registry"`) OR an inferred
   dict (`capability_source="inferred"`). Existing consumer at
   `threads.py:1164` is updated to check `capability_source == "registry"`
   instead of the `provider != "unknown"` sentinel — preserves D-067.3-N01-02
   active-provider fallback for unregistered model_ids with no recognizable
   prefix.

2. **Backend settings payload + frontend type** (Wave 2): The settings
   `GET /api/settings` response (`FullSettingsResponse` in
   `backend/app/api/settings.py`) gains two new fields:
   - `verified_models: list[str]` = `sorted(MODEL_CAPABILITIES.keys())`
     (Shape A per RESEARCH.md §6, locked at planner-time).
   - `inferred_provider_for: dict[str, str]` = mapping of each
     non-verified model in the user's configured model list to its inferred
     provider (so the frontend tooltip can render `{provider}` without
     mirroring the inference table).

   `frontend/src/lib/api.ts` `FullAppSettings` interface gains both fields.

3. **Frontend badge + UAT** (Waves 3-4): `SettingsPage.tsx` renders an
   amber "unverified" chip inline next to each unregistered model in the
   main LLM dropdown pill row AND next to the currently-selected `llmModel`
   label. Vitest component test (`SettingsModelBadge.test.tsx`) covers 6
   render-matrix rows. Chrome MCP UAT adds `gemini-99-flash` via Settings
   and confirms: chip visible inline + chip visible on selected-label +
   content streams on prompt "hi" + `model_capability_unknown` log line
   appears exactly once (warn-once dedup).

**Purpose:** Today, if the user types a model_id not literally in
`MODEL_CAPABILITIES` (e.g., the `gemini-3-future-flash` Google ships next

shows a chip so the user knows they're on inferred caps.

**Output:** Inference fallback + safe-default table + warn-once dedup +

+ Chrome MCP negative-test UAT.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings UI → backend `model_id` | User-typed strings flow into `re.search(pattern, model_id)` AND into `logger.warning("... %s ...", model_id, ...)`. Patterns are anchored; logging is parameterized. |
| Backend → frontend settings payload | `inferred_provider_for` dict carries user-typed model_ids back as JSON keys + lowercase provider strings as values. No HTML; React JSX auto-escapes. |
| Module-level `_WARNED_UNKNOWN_MODEL_IDS` | Mutated on every `_build_inferred_defaults` call. Single-uvicorn-worker rule (D-v2.5-02) means no cross-process race; multi-worker would emit N warnings per model_id (accepted per Assumption A5). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

Acceptance test: `test_redos_safe` runs each pattern against a 10KB pathological input string and asserts <100ms wall time. |
| T-075.3-02-02 | Tampering / Repudiation | Log injection via unsanitized `model_id` in `model_capability_unknown` warning | LOW | mitigate | `logger.warning("... model_id=%s ...", model_id, provider)` uses parameterized logging (NOT f-string), so newlines / control chars in `model_id` get escaped by the formatter. Acceptance test: `test_log_no_injection_newline` passes `"evil\\n[ADMIN] fake-log"` and asserts `caplog.records[0].getMessage()` contains the literal newline-escape representation, not an actual new log entry. |

        "openai": 8192, "anthropic": 8192, "google": 8192,
