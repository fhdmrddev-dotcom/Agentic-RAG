## Decisions Made

- **Multi-line `lambda:` form for threadpool wraps** rather than collapsing into a single line. The plan's Task 0 NOTE anticipated this: "If implementation chooses pure inline-lambda style, the lambda body's `.execute()` line will NOT contain `run_in_threadpool` — adjust the test to look back N lines." Multi-line preserves the existing fluent-chain shape; the grep test was widened to a 4-line look-back window (see deviations below).
- **`engine_used: str = body.engine` initialization** at the top of the extract block, mutated to `"pymupdf-fallback"` only after the PyMuPDF path is taken. This single mutable variable threads cleanly into `background_tasks.add_task` and is the canonical contract for Pitfall 3.
- **PARTIAL_SUCCESS detection placed inside `try/except` block** that imports `ConversionStatus` lazily — never block extract on a status check (RESEARCH.md Pitfall recommendation).
- **`_write_extraction_run_row` lives at module scope, not inside `reextract_document`** — keeps it grep-able for future fallback-path additions and consistent with the `extract_text` helper's placement.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Threadpool grep test false positives on multi-line `lambda:` form**
- **Found during:** Task 1 GREEN verification
- **Issue:** The grep regex written in Task 0 RED only checked the same line for `run_in_threadpool`. When the implementation chose the multi-line form (`await run_in_threadpool(\n    lambda: supabase...execute()\n)`), the `lambda:` line failed the check because `run_in_threadpool` was on the line above. This was a test-side bug, not a production-code bug — the production code was correctly wrapped.
- **Fix:** Expanded grep window to look back 4 preceding non-blank lines for `run_in_threadpool`. This is the exact mitigation the plan's Task 0 NOTE anticipated.
- **Files modified:** backend/tests/unit/test_071_1_threadpool_sweep.py
- **Verification:** Test now passes; if a genuinely unwrapped call is added, it will still fire (any line with `supabase.table(...).execute()` AND no `run_in_threadpool` within 4 preceding lines triggers the offender list).
- **Committed in:** 3675db6 (Task 1 commit — alongside the production code changes the test was scaffolded for)
