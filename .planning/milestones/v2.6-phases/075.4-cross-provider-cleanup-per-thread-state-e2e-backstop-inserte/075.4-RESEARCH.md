BUT if any field has an in-flight controlled-input value that's stale (e.g., `api_key` is "" because the user just typed and React hasn't flushed yet), the server sees the stale value, persists empty, returns empty, and hydrate sets it back to empty. On second click the value is now flushed and saves correctly.

**Diagnostic approach per D-075.4-F3**: use Chrome DevTools MCP to:
1. Navigate to Settings, expand a provider, type a new api_key (don't blur).
2. Click Save — observe network panel for the request body's `api_key` value.
3. If empty/stale on first click but populated on second → confirmed.

KEY_PLACEHOLDER triggers the skip-on-save in `save_override` → no write. Next render the UI still shows empty → user clicks again → typed value (now in state) goes through.

**Diagnostic confirmation**: the empty-string-to-KEY_PLACEHOLDER coercion is correct (don't overwrite existing key with empty) but masks the issue. The narrow fix is to trim and validate input state BEFORE building the body, and surface to user that an empty field means "keep existing." Or: stop coercing empty→KEY_PLACEHOLDER in the JS side; let backend handle empty as no-op.

### LangSmith API for trace polling

`runs.langsmith_run_id` is populated by the LangSmith client (verified in `backend/app/services/anthropic_service.py:143` decorator + `openai_service.py` wrap). To poll a trace:

```bash
curl -H "X-API-Key: $LANGSMITH_API_KEY" \
     "https://api.smith.langchain.com/runs/$run_id"
```

Returns 200 with full run JSON when trace exists, 404 when not yet ingested (LangSmith has ~1-5s ingest delay). The Playwright fixture should:
1. Capture `run_id` from the SSE terminal event.
2. Poll the LangSmith API with exponential backoff (1s, 2s, 4s, max 5 attempts = 8s ceiling).
3. Assert `trace.run_type === "llm"`, `len(trace.child_runs) >= 1`, `trace.metadata.provider === <expected>`.
