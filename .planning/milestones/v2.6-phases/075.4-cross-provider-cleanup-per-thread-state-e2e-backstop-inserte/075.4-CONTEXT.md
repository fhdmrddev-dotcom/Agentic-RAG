<decisions>
## Implementation Decisions

### A. Per-thread state shape & cache migration (Plan 01)

- **D-075.4-A1:** Per-thread state shape is `Map<threadId, Set<runId>>` (nested). Easy GC when thread closes; fast `hasAnyForThread()` selector; matches the way 067.5 buckets are keyed at `streamsStore.ts:44`. Applied to all 5 globals (`isStreaming`→`streamingThreads:Set<threadId>`, `loadingThreadId`→`loadingThreads:Set<threadId>`, `reconcileError`→`reconcileErrors:Map<threadId, Error>`, `fallbackNotice`→`fallbackNotices:Map<threadId, string>`, `subscriptionsByRunId`→`subscriptionsByThread:Map<threadId, Set<runId>>`).
- **D-075.4-A2:** No localStorage migration needed. `streamsCache` (Phase 068.5) persists ONLY `bucketsBySurface` (messages); the 5 refactored globals are transient/runtime-only. Cache shape unchanged → no version bump, no cold-paint impact at deploy. Verified in `frontend/src/lib/streamsCache.ts:130-165` (reader returns `Map<SurfaceId, Map<string, Message[]>>` — no global keys).
- **D-075.4-A3:** Plan 01 ships the explicit 067.5 empty-thread-until-refresh regression test (so Phase 082 inherits coverage per FORWARD-REF #5).

### B. Unknown-provider error semantics (Plan 02)

- **D-075.4-B1:** Explicit error fires at startup (lifespan), NOT lazily at first request. Backend refuses to boot if `llm_provider` resolves to an unknown name. Fails loud and early; deterministic across multi-worker (per FORWARD-REF #1 — each worker would crash identically).
- **D-075.4-B2:** `ollama` STAYS as a registered provider (real Module-1 feature, not silent default). Move from the special-case `if provider == "ollama"` branch into the registry with a dynamic resolver for `ollama_base_url`. Unknown providers hit the new explicit-error path.
- **D-075.4-B3:** Error type is a custom **`UnknownProviderError(ValueError)`** with structured attributes (`provider: str`, `known_providers: list[str]`) and a `__str__` that lists registered providers + points at the registry file. Catchable + introspectable; Phase 082.5 retrofits to unified error sink + trace_id (FORWARD-REF #6 hook).

### C. Gemini 3 `thought_signature` lifecycle (Plan 02)

- **D-075.4-C1:** Signature lives in an **in-memory closure variable** in `send_message` (same pattern as `full_content` / `persisted_tool_calls` / Plan 03's content-hash dedup dict / Phase 073 token accumulators). Per-run, dies with the run, no schema change. Single-worker safe per D-v2.5-02; Phase 079 multi-worker unaffected because a run never crosses workers (D-v2.5-08).
- **D-075.4-C2:** Capture in `_on_chunk_openai` per-tool-call slot, **gated on `active_provider == "google"`** (mirrors Phase 075.3 `chunk.usage` provider-aware accumulator at `threads.py:1806-1816`).
- **D-075.4-C3:** Echo in `_reconstruct_history` at `threads.py:1106-1109` (already on Plan 02's sweep list). Provider-gated branch adds `thought_signature` to the serialized tool_call shape on rebuild when `active_provider == "google"`. Matches Anthropic's `thinking_block` echo idiom.

### D. Content-hash output dedup (Plan 03)

- **D-075.4-D1:** Hash algorithm is **SHA-256** (existing project convention — used for `documents.content_hash`). Stdlib, collision-free at any scale; ~5 MB/s on a single CPU is ample (4 MB pptx hashes in <1s).
- **D-075.4-D2:** Dedup structure is `dict[content_hash, {filename, url, size, iteration}]` (overwrite-last-wins on hash collision). Hash is the canonical identity. If iteration N produces a different hash for the same filename, emit a delta event flagged `supersedes: <prev_filename>` — feeds Plan 04's "supersedes previous" UI affordance. If iteration N produces same hash with different filename, no-op (same file).
- **D-075.4-D3:** Deploy strategy = graceful empty dict on first iteration after restart. `_previous_files_in_run` is a per-run closure (`threads.py:1630`); in-flight runs at deploy time are cancelled by the run-buffer mechanism. New runs start with empty `dict[content_hash, …]`. Worst case: a MID-FLIGHT run double-emits one file on resume — acceptable. No Redis-backed persistence (overkill for an in-run-only need).

### E. User-visible warnings (Plan 03)

- **D-075.4-E1:** Sub-agent truncation warning surfaces as a **system-role message appended to the assistant turn** (`role: "system"`, `kind: "context_truncated"`). MessageList renders inline as a small neutral banner above the assistant reply. Persists as a real `messages` row (survives reload). Easy retrofit point for Phase 082.5's unified error sink (the structured `kind` field is the hook).
- **D-075.4-E2:** Iteration-cap silent-drop guard surfaces as an **inline warning at end of assistant reply** + `dropped_tool_calls` count in backend chunk-handler log. Wording: "⚠ Reached iteration limit — didn't run the last N tools the model requested." Closes the trust gap from the audit.
- **D-075.4-E3:** BUG-260522-01 fix = pass actual iteration counter into the fallback message string (one-line; currently hardcodes `max_iterations=15` regardless of actual count).
- **FORWARD-REF #6:** All three warnings ship as lightweight inline patterns. Phase 082.5 retrofits to unified error sink + trace_id. **Do NOT build a sophisticated error system here.**

### F. `save_override` sentinel guard + 2-click bug (Plan 04)

- **D-075.4-F1:** Sentinel guard uses an **allowlist by provider prefix** for api_key fields: OpenAI=`sk-`, Anthropic=`sk-ant-`, OpenRouter=`sk-or-`, Google=length-only minimum, ollama=accepts any non-sentinel non-empty string. Any value that doesn't match (sentinel strings like `"***"`, `"__KEEP__"`, masked-dots `"••••••"`, empty/whitespace) is rejected. Strongest guard; closes WR-02 because the 075.3 orchestrator data-loss case was "submitted a partially-masked value that didn't match any provider format". Existing `KEY_PLACEHOLDER == "***"` skip stays; new allowlist layer wraps it.
- **D-075.4-F2:** Rejection mode = **skip silently + WARNING log** (preserves existing 'don't overwrite the working key on disk' semantic). Add `logger.warning("rejected api_key write — sentinel/invalid format detected for provider=%s", provider)`. No HTTP 422 (that's Phase 081.1's API-level rejection territory). Defensive-only.
- **D-075.4-F3:** 2-click bug = **diagnose first, fix narrowly.** Use Chrome DevTools MCP + React DevTools to capture the failing render cycle; identify the actual stale closure / `useEffect` dep at `frontend/src/pages/SettingsPage.tsx:586-620` (`handleSaveAIModel`). Fix the smallest code path. If diagnosis reveals a structural problem, document as deferred to 081.1.
- **FORWARD-REF #4 + #5:** Sentinel guard + 2-click fix are interim — Phase 081.1 replaces `save_override` entirely. Plan 04's defensive logic MUST be portable to 081.1's new codepath. Document in plan.

### G. E2E backstop infrastructure (Plan 05)

- **D-075.4-G1:** Test user = **reuse `fhdmrd@gmail.com / 123456`** (existing dev login, what Chrome MCP already uses, local Supabase only). Document credential in Playwright fixture loaded from env. E2E extracts run_id from SSE terminal event, then polls `https://api.smith.langchain.com/runs/{id}` (requires `LANGSMITH_API_KEY` in CI env). Each scenario asserts trace exists, has ≥1 LLM span, matches provider. Closes the Anthropic-untraced gap from Plan 03 with measurable evidence.
