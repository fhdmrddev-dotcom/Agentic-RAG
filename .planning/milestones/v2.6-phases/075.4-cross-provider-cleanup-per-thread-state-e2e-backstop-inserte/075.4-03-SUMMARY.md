- **Terminal-status race (T-075.4-04) eliminated** via two surgical edits: (a) inline `_emit('done')` removed from the agent-loop-end region; (b) `_shielded_finalize` step order swapped so `finalize_run` UPDATE lands BEFORE `_emit_terminal` sentinel emit. SSE consumers now see `done` only AFTER the DB commit, closing the ~tens-of-ms race window that surfaced as "Saving response..." flash post-checkmark and snapshot polling racing the UPDATE.

- **Content-hash output dedup with supersedes** (PATTERNS.md §S5) — `harvest_output_files` pivoted from set-of-filenames to dict-keyed-by-SHA-256-hash. Three closures:
  - Identical bytes across iterations → skip (closes BUG-260523-03 OpenRouter duplicate output rendering).
  - Same filename + different bytes → delta carries `supersedes: <prev_filename>` (Plan 04 OutputFileCard "Replaces:" affordance).
  - Final emit projects `filename + url + size` from per-hash meta — naturally closes BUG-260522-02 (no url in payload) and auto-closes BUG-260521-02 (pinned panel no download link) per its `re_open_trigger`.

- **Iteration-cap silent-drop guard (T-075.4-05)** — at iteration-end when `force_no_tools AND tool_calls_buffer`: emit `system_warning kind='iteration_cap_dropped_tool_calls'` + structured log `iteration_cap_dropped_tool_calls run=%s iteration=%d dropped=%d tool_names=%s` + clear buffer (belt-and-suspenders skip exec). Trust-erosion class closed.

- **Sub-agent / iteration trim warning (D-075.4-E1)** — iteration-level `trim_messages_to_fit` now wrapped with pre/post len comparison; emits `system_warning kind='context_truncated'` when post < pre AND appends to `_persisted_system_warnings` for finalize-time persistence. New `_persist_system_messages` helper drains the list into `messages` rows during `_shielded_finalize`. Persistence is fail-silent (try/except + WARNING log) until migration 048 widens `messages_role_check`.

- **BUG-260522-01 one-liner** — empty-response fallback now reads `{iteration + 1} iteration(s)` (loop variable in scope) instead of misleading `{max_iterations} iterations`.

- **Anthropic LangSmith @traceable re-verified** — Step 1 langsmith package resolves (`inspect.getsourcefile` points to `langsmith/run_helpers.py`, NOT the fallback stub). ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 4 / mitigated as Rule 3 - Schema-vs-Plan conflict] Migration 048 shipped to unblock D-075.4-E1 persistence**

- **Found during:** Task 2 planning (sub-agent truncation warn persistence path).
- **Issue:** The plan (lines 337) said "INSERT each system_warning as a separate `messages` row via the existing supabase client (pattern: same INSERT shape as assistant rows but with `role='system'`)". But `messages_role_check` CHECK constraint at `supabase/full-schema.sql:418` limits `role` to `('user', 'assistant')` — INSERT with `role='system'` would crash at runtime. The plan also explicitly claimed "No schema change" in the objective.
- **Fix:** Two-pronged: (a) ship `supabase/migrations/048_messages_allow_system_role.sql` widening the CHECK constraint (idempotent DROP+ADD); (b) wrap the INSERT call in try/except + `logger.warning(...)` so pre-migration runs are fail-silent (SSE event already shipped = user-visible signal preserved). Documented in `key-decisions` + this section.
- **Files modified:** `supabase/migrations/048_messages_allow_system_role.sql` (created); `backend/app/api/threads.py` `_persist_system_messages` helper.
- **Verification:** Migration content reviewed against schema; helper code paths exercised in test (skip the actual DB write under mock; assert closure-var declaration + helper presence via grep).
- **Committed in:** `85269e1` (Task 2 commit).
- **Operator action required:** Apply migration 048 via Supabase Studio SQL editor per CLAUDE.md rule (never `db push`/`db reset`). Without this, `_persist_system_messages` logs `system_warning persist failed (kind=...) — migration 048 may be unapplied: ...` and the warnings remain SSE-only (no reload survival).
