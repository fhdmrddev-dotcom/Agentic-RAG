## Title / Subtitle / Counter Strategy (executor discretion area)

Per UI-SPEC §8.2 "Plan 02 owns final wording," the executor selected:

- **Title:** `outerBannerLabel(activeTool, hasTools, isPlanning)` — returns tool-specific phrasing during active tool runs ("Running code…", "Searching knowledge base…", etc.), "Thinking…" while planning, "Synthesizing answer…" between tools, "Setting up agent…" pre-first-delta. Sourced from existing `frontend/src/lib/toolMeta.ts` so copy stays consistent with the rest of the chat surface.
- **Subtitle:** `Step {iterationCount + 1}` in `text-xs font-mono text-muted-foreground` — sketched as `model_id · turn N · step M of total` in live-run-container.md D-HTML but that shape requires data not on the Message type today; using step-only keeps the contract clean and reuses the iteration_count SSE event Phase 56 D-03 already populates.
- **Counter chip:** folded into the title — `outerBannerLabel` already encodes the current step verb. A separate `.counter` chip would duplicate phrasing. Plan 03 can split if Chrome MCP UAT surfaces alignment gaps with the sketch.

## `expanded` State Behavior (executor discretion area)

Per PLAN.md action note: Plan 02 ships `useState(() => true)` (always-expanded body). Plan 03 will land the lazy initializer flip to `!shouldAutoCollapse` (auto-collapse on terminal+tools) AND the collapsed-row JSX + the streaming→terminal transition effect together. Rationale: shipping `!shouldAutoCollapse` alone would leave terminal+tools turns with only the sticky header visible (no body, no collapsed row to click) — broken UX. Both code paths land at the same end state after Plan 03.
