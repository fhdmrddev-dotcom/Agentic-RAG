```tsx
interface StatusPillProps {
  status: "preparing" | "running" | "done" | "interrupted" | "failed"

  runningLabel?: string // overrides "running" default (e.g., "searching", "executing")
```

### Task 5: `Next: ...` footer

**File:** `frontend/src/components/chat/RunCard.tsx` (or ToolCallPanel.tsx — RunCard is cleaner since it owns the run-level frame)

When `runStatus === "streaming"` AND there's a current narration / planning hint OR last tool is `done` AND agent hasn't terminated, render at the bottom of the run-body:

```tsx
<div className="next-up flex items-center gap-2 px-3 py-2 mt-2 border border-dashed border-border rounded-md text-xs font-mono text-muted-foreground">
  <span className="uppercase tracking-wider opacity-60">Next</span>
  <span className="flex-1 truncate">{nextHint || "deciding next step…"}</span>
  <span className="opacity-50">queued</span>
</div>
```

Source for `nextHint`: derive from `message.isPlanning` text OR fall back to a generic "deciding next step…" placeholder.

**Acceptance:** Chrome MCP on a multi-step run shows the footer mid-stream between tool completions.

### Task 6: Compact dim 💭 thinking row

**File:** `frontend/src/components/chat/ToolCallPanel.tsx` or `RunCard.tsx`

### Task 7: Editor inset for `execute_code` (highest-impact, depends on syntax library)

**Library decision:** **Shiki** (vscode-quality syntax via Oniguruma WASM; ~150KB total, async-loaded once). Alternative: **highlight.js** (~50KB sync). Defaulting to Shiki — operator can override before execute.

**File:** `frontend/src/components/chat/tool-bodies/ExecuteCodeBody.tsx`

Replace lines ~158-176 (the current "Python badge + italic description" block) with:

```tsx
{tc.args.code && (
  <div className="tc-editor grid grid-cols-[32px_1fr] bg-[#0d1117] max-h-[180px] overflow-y-auto rounded-md mt-2 border border-border">
    <div className="tc-gutter bg-[hsl(220_30%_7%)] text-muted-foreground/60 font-mono text-[11px] text-right py-2 pr-1.5 border-r border-border select-none">
      {tc.args.code.split("\n").map((_, i) => <div key={i}>{i+1}</div>)}
    </div>
    <ShikiCode language="python" theme="github-dark" code={tc.args.code} />
  </div>
)}
```

`<ShikiCode>` is a thin wrapper — lazy-loads `shiki/bundle/web` on first mount, caches the highlighter, renders highlighted HTML. ~30 lines.

Plus add a Python lang chip near the existing header per sketch (already exists in current `ExecuteCodeBody` — verify).

**Acceptance:** Chrome MCP on `execute_code` turn shows numbered gutter + syntax-highlighted code + lang chip; Lighthouse passes on the run page (no large layout shift from async highlighter load).
