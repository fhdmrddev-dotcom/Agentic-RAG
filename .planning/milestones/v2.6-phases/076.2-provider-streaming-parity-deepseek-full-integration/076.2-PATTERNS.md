### `backend/app/services/google_service.py` (service, streaming) — Skills Investigation

**Tool conversion pipeline** (lines 292-314):
```python
def _convert_tools_to_google(tools: list[dict]) -> list[types.Tool]:
    declarations: list[dict] = []
    for tool in tools or []:
        fn = tool.get("function") or {}
        name = fn.get("name", "")
        description = fn.get("description", "") or ""
        raw_parameters = fn.get("parameters") or {"type": "object", "properties": {}}
        parameters = _sanitize_schema_for_google(raw_parameters)
        if not name:
            continue
        declarations.append({
            "name": name,
            "description": description,
            "parameters": parameters,
        })
    if not declarations:
        return []
    return [types.Tool(function_declarations=declarations)]
```

**Pattern note:** Research Finding 6 confirms this pipeline is correct in code. BUG-260524-01 investigation should add debug logging here (log the declarations count + names) to verify tools reach the Google API. If tools are present, the issue is behavioral (Gemini model choice), not code-level.

## Shared Patterns

### SSE Event Lifecycle (Backend to Frontend)

**Source:** `backend/app/api/threads.py` line 115 (`_emit`) + `frontend/src/lib/api.ts` lines 388-467 (dispatch) + `frontend/src/providers/StreamsProvider.tsx` lines 241-307 (callbacks)

**Apply to:** All new SSE event types (reasoning_delta)

The full lifecycle for adding a new SSE event type:

1. **Backend emit:** `await _emit(redis, run_id, 'event_type', field=value)` (threads.py)
2. **Frontend dispatch:** `else if (t === "event_type" && callbacks.onEventType) callbacks.onEventType(parsed.field as Type)` (api.ts)
3. **Callback type:** Add `onEventType?: (field: Type) => void` to `StreamCallbacks` interface (api.ts)
4. **State reducer:** Add handler in `makeStreamCallbacks` that calls `setMessages(prev => prev.map(...))` (StreamsProvider.tsx)

### Conditional Spread for Optional Fields

**Source:** `backend/app/api/threads.py` lines 1154, 1161, 1168

**Apply to:** All places where `reasoning_content` is added to message dicts

```python
**({"reasoning_content": full_reasoning_content} if full_reasoning_content else {}),
```

This pattern is used consistently across `_reconstruct_history` and the in-memory message assembly. It prevents sending `reasoning_content: ""` or `reasoning_content: None` to providers that don't expect the field.

### Accumulator Reset Between Iterations

**Source:** `backend/app/api/threads.py` lines 2339, 2447 (`full_content = ""`)

**Apply to:** `full_reasoning_content` accumulator

The agent loop resets `full_content` after consuming it (either as prose-before-tools or as the terminal text). `full_reasoning_content` must follow the same pattern to prevent cross-iteration concatenation.
