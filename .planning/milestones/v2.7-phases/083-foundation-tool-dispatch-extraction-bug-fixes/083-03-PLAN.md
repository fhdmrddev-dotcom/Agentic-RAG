Modify the `_on_chunk_openai` function in `backend/app/api/threads.py` (per D-06):

The Kimi/Moonshot API sends thinking/reasoning content wrapped in `<think>...</think>` tags inside `delta.content`, NOT in a separate `delta.reasoning_content` field like DeepSeek. The current code at line 2220-2222 blindly accumulates all `delta.content` into `full_content` and emits it as a visible `delta` SSE event.

Replace the `if delta.content:` block (lines 2220-2222) with a provider-gated filter:

```python
if delta.content:
    _content = delta.content
    # BUG-260526-02 (D-06): Kimi/Moonshot thinking content filter.
    # Kimi wraps chain-of-thought reasoning inside <think>...</think>
    # tags in delta.content (unlike DeepSeek which uses a separate
    # reasoning_content field). Strip thinking tags from visible
    # content and route to reasoning_content instead.
    #
    # State machine approach: track whether we're inside a <think>
    # block using a nonlocal flag. Content inside tags goes to
    # full_reasoning_content; content outside goes to full_content.
    if active_provider_name in ("moonshot", "deepseek"):
        _visible = ""
        _reasoning = ""
        _remaining = _content
        while _remaining:
            if _in_think_block:
                # Look for closing </think> tag
                end_idx = _remaining.find("</think>")
                if end_idx != -1:
                    _reasoning += _remaining[:end_idx]
                    _remaining = _remaining[end_idx + len("</think>"):]
                    _in_think_block = False
                else:
                    # Still inside think block, consume all
                    _reasoning += _remaining
                    _remaining = ""
            else:
                # Look for opening <think> tag
                start_idx = _remaining.find("<think>")
                if start_idx != -1:
                    _visible += _remaining[:start_idx]
                    _remaining = _remaining[start_idx + len("<think>"):]
                    _in_think_block = True
                else:
                    # No think tag, all visible
                    _visible += _remaining
                    _remaining = ""
        if _reasoning:
            full_reasoning_content += _reasoning
            await _emit(redis, run_id, 'reasoning_delta', content=_reasoning)
        if _visible:
            full_content += _visible
            await _emit(redis, run_id, 'delta', content=_visible)
    else:
        full_content += _content
        await _emit(redis, run_id, 'delta', content=_content)
```

Also add the `_in_think_block` state variable. In the `_on_chunk_openai` closure, before the first chunk processing (near the `nonlocal full_content, full_reasoning_content` line), add:

This state-machine approach handles streaming correctly: `<think>` tags may span multiple chunks (e.g., chunk 1: "some text<thi", chunk 2: "nk>reasoning...", chunk 3: "...</think>visible"). Wait -- actually, since the `<think>` tag itself may be split across chunks, a simpler approach is better:

**Simpler approach (preferred):** Accumulate content across chunks and do tag stripping post-hoc. But this loses streaming granularity. Since Kimi's thinking blocks come at the START of a response before visible content, and thinking content should go to `full_reasoning_content` for the collapsible thinking panel, the state machine is correct.

**Edge case handling:** If a `<think>` tag is split across chunk boundaries (e.g., "<thi" in one chunk, "nk>" in next), the simple `find("<think>")` will miss it. To handle this robustly:

Use a buffer approach: accumulate a small tail buffer (last 7 chars, length of `<think>`) from the previous chunk. Prepend to current chunk's _remaining before processing. After processing, save last 7 chars as the new tail buffer. This handles split tags.

However, in practice Kimi sends tags as atomic tokens (the tokenizer outputs `<think>` as a single token), so split tags are extremely unlikely. Use the simple approach first and document the edge case.

**IMPORTANT:** Include `"deepseek"` in the provider gate along with `"moonshot"`. DeepSeek's thinking content currently works via the separate `reasoning_content` field (line 2225-2228), but some DeepSeek models (especially via OpenRouter) may also use `<think>` tags in content. Including deepseek in the gate provides defense-in-depth. The existing `reasoning_content` handler at lines 2224-2228 remains unchanged and catches DeepSeek's native field.
