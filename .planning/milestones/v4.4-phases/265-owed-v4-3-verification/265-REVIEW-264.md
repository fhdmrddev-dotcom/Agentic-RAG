## What I checked and found sound

- **HEAD assertion:** the worktree was bootstrapped and `git rev-parse HEAD` = `ca33dd9bb5ecc3e5babc2be92d761028f6b5f881`. `git status --porcelain` was clean after every plant.
- **Targeted suites green at base:** the four `test_264_*` files plus `test_seed125_skill_visibility_filter.py` → `74 passed`. With the four 260/261 scoping suites added → `99 passed`. I checked each file for DB access (asyncpg/create_client/integration markers) before running it and found none.
- **Plants that correctly went RED, so these guards can fail:**
  - A: the resolver ignores the `born_for` flag → 2 failed (non-opting caller, save_skill base predicate).
  - B: the `row_bundle is not None` guard is dropped → 1 failed (`test_each_none_guard_is_load_bearing_for_a_DIFFERENT_input`).
  - C: the born-for `is_enabled` term is dropped in the Python encoding → 1 failed (the dual-encoding table row `same_org_private_DISABLED_row_born_for_this_bundle`).
  - F: the sub_ctx propagation is set to None → 1 failed.
  - I: the load_skill miss branch uses a different filter → 4 failed.
  - J: save_skill opts in → 2 failed (the call-site count fence and the save_skill base-predicate fence).
- **Predicate structure:** the born-for term is nested inside the inner `or(...)` under `org_id.in.(...)`, never at the top level. An empty org set returns the bare `is_system.eq.true` before the bundle is looked at. The bundle is UUID-validated with `coerce_uid` before being spliced in, so the service-role query can't be string-injected through it.
- **Access check upstream:** `_resolve_thread_scoping` returns the bundle id only after `resolve_expert_bundle` succeeds (org check plus grant check). A failed resolve raises (fail-closed) and never returns a partial tuple.
- **Per-site decisions:** three sites opt in (load_skill, read_skill_file, execute_code injection). `save_skill`'s sibling filter keeps the base predicate, and the code comment beside it says why. load_skill's miss branch reuses the same `_skill_filter`.
- **Stamp scope (263 code, read for context):** the stamp is limited to the saver's own rows, in the saver's org, where the column is still NULL. So the born-for widening can't pull another author's skill in.
