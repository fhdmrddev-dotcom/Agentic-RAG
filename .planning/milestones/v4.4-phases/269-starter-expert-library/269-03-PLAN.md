## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user JWT + X-Org-Id -> /experts, /threads | the active org selects which install folder a run may read |
| restricted Expert scope -> retrieval | the Expert must read only its own install folder, even with a sibling corpus in the same org |
| agent -> web_search (Tavily) | a web answer can masquerade as a corpus answer or a refusal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-269-09 | Information disclosure | restricted scope across sibling corpora | mitigate | each refusal turn's search.query document_ids are joined to documents.folder_id; any sibling-folder document is a FAIL |
| T-269-10 | Information disclosure | cross-tenant read | mitigate | every joined document and chunk must carry org_id == the test org; audit_log.org_id is never used as evidence |
| T-269-11 | Repudiation | evidence honesty | mitigate | fixed questions before driving; one attempt; VERDICT lines written from SQL checks; helper + secrets kept out of the repo |
| T-269-12 | Spoofing | web-sourced answers | mitigate | web_search_calls counted from messages.tool_calls on every cited and refusal turn; any call -> FAIL |
| T-269-13 | Elevation of privilege | tier write | accept | the tier UPDATE is a LOCAL-only data step recorded as the named D-269-P1 operator step; prod tiers remain an approval-gated operator write (269-PROD-PARITY in 269-05) |
</threat_model>
