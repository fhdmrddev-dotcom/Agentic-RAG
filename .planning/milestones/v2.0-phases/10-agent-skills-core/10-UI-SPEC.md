# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope Note

Phase 10 is a **backend-infrastructure phase**. Its deliverables are: Supabase DB migration (skills table, skill_files table), Row-Level Security policies, FastAPI `/skills` router, and the `skill-files` Supabase Storage bucket.

There is **no new UI surface** in Phase 10. The dedicated Skills UI (skills tab, CRUD forms, file upload) ships in Phase 12.

This contract exists to:
1. Lock the design system state so Phase 12 inherits correct tokens without re-research.
2. Define the minimal interaction contract for any Phase 11 / Phase 12 surfaces that consume the Phase 10 API.
3. Establish copywriting and color conventions for skill-related UI elements before implementation begins.

Source of truth for Phase 10 visual design: the existing "Aether Intelligence" theme already in production at `frontend/src/index.css`.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact element spacing, button icon gap |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, form group gaps |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Touch targets for icon-only buttons: minimum 44px height (accessibility requirement)

Legacy frozen values (existing Sidebar and thread list components only — do not replicate in any new component work):
- `w-0.5` (2px) — active indicator stripe on selected sidebar items: inherited v1.0 pattern in `Sidebar.tsx`, frozen in place. Not authorized for new components.
- `py-1.5` (6px) — thread list item vertical padding: inherited v1.0 pattern in `Sidebar.tsx`, frozen in place. Not authorized for new components.

Note: New elements in Phases 11–15 must use 4px multiples only. The `w-0.5` and `py-1.5` frozen-legacy exemption is scoped exclusively to the existing production Sidebar and thread list components — it does not extend to any new component built in these phases.

Source: existing spacing patterns in `frontend/src/components/layout/Sidebar.tsx` and `frontend/src/components/ingestion/FolderDetail.tsx`.

## Typography

Maximum 4 sizes, 2 weights.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Label / meta / overline | 12px (text-xs) | 400 (regular) | 1.4 | Inter |
| Body | 14px (text-sm) | 400 (regular) | 1.5 | Inter |
| Heading / section label | 16px (text-base) | 600 (semibold) | 1.3 | Manrope (font-headline) |
| Display / card title | 20px (text-xl) | 600 (semibold) | 1.2 | Manrope (font-headline) |

Notes:
- Overline section dividers (e.g. "Recent", skill section dividers): use the 12px label/meta row with `tracking-widest uppercase` utility classes — no separate size needed.
- Code/instructions textarea: `font-mono text-sm` (JetBrains Mono, 14px, weight 400) — uses the body size row with `font-mono` applied, no bespoke 0.8rem value.
- Font-weight 700 (bold) is not used. 600 (semibold) is the maximum weight throughout, including display/card titles.

Source: existing patterns across `frontend/src/components/`.

## Color

| Role | CSS Variable | Light Value | Dark Value | Usage |
|------|-------------|-------------|------------|-------|
| Dominant (60%) | `--background` | hsl(220 20% 97%) | hsl(216 45% 4%) | Page background, main content area |
| Secondary (30%) | `--card` / `--sidebar` | hsl(0 0% 100%) / hsl(220 15% 95%) | hsl(220 30% 7%) / hsl(220 40% 5%) | Cards, sidebar, skill list panel |
| Accent (10%) | `--primary` | hsl(239 84% 67%) | hsl(239 100% 82%) | Reserved-for list below |
| Destructive | `--destructive` | hsl(0 84% 60%) | hsl(0 72% 51%) | Delete skill, remove file — destructive only |
| Success | `--success` | hsl(142 71% 45%) | hsl(142 71% 45%) | Enabled skill indicator, file upload success |
| Muted surface | `--muted` | hsl(220 14% 94%) | hsl(220 30% 11%) | Skill card backgrounds, disabled states |

Accent (`--primary`) reserved for:
- Global skill badge (`bg-primary/10 text-primary`) — matching existing Globe badge pattern
- Enabled toggle active state
- Active sidebar nav item text (`text-primary font-medium`)
- Primary action button background (`gradient-primary` for create/save CTA)
- Focus ring (`ring-primary/30`)
- Skill name link hover underline
- Selected skill card left border stripe (`border-l-[4px] border-primary`)

Accent is NOT used for: disabled skills, file size labels, dates, metadata labels, secondary buttons.

Source: `frontend/src/index.css` CSS variables; `frontend/src/components/layout/Sidebar.tsx` active nav pattern; `frontend/src/components/ingestion/FolderDetail.tsx` Global badge pattern.

## Interaction Contract for Skills UI Surfaces

These contracts are defined now (Phase 10) so Phase 12 can implement without ambiguity.

### Skill Card (future Phase 12)

| State | Visual Treatment |
|-------|----------------|
| Default | `bg-card border border-border/30 rounded-lg p-4` |
| Hover | `hover:border-border/60 hover:bg-accent/20 transition-all duration-150` |
| Disabled | `opacity-50` on skill name + description; toggle shows off state |
| Global badge | `inline-flex items-center gap-1 text-xs px-2 py-0.5 rounded-full bg-primary/10 text-primary font-medium` — exact pattern from FolderDetail Globe badge |
| Selected / active | `border-l-[4px] border-primary` — 4px left border using the standard 4px spacing token; do not use `w-0.5` (frozen legacy, Sidebar only) |

### Enabled / Disabled Toggle

- Use shadcn `Switch` component
- Enabled state: `--primary` fill
- Disabled state: `--muted` fill
- Label: "Enabled" / "Disabled" at `text-xs text-muted-foreground` to the right of the switch
- Touch target: minimum 44px height wrapper

### Skill Instructions Field

- Use shadcn `Textarea` component
- Minimum height: 120px (resize-y)
- Font: `font-mono text-sm` (JetBrains Mono, 14px) — instructions are code-adjacent content
- Placeholder: "Describe what this skill does and how the agent should use it..."

### File Attachment Row

| State | Visual |
|-------|--------|
| File listed | `flex items-center gap-2 px-3 py-2 rounded-md bg-muted/40 text-sm` |
| Filename | `text-foreground font-medium truncate` |
| File size | `text-xs text-muted-foreground ml-auto` |
| Delete button | Lucide `Trash2` icon, `h-3.5 w-3.5 text-muted-foreground hover:text-destructive transition-colors`, `aria-label="Remove file"` |
| Upload button | Variant `outline`, size `sm`, Lucide `Paperclip` icon |

### Destructive Confirmation Pattern

Matches existing thread delete pattern (inline dropdown, no modal):
- Inline confirmation in dropdown: first click shows "Delete Skill" in destructive color; inline re-confirm with "Are you sure?" text is shown in the same dropdown
- No modal dialog for single-skill delete
- Confirm button label: "Delete Skill" (destructive variant)
- File delete: direct action (no confirmation) — files can be re-uploaded; match existing document list delete pattern
