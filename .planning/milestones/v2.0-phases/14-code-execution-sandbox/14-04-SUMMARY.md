# Phase 14 Plan 04: Output File Harvesting Summary

**harvest_output_files() copies Docker container output to Supabase Storage sandbox-outputs bucket, inserts sandbox_files rows, and returns signed download URLs — enabling users to retrieve files generated by their code**

## Accomplishments
- harvest_output_files() function implemented in sandbox_service.py
- Copies /sandbox/output/ from container to local tempdir via session.copy_from_runtime
- Uploads each file to Supabase Storage sandbox-outputs bucket at user_id/execution_id/filename
- Inserts sandbox_files DB row per file (execution_id, user_id, filename, storage_path, file_size)
- Generates signed download URL (3600s expiry) per file
- Returns [] gracefully when output directory empty or copy raises any exception
- 10 unit tests all passing (3 new harvest tests + 7 existing session manager tests)

## Decisions Made
- harvest_output_files is a module-level function, not a SandboxSessionManager method — keeps it cleanly callable from execute_code handler without needing the manager instance
- os.walk used rather than direct listdir — copy_from_runtime may mirror container subdirectory structure so recursive traversal is safer
- signedURL key checked with fallback to signedUrl — defensive against Supabase Python SDK version differences in response key casing
