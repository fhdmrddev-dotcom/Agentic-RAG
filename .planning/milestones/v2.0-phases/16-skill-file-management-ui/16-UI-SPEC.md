## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline badge padding |
| sm | 8px | Compact element spacing (`gap-2`), button icon gaps |
| md | 16px | Default element spacing (`gap-4`), dialog section gaps |
| lg | 24px | Section padding (`gap-6`), dialog vertical rhythm |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- File row vertical padding: 4px top + 4px bottom (`py-1`) — compact list rows to keep dialog height manageable
- Label-to-input gap: 8px (`gap-2`) — replaces the pre-existing `gap-1.5` (6px) pattern in SkillFormDialog; 6px is not a multiple of 4 and is not introduced by this phase, but this phase standardises it to the nearest grid value
- Dialog container: `sm:max-w-lg` — matches existing dialog, no change

Source: established pattern in `SkillFormDialog.tsx` (`gap-4`, `py-2`)

## Typography

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 | Inter |
| Label | 14px (`text-sm`) | 500 medium (`font-medium`) | 1.4 | Inter |
| File name | 12px (`text-xs`) | 400 regular | 1.4 | Inter |
| File metadata (size, muted) | 12px (`text-xs`) | 400 regular | 1.4 | Inter |

Rules:
- Section label "Attached Files" uses `text-sm font-medium text-foreground` — same as Name/Description/Instructions labels in the dialog.
- File row names use `text-xs text-foreground`. File size uses `text-xs text-muted-foreground`.
- Error messages use `text-xs text-destructive` (file errors) or `text-sm text-destructive` (save error in footer).
- No display/headline font used in this phase — all content is within a dialog, not a page heading context.

Source: direct inspection of `SkillFormDialog.tsx` field label pattern; `SkillCard.tsx` badge/muted text pattern

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` — light: `hsl(220 20% 97%)`, dark: `hsl(216 45% 4%)` | Page background, dialog backdrop |
| Secondary (30%) | `hsl(var(--card))` / `hsl(var(--muted))` | Dialog surface, file row background (`bg-muted`), section dividers |
| Accent (10%) | `hsl(var(--primary))` — `hsl(239 84% 67%)` light / `hsl(239 100% 82%)` dark | "Attach File" button active state (Loader2 spinner color via primary), FileText icon color on file rows |
| Destructive | `hsl(var(--destructive))` — `hsl(0 84% 60%)` | Delete file button hover (`hover:text-destructive`), upload/delete error text |

Accent reserved for:
- The Loader2 spinner shown on the "Attach File" button during upload (spinner inherits text color which is primary when button is in active loading state)
- FileText icon on each file row (`text-muted-foreground` at rest, NOT primary — file icons are informational, not interactive)
- No other elements in the file section use primary — the Attach button uses `variant="ghost"` which does not apply primary color to text

Secondary color (`bg-muted`) reserved for:
- Individual file row container background (`bg-muted rounded px-2 py-1`)
- Section separator between Instructions and Attached Files (implicit via gap; no explicit rule needed)

Source: `index.css` CSS variable definitions; SkillCard ghost-border and muted usage patterns

## Interaction States

### "Attach File" Button
| State | Visual |
|-------|--------|
| Rest | Ghost button, `text-xs`, `gap-1`, Paperclip icon `h-3 w-3`, label "Attach File" |
| Uploading | Loader2 `h-3 w-3 animate-spin`, label "Uploading...", `disabled={true}` |
| Upload complete | Returns to rest state; new file appears appended to file list |
| Upload error | Returns to rest state; error message appears below file list in `text-xs text-destructive` |

### Delete File Button (per row)
| State | Visual |
|-------|--------|
| Rest | Ghost icon button `h-5 w-5`, Trash2 `h-3 w-3`, color inherits (`text-muted-foreground` via parent), `aria-label="Delete file"` |
| Hover | `hover:text-destructive` |
| In-flight | No spinner — delete is fast; optimistic removal is immediate |
| Delete error | Error message appears below file list in `text-xs text-destructive` |

Accessibility: The Trash2 button is icon-only. It must carry `aria-label="Delete file"` on the `<Button>` element so screen readers announce the action. No visible tooltip is required — the icon is in direct context of a file row.

### File Row
| State | Visual |
|-------|--------|
| Normal | `flex items-center justify-between text-xs bg-muted rounded px-2 py-1` |
| Owner view | Shows FileText icon + filename + size + Trash2 delete button |
| Non-owner view | Shows FileText icon + filename + size only (Trash2 hidden) |

### File Section Visibility
| Condition | Behavior |
|-----------|----------|
| Dialog in "New Skill" mode (`isEdit === false`) | File section is NOT rendered. User must save the skill first. |
| Dialog in "Edit Skill" mode (`isEdit === true`, skill prop is non-null) | File section IS rendered. Files loaded on dialog open. |

### Empty File List
| Condition | Visual |
|-----------|--------|
| `files.length === 0` and loaded | `<p className="text-xs text-muted-foreground">No files attached.</p>` |
| Loading in progress (initial fetch) | No explicit skeleton — dialog already has loading gates at parent level; file list initializes to `[]` and populates immediately |

## Copywriting Contract

| Element | Copy |
|---------|------|
| File section label | Attached Files |
| Primary CTA — attach | Attach File |
| Primary CTA — uploading | Uploading... |
| Empty state (no files) | No files attached. |
| Upload error — generic | Upload failed. Try again. |
| Upload error — from backend | Propagate backend detail message verbatim (e.g. "File too large. Maximum size is 10 MB.") |
| Delete error | Failed to delete file. Try again. |
| File load error | Failed to load files. Close and reopen to retry. |
| Attach File tooltip | Not required — button has visible text label |
| Delete file tooltip | Not required — icon is in context of file row; Trash2 is universally understood; `aria-label` handles screen reader requirement |
| Delete file confirmation | None — file delete is immediate with inline error fallback (no confirmation dialog). Files are recoverable by re-uploading. |
| Dialog title (edit mode) | Edit Skill (unchanged from Phase 12) |
| Save button (edit mode) | Update Skill (unchanged from Phase 12) |
| Discard button | Discard Changes (unchanged from Phase 12) |

Destructive actions in this phase:
- **Delete file:** Immediate on click. No confirmation dialog. Rationale: files are low-stakes attachments re-uploadable at any time. Inline error message on failure is sufficient recovery path. This matches the project's existing pattern for low-consequence deletes at item level (file rows, not skills themselves).
- **Delete skill** (existing, Phase 12): Confirmation inline on card — unchanged.

Source: SkillCard.tsx confirmation pattern used as reference; RESEARCH.md recommendation for no confirmation on file delete

## Phase-Specific Constraints

1. **No new shadcn components may be installed.** All required UI primitives are already present. The shadcn Windows CLI pitfall (creates files in literal `@/` directory) still applies if installation is ever attempted — but it is not needed for this phase.

2. **No new npm dependencies.** File upload uses browser-native `File` API + `FormData`. File size formatting uses an inline `formatBytes` helper — no library.

3. **`uploadSkillFile` must use `getAuthToken()` not `getAuthHeaders()`.** Setting `Content-Type: application/json` on a FormData request corrupts the multipart boundary. This is a documented pitfall from Phase 13.

4. **File section rendered only in edit mode.** The backend `POST /skills/{skill_id}/files` requires a valid skill_id. New skills have no ID until after the create POST completes.

5. **`currentUserId` prop required on SkillFormDialog.** The dialog currently has no user ID. It must receive `currentUserId: string` from `SkillsPage` (which gets `user` from `useAuth`) to gate the Attach/Delete controls.

6. **Optimistic state only — no re-fetch after mutation.** On upload success: append returned `SkillFile` to local `files` state. On delete success: filter deleted ID from local `files` state. No re-fetch from backend needed.

7. **Reset `fileInputRef.current.value = ""` in `finally` block.** Prevents the browser from blocking re-selection of the same filename. Pattern established in `SkillsPage.tsx` line 64.
