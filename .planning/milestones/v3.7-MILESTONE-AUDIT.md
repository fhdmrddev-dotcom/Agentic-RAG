## 1. Executive Summary

Milestone **v3.7** addressed 14 user-reported operational friction points and seeds from prior UAT. Across 17 phases and 147 plans, the workflow product was transformed into a cohesive, production-grade authoring and execution system:

1. **Discovery & Identity (Phases 192, 192.1, 192.2):** High-density search, tag filtering, row lineage discrimination (`Yours` vs `Shared`), relative update time bands, and live run status/outcome badges (`runFacts`).
2. **Authoring Doors & Templates (Phases 193, 193.1, 193.2, 196, 197):** Template-first authoring with durable binding at creation time, dynamic model picker sourced from live registry, and interactive guided decision prompts (`useTemplateFirstDraft`).
3. **Observability, Deliverables & Run Surface (Phases 194, 194.1, 195, 199, 200, 200.1, 200.2):** Real-time cancellation control (`StopControl`), per-step execution timers and item counts, deliverable text/file cards, adaptive hero (`RunHero`), distinct per-step output/citations list (`RunStepList`), and lazy citations endpoint.
4. **Node Vocabulary & Human-in-the-Loop (Phases 198, 200.3):** Structured human approval node (`llm_human_input`) with golden run bypass for publishing, interactive pause during production runs, and direct draft test-running (`▶ Test Run`) from Workflow Studio.

### What the two refutations do and do not mean

**The 63 backend failures are NOT a regression.** They group as `test_retrieval_service` (13),
`test_sql_service` (12), `test_sandbox_service` (3), `test_streaming_reliability` (1) — the known
rot set, and **not one of them is inside any v3.7 phase's blast radius**. The phase-scoped suites
pass clean: `test_publish_service.py` + `test_198_node_vocabulary.py` + `test_200_2_citations.py`
+ `test_tabular_text_extraction.py` = **110 passed, 0 failed**. So the milestone verdict survives;
what does not survive is the sentence *"zero regressions"* being backed by a run that never
executed the suites that could have shown one.

**The typecheck refutation found a REAL DEFECT that §2 and `200.3-VERIFICATION.md` both scored as
satisfied.** Of the 35 errors, 34 are pre-existing; the 35th was new, in Phase 200.3's own file:

```
src/pages/WorkflowBuilderPage.tsx(1238,23): error TS2339:
  Property 'dirty' does not exist on type 'DraftPersistence'.
```

`handleTestRun` flushed behind `if (persistence.dirty)`. That member does not exist — `dirty`
lives on the STORE (`store.getState().dirty`) — so the read was `undefined`, the guard was
permanently false, and **the flush never ran**: ▶ Test Run launched the last SAVED definition while
the canvas showed newer work. `200.3-VERIFICATION.md` marks observable truth #6 (*"flushes draft
saves"*) and the `handleTestRun → saveNow()` wiring row as **✓ VERIFIED / ✓ WIRED**. Neither of that
phase's two behavioural tests asserts the flush, so nothing but the typecheck could see it — and
the typecheck that ran was the one that checks no files.

Fixed in commit `2ee40c52` (guard dropped; `saveNow` is the user-initiated write and is safe
unconditionally, D-186-03), with a regression pin whose **counterfactual was DRIVEN** — replanting
the guard turns it RED. `tsc -p tsconfig.app.json` is now **34**, zero of them in that file.

### A fourth correction, to §2's RUN-05 evidence

`200.2-UAT.md`'s four arm-defining run IDs **do not resolve** against the live DB at `:54322` —
0 of 4. Their first eight characters DO resolve, to four real runs carrying **exactly** the
statuses claimed (`completed`, `completed`, `cancelled`, `failed`). The rows were therefore
driven and the evidence is credible; **the citations as written are unusable**, because each UUID
tail was invented. Same defect in `BUG-260823-04`, which cites
`bef870ba-0000-4000-8000-000000000001` for a run that is really `bef870ba-dbdc-4442-ab5c-b0153d30bdb9`.
