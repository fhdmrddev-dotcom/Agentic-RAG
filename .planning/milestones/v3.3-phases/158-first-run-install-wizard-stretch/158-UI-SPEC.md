> Visual and interaction contract for the pre-auth, full-page install wizard that automates the `docs/OPERATOR.md` Home-B manual runbook. **Utilitarian stepper — REUSES shipped, operator-approved primitives; introduces NO new visual language.** Every choice below is grounded in a live component and the Deep Midnight tokens (`frontend/src/index.css :.dark`). Generated by gsd-ui-researcher (autonomous), verified by gsd-ui-checker.

## Spacing Scale

The app is a **4px-base grid** (`--space-1`…`--space-16` in `index.css`). Declared values for the wizard's own layout rhythm (all multiples of 4):

| Token | Value | Usage in the wizard |
|-------|-------|---------------------|
| xs | 4px | icon-to-label gaps, chip inner padding |
| sm | 8px | compact stacks (label→input), rail node gaps |
| md | 12px | card inner padding rows, form-field vertical gaps |
| lg | 16px | card body padding, step-content block gaps |
| xl | 24px | page gutter (`px-6`), section separation |
| 2xl | 32px | step-to-step vertical rhythm |
| 3xl | 48–64px | full-page top/bottom breathing on the centered column |

**Exceptions (inherited, NOT re-specified — reuse mandate D-17):** the reused leaves `HealthSignals`, `PublishGauntlet`, `ProviderPicker` ship Tailwind half-step paddings (`gap-2.5`=10px, `px-3.5`=14px, `py-3`=12px). These are consumed **as-is** and are out of scope for re-spacing. New wizard chrome uses the 4px-grid table above.

**Radius:** `--radius: 0.625rem` (10px) is the app default. Cards/panels = `rounded-[10px]` or `rounded-lg`; status/preset nodes = `rounded-xl`; pills = `rounded-full`. Match the shipped surfaces exactly.

## Typography

Anchored to the shipped ladder (`ControlRoomPage` uses `font-headline text-lg font-bold` for page titles, `text-base font-bold` for sections, `text-sm`/`text-xs` for body/meta). Constrained to **4 roles**:

| Role | Size | Family | Weight | Line Height | Usage |
|------|------|--------|--------|-------------|-------|
| Display | 20px | Manrope | 600 | 1.2 | Step title ("Connect your database"), the "First-run setup" wordmark |
| Heading | 16px | Manrope | 600 | 1.3 | In-step section headers ("Supabase", "Redis", "What we found") |
| Body | 14px | Inter | 400 | 1.5 | Instructions, form labels, prose, plain-language guidance |
| Label / meta | 12px | Inter (400) / JetBrains Mono | 400 | 1.4 | Helper text, error copy, and — in **mono** — env-var identifiers (`SUPABASE_URL`), counts, the setup-token echo |

**Weights — exactly two:** `400` (regular, all body/meta) and `600` (semibold — every heading, label emphasis, and CTA). No 700 in the wizard's own chrome. *[assumption]* The wizard intentionally caps headings at Manrope 600 rather than the shipped `.font-headline` 700, for a calmer utilitarian tone; still the same family, a strict subset of the app.

**Never:** italic body, all-caps prose (mono `text-[10px] uppercase tracking-wide` micro-labels are allowed only as field captions, matching `PublishGauntlet`), or a 5th size in new chrome.

Deep Midnight, mirrored from `index.css :.dark` (values are the contract source of truth — cite the token, not a hex fork).

| Role | Token (`.dark`) | Approx | Usage |
|------|-----------------|--------|-------|
| Dominant (60%) | `--background` `216 45% 4%` | `#060A0F` | Full-page canvas behind the centered column |
| Secondary (30%) | `--card` `220 30% 7%` + `--muted` `220 30% 11%` + `--accent` `220 25% 14%` | `#0D1017` | Step cards, form panels, glass insets, rail track |
| Accent (10%) | `--primary` `239 100% 82%` | `#A3A5FF` | See reserved-for list — RESTRICTED |
| Destructive | `--destructive` `0 72% 51%` | `#DC2626` | Failed smoke rows, bad/expired-token error, down-connection dot |

**Semantic status trio** (the connection tests + smoke checklist — reused verbatim from `HealthSignals`, never colour-alone):

| State | Token / class | Meaning in the wizard |
|-------|---------------|-----------------------|
| pass / healthy | `--success` `142 71% 45%` (`bg-success`) `#22C55E` | connection OK · smoke row green · schema present |
| warn / degraded / needs-you | `amber-500` / `amber-400` `#F59E0B` | slow connection · token required · schema-missing guidance · zero-match |
| fail / down | `--destructive` `bg-destructive` | connection refused · smoke row red · bad token |
| off / neutral | `bg-muted-foreground/40` | optional provider skipped · "not configured" (NEVER red — Pitfall 6) |

**Accent (`--primary`) reserved for — explicit list (never "all interactive elements"):**
1. the **active** step node in the rail (`LifecycleStepper` current-stage ring/wash)
2. the **single primary CTA** per screen (Continue · Test connection · Create account · **Finalize setup**)
3. input **focus** border/ring (`focus:border-primary`)
4. the live/current pointer glyph and the "you are here" step label

Everything else: secondary buttons = `border-border` + `text-muted-foreground`; body text = `--foreground`; meta = `--muted-foreground` (never the `--muted-foreground-dim` ~3.6:1 trap for meaningful text — Phase 155 AA bar). Amber/green/red are **status only**, never decorative.

## Copywriting Contract

Plain-language, non-developer audience (LANG-01). Technical identifiers appear as **secondary mono hints**, never as the primary label.

| Element | Copy |
|---------|------|
| Primary CTA (phase culmination) | **"Finalize setup"** — disabled until all smoke rows are green; enabled label unchanged, blocked tooltip: "Every check must pass before you can finalize." |
| Per-step progression CTA | **"Continue"** (secondary-to-Finalize; primary within its step) |
| Entry / empty state heading | **"Let's set up your workspace"** |
| Entry / empty state body | "Paste the setup token from your server logs to begin. Run `docker compose logs backend` and copy the line that starts with **Setup token:**." (`docker compose logs backend` in mono) |
| Error — bad/expired token | "That token didn't match. Copy the **whole** token line from `docker compose logs backend` and paste it again." |
| Error — rate-limited token | "Too many tries. Wait about a minute, then paste the token again." |
| Error — connection failed (Supabase/Redis) | "Couldn't reach {Supabase\|Redis}. {verbatim probe reason}. Check the value and test again." (reason rendered verbatim, mono) |
| Sub-state — schema missing (D-10) | "Your database is reachable but empty. Paste this setup SQL into the Supabase SQL editor, run it, then test again." + a **copy-to-clipboard** SQL block (schema + the 9 ordered seeds + the global row). |
| Provider-key helper | "Paste one provider key to power the assistant. We'll verify it in the final step." |
| Destructive / irreversible confirmation (**Finalize lock**, D-14) | **Finalize setup:** "This locks first-run setup. After this, configuration changes happen in **Admin**, not here. Ready to finish?" |
| Post-finalize lock-out (SC#2) | Heading: **"Setup is already complete."** Body: "This workspace is configured. Head to the app to log in — to change settings, use the Admin area." CTA: **"Go to the app"**. |
| Finalized — login-fallback note (D-07 SHOULD) | "If login doesn't work right away, your server may need a quick restart to pick up the new address. Your operator can run `docker compose restart` (or rebuild the frontend)." |

**Honesty rules (carried from the reused primitives):** never a fabricated "High"/green when a check hasn't actually passed; a skipped optional provider reads neutral "not configured", never red; a failed check always names the fix; the smoke verdict renders server truth (a row is green ONLY when the server says so — the `LifecycleStepper` / `PublishGauntlet` never-recompute discipline).

## Surface-by-Surface Contract

The wizard is a **full-page, pre-auth, single centered column** (`max-w-2xl`, `[assumption]` matching `PublishGauntlet`'s `max-w-2xl` modal width) on the Deep Midnight canvas, with the `LifecycleStepper` rail across the top (or left on wide viewports). Each surface below cites its shipped analog.

### 0. Shell + entry (`SetupWizard` — NEW; analog: `ControlRoomPage` shell + `App.tsx` AuthPage branch)
- **Mount:** a pre-auth branch in `App.tsx` **before** `if (!user)` (~line 161). A public `GET /api/setup/status` probe at startup → if `needs_setup`, render `<SetupWizard/>`; a `window.location.pathname === "/setup"` check also forces it (D-06). Post-finalize, `/setup` renders surface 9 (lock-out).
- **Frame:** `flex min-h-screen flex-col` on `bg-background`; a slim top **setup-state banner** (analog: `MaintenanceBanner` — fixed strip, `role="status"`, but neutral/primary-tinted not amber): "First-run setup — configure this workspace to get started." A calm "First-run setup" header band echoing `OperatorBand` (wordmark + a `🔒 setup session` chip once the token is accepted).
- **Rail:** `LifecycleStepper` full variant, generalized to **6 nodes** — `Detect · Preset · Connect · Operator · Provider · Smoke`. Node states reuse the shipped `NODE_TONE` (ok=emerald / current=primary-or-amber / dim=muted) + numbered/`✓` glyphs + connector line. Only the **current** step narrates (quiet-idle discipline). Completed steps are click-to-revisit (idempotent, D-14).
- **Loading:** the `App.tsx` centered spinner (`animate-spin border-primary`) while the status probe resolves.

### 1. Setup-token gate (`SetupTokenGate` — NEW; analog: `AuthPage` form)
- **First screen, before any step.** Single centered `Input` (shadcn) + `Label` "Setup token" + a `Button` "Continue". Plain-language body copy (see Copywriting entry). The token line's source command (`docker compose logs backend`) renders in a mono code chip with a copy button.
- **States:** idle · validating (button → spinner + "Checking…") · error (bad token → destructive inline message; rate-limited → amber inline message, button disabled with a countdown *[assumption]*) · success (advance to step 1, mint the `🔒 setup session` chip in the header).
- **Security surface:** the token is entered **once**, held for the session, and silently attached to every `/api/setup/*` write (D-15). If a later write returns token-invalid, bounce back here with "Your setup session expired — paste the token again." **Never echo the token back in full** (mask to last 4, mono).
- **Focus:** autofocus the input on mount (mirrors `PublishGauntlet`'s golden-input autofocus).

### 2. Step 1 — Environment detect (`EnvironmentDetectCard` — NEW; analog: `HealthSignals` read-only tiles)
- **Read-only, orienting, light** (D-08 — not heavy discovery). A grid of neutral signal tiles (the `HealthSignals` card markup: dot + label + one-line sub): "Running in Docker" ✓/— · "Existing config found" ✓/— · "Database reachable" green/amber/— · "Redis reachable" green/amber/—. Dots use the status trio; unknown/not-probed = neutral em-dash (never red).
- Single **"Continue"** primary CTA. No inputs. A one-line honest caption: "This just orients the next steps — nothing is changed yet."

### 3. Step 2 — Preset pick (`PresetPickerStep` — NEW; analog: radio-card, closest shipped = `CapabilityGrid` card + `FeatureVisibility` audience rows)
- **Radio-card selection.** One-box is the **prominent recommended** card (primary-tinted border, a "Recommended" pill, selected by default — D-09). Managed / On-prem are selectable sibling cards, visibly secondary, each captioned "Pre-fills defaults + opens the runbook" (they do NOT launch a multi-preset engine — SHOULD, D-18).
- Selecting Managed/On-prem shows an inline honesty banner (analog: the app's dismissible banners) linking the relevant `OPERATOR.md` variant section; the built happy-path is one-box.
- Keyboard: a proper radiogroup (`role="radiogroup"`, arrow-key selectable) — Phase 155 AA bar.

### 4. Step 3 — Supabase & Redis bind (`ConnectionBindStep` + `SchemaGuidancePanel` — NEW; analog: `ProviderPicker` form + `HealthSignals` result dots)
- **Two grouped forms** in one scroll: **Supabase** (`SUPABASE_URL` + the 4 keys `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_SECRET_KEY` + `POSTGRES_DSN`) and **Redis** (`REDIS_URL`). Each field: plain `Label` + shadcn `Input`; the env-var name is a **secondary mono hint** under the label.
- **Secrets masked:** the 4 keys, `POSTGRES_DSN` (embeds the DB password), and `REDIS_URL` use the `ProviderPicker` masked-input pattern (`type="password"` + `Eye`/`EyeOff` toggle, `***`/last-4 placeholder). `SUPABASE_URL` is plain text.
- **DSN hint (from OPERATOR.md A4):** an always-visible `ⓘ` caption on `POSTGRES_DSN` — "Use the **Session pooler** on `:5432` — not the direct `db.<ref>` host, not `:6543`." (mono examples).
- **"Test connection" per group:** a secondary button beside each group; on click → server-side probe of the **submitted** values (reuses `health_probe`, D-10). Live inline result reuses the `HealthSignals` dot vocabulary: green "Connected" / amber "Slow" / red "Couldn't connect — {verbatim reason}". States: idle · testing (spinner) · pass · fail.
- **Schema-missing sub-state (D-10):** if Supabase connects but the sentinel table is absent, render `SchemaGuidancePanel` — an amber notice (not an error): the exact `OPERATOR.md` Step-3 sequence (`full-schema.sql` + the 9 ordered seed migrations by filename + `INSERT INTO app_settings (id) VALUES ('global')`) in a **copy-to-clipboard** mono code block, with "Paste into the Supabase SQL editor, run it, then Test again." *(A server-side "run it for me" DDL runner is a SHOULD, D-18 — if built, it's a single "Set up the database for me" primary button that streams progress and re-tests; the copy-guide is the MUST fallback.)*
- **Continue** is disabled until both groups test green (the schema sub-check included).

### 5. Step 4 — Bootstrap operator (`OperatorBootstrapStep` — NEW; analog: `AuthPage` sign-up form)
- **Create the first admin account.** Fields: email · password · confirm password. Plain caption: "This is your admin login — you'll use it to sign in and open the Admin area." A password-strength hint (a slim determinate bar + word — analog: the eval `RunBar` thin determinate bar; *[assumption]* length + character-class heuristic, client-side, advisory only).
- Confirm-mismatch = inline destructive message; weak password = amber advisory (never a hard block beyond a minimum). On submit → server creates the Supabase auth user + upserts `operator_users` (D-11). Result caption on success: "Admin account created — you can log in as operator right after setup."
- **Continue** disabled until email valid + passwords match + minimum met.

### 6. Step 5 — Provider keys (`ProviderKeyStep` — REUSE `ProviderPicker` + one required key)
- **Reuse `ProviderPicker`** for the default-LLM selection: preset `<select>` + the **always-on 🔒 endpoint footer** (endpoint · cloud/local tag). Provider logos are **@lobehub** via `@/lib/providerLogo` (Icon Convention §1 — byte-identical to chat/registry).
- **One required key** (OpenAI default, D-12), masked (`Eye`/`EyeOff`, `***`). Other providers listed as optional/skippable rows (neutral "not configured" when empty — never red). An inline note: "We'll verify this key in the next step."
- **Continue** disabled until the chosen provider has a non-empty key.

### 7. Step 6 — Smoke test (`SmokeChecklist` — REUSE `HealthSignals` rows + `PublishGauntlet` gated verdict)
- **The green-checklist, and it IS the finalize gate (D-13).** Five rows, each a `HealthSignals`-style card (dot + plain label + sub + verbatim reason on fail): **Supabase auth reachable · Postgres + schema present · Redis PING · Provider key works · Operator account exists.** Dot vocabulary = the status trio; a not-yet-run row is neutral.
- **Run + verdict pattern mirrors `PublishGauntlet`:** a primary "Run checks" triggers the server-side smoke; while running, a live elapsed clock + "checking…" per row (analog: the gauntlet's `PublishingNotice` elapsed clock + "don't close the tab" honesty, reduced-motion-gated). Each row resolves to green/amber/red **from server truth** — never optimistically green.
- **All-green unlocks `Finalize setup`** (the single primary CTA); **any red blocks it** with the row's plain-language fix (the gauntlet's gated-verdict discipline: a block leads with words, the raw reason is one glance away). A red row offers a **"Back to fix"** jump to the owning step (idempotent re-entry, D-14).
- **Finalize** → the irreversible-lock confirmation (see Copywriting); on success, transition to surface 9.

### 8. Finalize (in-flight) state
- After confirming Finalize: a blocking, calm progress panel (analog: `PublishGauntlet` in-flight notice) — "Saving your configuration…" with the honest note that the box may re-initialize its connections. Reduced-motion-safe. On success → surface 9; on failure → an honest error with retry (config is not half-written — the finalize writes both markers atomically per D-05).

### 9. Finalized / lock-out state (`FinalizedLockout` — NEW; analog: `PublishGauntlet` success card + a centered CTA)
- **Shown after finalize AND on any later `/setup` visit (SC#2).** A centered success card (success-tinted, `🎉`/`✓` — analog: the gauntlet `publish-success`): "Setup is already complete." **No config fields, no re-entry** — re-configuration is an Admin action (D-14). Single primary CTA **"Go to the app"** (routes to the normal auth/app surface).
- Includes the **login-fallback note** (D-07 SHOULD — see Copywriting) as a quiet secondary line, not an alarm.

## Interaction States (every async action)

Each of these carries the full **idle → loading → success → error** set, rendered with the shipped vocabulary (never a raw spinner with no words, never a silent fail):

| Action | Loading affordance | Success | Error |
|--------|--------------------|---------|-------|
| Token validate | button spinner "Checking…" | advance + `🔒 setup session` chip | destructive (bad) / amber (rate-limited) inline |
| Test connection (×2) | inline dot → pulsing + "Testing…" | green "Connected" | red "Couldn't connect — {reason}" |
| Schema probe | folded into test-connection | green "Schema present" | amber `SchemaGuidancePanel` |
| Create operator | button spinner "Creating…" | "Admin account created" | destructive inline (mismatch / server) |
| Run smoke | per-row "checking…" + elapsed clock | rows resolve green | red rows block Finalize + "Back to fix" |
| Finalize | blocking "Saving your configuration…" | → lock-out surface | honest retry (both markers atomic) |

**Blocked state discipline:** the `Finalize setup` button is the ONLY gate — it is `disabled` with a tooltip until all smoke rows are green (mirrors `PublishGauntlet`'s `canPublish` + disabled-until-valid). No screen ever advances on an un-passed check.

## Accessibility (Phase 155 WCAG AA bar)

- **Never colour-alone:** every status carries dot **+ word** (inherited from `HealthSignals`); rail nodes carry glyph (`✓`/`!`/number) **+** tone.
- **Keyboard-navigable stepper:** rail nodes for completed steps are `<button>` with `aria-label="Go to {step}"` (the shipped `LifecycleStepper` pattern); the preset picker is a real `role="radiogroup"` (arrow-selectable); the token gate + finalize confirm manage focus (autofocus in, focus-trap on any modal confirm — the `PublishGauntlet` Escape/Tab contract).
- **Contrast:** meaningful text uses `--foreground` / `--muted-foreground` (≥4.5:1), never the `--muted-foreground-dim` ~3.6:1 trap; the primary CTA text uses `--primary-foreground` on `--primary`.
- **Live regions:** connection-test results and the smoke rows announce via `role="status"`; hard errors (bad token, connection down) via `role="alert"`.
- **Reduced-motion:** the elapsed-clock comet/pulse (from `PublishGauntlet`) and any rail animation are gated behind `prefers-reduced-motion` (6 guards already exist in `index.css`); colour + glyph carry all state without motion.
- **Labels:** every input has an associated `<Label>`; masked-secret toggles carry `aria-label` ("Show/Hide value"); the copy-SQL button carries `aria-label`.
