<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| unbound box → running app | The finalized latch is the trust boundary between "provisioning" (gate ON, token required) and "running" (gate no-op) |
| mounted volume → app config | `/data/setup.json` holds the infra tier + token + marker; the config overlay merges it into `Settings` |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-158-05 | DoS | SetupMiddleware gate authority | mitigate | Gate reads the FILE marker + sticky latch, NEVER a live DB flag — a DB blip can never bounce live users into the wizard (D-05); the latch makes a configured box's hot path one bool, zero I/O (byte-identical, D-17). |
| T-158-08 | Elevation | setup token | mitigate | `secrets.token_urlsafe(32)` (256-bit) + `hmac.compare_digest` constant-time verify in `setup_store.verify_token`; brute-force is infeasible; endpoint rate-limit is added in 158-06. |
| T-158-09 | Information Disclosure | /data/setup.json at rest | mitigate | Atomic `tmp + os.replace` write with `os.chmod(0o600)`; store contents (secrets, token) are NEVER logged except the single boot token announcement. |
| T-158-04 | Information Disclosure | store logging | mitigate | No `logger` call prints store contents or infra secrets; only `announce_token_if_unfinalized` logs the token, once per unfinalized boot. |
| T-158-SC | Tampering | pip installs | accept | Zero new packages — stdlib `secrets`/`json`/`tempfile`/`hmac` + starlette (already present). |
</threat_model>
