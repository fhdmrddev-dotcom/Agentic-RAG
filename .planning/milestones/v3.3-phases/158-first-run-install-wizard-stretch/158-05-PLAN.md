## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| operator-submitted URLs/DSNs → backend | The backend opens connections to operator-supplied hosts (the wizard's purpose) — token-gated at the router |
| service-role admin API → auth.users | Creating the first operator uses the service-role key server-side only |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-158-03 | Information Disclosure / SSRF | submitted-value probes | mitigate | Probes return ONLY `type(exc).__name__` + a plain message — never the raw connection error, DSN, or host (no internal-topology leak); bounded 3s timeouts; the write path is token-gated (158-06) so the submitter already has host access. |
| T-158-06 | Spoofing | operator credentials | mitigate | Password policy delegated to Supabase GoTrue (its error surfaced verbatim, never a 500); create is idempotent (duplicate email → already_exists, not a crash); the auth user is created via the trusted service-role admin API, never a manual auth.users INSERT. |
| T-158-04 | Information Disclosure | provider key at rest | mitigate | The key is persisted only through `save_app_settings` (Phase-150 encrypt-on-write via SECRET_COLUMNS) — no second encrypt path, no plaintext log. |
| T-158-07-schema | Tampering | auto-runner DDL | mitigate | The SHOULD auto-runner is schema-absent-gated + `conn.transaction()`-wrapped (all-or-nothing, no half-schema) over a throwaway conn; a pooler privilege error raises a typed error → the router falls back to the copy-guide (the MUST path). |
| T-158-SC | Tampering | pip installs | accept | Zero new packages — asyncpg / redis.asyncio / supabase / fastapi all already present. |
</threat_model>
