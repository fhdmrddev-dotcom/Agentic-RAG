<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool-call → handler | Model-supplied `document_id` is untrusted input crossing into an owner-scoped Storage read |
| documents.filename → sandbox path | `documents.filename` is user-set at upload — untrusted when used to build a container path |
| Storage bytes → sandbox container | Original bytes move disk→disk via copy_to_runtime, never into model context |

## STRIDE Threat Register — FILE-02 `fetch_document_file` (T-01)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-151-02-01 | Information Disclosure | `_fetch_owned_document_bytes` doc resolution | mitigate | Owner→global resolver, `.eq(user_id)` FIRST (service-role has NO RLS backstop — the app gate is load-bearing). Proven: non-owner user_id → empty `.data` → "not found or access denied" (SC#4 unit test in test_151_fetch_handler.py) |
| T-151-02-02 | Tampering | filename → `/sandbox/input/` path | mitigate | `os.path.basename` + `workspace.py:184` charset scrub before landing. Proven: `../../etc/x` lands as scrubbed basename under `/sandbox/input/`, no `..` segment (T-01 unit test) |
| T-151-02-03 | Denial of Service | huge file → memory/context flood | mitigate | `documents.file_size` size gate runs PRE-download (D-02); over-cap returns error with NO download attempted (mock `assert_not_called`). Bytes go to disk via copy_to_runtime, never into `ToolResult` |
| T-151-02-04 | Integrity | corrupt half-binary on over-cap | mitigate | Over-cap = hard error, no partial write; refuse-never-truncate (D-02). Proven: no file materialized on over-cap |
| T-151-02-05 | Elevation of Privilege | tool runs when sandbox disabled | mitigate | Hidden from get_tools() when sandbox off AND refused in-flight via `_CAPABILITY_FLAG_TOOLS` (D-11, fail-closed, provider-uniform) |
</threat_model>
