<objective>
Close the round-2 minor gap on UAT Test 7: after a disabled-model fallback served the reply
via MiniMax (a compat-path reasoning model), the follow-up suggestion chips rendered raw
`<think>` reasoning markup — the chips read `<think>` followed by two chain-of-thought sentences.

Root cause: `suggestion_service.generate_suggestions` parses the raw completion content
line-by-line (~line 98: `content.split("\n")`) with NO think/reasoning stripping. Reasoning
models served via the compat path emit `<think>...</think>` inline in `message.content`
(MiniMax here, but equally any direct MiniMax/DeepSeek/GLM chat); each think line becomes a
question chip, and the real questions get pushed out of the 3-item clamp. The streaming chat
path separates reasoning via the compat adapter's `<think>` state machine; the non-streaming
suggestion call bypasses that separation.

Fix: strip `<think>` blocks from the completion BEFORE the line-parse and the clamp-to-3,
reusing the exact stripping logic the title path already uses.

Purpose: suggestion chips must be clean questions regardless of which model served the reply.
Output: a small, self-contained think-strip applied before parsing, plus regression tests.
</objective>

The EXACT stripping logic to mirror — from backend/app/api/threads.py:754-771 (the title path's
`_strip_think_blocks`, already handles MiniMax inline / GLM-4.6+ think + unclosed trailing think):
```python
def _strip_think_blocks(text: str) -> str:
    out = text or ""
    lower = out.lower()
    while "<think>" in lower and "</think>" in lower:
        start = lower.find("<think>")
        end = lower.find("</think>", start)
        if end == -1:
            break
        out = out[:start] + out[end + len("</think>"):]
        lower = out.lower()
    idx = out.lower().find("<think>")  # unclosed trailing think (ran out of budget mid-reasoning)
    if idx != -1:
        out = out[:idx]
    return out
```

threads.py sibling; converging both onto a shared util is a future de-dup, out of scope here.
