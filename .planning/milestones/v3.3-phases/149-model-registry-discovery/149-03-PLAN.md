<objective>
Close the folded bug BUG-260620-01 (D-149-15): make the `max_output_tokens` clamp honor (a) the EFFECTIVE model actually sent — not `user_settings.llm_model` — and (b) an operator's DB-edited `max_output_tokens` — not just the static `MODEL_CAPABILITIES` dict. This makes the registry's `max_output_tokens` edit honest (SC#1) and bars the gpt-4o `32768 > 16384 → 400` recurrence.

Purpose: The whole point of the registry write UI (MODEL-01) is that an edited capability takes effect. Today the clamp reads the static dict against the wrong model, so an edit to `max_output_tokens` is silently ignored on the request path. This is a surgical fix to the Phase-074 single-chokepoint — extend it, do not fork.
Output: `_resolve_max_tokens` clamps against the effective model via a DB-aware cap; all its callers pass the effective model + pre-resolved cap; `test_149_clamp.py` green.
</objective>
