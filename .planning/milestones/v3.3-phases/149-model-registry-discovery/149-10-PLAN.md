<objective>
Close the two remaining UI-honesty gaps from the Phase-149 live UAT (both low-severity, both label/affordance corrections inside existing admin components):

1. **Discovery per-model provenance label (Test 9, COSMETIC).** In `ModelDiscoveryPanel.tsx` the `NewModelRow` suffix (line ~478) reads `returnedFull ? "returned full capabilities ✓" : "returned IDs only"`, where `returnedFull = !anyUnknown` (line ~463-464). For a Google new model the token limits (context/max_output) ARE provider-returned (rendered green via `!isUnknown`), but `native_tools` is "unknown — you set it" (only OpenRouter returns native-tools metadata). So `anyUnknown` is true → the card reads "returned IDs only" — contradicting the google PROVIDER run card which correctly reads "capabilities ✓" (line ~385). The binary suffix lies whenever a provider returns SOME (not all) fields. Fix: derive the suffix from the actual per-field provenance (or drop it and rely on the provider card + the per-field green/amber fills).

2. **Deprecated-reason Enter-commit (Test 10, MINOR).** In `ModelRegistryTab.tsx` the `DeprecatedControl` reason input (line ~535-550) was reported as commit-on-blur-only — a typed reason lost on Enter. The current code already has an Enter handler (IN-02, line ~542) but, unlike the numeric `InlineNumberCell` (line ~416-443), it lacks an **Escape-cancel** and the **one-shot `settled` guard** that stops the Enter-commit from double-writing with the trailing blur. Fix: bring the reason input to full commit parity with the numeric cell — Enter commits (with `preventDefault`), Escape cancels (reverts to the stored reason without writing), and a one-shot guard prevents the Enter+blur double-write. Regression-lock the "Enter commits the typed reason" behavior the UAT reported missing.

Purpose: make discovery provenance labels honest (SC#3) and give the deprecated-reason input the same commit affordance as every other inline edit (no silently-lost input).
Output: a truthful per-model provenance suffix; a full-parity reason input; vitest coverage of both reproduced failure modes.
</objective>
