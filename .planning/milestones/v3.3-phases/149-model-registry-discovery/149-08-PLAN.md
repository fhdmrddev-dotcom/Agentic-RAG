<objective>
Close the two MAJOR backend request-path gaps from the Phase-149 live UAT:

1. **native_tools DB-blind routing (Test 1, SC#1 violation).** `resolve_calling_mode` (openai_service.py:1518) drives the native-vs-structured tool-calling decision off the SYNC `get_model_capability` (config.py:515) — which reads ONLY the static `MODEL_CAPABILITIES` dict and has no DB tier. An operator's `native_tools` toggle persists to `model_capabilities_overrides` but never changes the next request's routing. The fix makes the calling-mode decision DB-aware via the SAME 30s-TTL warm-cache read the max_output clamp already uses (`_resolve_db_max_output_cap`, openai_service.py:1416 — the D-149-15 fix that passed UAT Test 2 live), so no `await` enters the hot path and `resolve_calling_mode` stays sync (the D-14 byte-identical boundary).

2. **OpenRouter slash-ID 404 (Test 4; also unblocks Test 5's OpenRouter leg).** `PATCH /admin/models/{model_id}` (admin.py:1061) and `PUT /admin/models/{model_id}/lock` (admin.py:1224) use single-segment path params. Uvicorn ASGI-decodes `%2F`→`/` before Starlette routing, so namespaced IDs (`deepseek/deepseek-chat`, all 9 OpenRouter rows) never match → FastAPI 404. The fix is the Starlette `{model_id:path}` converter on both routes (the trailing `/lock` literal still anchors the PUT route).

Purpose: make an operator's native_tools toggle real (SC#1) and make every provider's registry rows uniformly editable (MODEL-01/MODEL-02 across all 8 providers, OpenRouter included).
Output: DB-aware `resolve_calling_mode` in `openai_service.py`; `{model_id:path}` on both write routes in `admin.py`; regression tests proving the exact UAT failure modes.
</objective>
