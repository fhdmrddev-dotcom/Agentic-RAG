<objective>
Close the round-2 major gap on UAT Test 1 (SC#1 second half): when an operator flips
`native_tools` OFF on an OpenAI/compat-path model, routing correctly resolves STRUCTURED
(the round-1 fix landed), but the chat then produces a hallucinated non-answer with ZERO
tool calls. Root cause: `agent_loop.py`'s pre-injection gate `_needs_pre_injection`
(~line 1560) hardcodes `active_provider == 'openrouter' AND openrouter_tool_strategy == 'xml'`.
A DB-flipped model on any OTHER compat provider (openai/deepseek/minimax/moonshot/zhipu/ollama)
gets NO `TOOL_USAGE_INSTRUCTIONS` before the first stream, and the STRUCTURED branch of
`create_adaptive_streaming_chat` deliberately omits the native `tools` param — so on iteration 0
the model has no tool mechanism at all. The post-stream fallback injection (~line 2046) only
takes effect "next iteration", but with no parsed tool call there IS no next iteration —
circular, never activates for a fresh run.

Fix: extend the pre-injection gate to ALSO fire when the effective calling mode resolves
STRUCTURED for a compat-path provider, mirroring the existing WR-05 native-SDK boundary
(anthropic/google always-native, never consulted for calling mode).

Purpose: SC#1's "still works" half must hold — native_tools=False on a compat model must
strip native tools AND provide the prompt-injected tool mechanism, not strip all tools.
Output: A small pure gate helper + its wiring in `run_agent_loop`, plus regression tests.
</objective>
