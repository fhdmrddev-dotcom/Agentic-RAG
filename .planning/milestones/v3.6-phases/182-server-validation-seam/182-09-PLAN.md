Both canvas routes carry `dependencies=[Depends(require_canvas())]` AND
`current_user: dict = Depends(get_current_user)`. `require_canvas._dep` resolves the caller
itself through `authenticate_canvas_request` (`supabase.auth.get_user(...)` plus `_is_banned(...)`),
and then `get_current_user` validates the SAME token again with another
`supabase.auth.get_user(...)` plus another `_is_banned(...)`. Per request that is two GoTrue
round-trips and two `auth.users` queries, on a route the seam header itself documents as firing
"on every canvas edit".

Both calls are synchronous `supabase-py` invoked directly inside `async def` — the pattern
CLAUDE.md forbids (D-v2.5-01: "Do not run blocking I/O directly inside async handlers — wrap with
`run_in_threadpool`"). The single-call form on `get_current_user` is pre-existing and shared by the
whole app; the DOUBLING on a keystroke-frequency route is what this phase introduced.

The existing suite structurally cannot see this: conftest's blanket `get_current_user` override
short-circuits one side, and `test_182_grounding_bundle` / `test_181_flip_on` monkeypatch the other.

Purpose: resolve the caller once, on the path that already validated it, and stop blocking the
event loop on the canvas auth call.
Output: a `request.state` hand-off from the gate to the handler, a `canvas_caller` dependency, a
threadpool-wrapped canvas auth read, and a counting-fake test that FAILS against today's code.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bearer token -> validated identity | The canvas gate converts an untrusted token into a trusted identity. Anything downstream that re-derives that identity is a second, independently-fallible conversion of the same untrusted input. |
| async request handler -> blocking `supabase-py` client | A synchronous GoTrue call inside `async def` occupies the event loop for the whole worker, degrading every concurrent SSE stream on that process (D-v2.5-01). |
| gate -> handler (`request.state`) | An in-process hand-off. Its integrity depends on nothing being able to reach the handler without passing the gate first. |
