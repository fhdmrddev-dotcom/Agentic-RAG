# Phase 188.1 Plan 01: Re-scope the canvas source fences before the move — Summary

Re-pointed twelve negative `?raw` assertions in the two canvas suites at an `import.meta.glob`
subtree source that already names the two modules plan 188.1-03 will create, so the 311-line
extraction of `PlaneEditingLayer` + `EDIT_AFFORDANCE` cannot silently shrink a fence's scope —
and made SC#4's no-focusable-control walk non-vacuous by rendering it in editable mode.

## What Was Built

**Task 1 — the subtree fence** (commit `004a6486`)

A module-scope `CANVAS_SUBTREE_PATHS` / `CANVAS_MODULES` / `canvasSubtreeSource` block was added
to **both** canvas suites, beside (never replacing) the shipped `workflowCanvasSource` import.
It uses the house `import.meta.glob("./*.{ts,tsx}", { query: "?raw", eager: true, import: "default" })`
sweep (`PhaseFormPanel.rails.test.tsx:422-426`), narrowed by an explicit three-literal path list:
`./WorkflowCanvas.tsx`, `./PlaneEditingLayer.tsx`, `./editAffordance.ts`. Two of the three files do
not exist at this commit; `import.meta.glob` expands over files that EXIST, so an absent path
simply has no key and contributes `""` rather than throwing.

deleted, renamed or re-described in this task):

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical guard] The non-vacuity control could not detect a SUBSTITUTED path literal**

- **Found during:** Task 1, while performing the plan's own RED-observation step
- **Issue:** The plan specified the control as `toContain("EDIT_AFFORDANCE = {")` +
  `toContain("function PlaneEditingLayer(")` + `toHaveLength(3)` + a non-empty-glob check, and its
  acceptance criterion required that *"changing one literal to `"./NotAFile.ts"`"* make the control
  FAIL. Measured, it did **not**: the length is still 3 and — because the moved code still lives in
  `WorkflowCanvas.tsx` until plan 188.1-03 — both `toContain` lines are still satisfied. A length
  pin catches a truncation but is blind to a substitution, so the exact edit that would quietly
  disconnect the fence from `PlaneEditingLayer.tsx` was undetectable.
- **Fix:** Added a loop naming each destination individually —
  `expect(CANVAS_SUBTREE_PATHS).toContain(path)` for both `./PlaneEditingLayer.tsx` and
  `./editAffordance.ts` — plus a forward guard that each path, **once its file exists**, must
  resolve to a non-empty string in the glob record (so a glob pattern that stops matching the new
  files after 188.1-03 also goes red rather than silently reading `""`).
- **Files modified:** `frontend/src/components/workflows/WorkflowCanvas.test.tsx`,
  `frontend/src/components/workflows/WorkflowCanvas.composition.test.tsx`
- **Verified:** RED OBSERVED #3 above — the strengthened form fails with
  `expected [ './WorkflowCanvas.tsx', …(2) ] to include './PlaneEditingLayer.tsx'`
- **Commit:** `004a6486`

**2. [Rule 3 - Blocking] `renderCanvas` in `WorkflowCanvas.test.tsx` had no `editable` option**

- **Found during:** Task 2
- **Issue:** The plan's `read_first` said to *"read its options object to learn the exact spelling of
  the editable flag"*. The helper has none — it is the READ-ONLY suite's helper, and `editable` is
  reachable only through `WorkflowCanvas.editing.test.tsx`'s separate helper. Without it the
  editable SC#4 walk cannot be written in the block the plan requires it to live in.
- **Fix:** Added `editable?: boolean` to the opts object and `editable={opts.editable}` to the JSX,
  following the shipped in-file precedent for `kbTools` (185-09) and `runState` (188-07) verbatim,
  including their docblock register. Every shipped call omits it, and `editable={undefined}` is
  identical to not passing the prop, so no existing assertion changed — proved by the 46 pre-existing
  cases still passing.
- **Files modified:** `frontend/src/components/workflows/WorkflowCanvas.test.tsx`
- **Commit:** `262543ae`
