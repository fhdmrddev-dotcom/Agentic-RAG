<objective>
Resolve CONFLICT 2 (decision D-20): make an external-action capability publishable without opening a
governance hole.

Purpose: `189-RESEARCH.md` measured that stage 2.6 rule 2 requires every `available_tools` entry to be
in `tool_names`, and `tool_names` is built from `get_tools(None)` — the LLM-facing schema list, not
`_TOOL_REGISTRY`. So a capability name in `available_tools` BLOCKS publish, which makes D-06 false.
And the obvious fix — adding the names to `get_tools()` — would put them in `GroundingBundle.tools`,
which binds straight into the author-facing whitelist rail, letting an author whitelist `send_email`
on an ordinary, UNARMED `llm_agent` step. That is precisely the wire-around SC#2 forbids, and closing
it is named as the single most important security property this phase owes.

Output: one new closed constant, one union applied at exactly one boundary, one corrected docblock —
and two suites that were RED in plan 189-02 going GREEN with their negative controls intact.
</objective>
