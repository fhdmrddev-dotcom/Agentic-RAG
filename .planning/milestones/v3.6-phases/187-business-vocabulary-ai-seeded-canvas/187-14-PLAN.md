<objective>
Put one quiet door to the three curated starters on the Builder's first screen — without creating a
second way a workflow comes into existence.

Purpose: "fork a starter" is already one of the four routes into the Builder, but you must already know
to arrive via the Workflows page. The first screen is deliberately the describe box alone, a 3-second
read. Sketch 151 measured the axis that decides this: it is **path count**, not clutter. A direct
template→canvas fork would be a second forward path with its own code and its own failure modes. C
collapses it back to one: picking a template fills the describe box with the starter's own
plain-language sentence, which you can still edit before anything is generated.

Output: `StarterTemplatePicker.tsx` and its suite.
</objective>
