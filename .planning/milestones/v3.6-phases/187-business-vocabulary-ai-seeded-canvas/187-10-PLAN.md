<objective>
Make a seeded name fall back to the derived tier the moment a config edit could invalidate it — and
give the two new surfaces their sentences a home where drift is testable.

Purpose: a stored name has no invalidation story. Re-bind a step's skill and a generator-written name
still promises the old behaviour — the face lies. The demote resolves it without a stale-name marker
and without a second corner on the card: clear the seeded name, and the face falls to the derived tier
and resumes tracking. A hand-typed name is the author's and is never cleared.

Output: the demote rule inside the one config-edit home, and the `SEED_RECEIPT_*` / `STARTER_DOOR_*`
copy constants that plans 187-13 and 187-14 import.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| author config edit → stored `name` | a client edit clears a stored field; it must not clear a field the author owns |
| server-derived grounding cause → rendered reason | the client may render the server's fact but must not invent one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-187-10-01 | Tampering | a hand-typed author name | mitigate | The demote is gated on `name_seeded_by_ai`; a test asserts a hand-typed name survives every identity-bearing patch. Losing an author's writing to an unrelated edit is data loss. |
| T-187-10-02 | Tampering | a stale face | mitigate | Clearing both `name` and the marker means the face falls to the derived tier and resumes tracking; no stale-name marker and no new card corner is needed. |
| T-187-10-03 | Tampering | scope creep of the PhaseSpec-level writer | mitigate | `setPhaseGovernance`'s narrow patch type is untouched (`git diff` grep returns 0), so it cannot quietly become a general `PhaseSpec` writer (T-185-06-02). |
| T-187-10-04 | Spoofing | an invented grounding reason | mitigate | The reason formatter takes the `GroundingCause` and the intersecting tool as inputs — it never classifies. Classification stays in `groundingCauseOf` over the server's `kb_tools` (D-187-08 / D-182-06). |
| T-187-10-05 | Repudiation | governance vocabulary drift | mitigate | Every sentence is an exported identifier asserted character-identically; a test forbids "safe"/"approved"/"proven", the words the shipped honesty rules already ban. |
</threat_model>
