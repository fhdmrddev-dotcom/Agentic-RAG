Close GAP-2 / WR-01: the single-flight rule lives in the CALLERS, and two of them —
`overwrite()` and `reload()` — do not implement it. `performWrite` enforces only `haltedRef`.

concurrent PATCHes carrying the same token; the loser is refused `stale_token` and the loop
drops back into a conflict banner for a conflict that does not exist.

Purpose: the mechanism built specifically to RESOLVE a concurrency conflict can itself
manufacture one. An invariant that each caller must remember is not an invariant — this is the
"one home per concern" red line applied to the write loop.

reports and disables while an exit resolves.

| the author's clicks → the write loop | a UI control that can be pressed twice before React re-renders is an untrusted trigger |
| browser tab → `PATCH /workflows/{id}` | two requests carrying the same token means one is refused; the refusal is a lie about the world |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-186-12-01 | Spoofing (false conflict) | `overwrite()` → `performWrite` | mitigate | The writer's own single-flight check makes two concurrent PATCHes carrying the same token unreachable, so the loop cannot mint a `stale_token` conflict banner for a conflict that never happened. F19a/F19b falsify it first. |
| T-186-12-02 | Tampering | `reload()`'s ref resets vs. an outstanding write | mitigate | The exit re-entrancy guard returns before mutating `tokenRef` / `haltedRef` / `pendingRef`, so an in-flight completion cannot overwrite a token `reload` just adopted, and a double Reload cannot double-`setDrafted`. F19c/F19d pin both halves. |
| T-186-12-03 | Elevation of privilege | the exits are user-only | accept | `reload` and `overwrite` remain ungated by `enabled` on purpose: they are user-initiated and D-186-08 requires that a person who has hit a conflict is always offered both ways out on any surface. The re-entrancy guard adds no automatic write, so D-181-01 is untouched by this plan (186-13 owns the automatic path). |
| T-186-12-04 | Repudiation | the disabled banner controls | mitigate | The banner stays mounted through the resolution and its controls read inert, so the surface never presents an enabled control that silently does nothing. `BuilderSaveRegion.test.tsx` asserts both the mount and the disabled attribute. |
| T-186-12-SC | Tampering | npm installs | accept | No dependency change; verified by an empty `git diff --stat frontend/package.json frontend/package-lock.json`. |
