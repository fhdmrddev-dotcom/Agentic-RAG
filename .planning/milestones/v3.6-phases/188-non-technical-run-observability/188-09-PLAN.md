<objective>
Stop dumping a running workflow into a chat message list.

Purpose: RUNVIZ-03, from the operator call of 2026-07-31 — *"a workflow that is RUNNING, and its
output, should have their own place — not be dumped into chat."* Today `doRun` ends
`selectThread(thread); onNavigate("chat")`. This plan replaces those two lines and adds the fourth
home. The thread still exists, still holds the run, and stays reachable — D-14 keeps the run
thread-backed and the harness engine the only executor. What changes is where the user stands.

Output: one union member, one render branch, one retargeted tail, and the wire test that fences all
three.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launch flow → run addressing | The id chosen to address the run decides which record a user is shown. Two differently-typed ids share the name `run_id` in this codebase. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-188-09-01 | Spoofing (of identity) | the two `run_id`s | mitigate | `doRun` resolves `threads.active_workflow_run_id` (the `workflow_runs` row) and never `PostMessageResponse.run_id` (the producer `runs` row). The wire test gives the two mocks different values so the wrong one is detectable, and a grep asserts the producer id is not referenced in `doRun`. |
| T-188-09-02 | Denial of service (data loss) | the WR-04 orphan cleanup | mitigate | A post-create failure must still delete the launch shell. The cleanup path is byte-unchanged and asserted directly, including that navigation does not occur on failure. |
| T-188-09-03 | Information disclosure | the run surface reached with someone else's run id | accept | Addressing is client-side, but authorisation is not: `GET /workflow-runs/{id}` ownership-gates and 404s (Plan 03, T-188-IDOR). A tampered `activeRunId` yields the "That run isn't available." state, not another account's run. |
| T-188-09-04 | Elevation of privilege | client-side flag gating | accept | No flag check is added on the client. Non-discoverability is server-side; a client gate would be a D-14 / D-181-02 red-line violation. |
| T-188-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed. |
</threat_model>
