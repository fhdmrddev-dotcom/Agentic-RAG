### The seven node readings — LOCKED words (D-188-04), plus this contract's clause layer

The **word** column is locked by CONTEXT and may not be reworded. The **clause** column is this
document's addition: it is what makes 154-A ("every node states its own truth") real without
re-deriving the panel's failure taxonomy.

| Reading | Source | Word (LOCKED) | Clause rendered after the word |
|---------|--------|---------------|-------------------------------|
| `not-started` | `status = "pending"`, or no matching row | **Not started** | — |
| `running` | `status = "running"` \| `"retrying"` (collapsed, D-188-03) | **Running** | — |
| `done` | `status = "done"` | **Complete** | — |
| `failed` | `status = "failed"` | **Failed** | one of three closed clauses — see below |
| `skipped` | `status = "skipped"` | **Skipped** | `— the run took a different path` |
| `waiting-for-you` | `pendingAsk != null` | **Paused for your answer** | `— it needs your reply before it can continue` |
| `unknown` | any status absent from the map | **State unknown** | `— we can't tell what happened to this step` |

**The failure clause is a CLOSED set of three, sourced only from the typed `Phase.emitFailure`
enum:**

| Condition (measured field, `types/index.ts`) | Clause |
|---|---|
| `emitFailure ∈ {model_failed_to_emit, render_failed, no_template_bound}` | `— it could not produce the document` |
| `emitFailure ∈ {citation_gate_rejected, integrity_failed}` | `— its answer did not pass the required checks` |
| `emitFailure == null` | `— this step did not finish` |

> **`Phase.error` is NEVER rendered on the canvas.** It is free-form harness text and may contain
> slugs, model ids or gate identifiers — exactly what Req 2's grep forbids on this surface. The
> detailed reason stays in the developer `PhaseTimeline`, reachable through `Open the chat thread`.
> This is why the canvas can state a reason at all without extracting `PhaseCard`'s classifier
> (which would widen scope into shipped panel vocabulary the SPEC put out of bounds).

### The run band — one line (154-A), and the total function at run level too

`workflow_runs.status` is a six-member CHECK constraint. The map is **total**: an unrecognised run
status renders *State unknown*, never *Complete* — the same discipline as `?? "unknown"` one level
down.

| `workflow_runs.status` | Band copy | Treatment |
|---|---|---|
| `active` | `● Running · {elapsed-live}` | `--primary` text, **no frame** |
| `active`, `claimed_at == null` | `Waiting to start` | muted, no frame, **no clock at all** |
| `paused` | `Paused for your answer · {elapsed-live}` | `--warning` text, no frame |
| `cap_paused` | `Paused at the step limit — it stopped after the maximum number of steps. · {elapsed-live}` | **amber FRAMED** (129-C tier 2) |
| `completed` | `✓ Complete · {elapsed-terminal}` | `--success` glyph, `--foreground` text, no frame |
| `failed` | `✕ Failed at "{step title}" · {elapsed-terminal}` | **red FRAMED** (129-C tier 3) |
| `cancelled` | `⊘ Cancelled · {elapsed-terminal}` | **dim**, no frame (129-C tier 1 — the user did it on purpose) |
| anything else | `State unknown — this run reported a state we don't recognise.` | muted, framed neutral |

**Glyph audit for the band:** `●` `✓` `✕` are inherited from `STATUS_META` (`PhaseCard.tsx:67-79`);
`⊘` is inherited from 129-C / `references/run-state-honesty.md` tier 1. **`‖` is DELETED** — sketch
154 flagged it as net-new for `cap_paused`, and this contract refuses it: the band's word carries
the state, so the phase ships **zero net-new marks anywhere**, canvas or chrome (D-188-06, applied
one step further than the sketch proposed).

**The band names the step by TITLE, never by index.** This is deliberate and it resolves sketch
154's What-to-Look-For #4: on a 1040px viewport a 5-phase spine (1540px) puts the last node
off-screen, so a failure on the final step would be invisible. Naming the step in the band makes the
fact legible with the node off-screen, at zero canvas diff. *(Deferred: auto-panning the canvas to
the active/failed step. Re-open trigger: an operator reports hunting for the step.)*

### The elapsed figure (D-188-18) — both strings, and the null case

`workflow_runs` has **no `started_at` / `completed_at`** (measured, `full-schema.sql:1947-1962`).
The anchor is `claimed_at`, and the label says so in plain words.

| Case | Visible string | ⌥ Technical names ON appends (11px mono) |
|---|---|---|
| Live (`active` \| `paused` \| `cap_paused`), `claimed_at != null` | `{elapsed} since it started processing` | `claimed_at 2026-08-05T14:03:11Z` |
| Terminal (`completed` \| `failed` \| `cancelled`) | `Ran for {elapsed} — from when it started processing to its last update` | `claimed_at 2026-08-05T14:03:11Z → updated_at 2026-08-05T14:09:52Z` |
| `claimed_at == null` | **`Waiting to start`** — no number, no clock, no "0s" | `claimed_at null` |

`{elapsed}` format: `< 60s` → `12s` · `< 60m` → `4m 12s` · else → `1h 06m`. It ticks once per second
while the run is live and is **frozen** at `updated_at − claimed_at` once terminal.

> An unlabelled clock that silently means *since queued* is a lie the moment a run waits. That is
> why the null case shows **no number at all** rather than a zero.

## The Status Ring (sketch 153-A) — buildable values

The 62×62 icon well becomes the status dial. **The arc SHAPE is the state; colour only ever
reinforces.** The ring spends **no badge slot, no `stepNumber`, no `technicalLine`, and no glyph**.

### Placement

The ring is a **sibling of the 3D-mark span, rendered immediately BEFORE it** inside
`PhaseNodeCard`, so the mark always paints above the arc.

```
absolute · left-1/2 · top-[-31px] · h-[72px] w-[72px] · -translate-x-1/2 · z-[5] · pointer-events-none · aria-hidden="true"
  └ <svg viewBox="0 0 72 72" class="block h-full w-full overflow-visible">
```

- `top: -31px` = the well's `-26px` minus `(72 − 62) / 2 = 5`. Concentric with the well.
- `z-[5]` sits **below** the ⛨ seal (`z-[6]`) and the verdict mark (`z-[8]`). None of the three ever
  overlap geometrically (ring spans x 94…166; seal 222…243; verdict −8…14), so `z` is hygiene, not
  arbitration.
- The ring stroke circle is `d = 68px` on a 72px box — **3px clear of the 62px well on every side**,
  so it never touches the 3D mark or its tint gradient.
- ⚠ **`overflow-hidden` is forbidden** on the ring, the card, the node box, and every element
  between `.react-flow__node` and the card (D-188-07(1) — the mark already overflows upward by 26px
  and the ring by 31px). `overflow-visible` on the `<svg>` is belt-and-braces.

### Geometry

`r = 34` on a `72 × 72` viewBox ⇒ **`C = 2π·34 = 213.628`**.
Track: `fill:none; stroke: hsl(var(--muted-foreground) / 0.35); stroke-width: 2.5`.
Arc: `fill:none; stroke-width: 3.5; stroke-linecap: round`.

⚠ **Gaps are placed with `stroke-dashoffset`, NEVER with a rotation.** Setting the SVG `transform`
attribute *and* CSS `transform-box`/`transform-origin` composes them and pivots the arc about a
**doubled** offset — that bug shipped in the sketch's first two drafts and put the amber gap in the
wrong quadrant. An SVG `<circle>` starts at 3 o'clock and runs clockwise, so
`3 o'clock = 0 · 6 = .25C · 9 = .5C · 12 = .75C`, and a gap whose centre must sit at path position
`p` needs:

```
offset = (D + G/2) − p
```

**Compute every number from that formula in code. The decimals below are the expected results, for
falsification — not literals to paste.**

| Reading | `stroke-dasharray` | `stroke-dashoffset` | Animation | Stroke |
|---------|--------------------|---------------------|-----------|--------|
| `not-started` | *(no arc element at all — track only)* | — | none | — |
| `running` | `0.26C 0.74C` → `55.543 158.085` | 0 (placement is irrelevant — it spins) | `ringspin 1.5s linear infinite` | `--primary` |
| `done` | *(none — an unbroken circle)* | — | none | `--success` |
| `waiting-for-you` | `D G` where `G = 0.26C`, `D = C − G` → `158.085 55.543` | `(D + G/2) − 0.75C = 25.635` | none | `--warning` + the pause chip |
| `failed` | `d1 g1 d1 g1` where `d1 = 0.42C`, `g1 = 0.08C` → `89.724 17.090 89.724 17.090` | `(d1 + g1/2) − 0.375C = 18.158` | none | `--destructive` |
| `skipped` | `5 7` | 0 | none | `--muted-foreground` |
| `unknown` | `1.5 6` | 0 | none | `--muted-foreground` |

**The pause chip** (`waiting-for-you` only) sits IN the ring's 12-o'clock gap: `absolute left-1/2
top-[-37px] -translate-x-1/2 z-[9] flex gap-[3px] rounded px-[5px] py-[3px] bg-background border
border-[hsl(var(--warning))]`, containing **two `3px × 9px` rectangles** filled `--warning`.
They are `<span>` elements — **not** the `‖` character. This is exactly how D-188-06's zero-net-new-
glyph rule is satisfied while still giving the waiting state a mark.

### Motion

One keyframe, added once to `index.css` under the existing `@layer utilities`:

```css
@keyframes ringspin { to { transform: rotate(360deg); } }
.canvas-ring-spin { transform-box: view-box; transform-origin: 36px 36px; }
@media (prefers-reduced-motion: no-preference) {
  .canvas-ring-spin { animation: ringspin 1.5s linear infinite; }
}
```

- **`.spin` is the ONLY transform anywhere in the ring.** Nothing else may set `transform`,
  `transform-box` or `transform-origin` on an arc — that is the composition bug above.
- **Reduced motion is safe by construction:** with the animation suppressed, `running` renders a
  static 26%-covered arc while `waiting-for-you` renders a 74%-covered arc with a two-bar chip.
  They remain unmistakable without motion.
- Flag-off byte identity holds by the same argument as the shipped xyflow stylesheet: these rules
  only match elements that never enter the DOM while `visual_workflow_canvas` is off.

### ✅ The greyscale acceptance clause (sketch 153's whole acceptance test — a BUILD CRITERION)

**With colour switched off, all seven readings must remain distinguishable by shape alone.** Each
row below states the shape property that is unique to it — a checker or auditor asserts *this*, not
"they look different".

| Reading | Unique shape property (colour off) | Non-colour text carrier | Assistive carrier |
|---------|------------------------------------|-------------------------|-------------------|
| `not-started` | **the only reading with no arc** — the track exists, nothing has travelled it | visible run line `Not started` | node aria-label suffix |
| `running` | **the only moving arc**; static, the only *short* single arc (26% covered) | `Running` | ″ |
| `done` | **the only closed, unbroken ring** | `Complete` | ″ |
| `waiting-for-you` | **the only ring with ONE wide gap, at 12 o'clock, with a two-bar chip inside it** | `Paused for your answer — it needs your reply before it can continue` | ″ |
| `failed` | **the only ring snapped into TWO arcs**, gaps at ~1:30 and ~7:30 | `Failed — {clause}` | ″ |
| `skipped` | **evenly dashed all the way round** (~11 coarse dashes, `5 7`) | `Skipped — the run took a different path` | ″ |
| `unknown` | **the only dotted ring** — fine sparse dots (`1.5 6`), deliberately not a closed ring | `State unknown — we can't tell what happened to this step` | ″ |

**Three carriers per reading, and colour is never one of the first two:** ring shape → visible run
line (real text, ≥7:1 on `--background`) → node accessible name. Colour is the fourth. This exceeds
WCAG 1.4.1 and matches the shipped `STATUS_META` discipline (glyph + REAL text + AA token), which is
the vocabulary this canvas is the business twin of.

**⚠ Never use `--muted-foreground-dim` — or any panel-scoped `--panel-*` token — for a meaningful
run-state string.** `--panel-*` tokens are contrast-tuned against `--panel-surface`; this surface
sits on `--background`.

## The Card Body Budget (D-188-17) — ONE budget, not three slots

154-A is the first thing to spend the card's free vertical space, and it competes with the Phase-187
⌥ subtitle and the still-free `technicalLine`. **This contract plans the card body as one budget
with an explicit stacking order and an explicit decline.**

### Stacking order inside the 248px card (`pt-[42px] px-5 pb-5`, `text-center`)

| # | Element | Size / class | Lines | Present when |
|---|---------|--------------|-------|--------------|
| 1 | **Title** | 14px/600 Manrope, `truncate` | 1 (hard) | always — shipped |
| 2 | **Subtitle** | 11px/400 Inter, `mt-1 leading-snug`, wraps | ≤ 2 | always — shipped; ⌥ swaps its CONTENT (187-09), never its presence |
| 3 | **Run line** ← NEW, 188 | 11px/400 Inter, `mt-1 leading-snug`, `line-clamp-2` | ≤ 2 | **whenever the canvas is in run mode** (i.e. `status` supplied) — including `Not started` |
| 4 | ~~`technicalLine`~~ | 10px mono | 0 | **NOT PASSED by this phase** — see the decline below |
| 5 | **Badge row** | `StatusChip`, `mt-2` | ≤ 1 row | shipped; **188 spends ZERO badge slots** |

### The three rules that make it one budget

1. **The run line is ALWAYS rendered in run mode, including for `Not started`.** If it appeared only
   for terminal readings, every card would change height as the run progressed — reflow on a live
   canvas, on the exact surface a non-technical person is watching. Constant height is why
   `NODE_MIN_HEIGHT` goes `104 → 120` for the whole run view rather than per-node.
   *(Edges are unaffected either way: `EDGE_ANCHOR_Y: 28` is measured from the node TOP, which is
   precisely what D-183-12 exists for.)*

2. **`technicalLine` is DECLINED by Phase 188.** Phase 187-09 left it "notionally free for 188"; 188
   chooses not to spend it, which is what dissolves the three-way competition D-188-17 warned about.
   Declining a slot is a decision, recorded here rather than discovered later.
   *Re-open trigger:* Phase 189's external-action node, or the first time a run reading genuinely
   needs a machine identifier on the face.

3. **When a long failure clause meets a long ⌥ subtitle, the RUN LINE clamps and the SUBTITLE does
   not.** The subtitle under ⌥ carries the whole slug — that is the entire reason 187-09 moved the
   reveal out of the truncating title slot, and re-truncating it here would undo a shipped fix. The
   run line is `line-clamp-2` and its clause set is bounded to three short fixed strings, so the
   clamp is a guard, not a routine event.
   **Worst measured case:** title 1 line + ⌥ subtitle 2 lines + run line 2 lines + 1 badge row
   ⇒ card height ≈ 42 + 17 + 34 + 34 + 30 + 20 ≈ **177px**. Cards grow downward from
   `NODE_MIN_HEIGHT`; the spine lane and the edge baseline do not move.

### The card border — precedence, and what may claim it

The shipped border ternary is `selected > grounded > default`, "mutually exclusive on purpose — one
border-colour utility per state". 188 prepends one branch:

**`run state (when supplied) > selected > grounded > default`**

This can never actually contend, and that is by design: **the run surface renders the canvas with
`selectedSlug={null}` and no `onSelectNode`, so no node is ever selected there; the Builder never
supplies `status`, so no node ever has a run reading there.** The two states are mutually exclusive
*by surface*.

| Reading | Border |
|---------|--------|
| `running` | `border-primary` |
| `waiting-for-you` | `border-[hsl(var(--warning))]` |
| `failed` | `border-destructive` |
| `done` · `not-started` · `skipped` · `unknown` | **unchanged** — falls through to `grounded` / default |

*Complete does not recolour the border.* The closed ring says it; painting every finished node green
floods the canvas exactly as the run ends and spends the 10% budget on the least urgent news.

### Hard invariants this phase may not break (typecheck- or test-enforced)

- **A third badge is a TYPECHECK ERROR** — `BadgeSlots` is a max-2 tuple. 188 spends **zero** slots;
  slot 1 stays empty and reserved for Phase 189.
- **No focusable control may live inside the card** — one tab stop per node. The run line is a `<p>`.
  No tooltip trigger, no button, no `tabIndex`, no click handler.
- **The ⛨ seal owns top-right and may NEVER be conditional on run state.** It renders **identically
  at all SEVEN readings** (D-188-04 clarifies the SPEC's "six"): same classes, same text, same
  position. Its own background and border are what let it survive the border being overwritten.
- **No `overflow-hidden`** anywhere in the node subtree or its wrapper.
- **`stepNumber` stays unrendered** — `phase_index` does not reach the face (D-183-07).
- Every authored string (workflow name, phase titles) renders as a plain React text child or a
  `title=` value — **never `dangerouslySetInnerHTML`** (T-124-01).

## Two Facts on One Node — the waiting `llm_human_input` step

A waiting human-input node draws **both** the shipped design-time badge and the run-time ring. They
must read as **two facts**, not one thing said twice. Four separations, all structural:

| Separation | Design-time fact | Run-time fact |
|---|---|---|
| **Channel** | word-badge in the badge row, **bottom** of the card | ring geometry **above** the card + the run line in the body |
| **Words** | `Waits for you` (shipped, unchanged) | `Paused for your answer — it needs your reply before it can continue` |
| **Grammar** | a property of the step: it *will* pause | a state of the run: it *is* paused, now, and nothing moves |
| **Colour** | `StatusChip` tone `primary` (shipped, unchanged) | `--warning` — arc, chip, border |

**Lifetime is the reading.** The badge is true of the step before anything has ever run and remains
true after the run ends. The ring exists only while the run is at that step. On a node that has
finished, the badge is still there and the ring reads `Complete` — which is precisely the pair a
user needs to see to learn what the badge meant.

**Req 5's mechanical acceptance:** the two strings are not equal, and differ in verb (*waits* vs
*paused*), object (*you* vs *your answer*) and aspect — not by tense. They are also deliberately
distinct from `PhaseCard`'s `llm_human_input` **type** label `Needs you`, which is a phase-type
label, not a run state.

## The Run Surface Layout

`ActiveView` gains one member, `"workflow-run"` (11 → 12). **No router** — the three-homes contract
holds. It renders in the **non-chat `else` branch** of `ChatLayout` (`<main className="flex-1
overflow-hidden">`), immediately **before** the trailing `<KnowledgeHealthPage />`.

> ⚠ That trailing element is a **positional fallback**, not a `default:` that throws. Adding the
> union member without adding a branch renders the Knowledge-Health page. Five inline comments in
> the file already say so.

**The free win:** the message list, the composer and the `<WorkspacePanel>` all live inside the
`activeView === "chat" ?` branch. A view on the `else` side renders **none** of them — so SPEC Req
6's "no message list and no composer" is satisfied **structurally**, and its test asserts a property
of the layout rather than a discipline. **The cost that comes with it:** no `WorkspacePanel`, so the
run surface renders its own deliverable list.

### Primary visual anchor (Checker FLAG applied — Dimension 2, 2026-08-05)

**The canvas region is the focal point of this surface, and within it the running node's status ring
is the single primary visual anchor** — it is the only element on the page carrying `--primary`
motion, and it is what the eye should find first at every moment of a live run. Secondary is the
**one-line run band** (the run-level verdict). Tertiary is the **deliverable list**, which earns
attention only once the run is terminal. The **header** is orientation, never a focal point — it
spends no accent except the "Open the chat thread" seam link.

This ordering is what the region stack below encodes; it is stated here so no future addition
competes with the ring for the accent budget (see the closed 5-item reserved-for list under Color).

**Layout decisions, stated:**

- **Full-width, not push/split.** A 5-phase spine measures 1540px (`4 × PITCH_X + NODE_WIDTH`);
  constraining it behind a panel column would clip the surface this phase exists to show. No
  `max-width` on any region — all four share `px-6`, so they align without a wrapper.
- **The canvas region is the only flexible one.** Header, band and deliverable are intrinsically
  sized; the canvas takes `flex-1 min-h-0`.
- **The ⌥ toggle stays where it ships** — inside the canvas header. It already reads the shared
  `TechnicalNamesProvider`, so the run header's `claimed_at` reveal and the canvas's subtitle reveal
  flip together, from one control.
- **`👁 View only` is correct on a run surface and is NOT reworded.** You genuinely cannot edit a
  running workflow's definition, and rewording it would spend insertions from the G-5 cap on
  `WorkflowCanvas.tsx` for zero honesty gain.

### Mobile (< 768px)

Same four regions, same order, stacked. Header wraps to two rows (identity row, then status row).
The canvas region keeps `min-h-[320px]` and relies on React Flow's own pan/pinch; **no alternate
mobile spine is designed**. The deliverable region drops its `max-h` and flows. The run band stays
one line and truncates — it is the only element whose single-line rule is absolute, because it is
the live region.

### The terminal-run render (no live stream)

Identical layout. Three differences, all subtractive:

1. The band is **frozen** and uses the terminal elapsed string.
2. **No animation anywhere** — no ring spins, because no reading is `running`.
3. First paint is seeded from the inline `run.phases` array returned by `GET /workflow-runs/{id}`,
   so the spine never flashes empty; **that seed is mapped through the same `canvasReading()`
   function** as the live slice. There is no second derivation and no second vocabulary — Req 8's
   grep must return zero either way.

## Accessibility Contract

### Focus order on the run surface

| # | Target | Notes |
|---|--------|-------|
| 1 | `‹ Workflows` | first, because it is the escape |
| 2 | `Open the chat thread` | the primary CTA |
| 3 | `⌥ Technical names` | shipped `TechnicalNamesToggle`, `aria-pressed`, inside the canvas header |
| 4…n | one tab stop **per node** | React Flow's own node wrapper (`role="button"`). **No focusable control inside a card** — that invariant is what keeps this list at one stop per step. |
| n+1… | the deliverable list | `role="list"`; each row a `<button>` whose accessible name is `Download {filename} ({size})` |

Nothing else is focusable. The ring, the pause chip, the ⛨ seal and the verdict mark are all
`pointer-events-none` with no role, no `tabIndex`, no handler.

### The node's accessible name

The shipped name is built by `canvasModel.ariaLabelFor` as
`Phase 4: Draft the renewal letter (llm_agent)` and is set as an explicit `aria-label` on the node
wrapper — so **the card's inner text is not part of the node's accessible name**. A screen-reader
user tabbing the spine would therefore hear no run state at all.

**Contract:** the run reading joins the node's accessible name, appended in `WorkflowCanvas`'s
`settledNodes` memo beside the existing `data` merge:

```
ariaLabel: run ? `${node.ariaLabel} — ${run.label}` : node.ariaLabel
```

`run.label` is the already-worded string supplied by the page, so **`WorkflowCanvas` imports no
vocabulary table and derives nothing** — it stays a pass-through. This line is inside the G-5 diff
cap (RESEARCH itemises the prop mirror at ~10 ins / 2 del against a ≤15 / ≤4 recommendation; this
adds one).

> **Known residual, recorded rather than fixed:** the shipped aria-label already exposes the raw
> `phase_type` (`llm_agent`) and the ordinal. It is shipped Phase-183 vocabulary shared with
> `PhaseSpineGraph`, and re-cutting it is out of SPEC scope. Req 2's grep is scoped to the run-state
> **render path**, which this is not. *Re-open trigger:* the first phase that touches
> `ariaLabelFor` — plain-language the label there, once, for both views.

### The ring's role

**`aria-hidden="true"` on the ring wrapper. No `role="img"`, no `role="progressbar"`, no `sr-only`
duplicate of the reading.** The visible run line already carries the word as real text, and the node
name carries it again for focus; a third announcement would make one step speak three times. *(The
`role="progressbar"` treatment belongs to the developer `PhaseCard` and stays there — this phase
does not re-home or re-style `PhaseTimeline`.)*

### Live-region policy — exactly one, and one alert

| Region | Politeness | Announces |
|--------|-----------|-----------|
| **The run band** | `aria-live="polite"` `aria-atomic="true"` | run-level state changes and the elapsed sentence |
| **A failure notice** | `role="alert"` (assertive) | fires **once**, on the transition into `failed` / `cap_paused` |

- **Per-node state changes are NOT announced.** A 5-phase run produces 10+ transitions; announcing
  each would render the surface unusable. The band is the announcer, matching the shipped panel's
  polite-announcer / separate-alert split (`PhaseCard.tsx:13-27`).
- The elapsed figure **must not** live inside the polite region's atomic content while ticking —
  a per-second announcement is a screen-reader denial of service. Render the ticking number in a
  sibling `aria-hidden` span and keep the band's live content to the state sentence.
- `aria-busy="true"` on the canvas section while the run status is live; flips `false` at terminal.
- The canvas region keeps its shipped section label; **`Workflow canvas (read-only)`** is what
  `editable={false}` already produces and is correct here.

### Reduced motion

`prefers-reduced-motion: reduce` suppresses the ring spin (see § Motion). No other motion is
introduced by this phase — the shipped card is "completely still", and motion keys off **run state**,
never off selection.
