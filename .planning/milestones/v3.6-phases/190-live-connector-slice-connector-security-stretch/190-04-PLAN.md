<!-- The amendment's three structural reasons, from CONTEXT D-01, to be authored VERBATIM in substance -->

1. **A third-party MCP server makes the outbound call itself.** Our egress guard would guard
   exactly one hop — the hop to the MCP server — and NOT the hop to Slack / Jira / the SMTP
   host. Through a remote MCP server, CONN-03 SC#2 is unprovable, because the socket that
   matters is in someone else's process.
2. **Credentials would live in the MCP server's config, not in our DB**, so CONN-03 SC#4 would
   be satisfied for a credential that is not the one doing the sending.
3. **Running MCP servers locally is a second runtime**, which red line D-14 of the milestone
   forbids in as many words — process supervision, lifecycle, sandboxing, a new failure class,
   inside a phase gated on `threats_open: 0`.

**What is NOT amended:** the MCP-first substrate direction, the "be callable BY the tools users
already run" bet, first-party-thin as exactly this three-capability slice, and broad catalog
deferring to Open Platform. **What moves is only the clause that said the first three
connectors would ride an MCP client on day one.**

**The re-open trigger, expressed as a check rather than a memory:** the MCP client arrives with
Open Platform (SEED-013/014). The observable is a phase number appearing on
`.planning/ROADMAP.md` for SEED-013. At that point each adapter either becomes an MCP client
call behind the unchanged `ConnectorAdapter` protocol, or is retired.

**The measured fact that makes this an honest amendment rather than a retreat:**
`grep -rni "\bmcp\b" backend/app --include=*.py` → **0**. Zero MCP code exists. "MCP-backed"
was always a direction, never infrastructure. `backend/tests/unit/test_189_no_egress.py`'s
Case A fences that zero, and its continued passing is part of this amendment's evidence.
</interfaces>
