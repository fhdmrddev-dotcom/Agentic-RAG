<objective>
Add the two transport binders to `egress.py`: a pinned HTTP sender and a pinned SMTP opener,
both consuming the SAME validated `(ip, hostname, port)` triple plan 190-02 produces.

Purpose: validating a hostname and then handing that hostname to the client leaves a
DNS-rebinding TOCTOU window between validation and connect. Research verified in this venv that
**both** transports are pinnable — httpx via `request.extensions["sni_hostname"]` (confirmed
present in the installed `httpcore`), smtplib via the measured fact that `SMTP.connect()` never
assigns `self._host`. **CONTEXT D-07 step 5's escape hatch is therefore not needed for the
mechanism** — but a DIFFERENT residual risk is real and must be named: both recipes depend on
non-public attributes.

Output: one validator, two thin binders, one honest residual risk with a fence that bites.
</objective>

<!-- Measured in backend/venv: httpx 0.28.1, Python 3.12.6, certifi 2026.02.25, idna 3.11 -->

**httpx** — `httpcore` passes `sni_hostname` straight into `start_tls(server_hostname=...)`,
independently of the host used for the TCP connection. Verified present:
```
$ python -c "import inspect, httpcore._async.connection as ac; print('sni_hostname' in inspect.getsource(ac))"
True
```

The recipe (research §R10):
```python
ip, hostname, port = egress.validate_http(url)          # the PINNED triple
pinned = url.copy_with(host=ip)                          # TCP goes to the validated IP
req = client.build_request("POST", pinned, json=..., headers={..., "Host": hostname})
req.extensions["sni_hostname"] = hostname                # SNI + cert hostname verification
resp = await client.send(req, follow_redirects=False)    # D-07 step 4, set EXPLICITLY
```

**smtplib** — the measured fact that makes pinning work:
```
$ python -c "import inspect, smtplib; print('_host' in inspect.getsource(smtplib.SMTP.connect))"
False
$ python -c "import smtplib; s=smtplib.SMTP_SSL(timeout=1); print(repr(s._host))"
''
```
`SMTP.connect()` never assigns `self._host`, and a bare construction does not connect. Both TLS
paths derive the certificate hostname from `self._host`:
`SMTP_SSL._get_socket` → `wrap_socket(..., server_hostname=self._host)`;
`SMTP.starttls` → `wrap_socket(self.sock, server_hostname=self._host)`.

**⚠ THE HONEST RESIDUAL RISK — RESIDUAL-190-01.** Research's wording supersedes CONTEXT's:

> Both pinning recipes depend on non-public attributes. `smtplib.SMTP._host` is private and
> `SMTP.connect()`'s non-assignment of it is an implementation detail, not a documented
> contract; `httpcore`'s `sni_hostname` request extension is an httpx/httpcore internal
> convention rather than a versioned public API. A CPython or httpx minor upgrade could
> silently break the pin **while every functional test still passes** — the connection would
> simply re-resolve and still work. **Mitigation (a test, not a sentence):** assert
> `"_host" not in inspect.getsource(smtplib.SMTP.connect)` and
> `"sni_hostname" in inspect.getsource(httpcore._async.connection)`, each with its own positive
> control. **Trigger:** any Python or httpx version bump in `requirements.txt`.

**⚠ `smtplib` IS BLOCKING.** `_exec_external_action` is `async def`, and CLAUDE.md's D-v2.5-01
forbids blocking I/O on the event loop. The SMTP binder's public entry must be the wrapped one.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| validated hostname → the actual socket | The TOCTOU window a pin closes; the DNS answer may change between the two |
| remote server → our client | A 30x is the remote deciding where we connect next; a large body is the remote deciding how much memory we spend |
| stdlib / httpcore internals → our security property | Non-public attributes can vanish in a patch release with every functional test still green |
