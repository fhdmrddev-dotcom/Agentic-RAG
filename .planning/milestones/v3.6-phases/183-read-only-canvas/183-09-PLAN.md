- **Why the Spine gets no click-away — the honest reason, so nobody re-derives a wrong one.**
  Two facts, and only the second one is the reason:

     recommended set at error severity (incl. `no-noninteractive-element-interactions` and

     container would break a gate that is clean today. React Flow's `onPaneClick` is a component
     PROP, so the canvas half is lint-safe.

     scans JSX attributes, not `addEventListener`, so the same imperative `useEffect` pattern
     this plan already uses for Escape (Part C.2) would sidestep it entirely. **The real reason

     pane element, so "the user clicked empty space" is free and unambiguous. The Spine has no
     pane — a correct click-outside there has to positively EXCLUDE every interactive child of

     per control, landing in `WorkflowBuilderPage.tsx` — a G-5 ledger file that Phase 184 is
     about to reopen as the 3rd authoring door.
