<objective>
Lay the carrier: widen `_resolve_thread_scoping` to return the Expert bundle id, and thread that id
through `RunContext` → `ToolContext` → sub-agent `sub_ctx` as an additive, default-`None` field.

Purpose: Phase 263 shipped the born-for provenance column and taught **resolve** time about it. The
**load** path has no way to even know which Expert is active — `ToolContext` carries 30+ fields and
none of them is the bundle. Nothing in this plan changes behaviour; it makes the later widening
*possible*. This is deliberately the FIRST wave (**D-264-03a**) because the arity change alone breaks **ten** unpack
sites inside `pytest tests/unit`, the gate with **zero headroom** — every later wave must start from
a green 71.

Output: a 5-tuple `_resolve_thread_scoping`, a `born_for_bundle_id` field on both dataclasses, four
wired build sites, one propagated `sub_ctx`, ten updated test unpacks, and a source-level fence that
counts all of it.
