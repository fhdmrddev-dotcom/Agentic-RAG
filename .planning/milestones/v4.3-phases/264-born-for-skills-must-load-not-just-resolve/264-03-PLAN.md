<objective>
Make the born-for arm reachable from the load path, at exactly the three call sites that serve an
Expert — and state the fourth site's refusal in source rather than leaving it implied.

Purpose: this is the defect. `expert_service` admits a born-for skill at **resolve** time and that
result becomes the **catalog only** — names and descriptions, no instruction body. The body is
fetched later by `load_skill`, through a predicate that has never heard of
`born_for_expert_bundle_id`. For every org member but the author, the run falls into the miss branch
and returns an error listing "loadable" names that **excludes the one the prompt just promised**.

Output: a resolver whose signature carries the decision, three widened sites, one deliberately
unwidened site with its reason in the code, and the first test in this repository that drives
`load_skill` as a non-author org member without neutralising the predicate.
</objective>
