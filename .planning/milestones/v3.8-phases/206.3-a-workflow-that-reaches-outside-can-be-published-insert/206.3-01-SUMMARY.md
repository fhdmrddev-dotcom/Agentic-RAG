# Phase 206.3-01 Summary: A Workflow That Reaches Outside Can Be Published

## 1. Problem & Root Cause

In Phase 206.2, workflows with MCP external action steps passed Stage 1, 2, and 2.6 of the publish gauntlet, but failed during Stage 3 (the Golden Run) with `blocked_stage: golden_run_error` and a bare named failure string `"None"`.

Investigation revealed two root causes:
1. **`KeyError: None` in `_exec_external_action` during golden runs**:
   `phase_types.py` used `_record()` to return output with `status = "recorded_not_sent"`. `_record()` called `_external_action_body(capability, resolved)`. For MCP external actions, `capability` is `None` or omitted. `_external_action_body` indexed `_EXTERNAL_ACTION_PHRASE[capability]` and `_EXTERNAL_ACTION_NEGATION[capability]`, raising `KeyError: None`.
2. **Exception swallowing / type loss in `publish_service.py`**:
   `publish_service.py:313` captured the exception as `str(e)`. Since `str(KeyError(None))` evaluates to `"None"`, the author was presented with `named_failures: ["None"]` with no exception type and no attached `golden_run_id`.

## 2. Changes Made

### A. Dedicated MCP Body Composer (`backend/app/services/harness/phase_types.py`)
- Created `_external_action_mcp_body(tool_name: str, resolved: dict) -> str` containing zero indexes into capability dictionaries.
- Updated `_exec_external_action`'s `_record()` helper to branch on `if mcp_tool_name:` and invoke `_external_action_mcp_body`.

### B. Exception Transparency & Golden Run ID Preservation (`backend/app/services/harness/publish_service.py`)
- Updated `publish_workflow` stage 3 error handling:
  - Formats exception as `f"{type(e).__name__}: {e}" if str(e).strip() else type(e).__name__`.
  - Attaches `golden_run_id` to both `harness_audit` and the `_block("golden_run_error", ...)` return dict.
- Updated `_drive_golden_run` to preserve `golden_run_id` when returning on failure.

### C. Comprehensive Unit Testing (`backend/tests/unit/test_publish_service.py`)
- Added 5 unit tests in `test_publish_service.py`:
  1. `test_an_mcp_external_action_workflow_publishes`: Proves an MCP workflow runs the gauntlet, records `recorded_not_sent` in Stage 3, and passes Stage 4 to reach `published: true` with version increment.
  2. `test_live_mcp_run_still_stops_at_approval_checkpoint`: Proves that live runs (with `is_golden_run=False`) still stop at the D-04 human-in-the-loop approval checkpoint when `action_risk_armed=True`.
  3. `test_golden_run_named_failure_preserves_exception_type`: Negative control asserting that exceptions in golden runs preserve their class name and description.
  4. `test_golden_run_failure_preserves_golden_run_id`: Verifies that `_block` return dictionaries carry `golden_run_id` when the golden run fails after creation.
  5. Integration with mocked and live registry components.

### D. End-to-End Browser Drive (`scripts/drive_phase_206_3_publish.py`)
- Programmed a Playwright Chromium drive script:
  - Authenticates via Supabase GoTrue magic link unwrapping `#access_token=...`.
  - Navigates to Workflows library and opens the builder for an MCP workflow draft.
  - Clicks `Publish`, enters golden input, and executes the 8-stage gauntlet.
  - Asserts on the verdict modal / post-publish CTA:
    - `Published <name> v1. Ready to run it.`
    - Database row status is `published` with `version >= 1`.
    - Audit log in `harness_audit` verifies `publish_attempted`, `judge_verdict` (`overall_passed: true`), and `publish_succeeded`.

### E. Hot-File Ledger & CLAUDE.md Governance Updates
