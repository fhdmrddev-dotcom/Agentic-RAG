## 1. Executive Summary & Root Cause Confirmation

In Phase 206.2, live verification in Chromium reproduced a publish blocker on an MCP-shaped external action workflow:
- `blocked_stage`: `"golden_run_error"`
- `named_failures`: `["golden run could not complete: None"]`
- `golden_run_id`: `null`

### The Diagnosis
1. **The Approval Checkpoint Is Innocent**: `test_v20_an_external_action_workflow_publishes` in `test_publish_service.py` passes because `is_golden_run=True` on `ctx` intentionally skips the interactive approval pause (D-19).
2. **The Real Culprit**: In `backend/app/services/harness/phase_types.py:2322-2324`:
   - Gate 1 checks `if getattr(ctx, "is_golden_run", False): return _record(...)`.
   - `_record(...)` calls `_external_action_body(capability, resolved)`.
   - For MCP steps, `capability` is `None` (it carries `tool_name` instead of `capability`).
   - `_external_action_body` attempts `_EXTERNAL_ACTION_PHRASE[capability]`, leading to `_EXTERNAL_ACTION_PHRASE[None] -> KeyError(None)`.
3. **The Exception Swallowing Trap**:
   - In Python, `str(KeyError(None))` is literally `"None"`.
   - In `backend/app/services/harness/publish_service.py:320`, `f"golden run could not complete: {e}"` formats into `"golden run could not complete: None"`.
   - Because `_drive_golden_run` raised before returning its tuple, `publish_workflow` only had `run_id=None`, returning `golden_run_id: null` even though the run row was inserted into `workflow_runs`.

## 2. Locked Constraints & Decisions

- **D-206.3-01 (TDD Gate: Failing Test First)**:
  - Add `test_an_mcp_external_action_workflow_publishes` in `backend/tests/unit/test_publish_service.py`.
  - Driven before modifying `phase_types.py`, verifying the exact exception (`KeyError: None`) and failing state.
- **D-206.3-02 (D-16 / D-17 / D-19 Governance: Suppress Live Send During Golden Run)**:
  - Golden runs remain unattended. MCP-shaped external action steps MUST NOT perform live network requests during publish checks.
  - Golden runs must record `status='recorded_not_sent'` with body `"NOT SENT — recorded only."` and `recorded_intent={"tool_name": tool_name, "capability": "mcp", "inputs": resolved}`.
- **D-206.3-03 (Exception Transparency & Run ID Preservation in `publish_service.py`)**:
  - In `publish_service.py`, `except Exception as e:` must format exceptions with `f"{type(e).__name__}: {e or repr(e)}"`.
  - In `_drive_golden_run`, wrap the inner execution after `create_workflow_run` so that if `run_workflow` raises an unexpected exception, the created `run_id` is retained and propagated to `_block`.
- **D-206.3-04 (Capability Shapes Untouched)**:
  - Shipped test `test_v20_an_external_action_workflow_publishes` and its sibling `test_the_armed_checkpoint_is_not_a_validator` must continue to pass unedited.
