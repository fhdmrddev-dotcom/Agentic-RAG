<objective>
Enable workflows carrying an MCP-shaped `external_action` step to successfully pass the publish gauntlet and reach `published: true`, while ensuring that publish-time golden-run failures honestly report their error details and preserve the `golden_run_id`.

**Purpose:**
In Phase 206.2, live verification in Chromium revealed that an MCP-shaped external action workflow could not publish (`golden_run_error: golden run could not complete: None`). The root cause is that `_exec_external_action` Gate 1 calls `_external_action_body(capability, ...)` which crashes with `KeyError: None` on MCP steps (where `capability` is None). Fixing this completes the end-to-end publish flow for MCP workflows.
</objective>

### Task 3: MCP External Action Body and Recorded Intent in `phase_types.py` (D-206.3-02 / D-206.3-05)
1. In `backend/app/services/harness/phase_types.py`:
   - Create `_external_action_mcp_body(tool_name: str, resolved: dict) -> str` composing:
     ```
     NOT SENT — recorded only.

     What this step would have done
       Action: Call MCP tool '{tool_name}'
       ... (resolved args)

     No external MCP tool was invoked. Nothing left this workflow. This is a record of an intention, not a receipt.
     ```
   - In `_exec_external_action`, update `_record(reason: str) -> dict`:
     - If `mcp_tool_name` is present:
       - Uses `_external_action_mcp_body(mcp_tool_name, resolved)`.
       - Sets `RECORDED_INTENT_KEY: {"tool_name": mcp_tool_name, "capability": "mcp", "inputs": resolved}`.
     - Else:
       - Uses `_external_action_body(capability, resolved)`.
       - Sets `RECORDED_INTENT_KEY: {"capability": capability, "inputs": resolved}`.
   - Update fallback branches in `_exec_external_action` (e.g. unbound connection or disabled connection) to route through `_record` safely for both MCP and capability shapes.
