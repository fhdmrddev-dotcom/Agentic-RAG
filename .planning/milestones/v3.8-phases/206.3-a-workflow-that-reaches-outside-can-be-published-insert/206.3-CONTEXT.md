## 2. Root Cause Analysis (SEED-201 Correction)

### The Refuted Hypothesis
The initial hypothesis in SEED-201 posited that unattended golden runs hang at the approval checkpoint for all external actions. This was **refuted** by `test_v20_an_external_action_workflow_publishes`, which passes and proves that `is_golden_run=True` bypasses the ask-user approval checkpoint per D-19 ("CONFLICT 1").

### The True Root Cause
1. In `backend/app/services/harness/phase_types.py:2322-2324`:
   ```python
   if getattr(ctx, "is_golden_run", False):
       return _record("this is a publish-time golden run — D-16 suppresses the SEND only")
   ```
2. `_record` calls `_external_action_body(capability, resolved)`.
3. For MCP steps, `capability` is `None` (the configuration carries `tool_name` instead of `capability`).
4. `_external_action_body` attempts `_EXTERNAL_ACTION_PHRASE[capability]`, evaluating `_EXTERNAL_ACTION_PHRASE[None]`, which immediately raises `KeyError: None`!
5. In `publish_service.py:312-322`, `except Exception as e:` catches `KeyError(None)`. Because `str(KeyError(None))` in Python is `"None"`, the failure is formatted as `"golden run could not complete: None"`.
6. Because `_drive_golden_run` raised before returning its `(run_id, ...)` tuple, `publish_workflow` defaulted `golden_run_id=None` in `_block`.
