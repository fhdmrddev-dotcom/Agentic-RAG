<objective>
Comprehensively fix all table ingestion and retrieval issues for CSV and Excel documents:

**Problem A (document_tables gap — SEED-149):**
`extract_and_store_tables` routes only PDF/DOCX; CSVs and spreadsheets hit the `else: return` branch,
so the `query_table` tool always returns "No tables found" for these document types.

**Problem B (semantic search header loss — SEED-060):**
`extract_text` for CSV returns flat tab-separated text without column context. When `chunk_text`
splits this on `\n`, all chunks after the first lose the header row entirely. A chunk like
`"Alice\t30\tEngineer"` has no schema — the embedding model cannot know that `30` is Age, not Salary.
The same problem applies to Excel workbooks: rows after splitting lose column identity.

**Problem C (large-file chunking — extension of SEED-060):**
A CSV with 5,000 rows produces one giant text string. `chunk_text` splits it on newlines into
arbitrary-boundary chunks. Even when a header row is present in the original text, it appears only
in the first chunk; all subsequent chunks are schema-blind.

**Solution:**
1. Add `extract_csv_tables` and `extract_excel_tables` to `multimodal_service.py`; route them in `extract_and_store_tables`.
2. Replace the flat CSV/Excel text output in `extract_text` with **header-anchored row batches**:
   each batch of `_TABLE_ROWS_PER_CHUNK = 50` data rows is prefixed with `[Columns: Col1 | Col2 | ...]`.
   Batches are separated by `\n\n` so `chunk_text` treats them as paragraph-level units and will not
   split them away from their header prefix.
3. Add comprehensive unit tests covering all three problems and their edge cases.
</objective>

    ### Problem being fixed
    Current CSV path (lines 312-315) produces: `"Name\tAge\nAlice\t30\nBob\t25"`.
    After `chunk_text` splits on `\n`, chunk 2+ contain only data rows with no column context.

    Current Excel path (lines 302-310) produces:
    ```
    ## Sheet: Revenue
    Year	Q1	Q2
    2023	100	200
    2024	300	400
    ```
    The `## Sheet: Revenue` heading separates well from other sheets, but within a sheet the
    first data row (`Year\tQ1\tQ2`) is the HEADER — and when `chunk_text` splits on `\n`, rows
    after the first chunk lose this schema information.

    ### Solution: add `_TABLE_ROWS_PER_CHUNK` constant and helper `_tabular_text_blocks`

    **Add constant near the top of the file (after existing constants):**
    ```python
    # Number of data rows to include per header-anchored chunk block.
    # Small enough that a block of 50 rows (≈50-200 chars/row × 50 = 2500-10000 chars)
    # fits within the default chunk_size=1000 only when rows are very short.
    # chunk_text will further split large blocks on \n while keeping blocks as units
    # via the \n\n paragraph separator — the header prefix appears in every block.
    _TABLE_ROWS_PER_CHUNK = 50
    ```

    **Add helper function `_tabular_text_blocks(headers, rows, prefix="") -> str`:**
    ```python
    def _tabular_text_blocks(
        headers: list[str],
        rows: list[list[str]],
        prefix: str = "",
    ) -> str:
        """Produce header-anchored text blocks for CSV/Excel data.

        Each block of _TABLE_ROWS_PER_CHUNK data rows is prefixed with:
          [Columns: Header1 | Header2 | ...]
        Blocks are separated by \\n\\n so chunk_text treats them as paragraph-level
        units and will not split a data row away from its column context.

        Args:
            headers: Column names for this table.
            rows:    Data rows (list of string lists).
            prefix:  Optional prefix prepended to each block (e.g., "Sheet: Revenue | ").
        """
        if not headers:
            return ""
        col_line = f"[Columns: {' | '.join(headers)}]"
        if prefix:
            col_line = f"[{prefix}{col_line.lstrip('[')}".rstrip("]") + "]"
        blocks: list[str] = []
        for i in range(0, max(len(rows), 1), _TABLE_ROWS_PER_CHUNK):
            batch = rows[i: i + _TABLE_ROWS_PER_CHUNK]
            row_text = "\n".join("\t".join(str(c) for c in row) for row in batch)
            blocks.append(f"{col_line}\n{row_text}" if row_text else col_line)
        return "\n\n".join(blocks)
    ```

        "application/vnd.ms-excel",
    ):

        wb = load_workbook(io.BytesIO(raw), read_only=True, data_only=True)
        sheet_blocks: list[str] = []
        for ws in wb.worksheets:
            all_rows = [
                [str(c.value) if c.value is not None else "" for c in row]
                for row in ws.iter_rows()
            ]
            non_empty = [r for r in all_rows if any(cell.strip() for cell in r)]
            if len(non_empty) < 2:

                cell.strip() if cell.strip() and not cell.strip().lstrip("-").isnumeric()
                else f"Column {i + 1}"
                for i, cell in enumerate(non_empty[0])

    ### Key invariants to preserve
    - The `extract_text` function is called from two paths: `upload_pipeline` (line 218) and `reextract_document` (line 1176). Both benefit automatically from this change.
    - `chunk_text` splits on `\n\n` first. Each header-anchored block (`[Columns: ...]\nrow\nrow...`) is separated by `\n\n`, so `chunk_text` keeps each block as a unit. Within a block, it falls back to `\n` splitting — but each `\n`-split line is still within the same column-header context window.
    - If a single block (50 rows) is still too large for `chunk_size=1000`, `chunk_text` will split on `\n` within the block. This is acceptable because the `[Columns: ...]` line is always the first line — it will appear in the first sub-chunk. Remaining sub-chunks within the same block lose the header line, but they stay within the same 50-row window (the column-loss is bounded to at most chunk_size chars of data, not unbounded as today).
    - An alternative "repeat header on every sub-chunk" approach would require modifying `chunk_text` itself, which is a larger change with broader impact. Phase 202 can layer that on top if needed.
