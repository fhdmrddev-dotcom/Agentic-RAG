## The two corrections-beside-their-originals

**(a) `ConnectionsTab.tsx:29-34` — D-206.1-08.** The shipped *"CAPABILITY MARKS, NEVER VENDOR LOGOS
(§10 / U-12)"* paragraph is kept **verbatim inside a `SUPERSEDED — do not re-apply` box**, with the
replacement rule beneath it. ⚠ **The correction records why the original's REASONING is obsolete
rather than merely outvoted:** it argued that *"sourcing them from a second package is exactly the
per-surface vocabulary the icon convention forbids"* — and `@lobehub/icons` ships `Github` and
`Google` and **no Slack and no Jira/Atlassian at all**, so it was arguing against a package that
could never have supplied these marks. The vocabulary the convention actually forbids is a **second
HOME for the same mark**, which is why the replacement is ONE module and not three imports.

**(b) `icon-convention.md` §3 — D-206.1-23.** §3's FACT is re-measured TRUE at HEAD and kept
(`direct-hit` genuinely absent, `bullseye` present). Its **MECHANISM** is corrected beneath it: under
`unplugin-icons` with a local collection an absent slug is a **transform-time hard error** and the
suite loads zero tests — so **the import IS the fence**, and what still needs a test is
*resolved-but-EMPTY*. The correction also names a class §3 did not anticipate —
**resolved-but-INVISIBLE** — and points at `connectionMark.tsx`'s ink contract, including its third
arm (never a fill utility on a lucide glyph, whose presentation attributes a CSS rule overrides).
