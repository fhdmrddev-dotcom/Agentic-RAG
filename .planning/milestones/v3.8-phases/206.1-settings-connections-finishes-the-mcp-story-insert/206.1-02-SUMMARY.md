### ⚠ A measured trap the plan did not anticipate: the capture was NOT stable as taken

The first dump printed `id="radix-_r_p3_"`, `id="radix-_r_pc_"` and `id="radix-_r_pl_"` on
three rows whose markup is otherwise character-identical. Radix's `DropdownMenuTrigger` sets
`id={useId()}`, and React's `useId` is a function of **how many components rendered before
it**, not of the row's own markup — so that value moves whenever a case is added *anywhere
above*, which is not a behaviour change and must not be able to redden the pin.

Resolved with **one declared and COUNTED normalization**: the id value is replaced, the
substitution count is returned, and it is asserted at **exactly 1 per row** and **exactly 0
per header**. A ⋯ trigger that stopped rendering yields zero replacements and goes red rather
than quietly passing against a shorter string — normalizing without counting is how a pin
stops watching the thing it names.

### The MCP-row exclusion is a decision, and it is written into the source

Plan 03's `credentialReadingOf` returns `CREDENTIAL_NO_CHECK_FOR_KIND` **unconditionally** for
an MCP row — it ignores `last_checked_at` entirely — so *any* MCP fixture's credential cell
renders different text once wave 3 lands, and no choice of timestamp avoids it. Pinning it
here would have made this baseline booby-trapped by its own phase.

## Deviations from Plan

### 1. ⚠ THE PLAN CONTAINED A GENUINE CONTRADICTION, and it is resolved rather than papered over

The plan requires **both**:

- `data-dense={dense ? "true" : "false"}` on the row — *"always present, both values"* (D-206.1-12;
  an absent attribute reads as falsy to every consumer), **and**
- Task 1's capture *"must pass UNEDITED"* / *"Do not restructure the wide shape"*.

**These cannot both be literally true.** Adding an attribute to the wide row changes the wide
row's DOM by definition, and the capture predates the attribute.

**Resolution — the house precedent, from the very file this idiom was imported from.**
`PhaseNodeCard.test.tsx` faced this exact situation at `199-01` and recorded the answer: *"the
honest move is neither to re-capture nor to abandon the change: it is to keep the capture
VERBATIM and declare the delta as a NAMED, SINGULAR, machine-checked transformation of it."*

So: **not one character of any capture literal is edited.** `withDeclaredDelta` asserts, before
applying anything, that the capture does **not** already contain `data-dense` (the delta is
real) and that the anchor occurs **exactly once** (it is singular) — then adds exactly that one
term at exactly that one position. The header capture takes **no delta at all** and is compared
verbatim, because `data-dense` is a row attribute and a header acquiring one would be new
surface.

**Verified mechanically:** `git diff | grep '^-[^-]'` over the suite returns **2** lines, and
neither is a capture literal — one is the assertion call itself, one is my own Task-2 fixture
(see deviation 3). The acceptance criterion *"no modification to any committed capture literal"*
is therefore satisfied **literally**, not by interpretation.
