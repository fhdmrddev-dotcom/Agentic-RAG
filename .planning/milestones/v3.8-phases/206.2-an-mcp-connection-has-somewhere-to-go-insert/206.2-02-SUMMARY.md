The plan and CONTEXT both said the needle is React 19's `«r0»` form, **not** `radix-…`. Half of
that is right and half is not. Read off a real render at this plan's base, before any edit:


⚠ **The fifth case PASSED at base, and that is worth recording rather than hiding.** Handing the
base component an unknown `shape` prop leaves `capability` `undefined`, so it called
`listConnectorConnections(undefined)` — which the mock answers with every row regardless. That

why the reachability case in the shipped suite is labelled **not SC#4's evidence**.

### The filter order, and why it is load-bearing

The MCP arm filters by `mcp_server_url` FIRST, takes `shapedCount` from that result, and only
then applies `is_enabled`. Counting before the shape filter would report *"every MCP server
connection is switched off"* whenever the only disabled row in the org was a Slack connection.
That case is in the suite by name (`⚠ THE FILTER ORDER — a disabled SLACK row does NOT make the
MCP shape say all-disabled`), because an ordering that is only correct by accident reads
identically to one that is correct on purpose.

### The capability arm is two arms, not one unified expression

`git show c92c4af6:…ConnectionPicker.tsx | grep -n 'rows.filter((row) => row.is_enabled)'` and
the same grep on the working tree return the SAME text (line 275 → line 376). The two filter
chains were deliberately NOT unified into one shared expression: that would rewrite the very
line D-206.2-08 protects.
