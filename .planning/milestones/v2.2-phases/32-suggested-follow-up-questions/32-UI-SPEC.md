## Spacing Scale

Declared values (multiples of 4 — 8-point base scale):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`) | Icon-to-text gap within a pill |
| sm | 8px (`gap-2`) | Gap between pills in the flex row |
| md | 16px (`px-4` or `mt-4`) | Pill row top margin from the citations section |
| label-bottom | 8px (`mb-2`) | Gap between "Follow-up:" label and pill row |
| pill-x | 12px (`px-3`) | Horizontal padding inside each pill |
| pill-y | 8px (`py-2`) | Vertical padding inside each pill |

Exceptions:
- Pill horizontal padding is 12px (`px-3`, not on the 8-point scale) to maintain comfortable touch target without over-inflating pill height. Minimum pill height resolves to approximately 36px with `py-2`, above the 28px minimum for non-primary interactive targets.

## Component Inventory

### New Component: `SuggestionPills`

**File:** `frontend/src/components/chat/SuggestionPills.tsx`

**Interface:**
```tsx
interface Props {
  questions: string[]       // 1–3 strings; empty array renders nothing
  onSelect: (question: string) => void  // populates input + submits immediately
}
```

**Structure:**
```
<div class="mt-3 animate-fadeSlideUp">          ← container; fades in on mount
  <p class="text-xs text-muted-foreground mb-2">Follow-up:</p>   ← section label
  <div class="flex flex-wrap gap-2">             ← pill row; wraps naturally
    <button class="text-xs px-3 py-2 rounded-full
                   bg-card/60 backdrop-blur-sm
                   border border-border/50 text-foreground/80
                   hover:bg-primary/10 hover:text-primary hover:border-primary/30
                   transition-all duration-200">
      {question text}
    </button>
    ...
  </div>
</div>
```

**Border radius:** `rounded-full` — pill shape. Consistent with existing `DocumentStatusBadge`, version badge pills (`rounded-full bg-primary/10 text-primary px-2 py-0.5`), and audit log filter pills.

**Animation:** `animate-fadeSlideUp` (already defined in `tailwind.config.js` and `index.css` as `fadeSlideUp 0.3s ease-out forwards`). Component mounts only when `suggestions` event arrives — animation fires naturally on mount. Source: D-08 (CONTEXT.md) + RESEARCH.md Pattern 4.

**Render condition (in MessageItem):**
```tsx
{!isStreaming && message.suggestions && message.suggestions.length > 0 && onSendMessage && (
  <SuggestionPills questions={message.suggestions} onSelect={onSendMessage} />
)}
```
`!isStreaming` guard ensures pills appear only after the main response streaming cursor stops.

**Explorer mode gate:** `SuggestionPills` is not rendered when `agentMode === "explorer"`. Gate implemented by not passing `onSendMessage` to the last assistant `MessageItem` when in Explorer mode (see RESEARCH.md Pattern 5 — `showSuggestions` prop approach). Source: D-10.

## Interaction Contract

### SUG-02: Click-to-submit behavior

1. User clicks a pill button.
2. `onSelect(question)` is called immediately — no hover state delay.
3. The handler populates the chat input with the question text AND submits immediately (same as pressing Enter after typing). No confirmation step. Source: D-09.
4. Pills remain visible in the message (they are not removed after click — the message is part of history).

### D-08: Loading / absence state

- No skeleton, no spinner, no placeholder row is shown during suggestion generation.
- The section below citations is simply absent until the `suggestions` SSE event arrives.
- If `stream_end` arrives without a `suggestions` event (failure path), the section remains absent permanently for that message.
- On thread reload from DB, `message.suggestions` is `undefined` — section is absent on all historical messages. This is correct by design.

### Pill layout

- Pills use `flex flex-wrap` — they wrap to a second line if all three questions are long. No horizontal scroll.
- Maximum 3 pills rendered (`questions.slice(0, 3)` in the component — the backend also clamps to 3).
- Minimum 1 pill rendered (if backend returns only 1 or 2 questions due to model variability, show what was returned).

## Copywriting Contract

| Element | Copy | Source |
|---------|------|--------|
| Section label | `Follow-up:` | D-07 (CONTEXT.md) — exact text specified |
| Empty state | None — section is absent; no empty state copy needed | D-08: no skeleton, no placeholder |
| Error state | None — section is absent on failure; no error message shown to user | D-08 + SUG-04 |
| Pill text | Verbatim question from LLM (dynamic) | SUG-01 |
| Destructive confirmation | Not applicable — no destructive actions in this phase | — |

**Primary CTA for this phase:** "Follow-up question pill" — no explicit CTA label beyond the `Follow-up:` section label. Click action is implicit (pill shape signals interactivity).

**System prompt for LLM (discretionary — Claude's choice):**
```
You are a helpful assistant. Based on the conversation excerpt below, generate
exactly 3 concise, actionable follow-up questions the user might want to ask next.
Each question should be distinct and directly relevant to what was just discussed.
Return only the questions, one per line, no numbering or bullets.
```
Questions should be 6–12 words in length — long enough to be meaningful, short enough to fit in a pill without wrapping awkwardly. The LLM is not constrained to this length — pill text wraps naturally if needed.
