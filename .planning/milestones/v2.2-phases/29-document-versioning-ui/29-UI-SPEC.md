- Version badge inline gap: `gap-1.5` (6px) — matches the existing topic pill gap used in MetadataPanel. Acceptable one-off; not added to scale.

## Interaction Contracts

### Contract 1 — Version Badge (VER-03)

**Trigger:** Document row renders with `version_number > 1`.

**Visual:** Inline chip in the filename cell, immediately after the filename text. Uses `flex items-center gap-1.5` wrapper on the filename cell content.

```
[filename text]  [vN chip]
```

Chip spec:
- Text: `v{version_number}` — e.g. `v2`, `v3`
- CSS: `rounded-full bg-primary/10 text-primary px-2 py-0.5 text-xs`
- Not rendered when `version_number === 1` or `version_number` is undefined/null — use `(doc.version_number ?? 1) > 1` guard

**v1 documents:** No badge, no change to filename cell layout.

### Contract 2 — Expand Toggle (VER-04 prerequisite)

**Trigger condition (extended):** Show the chevron toggle button whenever `hasMetadata(doc) || hasVersions(doc)`.

```typescript
const hasVersions = (doc: Document) => (doc.version_number ?? 1) > 1
const isExpandable = (doc: Document) => hasMetadata(doc) || hasVersions(doc)
```

**Aria label:** `"Expand details"` when collapsed, `"Collapse details"` when expanded. (Replace current metadata-specific labels to cover both panels.)

**Icon:** `ChevronRight` (collapsed) → `ChevronDown` (expanded) — existing pattern, no change.

### Contract 3 — Version History Panel (VER-04)

**Rendered when:** `hasVersions(doc) && expanded.has(doc.id)`.

**Position:** Second `<tr>` in the expanded Fragment (after MetadataPanel `<tr>` if present; first if no metadata).

**Panel container:**
```
<tr><td colSpan={7} className="p-0">
  <VersionHistoryPanel ... />
</td></tr>
```

**Panel inner layout:**
- Background: `bg-muted/30 border-t` — matches MetadataPanel visual style (source: CONTEXT.md D-03)
- Padding: `p-3` (12px) — matching MetadataPanel inner padding
- Contains a compact table (no outer border, no rounded corners — it is nested inside the parent table)

**Version history table columns:**

| Column | Content | Alignment | Style |
|--------|---------|-----------|-------|
| Version | `v{version_number}` | left | `text-sm font-semibold` |
| Uploaded | Formatted date (`created_at`) | left | `text-sm text-muted-foreground` |
| Size | `formatBytes(file_size)` | left | `text-sm text-muted-foreground` |
| Actions | Restore button | right | `Button variant="ghost" size="sm"` |

**Date format:** `new Date(version.created_at).toLocaleDateString()` — locale default, no custom format. Matches existing date display patterns in the app.

**Loading state:** While `GET /documents/{id}/versions` is in-flight, render a single row with a centered spinner:
```
<span className="h-3 w-3 animate-spin rounded-full border border-current border-t-transparent" />
```
Use `text-muted-foreground` on the spinner cell.

**Current version row:** The currently active version (`is_latest=true`) has no Restore button. Render a `text-xs text-muted-foreground` label "Current" in the Actions cell instead.

**Ownership guard:** Restore button renders only when `doc.user_id === currentUserId`. For globally-visible documents owned by another user, the Actions cell is empty for all versions (no "Current" label needed either).

### Contract 4 — Restore Confirmation Dialog (VER-05)

**Trigger:** User clicks "Restore" on a historical version row.

**Dialog spec — clone of delete dialog:**

| Element | Value |
|---------|-------|
| `DialogTitle` | `Restore version?` |
| `DialogDescription` | `Restore v{N}? This version will become active for retrieval. The current version remains in history.` |
| Cancel button | `variant="outline"`, label: `Cancel` |
| Confirm button | `variant="default"` (primary), label: `Restore` |

Note: Restore is NOT a destructive action (no data is deleted). Use `variant="default"` (primary blue), NOT `variant="destructive"` (red). This distinguishes restore from delete visually.

**In-flight state (while POST /restore is pending):**
- Confirm button: `disabled={true}`, replace label with spinner:
  ```
  <span className="h-3 w-3 animate-spin rounded-full border border-current border-t-transparent mr-2" />
  Restoring...
  ```
- Cancel button: `disabled={true}` — prevent double interaction

**On success:** Close dialog, call `onRestored()` callback to trigger parent `fetchDocuments()`. No optimistic update.

**On failure:** Close dialog, fire toast notification (see Copywriting Contract — Error state below).

## States and Transitions

| State | Trigger | Visual |
|-------|---------|--------|
| v1 document (default) | `version_number` is 1, undefined, or null | No badge; chevron shows only if has metadata |
| Versioned document (collapsed) | `version_number > 1`, row not expanded | Version badge visible; chevron shown |
| Versioned document (expanded, loading) | User clicks chevron; fetch in-flight | Version history sub-row shown with spinner |
| Versioned document (expanded, loaded) | Fetch complete | Version history table populated |
| Restore pending | User confirms dialog | Dialog buttons disabled; spinner on confirm button |
| Restore success | API 200 response | Dialog closed; document list refreshed; version badge updated to reflect new active version |
| Restore failure | API error response | Dialog closed; toast: "Failed to restore version. Please try again." |

---

## Layout Rules

1. **No new columns** in the document table. All version UI fits within existing 7 columns (colSpan=7 for sub-rows). Source: CONTEXT.md D-02.
2. **No modal for version history.** Version history is an inline sub-row, not a Dialog or Sheet. Source: CONTEXT.md D-03.
3. **Expand order when both metadata and versions exist:** MetadataPanel `<tr>` first, VersionHistoryPanel `<tr>` second.
4. **No optimistic update on restore.** Wait for API round-trip before refreshing the list. Source: CONTEXT.md D-04.

## Accessibility

| Element | Requirement |
|---------|-------------|
| Expand chevron button | `aria-label="Expand details"` / `"Collapse details"` (updated from metadata-only labels) |
| Version badge chip | `aria-label` not needed — it is a visual label next to the filename; screen readers read the filename then the badge text naturally |
| Restore button | Accessible name provided by button text `"Restore"` |
| In-flight restore button | `disabled={true}` + visible spinner; no `aria-busy` required (disabled communicates state) |
| Dialog | shadcn Dialog handles `aria-modal`, focus trap, and `aria-labelledby` automatically via Radix |
| Version history table | Add `aria-label="Version history for {doc.filename}"` on the `<table>` element inside VersionHistoryPanel |
