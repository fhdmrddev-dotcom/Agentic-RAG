# Requirements: Agentic RAG — v4.4 Experts That Actually Work

**Defined:** 2026-09-23
**Core Value:** The agent acts as an AI colleague — it knows your knowledge base, can run code, and
can be taught new behaviors (skills) that persist and can be shared.

**Milestone goal:** a client can install an Expert and get **grounded answers from its own
knowledge, in their own org** — proven by live drives as a real user, never by a mocked test.

### An Expert adds scope, it does not replace it (SEED-303 open arms)

- [x] **PACK-21**: An Expert's tools are the thread's normal tools **plus** its own — never fewer. No registered tool the user would otherwise have is stripped by inviting an Expert.
- [x] **PACK-22**: An Expert whose `required_connections` are not connected says so on its card and at invite ("Requires HubSpot — not connected") and offers the connect flow, instead of failing at run time (S7).
- [x] **PACK-23**: Swapping or removing the active Expert mid-thread appears in the transcript as an event that names its consequence (S2).
- [x] **PACK-24**: A user can "ask a second Expert" from a thread; it opens a new thread scoped to that Expert, carrying a handoff summary of the first (S3 — one active Expert per thread stays the rule).
- [x] **PACK-25**: Inviting a `restricted` Expert states the cost before the run — which of the thread's documents it will not read (S5).
