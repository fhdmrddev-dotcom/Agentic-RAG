## Interaction Contract

### Loading state
- Skeleton: show 4 `Card` components each with 3 skeleton rows (`animate-pulse bg-muted/30 h-10 rounded`)
- Spinner not used at page level (skeleton preferred for structured multi-panel layout)

### Error state
- API error: banner below page header: `bg-destructive/10 text-destructive text-sm px-4 py-2 rounded-lg`
- Text: "Health metrics could not be loaded. Refresh to try again."
- Individual action errors: inline below action buttons in a `text-xs text-destructive` line, auto-dismiss after 4 seconds (matches MemorySection.tsx pattern)

### Delete flow
1. User clicks Trash2 icon on a document row
2. shadcn Dialog opens: "Delete document?" confirmation
3. Dialog body: "This will permanently delete **{filename}** and all its chunks. This action cannot be undone."
4. Footer: `Button variant="outline"` "Keep Document" + `Button variant="destructive"` "Delete"
5. On confirm: call `DELETE /documents/{document_id}`, remove row optimistically, show spinner in button while in-flight
6. On API error: close dialog, show inline row error banner

### Re-ingest flow
1. User clicks RefreshCw icon
2. Inline confirmation tooltip: "Re-ingest this document? This replaces the current version." with "Yes, Re-ingest" / "Never mind" — no full Dialog (lightweight action)
3. On confirm: call `POST /documents` with re-upload (implementation detail for planner — may require file fetch from storage URL)
4. Row shows `Loader2 animate-spin` during in-flight request
5. On success: row chip updates; on error: inline error text

### Move to Folder flow
1. User clicks FolderInput icon
2. `MoveToFolderDialog` opens (full Dialog)
3. Dialog title: "Move to folder"
4. Body: `Select` populated with user's folder list + "Root (no folder)" option
5. Footer: "Keep Document" + "Move Document" (primary, disabled until folder selected)
6. On confirm: call `PATCH /documents/{document_id}` with `{ folder_id }`, close dialog, update row's folder_id chip if visible

### Sidebar nav addition
- Icon: `Activity` (Lucide) — represents health/monitoring
- Label: "Library Health"
- Placement: inside "Knowledge Base" section, after "Documents", before "Skills"
- Active state: `bg-primary/10 text-primary font-medium` + left 2px `bg-primary` indicator line (matches existing nav pattern)

## API Shape (from Phase 37 backend — pre-populated)

`GET /knowledge-health/summary` response shape:

```ts
interface HealthSummary {
  most_retrieved: MostRetrievedDoc[]
  never_retrieved: NeverRetrievedDoc[]
  low_confidence: LowConfidenceDoc[]
  stale: StaleDoc[]
}

interface MostRetrievedDoc {
  document_id: string
  filename: string
  folder_id: string | null
  created_at: string
  file_size: number
  retrieval_count: number
  last_retrieved_at: string
}

interface NeverRetrievedDoc {
  document_id: string
  filename: string
  folder_id: string | null
  created_at: string
  file_size: number
}

interface LowConfidenceDoc {
  document_id: string
  filename: string
  folder_id: string | null
  created_at: string
  file_size: number
  avg_similarity: number
}

interface StaleDoc {
  document_id: string
  filename: string
  folder_id: string | null
  created_at: string
  file_size: number
  days_stale: number
}
```
