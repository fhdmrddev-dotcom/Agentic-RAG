## Component Specifications

### 1. MessageFeedback — Thumbs Up/Down on MessageItem

**Location:** Below `SuggestionPills` (or in place of them when no suggestions), inside the assistant message content `div`, visible only when `!isStreaming` and `message.role === "assistant"` and `message.content`.

**Trigger:** Appear on hover of the parent message row (`group-hover` pattern). Once a rating is submitted, buttons remain visible (no longer need hover) with the selected button in its filled/active color.

**Layout:**
```
[ThumbUp icon btn] [ThumbDown icon btn]
```
- Container: `flex items-center gap-1 mt-2`
- Each button: shadcn `<Button variant="ghost" size="sm">` with `className="h-7 w-7 p-0"`
- ThumbsUp icon: `ThumbsUp` from lucide-react, `h-3.5 w-3.5`
- ThumbsDown icon: `ThumbsDown` from lucide-react, `h-3.5 w-3.5`

**States:**
- **Idle (not yet rated, not hovering):** `opacity-0 group-hover:opacity-100 transition-opacity` — hidden until row hover. Icon color: `text-muted-foreground`.
- **Idle (hovering):** Icon color: `hover:text-foreground`.
- **Rated positive:** Container always visible (`opacity-100`). ThumbsUp icon: `text-primary fill-primary`. ThumbsDown icon: `text-muted-foreground opacity-40` (dimmed). No interaction allowed on either button.
- **Rated negative:** ThumbsDown icon: `text-destructive fill-destructive`. ThumbsUp icon: `text-muted-foreground opacity-40`. No interaction allowed.
- **Submitting (loading):** Replace clicked icon with `<Loader2 className="h-3.5 w-3.5 animate-spin" />`. Disable both buttons.

**Tooltips:** Wrap each button in `<Tooltip><TooltipTrigger asChild>`. Tooltip content:
- ThumbsUp: "Good response"
- ThumbsDown: "Poor response"

**409 handling:** If backend returns 409, silently treat as already-rated. Set local state to the previously submitted rating. No error shown to user.

**Error handling (non-409):** If submit fails (non-409), show no visible error. Revert button to idle state. Fire-and-forget — never block conversation.

### 2. ReasonSelector — Inline reason picker after thumbs-down

**Trigger:** Appears immediately below the thumbs buttons after user clicks thumbs-down, before feedback is submitted. Slides in with `animate-fadeSlideUp`.

**Layout:**
```
Why was this response unhelpful?
[Wrong answer] [Not from my documents] [Incomplete] [Other] [Skip for now]
```
- Heading: `text-xs text-muted-foreground mb-2 mt-2`
- Buttons: `flex flex-wrap gap-2`
- Each reason: shadcn `<Button variant="outline" size="sm">` with `className="h-7 text-xs px-2"`. On hover: `hover:bg-primary/10 hover:text-primary hover:border-primary/40`.
- Skip: shadcn `<Button variant="ghost" size="sm">` with `className="h-7 text-xs px-2 text-muted-foreground"`. Label: "Skip for now".

**Reason labels** (map to API reason field):
| Display Label | API value |
|---|---|
| Wrong answer | `wrong_answer` |
| Not from my documents | `not_from_documents` |
| Incomplete | `incomplete` |
| Other | `other` |

**Behavior:** Clicking any reason button OR "Skip for now" immediately submits feedback to POST /feedback with `rating: "negative"` and `reason` (null if Skip for now). No confirmation step. Dismiss reason selector after click.

**Animation:** `animate-fadeSlideUp` on mount (0.3s ease-out — matches existing pattern).

### 3. FeedbackStatsPanel — New panel in KnowledgeHealthPage

**Location:** Added to `KnowledgeHealthPage` below the existing `RetrievalChart` and above the `grid grid-cols-1 lg:grid-cols-2 gap-6` panel grid. Full width (not inside the 2-col grid).

**Data source:** `GET /feedback/stats` → `{positive_rate: float, total_ratings: int, downvoted_documents: [{document_id, filename, folder_id, downvote_count}]}`

**Panel structure:**

```
Card (ghost-border bg-card/50 shadow-sm)
  CardHeader
    [ThumbsUp icon text-primary h-4 w-4] "User Feedback"   [N total ratings — text-xs text-muted-foreground]
  CardContent
    PositiveRateStat
    DownvotedDocumentsList
```

**PositiveRateStat:**
- Layout: `flex items-baseline gap-2 mb-4 px-4 pt-2`
- Value: `text-3xl font-bold font-headline tabular-nums leading-none text-primary` — shows `{Math.round(positive_rate * 100)}%`
- Label: `text-sm font-medium text-muted-foreground` — "positive rating"
- Subtext: `text-xs font-medium text-muted-foreground` — "all-time · {total_ratings} total ratings"

**DownvotedDocumentsList heading:**
- `text-xs font-medium text-muted-foreground px-4 pb-2` — "Most downvoted (last 30 days)"

**Each downvoted document row:**
- Reuse `HealthDocumentRow` component with a custom `metricChip`:
  - Chip: `<span className="text-xs px-2 py-0.5 rounded-full bg-destructive/10 text-destructive shrink-0 tabular-nums">{downvote_count} ↓</span>`
  - The HealthDocumentRow already provides file icon, filename truncation, and action buttons (delete, re-ingest, move). Use as-is.

**Empty state (no downvoted documents):**
- Use `<HealthEmptyState>` component pattern:
  - Icon: `ThumbsUp` from lucide-react, class `text-muted-foreground`
  - Heading: "No downvoted documents"
  - Body: "No documents have been downvoted in the last 30 days."

**Empty state (zero total ratings):**
- Heading: "No feedback yet"
- Body: "Thumbs up and down ratings will appear here once users start rating responses."

**Loading state:**
- Match the skeleton pattern from `KnowledgeHealthPage` loading block:
  ```
  ghost-border bg-card/50 rounded-lg p-4 mb-6 space-y-3
    animate-pulse bg-muted/30 h-4 w-40 rounded    (heading skeleton)
    animate-pulse bg-muted/30 h-8 w-20 rounded    (stat skeleton)
    animate-pulse bg-muted/30 h-10 rounded        (row 1)
    animate-pulse bg-muted/30 h-10 rounded        (row 2)
  ```

**Error state:**
- Same pattern as KnowledgeHealthPage error banner: `bg-destructive/10 text-destructive text-sm px-4 py-2 rounded-lg mb-6`
- Copy: "Feedback stats could not be loaded. Refresh to try again."

## Interaction Contract

### Fire-and-Forget Submission (FB-05)

POST /feedback is called immediately on button click. The UI must:
1. Optimistically set local `ratingState` to `"positive"` or `"negative"` immediately on click.
2. Disable both buttons during the in-flight request.
3. On success (201): keep the optimistic state. No toast, no modal, no scroll interruption.
4. On 409: treat as already-rated — update local state to the submitted rating and stop.
5. On other error: revert `ratingState` to `null`. No error message shown. Silent failure.

### Hover Reveal Pattern

Use CSS `group` on the parent assistant message container and `opacity-0 group-hover:opacity-100 transition-opacity` on the thumbs button container. After a rating is submitted, replace with `opacity-100` (remove opacity-0 / group-hover classes) so the selected state is always visible.

### Reason Selector Flow

1. User clicks ThumbsDown.
2. `ratingState` stays `null` (not yet submitted).
3. `showReasonSelector = true` — ReasonSelector mounts with `animate-fadeSlideUp`.
4. User clicks a reason button or "Skip for now".
5. ReasonSelector unmounts immediately.
6. POST /feedback fires with `rating: "negative"`, `reason: selected_reason | null`.
7. Optimistic state applied: `ratingState = "negative"`.

### State Management

Local state per MessageItem (no global store):
```ts
type RatingState = "positive" | "negative" | null
const [ratingState, setRatingState] = useState<RatingState>(null)
const [showReasonSelector, setShowReasonSelector] = useState(false)
const [submitting, setSubmitting] = useState(false)
```

On component mount: if `message.feedback_rating` exists (from persisted data), initialize `ratingState` from it. Note: Phase 39 backend does not currently return existing feedback on message load — so initialize to `null` and accept that users cannot see their previous rating on reload. This is acceptable per FB-03 (no modification allowed) — the immutable pattern means seeing prior rating on reload is a nice-to-have, not a requirement.
