## Color

All values from `frontend/src/index.css` CSS custom properties. No new color values introduced this phase.

| Role | Light mode | Dark mode | Usage |
|------|------------|-----------|-------|
| Dominant (60%) | hsl(220 20% 97%) — `--background` | hsl(216 45% 4%) — `--background` | Page background, table row background |

| Accent (10%) | hsl(239 84% 67%) — `--primary` | hsl(239 100% 82%) — `--primary` | Chip fill (`bg-primary/10`), chip text (`text-primary`) |

| Destructive | hsl(0 84% 60%) — `--destructive` | hsl(0 72% 51%) — `--destructive` | Delete button hover state only |

Accent (`--primary`) reserved for:
- Chip fill: `bg-primary/10` background on "N tables" chip
- Chip fill: `bg-primary/10` background on "N imgs" chip
- Chip fill: `bg-primary/10` background on existing "vN" version chip
- Chip text: `text-primary` on all three chip types
- Focus ring on interactive elements

Accent is NOT used for: table row hover, column headers, file size/date text, status badges (those use their own semantic colors), or the delete icon at rest.

## Interaction States

### Chip States

Chips are non-interactive display elements (no click, no hover effect, no tooltip). They are informational counters only.

| State | Behavior |
|-------|----------|
| Default | Chip rendered with `bg-primary/10 text-primary` |
| Hover | No hover state — chip is not clickable |
| Count = 0 | Chip not rendered (conditional guard `(doc.X_count ?? 0) > 0`) |
| Count = 1 | "1 tables" / "1 imgs" — label is not pluralization-aware (acceptable for v1) |

### Document Row States (unchanged from existing)

| State | Behavior |
|-------|----------|
| Row hover | Existing `hover:bg-muted/50` on `<tr>` — unchanged |
| Expanded | Existing version history accordion — unchanged |
| Deleting | Delete button hover turns `text-destructive` — unchanged |

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Chips carry semantic meaning | No `aria-label` required — chips are supplementary counts within a labeled table cell; screen reader reads cell as "{filename} v2 3 tables 2 imgs" which is meaningful |
| Chip contrast | `bg-primary/10` + `text-primary` in both light/dark modes provides sufficient contrast — same ratio as the existing vN chip which is in production |
| No new keyboard traps | Chips are non-interactive — no focus management needed |
| `flex-wrap` on filename cell | Prevents chips from clipping on narrow viewports; existing `max-w-xs truncate` on `<td>` provides outer bound |
