## Observation on T-137-04 (CLOSED, not a blocker)

The three declared mitigations for the carried "fabricated mid-run verdict" threat are all
present and verified: the 059-A determinate bar shows completion units only (no verdict,
never 100% while running — `RunHistory.tsx:119-137`), matrix arms emit no mid-run verdict
(`EvalsTab.tsx:437` `onEvalVerdict: () => {}`), and verdicts load from the durable DB
readout at `eval_complete` (`EvalsTab.tsx:194-196`).

For completeness: the **single-run** (non-matrix) path does append a real per-case
`PASS`/`FAIL` badge into its live map (`EvalsTab.tsx:186-193`) which surfaces in the
expanded running body (`RunHistory.tsx:164`). This is authentic streamed server data (the
backend `EVENT_VERDICT` emission, `eval_runner_service.py:663`), reconciled by the
authoritative durable rollup at finalize — it is **not fabricated state**, so the Tampering
threat does not apply, and this is carried behaviour secured in Phase 137. The only nuance
is a copy inconsistency: the same body's caption reads "no mid-run pass/fail is shown"
(`RunHistory.tsx:170`) while the single-run stream does show authentic per-case verdicts.
This is cosmetic, not a security gap. Optional follow-up (non-blocking): reconcile the
caption with the single-run live-verdict behaviour, or suppress the single-run live badge to
match the matrix surface.
