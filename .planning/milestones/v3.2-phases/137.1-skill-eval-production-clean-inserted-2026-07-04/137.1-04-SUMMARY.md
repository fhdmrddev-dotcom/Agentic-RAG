# Phase 137.1 Plan 04: Matrix Fan-Out + Engine Smoke Sweep + Engine-Health Summary

**One click fans a skill's eval across N configured providers as N parallel single-provider `run_eval_job` arms under ONE Redis group claim with exactly one designated gate-feeder (D-05/D-06); the engine smoke sweep rides that SAME machinery over a built-in in-memory SKILL-LESS fixture (NULL FKs, zero seeded rows — deploy-parity-safe) to assert per-provider ENGINE health; and an owner-scoped GET engine-health board + skill-less run readout serve Settings with honest tiles and resolvable tile deep-links — all owner-scoped, none hand-rolling orchestration.**

## Accomplishments
- **Matrix fan-out (EVAL-05b / D-05/D-06):** `POST /skills/{skill_id}/evals/matrix` spawns one `run_eval_job` per configured registry-valid provider, all sharing ONE `matrix_group_id`, under ONE `SET NX` claim keyed by `skill_id` with value `= group_id` (a second launch on the same skill 409s while the matrix is live), with exactly one `feeds_gate=true` (default = the user's active provider). A group coordinator releases the ONE claim only after ALL arms finish (Pitfall 1 — a per-arm `run_id` release CAS-no-ops against the `group_id`-valued claim).
- **Engine smoke sweep (EVAL-05a / D-01/D-02):** `POST /evals/engine-sweep` fans one representative model per configured provider (local excluded) over a BUILT-IN in-memory fixture synthesized IN-MEMORY (`_SMOKE_SKILL_VERSION` + `_SMOKE_CASE`, case id `None`) and passed DIRECTLY to `run_eval_job`'s EXISTING `skill_version`/`cases` params — creating NO rows in `skills`/`skill_versions`/`skill_test_cases`; each `eval_runs` arm persists SKILL-LESS (`skill_id`/`skill_version_id` NULL, `feeds_gate=false`), owner-stamped, under a per-user sweep claim (`eval_inflight:engine-sweep:{user_id}` — no per-skill 409 collateral).
- **Engine-health board (D-03):** `GET /evals/engine-health` returns the caller's LATEST skill-less sweep group as an `EngineHealthBoard` — one tile per provider (`provider`, `model`, `healthy`, verbatim `error`, `run_id`, `last_swept_at`) + `swept_at`. Owner-scoped (another user's newer sweep is invisible); never-swept returns the honest empty board (`{tiles: [], swept_at: null}`, 200 — never 404). Health is honest: completed + graded = healthy; failed/not_measured/judge_error render `healthy=false` with the VERBATIM provider error.
- **Skill-less run readout (D-03):** `GET /evals/runs/{run_id}` reads any of the caller's runs BY ID with NO `skill_id` filter, so a NULL-skill sweep run is resolvable by its owner — the existing `/skills/{skill_id}/evals/runs/{run_id}` filters `.eq("skill_id", …)` and could never match a NULL-skill row. This makes every engine-health tile's `run_id` deep-link have a destination. Owner-scoped on both reads, 404-never-403; `get_eval_run` shape parity (ratings merge).

## Decisions Made
- **Second router for the skill-less surface.** The sweep/health/readout routes have no `skill_id` in the path (a sweep run is skill-less), so they live on `router_evals` (`prefix=/evals`); the matrix launch stays on the existing `/skills` router.
- **`_spawn_eval_job` is the shared per-arm seam.** Extracted the `start_eval_run` companion machinery (anchor `is_eval` thread → companion `runs` row → ZADD → buffer seed → per-arm provider override → `run_eval_job` task → `RUN_TASKS`) so matrix + sweep + single-run never diverge; it returns the `asyncio.Task` so the group coordinator can await all arms before releasing the ONE claim.
- **Synthetic job key for the sweep.** `run_eval_job` receives `skill_id="engine-sweep:{user_id}"` (used ONLY for its inflight-release/ZREM keys); the `eval_runs` row itself is inserted by the route with `skill_id=None`, keeping the row skill-less while the claim/coordinator keys stay coherent.
- **`matrix_gate_feeder_run` is the gate-scoping primitive.** It returns the ONE `feeds_gate=true` run of a group (the gate reads only that run). Wiring it into Phase 136's actual publish-gate compute is out of scope (GATE-01's file) — this plan provides the resolver + proves the other arms never feed the gate.
