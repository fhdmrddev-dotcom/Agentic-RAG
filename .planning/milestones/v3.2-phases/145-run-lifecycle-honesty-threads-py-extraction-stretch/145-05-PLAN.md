Fix Direction A in the browser: a finished run must finalize the UI — no phantom
"running", no dead Stop — even when the terminal SSE event is missed and the
connection never closes (RESEARCH U7: today only a full page reload heals it,
because `streamingThreads` is written ONLY by the send path and `reconcile()` never
touches it). The load-bearing change is to make `streamingThreads` RECONCILE-DERIVED
from `snapshot.active_runs` (Pattern 2), so the Stop button agrees with the
authoritative `runs.status` in BOTH directions — Direction A (delete when the
snapshot is terminal) and Direction B (re-add when a still-active run is reconciled)
— through the existing Stop selectors with zero call-site changes. An inactivity
watchdog timer triggers the read-only `getSnapshot` probe for the missed-terminal
case, and the existing tab-focus belt heals it for free once the derive is in place.
Silent finalize, no banner (D-145-04). This also closes BUG-260707-01 (D-145-10):
the composer/feedback must not flip to "done" affordances until `runs.status` is
terminal.

This plan is frontend-only and independent of the backend owner (Plans 02-04) — it
depends only on the LIVE repro (Plan 01) confirming the mechanism. It runs in
parallel with the backend extraction.
