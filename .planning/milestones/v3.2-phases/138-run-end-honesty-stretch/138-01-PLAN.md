<objective>
RUN-01a: stop baseline/leftover sandbox files from leaking into a run's `final_output_files` SSE emit as dead "Download unavailable" cards or re-surfaced prior-run files.

Purpose: The current emit is `list(_previous_files_in_run.values())` — unfiltered. On a reused sandbox session, `harvest_output_files()` re-walks the ENTIRE `/sandbox/output/` dir and overwrites each baseline `iteration:-1/url:None` entry with a fresh `iteration:N/url:<real>` meta the moment the model calls `execute_code` once. The proposed "filter iteration == -1" fix is confirmed INSUFFICIENT (BUG-260626-02 live re-test): the `-1` marker is gone before the emit runs. The correct fix tracks "genuinely new to THIS run" in a separate run-scoped content-hash accumulator, independent of `_previous_files_in_run`'s mutated state.

Output: A run-scoped `_new_file_hashes_in_run` set, threaded exactly like `_previous_files_in_run`, that the final emit filters against. Display-only (D-07/D-08): `harvest_output_files`'s upload/insert side is deliberately NOT touched.
</objective>
