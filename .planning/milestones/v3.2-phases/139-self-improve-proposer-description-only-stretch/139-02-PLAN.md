<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → propose/approve/reject routes | Untrusted `run_id`, `skill_id` (path), `proposal_id` (path) cross here |
| service-role Supabase client → skill_proposals / skills / skill_versions | RLS is bypassed — the app-code `.eq("user_id")` filter is the SOLE runtime gate |
| tuner winner description → skill catalog (later, via the promoted skills.description) | The winning description flows into the model-facing catalog line as DATA |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-139-04 | Elevation of Privilege (IDOR) | approve/reject another user's proposal | mitigate | Verify the proposal on `id` AND `user_id` AND `skill_id` BEFORE any write; 404-not-403 (mirror evals.py:1008-1017) |
| T-139-05 | Information Disclosure | cross-user existence leak on any owner miss | mitigate | 404 (never 403) on every owner/skill/proposal miss; malformed UUID → 404 via try/except, never leak the error shape (skill_tuner.py:196-202) |
| T-139-06 | Spoofing | forged `user_id`/`skill_id` in the request body | mitigate | `user_id` from the auth token, `skill_id` from the path — NEVER the body (T-135-02); the body carries only `run_id` |
| T-139-07 | Tampering/Disclosure | `run_id`/`source_tuner_run_id` pointing at another user's tuner run | mitigate | `_fetch_owned_or_global_skill` gates the skill first; the `tuner_runs` row is read owner-scoped-by-skill and the evidence is snapshotted inline, decoupling from the FK |
| T-139-08 | Tampering | prompt-injection via a malicious winning description into the model catalog | mitigate | The winner is a MEASURED Tuner candidate rendered as DATA in the catalog line (`- **{name}**: {desc}`) — the same surface the Tuner + agent_loop already use (T-135-03 precedent); no new injection vector, rendered as text |
| T-139-09 | Denial of Service | event-loop stall from a blocking supabase-py call in an async route | mitigate | Every supabase-py read/write wrapped in `run_in_threadpool` (D-v2.5-01); explicitly do NOT copy skills.py:404's un-wrapped call |
| T-139-10 | Tampering | wrong-kind reject flipping an instruction proposal via the description route | mitigate | Kind-gate the description-reject route on `kind='description'` (404/409 on mismatch) — parity with the approve route's kind guard |
| T-139-SC | Tampering | npm/pip/cargo installs | accept | No package installs — the routes compose first-party modules only; nothing to slopcheck |
</threat_model>
