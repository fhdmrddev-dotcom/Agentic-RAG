<objective>
Add the one user-facing surface of the phase (SC#1/D-08): a non-blocking import
note. When a skill ZIP bundles a non-Python script, `import_skill` still succeeds
but attaches a `notes[]` entry saying the skill includes a step the sandbox can't
run yet while its instructions still work. This is a static ZIP extension scan
(the only import-time-knowable signal — D-10, G-B only) that reuses the endpoint's
existing per-skill loop over already-`_sanitize_zip_name`-validated entries
(T-142-03). The frontend appends the note text to the existing muted import
message — no new component (D-09, G-2 does not fire).

Purpose: the user learns at import time that a skill has a step the runtime can't
execute, without the import failing or a bespoke card.
Output: the `notes[]` field on both response branches + the `SkillImportResult`
type + the `handleImport` render + backend/frontend tests.
</objective>
