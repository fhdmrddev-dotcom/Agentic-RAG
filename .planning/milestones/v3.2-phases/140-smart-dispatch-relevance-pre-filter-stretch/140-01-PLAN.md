    (1) TABLE `public.skill_embeddings`: PK `skill_id uuid REFERENCES public.skills(id) ON DELETE CASCADE`
    (one vector per skill), `user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE`,
    `embedding public.vector(1536)`, `embedding_model text`, `embedding_dimensions integer`,
    `source_text_hash text NOT NULL`, `updated_at timestamptz NOT NULL DEFAULT now()`. NO HNSW/IVF index
    (skills are tens-hundreds of rows; a seq scan over the LEFT JOIN is sub-ms — that is the documented
    reason document_chunks needs HNSW and this table does not).

    (2) RLS: `ALTER TABLE public.skill_embeddings ENABLE ROW LEVEL SECURITY;` + an owner-only SELECT policy
    `USING (auth.uid() = user_id)`. Writes are service-role (bypass RLS); the backfill job hand-scopes
    `.eq(user_id)` (defense-in-depth, V4 precedent — the RPC/app scope is the primary gate).

    (3) RPC `public.match_skills(query_embedding public.vector, match_user_id uuid, p_embedding_model text
    DEFAULT NULL)` RETURNS TABLE(id uuid, name text, description text, similarity double precision),
    LANGUAGE plpgsql SECURITY DEFINER, `SET search_path = public, pg_temp`. Body: `SELECT s.id, s.name,
    s.description, CASE WHEN se.embedding IS NULL THEN NULL ELSE 1 - (se.embedding <=> query_embedding) END
    AS similarity FROM public.skills s LEFT JOIN public.skill_embeddings se ON se.skill_id = s.id AND
    (p_embedding_model IS NULL OR se.embedding_model = p_embedding_model) WHERE (s.user_id = match_user_id OR
    s.is_global = true) AND s.is_enabled = true ORDER BY similarity DESC NULLS LAST, s.name;`. The WHERE
    clause is the byte-exact clone of agent_loop.py:1207-1208 — NEVER widen it (Pitfall 3 / V4 cross-user
    leak). No `match_count`/`match_threshold` (trimming happens in Python; the RPC only ranks). LEFT JOIN +
    NULLS LAST means a vector-less skill returns similarity NULL and is kept last (D-05 fail-open).

    (4) TRIGGER `stale_skill_embedding` — SECURITY DEFINER fn `SET search_path = public, pg_temp`; for
    `TG_OP = 'UPDATE'` return NEW unchanged unless `NEW.name IS DISTINCT FROM OLD.name OR NEW.description IS
    DISTINCT FROM OLD.description` (instructions/toggle-only changes leave the vector valid — description +
    name are the only D-01 embed-source fields that live on `skills`); otherwise `DELETE FROM
    public.skill_embeddings WHERE skill_id = NEW.id`. `CREATE TRIGGER ... AFTER UPDATE ON public.skills FOR
    EACH ROW`.

    (5) TRIGGER `stale_skill_embedding_from_case` — SECURITY DEFINER fn `SET search_path = public, pg_temp`;
    `DELETE FROM public.skill_embeddings WHERE skill_id = COALESCE(NEW.skill_id, OLD.skill_id); RETURN
    COALESCE(NEW, OLD);`. `CREATE TRIGGER ... AFTER INSERT OR UPDATE OR DELETE ON public.skill_test_cases FOR
    EACH ROW` (should_fire prompts are part of the D-01 embed source).

    (6) COLUMN: `ALTER TABLE public.app_settings ADD COLUMN IF NOT EXISTS skill_catalog_max_tokens integer
    NOT NULL DEFAULT 1500;  -- 0 = disable (inject-all kill switch, D-04)`.

    NO SQL backfill INSERT — SQL cannot call the embedding API, so the table ships EMPTY; the Plan 02 job
    populates it (absence of a row == D-05 fail-open until then). Use `CREATE OR REPLACE FUNCTION` and
    `DROP TRIGGER IF EXISTS`/`CREATE TRIGGER` so re-application is idempotent.
