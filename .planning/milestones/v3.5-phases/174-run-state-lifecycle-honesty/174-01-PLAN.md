<objective>
Make the pre-first-token ("Setting up agent…") state honest: when a reasoning model is streaming reasoning before any tool or visible token exists, the pre-answer label reads "Reasoning…" instead of the dead "Setting up agent…". This is STATE-03 — a render-derive over the reasoning signal the frontend already stamps (`message.reasoningContent`), with NO new backend event and NO latency work (D-08/D-10).

Purpose: A reasoning-heavy model (Kimi ~4,000 reasoning tokens, GLM, DeepSeek) currently reads as idle during the setup gap. Counting already-emitted reasoning as activity makes the wait legible without shortening it.
Output: An additive `reasoningActive` param on `outerBannerLabel`, wired at `MessageItem.tsx:620`, plus a new `toolMeta.test.ts` that locks the D-14 byte-identical default.
</objective>
