<objective>
**RENDER-03** — a submitted general-chat message must always send or surface an honest failure; there must be no intermittent silent send-drop. Two halves (D-10), honesty load-bearing:

1. **Honesty guarantee (the durable property):** on any non-dispatch path — chiefly the `sendingThreadsRef` duplicate-guard early-return in `sendMessage` that today silently returns — stash the draft in `failedSendDrafts` + a quiet `reconcileErrors` hint so the EXISTING ChatArea prefill + banner seam restores the text ("Couldn't send — tap to retry"). The user never silently loses a message even if a race fires (D-10.2/D-11).
2. **Race-tighten (reduces frequency):** on a just-created/switched thread, mark the thread as *pending-send* BEFORE `setViewingThread` fires its reconcile, via a distinct pending ref the preserve-guard honors — WITHOUT adding to `sendingThreadsRef` (which would trip sendMessage's own duplicate-guard and drop the real send) (D-10.1).

Purpose: closes the general-chat intermittent silent send-drop (BUG-260603-01); mechanism #1 (per-thread mutex) was already root-fixed in SEED-055 Part 1.
Output: an honest non-dispatch recovery routed through the existing seam + a fresh-thread ordering tighten, covered by extended unit tests. Depends on 176-01 (shared `StreamsProvider.tsx`).
</objective>
