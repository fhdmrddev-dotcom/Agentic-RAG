<objective>
**RENDER-04** — after a user approves a description proposal in the Skill Studio Triggering tab, the Studio header `vN` and the Versions-tab LIVE badge must update **without a reload**. Today `loadSkills()` (WR-05) reconciles the description text and the `skill` object, but the shell's `versions` state is fetched once per `skillId` and goes stale, so `deriveLiveVersion(skill, versions)` falls back to the MAX of the STALE list (shows the old vN) and VersionsTab's own `[skillId]`-keyed fetch is likewise stale.

Fix (D-12, mirror the existing `refreshGate` pattern): add a `refreshVersions` callback in `SkillStudioPage` that re-runs `listSkillVersions(skillId)` + `setVersions`, thread it down as `onVersionPromoted` (SkillStudioPage → TriggeringTab → SkillTunerPage) and call it inside `handleApproveDescription`, and bump a `refreshNonce` so VersionsTab re-runs its own fetch. Frontend refetch only — no migration, no realtime.

Purpose: closes BUG-260706-01 (version pointer stale until reload).
Output: a `refreshVersions`/nonce refetch mirroring `refreshGate`, covered by extended unit tests.
</objective>
