<objective>
**EXEC-01** — the `execute_code` `libraries` parameter must install reliably (no silent no-op, no wasted retry rounds). Research read the installed `llm_sandbox` 0.3.37 source and found **three compounding, verified defects**: (A) `session.install` never raises on a pip failure (swallow is inside the library — our `except` is dead code); (B) `session.install` targets the **venv** pip while the code run is bare `python -u <file>` = the **system** interpreter, so a "successfully" installed declared lib is invisible to the run (the intermittency driver); (C) the streamed exit code is always 0 and the error scan reads stdout only while `ModuleNotFoundError` goes to stderr → a raw traceback under a "completed" status with zero honest signal.

Fix shape (D-01/02/03/04):
- **Declared install** — replace `session.install` with `python -m pip install …` via `session.execute_command` (non-streaming → reliable exit_code; system interpreter → visible to `python -u`), retry ONCE, never swallow.
- **Undeclared ModuleNotFound auto-heal** — after `exec_result`, detect the missing module (`_NO_MODULE_RE`), install it, re-run the code ONCE (threadpool-wrapped), bounded to **1 heal cycle per module per RUN** (tracked in a per-run Redis key on `ctx.run_id` so a re-attempt in a LATER `execute_code` call in the same run is suppressed — the actual BUG-260708-02 behavior); on persistent failure return an **honest tool result** on `llm_content`, never a raw traceback.

Purpose: closes BUG-260708-02 (execute_code libraries unreliable install) + SEED-043 half-b's bounded slice.
Output: a same-interpreter install + bounded honest auto-heal, ENTIRELY in `tool_dispatcher.py`, provider-uniform, Deep byte-identical.
</objective>
