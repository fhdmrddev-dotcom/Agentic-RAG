# Phase 25: Sub-Agent Intelligence & Model-Aware Context

## Goal

Three targeted improvements discovered through root-cause analysis of the context overflow
incident (run-423e5603). Sub-agents are independent API calls with their own context windows —
the current code treats them as if they share the main agent's budget, which is wrong and
results in documents being silently truncated to 32% of their content.

## Background & Research

**Key finding**: Each `run_sub_agent` call is a stateless API call with its own fresh context
window. It does NOT reduce or share the orchestrator's token budget. Spawning a sub-agent
with Claude Haiku (200k window) does not consume any of the main Claude Sonnet (1M window)
budget. They are billed and tracked independently.

**Why sub_agent_max_chars = 100,000 was wrong**: It was set to protect the main agent's
context budget. That protection is unnecessary. The correct ceiling is the sub-agent model's
own context window minus output headroom — for the cheapest models (Haiku 4.5, 200k context)
that is ~150k tokens = ~600k chars.

**Why context_window_max_tokens = 100,000 was stale**: Originally calibrated for GPT-4o
(128k window). OpenAI's current models (GPT-4.1, GPT-5.x) have 400k–1M windows. Google
Gemini has 1M. Anthropic has 1M. The fixed 100k budget unnecessarily trims conversation
history for users on cheap/large-context providers. However GPT-5.4 tiers pricing at 272k
tokens and Gemini Pro tiers at 200k, so we stay below those thresholds.

**Model specs verified via live web research (April 2026)**:
- Anthropic: Sonnet 4.6 ($3/1M), Haiku 4.5 ($1/1M) — expensive per token, cap conservatively
- OpenAI: GPT-5.4 ($2.50/1M, tiers at 272k), GPT-5.4-nano ($0.20/1M, 400k ctx)
- Google: Gemini 2.5 Flash ($0.30/1M), Gemini 3.x still preview — use 2.5 Flash for sub-agents
- Sub-agent defaults: cheapest stable model per provider that handles tool-free completion

### Task 2 — `backend/app/services/context_window.py`: Two changes

**2a. Export `resolve_context_budget` function**

Add after the `_TRIM_MARKER` constant:
```python
from __future__ import annotations
# (already present)

from app.config import settings, PROVIDER_CONTEXT_DEFAULTS

def resolve_context_budget(active_provider: str) -> int:
    """Return context budget for main agent based on active provider.

    Priority:
    1. CONTEXT_WINDOW_MAX_TOKENS env var if set (non-zero)
    2. Per-provider default from PROVIDER_CONTEXT_DEFAULTS
    3. 100,000 fallback
    """
    if settings.context_window_max_tokens > 0:
        return settings.context_window_max_tokens
    return PROVIDER_CONTEXT_DEFAULTS.get(active_provider, 100_000)
```

**2b. Fix JSON token estimation in `estimate_messages_tokens`**

Change the `tool_calls` estimation from `chars/4` to `chars/3`:
```python
# Before
if tool_calls:
    total += estimate_tokens(json.dumps(tool_calls))

# After — JSON is punctuation-heavy ({, ", :, [) so tokenises at ~3 chars/token not 4
if tool_calls:
    total += max(1, len(json.dumps(tool_calls)) // 3)
```

### Task 3 — `backend/app/services/sub_agent_service.py`: Model auto-selection

Add provider defaults map and model resolution logic:

```python
# Sub-agent model defaults: cheapest stable model per provider.
# These handle completion tasks well without needing the full orchestrator model.
# Gemini 3.x excluded — still in preview as of April 2026.
_SUB_AGENT_MODEL_DEFAULTS: dict[str, str] = {
    "anthropic":  "claude-haiku-4-5-20251001",
    "openai":     "gpt-5.4-nano",
    "google":     "gemini-2.5-flash",
    "openrouter": "",   # Unknown routing — fall back to user's selected model
    "ollama":     "",   # Local, user manages their own models
}
```

In `run_sub_agent`, replace:
```python
effective_model = model or (user_settings.llm_model if user_settings else None) or settings.llm_model
```

With:
```python
# Resolution order:
# 1. SUB_AGENT_MODEL env var (power-user override for all providers)
# 2. Provider default (cheap/fast model suited for heavy doc processing)
# 3. User's selected model (fallback for unknown providers)
# 4. Server default
if settings.sub_agent_model:
    effective_model = settings.sub_agent_model
else:
    provider = user_settings.active_provider if user_settings else ""
    provider_default = _SUB_AGENT_MODEL_DEFAULTS.get(provider, "")
    effective_model = (
        provider_default
        or (user_settings.llm_model if user_settings else None)
        or model
        or settings.llm_model
    )
```

## What Does NOT Change

- `_CTX_LIMIT_DEFAULT = 3000` and `_CTX_LIMIT_SUBAGENT = 10000` in threads.py — these
  cap how much of the sub-agent's result is stored back into the main conversation history.
  That IS still relevant (we don't want 17k chars of analysis flooding the orchestrator context).
- `trim_messages_to_fit` logic — no changes.
- No DB migrations, no UI changes, no new `.env` variables required (all have sensible defaults).

| Main agent budget (OpenAI) | 100k tokens | 200k tokens |
| Main agent budget (Google) | 100k tokens | 180k tokens |
| JSON tool_calls token estimate | chars/4 (undercount by ~25%) | chars/3 (accurate for JSON) |
