# Phase 300 — UI Design Contract

> The visual and interaction contract for Phase 300's small surfaces. It was written autonomously
> (the operator said "continue autonomously end to end for this phase"). Every choice comes from
> `300-CONTEXT.md` (D-01..D-24, locked), the shipped components named below, the
> `sketch-findings-agentic-rag` skill and the 299 contract's words-first rules. Each open choice is a
> numbered **UI-D** decision, marked "(self-decided)". `300-RESEARCH.md` was being written in
> parallel and was not waited for; the code was read directly. Generated by gsd-ui-researcher;
> checked by gsd-ui-checker.

## Surface Contracts

### S1 — The run-waiting email, and the shared email shell (NOTE-02, NOTE-03, NOTE-06 / D-02..D-06, D-21, D-22)

**One shell, two emails (UI-D4, self-decided).** One function in the mailer module renders every app
email from a list of paragraphs, so the run-waiting email and the invite email share the lockup,
spacing, escaping and the plain-text alternative. The invite keeps its shipped words verbatim; it
gains only the shell styling and a plain-text part. Every app email is `multipart/alternative`: plain
text first, HTML second.

**Headers:**

| Header | Value |
|--------|-------|
| From | `{from-name} <{from-address}>`, both from Settings (S3), via `email.utils.formataddr`. Default name "Syrel". Address falls back to the env `INVITE_FROM_EMAIL` while the Settings value is empty (D-08) |
| Reply-To | **absent** (D-03) |
| Subject (run waiting) | `{Workflow name} is waiting on you` (D-02) |
| Subject (invite) | `You're invited to {Org} on Syrel` (shipped, unchanged) |
| Subject when redirected (D-10, non-production) | `[Test] ` + the subject. **UI-D5 (self-decided):** the prefix is the only change. The body stays exactly as it would have been, and the original recipient is not written anywhere in it |

Subject rules: plain text, **never HTML-escaped**; every CR, LF and other control character in an
interpolated value becomes one space (the header-injection guard, D-02); a workflow name longer than
**120 characters** is clipped to 119 plus "…". An empty workflow name reads "A workflow".

**HTML body (run waiting) — the exact structure:**

```
┌ wrapper: max-width 560px, margin 0 auto, padding 24px, white, system font 16px/1.5, #0F172A ┐
│ [Syrel lockup PNG 160×80, alt "Syrel"]                       ← <p> margin 0 0 24px (shipped img)   │
│ **Compliance Gap Report** in **Acme** has been waiting       ← <p> margin 0 0 16px; names 600       │
│ 3 minutes for your approval.                                                                     │
│ **Open the run**                                             ← <p> margin 0 0 24px; <a> #4F46E5 600 │
│ ──────────────────────────────────────────────────────────── ← border-top 1px #E2E4E9, padding-top 16px │
│ Don't want these emails? Turn them off in Settings.          ← 14px #6B7280; the second sentence    │
│                                                                 is the link (same colour, underlined) │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

Markup notes: plain `<div>` and `<p>` with inline styles (no `<style>` block, no table layout, no
web font, no tracking pixel, no preheader). The logo URL is the shipped
`{primary_frontend_origin()}/brand/syrel-lockup-email.png`.

**Exactly what the email may contain (NOTE-03 + D-04), and nothing else:**

| Item | Rendered as | Source |
|------|-------------|--------|
| Workflow name | `<strong>`, HTML-escaped | the run's definition name |
| Org name | `<strong>`, HTML-escaped. **If the run has no org, the " in {Org}" phrase is dropped** (UI-D6) | `workflow_runs.org_id` → `organizations.name` (D-18), never `messages.org_id` |
| How long it has waited | duration words (table below), computed at send time from the notice's `created_at` (D-06) | notice row |
| Kind word | "answer" for a question, "approval" for an approval (D-04), from the pause kind only | notice row |
| Run link | `{primary_frontend_origin()}/app/runs/{run_id}`, attribute-escaped. No token, no query string (D-05) | |
| Settings link | `{primary_frontend_origin()}/app/settings`. No token, no query string (D-04) | |

Never in the email: the question or approval text, any document or file content, any step output,
the owner's own address, a token, an expiry ("the question expires in…" is forbidden, D-06).

**Duration words (one home, server-side; UI-D7, self-decided):** floor, never round up, so the email
never claims more waiting than happened.

| Waited | Words |
|--------|-------|
| under 60 s | "less than a minute" |
| 1 to 59 min | "1 minute" / "{n} minutes" |
| 1 to 47 h | "1 hour" / "{n} hours" |
| 48 h or more | "{n} days" |

The same function supplies the delay words S2 shows ("2 minutes"), so the two can never disagree.

**Body sentence variants:**

| Case | Sentence |
|------|----------|
| question, with org | "**{Workflow}** in **{Org}** has been waiting {duration} for your answer." |
| approval, with org | "**{Workflow}** in **{Org}** has been waiting {duration} for your approval." |
| no org | "**{Workflow}** has been waiting {duration} for your {answer \| approval}." |

**Plain-text alternative (run waiting), verbatim layout:**

```
Compliance Gap Report in Acme has been waiting 3 minutes for your approval.

Open the run:
https://app.example.com/app/runs/c41d8e2a-0b7e-4c2f-9e2d-5b7f0a63c41d

Don't want these emails? Turn them off in Settings.
https://app.example.com/app/settings
```

Plain-text values are not HTML-escaped (they would show literal `&amp;`), but every control
character in them becomes one space, so a crafted name cannot forge extra lines.

**Invite email on the shell (UI-D4):** HTML = the lockup, then "You have been invited to join
**{Org}** on Syrel." then the link "Accept your invitation" (#4F46E5, 600). No footer: an invite is a
one-off a person asked another person to send, not a notification there is a switch for. Plain text:

```
You have been invited to join Acme on Syrel.

Accept your invitation:
https://app.example.com/invite?token=…
```

**Escaping (D-22):** every interpolated value in HTML goes through `html.escape` (attribute values
with `quote=True`), including operator-set values such as the logo origin (the shipped WR-02 rule).
A test renders a workflow named `</a><script>alert(1)</script> & "Q3"` and an org named `<b>Acme</b>`
and asserts the HTML shows them as text, and the plain text shows them unescaped with no extra line.

### S2 — "Email me when a run is waiting on me" (NOTE-04 / D-09)

**Where:** Settings → **Preferences** tab (id "6", every caller), rendered by `PreferencesSection` as
its **third** block, after the default chat model. The two shipped blocks are not reordered or
re-styled. This is the member's own tab, so a member reaches it, and it calls **no**
`model_management`-gated endpoint (the `PreferencesSection` D-07 invariant); it reads and writes
through an ungated, RLS-scoped per-user endpoint.

**Anatomy:**

```
┌ row: flex items-center justify-between gap-4 rounded-lg ghost-border bg-muted/20 px-4 py-4 ────┐
│ Email me when a run is waiting on me                    ( ●━━ ) On   ← switch, right            │
│ If a workflow run is still waiting for your answer or approval after 2 minutes,                 │
│ we'll email you a link to it. Turning this off stops the email only. The run still waits for you.│
│ Email isn't set up on this server yet, so nothing is sent for now.   ← only when not configured  │
└────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- Title `<p id>` `text-sm font-semibold text-foreground`; description `mt-1 text-xs text-muted-foreground`.
- Switch: `<button type="button" role="switch" aria-checked={on} aria-labelledby={titleId}
  aria-describedby={descId} className="inline-flex items-center gap-2 py-2">` containing the track
  and the word "On" / "Off" (`text-sm`, 400, `text-primary` when on, `text-muted-foreground` when
  off), the shipped `Toggle` look (UI-D1).
- **"2 minutes"** is the operator's delay in words, composed by the server (S1's duration function)
  and returned with the preference. **UI-D8 (self-decided):** if the read carries no delay words, the
  sentence says "after a short wait" instead. The client never formats seconds itself.

**States (no state shows a value the server has not answered):**

| State | Render |
|-------|--------|
| Loading | Switch disabled, `aria-busy="true"`, track neutral (`bg-muted`), **no word** beside it. Never shows "On" before the read answers |
| Loaded | The server's value. Default for a user with no row: **on** (D-09) |
| Saving (after a flip) | Switch disabled until the write answers. Save-on-flip, no Save button (the `ModelDefaultPreference` pattern). The shown value is the server's reply, not the click |
| Save failed | The switch returns to the last server value; under the description, `role="alert"` `mt-1 text-xs text-[hsl(0_80%_80%)]`: "Couldn't save this. Try again." |
| Load failed | In place of the switch: `role="alert"` `text-xs`: "Couldn't load this setting." + `Button size="sm" variant="outline"` **"Retry loading"** (`gap-2`) |
| Email not configured on the install (`EMAIL_PROVIDER=none`, reported by the read) | The switch still works and saves. Extra line `mt-1 text-xs text-muted-foreground`: "Email isn't set up on this server yet, so nothing is sent for now." |

No receipt toast. The switch's own state is the receipt (skill rule 062-A: no toasts).

**The email's Settings link lands here only sometimes (recorded, not fixed):** `/app/settings` has no
tab address (tab addresses are not in the URL, per 299), so the link opens the reader's last-used
tab, and a member with none saved lands on Preferences (the member fallback). D-04's copy is locked,
and a query string is forbidden (D-04), so the email does not name the tab. G-4 row 4 checks a member
reaches the switch in one click from wherever the link lands.

### S3 — The operator's Email card (D-07, D-08, D-10)

**Where:** Settings → **Integrations** tab (id "2", `model_management` audience, operator only), as a
card **after** `ApiKeyLimits` and **before** the Save Integrations button. It is an `ApiKeyLimits`-style
leaf: own fetch of `GET /settings`, own drafts, and a ref handle whose `changes()` is merged into the
one **Save Integrations** PUT and whose `adopt()` takes the response. No Save button of its own.
The reasoning in the SEED-258 comment on that tab holds: `app_settings` is the operator singleton,
the tab is where the app's dealings with outside services live, and the Control Room writes no config.

**Anatomy:**

```
┌ Card ghost-border bg-card/60 ───────────────────────────────────────────────────────────────┐
│ Email                                                   ← CardTitle text-base font-semibold  │
│ Who run-waiting and invitation emails come from, and how long a run waits before its owner  │
│ is emailed.                                                   ← CardDescription              │
│ Sent through   Resend                                         ← read-only row (from the env) │
│ Send from (address)   [ notify@notify.example.com ]                                          │
│   Run-waiting and invitation emails come from this address. Replies are not read.           │
│ Send from (name)      [ Syrel ]                                                             │
│   The sender name people see in their inbox.                                                │
│ Wait before emailing (seconds)  [ 120 ]                                                     │
│   A run still waiting after 2 minutes emails its owner. Between 60 and 3600 seconds.        │
│ Test address (outside production)  [ you@example.com ]                                      │
│   Outside production, every email goes here instead of to its real recipient. Leave it     │
│   empty and nothing is sent outside production: each email is only logged.                 │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

Rows: `py-1`, a `flex items-center justify-between gap-4` line with `Label` `w-56 shrink-0 text-sm
text-muted-foreground` and the input `h-8 bg-muted/30 font-mono text-sm ghost-border` (delay `w-24`,
the addresses and the name `w-full max-w-xs`), then the hint `mt-1 text-xs text-muted-foreground`.

**"Sent through" (read-only, the env's `EMAIL_PROVIDER`, never editable here because the provider and
its secret are infra, D-08):**

| Provider | Value |
|----------|-------|
| `resend` | "Resend" |
| `smtp` | "Your mail server (SMTP)" |
| `none` or unset | "Nothing yet. Emails are only logged. Set `EMAIL_PROVIDER` in the server environment to send them." |

**Field rules:**

| Field | Default | Bounds and validation | Sent in `changes()` |
|-------|---------|-----------------------|---------------------|
| Send from (address) | empty (the env `INVITE_FROM_EMAIL` fallback applies) | Empty, or one address (`x@y.z`, no spaces). Invalid → under the field, `role="alert"` `mt-1 text-xs`: "That isn't an email address." | Only when changed and valid. An empty value is sent as empty, meaning "use the environment's address" |
| Send from (name) | "Syrel" | 1-60 characters, control characters refused client-side. Empty on blur → restores the loaded value | Only when changed |
| Wait before emailing (seconds) | 120 | Clamped to 60..3600 on blur (the `ApiKeyLimits` `limitFrom` rule; a cleared field is never sent, so `Number("") === 0` never reaches the server). The hint's "2 minutes" follows the draft value live, using the same floor words as S1 | Only when changed |
| Test address (outside production) | empty | Empty, or one address. Same invalid line | Only when changed and valid |

Load and failure states follow `ApiKeyLimits`: fields empty and disabled while loading; a failed read
shows `role="alert"` "Couldn't load the email settings." + `Button size="sm" variant="outline"`
**"Retry loading email settings"**; after a save, the fields show the **server's** values. A server
400 (out of bounds, bad address) surfaces in the Integrations save's existing error home, as the
server's sentence.

**UI-D11 (self-decided): the test address is shown on every install, production included.** Its hint
says it applies outside production, and production ignores it (D-10). Hiding it on production would
need the client to know the environment, which is a second reading of a server fact.

### S4 — Invite email failure (NOTE-06 / D-11)

**Wire need (for the planner):** `POST /org/invitations` and the resend call return how delivery went,
and the invitation list carries the latest attempt per pending invite. Suggested field:
`email_delivery: "sent" | "failed" | "not_configured"`. A mail outage never blocks the invite (D-11).

**The dialog's result panel has three arms (UI-D12, self-decided):**

| `email_delivery` | Title | Body |
|------------------|-------|------|
| `sent` | "Invitation sent" | "We emailed an invitation to **{email}**. You can also copy the link and send it yourself." + the shipped link box and Copy link |
| `failed` | "Invitation created" | The failure box (below), then the shipped link box and Copy link |
| `not_configured` (or absent, older backend) | "Invitation ready" (shipped) | "Share this link with **{email}**. They join your organization by opening it and signing in." (shipped, unchanged) |

The expiry line under the link ("The link expires in 7 days and can be used once…") stays on all three.
The `{email}` emphasis is `font-semibold` (600) in new markup.

**The failure box (`failed` only):**

## Accessibility contract

- **S2 switch:** `role="switch"`, `aria-checked`, labelled by the title and described by the
  description. Keyboard: Space and Enter flip it (native `<button>`). Disabled while loading or
  saving, with `aria-busy`.
- **Live regions:** the S4 failure box and the S2 "not configured" line are `role="status"`; S2/S3
  load and save failures and the S6 save-time refusal are `role="alert"`; the S6 row results keep the
  shipped split (`status` for started or refused, `alert` for a genuine error).
- **Retry buttons** name what they retry ("Retry loading", "Retry loading email settings"), so a
  screen-reader user hears the target without the surrounding sentence.
- **S6 busy:** `aria-busy` on the pressed Run now button and on the list during a refetch; focus stays
  on the pressed button (the list is not unmounted, so focus is not lost).
- **Colour is never the only signal:** every S5 dot has its value word; every S6 tone has its
  sentence; the S4 chip says "Email not sent".
- **Contrast:** new in-app text uses `--foreground` or `--muted-foreground` (≈7.7:1), the shipped
  warning and light-red tones for S6, or `--success` only as a dot. Email text: #0F172A on white
  (≈17:1), footer #6B7280 (≈4.8:1), link #4F46E5 (≈6.3:1).
- **Email:** the logo has `alt="Syrel"`; the link text names its destination ("Open the run"), never
  "click here"; the plain-text part is complete on its own.

## G-4 lived-experience scenarios (UI-observable)

Claude drives Chrome and the mail capture; the dev account's active org is proven first.
1. A scheduled run whose workflow asks for approval is left waiting past the delay → exactly one
   email arrives (redirected to the test address on dev, subject "[Test] {Workflow} is waiting on
   you"). It names the workflow, the org, "{n} minutes" and "approval", carries the "Open the run"
   link to `/app/runs/<id>` and the Settings footer, and contains no question text. The HTML and the
   plain text both read correctly in the capture. Answering inside the delay on a second run sends
   nothing.
2. Settings → Preferences: the switch reads On; flip it Off → it stays Off after a reload; a waiting
   run then sends no email (the outbox row reads skipped), and the run page still shows the wait.
3. Invite a member with the mail provider made to fail → the dialog shows "Invitation created" and
   D-11's sentence, Copy link has focus and works; the row shows "Email not sent"; a Resend after
   fixing the provider removes the chip.
4. Open the email's Settings link signed in, from a session whose last tab was Audit Log → Settings
   opens; Preferences is one click away and the switch is there.
5. Schedules dialog with three rows: a row shows "Didn't run — Client name is required and has no
   value. …" in amber, never `launch_failed`; Run now on row 2 spins only row 2, the list never reads
   "Loading…", and row 2's result lands under row 2 while row 1's earlier result stays.
6. Control Room → the Email tile reads "Held back" on a dev box without a test address, "Test mode"
   with one, and "Last send failed" with a time and a reason (and no address) after a forced failure.

**How we'd know the UI failed:**
- The email carries the question text, any document text, a token, a query string, an expiry, or a
  raw `frontend_url` with a comma in it; a workflow name renders as markup; the subject shows
  `&amp;`; a crafted name adds a line to the plain text.
- The S2 switch shows "On" before the read answers, or shows the click instead of the server's value
  after a failed save; it calls a `model_management`-gated endpoint (a member's Preferences tab 403s).
- S3 sends a cleared delay as 0, or an invalid address; the fields show typed values after a save
  instead of the server's.
- The invite dialog says "Please try again" for a mail failure, names the provider or an error code,
  or the invite is not created when mail fails; the chip appears for a `not_configured` install.
- The S5 tile goes red for "Off", "Held back", "Test mode" or a skipped send, or its reason shows a
  recipient address.
- A schedule row shows `launch_failed` or any other raw token; a refusal is truncated before the
  input name; Run now replaces the list with "Loading…" or disables every row.
- The step receipt still says "Destination: smtp.gmail.com" alone; the step email arrives as one line
  of literal `##` and `**`.
