# Phase 298 — UI Design Contract

> The visual and interaction contract for Phase 298's four small pieces of new UI. Produced
> autonomously (operator mandate: no questions). Every choice is resolved from `298-CONTEXT.md`
> (D-01..D-36), `298-RESEARCH.md` and the `sketch-findings-agentic-rag` skill, and each is
> recorded below as a numbered **UI-D** decision. Generated by gsd-ui-researcher; checked by gsd-ui-checker.

**Scope (new UI only):**
1. **Elsewhere line:** "N more … in <org> · Switch" under each narrowed list.
2. **Org-switch list behaviour:** each list's existing loading state, never "0" or "No …" before the new org's answer.
3. **Out-of-org folder marker** in the Builder pickers ("lives in <org>"), plus the worded ORG-05 refusal shown verbatim.
4. **Per-item "Move to <org>…"** control, the confirm sheet that names what moves, the worded refusals (D-33), and what happens after a move.

**Not in scope:** the org switcher itself (Phase 166, unchanged), deep links / cross-org prompts (299),
BUG-261027-02 first-paint "No recent chats" (299, see UI-D9), and thread or run moves (count + Switch only, D-19).

**Accent is reserved for exactly these elements:**
1. The inline **`Switch`** text button on the elsewhere line (`text-primary`, underline on hover/focus).
2. The **one filled button** in the move sheet: **"Move to <org>"** (`bg-primary text-primary-foreground`).
3. Focus rings (`focus-visible:ring-primary` / `ring-ring`), as everywhere else.

the "lives in" marker are not accent.

**UI-D2: amber means "this needs you first", red means "this destroys".** The two refusal
surfaces are amber, following the graded-guard rule and the sketch colour language (amber =
needs-you): the out-of-org marker and the move-refusal box. A move-sheet refusal blocks nothing
dangerous, and red would spend the signal that `Delete forever` relies on. **Exception:** the
ORG-05 save refusal lands in the Builder's existing save-error span (`text-destructive`,
`role="alert"`). That surface is shipped, so its colour is not re-decided here (UI-D14).

**UI-D3: no org-indigo band and no amber band.** The elsewhere line and the move sheet sit in the
user's own lists, not in the org-admin console. Indigo is the org-admin zone's band colour and
amber is the operator's (org-admin-and-identity D5), so neither applies here.

## Component Contracts

### 1. Elsewhere line (`ElsewhereLine`, ORG-06 / D-16 / D-17)

**Data.** One read returns the caller's own items outside the active org: a count for each kind
(folders, Root documents, workflows, threads, runs) for each other org, with that org's name. It is
held in a small module store keyed by `activeOrgId`. Requests in flight are shared, so the four
mounts cost one request. The store is invalidated after a move (research F7). An answer tagged
with an org other than the active one is discarded.

**Placement (UI-D4).** The line goes directly under each list's header and above its first row,
as one line per other org whose count for that list's kind is above 0. Orgs are ordered by name,
matching the route's `ORDER BY o.name`.

| List | Mount point | Kind(s) counted | Horizontal gutter |
|------|-------------|-----------------|-------------------|
| Library sidebar (Folders + Root) | `FolderTree`, under the "Folders" group header, above the Root `NavRow` | `folders` + `root_documents`, in ONE line | `px-2`, `mb-2` |
| Workflows page (published + drafts) | Top of the list scroll region (`p-6`), above the grid / empty state, inside `max-w-[1200px] mx-auto` | `workflows` (the caller's own, non-global; drafts + published) | grid gutter, `mb-4` |
| Chat history column | Top of `hc-list`, above the first date/folder group header | `threads` | `px-2`, `pb-2` |
| Run log | Top of the scroll region, above the loading line / count / rows | `runs` | `px-6`, `pt-4` |

**Copy (UI-D5).** The D-17 shape, with the list's own noun added so the number can never be
misread. Plurals are exact (`1 more folder`, `2 more folders`).

| List | Template | Example |
|------|----------|---------|
| Library (both kinds > 0) | `{F} more folder(s) and {D} more Root document(s) in {Org} · Switch` | "2 more folders and 5 more Root documents in Acme Legal · Switch" |
| Library (one kind > 0) | the non-zero part only | "1 more folder in Acme Legal · Switch" |
| Workflows | `{N} more workflow(s) in {Org} · Switch` | "3 more workflows in Acme Legal · Switch" |
| Chat history | `{N} more chat(s) in {Org} · Switch` | "12 more chats in Acme Legal · Switch" |
| Run log | `{N} more run(s) in {Org} · Switch` | "4 more runs in Acme Legal · Switch" |

- "Root documents" is the tree's own word for that row ("Root"). Plain "documents" would read as
  every document in the org, which the folder count already covers.
- `Switch` is a real `<button type="button">` with `aria-label="Switch to {Org}"`. The separator
  ` · ` and `Switch` are wrapped together in `whitespace-nowrap` so they never split across lines.
  The sentence part may wrap in narrow columns. Org names longer than 24 characters truncate with an
  ellipsis (`max-w-[12rem] truncate inline-block align-bottom`). The full name stays in the
  button's `aria-label` and in real DOM text inside the sentence, never in a `title` alone.

**States (UI-D6).** The line is a hint, never a promise, so every non-answer renders nothing.

| State | Render |
|-------|--------|
| Counts loading (first load or after a switch) | **Absent.** No placeholder, no shimmer, never "0" |
| Count for this kind = 0, or no other orgs, or the user has one org | **Absent** |
| Active org resolves to `None` (route returns `[]`) | **Absent**, because nothing is hidden when nothing narrows |
| Count read failed | **Absent**, logged to the console. Recorded trade-off: the list itself is complete for its org, and an error line on four surfaces for a supplementary hint would be noise |
| Answer tagged with the previous org | Discarded; treated as loading (absent) |
| Run log scoped to one workflow (`scope !== null`) | **Absent**, because the count covers all runs, not that workflow's |
| Count > 0 | One line per org: `text-[12px] leading-normal text-muted-foreground`, with `Switch` in `font-semibold text-primary hover:underline focus-visible:underline` |

- The line does **not** hide when the history column's title filter is active. It counts "more
  chats", not "more matches", and under "No chats match your search." it is the useful pointer.
- The wrapper element stays mounted (zero height when empty) with `aria-live="polite"`, so an updated
  count after a move ("1 more folder in Acme Legal") is announced. It is also the focus target in UI-D7.

**Interaction (UI-D7).** `Switch` calls the existing `switchOrg(org_id)` from `OrgProvider`, the same
call the profile-menu switcher makes. It does not navigate and does not remount anything: the user
stays on the same view, and the view's lists re-fetch for the new org (contract 2). Focus first moves
to the line's wrapper (`tabIndex={-1}`), then `switchOrg` runs, so focus never drops to `<body>`
when the button unmounts.

### 2. Lists on an org switch (ORG-01..04 / D-08 / D-09 / D-11 / D-12)

**UI-D8: drop at once, then show the list's own loading state.** When `activeOrgId` changes, every
narrowed list immediately shows **no rows from the old org**, then shows the loading state it
already ships, until the new org's answer arrives. It never shows "0", "No …" or an empty-state
sentence before that answer. Late answers for the old org are discarded.

| List | Loading state on switch (reuse) | Must NOT show while loading |
|------|--------------------------------|-----------------------------|
| Library Folder tree | The Root `NavRow` stays (Root always exists) with its **count omitted** (`NavRow` already omits a count it doesn't have). The tree body renders `SyrelLoader size="section" label="Loading folders…"` | "No folders yet" / "Create a folder to organize your documents." (today shown whenever `folders.length === 0`, so `FolderTree` needs the hook's new `loading`) |
| Library document list (Root / folder) | `useLibraryDocuments` cold state (the org joins the source key, so a switch counts as a cold source switch) | Any old-org row; a "0 documents" summary pill |
| Library summary / per-folder counts | Counts omitted (`summary = null`) | "0" on any `NavRow` |
| Workflows page | `LIBRARY_STATES.loading` → "Loading your workflows…" (`data-testid="library-loading"`), grid not rendered | "You have no workflows yet."; chip counts reading 0 |
| Chat history column | **New, minimal:** `SyrelLoader size="section" label="Loading your chats…"` in place of the list, driven by a `loading` prop that `ChatLayout` passes | "No recent chats" |
| Run log | `LOG_LOADING` (`data-testid="run-log-loading"`), rows cleared | `emptyWord`; `logCount(…)` |
| Chat composer folder picker / Builder pickers | Their shipped "no options yet" rendering | A blank `<option>` or a bound folder silently dropped (see contract 3) |

**UI-D9: BUG-261027-02 is not widened and not fixed here.** The history column's loading line shows
on a **switch** only. First paint keeps today's behaviour (`useThreads.loading` is `false` on the
first render), so the first-paint "No recent chats" stays exactly as it is and is fixed in Phase 299.
The executor must not "fix" first paint in this phase.

**UI-D10: switch side effects (every reset is visible, none is silent):**
- Library: folder selection returns to **Root**, and the document detail panel **closes**
  (`selectedDocId` reset). An old-org folder id would otherwise read a specific-folder list, which
  is not narrowed.
- Workflows page: the project-folder filter (`selectedProjectId`) resets to **All**.
- Chat composer: a folder scope that is not in the new org's folder list resets to the default
  ("All documents"). It never renders as a blank selection.
- A row-scoped sheet or menu open on an old-org row (move sheet, delete sheet) **unmounts with its
  row**. The org switcher cannot be reached while a modal sheet is open, so a move or delete in
  flight cannot cross a switch (D-12).
- A thread streaming at the moment of the switch keeps whatever `StreamsProvider` does today. It is
  simply not listed in the new org's history column, and the column must not crash (D-11).

### 3. Out-of-org bound folder + the ORG-05 refusal (D-14 / D-15 / D-36)

**Names come from a label read.** For ids the caller can see (today's unrestricted visibility,
nothing new revealed), the read returns `{id, name, org_id, org_name}`. Ids the caller cannot see are
omitted (research §D-15, recommended `folder-labels` read; route shape is planner discretion).

**UI-D11: the marker.** An out-of-org bound folder renders **by name plus where it lives**, never
blank, never as a raw id, and never silently unbound.

| Surface | In-org folder (today) | Out-of-org folder (new) | Caller cannot see the folder |
|---------|----------------------|------------------------|------------------------------|
| Builder bound-folder `<select>` (`WorkflowBuilderPage` breadcrumb) | `<option>{name}</option>` | `<option>{name} — lives in {Org}</option>` | `UNNAMED_KB_OPTION` ("A knowledge base outside your folders"), unchanged |
| Builder bound-folder chip (`builder-bound-folder`) | `{name}` | `{name}` followed by `<span class="text-warning"> · lives in {Org}</span>` | `UNNAMED_KB_OPTION` |
| Per-phase `folder_scope` chips (via `useBuilderNameMaps`) | `{name}` | `{name}` + amber ` · lives in {Org}` | `UNNAMED_KB_OPTION`, never the raw uuid |
| `DescribeKbPicker` | `<option>{name}</option>` | held id kept; `<option>{name} — lives in {Org}</option>` | dropped (`onChange("")`) **only** when the label read answers and omits the id: today's CR-R5-01 rule, now triggered by the lookup instead of by the list narrowing |
| While the label read is pending | — | held id kept; option text is `UNNAMED_KB_OPTION` (true, no new loading copy) | — |

- Marker text is exactly **`lives in {Org}`** (lower-case "lives"; em dash inside a native option,
  middot in a chip). It is real DOM text, never a `title` (the hover-only fence: touch has no hover).
- Amber colour applies only where markup allows it (chips). Inside a native `<option>`, the words carry it.

**UI-D12: the refusal is the server's sentence, verbatim, in the place that already shows refusals.**
The UI writes no prose of its own for ORG-05. The attended doors receive
`detail = {code: "folder_in_other_org", message}` (D-36), and each surface renders `message` as React text:

| Door | Where it shows (existing home) | Change |
|------|-------------------------------|--------|
| Builder save (create / PATCH draft) | `BuilderSaveRegion` error span (`data-testid="builder-save-error"`, `role="alert"`, 13px `text-destructive`) | A new named error class carries `message`. `useDraftPersistence.refusalOf` maps it to `{kind: "error", sentence: message}`; it is NOT folded into `HOLD_UNREADABLE` |
| Run modal (Workflows page / Library run) | RunModal's existing error text (`e.message`, verbatim) | `postMessage` picks `detail.message` when `detail` is an object |
| Chat launch form (`ChatLaunchForm`) | Its existing refusal line (scrolled into view, 296 G-4 row 11) | Same `postMessage` change |
| Chat in-thread picker (`ThreadWorkflowPicker` via `useStartWorkflowInThread`) | Its existing failure line (296-04) | A new `kind: "folder"` branch shows the server message instead of `startInputsRefused` |
| Scheduled run / "Run now" | The schedule's outcome line (296-02) | Plain string from the scheduler |
| API key | JSON `detail` string | Plain string |

**Copy contract for the server sentences** (the backend plan authors these; the UI shows them unchanged):
- Visible folder (D-14, locked): *"“Q3 Contracts” is in Acme Legal, not in this workflow's organization (Personal). Pick a folder from Personal."*
- More than one offender: name the first in definition order, then append *"2 other folders this workflow uses are outside Personal too."*
- Folder the caller cannot open (D-14, no folder org named): *"This workflow points at a folder you can't open. Pick a folder from this workflow's organization (Personal)."* The org named is the **workflow's** org, which the caller is acting in. The folder's org is never named.
- Never a 500, never "Invalid", never a status code in the sentence.

**UI-D13: save refusal does not discard the edit.** When a save is refused, the Builder keeps the
author's edit on screen (the existing `error` state, whose button stays retryable). Picking an
in-org folder and saving again clears the refusal. An **unchanged** pre-existing foreign binding saves
through (D-13), so the author sees the amber marker without being blocked until they launch.

**UI-D14:** the Builder's save-error span stays `text-destructive`, as shipped. Re-colouring a shipped
surface for one new refusal would fork its vocabulary. The amber marker on the chip is what tells
the author ahead of time.

### 4. "Move to <org>…" (ORG-06 / D-18..D-21 / D-31 / D-33 / D-35)

**UI-D15: where the control lives (on the item, D-21).**

| Item | Home | Shown only when (otherwise ABSENT, never disabled — org-admin D3) |
|------|------|-----------------------------------------------------------------|
| Library folder | `FolderNode` `⋯` menu, after "Share with org" / "Make private", before the separator and Delete | the caller owns the folder (`isOwner`) **and** belongs to 2+ orgs |
| Root document | `DocumentDetailPanel`, the header's second row beside `DocumentDownloadButton`, as an outline button (`variant="outline" size="sm"`) | `folder_id` is null **and** `is_latest` **and** the caller owns it **and** belongs to 2+ orgs. Not on `DocumentRow`: that row is icon-only and already holds three actions |
| Workflow draft | `WorkflowCardMenu` `⋯` menu, after the Run log / Schedules / API key group, before the fork and delete items | `row.provenance === "draft"` **and** owned **and** not system-global **and** the caller belongs to 2+ orgs. **Published and starter rows never show it** (D-31) |

- Label: **"Move to {Org}…"**, one item per other org, ordered by name. Icon: lucide `ArrowRightLeft`
  (`mr-2 h-3.5 w-3.5`, `aria-hidden`). The trailing ellipsis means a sheet follows.
- With **4+ orgs** (3+ targets) the items collapse into a single **"Move to another organization…"**,
  and the sheet opens on a radio list of target orgs (names only) before the preview is read.
- The folder menu widens from `w-40` to `w-56` when a move item is present. Long org names truncate in
  the item (`truncate`), with the full name in the item's `aria-label`.
- It must stay a `DropdownMenuItem` (the WR-03 `aria-required-children` sweep in `WorkflowCardMenu`'s suite).
- Disqualifiers the client already knows (not owner, published, starter, system-global, solo user)
  hide the item. **Every other blocker is the server's to state** in the sheet (UI-D17): org-shared,
  hold, watch, retention, bound chats or workflows, collision, version family, processing, a
  draft's bound folder.

**UI-D16: the confirm is a victim-naming sheet, not a red one.** Under the graded-guard rule, a
target-specific action with affected items gets a victim-naming sheet. A move is reversible (it can
be moved back the same way), so it borrows the sheet's **shape** without its danger colour. The sheet
is the bottom `Sheet` (`side="bottom"`, `mx-auto max-w-lg`, `aria-describedby` → body id) in the
`WorkflowDeleteSheet` arrangement. The preview is read **before** the action button exists, and the
sheet never shows guessed counts.

| Moved | unchanged | unchanged | `role="status"`: success check + **"Moved to Acme Legal · recorded"**. Stays until the list re-fetch removes the item (the delete-sheet precedent) |
| Refused at confirm (re-check inside the transaction finds a new blocker, 409) | "This can't move to Acme Legal yet" | The server sentence verbatim in the amber box | "Close" |
| Failed at confirm (network / 5xx) | unchanged | `role="alert"`: "Couldn't move it. Nothing was changed." (true: one transaction, D-35) | "Keep it here" · "Try again" |
| Lost membership (403) | "This can't move to Acme Legal yet" | Server sentence, e.g. "You're no longer a member of Acme Legal." | "Close" |

**Copy contract for the move refusals (D-33).** The server writes these, and each names the cause
and the way out. The UI shows them verbatim. Exemplars for the backend plan (planner may refine
wording; the shape is fixed: name the item, the cause, and what to do):

| Blocker | Sentence |
|---------|----------|
| Org-shared | "“Q3 Contracts” is shared with everyone in Personal. Make it private first, then move it." |
| Legal hold | "“Q3 Contracts” is under a legal hold, so it stays in Personal until the hold is released." |
| Watched by a connection | "“Q3 Contracts” is kept in sync from a connected source. Stop watching it first, then move it." |
| Retention policy | "“Q3 Contracts” has a retention policy in Personal. An org admin must remove it first." |
| Pending retention decision | "2 documents in “Q3 Contracts” are waiting on a retention decision." |
| Contents not owned | "“Q3 Contracts” holds 3 documents you don't own, so it can't move as a whole." |
| Chats bound to the folder | "2 chats in Personal use “Q3 Contracts”. Moving it would cut them off from it." |
| Workflow binds the folder | "The workflow “Contract review” uses “Q3 Contracts”. Moving the folder would stop it running." |
| Duplicate in target | "“MSA.pdf” is already in Acme Legal." |
| Version family split | "“MSA.pdf” has earlier versions outside this folder, so they would be split across organizations." |
| Still processing | "3 documents in “Q3 Contracts” are still processing. Try again when they finish." |
| Expert install / classification rule / saved view / recall check | "An Expert installed in Personal reads “Q3 Contracts”." / "A classification rule in Personal files documents into “Q3 Contracts”." / "The saved view “Invoices” looks inside “Q3 Contracts”." / "A recall check expects a document in “Q3 Contracts”." |

**UI-D19: after a move.** On success the client invalidates the elsewhere-count store and re-fetches
the affected list **at the same time**. The item leaves the list only on the server's answer, never
optimistically. The elsewhere line then reads, for example, "1 more folder in Acme Legal · Switch".
That line is the post-move way to reach the item, and its `aria-live` region announces it. A moved
folder that was selected sends the Library selection back to **Root**, and a moved Root document's
detail panel closes when the list drops it. In another tab, the folders Realtime UPDATE carrying the
new `org_id` removes the row (D-10). The audit receipt is the "✎ Recorded…" footer plus the
"· recorded" terminal. No toast.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (move sheet) | **"Move to {Org}"** (e.g. "Move to Acme Legal") |
| Secondary CTA (elsewhere line) | **"Switch"** (`aria-label="Switch to {Org}"`) |
| Row-menu item | "Move to {Org}…" / "Move to another organization…" (4+ orgs) |
| Cancel | "Keep it here" (sheet); "Close" (refused sheet) |
| Elsewhere line | "{N} more {noun} in {Org} · Switch"; Library: "{F} more folder(s) and {D} more Root document(s) in {Org} · Switch" |
| Out-of-org marker | "lives in {Org}" (`{name} — lives in {Org}` inside a native option) |
| Loading on switch (new strings only) | "Loading folders…" (Folder tree) · "Loading your chats…" (history column). All other lists reuse their shipped loading copy |
| Move checking | "Checking what this will move…" |
| Move terminal | "Moving…" → "Moved to {Org} · recorded" |
| Receipt footer | "✎ Recorded with your name in the audit log." |
| Empty state heading | **No new empty state.** Each list keeps its shipped empty sentence ("No folders yet", "You have no workflows yet.", "No recent chats", the run log's `emptyWord`), now shown only after the new org's answer, with the elsewhere line above it when items exist elsewhere |
| Empty state body | Unchanged ("Create a folder to organize your documents." etc.). The elsewhere line is the next step when this org is empty but another is not |
| Error state (move) | "Couldn't check what this would move." + Try again · "Couldn't move it. Nothing was changed." + Try again |
| Error state (ORG-05) | The server sentence, verbatim: "“Q3 Contracts” is in Acme Legal, not in this workflow's organization (Personal). Pick a folder from Personal." |
| Destructive confirmation | **None in this phase.** A move is reversible. Its confirm is the victim-naming sheet "Move to {Org}?", which names what moves before the button exists (UI-D16) |

Copy rules: plain sentences, no codes, no route names, no "query", no roadmap numbers. Item names
use curly quotes “…”. Org names are never abbreviated. A count is never shown before its answer.

## Accessibility contract

- The `Switch` button, the menu items and the sheet controls are keyboard reachable. The sheet uses
  Radix focus trap and restore. After a move completes, focus returns to the menu trigger if it still
  exists, otherwise to the list's elsewhere-line wrapper.
- Every refusal, marker and reason is real DOM text, linked by `aria-describedby` where it explains a
  control. Nothing is carried only in a hover `title` (fence F1, D-14 touch rule).
- Roles: loading = `SyrelLoader` (status), moving/moved = `role="status"`, refused/failed = `role="alert"`,
  the elsewhere wrapper = `aria-live="polite"`.
- Colour is never the only signal. The marker says "lives in", refusals are sentences, and the moved
  state has a check glyph plus words.
- Contrast: all new text uses `--muted-foreground` (≈7.7:1), `--foreground`, `--primary` or
  `--warning` on dark surfaces, all ≥ 4.5:1. `--muted-foreground-dim` is not used for any meaningful copy.

## G-4 lived-experience scenarios this contract must pass (from D-24, UI-observable form)

1. Library switch: the old org's folders never appear after the switch. The tree shows "Loading
   folders…" and never "No folders yet", then the new org's folders. Root's count is omitted, never 0, until it answers.
2. Workflows + run log switch: "Loading your workflows…" / the log's loading line, never "You have no
   workflows yet." or a 0 count, then only the new org's rows.
3. Switch with thread A streaming: the history column shows "Loading your chats…", not "No recent
   chats". Nothing crashes, and the stream behaves as `StreamsProvider` already does.
4. Builder: a crafted foreign binding renders "{name} — lives in {Org}". Saving a changed foreign
   binding shows the server sentence verbatim in the save-error span. Launching shows it in the Run modal.
5. "N more … in {Org} · Switch" shows the true count. Switch lands in that org, on the same view, with those items.
6. Move a folder: the sheet names "This folder, N subfolders and M documents move to {Org}". The item
   leaves the list on the server's answer, the line updates, and one audit row exists.

**How we'd know the UI failed:** a list paints the old org's rows after a switch; any list or count
reads "0" or "No …" before the new answer; the elsewhere line reads 0 or shows while loading; an
out-of-org binding renders blank, as a raw id, or is silently unbound; the ORG-05 refusal reads
"inputs weren't accepted", "we can't read this shape yet" or any generic sentence; the move sheet
shows a Move button before its preview, uses red, or makes an item vanish before the server answers;
a published workflow offers "Move to …".
