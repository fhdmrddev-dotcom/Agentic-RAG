## Surface Contracts

### S1 — "Can't be opened", in place (LINK-04 / D-12..D-15 / D-36 / sketch 299-1 B)

**When it renders:**
- the resolver answers **404** for a parsed entity link (`/app/chat|workflows|runs|experts/<uuid>`).
  Missing, deleted, another user's, an org the person is not in, and a turned-off Expert all
  produce the **same** 404 (D-06/D-08), so the card is identical for all of them;
- the address does not parse (297's S1 case: unknown `/app/...`, a bare unknown path, a malformed id);
- the admin refusal arms in `AppViewSwitch` (non-operator at `/app/admin*`). These render the
  **unparseable** variant, with the same words, from the same copy constant (T-297-07).

It never renders chat silently instead (D-15), never shows a title, an org or an owner, and never
gives a reason (D-13).

**Where it renders (UI-D5):** the overlay covers **the main region only**, over the generic area
for that kind. The nav rail and, for chat, the history column stay visible and usable. Clicking a
history row opens that chat and so replaces the card.

| Link kind | Area behind (unfiltered, unscrolled, identical for missing and forbidden) | Rail highlight |
|-----------|-------------------------------------------------------------------------|----------------|
| chat | History column (live) + an empty main region (no composer, no welcome) | Chat |
| workflow, run | `WorkflowsPage` library, no linked id, no focus, no highlight | Workflows |
| Expert | `ExpertCatalogPage`, no open id | Experts |
| unparseable, admin refusal | History column (live) + an empty main region | Chat (as in 297) |

- The area behind is wrapped in an element carrying `inert` and `aria-hidden="true"`, so nothing
  behind the dim layer can be focused or clicked.
- Below the layout's existing history-column breakpoint (`md`, where the column is `hidden md:flex`),
  there is no column. The card then sits over the main region alone (D-14).
- A run link renders the **library** behind, never `WorkflowRunPage` (RESEARCH Pattern 5).

**Anatomy** (sketch B, mapped to tokens):

```
┌ main region ──────────────────────────────────────────────────────┐
│  [generic area, inert]                                             │
│  ┌ overlay: absolute inset-0 grid place-items-center p-8           │
│  │          bg-background/60 ─────────────────────────────────┐    │
│  │   ┌ card: w-[min(420px,100%)] rounded-xl border-border        │  │
│  │   │       bg-card p-6 shadow-xl text-left ─────────────┐     │  │
│  │   │ This workflow run can't be opened                    │ ← h1 16/600 foreground, mb-2
│  │   │ If someone sent you this link, ask them to check it. │ ← p 14/400 muted, mb-4
│  │   │ ┌ app.syrel.ai/app/runs/c41d8e2a-…-9e2d5b7f0a63 ┐    │ ← code 11 mono muted, bg-muted/40
│  │   │ └────────────────────────────────────────────────┘    │    rounded-md px-2 py-2 mb-4
│  │   │ [ Go to Workflows ]  [ Copy address ]                │ ← flex gap-2; filled primary + outline
│  │   └──────────────────────────────────────────────────────┘     │
└────────────────────────────────────────────────────────────────────┘
```

**Address line (D-36 / F6 / T-297-09):**
- Shown **only** for a parsed entity link. The text is `window.location.host` + `formatAppRoute(parsed)`,
  the **rebuilt** canonical path (lower-case UUID, fixed vocabulary). The requested path is never echoed.
  `/app/chat/<UPPER-UUID>` displays the lower-case form.
- Unparseable and admin-refusal variants show **no address line and no Copy address button**.
- `<code>` has `select-all break-all` and real DOM text (never a `title`).

**Copy address (UI-D7):** an outline `Button`. It uses the same clipboard leaf as S4 (`lib/clipboard.ts`):
- success: the label becomes **"✓ Address copied"** for 2 s (`✓` in `text-success`), and a
  `role="status"` sr-only span says "Address copied";
- refused or unavailable: the address `<code>` text is selected (`Selection.selectAllChildren`), and
  the label becomes **"Press Ctrl+C to copy"** ("Press ⌘C to copy" on macOS) until the next click.
  It never flashes the success word for a copy that did not happen.

**Exit button:** "Go to Chat" / "Go to Workflows" / "Go to Experts" by kind. Unparseable and admin
use "Go to Chat". It calls the existing navigators (`onNavigate(view)`) as a **push**, so browser
Back returns to the link and the card renders again (297 D-15). There is no auto-redirect, no timer
and no toast.

**UI-D4: copy has one home.** The S1 strings live in the `CantBeOpened` module (the successor of
`ADDRESS_NOT_FOUND_COPY`). `AppViewSwitch`'s admin arms import the same constant. Tests assert the
**rendered words**, not a `data-testid` alone.

**UI-D6: focus moves to the card heading on mount.** The heading gets `tabIndex={-1}` and is focused
once, with no visible focus ring, so a screen reader announces it. The area behind is inert, so
focus would otherwise be lost. The wrapper is a `<section aria-labelledby={headingId}>`, not
`role="alert"`: this is a destination, not an interruption. App-wide focus-on-navigate stays out of
scope.

**Identical-render proof (G-4 row 3):** for a made-up UUID and another user's real id of the same
kind, the rendered DOM of S1 is byte-identical, and the network shows the same 404 body for
`GET /links/{kind}/{id}`.

### S2 — Holding while a link resolves (D-02 / Pitfall 5)

**When:** an entity address is on screen and its answer is not in yet. That covers the resolver call
in flight, the chat list not yet settled for the active org (`threadsPending`), and `activeOrgId`
still `null` on a fresh device.

**Markup:** 297's `AddressHolding` verbatim (`role="status"`, `text-sm text-muted-foreground`,
centred, no icon, no spinner, no minimum display time), in the main region. The history column
stays as it is.

| Kind | Sentence |
|------|----------|
| chat | "Opening the chat…" |
| workflow | "Opening the workflow…" |
| run | "Opening the run…" (the existing `COPY_LOADING`, reused, so the hand-off to `WorkflowRunPage`'s own loading state stays invisible) |
| Expert | "Opening the Expert…" |

⛔ While a chat address holds, the main region must **never** render `ChatArea` with `thread=null`
(the welcome composer). A keystroke there would create a new thread and overwrite the link's address.

### S3 — Switch org prompt (LINK-05 / D-16..D-19 / D-37 / D-38 / D-39 / sketch 299-2 A)

**When:** the resolver answers 200 with a **non-null** `org_id` that differs from the active org.
A `null` `org_id` (system-global workflow or system Expert, D-35) opens in the active org with no
prompt.

**Where (D-16):** the prompt **replaces the main region** where the item would open. The rail and
the history column (active org's chats) stay. Nothing switches without a click.

**Anatomy:**

```
                ( A )                                   ← OrgAvatar initial of the TARGET org (36px, shipped), mx-auto mb-4
          This is in Acme Legal                          ← h1 16/600 foreground
  You're working in Northwind. Switch to Acme Legal      ← p 14/400 muted, max-w-[440px], mb-4
  to open it? Your chat that's answering now keeps going.   (last sentence only when a chat is answering)
   ┌───────────────────────────────────────────┐
   │ WORKFLOW RUN                               │       ← item box: inline-flex flex-col gap-1 text-left
   │ Contract review — Q3 supplier batch        │         rounded-lg border-border bg-muted/40 px-4 py-2 mb-4
   └───────────────────────────────────────────┘          caption 11 mono uppercase muted; title 14/600
     [ Stay in Northwind ]  [ Switch to Acme Legal ]     ← flex gap-2 justify-center; outline + filled primary

   ╭ ● "Renewal clause comparison" is still answering  [Back to it] ╮   ← chip, only when a chat is answering
```

Container: `flex h-full items-center justify-center p-8`, inner `max-w-[440px] text-center`, and a
`<section aria-labelledby>`. Focus moves to the heading on mount (as UI-D6).

**Copy:**

| Element | Copy |
|---------|------|
| Heading | "This is in {Org}" |
| Body | "You're working in {Current}. Switch to {Org} to open it?" |
| Body tail (only when `streamingThreads` is non-empty in the active org) | " Your chat that's answering now keeps going." |
| Item caption (kind) | "CHAT" / "WORKFLOW" / "WORKFLOW RUN" / "EXPERT" (rendered uppercase by CSS from "Chat" / "Workflow" / "Workflow run" / "Expert") |
| Item title | the resolver's `title`, verbatim, as React text. This is safe because the resolver only returns it to someone who may open the item (D-16) |
| Decline | "Stay in {Current}" |
| Accept | `switchToLabel(org)` → "Switch to {Org}" (298 vocabulary) |
| Switching (`role="status"`, replaces the buttons) | OrgAvatar + "Switching to {Org}…" |

**UI-D8: org identity is name plus `OrgAvatar` (initial circle), never a per-org colour.** Orgs have no
colour field (F8). The sketch's coloured square becomes the shipped gradient initial circle. The org
name is always in real text beside it.

**The "still answering" chip (D-17), only while a chat in the active org is streaming:**
- Position: `absolute bottom-4 left-1/2 -translate-x-1/2`, `rounded-full border-border bg-card px-4 py-2 shadow-md`, 12px muted.
- A pulsing dot (`h-2 w-2 rounded-full bg-muted-foreground animate-pulse`, steady under reduced motion; the
  dot is decorative, `aria-hidden`), then the words, then `Button variant="outline" size="sm"` **"Back to it"**.
- One chat: "“{thread title}” is still answering". Two or more: "{N} chats are still answering".
- **Back to it** = Stay, landing on that chat (`/app/chat/<id>`). With 2+ chats it lands on the
  most recently started one. The active org is unchanged.

**Stay (D-17 / D-37):**
- The active org is unchanged, and `subscriptionsRef` is unchanged (no AbortError, the stream keeps
  climbing: G-4 row 2, four-axis).
- The address is **replaced** with where the person came from in this tab when an in-app previous
  entry exists, else `/app` (chat home). The mechanism is planner discretion inside
  `useAppNavigation`.
- **UI-D9: the Stay notice.** A one-line bar sits at the top of the surface the person lands on:
  `flex items-center gap-2 border-b border-border/40 bg-card px-4 py-2 text-xs text-muted-foreground`,
  `role="status"`:
  "You stayed in {Current}. The link wasn't opened." + `Button variant="outline" size="sm"`
  **"Open it after all"**. That button restores the link's address (push) and the prompt shows again.
  The bar goes away when the person navigates anywhere else. It has no close button.

**Switch (D-17 / D-37 / F4):**
- The prompt first takes a **snapshot** of the active org's streaming threads
  (`useStreamsStore.getState().streamingThreads`; this is a read, and `StreamsProvider.tsx` is not
  edited). Then it calls the existing `switchOrg(target.org_id)` once. The lists refetch (298), the
  gate re-evaluates once `activeOrgId === target.org_id`, and the item opens.
- The org chip in the rail updates through the shipped switcher. No extra animation is added.
- **UI-D10: the "still answering" line after a switch.** This line shows only when the snapshot was
  non-empty. It sits at the top of the opened item's main region:
  `mx-6 mt-4 flex items-center gap-2 rounded-md border border-border/40 bg-card px-4 py-2 text-xs text-muted-foreground`.
  Content: a decorative dot, "Your chat in {Previous} is still answering.", then
  `Button variant="outline" size="sm"` **"Switch back"**.
  - The wording is deliberately the present-tense fact the server guarantees (the run keeps going on
    the server, D-37). It does **not** promise "it'll be there when you switch back", because
    reattach-on-return is research assumption A1, still to be proven in G-4 row 2. If G-4 row 2
    proves it, the sketch's longer sentence may be restored as a copy-only change.
  - **Switch back** calls `switchOrg(previous)` and opens that chat (`/app/chat/<id>`, push).
  - The line is a snapshot. It stays on that item page until the person navigates away or presses
    Switch back. It is never re-derived from the (now torn-down) subscriptions.

**"Saves in {Org}" (D-18 / D-38 / research write inventory):**
- **UI-D11:** shown only on buttons that **create** an item from an item page (**Run** in `RunModal`,
  **Tweak** in `WorkflowCardMenu`, **Start a chat** in `ExpertDetailModal`), and only when the person
  belongs to **2 or more** orgs. Single-org users see no change.
- Form: a 12px muted caption, "Saves in {Org}", with the org name in `text-foreground`.
  - `RunModal`: directly under the Run button row, right-aligned with it (`mt-2 text-right`).
  - `ExpertDetailModal`: in the footer row beside "Start a chat" (`ml-2 self-center`).
  - `WorkflowCardMenu` Tweak item: the item's existing consequence line (its `aria-describedby`
    target) gains " Saves in {Org}." If the item has no visible line, a second line `text-[11px]` is
    added under the label inside the same `DropdownMenuItem`.
- `{Org}` is the active org, which equals the item's org on any page reached through S3. The caption
  is a hint. The guarantee is the server's (S8).
- No re-run button is added to the run page (D-38 / F5).

### S4 — The link surface (LINK-03 / D-20 / D-21 / D-33 / D-34 / D-39 / sketch 299-3 C)

**UI-D12: the trigger reads "Link", not "Share".** The surface heading in the sketch is already
"Link to this {noun}", and the trigger now uses the same word. The sketch's "🔗 Share" label is
changed because, in this product, "Share with org" (the folder menu) **changes who can see an item**.
A Syrel link grants nothing (LINK-03 is out of scope for outside-visibility sharing). A trigger
called "Share" would promise the capability this phase explicitly does not build. The winner's
shape is kept unchanged: one control, then a surface with the address, Copy and a who-can-open line.

**Trigger:**
- `Button variant="ghost" size="sm"` with `Link2` (`h-4 w-4`, `aria-hidden`) and the word "Link",
  plus `aria-label="Link to this {noun}"`. On the mobile chat header (`< md`), it is icon-only at
  `h-11 w-11`.
- It is a `DropdownMenuTrigger`, with `DropdownMenuContent align="end" className="w-[340px] p-4"`.

| Surface | Mount (one each) | Notes |
|---------|------------------|-------|
| Chat header | After the `<h2>` title, `ml-auto` (`ChatArea.tsx` header row) | Only when a thread exists |
| Workflow library card | **The first item of the card's ⋯ menu**: a `DropdownMenuSub`. `DropdownMenuSubTrigger` shows `Link2` + "Link to this workflow", and `DropdownMenuSubContent` has the same body (`w-[340px] p-4`) | One `DropdownMenuSub` (the `MoveToOrgMenuItem` one-mount pattern); WR-03 stays green |
| Builder header (draft only) | In the breadcrumb group, after the draft label | Absent on the pre-draft "Build a workflow" state (no id) |
| Run page header | In the title row, after the version chip and before the Stop control | Never moves or replaces Stop |
| Expert detail | In the `DialogHeader` title row, `ml-auto`, before the dialog's close control (inside the existing `pr-8`) | The menu portals above the dialog |

**Body (identical in all five mounts):**

```

Opens for members of Northwind.                ← DropdownMenuLabel 12/400 muted, px-1 pt-2; org name text-foreground
```

- **UI-D13: one focusable element.** The only interactive child of the `role="menu"` content is the
  **Copy link** `DropdownMenuItem`, so `aria-required-children` and WR-03 stay green. The address and
  the audience line are non-interactive label text, linked to the item through `aria-describedby`.
  There is no text `<input>`, because a Radix menu fights a focused input (memory
  `reference_radix_menu_focus_kills_inline_editor`).
- The address **shown** is `host + formatAppRoute(route)`, without the scheme. The address
  **copied** is `window.location.origin + formatAppRoute(route)`. Neither ever carries a token or a
  query string.

**Copy link and the one receipt (D-21 / UI-D14):**
- Selecting **Copy link** calls `copyText(origin + path)`, a real `navigator.clipboard.writeText` with
  the explicit failure arm from the `FilePreview` idiom. `onSelect` calls `event.preventDefault()`,
  so the surface **stays open** and shows the receipt where the person is looking.
- Success: the item's label becomes **"✓ Link copied"** (`✓` in `text-success`) for 2 s, then
  returns to "Copy link". A `role="status"` sr-only span says "Link copied".
- Refused or unavailable: the address `<code>` text is selected (`getSelection().selectAllChildren`),
  and the label becomes **"Press Ctrl+C to copy"** ("Press ⌘C to copy" on macOS). It never flashes
  the success word.
- **The receipt lives inside the surface, not in a bottom toast.** The sketch's bottom receipt is
  carried into the surface because the repo has no toast system (a verified zero-import; see the
  `WorkflowsPage.tsx` comment) and the skill's receipt rule is "no toasts" (062-A). "One receipt"
  (D-21) holds: there is exactly one.
- The surface closes on Escape, an outside click or the trigger (shipped Radix behaviour). Focus
  returns to the trigger.

**Who can open it (UI-D15: one line, derived from the D-07 rule as amended by D-33 / D-34).** It is
computed by one pure leaf (`lib/linkAudience.ts`) that mirrors the resolver's `audience` field and
is pinned with a shared fixture. It never promises more than the rule allows.

| Item | Condition | Line (verbatim) |
|------|-----------|-----------------|
| Chat | always | "Opens only for you, on any device you're signed in on." |
| Workflow draft | always | "Opens only for you, on any device you're signed in on." |
| Published workflow | not system-global (D-33) | "Opens only for you, on any device you're signed in on." |
| Starter / system-global workflow | `is_system_global` | "Opens for anyone signed in to Syrel." |
| Workflow run | not finished (D-34) | "Opens only for you, on any device you're signed in on." |

### S5 — The quiet return line on sign-in (LINK-06 / D-22..D-24 / sketch 299-4 A)

**When:** signed out, and `kindWord(parseAppLocation(window.location))` names an entity kind. A
return target that does not parse to an `/app/...` route (off-site, `//host`, absolute URL, non-app
path) shows **no line** and lands on chat (D-23). View addresses (for example `/app/library`) still
return, but show no line, because they name no "thing".

**Where:** `AuthPage`, as a sibling **after** the form component inside `AuthCardShell`'s children.
`SignInForm` and `SignUpForm` are **not modified**: their test pins `signInWithSSO("ssocorp.com")`
exactly, and they have no ledger rows (F10). **UI-D16:** the line therefore sits under the form's
"Don't have an account? Sign up" row, not between the SSO link and that row as in the sketch. It is
still "one quiet line under the form", and that placement is the binding part of winner A.

**Markup:** `<p className="mt-4 text-center text-xs text-muted-foreground">`. There is no icon, no
highlight and no box. The highlighted box was sketch variant B, which was not picked.

| Mode | Copy |
|------|------|
| Sign in | "After you sign in, you'll go to {kind}." |
| Sign up | "After you sign up, you'll go to {kind}." |

`{kind}` ∈ "a chat" / "a workflow" / "a workflow run" / "an Expert". The line names the **kind only**,
from the path, never the title (a signed-out visitor may not learn it). It is React text, never
`innerHTML`.

**After sign-in:** password keeps the address in place. SSO and sign-up return through
`redirectTo` / `emailRedirectTo`, rebuilt from `formatAppRoute`, plus the sessionStorage resume.
Whatever the item is, the person then sees S2, then the item, S1 or S3. They are never dropped
silently on chat.

### S6 — Boot screen, three stages on one clock (LINK-06 / D-26 / SEED-312)

One `BootScreen` replaces the splash JSX in `App.tsx` (one expression). Its clock starts at mount.
When the wait ends at any stage, the app proceeds at once, and a stage message never lingers.

| Stage | Time | Render |
|-------|------|--------|
| 1 | 0 to 8 s | Today's markup **verbatim**: `flex h-screen items-center justify-center`, `role="status" aria-label="Loading Syrel"`, `IrisAvatar state="thinking" size={56}`. No words |
| 2 | 8 to 20 s | The same Iris, and below it (`flex-col gap-4`) `<p className="text-sm text-muted-foreground">Still connecting…</p>` inside the same `role="status"` wrapper (announced politely) |
| 3 | after 20 s | `IrisAvatar state="idle" size={56}` (static), `<h1 className="text-base font-semibold text-foreground">Can't reach Syrel</h1>`, `<p className="max-w-[260px] text-sm text-muted-foreground">`, and `Button` (filled primary) **"Try again"**, all in a `flex-col items-center gap-4 p-6 text-center` stack |

Stage 3 body:
- Always: "Check your connection and try again."
- **UI-D17:** append " Your link is kept, so you'll still land on it." **only** when the address
  on screen is an entity route (the S5 `kindWord` is non-null). On plain `/app` the sentence would
  promise a link nobody opened.

**Try again** = `window.location.reload()`. The URL is kept, so the link survives, and this is not a
History write (`noRawHistoryWrites` stays green). The button gets focus when stage 3 appears.

Thresholds of 8 s and 20 s are as sketched and carried by D-26. A signed-in person whose session
read is slow stays on the boot screen through all three stages and is **never** shown the sign-in
form because of a timeout (Pitfall 6).

## Accessibility contract

- **Roles:** S1 and S3 are each a `<section aria-labelledby>` with an `<h1>` that receives focus once
  on mount (UI-D6). S2, S6 stage 1 and stage 2, and the "Switching…" state use `role="status"`. The
  Stay notice uses `role="status"`. The copy receipts use `role="status"` sr-only spans. Nothing in
  this phase uses `role="alert"`.
- **Inert background:** the area behind S1 carries `inert` and `aria-hidden`, so the Tab order
  contains only the rail, the history column (chat kinds) and the card.
- **The link surface:** Radix menu focus handling (shipped). The single `DropdownMenuItem` is
  described by the address and audience text (`aria-describedby`). Escape returns focus to the trigger.
- **Keyboard:** every action is a real `<button>` / menu item, and none is reachable only by hover
  (the hover-only fence: touch has no hover).
- **Colour is never the only signal:** every state is in words, the ✓ has the word "copied", and the
  org is named in text beside its avatar.
- **Contrast:** all new text uses `--foreground` or `--muted-foreground` (≈7.7:1), or `--success`
  for the ✓ glyph only. `--muted-foreground-dim` carries no meaningful copy.
- **Reduced motion:** the chip and line dots are steady. The Iris follows its shipped
  reduced-motion rule.

## G-4 lived-experience scenarios this contract must pass (D-31, UI-observable form)

The dev account is in two orgs, Claude drives Chrome, and the active org is proven first.
1. Chat header **Link** → **Copy link** → "✓ Link copied" in the surface → paste into a fresh tab →
   the same thread. Refresh stays on it. The audience line reads "Opens only for you, on any device
   you're signed in on."
2. A chat answering in org A, then a run link from org B is opened → S3 with the run's title,
   `OrgAvatar` and "Switch to {B}", plus the chip "“…” is still answering · Back to it". **Stay** →
   org A unchanged, the answer still streaming, and the Stay notice shown. **Open it after all** →
   **Switch** → the run opens with "Your chat in {A} is still answering. · Switch back". **Switch
   back** → the chat (answer present or still streaming: A1).
3. A made-up UUID and another user's real run id → the same S1 card with the same words over the
   Workflows library. The network shows the same 404 body. `/app/chat/<UPPER-UUID>` shows the
   lower-case address. `/app/nonsense` shows "This address doesn't open anything" with no address
   line and no Copy address.
4. Signed out at `/app/runs/<id>` → "After you sign in, you'll go to a workflow run." → password
   sign-in → on the run. Repeat for SSO (or ⛔ with the reason per D-41) and for sign-up. An
   off-site return target shows no line and lands on chat.
5. Slow 3G → "Loading your chats…" at desktop width **and** mobile width, never "No recent chats".
   Block `*/auth/v1/*` → the Iris, then "Still connecting…" at 8 s, then "Can't reach Syrel" +
   Try again at 20 s. Try again keeps the URL.

**How we'd know the UI failed:**
- S1 differs in any way (words, layout, address shown or not, focus) between a missing and a
  forbidden link of the same kind. It shows a title, an org, an owner or a reason. It echoes the
  requested path, or shows an address for an unparseable link. It filters or scrolls the area
  behind toward the item, or lets anything behind be focused. It falls back to chat.
- A cold thread link flashes the welcome composer, or "No recent chats", before S2.
- The org switches without a click. Stay changes the active org or aborts the live stream.
  "Switch to …" is not the only filled button in the prompt. A system-global or system item shows
  the prompt.
- The link surface's audience line says "members" for a thread, draft, published workflow or
  running run. Copy link flashes "copied" when the clipboard refused it. The copied text carries a
  token, a query string or a host other than the app origin. A bottom toast appears.
- The sign-in line names a title, or shows for an off-site target. `SignInForm` / `SignUpForm` are
  edited.
- The boot screen still spins past 20 s with no words, or shows the sign-in form to a signed-in
  person on a slow session read.
- "Saves in …" appears for a one-org user, or on a button that does not create an item.
