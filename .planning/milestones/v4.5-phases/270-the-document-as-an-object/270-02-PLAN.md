<objective>
Ship the download mint: a short-lived signed URL for a document's original file, minted ONLY after the
caller's access is proven through the user-JWT / RLS path, lifetime read from a bounded setting; and put
the file facts and the connection name on the wire (FIND-04 backend, FIND-05 serialization).

Purpose: SC#1 and SC#3 live or die here. The precedent signers (`workspace.py:588`, `sandbox_outputs.py:76`)
sign with the USER-JWT client and only work because the signer owns the file; the `documents` storage
bucket's SELECT policy is owner-folder-only (`full-schema.sql:8254`), so copying them would 404 every org
colleague. This plan uses P-06: RLS read on the user client, THEN service-role sign of that row's
`file_path`. D-04 ("never the service role before the check") is honoured, and proven by an ordered call log.

Output: the route, `DocumentDownloadUrl`, five optional `DocumentResponse` fields, the TTL setting field,
the `list_documents` connection-name batch, and two unit suites.

Decisions applied (operator may override): P-02 (connection name for "Added by", no email), P-03 (no
`document.download` audit type this phase), P-06 (architecture). See 270-VALIDATION.md.
</objective>

| Boundary | Description |
|----------|-------------|
| browser → `POST /documents/{id}/download-url` | untrusted `document_id`; JWT identifies the caller |
| API user-JWT client → Postgres RLS | the authorization decision (org membership + owner / shared folder) |
| API service-role client → Supabase Storage | privileged sign; must only run after RLS said yes, on a server-chosen path |
| signed URL → anyone holding it | bearer token until expiry |
