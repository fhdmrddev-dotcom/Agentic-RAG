<objective>
Give every newly ingested document its own file facts (pages, the date the FILE says it was created and
last modified, the author the file names), stored in typed columns so Phase 271 can filter on them, and
create the TTL setting the download route reads (FIND-05 data half; the FIND-04 setting column).

Purpose: SC#4 is only as true as the rows. D-01 forbids backfill, so an old row must read NULL
("not recorded"), never `0` and never the upload date. This plan also captures the phase baselines and
adds every hot-file ledger row the phase needs, so plans 02-04 run in parallel worktrees without any of
them editing `docs/HOT-FILE-LEDGER.md` or `CLAUDE.md` (P-07).

Output: `270-BASELINES.md`, ledger rows + sections, migration 199 (applied locally), `file_facts.py`,
the one call + one swallowed update in `splice_document`, two unit suites.

⚠ **Deviation from D-03's wording, flagged (operator may override):** D-03 says "page count is one line at
`extraction_service.py`'s page loop". Research measured that FALSE: `extraction_service.py:172` is
`LegacyExtractor._extract_text`, which is not on the primary ingest path (`splice_document` →
`extract_composable` → `aspects.TEXT_ENGINES` with an ordered fallback). D-03's INTENT (page count at
ingest, read from the file; dates/author from PDF/DOCX properties) is delivered by a new pure
`file_facts.py` called once in `splice_document` (P-06). `extraction_service.py` is NOT modified.
</objective>
