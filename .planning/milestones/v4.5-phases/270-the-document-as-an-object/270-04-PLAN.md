## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LibraryPage auth state → panel prop | `user?.id` decides the "You" label only (display, not authorization) |
| version-history rows (owner-only `/versions`) → per-version mint | each button mints for its own row id; the server re-authorizes every mint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-270-22 | Tampering | a version-history button fetching the parent row's version | mitigate | the button receives the version row `v` as `doc`; test asserts `startDocumentDownload` gets the v2 object; the client version assert (270-03) refuses a mismatch |
| T-270-23 | Elevation of Privilege | UI implying access the server would refuse | accept | the UI never pre-checks access (UI-SPEC rule 2); the server's RLS gate (270-02) decides every click and the refusal copy says nothing was minted |
| T-270-24 | Spoofing | `currentUserId` prop spoofed client-side | accept | it only chooses the words "You"; authorization never reads it |
| T-270-25 | Information Disclosure | download state leaking across documents in a reused panel | mitigate | `key={doc.id}` remounts the button per document (tested: an error on A is gone on B) |
| T-270-SC | Tampering | npm/pip/cargo installs | accept | no package installed |
</threat_model>
