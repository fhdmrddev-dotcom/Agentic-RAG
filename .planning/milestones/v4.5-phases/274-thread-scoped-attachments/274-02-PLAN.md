<objective>
Build ATT-03's server side: the explicit promote of a thread attachment into a chosen Library folder,
the read-only version/duplicate preview the dialog shows before confirming, and the per-thread
`library-links` read the chip and panel row render their `In Library` mark from — all in ONE new
module, `backend/app/api/workspace_promote.py`, composed from four shipped doors (D-09..D-14, D-22,
D-27, D-28). Plus the backend half of the D-18 negative audit: a fence that pins every `documents`
minter.

Purpose: SC#3. Promotion is the ONE deliberate act that crosses from the thread into the Library, so
it must use the Library's own minter, refusals, dedup and versioning (D-11/D-12/D-13), and it must read
the person's own attachment through RLS first (BUG-260903-02 shape). It cannot live in `workspace.py`,
whose 244 fence forbids any minter reach — that placement is the structural guarantee *"the chat door
cannot write the Library"*.

Output: the module + its models, one router include, four test suites, a regenerated OpenAPI snapshot
and public spec, and `router:workspace_promote` covered in the API overview page.
</objective>
