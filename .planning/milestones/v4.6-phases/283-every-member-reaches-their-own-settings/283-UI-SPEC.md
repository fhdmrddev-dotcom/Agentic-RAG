## Interaction Contract

### 1. Settings rail entry (FIX-01, D-01)
- Same icon, same label, same slot in `NAV_ITEMS`, for every role. The only change is removing `feature: "model_management"`; nothing visual moves for an operator.

### 2. Settings tab strip (FIX-01, D-02 – D-07)

| Caller | Strip, in DOM order | Lands on (no persisted tab) | Reset |
|--------|---------------------|-----------------------------|-------|
| Member (`model_management !== true`) | Preferences · Memory · Audit Log | **Preferences** (`"6"`) | absent |
| Operator (`model_management === true`) | AI Model · {Search \| Search & Retrieval under ⌥} · Integrations · **Preferences** · Memory · Audit Log | **AI Model** (`"0"`) | present |

- Triggers keep `flex-1` equal shares on the full-width card strip (existing rule, `SettingsPage.tsx:1141-1150`): the member strip is three equal thirds, the operator strip six equal sixths. No left-aligned stub, no placeholder slot.
- The "Preferences" trigger is written as a **literal JSX element**, e.g. `<TabsTrigger className={SETTINGS_TAB_CLASS} value="6">Preferences</TabsTrigger>`, never `{tabs.map(...)}`. Load-bearing: `scripts/lib/docs-content.cjs` and `scripts/check-landing-drift.cjs` regex-scrape literal trigger labels (RESEARCH Pattern 1 / Pitfall 1–2).
- Tab ids: `"6"` is new; `"5"` stays retired and is never reused (D-03).
- **Fallback (D-05):** a persisted `settings_active_tab` the caller cannot see (governed, retired `"5"`, unknown) silently lands on the caller's first visible tab (member → Preferences, operator → AI Model). No toast, no notice.
- **Fail-closed features map:** while the features map is loading, the page shows its existing spinner and decides nothing; a governed tab never flashes for a member (existing pattern).
- Operator `TabsContent` blocks `"0"`/`"1"`/`"2"` render only when `canManageModels` (RESEARCH Pitfall 9): a member's page mounts nothing that calls a `model_management`-gated endpoint, on load or on any tab click (D-07).
- Keyboard: Radix tabs defaults (arrow keys move between visible triggers, Home/End to ends). Hidden tabs are not in the roving order.

### 3. Preferences tab body (D-02)
- Container: `bg-card/50 ghost-border rounded-xl p-6 space-y-6`, the same wrapper the AI Model / Memory / Audit Log bodies use.
- Order: (1) the "Show technical names" row (`rounded-lg ghost-border bg-muted/20 px-4 py-3`), (2) `<ModelDefaultPreference />`. Markup moved byte-identical; only the host changes.
- The AI Model tab loses exactly these two blocks; it now opens on "LLM Providers". Nothing else in tab `"0"` changes.
- Persistence is owned by the components: the toggle via `localStorage` (per device), the default model via `PUT /me/preferences`. No Save button.

### 4. Bounded Chunks list (FIX-08, D-16 – D-20)
- Wrap the existing `<ul className="flex flex-col gap-2">` in one container:
  `role="region"`, `tabIndex={0}`, the `aria-label` above, classes `max-h-96 overflow-y-auto rounded-md focus:outline-none focus-visible:ring-1 focus-visible:ring-ring`.
- **No `overscroll-*` class anywhere** (D-17): wheel/trackpad at the list's end chains to the panel's own scroll container (`DocumentDetailPanel.tsx:327`).
- Keyboard: one Tab stop on the region; ArrowUp/Down and PageUp/PageDown scroll it; the next Tab leaves it. ~~No `tabIndex` on the per-chunk `max-h-32` bodies (1,000 Tab stops would be a trap).~~
  - ⚠ **CORRECTED 2026-10-16 (283-REVIEW CR-01; the original is struck through, not deleted).** Leaving `tabIndex` off the bodies was NOT enough: each body's own `max-h-32 overflow-auto` made it a nested scroll container, and Chrome 130+ ("keyboard-focusable scrollers") and Firefox put an overflowing scroller with no focusable children into the Tab order on their own. The live drive measured **736 of 764** bodies overflowing (`283-LIVE-EVIDENCE.md`), so the trap this line meant to prevent existed anyway. **The per-chunk `max-h-32` cap is REMOVED**: each chunk shows its full text, and the region is the ONLY scroll container in the list. `tabIndex={-1}` on the bodies was rejected because it would leave overflowing chunk text unreachable by keyboard. The unit fence now asserts the mechanism (no `overflow-*`/`max-h-*` class inside the region, and none in `ChunkRowView`'s source), because jsdom cannot model scroller focusability.
- The `jsx-a11y/no-noninteractive-tabindex` hit is suppressed with the justified inline disable from RESEARCH Pattern 5 (WCAG 2.1.1 / axe `scrollable-region-focusable`).
- Loading / empty / error arms are unchanged and are NOT wrapped in the region (the region exists only when `rows.length > 0`).
- Result to verify: with Chunks expanded, the next section header sits at a fixed offset (≤ one list-height, 384px + section chrome) below the Chunks header at any chunk count — measured by `getBoundingClientRect()`, never `scrollTop` (D-20).
- No virtualisation, no filter box, no "Show all" (D-19, Deferred).

## How We'd Know This UI Failed

- A member sees any tab other than Preferences · Memory · Audit Log, any lock/badge/"ask your administrator" text, or a Reset button.
- A member's network log (fresh load straight to Settings) shows any request to `/settings` (except `/settings/providers`) or `/settings/reembed*`. (The Library page's `LibraryStatTiles` 403 is pre-existing and out of scope — RESEARCH Pitfall 7.)
- "Show technical names" or "Default chat model" still renders under AI Model, or renders twice.
- The operator strip order differs from AI Model · Search · Integrations · Preferences · Memory · Audit Log, or the operator lands anywhere but AI Model.
- "Preferences" is styled differently from its neighbours (any class other than `SETTINGS_TAB_CLASS`).
- On a ~764–1,000-chunk document, the next section header is more than one list-height below the Chunks header; wheel at the list end does not scroll the panel; Tab gets stuck inside the list.
- A count or "N of M" appears inside the chunk list.
