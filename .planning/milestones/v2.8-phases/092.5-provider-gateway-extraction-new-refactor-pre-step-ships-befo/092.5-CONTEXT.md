# Phase 092.5: Provider Gateway Extraction - Context

**Gathered:** 2026-06-01
**Status:** Ready for planning

> **Refactor pre-step.** This phase ships BEFORE Phase 093 and exists only to give 093 (and
> every future provider feature) a shared provider boundary to consume. No new requirements
> beyond GATEWAY-01, no schema, no UI. The architecture (build a shared gateway, Deep
> byte-identical) was already locked by the Phase 093 discuss-phase (D-02/D-14, 2026-06-01);
> this discussion sharpens the **HOW** of the extraction.

<domain>
## Phase Boundary

**Extract `agent_loop.py`'s per-provider dispatch + chunk-normalization into ONE shared
provider-boundary module ("provider gateway") that Deep consumes now and the harness will
consume in Phase 093 — with Deep verified byte-identical in isolation (the 089 proof method).**

Today, all "how to talk to each AI provider" logic lives tangled inside the Deep agent loop:
the 3 per-provider branches — Anthropic native (`stream_anthropic`), Google native
(`stream_google`), and the OpenAI-compat path (`create_adaptive_streaming_chat` +
STRUCTURED-mode `parse_structured_tool_calls`) — each with its own `_on_chunk_*` callback that
normalizes raw chunks, mutates loop-local `nonlocal` accumulators, and emits SSE mid-stream.
A **second** OpenAI-shaped accumulator already exists (`task_service._consume_sync_stream`),
which is why the harness sub-agent path is OpenAI-only. A harness-local provider branch would
be a **third** copy. This phase creates the single home so 093 reaches parity by *consuming*
the gateway, not re-implementing dispatch.

**In scope:**
1. Extract the 3 provider branches + their 3 chunk-normalizers into a shared
   `provider_gateway/` package (adapter-per-provider).
2. Point Deep's `agent_loop` at the gateway; verify Deep BYTE-IDENTICAL (089 method).
3. Expose a seam (canonical event vocabulary) the harness sub-agent loop CAN consume in 093
   without re-deriving provider logic — no `threads.py`↔gateway import cycle.

**Out of scope (boundary — see `<deferred>`):**
- Wiring the harness / `task_service` to the gateway → **Phase 093** (it owns the cross-provider UAT gate).
- Killing the `task_service._consume_sync_stream` "3rd copy" → **Phase 093** (provable there, not here).
- A native Google SDK service (SEED-028) → future enhancement BEHIND the gateway; 092.5 extracts the *existing* compat path verbatim.
- Any Deep behavior change, any new provider, any new phase-type.

</domain>

<decisions>
## Implementation Decisions

### Gateway shape (the "one home")
- **D-01:** **Adapter-per-provider package.** Create `backend/app/services/provider_gateway/`
  with one file per provider (`anthropic.py`, `google.py`, `openai_compat.py`) + a thin
  dispatcher entrypoint. Each provider's dispatch + normalizer gets its own physical home —
  the operator's "separate per feature / one home, separated per concern / easiest to find a
  provider bug" principle. The 3 `_on_chunk_*` handlers are ALREADY structurally separate in
  `agent_loop.py` (the Google one is literally documented as a copy of the Anthropic branch
  kept inline so providers can diverge without cross-contamination) — this makes that
  separation physical. A thin internal registry/dispatcher is acceptable if it helps the
  dispatch site, but the per-provider-file structure is the contract, not a pluggable-plugin
  framework (that's v2.9).

### Where the seam cuts (the byte-identical-risk knob)
- **D-02:** **Events out — the consumer accumulates & emits.** The gateway's job is: given a
  provider + request, construct the provider stream AND normalize its chunks into ONE canonical
  event vocabulary (`delta` / `tool_preparing` / `tool_args_progress` / `tool_start` / `finish`
  / `usage` / `usage_delta`). It does NOT own accumulation or SSE emit. `agent_loop` keeps
  owning emit + accumulation — its three `_on_chunk_*` callbacks collapse into ONE
  provider-agnostic handler consuming the canonical events.
- **D-03:** **Why this cut, not "full turn in the gateway":** the load-bearing SSE-emit +
  `nonlocal` accumulation machinery (the exact surface that the 075.x cross-provider cascade
  lived on) NEVER MOVES — it stays in `agent_loop`. The gateway only owns the part 093 actually
  needs: chunk→canonical-event normalization (the harness's whole problem is that
  `_consume_sync_stream` only understands OpenAI chunks). This is "one UX, four adapters" made
  literal: gateway = the 4 adapters producing one event vocab; consumer = the UX layer
  (emit/accumulate). 093's harness writes its OWN tiny consumer against the same events — it
  does NOT inherit Deep's emit coupling.
- **D-04:** Anthropic + Google ALREADY emit a normalized event schema today, so their adapters
  are largely a move of stream-construction. **The real extraction risk is the OpenAI adapter**
  (entangled: STRUCTURED-mode `TOOL_USAGE_INSTRUCTIONS` injection that mutates `messages` +
  `_structured_tools_injected` flag, the `_in_think_block` Kimi/Moonshot `<think>` state
  machine, per-provider 5KB `tool_args_progress` boundary dicts, `reasoning_content`
  round-trip). The OpenAI adapter's chunk→event normalization MUST reproduce `_on_chunk_openai`
  verbatim in behavior.

### This-phase scope
- **D-05:** **Seam only — `task_service` deferred to 093.** Build the gateway, point Deep's
  `agent_loop` at it, prove byte-identical, expose the seam. Do NOT rewire
  `task_service._consume_sync_stream` here. Rationale honoring BOTH operator principles:
  (a) tightest provable byte-identical surface this phase ("never break working things");
  (b) the "3rd copy" dies in 093 where the cross-provider UAT gate can actually PROVE the
  harness/`task()` path works on native-7 — killing it in 092.5 would be unproven, and may
  surface that Deep sub-agents are themselves already OpenAI-limited (which is 093's domain,
  not a byte-identical-extraction concern). ROADMAP SC#3 says the module "exposes a seam the
  harness CAN consume" — 093 does the consuming.

### Proof gate (the red line, made concrete)
- **D-06:** **089 method, native-7, operator runs the live UAT.** Acceptance = Deep byte-identical:
  same-code run1-vs-run2 to establish the noise floor (raw-diffing live LLMs is impossible),
  then before/after STRUCTURAL SSE-diff (`capture_run_events` XRANGE `run:{run_id}` → normalize:
  mask message_id/run_id, drop captured_at → `diff_event_streams` == `[]`) + `eval_cross_provider.py`
  + the E2E backstop, across all native-7 (OpenAI, Anthropic, Google, DeepSeek, Moonshot,
  GLM/zhipu, MiniMax). OpenRouter best-effort (experimental).
- **D-07:** Every per-provider round-trip invariant preserved verbatim AND named in VERIFICATION:
  Anthropic `end_turn` tool execution, Google `thought_signature` echo, DeepSeek
  `reasoning_content` round-trip, Moonshot/Kimi `<think>`-strip + empty-retry,
  `force_no_tools`-on-last-iteration, iteration cap.
- **D-08:** Add a **seam contract test** (NOT in 089): feed the gateway a recorded/synthetic
  provider stream, assert it yields the expected canonical events. This proves the seam shape
  in isolation and IS the foundation 093 builds on. Operator restarts the backend + runs the
  live UAT (established pattern); orchestrator runs automated capture/diff + the contract test.

### Claude's Discretion
- The exact dispatcher entrypoint signature and whether a thin internal registry backs it
  (D-01), provided each provider has its own file and there's no import cycle.
- The exact canonical event dataclass/TypedDict shape (D-02) — but it MUST be a superset that
  losslessly carries every field today's `_on_chunk_*` handlers consume (incl. `thought_signature`,
  `reasoning_content`, `code_so_far`, `total_args_bytes_so_far`, tool-call ids/args).
- Plan-shape / risk sequencing (one wave vs clean-providers-first then OpenAI) — operator
  declined to pre-decide; planner picks, but the entangled OpenAI adapter is the high-risk unit
  and should be isolated as its own provable step (see D-04).

</decisions>

## Existing Code Insights

### Reusable Assets (move/wrap, don't re-derive)
- **`agent_loop.py`'s 3 provider branches + 3 `_on_chunk_*` normalizers** — the proven native-7
  dispatch. Moved into `provider_gateway/` adapters (D-01).
- **`stream_anthropic` / `stream_google` / `create_adaptive_streaming_chat`** — the raw SDK
  boundaries; the adapters WRAP these (they don't reimplement the SDK calls).
- **Google's normalized-event schema** (`google_service.py` docstring) — the template for the
  canonical event vocabulary all 3 adapters emit (D-02). Anthropic already matches it.
- **`parse_structured_tool_calls` + `TOOL_USAGE_INSTRUCTIONS`** — the OpenAI adapter carries
  STRUCTURED-mode recovery verbatim (the entangled part, D-04).
- **`_drain_stream_with_close_on_cancel`** — the shared cancel-safe drain; stays usable by both
  the gateway and the consumer (decide which side owns it at plan time).

### Established Patterns
- **One UX, four adapters** — provider translation lives at the boundary (now the gateway);
  the consumer (UI/SSE/accumulate) stays provider-agnostic. D-02 is this pattern made physical.
- **Additive / None-default no-op for the protected caller** — the F1–F8 + Phase 089 invariant:
  any shared-file change defaults to byte-identical for the Deep caller.
- **Callable-injection seam, no import cycle** — preserve the `threads.py`↔services boundary;
  the gateway must not import back up into `threads.py`/`agent_loop` orchestration (SC#3).

### Integration Points
- Consumption site (this phase): the 3 provider branches in `agent_loop.run_agent_loop`'s
  iteration loop (`:1388-1657`) collapse to ONE gateway call + ONE `_on_chunk` handler.
- Future consumption site (093, NOT this phase): `task_service._stream_one_iteration` (`:177`)
  + `run_task_sub_agent` (`:196`) point at the same seam.

### 🔴 Protect Surface (do-not-break — verified load-bearing)
- The SSE wire shape emitted by `_emit` (`agent_loop`/`threads.py:145-159`) — must be
  byte-identical before/after (D-06 SSE-diff is the gate).
- ALL per-provider round-trip invariants (D-07) — preserved verbatim, named in VERIFICATION.
- `sub_agent_service.py` — byte-frozen (D-085-16). NOT touched by 092.5.

<specifics>
## Specific Ideas

- **Value framing (operator):** this gateway is the structural unblock for the milestone's
  headline value — a durable automation engine that runs the same trustworthy way on EVERY
  provider, not just OpenAI. The harness working on 1-of-7 providers is the value at risk;
  this phase is the foundation that lets 093 fix it. It's first-class engine work, not polish.
- **Operator architecture principles governing this phase (verbatim intent):**
  (1) one home for provider logic, separated per concern → D-01; (2) the safest seam that keeps
  Deep byte-identical → D-02/D-03; (3) prove it where it can be proven (don't front-run 093's
  UAT gate) → D-05; (4) NEVER break working things → D-06/D-07 + the protect surface.
- The entangled OpenAI adapter (D-04) is the one place a "while-I'm-in-here" cleanup would
  re-open the 075.x cascade — extract it verbatim, isolate it as its own provable step.

</specifics>
