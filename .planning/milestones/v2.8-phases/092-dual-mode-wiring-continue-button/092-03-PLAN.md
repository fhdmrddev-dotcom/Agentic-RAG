## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /runs/{id}/continue | Untrusted run_id + repeated requests; ownership + the 3-cap must be enforced server-side |
| client → cancel | Untrusted run_id; ownership enforced; cancel must not strand the lock |
| persisted dropped-tool-calls carrier → continuation | The re-fed tool calls originate from the model's own prior request (server-persisted), not from the client request body |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-092-09 | Elevation of Privilege | POST /runs/{id}/continue | mitigate | Ownership SELECT (run.user_id = current_user) → 404 before any spawn; mirrors cancel_run (runs.py:633-645) — a user cannot Continue another user's run |
| T-092-10 | Denial of Service (runaway cost) | Continue cap bypass | mitigate | continues_used is a DURABLE column (survives WORKER_COUNT=2); the endpoint refuses server-side when continues_used >= max_continues_per_run — a crafted 4th request is refused regardless of client state |
| T-092-11 | Denial of Service (self) | dangling Harness lock | mitigate | SC#2: cancel AND natural terminal clear active_workflow_run_id in the same terminal transaction; a thread can never be stuck Harness-locked with a terminal run (SC#5 reconcile is the additional heal) |
| T-092-12 | Tampering | re-fed dropped tool calls | mitigate | The continuation pre-loads ONLY the server-persisted carrier-row tool_calls (model's own prior request), never client-supplied tool calls; `$N` placeholders for all DB writes |
| T-092-13 | Information Disclosure | continue on terminal/non-cap run | accept | Continuing a run that is not cap_paused is a no-op/clean refusal — no data exposed; low risk |
