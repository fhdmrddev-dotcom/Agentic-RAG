## Accomplishments

- **`useDerivedPanel(threadId)`** (StreamsProvider) — a PURE read selector over the viewing thread's persisted chat `tool_calls` (flattened across all assistant messages in `bucketsBySurface.get("chat")`). Consumes Plan-01's `shouldPopulate` (gate: `write_todos` OR ≥2 deduped MEANINGFUL tools) + `deriveWorkspacePanel` (the locked label precedence). Returns the stable module-level `EMPTY_DERIVED` ref when `threadId` is null OR the gate does not pass — so reading it never forces a chat re-render. **Option (b)**: it NEVER writes `todosByThread` and NEVER mutates the chat bucket reference (PANEL-06 / FC#1 isolation preserved by construction — no fallback to option (a) was needed). Reload-safe for free because `tool_calls` are DB truth reconstructed by `_mapMessageResponse`.
- **TodosSection precedence render** — real `write_todos` plan wins (precedence 1, today's behavior verbatim); else, when `useDerivedPanel` is non-empty, render activity-derived **read-only** rows with a subtle "derived from activity" marker at the section top (precedence 2); else `return null` (precedence 3, clean). A real plan is NEVER overwritten by derived rows.
- **Cross-provider parity by construction:** the derivation is a provider-agnostic projection over persisted activity — a provider that never loops `write_todos` (e.g. the OpenAI-gpt-5.4-mini bar) now gets the same filled panel from its real tool activity. Closes the panel-fill symptom of BUG-260604-01 and gives non-Anthropic runs meaningful labels via the Plan-01 `inferLabel` chain.

## Decisions Made

- **Option (b) over option (a):** implemented the panel wiring as a panel-side READ-ONLY derived selector that does NOT write `todosByThread` (RESEARCH Open-Q1 / A2). Chosen because writing derived items into the panel store from the chat path risks the PANEL-06 isolation contract and muddies real-vs-derived precedence; a pure read keeps ONE clean precedence and zero cross-store write. The FC#1 isolation test passed by construction — no fallback to option (a) was required.
- **Churn guard:** the store selector returns the STABLE chat `Message[]` reference (changes only when the bucket changes); the derivation is memoized over that ref + `threadId` so `useDerivedPanel`'s output identity is stable until the thread's tool activity actually changes — avoiding `useSyncExternalStore` re-render churn.
- **Marker placement (Claude's discretion per RESEARCH):** a single subtle, non-interactive "derived from activity" line at the section top (dim mono uppercase, reusing `text-panel-muted-foreground-dim`), within the existing TodosSection shape.
- **WorkspacePanel.tsx left UNTOUCHED** (per the plan — `files_modified` excludes it; the derived count surfacing in the section header is out-of-scope polish). The derived rows render inside the existing "Todos" PanelSection body via TodosSection.
