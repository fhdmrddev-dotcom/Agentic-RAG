# Phase 095.1: Cross-Provider Run Honesty & Workspace Parity - Context

**Gathered:** 2026-06-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Make every provider's runs **honest and legible**. Born from Phase 095's live
cross-provider UAT (2026-06-06), which surfaced 5 unplanned cross-provider/honesty
findings plus one operator design reversal. Six fixes, all shared / frontend /
gateway — so they naturally cover all 8 providers (openai, anthropic, google,
deepseek, moonshot, glm/zhipu, minimax, openrouter; OpenRouter/Ollama panel =
best-effort, structured mode):

1. The workspace todos/tasks panel fills **consistently** for every provider on
   genuine multi-step work — including providers that never call `write_todos` —
   and stays clean for trivial chats. Deterministic, never forced.
2. Provider errors read **truthfully** (a rate-limit is not "billing").
3. A run that produced its deliverables but ended failed/timed_out does **not**
   falsely offer "Resume".
4. The timer shows the **true** duration on reload, never time-since-creation.
5. Every assistant response surfaces **which model** generated it.
6. Output files render as **one flat list** — no misleading "hero" crown.

**Acceptance bar (operator's words):** every provider behaves like the OpenAI
gpt-5.4-mini run did — the workspace panel shows the *real tasks it actually
performed*. Verified LIVE across all 8 providers (SC#10 4-axis).

**NOT in scope:** fixing model *behavior* (whether a model loops todos or does
work step-by-step) — we make the panel honest about what each model *did*, not
force models to behave the same. The dedicated planner sub-agent (spike option B)
is deferred. No new migrations.

</domain>

<decisions>
## Implementation Decisions

### Workspace Parity — the deterministic panel (REQ: WORKSPACE-PARITY)

- **D-095.1-01 (panel derivation locus + render shape):** The panel is filled by a
  **frontend-derived projection**, layered additively on the existing todos store.
  Precedence: if the model called `write_todos`, show those real todos (today's
  behavior, untouched); otherwise, when the smart gate passes, **synthesize** panel
  items from the already-present/persisted `tool_calls`. Rendered as synthesized
  **read-only** todo items in the **same** todos panel UI (subtle "derived from
  activity" marker; status mirrors each tool's status — user can't tick a derived
  item). **No backend change, no new SSE event, no migration.** Reload-safe for
  free: `tool_calls` are persisted DB truth and reload-reconstructed (proven by the
  095 work), so the selector recomputes the identical panel next-day.
  - Rejected: backend-derived synthetic SSE events — touches the shared agent-loop
    emit path (cross-provider regression surface, violates the byte-identical Deep
    invariant) for zero benefit.
  - **Research flag:** confirm the frontend thread store retains
    `execute_code.description` through both live-stream AND reload-reconstruction
    (the run-card renders it, so it should — 5-min verify before planning).

- **D-095.1-02 (smart gate + meaningful-tool set + label precedence):** The
  spike-006/007 logic is the source of truth (see canonical refs — `spike.py` IS the
  validated algorithm). Port it to a frontend selector.
  - **Gate:** populate when the model called `write_todos` **OR** there are **≥2
    meaningful tool calls** (`GATE_MIN_STEPS = 2`). One-shot Q&A / single lookup →
    no panel (stays clean). Never forced, never prompt-instructed.
  - **Meaningful-tool set (one named constant `MEANINGFUL_TOOLS`):**
    *Producers* — `execute_code`, `workspace_write`, `workspace_delete`, `task`,
    `analyze_document`, `save_skill`. *Substantive retrieval* (inclusive, per
    operator) — `search_documents`, `query_documents`, `query_tables`, `web_search`.
  - **Excluded from the count:** read-only nav/inspection (`ls`, `tree`, `grep`,
    `glob`, `read`, `workspace_read`, `workspace_list`, `workspace_diff`,
    `read_skill_file`, `recall`) and meta/control (`load_skill`, `remember`,
    `ask_user`). `write_todos` is excluded from the *tally* but keeps its own
    always-populate branch (honor the model's explicit plan).
  - **Label precedence (deterministic, graceful):** `write_todos` >
    `execute_code.description` > **code-inferred** (spike-007 leading-comment +
    keyword heuristic: `.to_csv`→CSV, `savefig/plt`→chart, `from docx`→Word, etc.)
    > `"Run code"`. So Claude's derived panel comes out ≈ word-for-word identical to
    OpenAI's `write_todos` plan (spike-006 proved this).

- **D-095.1-06 (flat "Generated files" list):** Drop the "★ Your file" hero crown
  and the hero/working split. **Frontend-only.** Collapse `FinalOutputsPanel` into
  ONE equal "Generated files" list — every file an equal `OutputFileCard` row, all
  visible, all downloadable. **Keep** the url-less "Download unavailable" honest
  affordance (orthogonal to crowning — it's a real honesty fix). **Keep** the
  backend `is_hero` flag sitting unread (harmless, forward-compatible — no backend
  churn, nothing cross-provider can break). Reverses the visual part of 095-05/08.
  - Future, only if file-bloat is felt: a plain length-based "show all" — never a
    "this one's primary" guess again.

### Run Honesty (REQ: RUN-HONESTY)

- **D-095.1-04 (model attribution):** The run-sub line under the RunCard title
  (currently `turn N`, stubbed in 095-07 with a "model OMITTED" comment) becomes
  **`{provider} · {model} · turn N`**, showing the **real resolved model ID** from
  `runs.model` / `runs.provider` (so "which model actually answered" is honest —
  e.g. `google · gemini-3.5-flash`, `openai · gpt-5.4-mini`). **Visible at rest**
  (no expand needed) on **every** assistant response. Additive SELECT through the
  existing runs↔messages enrich → `MessageResponse` → `Message` type → `api.ts`
  mapper → RunCard runSub. **No migration** (data already in `runs`, NOT NULL,
  already joined). Legacy messages with no run row → no line (graceful).

- **D-095.1-05 (true reload timer):** `runs.completed_at` already exists AND is
  already written on finalize (`db/runs.py`) — confirmed. Add `started_at` +
  `completed_at` to the **same** runs→message join as D-095.1-04 (no migration, no
  new write). A finished run's duration = **`completed_at − started_at`** (true
  persisted wall-clock — identical live and on reload). Live ticking only while
  actually streaming. **Honesty rule:** never compute a finished run's elapsed
  against the current clock; a finished run with no real end-time shows **no
  duration** rather than a fabricated one.

- **D-095.1-07 (deliverable-aware Resume):** The Resume affordance gate (currently
  `runStatus ∈ {failed, timed_out}` at `MessageItem.tsx:425`) becomes
  **deliverable-aware** — a run that already produced its deliverables (e.g.
  `execute_code` persisted output files mid-loop) before a later iteration
  failed/timed_out does **not** falsely offer Resume. Frontend, all-provider.
  Re-opens the genuine-terminal case 075 didn't cover (075 fixed only the
  mid-stream transient case).

### Provider Errors (REQ: PROVIDER-ERR)

- **D-095.1-03 (gateway-boundary error classification):** Stop guessing the error
  cause from keyword-scanning the stringified exception (`agent_loop.py:2249`, which
  checks "billing" first with a keyword list containing "quota"/"rate limit" — so
  Google's 429 `RESOURCE_EXHAUSTED` text trips the billing branch). Instead,
  classify **per-provider at the 092.5 gateway boundary**: each adapter
  (`provider_gateway/anthropic.py` / `google.py` / `openai_compat.py`) maps its own
  native errors to a small **normalized error-kind** using **structured status
  codes** (429 = rate-limit, 401 = auth, 402 = billing, 400 = bad-request,
  5xx = server, else unknown). The shared chat loop renders one honest message per
  kind. 429/RESOURCE_EXHAUSTED → rate-limit-with-retry, ordered so it can NEVER fall
  into "billing" again. **Honesty rule:** only claim a specific cause when a
  structured signal proves it; when uncertain → neutral truthful message ("the
  provider returned an error" + raw detail), never a guessed cause. This re-homes
  the categories the current picker already has onto reliable per-provider signals
  (a refactor + fix, not new surface), honoring the gateway-separation architecture.

<specifics>
## Specific Ideas

- **Acceptance bar = OpenAI gpt-5.4-mini parity**: the operator's lived reference is
  the 5.4-mini run that showed the real tasks it performed ("print the numbers",
  "create the CSV", "make the chart") and ticked them off. Every provider must reach
  that bar via activity-derivation.
- **Honesty over guessing** is the through-line for D-095.1-03 / 04 / 05 / 06: never
  guess a billing cause, never fabricate a duration, never crown the wrong file,
  always show the real model. Show *nothing* before showing a *lie*.
- **Spike option B (dedicated planner sub-agent)** would only add an *upfront* plan
  before the first tool — explicitly NOT required for correctness; deferred.
