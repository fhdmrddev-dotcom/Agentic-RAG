<objective>
Close the second half of gap G1 (the per-file failure reason), finish gap G2 on the surface, and make the ONE
control of gap G3 actually appear.

Purpose: `SENTENCE_FOR_FILE_FAILURE` was written, tested and mounted by NOTHING — grep finds it in the vocabulary
leaf and its own suite only. Meanwhile `connector_watch_items` already stores per-file `state` and `name`, and
`GET /sources/watches/{id}` already returns them, and no frontend module has ever called it. So the reason a file
could not be read exists in the database and has never reached a person. And separately, the control that fixes a
stopped source is absent in the live tree, because `IngestionTab` mounts the card with no navigator — so
`Reconnect {name}` renders nowhere at all.

⭐ THE SEAM DECISION, STATED RATHER THAN IMPLIED. This plan renders **current-state** per-file failures — what is
wrong with the files RIGHT NOW — and says so on the screen. It does NOT claim per-RUN attribution. D-235-06
explicitly rejected `connector_watch_items` as the HISTORY source because it records current state, not history,
and that reasoning is unchanged: an item carries one `state` and one `updated_at`, so a file that failed in two
runs can only be attributed to the later one. Per-run attribution needs a new per-run writer; that is `SEED-254`,
created here with a trigger, not quietly skipped.

Output: the per-file list with its scope note, the last-good instant, the wired control, and the deferral record.
</objective>
