<objective>
Stop the Sync button reporting success for work that cannot happen, and stop one bad connection taking every
source's list down with it.

Purpose: `BUG-260906-02` is the defect that HID the blocking one. The endpoint replies
`status="scheduled", message="Watch {id} scheduled for immediate sync."` — describing the request, not the
outcome — and it says exactly the same thing with the loop switched off. The operator clicked Sync, waited, and
nothing happened; `last_run_at` was `None` and the watch had never run once.

And `list_folder_watches` declares `response_model=list[WatchResponse]` over a loop with no per-row boundary, so
one row failing validation is a 500 for every watch the caller owns — `SEED-239`'s measured shape, live.

Output: a refusal that names configuration, a reply that carries the outcome, and a list where a broken row is a
named degraded row rather than an error page.
</objective>
