<objective>
Thread what the tick actually did into the row Plan 01 built — at all four release seams, not two.

Purpose: `sync_watch` returns `{"status": "success", "counts": counts}` to `tick():111`, whose very next line is
`processed += 1`. The dict dies there. This plan is where SURF-02 stops being a schema and starts being a
record — and where the substring sniff that has been standing in for failure classification is replaced by a
named cause.

⛔ The single most likely way to get this wrong is to edit only `sync_watch`. Site 1 is `tick()`'s per-watch
`except` at `:107-117`, outside `sync_watch` entirely, and it is the arm that catches every crash-shaped
failure — precisely the failures a person most needs to see in a history.

Output: four seams each writing exactly one honest row, and a suite that fails if any one of them stops.
</objective>
