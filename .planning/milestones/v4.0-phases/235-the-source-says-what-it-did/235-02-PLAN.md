<objective>
Turn a source failure into a named cause on the backend, and give every cause exactly one sentence and one
control on the frontend — bound to each other so they cannot drift.

Purpose: `watch_service.py:189-197` is the only failure classification that exists today, and it is a substring
sniff (`if "403" in err_str or "permission" in err_str`). Its output is `str(exc)` written into a `text` column
and rendered verbatim at `WatchedFoldersSection.tsx:373` (`Last check error: {watch.last_error}`) — the exact
defect `ingestionErrorVocabulary.ts` was built to close, one directory over. LIB-10's *"offers the one action
that fixes it"* is impossible until the cause is a value rather than a string.

Output: `failure_cause.py` (data, writes nothing, imports no DB) and `sourceHealthVocabulary.ts` (presentation,
zero imports), with a suite that reds when either side gains something the other lacks.
</objective>
