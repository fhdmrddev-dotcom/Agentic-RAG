<objective>
Build the three client-side leaves every surface in this phase consumes: the API client, the single verdict
reader, and the pure fold that turns 17 stored ticks into 3 rendered lines.

Purpose: D-235-05 puts the debounce in exactly one place on the server so the badge, the Health row and the
source card can never disagree — which only holds if the client has exactly one reader too. D-235-07 stores
every tick, including the quiet ones, so *"when did it last successfully READ"* is answerable; that makes
density a rendering concern, and this plan is where that rendering rule lives as a pure, testable function.

Output: `lib/api/sources.ts` gains two calls and their types; `useSourceAttention` polls the verdict;
`runHistoryFold` + `RunHistoryList` render a history whose quiet runs collapse to one line.
</objective>
