<task id="237-03-02" name="Scope Selector in RuleBuilderPanel" wave="3">
In `frontend/src/components/classification/RuleBuilderPanel.tsx`:
- Add state `const [ruleScope, setRuleScope] = useState<"watch" | "classification">(rule?.rule_scope ?? "classification")`.
- Add Segmented control or radio group:
  - `Arrival (Watch)`: "Evaluated as files arrive — matches name, path, type, size, source."
  - `Extracted (Classification)`: "Evaluated after reading — matches metadata, topics, custom fields."
- Pass `ruleScope` to `ConditionPopover` when adding/editing conditions.
- If switching from classification to watch, warn or clear out-of-scope conditions that cannot be evaluated at watch time.
- Include `rule_scope: ruleScope` in the `createRule` / `updateRule` call.
</task>

<task id="237-03-03" name="Dynamic Field Filtering in ConditionPopover" wave="3">
In `frontend/src/components/ingestion/ConditionPopover.tsx`:
- Add optional prop `ruleScope?: "watch" | "classification"`.
- If `ruleScope === "watch"`:
  - Present only arrival fields: `name`, `path`, `mime`/`type`, `size`, `source_system`, `source_connection_id`.
  - Exclude extracted built-ins (`summary`, `topics`, `document_type`, `author`, `language`) and custom LLM metadata definitions.
- If `ruleScope === "classification"` or undefined:
  - Present the full set of built-in metadata, enabled custom fields, and source fields.
</task>
