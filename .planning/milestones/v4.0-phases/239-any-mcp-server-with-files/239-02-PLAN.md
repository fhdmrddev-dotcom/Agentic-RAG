# 239-02 — Tool Binding Discovery & UI Binding Selector

**Goal (SC#1, SC#2, D-239-02, D-239-04):** Ensure connecting any MCP server automatically infers file source tool bindings (`list_tool`, `read_tool`) from discovered tool metadata without hardcoding vendor names, persists them as data in `connection.config["source_tools"]`, publishes `"mcp"` from `/connectors/source-families`, and provides an explicit UI selector in `ConnectionFormPanel` so users can inspect and override tool mappings.

## Why this is one plan and not two

The discovery auto-detection in `connector_service.py`, route exposure in `api/connectors.py`, and the UI selector in `ConnectionFormPanel.tsx` form a single functional seam: discovery discovers tools, infers defaults into `source_tools` configuration data, and the UI presents them for human confirmation or override. Splitting them leaves discovery with unseen side effects or UI with missing endpoints.

<threats>
- threat_id: TM-239-05
  category: Injection / Untrusted Tool Name Exploitation
  component: discover_connection_tools / source_tools binding
  disposition: mitigated
  mitigation_plan: Tool names selected for `source_tools` must strictly exist in the sanitized `discovered_tools` list returned by `mcp_client.list_tools`. Arbitrary strings not present in discovered tools are rejected.
- threat_id: TM-239-06
  category: Information Disclosure / Config Leak
  component: ConnectionFormPanel.tsx
  disposition: mitigated
  mitigation_plan: `source_tools` contains only tool names (`list_tool`, `read_tool`), never secrets, API keys, or server URLs.
</threats>
</threat_model>

<action>
In `backend/app/services/connector_service.py`:
- Author helper `infer_source_tools(tools: list[dict[str, Any]]) -> dict[str, str] | None`:
  - Scans `tools` for candidate listing and reading tools:
    - `list_tool` candidates: names matching regex `r"^(list_dir|list_directory|list_files|browse|ls)$"` or tools whose `inputSchema` accepts `path` or `directory` and description mentions files/directory listing.
    - `read_tool` candidates: names matching regex `r"^(read_file|get_file_contents|view_file|cat|read)$"` or tools whose `inputSchema` accepts `path` or `file_path` and description mentions reading file contents.
  - Returns `{"list_tool": chosen_list, "read_tool": chosen_read}` if at least one is detected, else None.
- In `discover_connection_tools(connection_id: str, user_id: str)`:
  - After tools are discovered via `mcp_client.list_tools`, call `infer_source_tools(sanitized_tools)`.
  - If detected and `config.get("source_tools")` is not already explicitly set by user, merge into `config["source_tools"]`.
  - Save updated config to `connector_connections` table.
</action>
<acceptance_criteria>
- `infer_source_tools([{"name": "list_directory", "inputSchema": {}}, {"name": "read_file", "inputSchema": {}}])` returns `{"list_tool": "list_directory", "read_tool": "read_file"}`.
- `infer_source_tools([{"name": "send_slack_message", "inputSchema": {}}])` returns `None`.
</acceptance_criteria>
</task>

## How we'd know this failed

- An MCP file server with `list_directory` / `read_file` is connected but requires manual tool typing because auto-detection failed.
- Discovery overwrites an existing user-specified tool mapping.
- `/connectors/source-families` omits `"mcp"`.
- `ConnectionFormPanel` fails to submit `source_tools` inside `config`.
