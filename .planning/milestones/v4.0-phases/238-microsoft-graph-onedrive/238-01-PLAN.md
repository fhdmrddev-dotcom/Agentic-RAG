# 238-01 — The Graph adapter and its two egress keys

**Goal (SC#2, SC#3, and the material for SC#4):** a `MicrosoftGraphSourceAdapter` that
implements the Phase 232 contract against Microsoft Graph v1.0 for OneDrive, with the
**302 download dance sealed entirely inside the adapter** — no contract parameter, no
`follow_redirects`, no shared-path change.

## Why this is one plan and not three

The egress keys, the adapter and its tests cannot land separately: an adapter without its
keys raises `KeyError` at the socket, and keys without an adapter are dead entries the
`test_190_egress` wiring assertion would still pass on. One worktree, one commit.

## Tasks

### T1 — Egress: two new keys, wired into ALL THREE tables (TDD: extend the wiring test first)

`backend/app/security/egress.py`:

- `ALLOWED_HOST_SUFFIXES`:
  - `"graph_read": ("graph.microsoft.com",)`
  - `"graph_download": ("1drv.com", "sharepoint.com")`
- `_HOST_MATCH`: both `_SUFFIX`.
- `_TLS_SCHEMES`: both `frozenset({"https"})`.

Comment block must state, at the site:
- why a **second** key exists (D-238-01) — Graph's `/content` answers **302** to a
  *different host*, `send_pinned_http` refuses redirects **by design**, and the documented
  remedy is `@microsoft.graph.downloadUrl` + a second pinned call;
- why the download allow-list carries **two** suffixes (D-238-02) — personal OneDrive
  serves `*.files.1drv.com`, OneDrive for Business serves `<tenant>.sharepoint.com`;
  pinning only the first is a fence that holds exactly where the operator tests and
  nowhere else;
- that the URL is **server-supplied by Graph** and therefore semi-trusted — the suffix pin
  is its fence, and the call carries **no `Authorization` header** by design.

⚠ Neither key joins `EXTERNAL_ACTION_CAPABILITIES`. `test_190_egress.py:577-580` already
asserts the extra-key rule; it must stay green without editing it.

**Acceptance:** `pytest backend/tests/unit/test_190_egress.py -q` green, including
`test_the_capability_keys_agree_with_the_shipped_closed_set`.

### T2 — RED first: `test_238_microsoft_graph_adapter.py`

Write the suite BEFORE the adapter and see it fail. Cases:

1. `browse(None)` returns exactly one node — `SourceNode(id="onedrive", name="OneDrive")` —
   and issues **no HTTP call**.
2. `browse("onedrive")` GETs `…/me/drive/root/children` under **`graph_read`**; folder
   facets become `SourceNode(kind="folder")`; file facets are excluded.
3. **`@odata.nextLink` is carried verbatim** as `next_page_token`, and passing it back
   re-issues *that URL* rather than composing a new one. Assert the second call's URL is
   byte-identical to the `nextLink` the fake returned. (D-238-05 — the contract does not change.)
4. `list_files` maps `file.mimeType` → `SourceFile.mime_type`, `size`,
   `lastModifiedDateTime` → `modified_at` (**the version key** — D-238-03), `webUrl` →
   `web_view_url`, and **`parentReference.path` → `SourceFile.path`** with the
   `/drive/root:` prefix stripped (D-238-07.1).
5. **THE 302 DANCE, driven:** `read_file` makes exactly **two** calls —
   (a) `graph_read` to `…/me/drive/items/{id}` whose `$select` contains
   `@microsoft.graph.downloadUrl`; (b) `graph_download` to the returned URL, **with no
   `Authorization` header in the kwargs**. Assert both capabilities, the ordering, and the
   absence of the header.
6. **`/content` is NEVER called.** Assert no requested URL ends in `/content` — this is the
   fence against someone "fixing" the two-step later by following the redirect.
7. **A download URL on an unexpected host is refused** — drive `send_pinned_http` raising
   `EgressRefused("host_not_allowed")` for `https://evil.example.com/x` and assert the
   adapter surfaces a refusal rather than swallowing it.
8. Errors are **enum-only**: a Graph error body carrying a user query string produces a
   message containing the `error.code` and **not** the query text (mirrors
   `_google_error_reason`).
9. `check()` GETs `…/me/drive` and returns `SourceHealth(ok=True, details={...})`;
   a non-200 returns `ok=False` with an enum reason and **does not raise**.

### T3 — `backend/app/services/sources/adapters/microsoft_graph.py`

```
GRAPH_API_BASE = "https://graph.microsoft.com/v1.0"
MAX_FILE_BYTES = 25 * 1024 * 1024          # same ceiling as google_drive.py
SELECT_FILE_FIELDS = "id,name,size,file,folder,parentReference,lastModifiedDateTime,webUrl"
```

- `@SourceRegistry.register("microsoft")` (and `"microsoft_graph"` as an alias, mirroring
  Drive's two-decorator pattern).
- `_get_auth_token` — `get_fresh_access_token(conn_id)`, identical four lines to Drive's.
- `_graph_error_reason(body)` — parses `error.code` / `error.innerError.code`, keeps only
  `[A-Za-z_]` tokens, **never** reflects the raw body.
- `_normalise_path(parent_reference)` — `parentReference.path` arrives as
  `/drive/root:/Documents/Finance`; strip the `/drive/root:` prefix (and any
  `/drives/{id}/root:` form) to leave `/Documents/Finance`; return `None` when absent.
- `browse(conn, folder_id=None, page_token=None)`:
  - `None`/`""`/`"virtual_root"` → the single `onedrive` node, **no HTTP**.
  - `"onedrive"` → `{BASE}/me/drive/root/children`; any other id →
    `{BASE}/me/drive/items/{id}/children`.
  - `page_token` that starts with `https://graph.microsoft.com/` is used **as the URL**.
  - `$select=SELECT_FILE_FIELDS`, `$top=100`; keep items with a `folder` facet.
- `list_files(...)` — same URLs, keep items with a `file` facet, honour `query` via
  `$filter=startswith(name,'…')`… ⛔ **no**: Graph's `$filter` on `name` is unreliable
  across drives. Use `{BASE}/me/drive/root/search(q='…')` when `query` is set, and plain
  children listing otherwise. Single-quote-escape the query (`'` → `''`).
- `read_file(conn, file_id)` — **the two-step of D-238-01**, and nothing else.
- `check(conn)` — `{BASE}/me/drive`, returns `owner.user.displayName` / `email` in details.

**Line budget:** target ≤ 399 lines (the `google_drive.py` yardstick). Record the actual
number — it is SC#4 evidence, not a style note.

## How we'd know this failed

- A `follow_redirects` / `site_id` / `hash_kind` parameter appeared anywhere above `adapters/`.
- `base.py` changed to make the adapter resolve.
- The download call carried an `Authorization` header (Microsoft documents it as unnecessary;
  sending it is how a preauthenticated URL starts failing CORS-shaped for no visible reason).
- `/content` is called anywhere.
- The suite passes with the adapter deleted.
