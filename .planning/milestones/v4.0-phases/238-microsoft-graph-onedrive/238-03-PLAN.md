# 238-03 — The client stops guessing

**Goal (SC#1, and the frontend half of "rows, not code"):** a Microsoft connection appears in
the connected-source picker and the create-watch modal **because the server said its family is
registered**, not because a client-side string test happened to be widened.

## Why this and not a two-character edit

`ConnectedSourceSection.tsx`'s own docblock specifies this plan:

> *"The server's `SourceRegistry` is the authority and there is no endpoint that publishes its
> list, so this filter is the client's honest approximation of it… When a second family lands
> (Microsoft Graph, Phase 238), this predicate is the thing to widen, **and widening it by
> guess is how a dead option appears in a dropdown**."*

Adding `|| id.includes("microsoft")` in two files would satisfy SC#1 and **falsify the
milestone's constraint on the frontend**: Phase 239's second MCP file server would need the
same edit again. `SourceRegistry.list_supported_services()` already exists in `base.py`.

## Tasks

### T1 — Backend: publish the registry

`backend/app/api/connectors.py` — `GET /connectors/source-families`, auth'd like its
neighbours, returning `{"families": ["google", "google_workspace", "microsoft", "microsoft_graph", ...]}`
straight from `SourceRegistry.list_supported_services()`.

- ⚠ **`mock_source` must not leak into production.** Filter it out unless the same dev gate
  `SourceFolderPicker` already uses is on (mirror whatever `D-232-03` shipped — read it, do
  not invent a second gate).
- No new model, no migration, no config. The route is four lines and a docstring naming
  D-238-08.
- ⚠ G-5: `connectors.py` is a FIRING row whose **extraction is still OWED**. Adding a
  four-line route is *honoured by construction* only if it adds no branch and no logic — say
  so in the ledger cell, and do not let this become the place the picker's rules live.

### T2 — `test_238_source_families_route.py`

- Returns exactly what the registry holds, sorted.
- `mock_source` absent when the dev gate is off, present when on.
- Requires auth.
- ⭐ **The route reflects a NEW registration with no route change**: register a throwaway
  adapter inside the test and assert it appears. That is the "rows, not code" property made
  executable rather than asserted in prose.

### T3 — Frontend: one predicate, fed by the server

`frontend/src/components/sources/sourceCapability.ts` (new, ~25 lines):

```ts
export function isSourceCapable(c: ConnectorConnection, families: string[] | null): boolean {
  if (c.status === "revoked" || c.status === "error") return false
  if (families === null) return false          // ⚠ fail CLOSED while unknown — an offered
                                               //    connection that cannot browse is worse
                                               //    than one not offered (the docblock's rule)
  return families.includes((c.service_id || "").toLowerCase())
}
```

- `frontend/src/lib/api/connectors.ts` — `listSourceFamilies(): Promise<string[]>`.
- `ConnectedSourceSection.tsx` and `CreateWatchModal.tsx` — delete both copies of the
  `includes("google")` predicate, fetch the families once, pass them in. Replace each
  docblock's "widen this predicate" paragraph with what actually happened.
- ⚠ **Keep the render contract identical** — `ConnectedSourceSection` still returns `null`
  when nothing is offerable, so a families fetch that fails renders nothing rather than an
  empty picker that explains itself.

### T4 — `sourceCapability.test.ts` + count-gate adoption

- `revoked` / `error` excluded regardless of family.
- `families === null` → **false** (the fail-closed arm, named).
- `"microsoft"` in families → true; `"microsoft"` NOT in families → **false even though the
  string looks like a source** (the arm that proves the guess is gone).
- Add the new suite to `scripts/vitest-count-gate.cjs`'s TARGETS **and** BASELINE knobs.
  ⚠ Phase 214 measured that a suite can sit on the wrong side of exactly one: TARGETS decides
  what runs, BASELINE decides what is guarded. Put it in both.

## How we'd know this failed

- A Microsoft connection appears in the picker but `browse` 404s — the families list and the
  registry disagreed, which is the exact "dead option in a dropdown" the docblock warns about.
- `mock_source` appears in a production build.
- The predicate fails OPEN while the families list is loading, so every connection is briefly
  offered.
- Phase 239 has to touch a frontend file to add its family. That would mean this plan moved the
  guess rather than removed it.
