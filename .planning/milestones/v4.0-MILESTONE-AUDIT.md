## ⭐ What this audit is actually worth remembering for

**Not the gaps — the method failures, three of them, all mine, all the same shape.**

1. The audit asked *"is a VERIFICATION file present?"* and reported its absence — **never opening
   the review that WAS there.**
2. The correction opened the review and escalated its two CRITICALs to *"open, data loss"* —
   **never opening the code.** They had been fixed two days earlier, in an ancestor of the very
   commit being audited.
3. The verifier then found `HI-04` had been fixed at plan `239-07` **after** `239-05-SUMMARY.md`
   logged it as owed — so reading that summary alone would have under-reported it too.

⛔ **Each register only knows about the one below it, and the code is the bottom.** A file listing
is not a review; a review is a claim ABOUT code; a summary is a claim about a moment. **Drive it,
or do not report it.**

⭐ **The same day produced the mirror-image error four times** — assertions so STRICT they would
have failed a CORRECT implementation. Both directions share one root: **asserting a SHAPE that
resembles the property instead of the property itself.** That is [[SEED-270]], and this audit is
its clearest case study because the audit written to catch it committed it twice.
