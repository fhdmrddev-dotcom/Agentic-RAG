<design_notes>
- Slot 106 is the next free migration (live head after 105 = 105).
- Suggested clean implementation (executor may choose an equivalently-correct shape): TWO SECURITY DEFINER functions with a PINNED search_path (`SET search_path = ''`, all refs schema-qualified — hygiene, matches the mig-104 SECDEF pattern), parameterized by trigger args (`TG_ARGV`) so 35 tables share 2 functions:
    * `public.autofill_org_id_by_owner()` — TG_ARGV[0] = owner column ('user_id' or 'created_by'); reads `(to_jsonb(NEW)->>TG_ARGV[0])::uuid`, looks up `org_members.org_id` for that user (LIMIT 1).
    * `public.autofill_org_id_from_parent()` — TG_ARGV[0] = FK column on NEW, TG_ARGV[1] = parent table; reads the parent row's org_id.
  Both: `IF NEW.org_id IS NOT NULL THEN RETURN NEW; END IF;` FIRST (forward-compat no-op when 163 sets it); resolve and assign; if unresolved, leave NULL (fail-safe — NOT NULL rejects). `to_jsonb(NEW)->>col` gives dynamic column access without 35 hardcoded functions.
- BEFORE INSERT fires before the row is written; it does NOT conflict with the UPDATE-only immutability triggers (skill_versions_no_update / workflow_definitions_block_published) — those gate UPDATE, not INSERT. No DISABLE needed here.
- Performance: one indexed org_members lookup per insert (org_members has a user_id index from mig 104) — negligible for the transitional net.
- Multi-org note: LIMIT 1 is correct pre-167 (one membership per user). 163 supersedes this net before 167's multi-org invitations land, so no personal-org disambiguation is needed now — record the assumption in the file + SUMMARY.
- NOT seed-bearing; not a bundled service / env var / sandbox tag → no deploy-artifact (Phase-157/D-16) change.
</design_notes>
