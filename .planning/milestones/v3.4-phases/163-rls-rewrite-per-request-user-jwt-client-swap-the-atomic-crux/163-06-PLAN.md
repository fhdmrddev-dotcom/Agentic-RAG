<objective>
Wave 4, part 1 — the flip on the CHAT/STREAMING hot path. Now that the predicates are applied and inert (plan 05), swap the chat cluster's request-scoped handlers to the user-JWT clients so RLS becomes the real gate, while the agent-loop/producer async-writer path stays service-role (widened to org-aware). This is the CONCUR-01- and SC#10-critical file group (threads.py is the streaming core, just extracted clean in 162.5). The org context rides the request seam ONLY — the provider/gateway path and `agent_loop.py::run_agent_loop` are untouched, so Deep Mode stays byte-identical.

This plan explicitly covers the 162.5-EXTRACTED request-path modules that are called synchronously inside `send_message`: `preflight_workflow_kickoff` (workflow_kickoff.py) still reads `workflow_runs` (a TEN-01-rewritten table) via a raw `get_pg_pool().fetchval` — after the swap that is a live cross-org BYPASSRLS leak on the hot path, so it MUST move to `get_user_pg_connection`. `thread_title.py` must be explicitly classified, not silently inherited.

Purpose: threads.py is the milestone's hottest file and the one that touches streaming + the agent loop. Isolating its swap here keeps the Deep red line and the CONCUR-01 benchmark focused, and forces the sibling 162.5 modules (which a threads.py-only grep would miss) into the same coverage.

Output: the chat cluster + its 162.5-extracted request-path modules running on the user-JWT clients on both DB paths, with the agent-loop writer widened.
</objective>
