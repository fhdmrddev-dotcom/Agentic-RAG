## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /org API | Untrusted `X-Org-Id` header + JWT cross here; the server is the sole authority (no RLS backstop on the roster/audit reads that use service-role) |
| app code → audit_log | audit_log has NO authenticated SELECT policy → RLS cannot scope this read; app-code authz is the only gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-166-01 | Spoofing | get_active_org_id (X-Org-Id header) | mitigate | Validate the header against org_members via a user-JWT/RLS connection; a non-member org → 403. Never trust the client's claimed active org (D-166-06). Locked by test_166_org_gate spoof test. |
| T-166-02 | Elevation | require_org_manage on /org/members | mitigate | Default-deny: current_user_has_permission(active_org,'org:manage') run as the caller; 403 on false. Router-level membership gate + per-endpoint manage gate. |
| T-166-03 | Information Disclosure | GET /org/audit (service-role read) | mitigate | app-code authz: org:audit_view → all org rows; else own-only `.eq(user_id)`; always `.eq(org_id, active_org)`; source = audit_log only (excludes harness_audit/operator_audit_log). `scope` flag → RLS-honest banner, never a silent empty list (ADMIN-04). |
| T-166-04 | Tampering | current_user_has_permission invoked on wrong role | mitigate | Helper runs on get_user_pg_connection (SET LOCAL ROLE authenticated + auth.uid() claims), never the BYPASSRLS pool — so it evaluates the CALLER's permissions, not postgres's. |
| T-166-SC | Tampering | npm/pip installs | accept | No new packages — pure app code over shipped mig-104 substrate + existing supabase/asyncpg clients. No install task. |
</threat_model>
