<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| invite link → app | The raw token is a bearer capability crossing from the (possibly email) channel into the app; the token — not the email — is the authorization |
| invitee → accept path | The invitee is NOT yet a member; the accept INSERT legitimately precedes membership and cannot use the user-JWT RLS write policy |
| app config → email provider | Provider secrets (RESEND_API_KEY) are env-only; the none-log default needs no secret |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-167-01 | Information Disclosure | invite token at rest | mitigate | Store ONLY sha256(token) (token_hash); the raw token exists only in the returned link (T-161-04). none-log logs the LINK, never a bare token elsewhere. |
| T-167-02 | Spoofing | token verification | mitigate | hmac.compare_digest (constant-time) — no timing side-channel; high-entropy token_urlsafe(32); NOT the reversible Phase-150 cipher. |
| T-167-03 | Tampering | concurrent first-login / double-accept | mitigate | pg_advisory_xact_lock + org_members UNIQUE + ON CONFLICT DO NOTHING; status flip guarded WHERE status='pending' (single-use). |
| T-167-04 | Tampering | expired / revoked invite replay | mitigate | Re-validate status='pending' AND expires_at > now() INSIDE the advisory lock before any insert. |
| T-167-05 | Elevation | accept INSERT bypassing RLS on the wrong role | mitigate | The accept is a token-authorized pool/service-role path; the role written is the invite row's role (member/org-admin), and the org is the invite's org — never client-supplied. |
| T-167-06 | Elevation | invitation write without org:invite | mitigate | require_org_invite (org:invite) + the mig-104 org_invitations RLS WITH CHECK as the backstop (Plan 02 writes on the user-JWT connection). |
| T-167-SC | Tampering | pip install `resend` | accept | `resend` is OPT-IN (off by default), slopcheck `[OK]` (RESEARCH Package Legitimacy Audit), lazy-imported only when EMAIL_PROVIDER=resend; the offline default installs nothing. No install task in this plan. |
</threat_model>
