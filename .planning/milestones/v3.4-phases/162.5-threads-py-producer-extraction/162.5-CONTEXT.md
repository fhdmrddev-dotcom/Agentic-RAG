## Implementation Decisions

### The promote decision (resolved D-01)
- **D-A1:** The extraction is a **standalone phase (162.5), executed BEFORE the crux**, not a Wave 0 of 163 (operator-approved 2026-07-19). Rationale: measured ~13–16 combined plans exceed a single phase's full-fidelity budget; the extraction is a pure refactor with a *distinct acceptance bar* (Deep byte-identical) and *zero threat surface*, vs the crux's security core (two-user leak / CONCUR-01 / SC#10); and the hard gate becomes a real **phase boundary** (162.5 verify-work must pass) — strictly safer. ### Module boundaries (from `163-PATTERNS.md`)
- **D-A2:** Four new modules under `backend/app/services/` (or `backend/app/api/` helpers — executor's call, mirroring `run_lifecycle.py`'s location):

  - **`thread_title.py`** — `generate_thread_title` (`:803-898`) + `_strip_think_blocks`/`_derive_title_from_message`/`_clean_llm_title` (`:754-802`) + the inline auto-title emit (`:1360-1408`).

### The 8 finalize-ordering invariants (byte-identical — the acceptance bar)
- **D-A3:** `run_producer.py` MUST preserve, in order: (1) `asyncio.shield`ed assistant-message persist → (2) system_warnings persist → (3) the RUN-01b two-clause todo-reconcile gate → (4) `finalize_run_terminal` atomic run-status co-write → (5) terminal sentinel `XADD` **after** finalize / **before** EXPIRE → (6) `EXPIRE` → (7) harness F2 terminalize → (8) `RUN_TASKS.pop`. (Enumerated in `163-PATTERNS.md`.) The unification of `agent_runner` + `spawn_continuation_run` must not diverge either path from this order.

### Extraction discipline (from the `run_lifecycle.py` precedent)
- **D-A4:** Follow the established "extract a cohesive unit out of `threads.py` into a service module" discipline: **docstring-states-invariant**, **additive / dead-until-wired** (extract the function, then repoint the `send_message` call site), **late imports** to break the `threads.py` ↔ service import cycle. Analog: `backend/app/services/run_lifecycle.py` (the `register_run_start`/`finalize_run_terminal` extraction).
- **D-A5:** **All plans are sequential** — every plan edits `threads.py`, so file-ownership forces serialization (no parallel waves on the same hot file). Order lowest-risk-first: leaves (`thread_title.py`, `run_model_resolution.py`) → `workflow_kickoff.py` → `run_producer.py` (the heart) → the byte-identical gate.

### The acceptance gate
- **D-A6:** **Deep-Mode byte-identical is THE gate.** The final `[BLOCKING]` plan runs the Phase-089 byte-identical harness + full integration suite + a native-provider Deep smoke. `autonomous: false` (the operator starts the backend — `feedback_user_starts_backend`). **Phase 163 does not start until this verify-work passes.**
- **D-A7:** **Zero org/RLS/client-swap content** (pure refactor) → no `<threat_model>` beyond "no new threat surface"; no migration; no new dependency; no new runtime (D-14).
