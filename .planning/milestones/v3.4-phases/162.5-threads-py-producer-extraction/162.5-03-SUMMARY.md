## Decisions Made

- **Missing-usage warning unified onto the shared finalizer.** The producer's `_shielded_finalize` logged `runs.usage missing …` when both token totals were None; the continuation's near-duplicate `_finalize` had omitted it. The unified routine keeps it (the only way the PRODUCER path stays byte-identical from a single routine). Effect on the continuation: one best-effort LOG line when tokens are None — every DB write / ZREM / sentinel / EXPIRE stays byte-identical (log-only, not functional behavior; the plan's whole goal is that the two orderings can never drift).
- **Superset gates, not caller-branching.** Step-3 uses `completed AND cap_disposition != cap_paused` and step-5 uses `terminal_status in _RUN_STATUS_TO_TERMINAL_TYPE` — each subsumes the producer's stricter form and the continuation's plainer form, so ONE routine reproduces both without knowing its caller (per `<interfaces>`).
- **Re-export imports kept in threads.py.** `finalize_run` / `finalize_run_terminal` / `run_agent_loop` / `RunContext` / `load_user_settings` stay imported at threads.py top level even where threads.py's own remaining code no longer uses them — they are the re-export surface `run_producer` late-imports + the `patch("app.api.threads.*")` surface tests target (Plan-02 precedent; no commit hook lints unused imports).
