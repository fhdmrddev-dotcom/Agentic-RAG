# Phase 200.3 Plan 01 Summary: Golden Run Bypass for Human-in-the-Loop Workflows (SEED-164)

## One-Liner
Enabled publishing for human approval workflows by allowing the background golden run to mock-continue `llm_human_input` steps while keeping live execution interactive.

---

## What Was Done

1. **`human_input.py` (`backend/app/services/harness/human_input.py`)**:
   - In `_exec_llm_human_input`, added a check for `getattr(ctx, "is_golden_run", False)`.
   - When active, logs that the background golden run is mock-approving the step and immediately returns `{"text": prompt, "answer": default_answer, "tool_call_id": tool_call_id, "_golden_run_mock": True}` without pausing for human interaction.
   - Live runs without `is_golden_run` continue to wait for real operator interaction.

2. **`publish_service.py` (`backend/app/services/harness/publish_service.py`)**:
   - In `_interactive_phase_failures`, removed `config.phase_type == "llm_human_input"` from the pre-flight check, allowing human-in-the-loop workflows to advance to golden run validation.
   - In `_validate_with_golden_run`, ensured `is_golden_run=True` is provided on `ctx`.

3. **Backend Unit Tests**:
   - Updated `test_publish_service.py` to assert that `llm_human_input` is permitted during publication.
   - Added unit tests in `test_198_node_vocabulary.py` verifying that `_exec_llm_human_input` returns immediately when `is_golden_run=True` with `_golden_run_mock: True`.
