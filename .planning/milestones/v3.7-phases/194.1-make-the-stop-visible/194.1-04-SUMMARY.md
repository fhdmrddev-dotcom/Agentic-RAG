# Phase 194.1 Plan 04: The Shared StopControl, and the Composer Mount — Summary

Pressing Stop in the composer now replaces the control with `⊘ Stopping this run…` in the same
slot and the same synchronous tick; while stopping there is **no Stop control in the DOM at all**,
so a second press is impossible by construction; a stop that never resolves returns a pressable
control at 8 s beside copy stating it was not confirmed; and two Stop mounts for one thread move
together because neither owns the state.

## ⚠ Two behaviour changes that must not be read as details

**1. The composer's Stop is now gated on `threadId`.** `<StopControl threadId={null}>` renders
nothing. **It loses no live case, and that is a measurement rather than a hope:** `ChatArea.tsx`
passes `disabled={isStreaming}` where `isStreaming = useStreamingForThread(thread?.id ?? null)`,
which is `false` whenever there is no thread — so `disabled === true` **implies** a thread exists.
It is nevertheless a real conditional the shipped button did not have, it is stated in three places
(`MessageInput`'s mount comment, the superseded baseline block, and a dedicated
`ChatAreaMode.test.tsx` case asserting the no-thread arm), and **an inert control is exactly what
this phase exists to remove**, so rendering nothing is the honest arm.

**2. The composer no longer reaches `stopStream` (D-22).** It used to:
`onStop={stopStreaming}` → `actions.stopStream`. It now goes through `stopThread(threadId)`, which
is behaviour-preserving — `stopStream` resolved `activeThreadIdRef.current`, which *is* the
composer's thread, and after plan 03 the two bodies are mirrors — and it **retires the second
resolver as a consequence rather than as extra scope.**

⚠ **`stopStream` ITSELF SURVIVES and was deliberately NOT deleted.** It is exported through
`useMessages`' action surface and its removal is a Deep-path change. RESEARCH records it as a
DEFERRAL with a trigger — *"a phase that touches `useMessages`' action surface"* — and that
deferral is carried in **two production files** (`MessageInput.tsx`'s `Props` docblock and
`ChatArea.tsx`'s `inputBar` comment) plus here, because a deferral that lives only in a deleted line
is exactly as invisible as one never written (193.2 WR-05).
