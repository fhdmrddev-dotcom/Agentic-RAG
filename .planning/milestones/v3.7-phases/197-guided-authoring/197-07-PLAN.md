<objective>
Build the five rows — the half of the arrival card that makes the AI's decisions **answerable**
rather than merely reported.

Purpose: AUTH-02 asks that an author drafting from a description be *guided through the decisions
that matter*. D-07 fixes what those are and refuses a per-row "did the AI get this right?" predicate,
because for the requirement row **no such predicate exists** — `SEED-163` measured `gpt-5.5` naming
one-run parameters in 5 of 5 requirements, all 20 of which were still correctly stamped. A fixed row
set is testable by count and mirrors `SeedReceipt`'s own rule that *every* sealed step is listed.

Output: one component and its suite. It is mounted by nobody yet — plan `197-08` composes it.

## The four things this component is NOT allowed to do

Copied from `SeedReceipt`'s charter, which its own suite enforces with `?raw` fences and positive
controls, and which this sibling adopts deliberately:

1. **It authors no sentence of its own.** Every user-visible string is an identifier imported from
   `decisionsVocabulary`, except the requirement verdict, which is the SERVER's sentence arriving on
   the wire and rendered verbatim.
2. **It declares no predicate of its own.** It does not decide whether a requirement is durable, a
   name is good, or a draft is publishable. `D-16` binds every string: the mark means *a model wrote
   this*, never *this is good*.
3. **It opens no request and names no route.** Its ONE contact with the API client is a **type-only**
   import for the readiness shape — asserted as type-only, not merely absent.
4. **It renders every server- and model-authored string as a plain React text child.** The workflow
   name, the requirement text and the template filename are all model- or user-authored. React
   escapes text children; the raw-HTML prop is never used here (`SeedReceipt.tsx:119-121`).

## Row 5's scope is fixed by D-08, and the correction is the useful part

**D-08 — the deliverable row covers the deliverable and NOTHING else. There is no suppression to
report.** The original decision was to surface 193.2's suppression of an `llm_human_input` step, and
that premise was measured FALSE: 193.2's fix is a **prompt clause**
(`workflow_authoring.py:141`), not a post-hoc deletion, and its own comment binds the claim — *"A
prompt clause reduces how often the model composes such a step; it can never guarantee absence."*
**Nothing is removed, so there is no event to surface.** Row 5 states what the workflow produces and
hands the author to the step that decides it. Do not add a suppression line.

## D-20 shapes the copy, and it is a measurement not a preference

Research enumerated every gauntlet stage from source. Stage 1's `business_requirement_missing` is the
**only** definition-level predicate; stage 2 is structural, 2.5 is interactive phases, 2.6 is
grounding fidelity. **Nothing anywhere refuses a publish for a missing KB binding, a missing
template, an AI-chosen name or the deliverable.** So exactly one row may borrow the gate's register,
and it borrows the gate's actual sentence. The other four say *here is what I chose*.

**D-11 is not reversed — its SCOPE is corrected, and both halves stand.** *"The rows ARE the publish
requirements"* is true of **row 3 and of nothing else**. That is not a reason to invent four server
predicates to make the surface read evenly; inventing them would be a publish-gate change, which
this phase puts explicitly out of scope.

**This plan is where ROADMAP SC#1 is satisfied** — *a user drafting from a description is asked the
decisions that change the result, rather than receiving a finished draft in one shot.* The rows are
the asking. ⚠ `REQUIREMENTS.md:34-60`'s recorded lesson binds here: *a requirement that names a
solution rather than a user's goal will be built to literally.* **The acceptance bar is sketch 174's
screen and G-4 rows U1–U9, not the row count.**

```ts
export interface DecisionsListProps {
  /** ── LIVE. Read off the definition by the CALLER on every render, with no `useState`
   *  mirror — the shipped `requirementIsAiProposed` idiom. These are what the definition
   *  says NOW, not what the generation said. ── */
  /** The bound knowledge base's display name, or `null` when unbound. Resolved by the
   *  caller off its own `folderOptions`; this component looks nothing up. */
  folderName: string | null
  /** The bound template's filename, or `null` when none is bound. */
  templateFilename: string | null
  /** The durable business requirement. `""` when absent — never `null`. */
  businessRequirement: string
  /** The workflow's name. `""` when absent — never `null`. */
  name: string
  /** The step that produces the deliverable, from `terminalEmitSlug`. `null` when the
   *  workflow answers in chat. Rows 2 and 5 both jump here — ONE mechanism. */
  deliverableStepSlug: string | null

  /** ── SNAPSHOT. What the server said about ONE generation. ⚠ ABSENT means the server
   *  said nothing, and must never render as a pass. ── */
  readiness?: GenerateReadiness

  /** ── Actions. All REQUIRED (the 192.1 rule): a required member makes the typechecker
   *  enumerate the call sites where a default would let one hide. ── */
  onChangeKb: () => void
  onChangeRequirement: () => void
  onOpenStep: (slug: string) => void
  onChangeName: (name: string) => void
}
```
