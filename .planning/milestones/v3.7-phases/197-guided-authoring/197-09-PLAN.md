<objective>
Mount the card and wire it to the page's shipped seams.

Purpose: this is where the phase becomes real, and it is also where its single most likely
correctness bug lives. The card renders **two different classes of value** and they must be kept
apart:

- **SNAPSHOT** — what the server said about ONE generation: `receiptPhases` (shipped) and
  `readiness` (new). `SeedReceiptProps.phases`' contract is explicit
  (`SeedReceipt.tsx:147-172`): *"an immutable SNAPSHOT of one `POST /generate` result, NEVER a live
  store selector … Hand this prop an array that tracks later edits and the card starts narrating the
  AUTHOR's acts in the AI's voice."* The readiness verdict is the same class of value.
- **LIVE** — what the definition says NOW: `meta.project_folder_id`, `meta.assets`,
  `meta.business_requirement`, `meta.name`, and the terminal emit step. Read on every render with
  **no `useState` mirror**, the shipped `requirementIsAiProposed` idiom.

Conflating them is CR-01's shape for the fourth time. This plan keeps them apart and fences it.

Output: the mount, the snapshot capture, the live reads, two focus seams, and the page suite's
extensions.

**D-01 and D-06 are both satisfied by WHERE this mount sits, not by a guard anyone has to write.**
D-01 — guidance is on the draft, AFTER — holds because the card lives in `graphColumn`, which only
exists in the drafted view. D-06 — **fresh generations only** — holds because the card's `open` is
`showReceipt`, which is set exclusively in the `onDrafted` handler and never on opening an existing
draft or a fork; a re-opened draft, a fork and a hand-built canvas workflow therefore never see it,
which is correct, because the card's claim (*an AI just made these decisions for you*) is only true
at that one moment. ⚠ **Do not add a second gate for D-06 and do not widen `showReceipt`'s setters.**

**ROADMAP SC#1 becomes visible here** — this is the plan after which a user drafting from a
description is actually asked the decisions that change the result.

⚠ **This plan does NOT touch the header identity `<span>` at `:2203`.** D-19 and its declared
`FLAG_OFF_HEADER_MARKUP` re-capture are plan `197-10`'s work, deliberately separated so a header
byte-pin failure can never be confused with a mount failure. Everything this plan adds to the header
group lives INSIDE the existing `canvasEnabled ? (…) : null` affordances — the placement
`193.2-09` established (`WorkflowBuilderPage.tsx:2181-2190`) so *"band 3 is unmovable BY
CONSTRUCTION rather than by care"*. A `ref` also renders no DOM attribute at all.
</objective>
