<objective>
Widen `POST /workflows/generate`'s success payload with the server's readiness verdict (D-13), and
install the mechanical fence against a fourth D-22 instance (D-14).

Purpose: the authoring surface must never invent a verdict. `grounding.py` already owns the ONE
publish predicate and the ONE sentence the gate shows an author; this plan makes the generate path a
second consumer of that same source and ships the verdict on the wire, so the client renders and
never decides (187-24). D-14 then makes the *pattern* checkable rather than the *field*: the
authoring contract advertising something the authoring path never populates is exactly the shape
that produced `SEED-157`, `SEED-163` and the AI-chosen name — and there is a **live fourth
instance** in the tree today for the fence to fire on.

Output: one new key on one `return`, and four new deterministic backend cases with two positive
controls.

⚠ **D-20 binds the payload.** Research enumerated every gauntlet stage from source: stage 1's
`business_requirement_missing` is the **only** definition-level predicate. The payload therefore
carries **ONE** verdict. It must not carry four invented greens for the KB binding, the template,
the name or the deliverable — nothing anywhere refuses a publish for any of them, and a field that
silently carried four invented greens would be strictly worse than no field.
</objective>
