**DEC-11-A — FOUR ARMS, AND THE RESOLUTION ORDER IS EXTENDED, NEVER REORDERED.**

```
1. lastRunStatus === undefined                     -> unknown      (UNCHANGED, and still FIRST)
2. lastRunStatus === null  &&  hasAnyRun === true  -> not-by-you    (NEW)
3. lastRunStatus === null  &&  hasAnyRun === false -> never
4. lastRunStatus === null  &&  hasAnyRun absent    -> unknown       (see DEC-11-B)
5. unrecognised / blank status                     -> unknown      (UNCHANGED, never success)
6. terminal status                                 -> ran          (UNCHANGED)
```

Rule 1 stays first for the reason its docblock gives: it is the stale-deploy case and it must not
fall through to anything that reads a timestamp.

**DEC-11-B — `never` GAINS A PRECONDITION, AND THAT IS THE WHOLE FIX.** ⚠ **This is the single most
important sentence in this plan.** `never` is an AFFIRMATIVE row-level claim (*nobody has ever run
this*), and D-08's governing rule is that the product must not assert a fact it does not hold. When
`has_any_run` is ABSENT — a backend at the `192.2-03` shape, i.e. one that carries the two run fields
but not the new bit — **we know the caller has no run and we do NOT know whether anybody does.** That
is precisely `unknown`'s meaning, so rule 4 takes the EXISTING third arm and adds nothing.

**This is not a deviation from the operator's locked four arms — it is the case those four did not
name.** The two they did name (`has_any_run = false` → *never*; `has_any_run = true` → *not-by-you*)
are honoured exactly. The absent case resolves into an arm that already exists, so the arm count
stays four.

⚠ **Consequence, stated rather than discovered later:** during any window where the frontend runs
ahead of the backend, published rows read *Not recorded* where they used to read *Never run*. That is
a **quieter and honest** degradation and it is the direction D-08 already chose. It is also the arm
`192.2-VALIDATION.md` U4 exercises, which is why U4's script is amended in this plan.

**DEC-11-C — THE FOURTH ARM'S COLOUR: `bg-muted-foreground`, and the three quiet arms must be
pairwise distinguishable.** `unknown` is `bg-transparent` (no mark — no information, T-22's
mitigation in the colour axis); `never` is `bg-border` (a real, quiet bar — a real fact);
`not-by-you` is a real fact carrying MORE signal than `never` (somebody ran it), so it takes a
brighter neutral. ⚠ **It must not be `bg-success`, `bg-destructive` or `bg-warning`** — the caller
has no outcome to report and a coloured outcome would be a fabricated one. `RUN_TONE["not-by-you"]`
is `text-muted-foreground`, matching `never`/`unknown`: the WORDS carry the distinction, which is
what D-01's *colour, and never colour alone* actually requires.
