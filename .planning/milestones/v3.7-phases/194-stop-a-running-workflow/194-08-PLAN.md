<objective>
SC#1, mounts 2 and 3. Both already ship — this plan **verifies and pins** them, and closes the one
real gap RESEARCH found.

Purpose: CONTEXT feared the composer Stop might not fire during a harness run, because
`BUG-260815-04` leaves the chat surface stuck pre-tools and `stopThread` scans for an assistant
message with `runStatus === "streaming"`. **Measured, that fear is not borne out — and the stuck
banner is itself the proof:** the banner branch (`MessageItem.tsx:635`) *requires*
`isStreaming && !hasAnyTools` on the very message the scan targets, so if the banner is on screen,
the scan's target is on screen. The kickoff stamps `runId: run_id` from the kickoff body — the
**producer** id, the correct type. **Mount 2 is a VERIFY-and-pin task, not a fix task.**

⚠ **One real, narrow gap remains, and it is the exact failure class SC#2 forbids.** Between the
optimistic placeholder (`runStatus: "streaming"`, **no `runId`**) and the kickoff stamp, both
resolvers do `if (!runId) return`. **A Stop in that window is a silent no-op.** It is short — one
kickoff RTT — but a silent success is worse than a visible failure in a phase about honesty.

Output: the V-06 and V-08 pins, and the pre-stamp window made observable.
</objective>
