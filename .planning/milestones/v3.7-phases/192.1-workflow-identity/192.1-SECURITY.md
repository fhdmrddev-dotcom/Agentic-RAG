> Per-phase security contract: threat register, accepted risks, and audit trail.

**29 threat entries across 8 plans — 24 `mitigate` CLOSED · 4 `accept` logged · 1 `n/a` verified.**
Every one of the 8 PLAN files carried a parseable `<threat_model>` block, so this audit ran in
**verify-mitigations** mode, not retroactive-STRIDE: the register was complete at plan time and the
auditor's job was to confirm each named control is actually present in the shipped code at HEAD.

**Every SUMMARY.md claim was re-verified independently** rather than taken on the executors' word —
the standing lesson from Phase 190, where nineteen plans of RED-first self-checking still shipped a
real credential exposure (CR-01) because five fences *could not fire*. That is why this document
carries three fence-quality escalations below despite closing at `threats_open: 0`: **all 29
security PROPERTIES hold at HEAD and were each grepped independently; three of the DURABILITY

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| asyncpg pool → API layer | **The pool BYPASSES RLS** (`backend/app/db/workflows.py:277-281`). Whatever the SELECT projects and the API serializes is what the caller gets — the projection *is* the access control. | Workflow rows: slug, version, name, timestamps, concurrency token |
| API layer → browser | Every field on `PublishedWorkflow` / `DraftRow` is public to the authenticated caller. | Same, plus the new `updated_at` |
| browser → API (`POST /workflows`) | The fork write. Unchanged by this phase — same `createWorkflowDraft` call, same body. | User-typed workflow name (free text) |
| server error → user-visible notice | `forkFailed` is the only path from a thrown error to the screen. | `{ name: string; conflict: boolean }` — a shape that cannot hold server prose, a status code or an id |
| wire row → derived claim | The resolver turns slugs and versions into a sentence a person will believe. A wrong claim here is indistinguishable from a right one at a glance. | Provenance / lineage / recency |
| slug string → lookup key | User-influenced strings index into the identity maps. | Slugs — incl. adversarial `constructor` / `__proto__` |
| user keystrokes → new workflow name | Free text rendered back into the DOM and sent to the server as JSON. | Untrusted string |
| documentation → future phases | A wrong number in `CLAUDE.md` or a docblock survives every gate — **nothing typechecks prose** (Phase 189's banked lesson). | Measured figures |

## Escalations — fence DURABILITY (2 WARNING · 1 INFO)

**None of these is a blocker, and none is a property failure.** All 29 security properties hold at
HEAD and each was independently grepped. What follows is where a *future* change could break a
property without any gate noticing — the Phase-190 CR-01 shape, which is precisely what this audit
exists to catch.

### E-1 — WARNING · T-192.1-16's declared assertion does not exist

The register says the `[rows]`-only memo key is *"grep-asserted on the literal dependency array."*
**It is not.**

```bash
grep -rn "\[rows\])" frontend/src --include=*.test.*
# → exactly one hit: rowIdentity.test.ts:815 — a COMMENT explaining why the key must be [rows]
grep -an "identityIndex\|buildIdentityIndex\|useMemo" frontend/src/pages/WorkflowsPage.test.tsx
# → nothing
```

Widening the key to `[rows, query]` — the precise D-05 violation this phase names, and the shape the
page's own neighbouring `counts` memo **already uses** — would pass `tsc`, `eslint`, the count gate
and all 52 page cases.

**Closing shape:** a `WorkflowsPage?raw` source assertion in the OD block (`fences.test.ts:875`),
where `pageSource` is already imported. Roughly one assertion.

### E-2 — WARNING · the subtree sweeps can pass VACUOUSLY per module

All four `it.each(LIBRARY_SUBTREE_PATHS)` sweeps read `LIBRARY_MODULES[path] ?? ""`
(`fences.test.ts:263, 285, 543, 634`). **A module whose glob key disappears — rename, move into a
subdirectory, extension change — is swept against the empty string and passes green.** The
non-vacuity guard (`:164-172`) only asserts `SWEPT.length >= 3` and names three of twelve modules by
hand, so **nine of twelve have no proof they are loaded** — including both new rendering modules.

Mitigating facts, measured rather than assumed:

- F6's scoping control (`:520-525`) does prove `./WorkflowCard.tsx` and `./useWorkflowFork.ts` load
  non-empty.
- Both new rendering modules were independently grepped for all four forbidden properties
  (`title=`, `dangerouslySetInnerHTML`, owner-name fields, `Date(token)`) → **none present**.

So every property holds today; only **durability** is at risk.

**Closing shape:** one line —
`expect(SWEPT.map(f => f.path)).toEqual([...LIBRARY_SUBTREE_PATHS])` — which also subsumes the
existing `toHaveLength(12)` pin.

### E-3 — INFO · T-192.1-03(P03) has no shipped regression fence at the code's new home

The "grep-assertion" for the `forkFailed` shape was an **execution-time check**
(`192.1-03-PLAN.md:288`), not an artifact. After the Wave-3 cut, the only durable control is the
TypeScript annotation at `useWorkflowFork.ts:169`/`:205`. Widening it to carry `String(e)` would
typecheck and pass every suite — and the raw error is **in lexical scope in the same `catch` block**
that already calls `isForkConflict(e)` (`:416`). The widening is one token away. The page-side OD
fence (`fences.test.ts:867`) only asserts the page no longer *declares* the state; it says nothing
about its shape.

Each is ≤ 1 file / ≤ 10 lines with no schema or API surface → **`/gsd:fast` under G-3**, never a
gap-closure round (**G-7**). E-1 and E-2 are the two worth taking; E-3 is INFO and may be left to
