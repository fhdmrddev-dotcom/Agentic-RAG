## Summary

This phase is **one rendered line, one modal, one additive wire field, and one refactor that must
happen first**. The research found the code exactly where CONTEXT said it was — with one line-number
correction and five factual corrections, all recorded below.

Three findings change how the plan should be shaped. **First, the identity resolver as sketched is
not O(n²) — it is worst-case O(n³), and on the operator's real shape it costs ~232,000 inner-loop
iterations per render, on every keystroke.** The fix is not a micro-optimisation but a
restructuring: three linear passes producing three lookup maps, memoised on `[rows]` alone so
typing in the search field never recomputes it. **Second, the fences file is a hard trap: adding
any module under `library/` reds `librarySubtree.fences.test.ts` by construction**, because line 93
asserts `LIBRARY_SUBTREE_PATHS` has exactly 7 entries. Three new modules is a three-line edit in
one file — trivial once known, a confusing mid-wave RED if not. **Third, `PublishedWorkflow` is ONE
Pydantic model serving TWO of the three feeds**, so D-15's "one field per feed" is really two model
edits, four SQL edits, and three builder edits — the additional_context's premise of "a Pydantic
model per feed" is wrong and is corrected below.

The live-DB measurement reproduced CONTEXT's D-13 figures exactly (69 shape / 57 resolve / 12
orphan by ROW) and then found something CONTEXT did not: **`compliance-gap-report` — the slug behind
the 43-row cluster this whole phase exists for — is itself an orphan.** Its `report` suffix is six
legal base-36 characters, so the resolver looks for a parent `compliance-gap` that does not exist.
The consequence is precise and benign but must be stated in the plan: the true ORIGINAL of the
largest family renders **no lineage segment** rather than `Original`. Its 42 children resolve
correctly to `Copy of Compliance Gap Report`.

**Primary recommendation:** Wave the extraction first (D-01), with characterization baselines
captured against the UNMOVED page; build the identity resolver as a pure module with a
precomputed-index signature (`buildIdentityIndex(rows) → resolve(row)`), memoised on `[rows]`;
project `updated_at` additively following Phase 192's own `is_mine` precedent exactly; and add all
new modules to `LIBRARY_SUBTREE_PATHS` in the same commit that creates them.

## Architectural Responsibility Map

| Capability | Primary Tier | Secondary Tier | Rationale |
|------------|-------------|----------------|-----------|
| `updated_at` projection | Database / Storage | API | Column exists (`full-schema.sql:1941`, NOT NULL) and is maintained by a trigger. Pure SELECT widening. |
| `updated_at` serialization | API / Backend | — | Two Pydantic models; the API layer already owns the `is_mine` computation precedent for exactly this. |
| Namesake counting (`1 of N`) | Frontend Server (page) | — | Needs the FULL merged feed (D-05). Only the page holds it. Same reason `hasExistingFork` is a prop. |
| Lineage resolution | Frontend Server (page) | — | Needs the merged slug set. **Never the card** — D-12's discipline: "the card computes nothing about slugs or versions." |
| Relative-time formatting | Browser / Client | — | Pure presentation from a timestamp; no server involvement, no date dependency (D-18). |
| Identity line render | Browser / Client (card) | — | Renders a resolved value handed down as a prop; computes nothing. |
| Fork name collection | Browser / Client (dialog) | — | Collects an input the system cannot know (D-19). |
| Fork pre-flight collision check | Frontend Server (page/hook) | — | Reads the caller's own merged rows — free, already in memory (D-21). Explicitly NOT a server round-trip and NOT a slug check. |
| Fork write (`createWorkflowDraft`) | API / Backend | — | Unchanged. The throw site is explicitly out of scope (D-22). |

**The one misassignment this map exists to prevent:** putting lineage or namesake counting **in the
card**. It is the natural-looking place (the card renders the line) and it is wrong three ways — it
violates D-12's shipped discipline, it makes the resolver O(n) *per card* which is the O(n²) trap
below, and it needs data the card does not have.

### 1c. ⚠ The declaration-order trap, generalised

192-14 recorded that `onOpenDraft` must be declared **above** `onTweak` because a dep array is
evaluated at render time, so a later `const` is a TDZ `ReferenceError` — *a crash, not a lint
warning* (`WorkflowsPage.tsx:543-547`).

**That hazard does not disappear with the extraction; it MOVES to the hook call site.** If the page
calls `useWorkflowFork({ onOpenDraft, drafts, refetchDrafts, … })`, then **`onOpenDraft`,
`refetchDrafts` and `drafts` must all be declared above that call.** Today `onOpenDraft` is at
`:548` and `refetchDrafts` at `:379`; a `useWorkflowFork(...)` call placed where `draftBySlug`
currently sits (`:531`) would be **above `onOpenDraft` and would crash on first render**.

This is the single highest-risk mechanical defect in the extraction. It typechecks clean.

### 1d. ESM cycle risk — F4 and what it does and does not cover

`librarySubtree.fences.test.ts:235-236` defines the fence:

```
IMPORT_FROM_PAGE   = /from\s+["'][^"']*WorkflowsPage(\.[jt]sx?)?["']/
DYNAMIC_IMPORT_PAGE = /import\s*\(\s*["'][^"']*WorkflowsPage(\.[jt]sx?)?["']\s*\)/
```

- **The fork hook needs nothing from `WorkflowsPage`.** All its imports are `@/lib/api`,
  `./libraryVocabulary`, `./libraryRow` — F4-clean by construction.
- ⚠ **A near-miss worth naming:** the page imports `type BuilderInitial` and `useCanvasGate` from
  `@/pages/WorkflowBuilderPage` (`:80`). **F4's regex does NOT match `WorkflowBuilderPage`** — the
  string "WorkflowsPage" is not a substring of "WorkflowBuilderPage". So a library module importing
  the Builder page would pass F4 while creating a page↔library coupling of exactly the kind F4
  exists to prevent. **The fork hook must not import `BuilderInitial`**; it should return a plain
  seed object and let the page adapt it. (This is also why the `onForked` callback shape below is
  the right one.)
- **Precedent for the fence being real:** 188.1-03 shipped a `?raw` ESM-cycle fence for the same
  hazard on `WorkflowCanvas`; 192-05 re-homed `UNBOUND` into `libraryFilter.ts` rather than import
  it back. Both are recorded in the fences file's own docblock.

### 1e. Hook or plain module? — recommendation with a shipped analog

**Three files, not one**, matching the directory's existing split:

| New module | Kind | Contents | Why |
|---|---|---|---|
| `library/libraryFork.ts` | **plain module** | `freshHash`, `isForkConflict` | Both are pure and close over nothing. `libraryFilter.ts` is the shipped precedent: pure predicates, *"unit-proved there without a DOM"* (`WorkflowsPage.tsx:445-448`). | `library/useWorkflowFork.ts` | **custom hook** | `forkFailed` state, `draftBySlug`, `onTweak`, `onUseStarter`, the two adapters | It owns React state and `useCallback`s. A plain module cannot. |
| `library/ForkNameDialog.tsx` | **component** | 162-B's prompt | Standard. |

**Shipped analog for the hook shape: `frontend/src/hooks/useDraftPersistence.ts:472`.**

```ts
export function useDraftPersistence(args: DraftPersistenceArgs): DraftPersistence {
  const { definition, enabled, initialDraftId, initialToken, store,
          publishInFlight, validationCause, onDraftCreated } = args
```

It is the exact posture this extraction needs: **a single args object in, and an `onDraftCreated`
CALLBACK out**, so the page keeps ownership of what happens next. Applied here:

```ts
useWorkflowFork({
  drafts,                    // for draftBySlug
  refetchDrafts,             // NOT moved — the fetch concern stays on the page
  onOpenDraft,               // NOT moved (D-01) — must be declared ABOVE this call (§1c)
  onForked,                  // ← the page's setBuilderInitial + setPageView, as one callback
}) => { forkFailed, draftBySlug, onForkNewVersion, onForkStarter, forkNotice? }
```

⚠ **`onForked` is load-bearing, and the reason is recorded in the shipped code.** 192-14 reused
`onOpenDraft` inside `onTweak` *"rather than a third `setBuilderInitial` call site"*, because that
**"threads 186-07's opaque concurrency token by construction instead of by remembering to — a
dropped token is a silent-clobber bug that typechecks"** (`WorkflowsPage.tsx:576-578`). A hook that
hands back a seed through **one** callback preserves that property. A hook that took
`setBuilderInitial` directly would re-open two call sites.

**Home:** `library/`, per D-01 and the scope fence. Note this differs from `useDraftPersistence`'s
own home (`src/hooks/`) — that is fine, but it means the new modules land **inside the fences** (§7).

## 4. The identity resolver — signature, and the complexity fix

### 4a. ⚠ The sketch is worst-case O(n³), not O(n²) — measured from the source

`163/index.html:297-320`:
```js
function identity(row, rows) {
  var sibs = rows.filter(r => r.name === row.name);            // O(n)
  function varies(fn) { var v={}; sibs.forEach(s => v[String(fn(s))]=1); ... }
  var lp = lineagePhrase(row, rows);                            // O(n)  ← lineageOf does rows.forEach
  if (collides) {
    if (varies(s => lineagePhrase(s, rows)) && lp) segs.push(lp);   // ← O(k) × O(n) = O(k·n)
```
and `library-fixture-192-1.js:334-350` — `lineageOf` does `rows.forEach` in **both** branches.

So one `identity(row, rows)` call costs **O(k·n)** where `k` is the row's family size. Summed over a
family of size `k` that is **O(k²·n)**, and over the whole list **O(n · Σk²)**.

**Cost on the operator's real shape** (n = 106; families 43, 11, 9, 8, and ten 2s):
Σk² = 1849 + 121 + 81 + 64 + 40 + ~15 ≈ **2170** → **≈ 230,000 inner-loop iterations per render.**
Worst case (all rows one name) = **O(n³)**.

⚠ **And it runs twice per render.** `163/index.html:494-495` calls `identity` over ALL rows again
just to compute the "identity lines" counter, then `:559` calls it once per rendered card.

⚠ **And the page re-renders on every keystroke** — `setQuery` is page state (`WorkflowsPage.tsx:249`).

### 4b. The fix — three linear passes, the shipped-pattern shape

`draftBySlug` (`WorkflowsPage.tsx:531-538`) is the exact shipped precedent: a `useMemo` that builds
a `Map` index once so per-row lookups are O(1). Apply the same shape, three times:

```ts
// library/rowIdentity.ts  — pure, no React, unit-proved without a DOM (libraryFilter.ts precedent)
export interface IdentityIndex { /* opaque */ }

export function buildIdentityIndex(rows: readonly LibraryRow[]): IdentityIndex
export function resolveIdentity(index: IdentityIndex, row: LibraryRow, now: number): RowIdentity

export interface RowIdentity {
  own: "Yours" | "Shared"
  segs: readonly string[]      // max 2 (D-04)
  ofN: string | null           // "1 of 43" — only when the name collides (D-04)
  when: string                 // "changed 2 months ago"
}
```

`buildIdentityIndex` — **three passes, all O(n):**

| Pass | Builds | Cost |
|---|---|---|
| 1 | `slugSet: Set<string>`, `byName: Map<string, LibraryRow[]>`, `maxLowerVersionBySlug: Map<string, number>` | O(n) |
| 2 | `lineageByRowId: Map<string, Lineage>` — each row resolved **once** using pass-1 maps | O(n) |
| 3 | `variesByName: Map<string, {lineage, project, state, version: boolean}>` — computed **once per FAMILY**, not once per row | O(n) total |

`resolveIdentity` is then **O(1)**. Whole thing: **O(n)**.

**Where it goes:** the index in a `useMemo` **on the page**, keyed **`[rows]` — NOT `[visibleRows]`,
NOT `[query]`**. Two reasons, and both are requirements rather than optimisations:
1. **D-05 demands it.** `N` is counted over the FULL merged library before filtering. Keying on
   `visibleRows` would make `1 of 43` shrink as you type — CONTEXT: *"a count that shrank as you
   typed would both flicker and misdescribe the library."*
2. **It makes typing free.** With `[rows]`, a keystroke re-runs `filterLibrary` only.

The card receives the resolved `RowIdentity` as a prop, exactly as `hasExistingFork` arrives
(`WorkflowsPage.tsx:1082`). **The card computes nothing.**

### 4c. ⚠ D-13 forces a THREE-valued lineage return, not `Lineage | null`

The sketch's `lineagePhrase` (`163/index.html:287-294`) returns `LINEAGE_ORIGINAL` whenever
`lineageOf` returns `null`. Under D-13 there are **three** outcomes and `null` cannot express them:

| Case | `lineageOf` today | D-13 requires |
|---|---|---|
| slug has no fork shape | `null` → `"Original"` | `"Original"` ✅ |
| shape matches, parent present | `{kind, of}` → `"Copy of X"` | `"Copy of X"` ✅ |
| **shape matches, parent ABSENT** | `null` → **`"Original"`** ❌ | **silence — no segment at all** |

So the resolver needs a discriminated return, e.g.
`{ kind: "original" } | { kind: "copy"; of } | { kind: "version"; of } | { kind: "unknown" }`,
where `"unknown"` renders nothing. **A `null` return type cannot carry D-13 and would silently
re-introduce the fabricated claim.** This is the single most important type-level decision in the
resolver.

### 4d. ⚠ Why the sketch could not surface the orphans — the exact mechanical cause

`library-fixture-192-1.js:335`:
```js
function lineageOf(row, rows) {
  if (!row.parentSlug) return null;         // ← THE SHORT-CIRCUIT
```
`parentSlug` (`:123, :148, :172`) and `forkKind` (`:125, :150, :174`) are **fixture-only fields set
at generation time**. They do not exist on `LibraryRow` and there is no wire equivalent.

**Production must delete that line** — and deleting it is exactly what admits every slug whose last
segment happens to be six base-36 characters. That is D-13's 12 orphans, and it confirms CONTEXT's
explanation at the code level rather than by argument.

**Consequence for the port:** the branch selection also changes. The sketch picks the version branch
via `row.forkKind === "version"`. Production must derive it: **same slug with a lower version present
in the merged list → version fork; else regex + parent present → copy fork; else Original; else
silence.** Order matters and must match the sketch's (version first).

## 10. Risks and pitfalls specific to this phase

### P-1 ⚠ The relative-time clock — freeze vs. drift, and there is no free option
**What goes wrong:** `changed <rel>` depends on "now". If `Date.now()` is called per card, two cards
in one render can disagree across a band boundary. If it is captured inside the `[rows]`-keyed
`useMemo`, the whole line **freezes** — a card can still read `just now` an hour later.
**Recommendation:** split the memo. Identity + lineage + `1 of N` are keyed on `[rows]` (they do not
depend on time). `changed <rel>` is computed during render from **one** `const now = Date.now()`
hoisted to the top of the component body, so every card in a render agrees. Accept that the value
only refreshes when something else re-renders, and say so in the plan rather than shipping a ticker.
**Warning sign:** a test that mocks the clock and passes at one instant but flakes at another.
**Do NOT add a `setInterval`** — 188's `WorkflowRunPage` tick-gate bug (`vitest-count-gate.cjs:497-504`)
is this project's recorded lesson that a live clock is its own defect class.

### P-2 ⚠ Keying the identity memo on the wrong list — flicker AND a D-05 violation in one
Keying on `visibleRows`/`query` makes `1 of 43` shrink as you type, recomputes ~230k iterations per
keystroke, and re-renders every card. **Key on `[rows]`.** (§4b)

### P-3 ⚠ The `allSettled` partial-failure path changes what lineage resolves
**Measured:** for the operator, drafts are **76 of 106** merged rows — **72 %**. If
`/workflows/drafts` 403s (it is the one gated feed — `WorkflowsPage.tsx:389-393`), the merged list
loses 72 % of its rows. Consequences: `1 of N` collapses (43 → the published subset), version-fork
lineage stops resolving (`vN of vM` → silence), and copy-fork parents may disappear.
**None of this is wrong — the resolver is honest about the list it can see — but `1 of 12` rendered
confidently while the banner above says the list is incomplete is a subtler version of the exact
CR-01 failure Phase 192's review caught** (*"You have no workflows yet"* over failed feeds).
**Recommendation:** name this as an explicit UAT row and a decision. Options: (a) accept — the
`library-source-failed-draft` banner already discloses incompleteness; (b) suppress `1 of N` when
`failedSources.length > 0`. **(a) is defensible and cheaper; the plan must choose deliberately, not
by omission.** The page already computes `failedSources` (`:489-492`) so either is one prop.

### P-4 ⚠ The sketch SORTS and the shipped page DOES NOT
`163/index.html:557` — `vis.sort(function (a, b) { return a.name.localeCompare(b.name); })`.
Measured: `grep -n "sort" frontend/src/components/workflows/library/libraryFilter.ts` → **no hits**.
`mergeLibrary` concatenates in feed order and each feed arrives server-`ORDER BY name`. **Porting the
sketch's sort would silently re-order the list** — violating the scope fence (*"change the server
`ORDER BY`"* / *"add a sort control"* are both forbidden) and re-litigating 160-C, which LOST.

### P-5 ⚠ The declaration-order TDZ crash at the new hook call site
See §1c. A dep array evaluates at render time; `useWorkflowFork({ onOpenDraft, … })` placed above

### P-6 ⚠ Reading `token` as the timestamp
See §3c. It is right there on draft rows and it is microsecond-precision. Fence it.
