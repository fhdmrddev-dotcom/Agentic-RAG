## Sampling Rate

- **After every task commit:** the touched suite + `npx tsc --noEmit -p tsconfig.app.json` (expect **33**)
- **After every plan wave:** `GSD_VITEST_MAX_WORKERS=2 node scripts/vitest-count-gate.cjs` **and**
  `cd backend && venv/Scripts/python.exe -m pytest tests/unit -q`
- **Before `/gsd:verify-work`:** full suite green **and** the manual SC#2 row driven with its artifact recorded
- **Max feedback latency:** ~40 s (quick) / ~6 min (full gate)

## ⚠ Cross-provider roster ruling — DECIDED, not forgotten

`CLAUDE.md`'s UAT recipe requires the **full native roster (7 + OpenRouter)** for any phase touching
streaming, the agent loop, provider routing, or UI state.

**Measured: `/generate` is none of those.** `generate_workflow_definition` resolves ONE model from
`settings.harness_authoring_model` (`workflow_authoring.py:259`), derives its provider from
`get_model_capability`, and calls `forced_emit` once (twice on a validation failure). **There is no
per-request `model`/`provider` override on `POST /workflows/generate`** (`GenerateRequest`,
`workflows.py:1539-1547`), so the recipe's cheap per-request scoreboard method **does not apply** —
driving eight providers would mean mutating a global setting eight times, which the recipe explicitly
avoids.

**Ruling: drive SC#2 on the configured authoring model and RECORD which model and provider served
it.** Roster coverage of `harness_authoring_model` is a separate scoreboard and must be scoped as
such — **not smuggled into this phase's rows.** This ruling is stated here so a reader can see the
axis was decided rather than skipped.

⚠ **Measured at plan time (D-23):** with `harness_authoring_model` unset, `resolve_authoring_model`
falls through to the registry default **`claude-opus-4-8`** (provider `anthropic`,
`forced_emission: True`), and `ANTHROPIC_API_KEY` is present. **SC#2 is provable.**

## Accepted, bounded risks — named here so the security audit does not "discover" them

- **Prompt injection via placeholder names.** A `.docx` can contain `{{ ignore_previous_instructions }}`
  and it lands verbatim in the grounding prompt (`grounding.py:577`). **Pre-existing** — the same path
  has been reachable since Phase 103 via `template_asset_id`. Bounded by server-side grounding
  **fidelity** enforcement *after* the emit (`_check_grounding_fidelity`, `workflow_authoring.py:203-230`:
  folder scopes ⊆ the project subtree, tools ∈ the real registry, `skill_ref` ∈ the enabled set) and by
  `extra="forbid"` rejecting invented keys. **Accepted and bounded, with the fidelity check named.**
- **Zip-bomb decompression.** ⚠ **A real gap, inherited from the shipped doors so it looks
  pre-approved.** `zf.read()` (`template_render_service.py:387`) is uncapped; a 10 MB OOXML container
  can hold a multi-GB `word/document.xml` and the two-stage size gate passes it. Recommend capping
  `sum(zi.file_size for zi in zf.infolist())` or bounding the read on the **new** route.
