**This is the finding that most changes the plans, and it was not visible to CONTEXT or to

## ⚠ CORRECTION C-2 — `useWorkflowFork.ts` IS THE WRONG ANALOG FOR THE STATE MACHINE, AND THE RIGHT ONE FOR THE MODULE

The mandate asked this loudly and the answer is: **CONTEXT names one precedent where the cut needs
two, and the missing one is the harder half.**

| Half of D-01's cut | Best analog | Measured |
|---|---|---|
| **The module shape** — an args interface, a return interface, handlers, a failure state, page concerns passed IN as callbacks, types declared locally so nothing imports the page back | **`useWorkflowFork.ts`** — `frontend/src/components/workflows/library/useWorkflowFork.ts`, **517 L** | ✅ CONTEXT correct |
| **The read state machine** — five arms, an in-flight arm, abort, and "an answer about a different subject reads as loading" | **`useTemplatePlaceholders.ts`** — `frontend/src/hooks/useTemplatePlaceholders.ts`, **154 L** | ⚠ **NOT NAMED IN CONTEXT.** RESEARCH lists it in Standard Stack as *"the SHAPE precedent, not the implementation"* but never names it as the analog for the new hook's union. |

`useWorkflowFork` contains **no fetch state machine at all**: its failure state is a two-field
object (`{name, conflict} | null`, `:205`) held until the next attempt, and it has no `loading`
member, no `AbortController`, and no staleness rule. Copying it for the read half would produce a
hook with no honest in-flight arm — which is the exact thing D-07 and D-09 are about.

`useTemplatePlaceholders` is the opposite: it IS the five-member union (`:56-70` —
`idle | loading | fields | none | unavailable`), it carries the abort predicate (`:89-94`, itself
copied from `usePanelReconcile.ts:84-92`), and it enforces the one rule that matters here —
**the answer is stored together with the subject it answered for, and `loading` is DERIVED when
they differ** (`:79-86`, `:149-153`). For a pre-draft hook the subject is the held `File` instead of
an `assetId`; the rule is identical.

**Why the existing hook cannot simply be reused:** its effect key is `[definitionId, assetId]`
(`:147`) and **neither value exists before a draft**. It is a sibling, not a parameterisation.

**Two module-location conventions are in play and the plan must pick deliberately:**
`useWorkflowFork.ts` lives under `components/workflows/library/`; `useTemplatePlaceholders.ts` and
`useDraftPersistence.ts` live under `hooks/`. RESEARCH proposes
`components/workflows/useTemplateFirstDraft.ts`. Either is defensible; **the D-14 fence entry's
`path` label and the `?raw` import specifier both hard-code the choice**, so it cannot be changed
later without editing the fence.
