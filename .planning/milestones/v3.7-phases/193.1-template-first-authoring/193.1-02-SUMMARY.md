# Phase 193.1 Plan 02: The Stateless Template Read — Summary

`POST /workflows/template/placeholders` takes uploaded bytes, returns the template's field names,
and persists nothing — the missing producer that lets a template be supplied *before* a workflow
exists, with the q5r cross-tenant class removed by construction rather than by a guard.

## What shipped

**The route** (`backend/app/api/workflows.py:1672-1795`), declared inside the Phase 193 template
block immediately BEFORE `POST /{definition_id}/template` — no extraction, no G-5 override (D-03).

- **Dependencies: exactly two.** `Depends(require_visible("workflow_authoring"))` and
  `current_user: dict = Depends(get_current_user)`. **No Supabase client. No pool.** The docblock
  records this as a *class elimination*: q5r needed an owner-prefix check and a `..` traversal check
  because its route resolves a caller-supplied Storage PATH through a client on a service-role pool.
  This route accepts no path and owns no row, so there is nothing for that class to attach to.
- **The gate ladder, in the sibling's exact order** — declared size (WR-04, before `.read()`) →
  extension → read → empty → length → `validate_upload`.
- **Plus the cap the ladder does NOT include.** `_TEMPLATE_MAX_UNCOMPRESSED_BYTES = 50 MB`, checked
  against `sum(zi.file_size for zi in zf.infolist())`. Stated in the docblock as INHERITED and
  flagged: capping it here does **not** close it on `POST /{id}/template` or on the q5r read door,
  and it caps the *declared* uncompressed total — a central directory that under-declares would
  still get past it, and closing that needs a bounded read inside the shipped parser.
- **The parse runs through `run_in_threadpool`** (CLAUDE.md / D-v2.5-01).
- **`read="unreadable"` is unreachable here**, stated in the docblock using the idiom
  `TemplatePlaceholdersResponse` already uses for `"not_requested"`. The field is kept for shape
  parity so the client derives its arms from one wire shape.
- **The response echoes nothing from the upload** — asserted, not asserted-about: the happy-path
  test checks the payload key-set is `{read, placeholders}` and that the filename appears nowhere in
  it. That is why WR-05's `safe_name` sanitisation is not carried across.

**The shared assembly** — `placeholder_names_from_parsed(parsed) -> list[str]` now lives in
`template_render_service.py` beside the parser it consumes, and `grounding.py:315-323`'s
re-implementation is gone. Scalars PLUS every loop column, EXCLUDING `collections`, deduped and
sorted. Behaviour-identical lift; the three-state `(names, read)` contract, the `not data` arm and
the `degraded` exclusion are untouched.

## Deviations from Plan

### [Rule 1 — Correction] `valid_docx_bytes` cannot produce the happy path

**Found during:** Task 1.
**Claim:** the plan's `<action>` says *"Use the upload suite's `valid_docx_bytes` fixture for every
happy path."*
**Measured:** `tests/conftest.py:1037-1040` writes `word/document_marker.xml`, **not**
`word/document.xml`. `parse_docx_template_variables` reads only `word/document.xml` and
`word/header|footer\d*.xml` (`template_render_service.py:382-385`), so `valid_docx_bytes` yields
zero parts, the parser returns `None`, and the route answers `ok` + `[]`. **It can only ever
exercise the empty arm.** The plan's own `<interfaces>` block also warned that the lighter
`test_q5r` `_docx` builder fails `_validate_ooxml_container` — which is true — so **neither existing
helper satisfies both gates at once**.
**Fix:** added `_template_docx(body)` in the new suite: `[Content_Types].xml` (for the container
gate) **plus** a real `word/document.xml` (for the parser). `valid_docx_bytes` is used for exactly
the arm it can honestly prove, with a comment saying which is which and why they are not
interchangeable.
**Commit:** `a03f3607`.

### [Rule 2 — Strengthening] The no-client fence sweeps CODE, not RAW source

**Found during:** Task 3 (the fence went RED against the shipped route).
**Issue:** the plan's Task 3 acceptance asks that the route source contain no
`get_user_supabase_client` / `get_pg_pool` / `_owned_slug_or_404` / `safe_name`. A RAW sweep over
`inspect.getsource` fires on the **docblock**, which names `get_supabase` precisely in order to
record that the route must never take one — the same shape as Phase 193's D-24(a), but pointed at
the wrong property. A raw sweep here would pressure the next author into deleting the explanation to
keep the fence green.
**Fix:** `_code_without_prose(fn)` parses the function with `ast`, drops the docstring node and
`ast.unparse`s the rest (which also discards comments). The sweep runs over that. The scope decision
is written into the helper's docblock, and `test_the_no_client_fence_can_actually_fire` is an inline
positive control proving the sweep still catches a real `get_pg_pool()` in a body — plant 1 above is
the same proof against production source.
**Commit:** `36d203c2`.
