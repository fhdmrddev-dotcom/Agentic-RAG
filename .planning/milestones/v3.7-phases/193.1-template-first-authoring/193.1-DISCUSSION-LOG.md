## G-5 refactor recommendation (mandated by ROADMAP before any feature discussion)

Presented with measurements taken at discuss time. ⚠ Both `CLAUDE.md` hot-file ledger cells were
found **stale by one commit** and the corrected figures were reported rather than the cell's:
`WorkflowBuilderPage.tsx` 33 → **34 commits**, 2055 → **2073 L**; `workflows.py` 32 → **33
commits**, 1813 L unchanged.

| Option | Description | Selected |
|--------|-------------|----------|

| Build the feature, log a G-5 override | Edit the page in place, record the waiver under `STATE.md → Guardrail overrides`. | |

**User's choice:** Extract first, then build.
**Notes:** The recommendation distinguished the two fires rather than treating them alike — the
page gains a genuinely **sixth concern** (a pre-draft template read state machine), while
`workflows.py` gains **a third door in the template block it already owns**, twenty lines from its
two siblings. A G-5 override was therefore **offered and declined**; `STATE.md` must record **no
guardrail override for Phase 193.1**, and that absence is a measurement, not an omission.

## The chicken-and-egg route

| Option | Description | Selected |
|--------|-------------|----------|
| Stateless read | New route takes the bytes, returns the field names, persists nothing. Matches the ROADMAP's recorded recommendation and sketch 165's approved filled states. | ✓ |
| Create an empty draft up front | Picking a file silently creates a workflow row so the shipped upload route works unchanged. | |
| Stash the file, bind later | Upload to a scratch Storage path immediately, attach once a definition exists. | |

**User's choice:** Stateless read.
**Notes:** Rejected options were priced in business terms at the operator's request. *Empty draft
up front* mints library rows the user never asked for — degrading exactly what Phases 192 and 192.1
spent two phases buying — and opens a second writer against 186-07's concurrency token. *Stash the
file* creates an orphan-cleanup problem nobody owns on a product already carrying RLS-sensitive
template bytes. The accepted cost: the `File` lives in browser memory until save, so a tab crash
before save loses it; and reading and binding become two separate calls.

## Read vs bound — does the run actually fill it?

This area was **not** in the sketches. It surfaced from a wire-level measurement during the
codebase scout and is the one that decides whether AUTH-03 can be ticked.

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-bind on first save | The held file is uploaded to `POST /{id}/template` the moment a `definition_id` exists. One file, one hand-off. | ✓ |
| Author re-attaches on the rail | After the draft, the user attaches the same file again with the shipped `TemplateAttachSection`. Zero new code. | |
| Bind explicitly, with a visible control | A visible "Use this template for every run" confirmation binds the held file. | |
| Read only — binding stays out of scope | 193.1 makes the draft template-aware and stops. | |

**User's choice:** Auto-bind on first save.
**Notes:** The framing that decided it: **none of the four ROADMAP success criteria mention the
fill**, so a phase that stops at the read passes all four criteria and still leaves AUTH-03
untickable — the exact trap Phase 193 fell into. Measured constraint reported: `template_asset_id`
is typed `UUID` while asset ids are Storage **paths**, a measured 422, so `template_placeholders`
is the **only** wire that works from the browser and the read cannot be folded into the bind. Two
rules were attached to the choice: the save must never roll back on an upload failure, and the
silent write needs its own honest failure line.

## The loading race (sketch 166's declared-open question)

| Option | Description | Selected |
|--------|-------------|----------|
| Disable the CTA while reading | Makes the blind draft impossible rather than recoverable. Scoped by construction to authors who attached a template. | ✓ |
| Let the draft wait for the read | The button stays live; pressing it queues the generate until the field names land. | |
| Let it through, say so afterwards | Cheapest — the draft goes out blind and the 167 reconcile catches it later. | |

**User's choice:** Disable the CTA while reading.
**Notes:** Chosen because the failure is otherwise **invisible to the author** — the screen makes a
promise and silently breaks it, discoverable only at run time when the fill comes back wrong. SC#4
(*the fast door stays fast*) holds by construction: no template means nothing to wait for, so no
guard is needed. The choice **requires** 166-B's `loading` footing line to ship with it — a
disabled button that does not say why reads as broken. *Let it through* was additionally rejected
for leaning 167-C's admitted heuristic into being load-bearing for the main path.

## Where a large reconcile lives (sketch 167's declared limit)

| Option | Description | Selected |
|--------|-------------|----------|
| Cap the rail, expand in place | First few rows per bucket with a "show all N" that expands where it stands. One home for one list. | ✓ |
| Always scroll the rail, no cap | Nothing hidden; the rail just scrolls. | |
| Escalate to a modal past a threshold | Small lists on the rail, large ones in a wide surface. | |
| Put it on the canvas | Mark the steps directly, where the rows are actually about. | |

**User's choice:** Cap the rail, expand in place.
**Notes:** Decided on consistency with two rulings the operator had already made: 165-C's *"two
presentations of one list is two homes, and two homes drift"*, and 167-B's rejection **on SIZE**
— a modal or a canvas surface is disproportionate spend on what that ruling established is a
**safety net**, not the headline feature. The canvas option carried a third cost: 188.2 spent the
card's badge and corner-mark budget deliberately, and it would fire G-5 on a **third** file in one
phase. Accepted cost stated: on a 15-field template where 12 fields are named nowhere, the author
expands to see the full picture.
