## How the read crosses the handoff

**It follows the `initialProjectFolderId` precedent exactly. No store, no context, no global, no
new mechanism.**

`WorkflowDoorSwitch.tsx` already handed the Builder four pre-draft values (`initial`,
`initialDescribe`, `autoDraft`, `initialProjectFolderId` — the last added in `187-26` for the
identical problem: state picked on the loose door that only the Builder can spend). This plan
adds a fifth and sixth **in that same element, in that same shape**:

```tsx
initialProjectFolderId={kbFolderId}
registerCanLeave={registerCanLeave}
// …
{...(templateAnswer
  ? { initialTemplateFile: templateAnswer.file, initialTemplateRead: templateAnswer }
  : {})}
```

The Builder accepts them as two additive-optional props and passes them straight to
`useTemplateFirstDraft`, whose `useTemplateRead(file, seed)` **installs** the answer for the
exact `File` it names. Nothing else was introduced.

⚠ **ONE spread, not two — the pair invariant made structural.** `completedTemplateAnswer(file,
state)` returns `null` until the reading has settled (it excludes `idle` and `loading` rather
than listing the settled arms, so a future sixth arm defaults to the safe side). So a document
can **never** reach the Builder without the answer that goes with it — which is the only shape
that could make the Builder issue its own read, and a read in flight at the instant the one-shot
auto-draft fires is precisely the blind draft D-07 removes. *"Seed, do not re-read"* is
therefore a property of the type, not a rule someone has to remember.

**Measured, not asserted** — `WorkflowDoorSwitch.test.tsx`, *"the reading CROSSES the hand-off
— ZERO further reads, and the first `/generate` carries the fields"*:

```ts
await screen.findByTestId("describe-template-fields")
expect(mockReadPlaceholders).toHaveBeenCalledTimes(1)
fireEvent.click(screen.getByTestId("describe-draft"))
await waitFor(() => expect(mockGenerateWorkflow).toHaveBeenCalledTimes(1))
expect(mockReadPlaceholders).toHaveBeenCalledTimes(1)          // ⚠ STILL ONE
expect(mockGenerateWorkflow.mock.calls[0][0]).toMatchObject({
  template_placeholders: ["project_name", "overall_rag_status"],
})
```

With nothing supplied the hand-off is byte-identical to today — asserted on the **key set**,
because `template_placeholders: undefined` would satisfy a `toBeUndefined` and still be a
changed body: `Object.keys(body).sort()` → `["describe"]`, zero reads.
