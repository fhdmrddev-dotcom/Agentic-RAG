## THE ONE PATTERN EVERY PLAN MUST COPY — the positive control

**Source:** `frontend/src/components/workflows/library/rowIdentity.test.ts:167-179`
**Apply to:** F-1 … F-8, every source fence, every absence assertion in this phase.

This is the phase's most-repeated lesson made concrete: *a fence that was never driven RED has never
been shown to see anything* (four such fences in 193.1 alone; three in 192.1). The shipped T-7 / P-4
fence — which D-17 requires to stay green — is the template:

```typescript
  it("T-7 / P-4 — the ROW LIST is never re-ordered, and every sort says what it sorts", () => {
    const sorts = code.split("\n").filter((l) => l.includes(".sort("))
    // POSITIVE CONTROL — the needle catches the shape 163/index.html:557 ships and this must not.
    expect("const shown = rows.sort((a, b) => a.name.localeCompare(b.name))").toMatch(
      /\brows\.sort\(|\bfamily\.sort\(|\blist\.sort\(/,
    )
    expect(sorts.length).toBeGreaterThan(0) // non-vacuity: there ARE sorts to judge
    for (const line of sorts) {
      expect(line).not.toMatch(/\brows\.sort\(|\bfamily\.sort\(|\blist\.sort\(/)
    }
    // …and each one is annotated as such, in the prose the stripper removed.
    expect((source.match(/NEVER THE ROW LIST/g) ?? []).length).toBeGreaterThanOrEqual(2)
  })
```

**The four moving parts a new fence must reproduce — all four, not three:**

| Part | In the excerpt | Why it is load-bearing |
|---|---|---|
| **1. The plant, INLINE** | `expect("const shown = rows.sort(…)").toMatch(/…/)` | The forbidden string is asserted to MATCH the needle. This is the RED observation, kept permanently in the file rather than performed once and described in a summary. |
| **2. Non-vacuity** | `expect(sorts.length).toBeGreaterThan(0)` | Without it the loop passes over an empty array. An absence assertion over an empty corpus is the commonest way a fence stops seeing. |
| **3. The absence** | `for (const line of sorts) expect(line).not.toMatch(/…/)` | The property itself. |
| **4. Scope stated** | fence runs over `code`, not `source` | See the comment-stripper pattern below. |

**The comment-stripper, and why it is not optional** (`rowIdentity.test.ts:89-99`):

```typescript
const code = source.replace(/\/\*[\s\S]*?\*\//g, "").replace(/^\s*\/\/.*$/gm, "")
```
> ⚠ SOURCE FENCES ARE VERIFIED OVER NON-COMMENT CODE LINES … The 187-24 trap: a module that
> DOCUMENTS why a symbol is absent reds a raw grep for it. It fired here on its **sixth** recorded
> instance …

…paired with its own non-vacuity guard (`:108-115`) so the stripper cannot pass by deleting the file:

```typescript
  it("the comment stripper leaves the CODE and removes the PROSE (non-vacuity)", () => {
    expect(code.length).toBeGreaterThan(1500)
    expect(code).toContain("export function buildIdentityIndex")
    expect(source).toContain("D-31")
    expect(code).not.toContain("D-31")
```

⚠ **F-3 is the exception and must go the OTHER way — RAW, not stripped.** F-3 forbids
`llm_human_input` / `ask_user` / the slug in the *refusal message*, and the message is a Python
string literal, not a comment. But `publish_service.py`'s docblock (`:442-444`) QUOTES both words.
So F-3 must assert over the **composed message value**, never over the module source — the only
scoping that can be both correct and non-vacuous. This is the 193 D-24(a) distinction (raw sweep

```python
        config = getattr(phase, "config", None)
```

```typescript
export function canRemovePhase(
  phases: readonly PhaseSpecJSON[],
  slug: string,
): RemovalOutcome {
  const referrers = orderPhases(phases).filter(…)
  if (referrers.length === 0) return { ok: true }

  const lead = `"${nodeTitle(referrers[0])}"`
  const others = referrers.length - 1
  const subject =
    others === 0 ? `${lead} sends` : `${lead} and ${others} other step${others > 1 ? "s" : ""} send`

}
```
