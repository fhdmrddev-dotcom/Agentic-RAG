# Phase 067.5 Plan 01 SUMMARY — Frontend reconcile fix (Row 11 RED → GREEN at vitest gate)

## Selected branch and rationale

**Branch D-3-CLEAR-WIPES-STREAMING-BUCKET** (corrected from initial D-2-EARLY-WINDOW after RED test phase invalidated the first hypothesis).

Root cause: `ChatArea.tsx:89-126` useEffect unconditionally calls `clearMessages()` on every `thread.id` change. `clearMessages()` at `useMessages.ts:572-588` (pre-fix) deleted the bucket of `activeThreadIdRef.current` without checking whether that thread was currently being streamed into. When the user switched BACK to a still-streaming thread:

1. `activeThreadIdRef.current === streamingThreadIdRef.current === thread-being-switched-to`.
2. `clearMessages()` wiped the live bucket containing the optimistic placeholder.
3. `loadMessages(threadId)` at `ChatArea.tsx:124` early-returned at `useMessages.ts:603` because `isSendingRef.current === true`.
4. Bucket stayed empty.
5. Subsequent SSE `onDelta`/`onTerminal` callbacks targeting the dropped placeholder's `assistantId` no-op via the `m.id === assistantId` map.
6. User saw an empty thread until F5 forced a fresh mount → reconcile → loadMessages-without-isSendingRef-guard → MERGE-with-fresh-DB-row repaired the render.

## The exact surface fixed

`frontend/src/hooks/useMessages.ts:572-590` — `clearMessages` callback. Single-line predicate change plus a 13-line comment block:

```
- if (tid) {
+ if (tid && tid !== streamingThreadIdRef.current) {
```

Total diff: **14 insertions, 1 deletion** (well within Branch D's ≤30 LOC budget).
