# Phase 067.4 Plan 01: R-3 Streaming Suggestions Fix Summary

**One-liner:** R-3 gate-blocker closed via four cohesive backend changes — `max_completion_tokens=2000` budget bump, `run_in_threadpool` wrap on `generate_suggestions`, unconditional `suggestions` SSE emit (always-emit-empty), and narrowed OpenAI API exception classes with WARNING/ERROR severity split. ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking issue] Suggestion-emit moved before `'done'` _emit**

- **Found during:** Task 2 — initial integration test run after applying the plan's literal Step-3 refactor.
- **Issue:** The plan's Step 3 refactor preserved the wire ordering `done → suggestions → stream_end`. But `'done'` is in `TERMINAL_TYPES` (`threads.py:88`), so the SSE replay consumer at `runs.py:170` returns immediately after yielding the first `'done'` entry. Suggestion events emitted-after-done are INVISIBLE to SSE-replay readers — the test `test_always_emit_when_empty` failed with `events = ['iteration_start', 'delta', ..., 'done']` (no `suggestions`) even after the always-emit fix, because the consumer broke before reading the suggestion entry.
- **Fix:** Moved the entire `try/except` suggestion block from line 2487 (post-fix would be after `done`) to line 2487 (BEFORE `done`). New producer-side ordering: `suggestions → done → stream_end`. The SSE replay consumer now yields the `suggestions` entry, then yields `done`, then breaks — wire delivers suggestions to the SSE-replay reader as the plan's must-have demands. SUG-04 invariant unchanged: `stream_end` still emitted by the producer (covered by static-source grep gate, not by SSE drain).
- **Files modified:** `backend/app/api/threads.py` (refactor block placement)
- **Commit:** `bd9d661`
- **Why this is Rule 3 (not Rule 4):** The fix doesn't restructure databases/services/architecture; it's a 4-line move within the same function preserving every other contract. The plan's stated must-have (`When a Fahed-Mrad search-only prompt completes, the SSE stream contains exactly one 'suggestions' event`) cannot be satisfied without this move — making it a blocking issue, not an architectural decision.

**2. [Rule 3 — Test assertion follow-up] Test SUG-04 invariant uses `done` not `stream_end`**

- **Found during:** Task 2 — first integration test pass after applying the Rule 3 reorder fix.
- **Issue:** My initial integration test asserted `'stream_end' in types_emitted`. But `stream_end` is emitted post-`done` and the SSE consumer breaks on `done` — so `stream_end` is correctly emitted by the producer but NEVER visible via SSE replay. This is the same TERMINAL_TYPES issue as deviation #1 above, just on a different event.
- **Fix:** Changed the SUG-04 assertion to `'done' in types_emitted` (the consumer's contractual exit, which IS visible). The `stream_end` emit is verified statically by the production-code grep gate `await _emit(redis, run_id, 'stream_end')` at threads.py:2539.
- **Files modified:** `backend/tests/integration/test_067_4_suggestion_emit.py`
- **Commit:** `bd9d661` (folded into the production-code commit since they were both authored together)
