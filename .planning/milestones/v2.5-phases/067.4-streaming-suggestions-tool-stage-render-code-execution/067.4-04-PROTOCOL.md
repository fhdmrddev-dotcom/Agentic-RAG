## Protocol — Model A (`moonshotai/kimi-k2.5`)

1. **Edit `backend/.env`** — append (or replace) the override line:

   ```
   LLM_CALL_TIMEOUT_OVERRIDES=moonshotai/kimi-k2.5=10
   ```

   The 10s budget is intentionally tight — well below typical agent stream
   completion time — so cancellation fires deterministically inside the
   first iteration's LLM call.

2. **Restart uvicorn.** Stop the dev backend (Ctrl+C in its terminal) and
   re-run the dev command (e.g., `uvicorn app.main:app --reload --port 8000`
   from `backend/` with the venv activated). Single worker only — never
   `--workers N` (CLAUDE.md rule + decision D-v2.5-02). The override is
   loaded at startup via `Settings`.

3. **Open the dev app** at http://localhost:5173/ and login with the test
   account `fhdmrd@gmail.com` / `123456` (Chrome MCP authenticated session).

4. **Switch the model picker** to `moonshotai/kimi-k2.5`. Confirm the picker
   value is reflected in the next outbound `/threads/.../runs` POST body.

5. **Submit a long-form prompt** that will exceed 10s of LLM time. Suggested:

   > Write a 10-page detailed technical spec for a real-time chat application
   > with all components, sections, examples, and code samples.

6. **Wait for cancellation** (~10s into the run). The UI should surface the
   run as failed/timed_out; the SSE stream should close cleanly without a
   raw `GeneratorExit` traceback bubbling up.

7. **Capture `run_id`** from the network panel — either the `/runs` POST
   response, the SSE event payload, or a subsequent `cancelRun` POST trace.

8. **Run the DB query** against the `runs` table (Supabase SQL editor or psql):

   ```sql
   SELECT run_id, status, error
   FROM public.runs
   WHERE run_id = '<captured run_id>';
   ```

9. **Acceptance:**
   - `status = 'timed_out'`
   - `error` matches regex `^timed_out: \d+s per-call deadline exceeded at iteration \d+ \(model=.+\)$`
   - **GREEN** if both match. Capture verbatim `error` string in Plan 05
     evidence row for **NR-067.2-11**.
   - **NOT** `GeneratorExit` format (e.g., `error LIKE '%GeneratorExit%'`) —
     that would indicate a Track A regression and must escalate to Phase 067.5.

## Protocol — Model B (`minimax/minimax-m2.7`)

1. **Replace** the `LLM_CALL_TIMEOUT_OVERRIDES` line in `backend/.env`:

   ```
   LLM_CALL_TIMEOUT_OVERRIDES=minimax/minimax-m2.7=10
   ```

   (Replace, do not append a second line — only the last assignment of
   the same key wins in dotenv-style files. Cleaner to swap.)

2. **Restart uvicorn** to pick up the new override.

3. Repeat **steps 3-9** from the Model A protocol with `minimax/minimax-m2.7`
   selected in the model picker.

4. **Acceptance:** same regex match, but the `error` string must contain
   `model=minimax/minimax-m2.7` (distinct from Model A's run, which contained
   `model=moonshotai/kimi-k2.5`). This proves both runs originated from the
   OpenRouter provider class, not stale cached state from one model.

## Cleanup

After both models are tested:

1. **REMOVE** the `LLM_CALL_TIMEOUT_OVERRIDES` line from `backend/.env`
   (or set it to empty: `LLM_CALL_TIMEOUT_OVERRIDES=`). Leaving the override
   in place would leak the 10s budget into ordinary dev sessions.

2. **Restart uvicorn** one final time so the dev session returns to normal
   per-model timeout policy.

3. **Spot-check** that an ordinary Anthropic / OpenAI prompt completes
   normally (no early `timed_out`), to confirm the override has been removed.
