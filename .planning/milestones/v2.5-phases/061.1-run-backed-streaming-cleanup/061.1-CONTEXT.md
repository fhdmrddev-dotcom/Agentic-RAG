<decisions>
## Implementation Decisions

### S2 — Test race fix mechanism

- **D-061.1-01 — Await the producer task via `RUN_TASKS` lookup with `asyncio.wait_for(task, timeout=10.0)` before asserting on mocks.** Selected over fixed `asyncio.sleep(5.0)` (status quo in `test_059_disconnect.py::test_agent_task_SURVIVES_on_disconnect`) and over poll-for-terminal-sentinel. Rationale: deterministic (zero flakes, zero CI-load sensitivity), no shared state with prod beyond the already-public `RUN_TASKS` registry (D-061-11), and removes ~25s of fixed sleeps from the integration suite. Cancelled-on-shutdown is absorbed via `try/except asyncio.CancelledError: pass`.
- **D-061.1-02 — Implement as a shared helper in `backend/tests/integration/_run_helpers.py`** (e.g., `await_producer_finalized(mock_supabase, *, timeout=10.0)`). All 5 failing tests adopt it. The existing `test_059_disconnect.py::test_agent_task_SURVIVES_on_disconnect` also migrates — its `await asyncio.sleep(5.0)` at line 300 is replaced with the new helper (this is what WR-04 asks for).
- **D-061.1-03 — Helper signature must tolerate `RUN_TASKS.get(run_id) is None`** (the producer may have already finalized and self-evicted before the test calls the helper). When the registry lookup is empty, the helper RETURNS IMMEDIATELY — eviction implies finalization. Rationale: D-061-04 locks the shielded finalizer's 5-step ordering as `sentinel → UPDATE → EXPIRE → ZREM → RUN_TASKS.pop`. Self-eviction is the LAST step, so by the time `RUN_TASKS.get` is empty, all observable side-effects (terminal sentinel in stream, runs row UPDATE, EXPIRE, ZREM) have already landed. An xrange-based safety-net poll was considered (original intent of this decision before the planner reasoned through D-061-04 ordering) but rejected: it would add `redis_client` kwarg plumbing, a 6s poll loop, and ~50 lines of test-only code that defends against an invariant violation which is itself already a bug. If D-061-04 ordering ever ships broken, the right fix is to restore the ordering, not to mask it in a test helper. Plan 02 Task 1's helper consequently does not implement the xrange fallback. **Amended 2026-05-03 during planning iteration 1.**

### S1 — `ERR_INCOMPLETE_CHUNKED_ENCODING` disposition

- **D-061.1-04 — Diagnose AND fix in-place.** Selected over diagnose-and-defer (which the SPEC explicitly allowed) because producer architecture is sound and the consumer drop is the last brittleness before Phase 063's frontend cutover. A clean consumer raises confidence in 062's `GET /runs/{id}/stream?since=N` work landing on a stable foundation. `061.1-DIAGNOSIS.md` is mandatory regardless of whether a fix lands — it documents the reproduction, the bisection evidence, and the prime-suspect cause for future audits.
- **D-061.1-05 — Hypothesis investigation order: H4 (Vite dev proxy) → H3 (sub_agent_delta volume) → H1 (consumer generator raise) → H2 (sse-starlette ping interval).** H4 + H3 first because the symptom is browser-side `TypeError: network error` triggered only on sub-agent flows that emit ~1000 sub_agent_delta events. Bisection plan:
  - **H4 test:** Bypass Vite proxy — `curl -N http://localhost:8000/threads/{id}/messages` directly against backend; if no drop, Vite proxy is the cause (fix: disable proxy buffering / increase proxy timeout in `vite.config.ts`).
  - **H3 test:** Throttle or batch sub_agent_delta emissions; if drop disappears, the high-volume per-event XADD + SSE write is the cause (fix: coalesce sub_agent_delta into time-windowed batches, OR add backpressure between XREAD and the SSE writer).
  - **H1 test:** Wrap `event_consumer()` xread loop body in `try/except BaseException: log + re-raise` and inspect logs.
  - **H2 test:** Set `EventSourceResponse(ping=None)` or `ping=2` and re-run UAT.
- **D-061.1-06 — Reproduction script lives in `061.1-DIAGNOSIS.md`.** Steps mirror the original UAT session: navigate to a thread with the dev PDF library, ask any RAG question that triggers a sub-agent (the SPEC-noted `*Fahed*` topics work), watch DevTools network tab for `ERR_INCOMPLETE_CHUNKED_ENCODING`. Run ID `f4b2b8cc-c643-4107-9f4a-70e715641b63` from the original UAT is the reference reproduction.

### S3 — Production-code fixes

- **D-061.1-07 — WR-01 consumer cursor fix:** Replace `last_id = "$"` reset at `backend/app/api/threads.py:2079` with "keep `last_id` at the value of the last replayed entry id (or `'0'` if replay was empty)". This eliminates the race window between replay-drain and tail-subscribe per the standard Redis pattern. **Add a regression test** (`tests/integration/test_061_consumer_cursor_race.py` or extension of existing test_061_consumer.py) that reproduces the race: producer XADDs `done` between an empty replay xread and the first tail xread, asserts consumer still receives `done` instead of timing out on the deadline.
- **D-061.1-08 — WR-07 redis-py pin tightening:** Change `backend/requirements.txt` from `redis>=5.2,<8` to `redis>=5.2,<6`. Rationale: redis-py historically makes breaking changes to XREAD response shape across major versions; the 6.x bump should be intentional and verified, not an automatic dependency-updater win.
- **D-061.1-09 — IN-03 double-nonlocal refactor:** Change `_persist_assistant_message` to **return** the inserted `message_id` instead of mutating `_persisted_msg_id` via `nonlocal`. The `_shielded_finalize` closure holds the returned id in its own local. Eliminates the two-level `nonlocal` declaration that reaches into `send_message`'s scope. **Behavior must not change** — same idempotent-second-call shape (cached return on the second invocation), same shielded execution. Land as a separate atomic commit with explicit "no-behavior-change" rationale in the commit message.
- **D-061.1-10 — IN-04 event_consumer extraction:** Extract the `event_consumer` async generator from inside `send_message` to a module-level function `event_consumer(redis, run_id, settings, deadline_seconds)` in `backend/app/api/threads.py` (or a sibling `_event_consumer.py`). Enables direct unit testing of cursor advancement, replay→tail transition, and TERMINAL_TYPES break logic — IN-04 explicitly calls out that `test_061_consumer.py::test_xread_advances_last_id` currently exercises an in-test replica, not the real consumer. **Behavior must not change** — same XREAD calls, same yield shape, same deadline arithmetic. Land as a separate atomic commit. After extraction, expand `test_061_consumer.py` to exercise the real function directly (kill the in-test replica).
