- **State shape flipped**: `messages: Message[]` -> `messagesByThread: Map<string, Message[]>`. Visible `messages` derived via `useMemo` against `viewedThreadId` (state slot mirroring `activeThreadIdRef`).

## Decisions Made

- **Ref-mirror for `messagesByThread`** (NEW pattern; not in the plan's literal task spec but called for by D-067.3-R1-08 audit): added `messagesByThreadRef` updated via a 1-line `useEffect`. Reconcile reads `messagesByThreadRef.current.get(threadId)` for the runId-match dedup so its `useCallback` identity stays stable. Without this, putting `messagesByThread` directly into reconcile's deps would have invalidated the WR-08 invariant in ChatArea.tsx (the listener-effect treats reconcile as stable; identity churn would tear down + re-attach visibilitychange/focus/pageshow listeners on every bucket write). Documented in code with cross-references to WR-08.
- **`messagesRef` source switched** from `messages` (the derived viewed-thread bucket) to `streamingThreadIdRef.current`'s bucket with `activeThreadIdRef` fallback. Under cross-thread switch the streaming bucket and viewing bucket diverge; `stopStreaming` derives `run_id` from this ref and would otherwise lose the streaming run the moment the user navigates away. The fallback covers the Stop-after-completion edge case where `streamingThreadIdRef` is null.
- **reconcile's runId-match dedup reads `messagesByThreadRef.current.get(threadId)`**, NOT `messagesRef.current`. The latter tracks the streaming bucket (potentially a different thread under cross-thread switch); the former is correctly scoped to the `threadId` reconcile was invoked for.
- **Existing reconcile in-flight ref behavior preserved as-is** (D-063.1-11 / Gap-005). Cursor/dedup audit (D-067.3-R1-08) confirmed no per-thread cursor needed — both `lastSeenOffsetRef` and `subscriptionsRef` are run-keyed and compose correctly with the bucket key.
