<objective>
Fix Gap-005: concurrent reconcile calls (visibilitychange + focus firing in the same tick) wipe the temp `${run_id}` placeholder. Two complementary fixes:
1. **In-flight guard** at the top of reconcile() — only one reconcile body runs at a time; subsequent triggers return immediately. The active reconcile picks up the latest state when it finishes.
2. **loadMessages MERGE** — when `setMessages(data)` is called from the in-flight reconcile, preserve any live temp- placeholders whose runId is not yet a DB row (belt-and-braces for any code path that calls loadMessages while a reconcile-inserted placeholder is in flight: terminal-time refetch, buffer_expired fallback, future code paths).

Purpose: When a passive tab gets BOTH visibilitychange and focus events on tab activation, ChatArea fires reconcile() twice. Without the guard, two for-loops race: A inserts temp placeholder, B's loadMessages calls setMessages(data) which OVERWRITES it, B's for-loop short-circuits because A's subscriptionsRef.set already ran. Net result: SSE open but no bubble rendered. The guard + MERGE fix this without skipping legit single triggers (no debounce — fragile against pageshow latency).

Output: Modified useMessages.ts with reconcileInFlightRef + loadMessages MERGE block.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-063.1-11 | T (Tampering) | reconcileInFlightRef bool race | accept | JavaScript is single-threaded; setting/checking a boolean ref is atomic with respect to React's microtask queue. Two reconcile calls in the same tick: the first synchronously flips the ref to true; the second reads true and returns. No interleaving possible. |
| T-063.1-12 | I (Information disclosure) | merge logic accidentally preserving cross-thread placeholders | mitigate | The merge runs INSIDE loadMessages's post-await guard `if (activeThreadIdRef.current !== threadId) return` (D-060-02). If the user navigated away during the await, the merge is skipped entirely. The merge filter `m.runId && !dbRunIds.has(m.runId)` operates only on the prev state which is already scoped to the current viewing thread. No cross-thread leak possible. |
| T-063.1-13 | D (Denial of service) | reconcileInFlightRef stuck true after exception | mitigate | finally block ALWAYS resets to false, even on async exceptions inside the try body. Test 4 (above) verifies this — a synthetic throw inside the body still allows the next reconcile call to run. |
| T-063.1-14 | S (Spoofing) | placeholder forged with arbitrary runId | accept | placeholder.runId is set by reconcile() from `run.run_id` returned by getActiveRuns — that endpoint is RLS-gated by user_id (Phase 062 D-062-12). User cannot forge a runId for another user's run. |
</threat_model>
