<objective>
Extend the `GET /threads/{tid}/messages` endpoint to surface `run_id` and `run_status` per assistant row by JOINing with `public.runs` via the `message_id` FK. This unlocks the dedup-via-runId logic in plan 063.1-02 and the Resume button data flow (Gap-002).

Purpose: The frontend Resume button (D-063-04) only renders when `message.runStatus === "failed"`. After F5/reload, `loadMessages` returns raw DB rows that lack `runStatus`. This plan makes the JOIN happen server-side in a single round-trip — no separate `getFailedRuns` endpoint, no UI flicker between "loaded without status" and "with status."

Output: Two-query Python merge implementation + extended Pydantic model + 3 integration tests (happy path, pre-run-backed null, cross-user RLS guard).
</objective>

    ```python
    @router.get("/{thread_id}/messages", response_model=list[MessageResponse])
    async def get_messages(
        thread_id: str,
        current_user: dict = Depends(get_current_user),
        supabase: Client = Depends(get_supabase),
    ):
        # Ownership check — UNCHANGED from current implementation.
        thread = await aexec(
            supabase.table("threads")
            .select("id")
            .eq("id", thread_id)
            .eq("user_id", current_user["id"])
            .single()
        )
        if not thread.data:
            raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Thread not found")

        # 1. Fetch messages — UNCHANGED from current implementation.
        msgs_resp = await aexec(
            supabase.table("messages")
            .select("*")
            .eq("thread_id", thread_id)
            .eq("user_id", current_user["id"])
            .order("created_at")
        )
        messages = msgs_resp.data or []

        # 2. NEW (D-063.1-13): Fetch runs for this thread keyed by message_id.
        # Defense-in-depth: .eq("user_id", ...) alongside RLS policy runs_select_own
        # (migration 035 lines 47-49). idx_runs_history index serves this exactly.
        runs_resp = await aexec(
            supabase.table("runs")
            .select("run_id, message_id, status")
            .eq("thread_id", thread_id)
            .eq("user_id", current_user["id"])
        )
        runs_by_message = {
            r["message_id"]: r
            for r in (runs_resp.data or [])
            if r.get("message_id") is not None
        }

        # 3. Zip — assistant rows get run_id/run_status from FK match; user rows
        # and pre-run-backed assistant rows return null.
        for m in messages:
            run = runs_by_message.get(m["id"])
            m["run_id"] = run["run_id"] if run else None
            m["run_status"] = run["status"] if run else None

        return messages
    ```

| T-063.1-02 | T (Tampering) | message_id FK in runs table | accept | FK is set by the agent_runner producer task during run lifecycle; user cannot directly write to runs table (RLS allows SELECT only per migration 035 lines 47-49 — no INSERT/UPDATE policy for end users); two-query merge reads message_id, doesn't accept user input on this field |
| T-063.1-03 | D (Denial of service) | extra runs SELECT per messages request | accept | runs SELECT hits `idx_runs_history` index (user_id, thread_id, started_at DESC); result-set bounded by thread length; single integer-sized round-trip; no measurable impact at single-user scale; same access pattern already used by `list_active_runs` |
