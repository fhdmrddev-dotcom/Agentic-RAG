<objective>
Extend the existing `DELETE /documents/{id}` endpoint to accept a `scope` query parameter (`version` | `all`), implementing two deletion paths:

- `scope=version` (default): delete only the targeted document row and its storage file; if the row was `is_latest=True`, promote the next-highest `version_number` sibling
- `scope=all`: find all siblings by `(user_id, filename, folder_id)`, delete all their storage files, then delete all rows (ON DELETE CASCADE handles chunks/tables/images automatically)

Purpose: Satisfies DOC-01, DOC-02, DOC-03 — users can delete a single version or the entire document history with full cleanup.

Output: Modified `backend/app/api/documents.py` with extended `delete_document` function.

    target = doc_resp.data
    folder_id = target.get("folder_id")

    if scope == "all":
        # D-07: find all sibling rows by (user_id, filename, folder_id)
        siblings_q = (
            supabase.table("documents")
            .select("id, file_path")
            .eq("user_id", current_user["id"])
            .eq("filename", target["filename"])
        )
        if folder_id is None:
            siblings_q = siblings_q.is_("folder_id", "null")
        else:
            siblings_q = siblings_q.eq("folder_id", folder_id)
        siblings = siblings_q.execute().data or []

        # D-10: delete all storage files; failures silently swallowed
        for sibling in siblings:
            if sibling.get("file_path"):
                try:
                    supabase.storage.from_("documents").remove([sibling["file_path"]])
                except Exception:
                    pass

        # Delete all sibling rows; ON DELETE CASCADE handles chunks/tables/images (D-09)
        sibling_ids = [s["id"] for s in siblings]
        if sibling_ids:
            supabase.table("documents").delete().in_("id", sibling_ids).execute()

    else:
        # scope == "version" (default) — D-06: delete only the targeted row + storage file
        # D-10: storage failure silently swallowed
        try:
            supabase.storage.from_("documents").remove([target["file_path"]])
        except Exception:
            pass

        supabase.table("documents").delete().eq("id", document_id).eq("user_id", current_user["id"]).execute()

        # D-06: if deleted row was is_latest, promote next-highest sibling
        if target.get("is_latest"):
            siblings_q = (
                supabase.table("documents")
                .select("id, version_number")
                .eq("user_id", current_user["id"])
                .eq("filename", target["filename"])
                .neq("id", document_id)
            )
            if folder_id is None:
                siblings_q = siblings_q.is_("folder_id", "null")
            else:
                siblings_q = siblings_q.eq("folder_id", folder_id)
            siblings = siblings_q.execute().data or []

            if siblings:
                # Sort descending by version_number; promote the highest
                siblings.sort(key=lambda s: s.get("version_number") or 0, reverse=True)
                next_latest_id = siblings[0]["id"]
                supabase.table("documents").update({"is_latest": True}).eq("id", next_latest_id).execute()

    # D-11: audit log for both paths — include scope in metadata
    background_tasks.add_task(
        write_audit_entry,
        user_id=current_user["id"],
        action_type="document.delete",
        metadata={
            "document_id": document_id,
            "filename": target.get("filename", ""),
            "scope": scope,
        },
        supabase=supabase,
    )

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → DELETE /documents/{id} | Unauthenticated or authenticated user sends deletion request with optional scope param |
| scope param → deletion logic | User-supplied query string controls which records are deleted |
| Python → Supabase storage | Storage file paths taken from DB rows, used in remove() call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-01 | Spoofing | DELETE /documents/{id} | mitigate | `get_current_user` dependency enforces JWT auth; all queries filter by `eq("user_id", current_user["id"])` — executor must NOT remove user_id filter from sibling queries |
| T-46-02 | Tampering | scope query param | mitigate | FastAPI `Query(pattern="^(version\|all)$")` rejects any value other than "version" or "all" — 422 Unprocessable Entity returned for invalid scope |
| T-46-03 | Elevation of Privilege | scope=all sibling query | mitigate | Sibling query includes `.eq("user_id", current_user["id"])` — user cannot delete another user's document versions even if they know the document_id |
| T-46-04 | Tampering | storage file_path injection | accept | file_path values originate from DB rows already owned by current_user (RLS enforced at DB level); no user-supplied path is used in storage.remove() call |
| T-46-05 | Denial of Service | bulk delete scope=all | accept | Scoped to user's own documents; no rate limiting needed for v2.4 single-user app |
| T-46-06 | Information Disclosure | 404 vs 403 distinction | accept | Both cases return 404 ("Document not found") — does not reveal whether document exists for another user |
