<objective>
Refactor the Library Health backend to support pagination, aggregate metrics, a library health score, and query-level low-confidence analysis. Replace in-memory TOP-N aggregation with SQL-level pagination.

Purpose: Current backend is limited to fixed top-10 lists with no pagination, making it unusable for large libraries. It incorrectly flags "low confidence documents" when the real insight is "which queries trigger low confidence." This plan adds paginated endpoints, a 0-100 health score, and query-level analysis.

## Current state

Existing `/knowledge-health/summary` returns four fixed top-10 arrays:
- `most_retrieved`: top 10 docs by retrieval count (30 days)
- `never_retrieved`: top 10 docs never retrieved (scans 500 docs + 5000 audit rows in Python)
- `low_confidence`: top 10 docs with avg similarity < 0.40
- `stale`: top 10 docs older than stale_days

Problems:
1. `never_retrieved` loads 500 docs + 5000 audit rows into memory — O(n) set difference
2. `low_confidence` averages similarity per document — wrong metric (confidence is query-dependent)
3. No pagination — frontend shows "Showing top 10" with no way to see more
4. No aggregate overview — no health score, no trend data, no coverage %

## New endpoints

### GET /knowledge-health/overview
Returns aggregate KPIs + health score (0-100):
```json
{
  "health_score": 78,
  "total_documents": 1523,
  "retrieved_this_month": 89,
  "never_retrieved_count": 45,
  "stale_count": 12,
  "low_confidence_queries_count": 23,
  "coverage_percent": 5.8,
  "avg_confidence": 0.62
}
```

Health score formula (documented in code):
```
coverage = (retrieved_this_month / total) * 100
freshness = ((total - stale) / total) * 100
confidence = (avg_similarity / 0.70) * 100
feedback = positive_rate * 100 (default 50 if no feedback)
health_score = coverage*0.40 + freshness*0.30 + min(confidence,100)*0.20 + feedback*0.10
```

### GET /knowledge-health/most-retrieved?offset=0&limit=20
Paginated. Returns `{items, total, offset, limit}`.

### GET /knowledge-health/never-retrieved?offset=0&limit=20
Paginated. Uses SQL `not.in_` instead of Python set difference.

### GET /knowledge-health/stale?offset=0&limit=20&stale_days=90
Paginated.

### GET /knowledge-health/low-confidence/documents?offset=0&limit=20
Paginated document-level low confidence (backward compat behavior).

### GET /knowledge-health/low-confidence/queries?offset=0&limit=20
**NEW**. Returns query-level analysis:
```json
{
  "items": [
    {
      "query_text": "What is the company vacation policy?",
      "avg_similarity": 0.32,
      "occurrence_count": 5,
      "document_count": 3
    }
  ],
  "total": 23,
  "offset": 0,
  "limit": 20
}
```

Groups by user query text from messages table where the assistant response had confidence_avg_similarity < 0.40.

### GET /knowledge-health/retrieval-trend?days=30
Returns daily counts for line chart:
```json
[
  {"date": "2026-04-01", "retrieval_count": 5, "unique_documents": 4},
  ...
]
```

## Decisions
- **D-01:** Keep old `/summary` for backward compat, mark deprecated
- **D-02:** Health score calculated server-side with simple weighted formula
- **D-03:** `never_retrieved` uses SQL `not.in_` filter instead of Python set difference
- **D-04:** `low-confidence/queries` groups by assistant message content (or preceding user message if feasible) where confidence < 0.40
- **D-05:** All paginated endpoints: `offset` (default 0), `limit` (default 20, max 100)
