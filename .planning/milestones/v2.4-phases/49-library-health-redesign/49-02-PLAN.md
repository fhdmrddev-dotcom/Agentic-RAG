<objective>
Redesign the Library Health frontend into a professional analytics dashboard with multiple chart types, a health score gauge, tabbed low-confidence analysis, paginated tables, and positive actionable empty states.

Purpose: The current dashboard shows static top-10 lists with a single bar chart. For large libraries, this is insufficient. Users need aggregate metrics, trends over time, and query-level insights to understand their knowledge base health. The redesign follows industry analytics patterns (Datadog, Grafana, PostHog) while keeping the implementation pragmatic.
Output: Updated `KnowledgeHealthPage.tsx` and supporting components.
</objective>

## New design

### Layout (top to bottom)

**Row 1: Health Score + KPI Cards**
- Large gauge chart showing health score (0-100) with color coding:
  - 80-100: green "Healthy"
  - 60-79: yellow "Needs Attention"
  - 0-59: red "At Risk"
- 4 smaller stat cards: Total Docs, Coverage %, Avg Confidence, Active This Month

**Row 2: Charts**
- Left (2/3): Line chart — "Retrieval Trend" (daily retrieval count over 30 days)
- Right (1/3): Area chart or mini stat cards — "Coverage Over Time" (unique docs retrieved / total)

**Row 3: Tabbed Metric Panels**
- Tabs: Most Retrieved | Never Retrieved | Stale | Low Confidence
- Active tab shows paginated table (not expandable list)
- Low Confidence tab has SUB-tabs: "By Document" | "By Query"
  - By Document: old behavior (docs with avg similarity < 0.40)
  - By Query: new behavior (queries that triggered low confidence + suggested actions)

**Row 4: Feedback Section**
- Gauge chart: Positive feedback rate (0-100%)
- Below: "All clear — no negative feedback in the last 30 days" (when empty)
- Downvoted documents table (paginated)

### Chart types to use (recharts — already installed)

- **Health Score**: Custom SVG gauge (or use recharts RadialBar if available, otherwise custom CSS donut)
- **Retrieval Trend**: `LineChart` with `Area` fill
- **Coverage**: `AreaChart`
- **Feedback Rate**: Same gauge component reused

### Pagination component

Create a simple `PaginationControls` component:
- Previous / Next buttons
- Shows "Showing X-Y of Z"
- Disabled states at boundaries

### Empty state messaging

Current (passive/negative):
- "No downvoted documents"
- "No documents were retrieved"

New (positive/actionable):
- "All clear — no negative feedback in the last 30 days"
- "Great coverage — every document has been retrieved at least once"
- "High quality matches — no documents show consistently low similarity"
- "Library is fresh — all documents are newer than 90 days"

## Decisions
- **D-01:** Use recharts (already installed) for all charts — no new dependencies
- **D-02:** Health gauge is a custom SVG component (simple arc + needle) rather than importing a heavy chart library
- **D-03:** Pagination is client-driven via URL params — backend returns {items, total, offset, limit}
- **D-04:** Low confidence "By Query" tab shows the user query text + avg similarity + occurrence count + a helpful explanation: "These queries returned low-confidence results. Consider adding documents about [topic] or rephrasing similar questions."
- **D-05:** Keep `HealthDocumentRow` actions (Delete, Re-ingest, Move) but add them to paginated table rows
- **D-06:** Use shadcn Tabs component for main metric tabs and sub-tabs
