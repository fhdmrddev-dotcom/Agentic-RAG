## 3 · ✅ GAP 1 — RESOLVED 2026-09-04 — Phase 219 is unstarted, and it is not a simple "finish it"

`#### Phase 219: A Connected Source Feeds the Library` sits in this milestone's roadmap with
requirements **LIB-08 / LIB-09 / LIB-10** and reads **`0/? Not started`**.

⚠ **Its success criteria are the milestone's own re-open trigger.** SC#1 is *"watched on a
schedule"* — an automatic, background sync. The scope section defers `SEED-209/210/211/212` with
this binding sentence:

> **RE-OPEN TRIGGER: the first AUTOMATIC or BACKGROUND sync from a connected source.**
> Shipping auto-ingest without them is **not a gap, it is a security defect.**

`SEED-210` measures that synced documents flatten source ACLs and that source deletions never
propagate. So Phase 219 cannot be "just built to close the milestone" — building it *is* the
trigger that requires the deferred security work first.

**This is an operator decision, not a task.** Three honest options:

1. ⭐ **TAKEN (operator, 2026-09-04): defer 219 to the Connected Knowledge milestone** the scope
   section already names, carrying LIB-08/09/10 and `SEED-209..212` together. It keeps the security
   seeds attached to the feature that needs them, which is the whole point of the trigger.
   **Applied:** the ROADMAP row and the phase section both record the deferral with the reasoning
   and the phase text kept verbatim; all four seeds now carry a matching *"SEQUENCED INTO THE
   CONNECTED KNOWLEDGE MILESTONE"* note and stay `planted` deliberately — they are prerequisites of
   a named future phase, not answered ideas. ⚠ The trigger did NOT fire: it was kept from firing by
   moving the feature.
2. **Hold v3.9 open** until 219 and its four seeds ship. Honest, but it re-opens a milestone whose
   other 15 phases are done and drags a security axis into a connections milestone.
3. **Close v3.9 with 219 explicitly unstarted**, recorded in the archive as carried forward.

⚠ Whichever is chosen, `LIB-08/09/10` are **still absent from `REQUIREMENTS.md`** (`STATE.md:400`
records the same gap for LIB-05..07). A requirement that exists only in a roadmap heading is
invisible to every coverage check.
