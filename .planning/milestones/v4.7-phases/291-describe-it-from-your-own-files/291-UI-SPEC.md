How the constants are shared:
- `ROW_CLASSES`, `NOTE_CLASSES`, `FOOTING_CLASSES` and `FILENAME_CLASSES` are exported from `DescribeTemplateRow.tsx`, or moved to one tiny shared const module; the planner chooses which.
- `FOLD_LINE_CLASS`, `FOLD_ACTION_CLASS` and `FOLD_BODY_CLASS` are exported from `DraftArrivalCard.tsx` for the inputs-fold leaf.

**The fence that enforces this (named, so the planner writes it):** a raw-source spacing fence (`?raw`) in `DescribeReferencesSection.test.tsx` and in the inputs-fold leaf's test (`DraftInputsFold.test.tsx`). It asserts two things about each new file's source:
1. it **imports** the shipped constants by name: `ROW_CLASSES`, `NOTE_CLASSES` and `FOOTING_CLASSES` for the references section; `FOLD_LINE_CLASS`, `FOLD_ACTION_CLASS` and `FOLD_BODY_CLASS` for the leaf;
2. it contains **zero** literal `mt-1.5`, `px-2.5`, `py-[3px]`, `pl-3`, `px-3`, `py-5` or `text-[10.5px]`.

The same fence runs over the diff hunk added to `DescribeTemplateRow.tsx`, where the new arms must use the existing constants.

Sketch values **not** carried over:
- the 18px list indent becomes `pl-4` (16px);
- the 2px grid row gap becomes `gap-y-1` (4px);
- the 20px column gap becomes `gap-x-4` (16px);
- the removed line's 2px vertical padding becomes `py-1` (4px);

**Touch targets:** every new interactive control has a hit area of at least 24×24px (WCAG 2.5.8): `min-h-6` on each placement label row, each switch segment and each Remove file button. A wrapping `<label>` counts as the checkbox's hit area.

## Typography

**The final set: four sizes; new markup uses two weights (400 and 500) only, and the shipped 600 step-count heading is untouched.** No other size may appear in new markup.

| Size | Status | Weight | Line height | Role, and every place it is used |
|------|--------|--------|-------------|----------------------------------|
| 10.5px | **Inherited class only.** It arrives through the imported `NOTE_CLASSES`; new markup never types `text-[10.5px]`. | 400 | 1.375 (`leading-snug`, inside the const) | **Door explanation**, always `text-muted-foreground`: reading, provenance and back lines; the refs note and types note; the powers and keep lines; each reference's reading line (`NOTE_CLASSES` + `pl-4`); and the existing shipped notes. |
| 11px | New markup, plus the inherited `FOOTING_CLASSES` and prompt class | 400; 500 for section prompts, picker labels and the selected switch segment | 1.375 on the door; 1.5 on the card | **Door content and card metadata.** Door: section prompt, picker label, field names and type words in the field grid, placement lines and their type words, the `suggested` tag, reference filenames, the Remove file button, footing lines. Card: the inputs-fold `h3` (`font-mono text-[11px] uppercase tracking-widest text-muted-foreground`), the type word on each input row, the switch segments, the added-by line. |
| 12.5px | New markup, plus the inherited `FOLD_LINE_CLASS` | 400 | 1.5 (`leading-[1.5]`) | **Card content**: the inputs fold summary (shipped `FOLD_LINE_CLASS`), each input row's label, `INPUT_SOURCE_EXPLANATION`. |
| 13.5px | New markup, matching the shipped heading size | 400 for the reason; 500 for the lead clause | 1.5 (`leading-[1.5]`) | **Card notice**: the `⊘ Removed:` line on the card face. |

**There is no 12px anywhere in this phase.** The inputs-fold `h3` is 11px mono uppercase. It is 1px smaller than the shipped decisions-body `h3` (12px). That difference is not visible at uppercase mono tracking, and those two bodies are never open at the same scroll position as a pair to compare.

**Weights:** 400 (regular) and 500 (`font-medium`) only. The card's existing 600 title and step-count heading are shipped and untouched; no new element uses 600.

**How the hierarchy stays legible when sizes sit 0.5 to 1.5px apart.** Size is never the only signal. Each step is also a change of colour, weight or case:
- **Door, 10.5 to 11px:** 10.5px is always muted, regular, sentence case: *explanation*. 11px is foreground, either the 500-weight prompt/label (*question*) or the 400 field, file and footing text (*content*). The fact lines (scan, cut short, couldn't place, refused, no fields) are the only 10.5px text drawn in `text-foreground`, so they stand out by colour, not size or hue (D-17).
- **Card, 11 to 12.5 to 13.5px:**
  - 11px is metadata: muted, with the heading in uppercase mono.
  - 12.5px is content: a foreground label on a bordered row.
  - 13.5px is the notice: a 500-weight foreground lead behind a left rule.
  - The step-count heading above it stays dominant through weight 600, not size.
- The door's two sizes and the card's three never meet on one surface, so no reader compares 10.5 against 12.5.

### Field grid (PDF forms, D-04 / D-11)

- Markup: `<div role="list" data-testid="describe-form-fields" class="mt-1.5 grid grid-cols-[minmax(0,max-content)_max-content] justify-start gap-x-4 gap-y-1 pl-4 text-[11px] leading-snug">`.
- Each field is two cells: the name in `text-foreground [overflow-wrap:anywhere]` with `role="listitem"`, and the type word in `text-muted-foreground whitespace-nowrap`.
- **The server's order, never re-sorted.** The name is the field's label as the server read it: `/TU`, else the nearest text label, else the AI-proposed label, which is tagged. The raw qualified field name (for example `topmostSubform[0].Page1[0].f1_01[0]`) is **never** shown when a label exists.
- **Cap:** the first 8 fields show. With more than 8, a text button `showAllLabel(n)` (shipped formatter, `Show all 27`) sits under the grid and expands in place (`aria-expanded`). The footing always states the **full** count, because it counts the list the author can expand. This keeps the shipped rule that the count matches the list.
- **Type words** come from one formatter, `fieldTypeWord(input)`, in `templateFirstVocabulary.ts`. The arrival fold imports it, so both surfaces say the same word.
  - `text` → `text`
  - `number` → `number`
  - `date` → `date`
  - `file` → `file`
  - `enum` whose options are exactly yes and no, compared case-insensitively → `yes / no`
  - any other `enum` → `choice of {n}`, where `n` is the option count
- The `suggested` tag is `ml-1 rounded-sm border border-border px-1 text-[11px] text-muted-foreground`, with visible text `suggested`. It is provenance, not a verdict. It never appears on AcroForm fields, which are read exactly.

### Placement list (Word blanks, D-26 / D-27 / D-28)

This **is** the D-04 list for Word forms. It is not a second list.
- `<ul data-testid="describe-form-places" class="mt-1.5 flex flex-col gap-1 pl-4 text-[11px] leading-snug">`.
- Each placed field is an `<li>` holding a `<label class="flex min-h-6 items-baseline gap-2">`:
  - a native `<input type="checkbox">`, checked by default;
  - the document's own line: `{before}` and `{after}` in `text-muted-foreground`, with the field label inside the accent mark (`bg-primary/15`, a dashed `border-b border-primary/60`, `rounded-sm px-1 text-foreground`);
  - the `suggested` tag;
  - the type word (`text-[11px] text-muted-foreground whitespace-nowrap`), pushed right with `ml-auto`.
- **The whole row is the label**, so the hit area is the line. The checkbox's accessible name is the line text, for example `Supplier name: Supplier name suggested text`. The planner may add `aria-describedby` to the type word to make it read cleaner.
- **Unticked state:** the mark loses its fill (`bg-transparent`, dashed `border-border`, `text-muted-foreground`) and a **real DOM** span appears after the line: `PLACE_STAYS_BLANK` (` · stays blank`). ⚠ It is **not** CSS `::after` content and **not** a line-through. The words say "stays blank", and strike-through reads as "deleted", which the sketch README asked to avoid.
- **Couldn't-place rows** (D-28) are `<li>` items with no checkbox: `<span aria-hidden>·</span>` followed by the **server's sentence** in `text-foreground`. Example shape: `Couldn't place “Signature”: that label appears twice in the document. It stays blank in the filled copy.` They come after the placed rows and are not counted by the footing.
- **Order:** the document's order as the server returns it. All rows always show, with **no cap**: the author must see where every answer lands (D-27).
- **Ticks are authoring state.** They travel in the `/generate` body (the ticked anchors) and decide which tokens go into the copy. Unticking never removes the question from the draft's reading. It only leaves the blank empty.

### Rules

- **Limit: 5 (D-03).** A multi-pick that overflows adds the first files that fit and shows `refsOverflow(names)` under the picker. At 5 the native input is `disabled`, carries `aria-describedby` pointing at `REFS_FULL`, and gets the classes `opacity-50 pointer-events-none`.
- **Refused file** (type, magic bytes or size, from the read door): the file is **not added**. One line under the picker reads `refsRefused(filename, serverSentence)`; with no server sentence it uses `REFS_REFUSED_FALLBACK`. The line is `text-foreground` with no colour and no `role="alert"`, because this is the author's own pick being declined, not an emergency.
- **Duplicate** (same name and size as a held file): not added; show `refsDuplicate(filename)`.
- **Remove** pre-draft is an un-pick of bytes that never left the browser except for the stateless read, so it has **no confirmation**. After the draft exists, the door is gone and references are not removable in 291.
- **The CTA waits for reads (Pitfall 11).** While any reference or the form slot is reading, `Write the first draft` stays disabled (the shipped gate, extended). The references footing `REFS_FOOTING_READING` says why. Nothing is read twice: the draft sends the read results.
- **No run-time claim.** Nothing on this section, the card or the decisions row may say a step reads a reference when the workflow runs. Orchestrator decision 2: run-time reading is deferred to a seed.
- The powers line is a **structural** claim about what files can do. It is never a claim that a file is safe (D-17).

### 3a · The removed line(s) (D-14 / D-15)

## Accessibility

- **One live region per surface.** The form slot keeps its single `role="status"` reading region (shipped). The references list sits inside one `role="status"` wrapper. No `role="alert"` anywhere: nothing here is an emergency.
- **Native controls only.** File inputs (shipped reasoning), checkboxes for ticks, and radios for the source switch. No div-buttons.
- **Keyboard order follows DOM order:** slot picker → Remove this document → Show all → each tick → references picker → each Remove → CTA. On the card: dismiss → See what I asked for → inputs fold → grounding fold → decisions fold → the switches inside an open inputs fold.

## Deviation from D-05 (recorded, not hidden)

D-05 says reference files *"are saved with the draft so its steps can cite or read them at run time."* **291 delivers the first half and not the second:**
- Reference files are saved with the draft as `assets[kind=reference]`.
- They inform the draft as fenced content when it is written.
- They are shown on the door before drafting, and on the decisions `template` row after a reload.
- **Steps do not read them when the workflow runs.**

Measured in research (A9 / Open Question 2), `assets[kind=reference]` has no run-time consumer today, and building one is a new capability. Orchestrator decision 2 defers it to a seed.

**The UI consequences are binding:**
- No surface says or implies that a step reads a reference at run time.
- The decisions row says the opposite in plain words (`templateRowReferencesLine`).

The planner records the same deviation in CONTEXT. Re-open trigger: the seed that adds run-time reference reading. That phase owns changing `templateRowReferencesLine`'s second sentence, in the same commit as the capability.
