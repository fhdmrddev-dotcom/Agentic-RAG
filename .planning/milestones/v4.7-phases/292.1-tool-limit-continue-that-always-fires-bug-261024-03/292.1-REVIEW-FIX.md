### CR-01: SEED-324's 409 refuses the Continue button on every first-turn Deep pause

**Files modified:** `backend/app/db/runs.py`, `backend/app/api/runs.py`, `backend/tests/unit/test_2921_continue_same_model.py`
**Commit:** 8d5ba6f1c
**Applied fix:** Followed the binding direction. The finalizer is unchanged: a first-turn pause still finalizes as `completed`, so Phase 250 LOCK-2, test_250 and test_244 are untouched. A new helper, `run_is_cap_paused(conn, run_id, *, org_id=None)`, sits in `app/db/runs.py` next to `load_cap_paused_tool_calls`. It is the only pause predicate. It uses one SQL statement with `$N` placeholders only. A run counts as paused when either:
- `status = 'cap_paused'`, or
- all of the following hold:
  - `status = 'completed'`;
  - it is a root run (`parent_run_id IS NULL`);
  - `continues_used = 0`;
  - the thread's latest `iteration_cap_paused` carrier was written at or after the run's `started_at` (org-scoped like the consume read);
  - no newer root run has started in the thread.

`continue_run` now raises its 409 only when the run is terminal and this predicate says it is not paused. `failed`, `cancelled` and `timed_out` never cost the read. `streaming` is still accepted.

Two clauses go beyond the binding text, and both make the check stricter:
- **`continues_used = 0`.** A continued run that ends `completed` has finished; a continuation that pauses again writes `cap_paused`. Without this clause, an old Continue card would re-run the dropped calls after a successful continuation.
- **"No newer root run".** Under the 244 rule, a pause belongs to the latest run or to nobody. Without this clause, an older run would be accepted on a newer run's carrier.

**Evidence:**
- **RED → GREEN:** the new test `test_a_first_turn_pause_finalized_completed_with_its_carrier_is_accepted` (the predicate is called with the run id and its org). The existing `completed` refusal now explicitly means "no pause".
- **Read-only run against the live local DB:**
  - The four runs the reviewer named (`5835720e`, `78784975`, `e4313e30`, `5ec12235`) read as paused.
  - None of the following read as paused: 50 `completed` runs in threads with no carrier, 2 `completed` runs newer than their thread's latest carrier, 50 sub-agent rows, and a missing run id.

### WR-01: A prose mention of `<tool_call>` / `<|tool_call>` / `<function=` was cut off and could cause a false pause

**Files modified:** `backend/app/services/text_tool_calls.py`, `backend/tests/unit/test_2921_text_tool_calls.py`, `backend/tests/unit/test_2921_cap_text_calls.py`
**Commit:** d7d50f16a
**Applied fix:** A non-DSML opener now counts as a call only when what follows it has its family's measured call shape:

| Family | Counts as a call when the opener is followed by |
|---|---|
| `<tool_call>` | `{`, or `<function=`, or `NAME` then `<arg_key>` / `</tool_call>` (GLM) |
| `<\|tool_call>` | `{`, or `[call:]NAME{` |
| `<function=` | `NAME>`, and only at the start of a line |

A block that is cut off before its shape can be told counts only when it starts a line. `TagHoldback` now holds an undecided opener without sticking and releases it as soon as the following text proves it is prose. Only a proven call shape, or DSML, sticks. DSML handling is unchanged.

**Evidence:**
- **RED → GREEN:** 26 module cases (the reviewer's two sentences, plus `<function=` variants, are byte-identical through `detect_markup`, `strip_markup` and `settle`, and the holdback releases them live at splits of 1, 2, 5 and 50) and 12 loop cases.
