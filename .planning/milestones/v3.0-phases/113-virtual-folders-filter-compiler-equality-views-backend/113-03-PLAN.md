<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (JWT) → /document-views (CRUD + resolve) | Untrusted `filter_expr`, `folder_scope`, and `view_id` cross here |
| resolve query construction → documents (Postgres + RLS) | The single most dangerous boundary: the query scope MUST come from the caller, never the view owner |
| create → audit_log | The `view.create` governance receipt (DMF-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-09 | Information Disclosure (cross-user content/count/existence leak — VIEW-06) | resolve query construction | mitigate | Per-viewer resolution: EVERY query leg scoped from `caller` (own docs + caller's globally-visible-folder docs), NEVER `view["user_id"]`. A global view's definition is shared; its results are computed fresh over each caller's visible set. Verified LIVE in secure-phase (the two-user leak test — RLS label is NOT proof, D-102/D-110-5). |
| T-113-10 | Information Disclosure (view-existence enumeration) | CRUD + resolve 404 path | mitigate | A view id the caller can't see (not own AND not global) → generic `HTTPException(404)`, never 403, never a distinct error message. `test_cross_user_miss_404` asserts live. |
| T-113-11 | Tampering (SQLi/SSTI via filter value — SC#4) | resolve `.contains("metadata", metadata_filter)` | mitigate | The compiled `metadata_filter` is bound as one `$1::jsonb` via supabase-py `.contains()` — never string-interpolated. `test_injection_value_neutralized_live` asserts 0 matches + table intact (the live half of SC#4; the unit half is in Plan 01). |
| T-113-12 | Tampering (field-name injection at save/update) | router whitelist validation | mitigate | `validate_fields` runs against `set(DocumentMetadata.model_fields) ∪ enabled custom defs` before create AND update; unknown/`_`-prefixed field → 422. |
| T-113-13 | Elevation of Privilege (escalate to global view) | create/update | mitigate | Service hard-sets `is_global=false`; RLS WITH CHECK forces it; the body never supplies it. CRUD integration test asserts the created row is non-global. |
| T-113-14 | DoS (unbounded subtree recursion on corrupt folder data) | `resolve_project_subtree` | mitigate | Reuses the shipped cycle-guarded (IN-01) subtree walk; returns a bounded `list[str]`. Not re-derived. |
| T-113-15 | DoS (blocking I/O in async route) | every `.execute()` in the router | mitigate | All DB calls wrapped in `aexec` (`run_in_threadpool`) per D-v2.5-01. |
</threat_model>
