<objective>
Build the two net-new backend primitives Phase 118 stands on — the Pydantic rule models
and the PURE in-Python condition matcher — plus the Wave-0 test scaffolds every later 118
plan verifies against. This is the load-bearing research finding: the Phase 113/114 SQL
compiler CANNOT be reused at the ingest call site (the doc is not yet persisted), so a thin
`match_metadata(match_expr, metadata_dict) -> bool` evaluator is required. It REUSES the
`ViewFilter` AST (parse-time op-reject) + `validate_fields`/`validate_operands` (whitelist +
operand guards) + mirrors the operator normalization, but compares the dict in Python.

Purpose: Lock the matcher semantics to the SQL semantics (so the builder's "would match N"
preview ≈ the on-upload match — Pitfall 2) and give Plans 02/03 a contract to implement.
Output: `classification_rule.py`, `classification_matcher.py`, and 8 Wave-0 test files.
</objective>
