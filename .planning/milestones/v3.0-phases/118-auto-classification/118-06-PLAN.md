## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| builder scope toggle → createRule/updateRule | The client offers a global scope choice; the backend (Plan 02) is the gate that hard-sets is_global on CREATE |
| rules list → DOM | Only the caller's own + global rules are listed (backend list_rules leak-safe predicate) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-06-01 | Elevation | RuleBuilderPanel save (scope) | mitigate | createRule's body OMITS is_global (Plan 04) — the server hard-sets is_global=false on CREATE (Plan 02 T-118-02-01). The builder's "Global" scope cannot self-elevate a created rule; global-rule authoring is an admin-gated server path, not a client body flag. |
| T-118-06-02 | Information Disclosure | rules list render | accept | listRules() returns only own + global rules (Plan 02 leak-safe `.or_()`); the UI cannot render another user's private rule because the backend never returns it. |
| T-118-06-03 | (a11y, not security) | builder + toggle + kebab | mitigate | Keyboard-operable, AA tokens, mobile-responsive (UX-01 / WCAG 2.1 AA); coarse-pointer always-on for icon controls. |
| T-118-06-SC | Tampering | npm installs | accept | No new package; slopcheck moot. |
</threat_model>
