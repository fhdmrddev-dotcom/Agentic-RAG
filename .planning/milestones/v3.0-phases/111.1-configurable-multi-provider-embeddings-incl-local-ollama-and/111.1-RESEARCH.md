**Cross-cutting principle**
- **D-01 — Quality-first, not cost-first.** Picker opens the field to the *most capable* embedders per provider; large/high-dimension models are first-class choices. **Dimensions stay flexible — NO forced down-truncation.** Explicitly REJECTS the "standardize everything to 1024 via Matryoshka truncation" idea.

**Re-embed lifecycle & UX (Area 1)**

- **D-03 — The confirmation is a SERIOUS, attention-demanding gate** (hard design contract for the G-2 sketch). Must name in plain language: # chunks re-embedded, target model, that search quality dips until done, a rough ETA, and that the change is reversible only by switching back + re-embedding.

## Summary

This phase is **~85% wiring of existing, verified primitives** — not greenfield. The embedding client (`get_embedding_client`, `openai_service.py:1011-1034`) is already an OpenAI SDK pointed at a configurable `base_url`/`api_key`, so OpenAI / Google / Ollama / LM Studio / Cohere / Jina / Mistral all work through the same code path with zero new client code (each exposes an OpenAI-compatible `/v1/embeddings`). The local-provider plumbing (`_PROVIDER_BASE_URLS`, `lmstudio`/`ollama` dummy keys, `resolve_llm_provider`) already exists from Phase 111. The re-embed lifecycle has a pre-built (never-called) `resize_embedding_column(N)` SQL function and a `content`-preserving chunk table to regenerate vectors from. The migration pattern (072 → **073**), the `app_settings` env_attr=None field pattern, and the test layout are all established and copyable.

The genuinely net-new work is: (1) a **reusable React provider-picker component** generalizing the rerank `<select>`, reused for embedding + extraction; (2) a **migration 073** adding `embedding_model` + `embedding_dimensions` to `document_chunks` (D-10) plus the `embedding_provider`/`extraction_provider` `app_settings` columns + threshold/confidence-bucket defaults; (3) a **batched, resumable, RLS-scoped re-embed background job**; (4) the **D-03 destructive-change modal** (operator-approved sketch 025); and (5) the **three D-09 routing fixes** that close BUG-260616-01 (all three code seams confirmed in this session). The EMBED-04 bug is a one-line root cause: `documents.py:1475` calls `embed_chunks(..., model=...)` but never threads `user_settings`, while the query path does — so a configured non-default embedder embeds chunks via env creds and queries via configured creds → mismatched vector spaces.

The two highest-risk seams are **vector-space integrity** (a half-finished re-embed must never let search compare across embedding models/dims — solved by the D-10 per-chunk tag + a `match_document_chunks` filter) and **data egress** (the BUG-260616-01 mis-route silently ships local document text to OpenRouter cloud — solved by explicit `(provider, model)` pairing + the two mangling/routing fixes). Both are security-relevant and must be live-tested, not mocked (the project's "static would false-green" lesson).

**Primary recommendation:** Add migration 073 (chunk tags + app_settings provider/threshold/bucket columns), thread `user_settings` through `embed_chunks` (EMBED-04), add a `WHERE embedding_model = <current>` filter to `match_document_chunks` (D-10), build the one reusable picker, land the three D-09 routing fixes, and wire `resize_embedding_column` into a resumable batched job gated by the D-03 confirm modal. Do NOT pass `dimensions=` as a forced global cap (D-01) — only as an optional per-truncation-capable-provider convenience.

- **Inferring embedding provider from the model-name string.** This is the exact BUG-260616-01 root cause (`config.py:362` `^word/word → openrouter`). Store `(provider, model)` explicitly; inference is last-resort legacy only.

- **Deleting old vectors before the replacement is written.** Violates D-05 non-destructive guarantee; a failed run would leave the corpus worse than "partial."

## Common Pitfalls

### Pitfall 1: The EMBED-04 credential mismatch (the bug this phase fixes — verified live this session)
**What goes wrong:** A configured non-default embedder embeds CHUNKS via env creds but QUERIES via configured creds → two different vector spaces → cosine similarity is meaningless → silent retrieval failure (low scores, wrong/empty results, no error).
**Root cause (CONFIRMED):** `documents.py:1475` calls `embed_chunks(texts_to_embed, model=app_settings.embedding_model or None)` — passes `model=` only. `embed_chunks` → `embed_texts(chunks, model=model)` with `user_settings=None` → `get_embedding_client(None)` falls through to `settings.*` (env). The QUERY path (`retrieval_service.py:43`) correctly passes `user_settings=user_settings`. `[VERIFIED: documents.py:1475 vs retrieval_service.py:43]`
**How to avoid:** Add `user_settings` param to `embed_chunks`; pass `user_settings=app_settings` at the call site; both paths resolve identical creds via `get_embedding_client`.
**Warning signs:** Retrieval returns nothing/low-similarity right after switching embedders, with no error in logs.

### Pitfall 2: Half-finished re-embed compares across vector spaces (D-10)
**What goes wrong:** During a model change, some chunks are new-model, some old-model — same column, possibly same dims (the "mixed-space trap"). `match_document_chunks` would compare a query in the new space against old-space chunks → garbage similarities.
**Why it happens:** `NULL` only catches dims-incompatible resizes; a same-dim different-model swap leaves non-NULL stale vectors.
**How to avoid:** D-10 per-chunk `embedding_model` tag + `WHERE dc.embedding_model = <current>` in `match_document_chunks` (`full-schema.sql:120-137`). Filtered-out chunks = the graceful-dip recall reduction (D-04).
**Warning signs:** Intermittently wrong results only while a re-embed is in progress.

### Pitfall 3: Local model silently mis-routes to OpenRouter cloud (BUG-260616-01 — data egress)
**What goes wrong:** A slashed local model id (`google/gemma-3-4b`) is classified `openrouter` by `config.py:362`; `forced_emit` injects the OpenRouter key + base_url; document text ships to the cloud with a green result. Even when provider is forced to `lmstudio`, the OpenRouter `:exacto`/`response-healing` mangling (gated on `"/" in model`, `openai_service.py:1448-1456`) 500s the local server.
**How to avoid (all three, D-09):** (1) explicit `extraction_provider`, skip inference when set; (2) local-aware `forced_emit` (resolve `:1234`/`:11434` + dummy key — currently `getattr(settings, f"{provider}_api_key")` returns `""` for lmstudio/ollama and the block no-ops, falling through to the wrong active provider); (3) gate the mangling on `provider=="openrouter"`.
**Warning signs:** A "local" extraction/embedding that's actually fast + cloud-priced; a 500 HTML page from `:1234`. Live-proven fix already exists in `scripts/_uat111/test_lmstudio_extraction.py`.

### Pitfall 4: Thresholds tuned for `text-embedding-3-small` are NOT portable (D-11/D-12)
**What goes wrong:** `retrieval_match_threshold=0.3` and confidence buckets `0.54`/`0.38` (`agent_loop.py:678-680`) were calibrated for `text-embedding-3-small` (Phase 076, N=121). A different embedder's score distribution shifts → silent over/under-filtering + dishonest confidence labels.
**How to avoid:** Carry per-preset threshold + bucket defaults (D-11/D-12); lift the hardcoded buckets into settings. No auto-calibration in v1 (deferred).
**Warning signs:** After switching embedders, everything reads "low confidence" or everything reads "high," or recall collapses/explodes.

### Pitfall 5: `dimensions=` misuse breaks D-01
**What goes wrong:** Passing `dimensions=1024` globally truncates a strong 3072-dim model, throwing away the accuracy D-01 refuses to compromise. Also: not every provider supports the param (OpenAI 3-large + Google gemini-embedding-001 + Cohere v4 + Jina do via MRL; some local models do NOT).
**How to avoid:** Treat `dimensions=` as an optional per-provider convenience only; never a forced global cap. The chunk's actual dims are recorded in the D-10 tag.

### Re-embed job skeleton (D-04/D-05 — resumable, non-destructive, threadpool)
```python
# PATTERN (assembled from VERIFIED seams: resize_embedding_column + embed_texts + run_in_threadpool)
async def reembed_job(supabase, user_id, app_settings):
    current = app_settings.embedding_model
    if dims_changed:
        await run_in_threadpool(lambda: supabase.rpc("resize_embedding_column",
                                {"new_dim": app_settings.embedding_dimensions}).execute())
    while True:  # resumable: same stale predicate each pass
        batch = await run_in_threadpool(lambda: supabase.table("document_chunks")
            .select("id, content").eq("user_id", user_id)        # RLS-scoped
            .neq("embedding_model", current).limit(BATCH).execute())  # IS DISTINCT FROM <current>
        if not batch.data: break
        vectors = await run_in_threadpool(embed_texts,
            [r["content"] for r in batch.data], user_settings=app_settings)
        for row, vec in zip(batch.data, vectors):  # write replacement THEN tag (D-05)
            await run_in_threadpool(lambda: supabase.table("document_chunks")
                .update({"embedding": vec, "embedding_model": current,
                         "embedding_dimensions": app_settings.embedding_dimensions})
                .eq("id", row["id"]).execute())
```
