<decisions>
## Implementation Decisions

### Cross-cutting principle (drove every choice below)
- **D-01 — Quality-first, not cost-first.** Accuracy/quality is the priority; cost is a
  secondary tiebreaker. The picker opens the field to the **most capable embedders per
  provider** (large / high-dimension models are **first-class choices**, not buried
  overrides). **Dimensions stay flexible — NO forced down-truncation.** This explicitly
  **rejects** the optional "standardize everything to 1024 via Matryoshka truncation" idea:
  truncating a strong 3072-dim model down to 1024 throws away exactly the accuracy we refuse
  to compromise. (Happy fact: even "large" embedders cost fractions of a cent and local ones
  are free — so quality-first carries almost no cost penalty for embeddings.)

### Re-embed lifecycle & UX (Area 1)
- **D-02 — Trigger = confirm-on-save.** Changing the embedding model/dimension in Settings
  and hitting **Save** pops a destructive-change confirmation. NOT silent-auto, NOT a
  separate hunt-for-a-button as the primary path.
- **D-03 — The confirmation is a SERIOUS, attention-demanding gate** (hard design contract
  for the G-2 sketch — operator emphasis). It is **not** a casual toast. It MUST name, in
  plain language: how many chunks will be re-embedded, the target model, that **search
  quality dips until the job finishes**, a rough ETA, and that the change is only reversible
  by switching back + re-embedding again.
- **D-04 — Execution = Option A "graceful-dip"** (chosen over zero-downtime shadow-build B).
  A **background batched re-embed job** runs; chunks not yet re-embedded are filtered out of
  search (see D-10), so **search stays up at reduced recall** and **fully recovers** as the
  job completes. A temporary "search is catching up" window is an accepted, honest cost for a
  rare deliberate admin act. (Option B reserved for a future large-corpus customer who can't
  tolerate any dip — captured as deferred.)
- **D-05 — Resumable + non-destructive.** The job targets a stale predicate (D-10), so a
  re-run picks up where it stopped. **Old vectors are never deleted until their replacement is
  written**, so a failed/interrupted run never leaves the corpus worse than "partial." A
  manual **"Re-embed now"** control re-kicks a failed/partial run.

### Provider picker & presets (Area 2)
- **D-06 — Ship an OpenAI-compatible `/v1/embeddings` preset picker**, modeled on the rerank
  provider `<select>` (`SettingsPage.tsx:959-967`). Presets: **OpenAI, Google, Ollama
  (local), LM Studio (local), Cohere / Jina / Mistral, Custom / OpenAI-compatible.** Each
  preset auto-fills `base_url` + a **strong default model** + default dimensions; local
  providers relax the API key to a dummy value (Ollama `http://localhost:11434/v1`,
  LM Studio `http://localhost:1234/v1`). Satisfies EMBED-01/02/03.
- **D-07 — Lock the picker SHAPE now; curate exact default model IDs as a phase task.** Exact
  embedding-model IDs drift, so the per-provider default IDs are validated against each
  provider's live `/models` during the phase, not hard-pinned in CONTEXT. (Model names are
  representative of a provider/quality class, not pinned versions.)
- **D-08 — Shipped zero-config default stays the current OpenAI small / 1536** for
  back-compat — **no surprise re-embed on upgrade** — with the high-quality / large options
  **one click away** in the picker. Opting into a stronger embedder is what triggers the D-02
  confirmation.
- **D-09 — Symmetric extraction fix IS IN SCOPE (closes BUG-260616-01).** Build **ONE
  reusable provider-picker component** and use it for **both** the embedding model **and** the
  extraction model — so a model can't be selected without pinning **where it runs** (the
  structural cure for the "slashed id → mis-routes to OpenRouter cloud" data-egress bug). The
  three backend routing fixes land regardless of the UI:
  1. Explicit `extraction_provider` (beside `extraction_model`) — route by stored provider,
     **skip name-inference when set**; inference stays only as a last-resort legacy fallback.
  2. **Local-aware `forced_emit`** — a forced shot targeting a local provider resolves that
     provider's `base_url` (`:1234` / `:11434`) + dummy key (`forced_emit.py:251-275`).
  3. **Gate the OpenRouter "quality" mangling on `provider=="openrouter"`**, NOT on `"/" in
     model` (`openai_service.py:1449-1456`) — as-is it appends `:exacto` + a `response-healing`
     plugin to ANY slashed model id and 500s LM Studio/Ollama.

### Per-chunk model tagging (Area 3)
- **D-10 — Add `embedding_model` + `embedding_dimensions` columns to `document_chunks`**
  (migration). Guards the silent **same-dimension / different-model** mixed-space trap
  (vectors match in shape but not meaning, with no `NULL` to signal staleness). Effects:
  - Search **filters to the currently-configured model only** → a half-finished re-embed can
    never silently compare across vector spaces.
  - The re-embed/resume predicate (D-05) = `WHERE embedding_model IS DISTINCT FROM <current>`
    (stricter + safer than `WHERE embedding IS NULL`).
  - Backfill existing rows with the current default model on migration.
  - Seam for future multi-model coexistence (out of scope now).

### Threshold portability (Area 4)
- **D-11 — Retrieval threshold travels WITH the embedder preset.** Each preset carries a
  recommended `retrieval_match_threshold` default for that model; it stays an editable
  setting. (High-stakes: a fixed `0.3` tuned for `text-embedding-3-small` silently over/under-
  filters other embedders.)
- **D-12 — Lift the hardcoded confidence-bucket cutoffs (`0.54` / `0.38`,
  `agent_loop.py:664-682`) into settings with per-preset defaults** — keeps the user-facing
  high/medium/low confidence labels honest after a switch. **Trimmable to a documented
  limitation only if scope tightens** (quality-first argues for doing it). **No
  auto-calibration in v1** (deferred → future eval phase).

### Locked requirement (no decision needed, restated for the planner)
- **D-13 — Fix the `embed_chunks` credential bug** (EMBED-04): `embed_chunks` drops
  `user_settings` (`embedding_service.py:94` / `documents.py:1405`), so a configured
  non-default embedder embeds chunks via env but queries via the configured provider →
  mismatched vector spaces. Chunk-embedding and query-embedding MUST use the SAME configured
  model + creds. **Proven by a live cross-embedder ingest+search test.**

### Claude's Discretion
- Exact migration number + column-resize wiring (`resize_embedding_column(N)`,
  `full-schema.sql:173-191`, currently never called).
- Re-embed batch size + the background-job mechanism (reuse existing app patterns; respect
  `run_in_threadpool` / no-blocking-I/O-in-async-handlers rule).
- Whether to pass `embedding_dimensions` into `embeddings.create(dimensions=…)`
  (`openai_service.py:1473`, currently not passed) for truncation-capable providers — allowed
  as a coexistence convenience, but NOT as a forced global cap (D-01).
- Modal copy wording (within the D-03 contract).

</decisions>

## Existing Code Insights

### Reusable Assets
- Rerank provider `<select>` (`SettingsPage.tsx:959-967`) — the exact picker pattern to
  generalize into the **one reusable provider-picker component** (D-09).
- `lmstudio` first-class provider plumbing + the 3 `app_settings`-backed settings + admin-DB-
  setting pattern from Phase 111 — reuse for `embedding_provider` / `extraction_provider`.
- `resize_embedding_column(N)` (`full-schema.sql:173-191`) — already exists, never called;
  wire it into the re-embed lifecycle (D-04).
- `get_embedding_client` (`openai_service.py:~1011`) — single embedding client seam; already
  OpenAI-compatible, so Ollama/LM Studio/Jina/Mistral/Cohere need zero new client code.

### Established Patterns
- `MODEL_CAPABILITIES` registry + provider resolution (`config.py`) — extend for explicit
  `(provider, model)` pairing rather than name-inference.
- `forced_emit` TIER-COERCE + graceful degradation — the safety net that lets a too-weak local
  model honest-fail (null metadata, doc still completes) instead of producing garbage.
- No-blocking-I/O-in-async-handlers (D-v2.5-01): the re-embed background job must respect
  `run_in_threadpool` for supabase-py calls.

### Integration Points
- Settings UI → `app_settings` (`embedding_provider`, `extraction_provider`, threshold +
  confidence-bucket defaults).
- New migration → `document_chunks` (+ `embedding_model`, `embedding_dimensions`), then regen
  `full-schema.sql` (no reset) per CLAUDE.md.
- Re-embed job reads preserved `content` from `document_chunks` to regenerate vectors.

</code_context>

## Specific Ideas

- Operator emphasis (verbatim intent): the model-change is "a serious step that should be
  handled carefully to **get the attention of the user about the consequences**" → D-03 is a
  hard contract, not a nicety.
- Quality posture (verbatim intent): "we want **accuracy**, we will **not compromise on
  quality**; the purpose is to **open the choices** to the **most decent embedding models**."
  → D-01.
- Live proof on hand (BUG-260616-01, 2026-06-16): a 12B local model (`gemma-4-12b-qat`)
  extracts full confidence-scored metadata through the real engine once the routing/mangling
  is bypassed — the local path is sound; only the three D-09 fixes block it.
