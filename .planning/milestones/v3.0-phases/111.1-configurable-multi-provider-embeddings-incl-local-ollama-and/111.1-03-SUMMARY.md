# Phase 111.1 Plan 03: EMBED-04 Cred Fix + D-10 Chunk Tag + D-12 Buckets Summary

**Closes the headline retrieval-correctness bug (EMBED-04): `embed_chunks` now threads `user_settings` so chunk-embedding and query-embedding resolve the identical `get_embedding_client` (no env-vs-configured cred split → no silent two-vector-space failure); each new chunk is tagged with its embedding model + dims (D-10 write); the retrieval RPC filters search to the currently-configured model so stale-model chunks are excluded instead of compared cross-space (D-10 filter); and confidence buckets are lifted into settings (D-12) so labels stay calibrated after an embedder switch — all with 0.54/0.38 / text-embedding-3-small defaults preserving byte-identical back-compat.**

## Accomplishments

- **EMBED-04 (the headline bug):** `embed_chunks(chunks, model=None, user_settings=None)` now forwards `user_settings` to `embed_texts`, so the ingest path resolves the SAME embedder client the query path uses (`retrieval_service.py:42-44`). `documents.py` chunk-embed passes `user_settings=app_settings`. Before this, a configured non-default embedder embedded CHUNKS via env creds while QUERIES went via configured creds — two vector spaces, a silent retrieval failure.
- **D-10 write path:** each `chunk_rows` entry now carries `embedding_model` (= `app_settings.embedding_model` or the shipped `text-embedding-3-small` default) + `embedding_dimensions`, mirroring the migration-073 backfill.
- **D-10 retrieval filter:** `_vector_search` passes `p_embedding_model` (the currently-configured model, defaulting to `text-embedding-3-small`) into `match_document_chunks`. Stale-model chunks are excluded — the graceful-dip recall reduction (D-04) during a re-embed, never a cross-vector-space comparison (Pitfall 2). All existing RPC args (`match_user_id`/`match_count`/`match_threshold`/`metadata_filter`/`p_folder_ids`) are intact; the new param is additive + NULL-defaulted so the call stays valid before the migration is applied.
- **D-12:** `_compute_confidence` reads `confidence_bucket_high`/`confidence_bucket_medium` from the resolved `user_settings`, defaulting to 0.54/0.38; the call site in `run_agent_loop` threads `user_settings`. Labels stay calibrated after an embedder switch. Behavior is byte-identical to today when settings are unset (D-08 back-compat — proven by an explicit boundary test).

## Decisions Made

- **`_compute_confidence` dual signature:** the Wave-0 scaffold's un-markable test calls `_compute_confidence(0.40, bucket_high=0.30, bucket_medium=0.20)` (explicit kwargs), while the plan's action snippet uses a `settings_obj`. I made the signature accept both — `bucket_high`/`bucket_medium` kwargs win, then `settings_obj` attrs, then 0.54/0.38 — so the existing scaffold passes unchanged AND the production call site (`run_agent_loop`) can pass the live `user_settings` object. The call site uses the `settings_obj` positional form.
