## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| view list / count fetch → backend | The Views group reads listViews + count-only resolve — both caller-scoped leak-safe from Phase 113/Plan 02; the client renders only the caller's own visible views |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-114-06-01 | Information Disclosure | per-view count badge | mitigate | The badge calls the count-only resolve endpoint which is caller-scoped own+global (Plan 02); a global view's badge shows the CALLER's matching count, never the view owner's — no cross-user count leak. Lazy fetch does not change the scoping. |
| T-114-06-02 | Information Disclosure | the Views list render | mitigate | `listViews()` returns only the caller's own + global views (Phase 113 leak-safe service); the client renders what the server returns — no client-side filtering bypass. |
| T-114-06-03 | Tampering | sidebar pin / view selection state | accept | The collapse-pin + selectedViewId live in client/session state only; they affect layout/selection, not authz — a tampered value cannot widen data access (every resolve is server-scoped). Low risk. |
| T-114-06-SC | Tampering | npm/pip installs | accept | This plan installs NO packages (composes existing primitives). No supply-chain surface. |
</threat_model>
