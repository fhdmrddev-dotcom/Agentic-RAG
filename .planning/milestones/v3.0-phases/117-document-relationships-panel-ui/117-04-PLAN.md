<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rendered relationship filename → DOM | An attacker-controlled filename could attempt XSS if rendered unescaped. |
| client candidate filter → create | The client exclusion is clarity-only; the backend visible-both gate + idempotency are the correctness/access boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-04-01 | Tampering (client XSS) | filename render in a relationship row | mitigate | Filenames render as React text children (escaped by default); NEVER `dangerouslySetInnerHTML`. The masked row renders the constant mask string, never server HTML. |
| T-117-04-02 | Information Disclosure | masked-row id leak in the UI | mitigate | The masked row's `document_id` is null (the type enforces it); the UI renders only `filename` (the mask string), never an id/title — proven by the RelationshipsSection masked-state test. |
| T-117-04-03 | Elevation (client trust) | client candidate exclusion bypass | accept | The client exclusion is clarity-only (D-117-4); the backend POST visible-both gate (uniform 422) + idempotent-create (D-116-6) are the real correctness/access gate. A bypassed stale candidate is a no-op or a uniform 422, never a leak. |
| T-117-04-04 | (a11y, not strictly STRIDE) | remove ✕ unreachable on touch/keyboard | mitigate | `:focus-visible` + `@media (pointer:coarse)` always-on (the audit's #1 fix); combobox APG roles wired by hand; verified by the vitest-axe a11y test. |
| T-117-04-SC | Tampering | npm/pip/cargo installs | accept | No package installs (the typeahead is bespoke — NO cmdk; verified by `git diff package.json`). RESEARCH §Package Legitimacy Audit vacuously clean. |
</threat_model>
