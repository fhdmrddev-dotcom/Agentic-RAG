<objective>
Close the publish-path security + robustness warnings (operator-approved fold), all QUAL-01:

- **WR-02 (security):** `get_definition` uses `WHERE id=$1 AND (created_by=$2 OR is_global=true)` with NO status filter → it exposes another user's GLOBAL DRAFT; `publish_definition` then flips it. A non-owner can drive a golden run + publish flip on a global draft (a privileged state change by a non-owner). Restrict the publish read to true ownership.
- **WR-03:** `publish_definition` returns `-1` when the draft flip found no row (concurrent double-publish), but `publish_workflow` never checks the sentinel → returns `{published:True, version:-1}` + writes a FALSE `publish_succeeded` receipt. Route `version==-1` to an honest `already_published` block.
- **WR-04 (minimum-viable hardening — NOT the full background-job rework, which stays deferred to Phase 103):** the publish endpoint synchronously drives a full golden run with no deadline, and interactive phases (`llm_human_input` / `ask_user` validator dispositions) dead-end the synchronous publish path. (1) Wrap `_drive_golden_run` in `asyncio.wait_for` with a publish-level budget mapping a timeout to a `golden_run_timeout` block; (2) block definitions containing interactive phases from the synchronous publish path with a named failure pre-run.
- **IN-02 (cheap, same file):** annotate `write_audit(run_id: UUID | None)` + note the nullable-receipt contract in the docstring.

Purpose: WR-02 closes a real EoP (a non-owner publishing a global draft); WR-03 stops a false governance receipt; WR-04 stops the request hanging for hours and dead-ending on interactive phases.
Output: An owner-only publish read; an honest concurrent-publish block; a deadline + interactive-phase guard on the synchronous publish; the nullable receipt annotation; tests for each.
</objective>
