<objective>
Close the 101.1 live-UAT blocker: the citation gate over-rejects 100% of emissions on every
provider. Live run a12ee906 (gpt-5.4-mini): gate_verdict cited=0/uncited=0/invented=24 —
the model emitted all 24 values WITH citations, but every citation read as "invented".

Root cause (two coupled wiring gaps in _exec_llm_emit):
1. The emit user turn is the prior phase's PROSE (_first_phase_user_turn) — never a
   <doc id=...> spotlight over the retrieved evidence. The tool description says "cite
   the <doc id> it came from" but no <doc id> was ever shown → the model fabricates ids.
2. _retrieved_ids scans refs for chunk_id/source_chunk_id/id keys, but live enriched
   retrieval refs carry document_id + chunk_index (no such keys) → valid set ALWAYS
   empty → everything cited is "invented".
This is the 097 carry-forward ("thread a stable chunk id end-to-end") that was never
actually closed. The offline tests passed because their fakes used chunk_id-shaped refs —
mock-shape drift from the live shape (the 099 lesson again).

Fix (ONE id namespace end-to-end, security-preserving): a single _emit_evidence walk
assigns each retrieved ref a stable spotlight id (explicit chunk_id when present, else
the composite "{document_id}#{chunk_index}"), renders the <doc id=.. file=..>passage</doc>
spotlight appended to the emit user turn, AND returns the gate's valid-id set from the
SAME assignment. Genuine citations pass; fabricated ids still reject (the valid set is
computed server-side from the refs — ids injected inside passage TEXT are not in the set,
so KB-content prompt injection cannot whitelist itself).
</objective>
