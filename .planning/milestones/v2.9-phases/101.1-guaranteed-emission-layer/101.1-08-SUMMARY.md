# Phase 101.1 Plan 08: Guaranteed-Emission Last-Mile (binary persist + ephemeral path + snapshot degrade) Summary

**A binary-safe write_file (skip the NUL-bearing JSONB delta), a distinct ephemeral output filename (never overwrite the uploaded template), and a snapshot endpoint that degrades on a GC'd run buffer instead of 503-ing — the two defects that let an emit pass every gate then die at the last mile.**

## Accomplishments
- **Gap 5a (the crash root):** `write_file` now skips the unified-text delta for binary mimes, so a docx/pptx/xlsx second version never decodes its `\x00` zip bytes into a NUL that Postgres JSONB rejects (`UntranslatableCharacterError` — UAT run 4ea9bc56). Defense-in-depth: `_compute_delta_from_prev` returns the NUL-free binary verdict if a NUL appears in either side, so no NUL can reach a JSONB delta even on a mis-typed extension.
- **Gap 5b (no template overwrite):** the ephemeral-upload branch of `_render_template_post` now writes `deliverable-filled.<ext>` — a DISTINCT path that preserves the template extension — so the rendered deliverable persists as a fresh v1 instead of overwriting the user's uploaded template AND tripping the version-2 binary-delta crash. The bound branch is unchanged.
- **Gap 4 (backend half):** `GET /threads/{id}/snapshot` distinguishes a GC'd terminal-run buffer (`ResponseError('no such key')` → skip that run's cursor, return 200) from a genuine Redis outage (connection-level `RedisError` → still 503 + Retry-After). The DB reconcile is the source of truth for a terminal run's final state (D-v2.5-03).

## Decisions Made
- Fixed BOTH halves of gap 5 (binary delta skip + distinct ephemeral name) as the objective mandates — fixing either alone is insufficient (skip-only still overwrites the template; distinct-name-only still risks a NUL delta if any binary ever reaches version>1).
- Ephemeral output name `deliverable-filled.<ext>` is deterministic and matches `_handle_render_template`'s `_safe_out_filename` allow-list `^[A-Za-z0-9._ -]+\.(docx|pptx|xlsx)$`, so it survives the CR-01 coercion unchanged.
- Snapshot degrade re-raises any ResponseError whose message is NOT "no such key" into the broad handler — a `WRONGTYPE`-class fault is still a real fault and must 503, not be silently swallowed (covered by `test_snapshot_non_missing_response_error_still_503`).
