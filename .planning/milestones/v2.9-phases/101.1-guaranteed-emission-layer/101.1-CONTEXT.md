# Phase 101.1: Guaranteed Structured Emission Layer (Template-Fill Gap-Closure) - Context

**Gathered:** 2026-06-11
**Status:** Ready for planning

> Origin: Phase 101 (Template-Fill) shipped code-complete + code-verified but its **live UAT BLOCKED — 0 .docx produced across 4 runs** (GAP-A..D, see `101-LIVE-UAT-FINDINGS.md`). An evidence-based investigation (two adversarial multi-agent workflows, 2026-06-11) traced the failure to a **systemic architecture gap, not a one-off bug**: the fill step was wired as an *open auto-tool-choice agent loop*, so reasoning-native models narrate a structured field-map as prose instead of emitting it, and the bound library template was never handed to the tool. The operator ratified the **foundational** fix (this phase), not a minimal patch.

<domain>
## Phase Boundary

**This phase delivers ONE shared "guaranteed structured emission" engine layer** — a new generic harness phase type (`llm_emit`) that **forces** the model to emit cited DATA against a strict schema, which a **pinned, deterministic, no-model-code driver** then renders into the deliverable — and makes **template-fill its first concrete instance**, closing GAP-A..D live across the native-7.

**In scope:**
- The gateway **capability-tiered forcing seam** (`tool_choice == "forced"`), per-provider, at the service boundary only.
- **NATIVE-path narrated-JSON recovery** + finish_reason guard (closes the silent-drop on reasoning-natives).
- The `llm_emit` phase type + `_exec_llm_emit` executor + emit substrate (`forced_emit` / `_emit_one_forced`).
- A closed **`EMITTER_REGISTRY`**; `render_template` demoted to its first entry (schema + deterministic post-processor).
- **Flattened** GenericFieldMap (back-compatible / gated).
- **GAP-B**: server-side resolution of the bound library template AssetRef injected into emit args at phase-build time.
- **GAP-C**: emit-moment run-honesty (discrete `forcing → emitting → rendering → validating` sub-events + explicit failure states).
- **Audit receipt substrate**: INSERT-only `harness_audit` rows per transition, keyed to `run_id` + `definition@version`.
- Live cross-provider UAT (the 8 rows of `101-HUMAN-UAT.md` + the 4-axis SC#10 mandate).

**Out of scope (CONSUMERS of this layer — deferred):** the `llm_judge` publish-quality gate (→ Phase 102), NL authoring reusing the seam (→ 103), grid/other emitters (→ 106), the receipt VIEW (→ 107), the broad run-legibility/latency work (its own phase — see Deferred).

**The red line (non-negotiable):** workflows COMPOSE the shipped harness; **Deep Mode stays byte-identical**; **all** per-provider forcing translation lives at the service boundary — the shared SSE/chunk path is NEVER branched; no `docxtpl` import in `backend/app/**` (render is sandbox-only, Pitfall 4); `threads.py` is NOT grown (G-5).
</domain>

<decisions>
## Implementation Decisions

### A. Core architecture (LOCKED — operator-ratified 2026-06-11)
- **D-01:** The deliverable step is a **SEALED FORCED EMIT**, never an open auto-tool-choice loop. The weakest mode (reasoning model + `tool_choice=auto` in an open loop) is the live root cause of the 0-docx failure (GAP-A) and is NEVER used for emission.
- **D-02:** **Emission and rendering are DECOUPLED.** The model emits **cited DATA only** (a structured object, every value tagged with its KB source). A **pinned deterministic driver in the sealed sandbox** renders the data into the file. **No model-written code touches the deliverable on any path** — this is held as a **milestone-level principle**.
- **D-03:** The old `weekly-report-writer` skill's *write-python-docx-code-into-execute_code* path is **explicitly NOT adopted** as the fallback. It is the proof the capability is real (it fills docx on ANY provider today) but it reopens SSTI / non-reproducibility / no-citation-gate — exactly what Phase 101 exists to prevent. It remains the **Deep-chat** answer; `render_template` owns **workflow mode**.
- **D-04:** `render_template` is **demoted** from a bespoke tool to the **first entry in a closed `EMITTER_REGISTRY`** (mirrors `PROGRAMMATIC_PHASE_REGISTRY` / `VALIDATOR_REGISTRY`). A new generic **`llm_emit`** phase type (6th in `PHASE_TYPE_REGISTRY`) is the ONLY path that produces a typed object. Adding a future deliverable = register one entry (schema + deterministic driver), never new engine code.

### B. Cross-provider forcing (LOCKED — grounded in provider-docs research, see canonical refs)
- **D-05:** **Capability-tiered forcing at the gateway service boundary only.** Three tiers (registry-driven, defaults **SAFE** — unknown ⇒ coerce, never assume force works):
  - **TIER-FORCE (6/8 native):** OpenAI (incl. reasoning), Google Gemini (`tool_config.function_calling_config.mode=ANY` + `allowed_function_names`), DeepSeek (incl. `deepseek-reasoner`), Z.ai/GLM, MiniMax, OpenRouter (with `provider.require_parameters=true`) → native `tool_choice=required`/named, plus strict `json_schema`/`responseSchema` where supported.
  - **TIER-FORCE-NOTHINK (Anthropic):** Anthropic **cannot force tool use OR structured output while extended thinking is ON** (it errors). So the emit call runs with **extended thinking DISABLED**; the 097 spike proved Anthropic non-thinking forced-emit holds attempt-1 with full citation coverage.
  - **TIER-COERCE (Moonshot/Kimi):** genuinely **unforceable** (no `required`, no named forcing; thinking further restricts to auto/none). Inject an explicit "you MUST call `<emitter>` now" directive, keep `tool_choice=auto`, then **hard-validate** `finish_reason`/`tool_calls` and retry/route — **never** fall back to model-written code.
- **D-06:** Wire **NATIVE-path narrated-JSON recovery + finish_reason guard.** Today recovery is STRUCTURED-mode-only and reasoning-natives resolve to `CallingMode.NATIVE` and bypass it (`agent_loop.py:1745` / `openai_service.py:~1274-1278`) → a narrated emission is **silently dropped**. After the fix, a still-narrated emission is **parsed back (fenced object matching the schema) or the run fails honestly** — never silently dropped.
- **D-07:** Provider-feature-fit routing: for the 104 flagship, **default emit-critical phases to a forceable provider**; treat Kimi/Moonshot as **best-effort** (honest gated failure over a code-emission fallback).

### C. The no-fail ladder (LOCKED — layered; no single mechanism covers all providers)
- **D-08:** Reliability is **6 stacked layers**, owned by the engine not the model: (1) **isolation** (single forced shot, outside the loop); (2) **tiered forcing** (D-05); (3) **NATIVE-path recovery** (D-06); (4) **schema validation** on every tier + truncation/cutoff rejects half-objects; (5) **bounded retry ≤3** re-prompting with the validation error (reuse `_run_phase_with_gates` feedback); (6) **honest failure** via `_surface_failure_message`/RC-4 with a receipt naming which gate refused. **Net definition of "no risk to fail": the deliverable is provably correct, or the run is provably failed with a reason — NEVER a silent 0-docx and NEVER a Markdown stand-in masquerading as the artifact.**

### D. Field-map shape (LOCKED — biggest single reliability lever)
- **D-09:** **FLATTEN GenericFieldMap:** shallow `scalars` dict + flat `list-of-rows`; **citation as a SIBLING field, not a per-leaf `Cited{}` wrapper**; `additionalProperties:false`; all-required-with-null-optionals (OpenAI/DeepSeek strict requirement); **no recursion / minLength / maxLength** (unsupported by Anthropic + DeepSeek strict). **Chunk very large maps into multiple forced emits.** Make it **additive/back-compatible or gated behind the new phase type** so existing 097/101 nested-cited artifacts still `model_validate()`. Re-touch the citation gate + docxtpl driver mapping as a scoped sub-task **with its own tests**.

### E. GAP-B / GAP-C (LOCKED)
- **D-10:** **GAP-B** closed by **server-side resolution of the bound library `assets[]` AssetRef**, injected into the emit tool args at **phase-build time** — the model NEVER selects the template (closes the fall-through to the ephemeral-upload branch where `asset_ref=None`).
- **D-11:** **GAP-C** closed by emitting **real emit sub-events** (`forcing → emitting → rendering → validating`) replacing the static "Step 0 · working…" box. Because an isolated single-shot emit **cannot stream tokens** (atomic answer), the emit moment gets its own honest discrete-step affordance. **Observable failure states must be distinguishable:** (a) model-failed-to-emit (narrated / no tool call, even after recovery); (b) citation-gate-rejected (uncited/invented); (c) render-failed; (d) integrity-failed (won't open / residual tokens); (e) no-template-bound. Each fails honestly with a receipt.

### F. Audit substrate (LOCKED)
- **D-12:** Every emit transition writes an **INSERT-only `harness_audit` row** keyed to `run_id` + `definition@version` (evidence set, tier used, raw field-map, gate verdict-with-evidence, integrity verdict, output file hash). Captured **now** because it is the literal substrate STRETCH Phase 107 (EU AI Act Art. 12 receipt) reads as a pure query later — bolting it on afterward would mean re-instrumenting the hot path.

### G. Authoring pattern (LOCKED — resolved detail)
- **D-13:** **The Anthropic two-step pattern is the canonical shape, not an exception.** Reasoning that the field-map needs happens in a **PRIOR** `llm_agent`/`llm_single` planning phase whose text feeds the `llm_emit` phase; the emit call itself is non-thinking + forced. This *improves* auditability (the reasoning is a separate inspectable phase output) and matches the natural plan-then-serialize shape on every provider. **Bake the two-step pattern into the 104 templates** so authors never hit it raw.

### H. Guardrails (decided routing)
- **D-14 (G-5 FIRES):** the forcing seam touches **`anthropic_service.py`**, already on the hot-file ledger as "adapter pattern audit due." **Plan-phase must decide** whether the per-provider forcing translation lands as part of an adapter audit/extraction or as a tightly-scoped additive seam. Either way: shared SSE/chunk path untouched + a **guard test that asserts no provider branch leaks into the shared path**.
- **D-15:** `MODEL_CAPABILITIES` gains `forced_emission` / `strict_json_schema` flags — **default SAFE** (unknown ⇒ TIER-COERCE) and **live-validated per provider** (the known zhipu/minimax case-sensitivity tool-drop trap means a wrong flag would silently downgrade a forceable provider).

Planner/researcher to choose, consistent with shipped patterns.

<specifics>
## Specific Ideas

- **The convergence signal:** three architecture proposals argued from *different* priorities (reliability-first / capability-first / audit-first) and **independently converged** on the same design (a 6th forced-emit phase type + emitter registry + capability-tiered gateway forcing + pinned driver downstream + honest failure + audit receipt). That convergence is the primary confidence signal for this CONTEXT.
- **The reframed "GAP-D":** the original fear ("structured emission is universally fragile") was **over-broad**. The real failure was running ALL providers in the *weakest* (auto, open-loop) mode. 6/8 providers force natively today; only Anthropic-under-thinking and Kimi/Moonshot are genuine problem children, each with a named escape hatch.
- **The single sentence:** Phase 101 moved the model's job from "write code into a universal always-callable tool" to "volunteer a large nested cited form into a conditionally-visible tool under an open loop" — and under-enforced both halves. 101.1 keeps the safe deterministic renderer but restores the model's *strongest act* (a forced single-shot emission) instead of the fragile one.
</specifics>
