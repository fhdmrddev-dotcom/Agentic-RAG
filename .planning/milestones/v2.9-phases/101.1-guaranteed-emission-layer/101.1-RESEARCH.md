## Summary

Phase 101 built a sound deterministic template-fill core (cited field-map shape → citation gate → sealed-sandbox render → integrity re-open → workspace persist) but wired the model's *production* of the field-map as an **open auto-tool-choice agent loop**. Reasoning-native models satisfy "fill" by narrating prose instead of committing the tool call; the bound library template was never handed to the tool. Result: 0 .docx live (GAP-A..D). 101.1 keeps the entire downstream UNCHANGED and replaces *only* the act of producing the field-map: a new `llm_emit` harness phase type runs a **sealed, single-shot, capability-tiered FORCED emission** through the existing provider gateway, recovers a still-narrated emission on the NATIVE path, validates/retries/fails-honestly, and writes an INSERT-only audit receipt.

The codebase is **exceptionally well-positioned** for this. The closed-registry pattern (`PROGRAMMATIC_PHASE_REGISTRY`) is the exact template for `EMITTER_REGISTRY`. The provider gateway (`provider_gateway/`, Phase 092.5) already routes all 3 native paths through one `open_stream(provider, GatewayRequest)` dispatcher whose request envelope **already carries a `tool_choice` field** — the cleanest possible home for tiered forcing, keeping `anthropic_service.py` growth to one parameter (decisive for the D-14 G-5 question). The `harness_audit` table already exists (migration 059) with INSERT-only RLS and a `write_audit()` helper. The retry-feedback producer/consumer (`_run_phase_with_gates`) and honest-failure surface (`_surface_failure_message`/RC-4) already exist for D-08 layers 5-6. The deterministic field-map core (`template_render_service.py`) already tolerates BOTH the nested-envelope AND a flat shape in `_iter_leaves`/`build_context`/`check_coverage`, which makes the D-09 flatten *additive and back-compatible by design*.

**Primary recommendation:** Land the tiered forcing as a **gateway-boundary seam** — add `forced_emission` handling driven off `GatewayRequest.tool_choice` in the 3 adapters (`provider_gateway/{anthropic,google,openai_compat}.py`), default-SAFE off two new `MODEL_CAPABILITIES` flags. Build `_exec_llm_emit` as a thin executor that calls a new `forced_emit` substrate (NOT the open agent loop), runs the EXISTING D-08 gates + retry + honest-failure, and writes the audit receipt. Flatten `GenericFieldMap` as an additive sibling model gated behind the `llm_emit` phase type. `anthropic_service.py` gains exactly one `stream_anthropic` parameter (`tool_choice` already a dict at :177) — no adapter extraction needed; the guard test asserts no provider branch leaks into the shared chunk/SSE path.

## 3. Flattened GenericFieldMap (D-09 — biggest reliability lever)

### Current shape (the per-leaf wrapper to replace)
`template_render_service.py:79` — `GenericFieldMap` nests `Cited` (`:65`) per leaf:
```python
class GenericFieldMap(BaseModel):
    scalars: dict[str, Cited] = Field(default_factory=dict)                 # nested Cited per scalar
    collections: dict[str, list[dict[str, Cited]]] = Field(default_factory=dict)  # nested Cited per cell
```
This nesting (a) confuses strict providers (deeply nested `$ref` objects), (b) uses an open `dict[str, ...]` (no `additionalProperties:false`), and (c) the dynamic key dict has no fixed required set — exactly what DeepSeek/OpenAI strict and Anthropic dislike.

### Proposed flattened, strict-friendly model (additive — `EmitFieldMap`, gated behind `llm_emit`)
```python
# NEW model — does NOT replace GenericFieldMap (097/101 nested artifacts still model_validate()).
class FlatScalar(BaseModel):
    model_config = ConfigDict(extra="forbid")          # additionalProperties:false
    key: str                                            # the placeholder name (was a dict key — now a field)
    value: str | None                                   # null = declined (D-03 honest decline)
    source_chunk_id: str | None                         # CITATION AS SIBLING, not a wrapper
    source_doc: str | None
    source_page: int | None

class FlatRow(BaseModel):
    model_config = ConfigDict(extra="forbid")
    collection: str                                     # which collection this row belongs to
    cells: list[FlatScalar]                             # each cell is a FlatScalar (key=column name)

class EmitFieldMap(BaseModel):
    model_config = ConfigDict(extra="forbid")
    scalars: list[FlatScalar]                           # FLAT list (not a dict) — stable, ordered, strict-friendly
    rows: list[FlatRow]                                 # FLAT list-of-rows
```
**Strict-schema rules honored (D-09):** `extra="forbid"` everywhere → `additionalProperties:false`; every field present + nullable (all-required-with-null-optionals); NO recursion (max depth = `EmitFieldMap → FlatRow → FlatScalar`, fixed 3); NO `minLength`/`maxLength`/`pattern` (unsupported by Anthropic + DeepSeek strict). Citation lives as `source_chunk_id` **sibling fields** on the SAME object as `value`, not a `Cited{}` wrapper.

### Back-compat (the free win)
`_iter_leaves` (`:148`), `check_coverage` (`:182`), and `build_context` (`:304`) ALREADY branch "generic-envelope shape OR flat spike-style shape." Add a THIRD branch for the flat-list shape (or normalize `EmitFieldMap` → the existing flat-dict shape before calling them). Because the model is NEW and gated behind the `llm_emit` phase type, **every existing nested-cited artifact (097 field-map.json, 101 fixtures) still `model_validate()`s against the OLD `GenericFieldMap` unchanged.** The scoped sub-task (D-09) = "add a normalizer `emit_field_map_to_legacy(EmitFieldMap) -> dict` + a third `_iter_leaves`/`build_context` branch + tests asserting (i) old nested artifacts still validate, (ii) the flat model maps to the SAME docxtpl context."

### Map to docxtpl driver + citation gate
- **Citation gate (`check_coverage`):** walks `(value, source_chunk_id)` per leaf. The flat model exposes both as siblings → the gate is *simpler*. Re-touch: feed `EmitFieldMap`'s leaves through `_iter_leaves`'s new branch; `invented_citation_count`/`uncited_value_count` semantics UNCHANGED.
- **docxtpl mapping (`build_context` → `render_docx_template`):** the docxtpl template references `{{ scalar.value }}` and `{% for r in rows %}{{ r.col.value }}{% endfor %}`. `build_context` must turn the flat lists back into the keyed dict the template expects (`{key: _cell(...)}` + `{collection: [{col: _cell(...)}]}`). The driver (`_RENDER_DRIVER_SRC` / `render_docx_template`) stays UNCHANGED downstream of `build_context`. **Add tests** that a flat `EmitFieldMap` renders the SAME bytes as the equivalent nested map (the WR-04 "two copies cannot drift" discipline).

### Chunking very large maps (D-09)
A register with hundreds of rows can exceed a forced emit's output budget (the 097 spike hit `stop_reason=max_tokens` at 4096 → raised to 16384). For very large maps: the emit substrate splits the collection into N forced emits (e.g. rows 1-50, 51-100), each its own forced call + truncation guard (`is_truncated`, `:253`), then concatenates `rows` before render. The truncation guard already rejects a half-object; chunking is the planned escape. **Plan note:** size the chunk by the per-model `max_output_tokens` (`config.py` registry) — a row's token cost × rows-per-chunk < budget.

## 7. Risks / Landmines / Pitfalls

### Pitfall 1: SSTI / model-written code on the deliverable (D-03, milestone-level line)
**What goes wrong:** a "helpful" fallback lets the model write python-docx code into `execute_code` (the old `weekly-report-writer` path), reopening SSTI + non-reproducibility + no citation gate.
**How to avoid:** D-02/D-03 — the emit step produces DATA only; the pinned driver renders. `select_engine` (`template_render_service.py`) hard-asserts `engine != "docxtpl"` for untrusted uploads (provenance boundary). **NO `docxtpl` import in `backend/app/**`** (Pitfall 4 — verified: heavy libs are function-local / sandbox-only). The guard: an untrusted (ephemeral) upload NEVER reaches the Jinja engine → SSTI structurally impossible.
**Warning sign:** any new top-level `import docxtpl` in `backend/app/`, or any code path that lets the model's text become a render command.

### Pitfall 2: `out_filename` injection (101-06 CR-01 history)
**What goes wrong:** model-controlled `out_filename` (prompt-injectable via untrusted doc content) interpolated into the sandbox shell command.
**How to avoid:** `_safe_out_filename` (`tool_dispatcher.py:1499`) already coerces to `^[A-Za-z0-9._ -]+\.(docx|pptx|xlsx)$` → SAFE default `deliverable.<ext>`; the command is built argv-safely with `shlex.quote`. **Reuse the existing hardened `_handle_render_template` handler verbatim** (don't re-implement the render command in the emit executor).

### Pitfall 3: truncation / cutoff producing half-objects
**What goes wrong:** a forced emit truncated at `max_tokens` silently drops `collections` (default_factory empties them) → a "valid" empty field-map → 0 rows.
**How to avoid:** `is_truncated` (`:253`) rejects `stop_reason=max_tokens` / `finish_reason=length` BEFORE accepting the emission (D-08 layer 4). Size `max_tokens` off the per-model registry cap; chunk large maps (§3). The 097 spike hit this exactly (4096 → 16384).

### Pitfall 4: residual-token / won't-open integrity (TMPL-03)
**What goes wrong:** a rendered file with surviving `{{token}}`s or that won't re-open is delivered as "done."
**How to avoid:** `assert_integrity` re-opens with the same library + scans residual tags; WR-03 folds `residual_clean` into the gate. The D-08 integrity gate (failure class 2) never persists a non-opening file; the cited field-map is preserved as fallback. UNCHANGED from Phase 101 — keep it.

### Pitfall 5: the open-loop weakest mode must be UNREACHABLE for emission (D-01, the GAP-A root cause)
**What goes wrong:** the emit step accidentally routes through `run_task_sub_agent` / the open agent loop (auto tool-choice) → reasoning models narrate → 0-docx (the exact GAP-A failure).
**How to avoid:** `_exec_llm_emit` does its OWN sealed forced single call (model `_stream_one_iteration`'s gateway drive, but `tool_choice=<forced>` + the D-06 recovery + the D-08 gates) — it MUST NOT call `run_task_sub_agent` (`task_service.py`) nor the Deep `run_agent_loop` (`agent_loop.py`). **Guard test:** `_exec_llm_emit` never invokes the bounded agent loop; the forced call's `tool_choice` is never `"auto"` on a TIER-FORCE provider.

### Pitfall 6: TIER-COERCE false-confidence (Kimi/Moonshot)
**What goes wrong:** treating a coerced provider as forced → accepting narration as success.
**How to avoid:** D-05 TIER-COERCE = directive + **hard-validate** `finish_reason`/`tool_calls` + retry/route; D-07 routes emit-critical phases to a forceable provider by default. Honest gated failure (state (a)) over a code-emission fallback. Relates to open bug `minimax-m3-invalid-tool-args-400` — confirm at plan-phase whether the hard-validate path subsumes it.

### Pitfall 7: case-sensitivity registry miss silently downgrading a forceable provider (D-15)
**What goes wrong:** a mis-cased model id (`minimax-m3` vs `MiniMax-M3`, `GLM-5.1` vs `glm-5.1`) misses the registry → wrong flag.
**How to avoid:** default-SAFE — `get_model_capability(id).get("forced_emission", False)` → a miss is TIER-COERCE (never wrongly assumes force). Live-validate per provider in UAT (§8). The inferred-defaults path (`config.py:378`) does NOT set `forced_emission` → safe.
