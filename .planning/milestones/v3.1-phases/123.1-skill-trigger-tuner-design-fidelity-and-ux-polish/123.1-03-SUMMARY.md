# Phase 123.1 Plan 03: Builder Picker from Configured Models Summary

**The Skill-builder model dropdown now lists the operator's configured per-provider models (strong models like Sonnet/Opus and GPT-pro selectable), grouped as optgroups, with a cheap Auto default kept pre-selected and a soft amber hint (never a block) on unverified models — the IN-02 placeholder local ids are gone.**

## Accomplishments
- Replaced the hardcoded cheap-only `SKILL_BUILDER_MODEL_OPTIONS` list with options derived from the user's configured `providers[].models` (the same source the chat picker uses), grouped per provider as `<optgroup>`s — strong configured models are now selectable (D-09).
- Removed the two IN-02 placeholder local ids (`lm-studio/qwen3`, `openai-compat/local-model`); local options now come from real providers (e.g. an Ollama provider's models).
- Preserved the `value=""` Auto default (pre-selected, not forced) and the custom-persisted-value `(current)` branch so a stored id never drops (D-10).
- Added a soft amber `unverified` hint next to the picker (mirrors the Active-Model chip) when the chosen builder model is absent from `verified_models` — it is a hint, never a hard block; no option carries a `disabled` attribute (D-10, A4).

## Files Created/Modified
- `frontend/src/pages/SettingsPage.tsx` — Deleted `SKILL_BUILDER_MODEL_OPTIONS` + its `BuilderModelKind` type (incl. the two IN-02 placeholders); added `builderModelGroups` / `builderConfiguredModels` derived from `providerStates`; rewrote the builder `<select>` to render configured models as per-provider optgroups with the Auto + custom-value branches kept; added the soft amber unverified hint; rewrote the no-SPOF footer to a provider-derived line.
- `frontend/src/pages/SettingsPage.test.tsx` — Extended to 7 tests against a multi-provider mock (strong cloud model + a real local Ollama provider): strong model listed + optgroup grouping, placeholders absent, local-from-provider, Auto default pre-selected, custom-value kept as `(current)`, soft hint renders + no disabled option, resolved default label.

## Decisions Made
- Builder options derive from `providerStates` across ALL providers (not just the active one). Provider group labels use `PROVIDER_META[id].label` with an `id` fallback; empty providers are filtered out so no empty optgroup renders.
- **A4 honored:** no new `forced_emission_models` contract field — the soft hint uses the existing `verified_models` signal, mirroring the Active-Model `unverified` chip exactly.
- The custom-persisted-value guard now checks a `builderConfiguredModels` Set (was `SKILL_BUILDER_MODEL_OPTIONS.some(...)`), so a stored id that IS configured doesn't double-render as a `(current)` duplicate.
- The no-SPOF footer's old cloud/local `kind` came from the deleted list; rewrote it to a provider-derived line (`{model} · your configured models · no single-point-of-failure`) — keeps the always-on reassurance without the removed data.

## Deviations from Plan

None - plan executed exactly as written.

This is a test-scoping detail, not a deviation from the planned behavior.
