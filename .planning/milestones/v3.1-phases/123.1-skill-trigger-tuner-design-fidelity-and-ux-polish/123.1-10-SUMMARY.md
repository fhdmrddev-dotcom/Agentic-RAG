# Phase 123.1 Plan 10: Silence LangSmith 429 Uploader Flood (TT-10) Summary

Silenced the LangSmith background-uploader's "Failed to multipart ingest runs: ... 429 Too Many Requests" WARNING flood to ERROR at module scope in `main.py` (next to the existing asyncio suppressor), and documented an optional commented-out `LANGSMITH_TRACING_SAMPLING_RATE` knob in `.env.example` — making the tuner backend log legible during a run without disabling tracing.

## What Was Built

Closes **TT-10** from the 123.1 live-UAT audit backlog (`123.1-AUDIT-BACKLOG.md` §2). During a tuner run (and any heavy LangSmith-traced run), once the monthly unique-trace quota is exceeded, the langsmith client's background ingest thread emits a repeating 429 retry WARNING that drowns the backend log — during the exact runs an operator needs to read. The audit confirmed this is NOT on the latency path (it does not compound tuner slowness — that is TT-06); it is purely a log-legibility problem.

Two surgical edits, the smallest correct fix per the backlog row:

1. **`backend/app/main.py`** — one line at module scope, directly beneath `logging.getLogger("asyncio").setLevel(logging.ERROR)`:
   ```python
   logging.getLogger("langsmith").setLevel(logging.ERROR)
   ```
   Preceded by a comment explaining WHY (background-uploader 429 retry noise, not the latency path; ERROR-and-above still surfaces real failures; scoped to langsmith only; points at the .env knob for source-side throttling). Reuses the `import logging` already present at line 2 — no new import. Placed at module scope so it applies before any langsmith client log, NOT inside a function or the lifespan handler. The asyncio suppressor and the `os.environ["LANGSMITH_*"]` wiring (lines 76-80) are untouched.

2. **`backend/.env.example`** — extended the LangSmith block (after `LANGSMITH_TRACING=true`) with a documented, commented-out `# LANGSMITH_TRACING_SAMPLING_RATE=0.1` plus a 5-line comment: it throttles the fraction of traces uploaded (0.0-1.0); set it below 1.0 if over the monthly unique-trace quota and seeing the 429 flood; the langsmith client reads it from the environment (load_dotenv populates os.environ) so no code change is needed. Kept commented out so default behavior (full tracing) is unchanged for installs that are not over quota.

## How It Works

- **The silence is reduce-only and scoped.** Raising the `langsmith` logger to ERROR REDUCES log volume; it never logs MORE. The repeating 429 WARNING is suppressed, but ERROR-and-above (auth failure, hard client error) still reaches the log. App, uvicorn, and asyncio logging are completely unaffected — the suppressor names exactly one logger.
- **Tracing is NOT disabled.** This only quiets the uploader's retry-noise WARNING; traces still upload (subject to quota). The optional sampling-rate knob is the operator's source-side lever to actually reduce upload volume if they are over quota.
- **The knob needs zero code.** `load_dotenv(...)` (main.py:15) populates `os.environ` from `backend/.env` before any module reads it, and the langsmith client reads `LANGSMITH_TRACING_SAMPLING_RATE` from `os.environ` at import. So an operator-set value in `.env` reaches the client with no Settings field and no code change — this plan only DOCUMENTS the knob.
