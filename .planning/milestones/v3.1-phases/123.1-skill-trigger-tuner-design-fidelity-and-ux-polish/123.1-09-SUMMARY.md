# Phase 123.1 Plan 09: Remove Decorative bg-sidebar Rails (TT-11) Summary

Removed the two decorative `w-16 shrink-0 bg-sidebar` rails — one in SkillsPage, one in SkillTunerPage — that rendered as a redundant grey second-sidebar dead band next to the real NavPanel, closing TT-11 from the 123.1 live-UAT audit backlog (§2).

## What Was Built

A purely presentational deletion confined to two page files:

- **SkillsPage.tsx** — removed the `{/* Pane 1: Decorative left ... */}` comment + the `<div className="w-16 shrink-0 bg-sidebar" />` rail (was lines 71-72). The center content pane is now the first child; it keeps its existing `px-8` and `border-r border-border/10`, so it sits flush against the real NavPanel.
- **SkillTunerPage.tsx** — the matching decorative rail had survived the 123.1-05 full-width restructure plus the 07/08 run-surface edits, relocated to lines 494-495. It was still present (NOT already removed by 05), so this plan removed it. The focused-surface header keeps its `px-8`.

The real NavPanel (`ChatLayout.tsx:289`) was explicitly untouched.

## How It Works

Each page body opened with `<div className="flex h-full overflow-hidden">` followed by a decorative `bg-sidebar` rail div as the first flex child, then the actual content column. Because `bg-sidebar` is the same token the real NavPanel uses, the rail read as a second sidebar. Deleting only the rail div lets the content column (which already carries `px-8`) become the first child and sit flush against the legitimate nav — spacing is unchanged, no other classes were altered.
