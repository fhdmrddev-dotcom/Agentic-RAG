# Phase 123.1 Plan 08: Tuner Run-Surface Honesty — Unmeasured Cell · Seeded Note · No-Flash · run_id-Gated Reconnect (TT-09/TT-12/TT-14/TT-16) Summary

**Closed the four run-resilience / honesty defects from the 123.1 live-UAT audit (backlog §2) so the run surface never lies or flashes: an all-error provider cell (measured:false / score:null from 123.1-06) now renders an honest "could not measure" row instead of a fabricated 0.00 / a 1.00 axis (TT-12 render half), backed by a widened nullable `TunerCell` type; a `getSeededCases` failure surfaces an inline non-fatal note + a `console.error` (no more silent `setCases([])` so the editor's "0 cases" / the cost-preview can't present a load failure as the measured truth — the "live docx 0 cases" symptom — TT-09); on completion the `LiveRunCard` stays MOUNTED through a new "reconciling" sub-state (frozen never-vanishes timer + "finishing — loading results…") and the scoreboard is not nulled while a durable latest result is shown, so the pane never flashes empty (TT-14); and reconnect exhaustion now polls the durable `getTunerLatest` and keeps an honest "still running" state ONLY when the durable row's `run_id` matches THIS run, while a genuinely-dead run (null/404 OR a previous run's row) still reaches the retained "Lost the live connection" hard-error terminal so it is never stuck forever (TT-16) — all frontend-only, confined to `api.ts` + `SkillTunerPage` + `LiveRunCard`(+new test) + `ProviderScoreboard`(+test), with NO backend / scoring core / `forced_emit` / `agent_loop` / `threads.py` / `anthropic_service` / `StreamsProvider` / `useMessages` change.**

## Accomplishments

- **Task 1 — honest unmeasured-cell render (TT-12 render half) + the nullable TunerCell sentinel (`api.ts`, `ProviderScoreboard.tsx`, `ProviderScoreboard.test.tsx`):**
  - **`api.ts` TunerCell type:** `axes: { fires: number | null; no_false: number | null }` and `score: number | null`, plus optional `measured?: boolean` / `error_count?: number` — mirrors EXACTLY what 123.1-06's `build_cell` returns (verified against `skill_tuner_service.py:513-523`: `axes.fires`/`no_false` are `_score_axis(...)` or `None`; `score` is the mean of measured axes or `None`; `measured` true iff ≥1 real decision; `error_count` the summed raise count). The optional fields keep a legacy/hand-built cell typeable.
  - **ProviderScoreboard unmeasured branch:** when `c.measured === false || c.score == null`, the row renders an honest muted "could not measure" state — provider·model column KEPT (so the author sees WHICH column failed), the score number / colored magnitude bar / fires+no-false sub-scores all REPLACED by the single label (plus an optional "(N calls failed)" from `error_count`), and a `data-testid="cell-unmeasured"` hook. A MEASURED cell renders exactly as before. `fmt`/`railTone`/`scoreTone` are never called with null (the unmeasured branch short-circuits; an individually-null axis renders "n/a" via a new `SubScore` component).
  - **Non-vacuous test:** a measured cell + an unmeasured cell render DIFFERENTLY — the measured cell shows its number + bar + sub-scores; the unmeasured cell shows "could not measure" (via `cell-unmeasured`) and renders NO `cell-score` / `scoreboard-bar` / `cell-fires` / `cell-no-false`, keeps provider·model, and surfaces the failure count. A second test asserts a single null axis renders "n/a" on an otherwise-measured cell.
- **Task 2 — honest seeded note (TT-09) + reconciling no-flash (TT-14) + durable-poll reconnect with run_id gate (TT-16) (`SkillTunerPage.tsx`, `LiveRunCard.tsx`, `LiveRunCard.test.tsx`):**
  - **TT-09:** a `seededError: string | null` state. The mount effect's `getSeededCases` `.catch` now `console.error("tuner: getSeededCases failed", err)` + `setSeededError("Couldn't load the seeded benchmark cases — add cases manually, or run to auto-seed.")` (cleared on the success branch). An inline muted amber `seeded-error-note` (`role="status"`, NOT a toast / error boundary) renders below the CaseEditor; the cost-preview appends "(seed load failed)" when `seededError` is set AND `cases.length === 0` — zero is never presented as the measured truth. `getSeededCases` in `api.ts` is untouched.
  - **TT-14:** `RunPhase` gains `"reconciling"`. `startRun` no longer nulls the scoreboard when a durable `latestRun` is shown (`if (!latestRun) setScoreboard(null)`; `latestRun` added to the deps). The non-error 'done' terminal sets `runPhase="reconciling"` and keeps rendering `LiveRunCard` (now `phase="reconciling"`, an honest "finishing — loading results…" footer, frozen timer) until `getTunerResults` resolves, THEN drops to `"done"` (and to `"done"` on a results-read failure too, keeping the SSE-carried scoreboard — never a flash, never a false error for a finished run). The results-block + LiveRunCard mount conditions use a derived `runActive = running || reconciling`.
  - **TT-16:** in the reconnect-exhaustion branch (`reconnectsRef >= MAX_RECONNECTS`), the UI now polls `getTunerLatest(skillId)` instead of immediately flipping red. It keeps `runPhase="running"` + an honest `runBackgroundNote` ("Still running — this is taking a while…") ONLY when `latest && latest.run_id === runIdForStream` (THIS run persisted a durable row; the scoreboard/latestRun rehydrate, no red error). A `null`/404 return OR a row whose `run_id !== runIdForStream` (a PREVIOUS run's durable row) OR the poll itself throwing → the RETAINED `setRunPhase("error")` + "Lost the live connection to the tuning run. Reopen this skill to load the finished scoreboard." So a persisting run is never falsely failed, a previous run's row never masks a dead current run, and a genuinely-dead/unprovable run STILL reaches an honest terminal (never stuck).
  - **LiveRunCard:** `phase` widened to `"running" | "reconciling" | "error"`; a `live-run-reconciling` footer ("finishing — loading results…", not the red error / not the idle line); Cancel hidden while reconciling/error (rendered only when `phase==="running"`); the never-vanishes timer preserved (freezes when `phase !== "running"`). New `LiveRunCard.test.tsx` pins all three phase footers, the frozen-but-mounted reconciling card with NO Cancel + NO alert, the queued≠running lane vocabulary, and Cancel firing onCancel while running.
