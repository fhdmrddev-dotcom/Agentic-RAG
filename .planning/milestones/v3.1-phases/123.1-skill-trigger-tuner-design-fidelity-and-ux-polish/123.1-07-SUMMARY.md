# Phase 123.1 Plan 07: Tuner Run UX — Honest Progress + a Real Cancel (TT-07/TT-08) Summary

**Closed the two run-UX defects from the 123.1 live-UAT audit (backlog §2): the live run now shows honest per-provider progress (a `tuner_progress` event with `stage="provider_start"` carrying provider/model is emitted at each column START via the tuner's own `_emit_tuner`, and the frontend flips the matching lane `queued -> running` on it — lanes no longer sit "queued" for the whole run then jump to "done" — TT-07); and Cancel is REAL (a `DELETE .../tuner/runs/{run_id}` route gated by owner-verify THEN run<->skill bind sets a TTL'd `tuner_cancel:{run_id}` flag + releases the `tuner_inflight` claim immediately, the job checks the flag at the candidate AND provider loop tops and stops without persisting a partial scoreboard while still running its finally cleanup, and the frontend awaits the DELETE before going idle — TT-08), all confined to the tuner route + test + api.ts + SkillTunerPage with the shared runs.py consumer, scoring core, and chat surface untouched.**

## Accomplishments

- **Task 1 (TDD) — provider_start emit + cancel route + job checkpoint (`skill_tuner.py`):**
  - **TT-07 (provider_start):** inside `_run_tuner_job`, at the START of each `for target in targets` iteration (after the `if not model: continue` skip, before the per-case loop), the job now `await _emit_tuner(redis, run_id, EVENT_PROGRESS, stage="provider_start", candidate_index=cand_idx, provider=provider, model=model)`. This rides the tuner's OWN `_emit_tuner` to `run:{run_id}` (NOT the shared runs.py consumer — the TT-06 heartbeat is Wave C). The existing `tuner_provider_done` emit is unchanged.
  - **TT-08 (cancel flag + checkpoint):** a module-level `_cancel_key(run_id) -> f"tuner_cancel:{run_id}"` helper near `_inflight_key`. The job reads `await redis.get(_cancel_key(run_id))` at the TOP of the candidate loop AND the provider loop (one redis.get per loop iteration, not per case); on a truthy flag it sets a shared `cancelled` flag and breaks. A cancel observed in the provider loop breaks the candidate loop too (`if cancelled: break` after the provider loop) so a partial candidate is never appended. After the loops, an `if cancelled:` early-return skips the winner pick + the Redis stash + the D-07 durable upsert, emits `TERMINAL_ERROR(error="cancelled")`, and falls through to the existing `finally` (claim release + runs:active / per-skill ZREM).
  - **TT-08 (the DELETE route):** `@router.delete("/{skill_id}/tuner/runs/{run_id}") async def cancel_tuner_run(...)`. Load-bearing check order (mirrors CR-01): (1) `_fetch_owned_or_global_skill` — 404 on cross-user / non-global BEFORE any flag is set; (2) run<->skill bind — `redis.zscore(runs_by_thread:tuner:{skill_id}, run_id) is None -> 404` (refuse a foreign/leaked run_id even for a visible skill). Only AFTER both gates: `redis.set(_cancel_key(run_id), "1", ex=_TUNER_BUFFER_TTL_S)` + `redis.delete(_inflight_key(skill_id))` + `_INFLIGHT_SKILLS.discard(skill_id)`. Returns `{"cancelled": True, "run_id": str(run_id)}` (200).
  - **5 non-vacuous tests:** the provider_start emit-before-provider_done ordering test (asserts a provider_start for each measured column AND that its index precedes the column's tuner_provider_done); cross-user cancel 404 (+ no flag set); foreign-run-id cancel 404 (+ no flag, + the unrelated claim NOT released); happy-path cancel 2xx (+ flag set, + claim released); and the checkpoint early-stop test (a pre-set flag yields FEWER classify calls than a baseline run, NO durable upsert, AND the finally still cleared the claim + ZREM'd runs:active).
- **Task 2 — frontend cancel wrapper + lane flip + awaited cancel (`api.ts`, `SkillTunerPage.tsx`):**
  - `api.ts`: `cancelTunerRun(skillId, runId)` DELETE wrapper mirroring `startTunerRun`'s auth+fetch shape; best-effort (throws `ApiError` on a non-ok so the caller CAN log it). ONLY `cancelTunerRun` added — `TunerCell` is untouched (123.1-08's scope).
  - `SkillTunerPage.tsx`: `onProgress` gets a `data.stage === "provider_start"` branch that flips the matching `(provider[,model])` lane `queued -> running` (the legacy provider-presence branch is kept, idempotent). `cancelRun` is now `async` and `await`s `cancelTunerRun(skillId, runId)` (guarded on `skillId && runId`) in a try/catch BEFORE `setRunPhase("idle")`, still aborting the local SSE and still going idle on a failed DELETE. Dependency array now `[skillId, runId]`.
