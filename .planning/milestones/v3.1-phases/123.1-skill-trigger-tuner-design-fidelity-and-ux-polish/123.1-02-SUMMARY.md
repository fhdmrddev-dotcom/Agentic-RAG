## Decisions Made

- **Plan interface snippet vs. actual wire type:** The plan's `<interfaces>` listed `TunerCell { fires; no_false; score; ... }` as flat fields, but the shipped `TunerCell` (api.ts:2666) nests the sub-scores under `axes: { fires, no_false }` with `score` flat. Drove the bar/number from the flat `cell.score` (as the plan intended) and read the sub-scores from `cell.axes.*` (as the code requires). No behavior change vs. plan intent.
- **Test file location:** The CandidateCard tests previously lived inside `ProviderScoreboard.test.tsx`. The plan lists `CandidateCard.test.tsx` as a file_modified and Task 2's verify is `npm test -- CandidateCard`, so the tests were moved into a dedicated `CandidateCard.test.tsx` (and the now-unused `vi`/`userEvent`/`CandidateCard` imports were dropped from `ProviderScoreboard.test.tsx`).
- **Grep acceptance nuance:** `grep -c "line-clamp"` returns 1 because the clamp is held in a single `clampClass` constant reused across 3 elements; the ≥1 bar is met and the passing tests assert the class on all three testids. `grep -c "repeat("` is 0 in code (the only `repeat(N,1fr)` mentions were reworded out of comments).
