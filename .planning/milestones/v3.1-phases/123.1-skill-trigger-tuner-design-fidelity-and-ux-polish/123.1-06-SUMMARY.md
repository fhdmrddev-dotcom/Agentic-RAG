# Phase 123.1 Plan 06: Tuner Scoreboard Honesty (TT-05/TT-12/TT-15) Summary

**Closed three backend honesty defects from the 123.1 live-UAT audit: an empty should-fire/should-NOT axis now renders as the unmeasured sentinel None (frontend "n/a") instead of a fabricated 1.00 recall (TT-05); an all-error provider column (every classify call raised) is marked measured=False and EXCLUDED from the persisted target_count / "measured on N models" attribution (TT-12); and cell_score returns the single stored cell["score"] verbatim so it can never drift from what build_cell computed (TT-15) — all backend-only, with the held-out math, the gateway, and the frontend untouched.**

## Accomplishments

- **Task 1 (TDD) — honest empty axis + per-cell error accounting + single-source cell_score (`skill_tuner_service.py`):**
  - **TT-05:** `build_cell` now renders an axis with NO aggregated decisions as the unmeasured sentinel `None` (the frontend shows "n/a"), never `_score_axis`'s vacuous `1.0`. The combined `score` is the mean of the MEASURED axes only — both measured -> mean; exactly one -> that one; neither -> `None` (wholly unmeasured). `None` (no cases of that class) is documented as DISTINCT from a measured `0.0` (the model genuinely scored badly). `_score_axis` itself is unchanged (its 1.0-empty floor is correct for the internal held-out math).
  - **TT-12:** two new optional params `fire_error_count` / `no_false_error_count` (counts of classify calls that RAISED per axis). The cell now carries `measured` (True iff at least one real aggregated decision landed) and `error_count` (the summed raise count). An all-error column has BOTH decision lists empty AND `error_count > 0` -> `measured=False`, distinct from a measured `0.0`.
  - **TT-15:** `cell_score` returns `cell["score"]` verbatim when the key is present (no recompute that could drift), with the `(fires+no_false)/2` recompute kept ONLY as a legacy fallback for cells lacking a stored score (a None axis treated as 0.0 there).
- **Task 2 (TDD) — count only MEASURED cells in target_count + thread error counts (`skill_tuner.py`):**
  - The `_run_tuner_job` repeat loop now distinguishes a classify EXCEPTION from a real "did-not-fire": a held-out case whose EVERY repeat raised increments the per-axis error count and is NOT appended to the decision list (so an all-error column ends with empty lists + a positive error_count). A PARTIALLY-failing case keeps the existing honest-fail floor (a failed repeat counts as did-not-fire in the majority vote) — robustness preserved.
  - The per-axis error counts are threaded into `build_cell`, so every cell carries `measured` + `error_count`.
  - The persisted `target_count` is now the count of DISTINCT MEASURED `(provider, model)` columns across the run's cells (was `len(targets)`), so an all-error column is excluded from the durable "measured on N models" attribution.
  - `held_out_score` now skips `None` (unmeasured) cell scores, falling back to `0.0` only when NO cell measured — never crashing on a None score.

## Deviations from Plan

None — plan executed exactly as written. Both tasks built to spec. The plan's acceptance criterion referenced `grep -n "cell.get(\"score\""` for the single-source read; the implementation uses the equivalent `if "score" in cell:` idiom, which is STRONGER for the requirement — it returns the stored value verbatim INCLUDING `None` (a `cell.get("score", recompute)` default would silently mask a missing key but not a stored None, and would not let None propagate to the held-out-mean skip). The intent (single source of truth, no second computation) is fully met and proven by `test_cell_score_returns_stored_value_verbatim` (stored 0.42 vs recompute 1.0).
