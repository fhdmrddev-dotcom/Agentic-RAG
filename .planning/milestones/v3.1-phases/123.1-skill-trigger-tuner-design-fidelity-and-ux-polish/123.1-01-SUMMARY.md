## Decisions Made
- **Latest-wins, one row per skill:** `on_conflict="skill_id"` overwrites (UNIQUE(skill_id)); a re-run never accumulates. `user_id` is the last-runner attribution (documented in the migration table comment for the global-skill T-123.1-05 accept).
- **New provenance fn, not a rewrite:** `seed_cases_with_provenance` wraps the unchanged string-only `auto_seed_cases`, so the `_run_tuner_job` run-path seed contract is byte-identical (no break).
- **Route registration order is load-bearing:** `/runs/latest` is declared before `/runs/{run_id}` (UUID-typed) so the literal matches; otherwise `"latest"` would 422 against the UUID converter.
- **Durable upsert is best-effort:** D-07 persistence never gates the run — `try/except` + `run_in_threadpool` means the Redis stash still serves the per-run-id GET if the DB write fails.

## Issues Encountered
- **Route collision risk (resolved as planned):** the literal `/runs/latest` could have been shadowed by the UUID-typed `/runs/{run_id}` route. Resolved by declaring the `latest` route BEFORE the `{run_id}` route (FastAPI matches in registration order; a UUID converter rejects `"latest"` with 422 rather than falling through). Verified by `test_get_latest_global_skill_visible` / `test_latest_result_persists_after_run` returning 200.
- **`"held"` grep nuance:** the acceptance grep `grep -c '"held"'` returns 2 in the service file, but both occurrences are in the explanatory docstring/comment stating `"held"` is NEVER authored. The actual return values use only `PROVENANCE_SEEDED`/`PROVENANCE_SIBLING`; `test_seeded_cases_returned` asserts `"held" not in all_provenances` and passes — the intent of the criterion is satisfied.
