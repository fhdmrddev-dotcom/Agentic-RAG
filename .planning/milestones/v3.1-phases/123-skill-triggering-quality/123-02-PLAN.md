<objective>
Deliver CTX-03: a loaded skill's instructions stay available for the rest of the session instead of silently rolling out of the trim window. This is a surgical, single-function change to the G-5-hot `trim_messages_to_fit()` — adding a THIRD protected class (pinned `load_skill` tool-result groups) alongside the system message and the `reserve_recent` tail. The pin flag is set in code in `_reconstruct_history` (identified by the parent tool_call name being `load_skill`), never by sniffing the tool-result JSON. De-dupe on reload, cap total pinned at 1/3 of the resolved context budget, evict the least-recently-loaded pinned skill on overflow, and emit the honest `_TRIM_MARKER` on any eviction.

Purpose: A loaded skill that silently disappears mid-session is the exact CTX-03 failure; pinning every loaded skill with a safety valve fixes it without starving the recent-message budget (Pitfall 5).
Output: the extended `trim_messages_to_fit()`, the `_reconstruct_history` tag, and extended `test_context_window.py` coverage (the trim-pin behaviors AND the _reconstruct_history tag test — ALL in this one existing file).
RED LINE (D-14 / G-5): NO fork of the trim path. ONE new protected class inside the existing function. Re-run the full `test_context_window.py` + subagent-truncation suite after the change.
