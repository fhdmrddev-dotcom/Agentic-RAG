## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /skills/{id}/tuner/runs | An authenticated user requests a tuning run for a skill id |
| tuner route → skills table | The route must only operate on the caller's own/global skills |
| background task → N provider APIs | Multi-minute live LLM fan-out — resource/cost surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-123-04-01 | Information Disclosure / Elevation | A user starts/streams/reads a tuning run for another user's non-global skill | mitigate | Every route owner-scopes via `.eq("user_id", current_user["id"])` (write) / `.or_(...own,global)` (read), 404 otherwise; get_supabase() is service-role so app-code scoping is the SOLE gate. The cross-user-404 integration test is the load-bearing proof. |
| T-123-04-02 | Denial of Service | The background run (cases × N targets × 3 repeats × ≤5 iter live LLM calls) exhausts resources/cost | mitigate | Bound the run: cap cases, cap N targets, cap iterations ≤5, per-call timeout (llm_call_timeout_seconds), ONE job per skill (no unbounded fan-out). The bound integration test asserts the cap. |
| T-123-04-03 | Tampering | Overloading chat SSE event types with tuner progress confuses the chat consumer | mitigate | Tuner-specific event vocabulary (tuner_progress/tuner_provider_done/tuner_complete) on the same run-buffer transport; grep gate confirms no chat event types emitted (Open-Q4). |
| T-123-04-04 | Information Disclosure | Run state persisted cross-user | mitigate | Benchmark cases are ephemeral/client-held (A2); only the winning description persists later via the owner-scoped PATCH; the run-buffer key carries no other user's data. |
| T-123-04-SC | Tampering | npm/pip installs | accept | No packages installed this plan (zero new deps per RESEARCH). |
