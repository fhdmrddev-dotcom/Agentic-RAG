<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Deep/Harness run → sandbox container (`/sandbox/output/`) | The harvest reads files from the thread's own Docker container; a stale file from a prior run is untrusted-for-emit (it is not THIS run's output). |
| Sandbox session → thread scope | The session comes from `sandbox_manager.get_or_create(thread_id)` — already per-thread keyed; the snapshot must read ONLY this thread's container. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-120-01 | Information Disclosure | `snapshot_output_baseline` reading another thread's / user's container | mitigate | Seed reads `sandbox_manager.get_or_create(ctx.thread_id)` — the SAME thread-keyed container the run already uses (no new attack surface; sessions are per-thread cached). Acceptance: the seed call passes the run's existing `session`, never a foreign thread_id. |
| T-120-02 | Information Disclosure (cross-run leak — the core bug) | Harvest re-emitting a prior workflow's leftover into a Deep skill turn | mitigate | Run-scoped baseline seed excludes any file present at run start by SHA-256 hash; headline test `test_stale_workflow_file_excluded_from_skill_emit` proves exactly-one-file emit. |
| T-120-03 | Denial of Service | Snapshot container I/O blocking the event loop / failing the run | accept→mitigate | `run_in_threadpool` (never blocks the loop, D-v2.5-01); the helper is fully try/except-wrapped → empty/failure returns `{}` = today's behavior, never raises into the run. |
| T-120-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (stdlib hashlib/os/tempfile + existing pinned stack only — RESEARCH Package Legitimacy Audit: N/A). |
</threat_model>
