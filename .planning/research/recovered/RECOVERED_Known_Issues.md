# Known Issues## KI-001: In-flight LLM calls and tool executions continue after SSE disconnect**Status:** Deferred  **Date:** 2026-04-23  **Related Phase:** 44 (SSE Stop Reliability)### DescriptionWhen a user clicks the Stop button during a streaming response, the SSE connection closes and the `_SilentSSEIterator` stops iteration immediately via a shared `asyncio.Event`. This prevents the agent loop from starting new iterations or tool calls after the disconnect. However, any **in-flight LLM call** (`create_streaming_chat`) or **in-flight tool execution** that is currently blocking the generator cannot be interrupted ÔÇö it runs to completion on the server before `GeneratorExit` can be thrown into the generator.This affects ALL long-running operations inside `event_stream()`, not just sub-agents:- Main LLM streaming calls (`create_streaming_chat`)- Tool executions (search_documents, analyze_document, execute_code, etc.)- Sub-agent LLM calls (`run_sub_agent`)- Suggestion generation### Root CausePython async generators can only receive `GeneratorExit` at `yield` points. The `event_stream()` generator is structured as:```pythonfor iteration in range(max_iterations):    stream = create_streaming_chat(...)     # blocks until LLM completes    for chunk in stream:                     # yields between chunks        yield f"data: ..."                   # ÔåÉ GeneratorExit can only arrive here    # tool execution...    result = search_documents(...)           # blocks until DB query completes    yield f"data: ..."                       # ÔåÉ or here between tools```When `stop_event` is set by `_safe_send`, `_SilentSSEIterator.__anext__` returns `StopAsyncIteration` on the next call. But the current `await self._gen.__anext__()` won't return until the generator reaches its next `yield`. If it's inside `create_streaming_chat()` (a sync OpenAI streaming call), the entire LLM response completes before the generator yields again.### What Currently Works (Phase 44)- Frontend Stop button marks the message as `stopped` with "Response stopped" indicator- Running tool calls are marked as `interrupted` with amber square icons- Only completed tool calls (`status=done`) are persisted to the database- `_SilentSSEIterator` stops iteration immediately once the in-flight yield returns ÔÇö prevents starting NEW iterations or tool calls- `SSEStreamingResponse` suppresses transport errors ÔÇö no noisy stack traces in logs- Backend `finally` block runs and persists accumulated content### What Doesn't Work- An in-flight LLM call (`create_streaming_chat`) or tool execution continues until it reaches the next `yield` in the generator- The OpenAI Python SDK's sync `client.chat.completions.create(stream=True)` call cannot be interrupted by `asyncio` ÔÇö it runs synchronously in the event loop thread- `run_sub_agent` uses the sync OpenAI client, compounding the issue for analyze_document### Potential Solutions (for future investigation)1. **Convert OpenAI calls to async** ÔÇö Use `AsyncOpenAI` client so `asyncio.CancelledError` propagates through `await` cancellation points in the streaming loop. This would let `aclose()` cancel in-flight LLM calls.2. **Pass a cancellation event into the generator** ÔÇö Thread an `asyncio.Event` through `event_stream()` that's checked between LLM streaming chunks and tool dispatches. Set it from `SSEStreamingResponse` on disconnect. This is the simplest approach:   ```python   # In SSEStreamingResponse.__call__:   self.body_iterator._stop_event = stop_event  # already done      # In event_stream():   for chunk in stream:       if stop_event.is_set():           return       yield ...   ```3. **Convert `run_sub_agent` to async** ÔÇö Same as #1 but specifically for the sub-agent:   ```python   async def run_sub_agent_async(content, filename, task, *, cancel_event=None):       client = AsyncOpenAI(...)       stream = await client.chat.completions.create(stream=True, ...)       async for chunk in stream:           if cancel_event and cancel_event.is_set():               break           yield chunk.choices[0].delta.content or ""   ```4. **Run sync calls in `asyncio.to_thread` with cancellation** ÔÇö Wrap blocking calls in `asyncio.to_thread()` and use `asyncio.wait_for(timeout)` or `asyncio.shield` patterns to enable cancellation.### Recommended ApproachCombine #2 and #3:- Pass `stop_event` into the `event_stream()` generator via closure or parameter- Check `stop_event.is_set()` at each iteration boundary and between LLM streaming chunks- Convert `run_sub_agent` to async (`run_sub_agent_async`) so `asyncio.CancelledError` can propagate- This provides immediate cancellation at iteration boundaries and between streaming chunks while keeping the implementation simple
