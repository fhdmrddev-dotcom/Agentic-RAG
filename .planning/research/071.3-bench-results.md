### Failure root cause — gmft + transformers 5.7.0 + huggingface_hub 1.13.0

gmft 0.4.3 instantiates `TableTransformerForObjectDetection.from_pretrained(...)` from microsoft/table-transformer-detection. Loading that pretrained config goes through `transformers.configuration_utils.PretrainedConfig.__init__` which (in transformers >=5.x) uses `huggingface_hub.dataclasses` strict-validation. The TATR model's published config has `dilation=None`, but the strict dataclass field is declared `bool`, so validation rejects it before the model can be constructed.

This is a known-issue-class problem: gmft pins `transformers>=4.35.2` with no upper bound. Installing per `bench_requirements.txt` pulled `transformers==5.7.0` + `huggingface_hub==1.13.0` (both very recent majors), and gmft's lazy detector init crashes on the first call.

Implications for Plan 02 if gmft were chosen as winner:
- Production would need a transformers upper-bound pin (`transformers<5`) in `backend/requirements.txt`, increasing dep-discipline burden.
- Or wait for gmft 0.4.4+ which fixes the model-config validation path (no patch on PyPI as of 2026-05-16).
- Or pin the TATR model to an older revision via `from_pretrained(..., revision=<sha>)` — fragile.

Per `feedback_docling_skepticism` and `project_docling_quality_unproven` memory entries, the user has lost confidence in tooling that "repeatedly breaks the fast/light system." gmft's brittle dep chain (torch CPU + transformers + huggingface_hub strict-dataclass) is materially worse than Docling's, and the lazy-download UX (~120 MB on first call) adds another fragility surface. Net: gmft is high-risk to ship as default even if the bench succeeded.

**Bench limitation acknowledged:** because gmft failed at init, we have NO recall number for it on either fixture. Per D-071.3-03 (ship best-available) the decision can proceed with pymupdf + camelot data alone — but a future re-bench with an older transformers (e.g. `pip install "transformers<5"`) would be needed if the user wants gmft numbers before declaring the winner.
