How it works

Upload. Ask. Get the file.

01

Upload your knowledge

PDF, Word, Excel, PowerPoint, CSV, images, Outlook email. Tables and figures are extracted, metadata is read with a confidence you can see, and documents are auto-classified into folders and saved views.

02

Ask in plain language

The agent decides what to do — search, calculate, draft, build — and shows each step live as it happens. Every claim it makes from your documents carries a numbered citation back to the page.

03

Get a real deliverable

Spreadsheets, charts, Word and PowerPoint files, PDFs — built by real code in an isolated sandbox and dropped into your workspace files. If it needs to send, post or write anywhere outside, it asks you first.

Everything inside

One workspace, not six subscriptions.

Chat, knowledge base, sandbox, workflow studio, connectors, skills and an operator control room — sharing one set of documents and one set of permissions.

Hybrid search with citations

Semantic plus keyword retrieval with reranking. Numbered markers in the answer link to the exact document and page.

Sandboxed code execution

Python in an isolated container with pandas, matplotlib, openpyxl, python-docx, python-pptx, reportlab and more preinstalled.

Real output files

XLSX, DOCX, PPTX, PDF, PNG charts — previewed in the workspace panel, versioned, downloadable. Fill your own templates.

Human checkpoints

Any outbound action — email, Slack, calendar, file write — pauses with a NEEDS YOU card. Approve, edit the draft, or refuse.

Workflow Studio

Describe recurring work in a sentence or build step-by-step on a canvas. Per-step model, sources, checks and approvals.

Publish gauntlet

Ten checks including a real golden run against your knowledge base and an independent judge model. Fails are worded, not coded.

Schedules and run history

Run on a cron, on demand from chat, or from the library. Every run keeps its receipt — what ran, what it produced, where it paused.

Graded governance

Per step: must it cite? From which folders only? Strict grounding can be locked — and only the person who locked it can undo it.

Teachable skills

Teach it a procedure once; it persists as a versioned skill with its own evals, triggers and a studio to tune when it fires.

Connectors

Google Workspace, Slack, GitHub, Notion, Microsoft 365, Jira, email, or any MCP server — granted per workflow, per action.

Library and knowledge health

Folders, saved views, relationships between documents, and a health tab that shows what retrieval could not find.

Operator control room

Live runs with a kill switch, dependency health, an audit ledger of every write, users and feature visibility per audience.

Skills

Teach it once. It keeps the procedure, versions it, and knows when to use it.

A skill is a written procedure plus optional files and scripts. The agent can create one from a conversation, load one when the request matches, and you can evaluate, tune and version each one in the Skill Studio.

USE IT FOR

“How we quote a roofing job” — the takeoff procedure, the rate sheet, the rounding rules.
“Weekly KPI pull” — the exact SQL-like table queries and the chart style.
A shared org skill everyone’s agent uses, published only after its evals pass.

Control Room

The operator’s seat: what is running, what is healthy, what is switched off.

Five tabs behind an operator role: Control Plane, Users & Access, Model Registry, Secrets, Audit log. Every destructive action is guarded in proportion to its blast radius — a victim-naming sheet, an arm-to-confirm, or a direct flip — and every one leaves a receipt.

USE IT FOR
Kill a runaway run without restarting anything.
Turn off outbound connectors org-wide during an incident, with one guarded switch.
Register a new model and set what it can do before anyone selects it.
Answer “who changed that setting?” from the ledger, with a CSV for the auditor.
Control PlanePinned vitals: dependency health (database, Redis, sandbox, providers), active runs with Kill, a kill-switch grid, and spatially separated maintenance actions.
Users & AccessRoster across orgs, disable with victim-naming, flagged operator grants, feature visibility per audience.
Model RegistryEvery model with provider, capabilities (native tools, structured output, vision, context window) and the emission tier that governs tool-call reliability.
SecretsProvider keys and integration secrets, write-only, with rotation receipts.
Audit logTwo ledgers — operator actions and system writes — chip filters and a recorded CSV export.
Technical-names revealOne toggle swaps friendly labels for the identifiers engineers need, everywhere in the room.
Feature visibilityAn API-enforced audience map: what each role sees, with an extensible-audience contract for new roles.
ObservabilityLangSmith tracing on every model call; workers, run buffers and Realtime reconciled by fetch, never trusted blindly.

Workflow Studio

Automation that has to prove itself before it runs for you.

Two doors, same destination: describe the work and let the AI draft the steps, or open the editor and set each step yourself — what it must cite, which checks have to pass, and which model runs each step. Either way it cannot publish until every check below goes green.

Per-step model. Cheap model for extraction, strongest for judgment, local for anything that must not leave the network.
Per-step grounding. Which folders it may read, whether it must cite, whether a human must review before the next step.
Declared inputs. Ask for a date range or a customer name at launch — from chat, from the library, or on a schedule.
Templates. Hand it your own Word or PowerPoint template and it fills it, rather than inventing a layout.
