A — Focused full-surface (the Tuner precedent, 041-A)

The skill's detail panel keeps ONLY the edit form + a one-line eval summary. "Open evals" swaps the whole working area for a dedicated Skill Evals studio — ‹ Skills returns. Cases + versions get a real left column; runs + the side-by-side detail get the full main column. This is exactly how the Trigger Tuner resolved the same 384px wall.

Try it: click Open evals in the right panel, then click a run row in the studio. The side-by-side WITH / WITHOUT arms only fit because the studio owns the full width.

B — In-panel stacked accordion (the workspace-panel pattern, 004-B / 027-A)

Everything stays in the 384px detail panel, but reorganized: the edit form collapses to one section instead of dominating, and Status / Test cases / Runs / Versions become accordion sections. Opening a run does a full-replace drill-in (005-A) inside the panel — WITH / WITHOUT arms stack vertically because the column is narrow.

Try it: expand/collapse the sections, then open the first run under Runs — the drill-in replaces the panel body with ‹ Back. Ask yourself: does the stacked WITH/WITHOUT comparison still feel like a comparison?

C — Expand-to-wide panel (the Documents rail-collapse precedent, 032-A)

The panel keeps a compact eval summary. "Open evals ⤢" widens the panel to ~85% — the skill list collapses to a thin icon rail (the same move the Documents page makes when the detail panel opens). The wide panel hosts the same two-column studio as A, but you never "leave" the Skills page — the panel is the studio.

Try it: click Open evals ⤢, then ⤡ collapse to come back. Compare with A: same room, but the shell is a panel state, not a separate surface. Which mental model is more honest?
