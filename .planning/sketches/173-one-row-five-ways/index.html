One row, five ways

Sketch 172 asks where the five decisions live. This one asks what one row looks like — and it draws all five rows in every state each can actually be in, because the five are not alike: two have shipped empty-state sentences, one has no control anywhere, and one has no field at all.

⚠ Read this page as a DRAWING, unlike 172.

172's central surfaces ship, so it renders them. Here the decisions card exists in no component, so almost every node is a proposal — 27 of them, each tagged data-s173="NEW". What keeps it honest is that every sentence the product already owns is parsed out of sketch 172's dump of the real rendered WorkflowBuilderPage rather than re-typed, and row 3 wears the shipped AI-proposed mark markup lifted whole. This build asserts that ratio rather than asking you to trust it.

D-16 is the floor on every string here. The mark means a model wrote this. It never means this is good or this is durable — measured: gpt-5.5 named one-run parameters in 5 of 5 QBR requirements and all 20 were still correctly stamped, because the stamp's question is the anti-echo one. The shipped explanation obeys this and is asserted to: “The generator proposed this line when this workflow was created. Edit it and this mark clears.”

EVIDENCE

D-07 says five fixed rows, always all of them, always the same order. It does not say the five are alike — and they are not. This table is why a single row treatment has to survive five quite different shapes.

rowthe ask (proposed)what backs itempty statethe catch
kb Which knowledge base should this search? stored field SHIPPED The shipped empty state already says what unbound MEANS — 'searches everything' — which is a fact about configuration, not a warning. A row that re-words it would be a second truth-teller.
template Is there a template it has to fill? stored, elsewhere PROPOSED The only row whose control lives on another surface. Its answered state is the one place this card could usefully show a COUNT, because the count is what tells you the draft was aimed at the right questions (SEED-157).
requirement What must this workflow deliver? stored field SHIPPED The publish gate's own predicate (grounding.py business_requirement_missing). D-12 says the row reads the SERVER's source, never a copy. It is also the only row that ships a provenance mark today.
name What should this be called? stored, no control PROPOSED ⚠ The drafted view shows the workflow's NAME nowhere at all (measured in sketch 172 — the header renders the slug). So this row is not adding a second control; it is adding the FIRST display.
deliverable What does it produce? no field PROPOSED ⚠ There is NO FIELD. soulDeliverable() derives this from whether a terminal llm_emit exists. 'Answering' it means editing a step, so an Edit control here would write a cheque the store cannot cash.

⚠ Row 5 is the one that breaks a uniform treatment

There is no deliverable field. soulDeliverable() derives the answer from whether a terminal llm_emit step exists — so “answering” row 5 means editing a step, which D-03's write path (builderStore, one set()) does not express as a row edit. All three variants therefore give row 5 a stated fact instead of a control. If a build wants row 5 answerable, that is a different and larger change than the other four, and it should be priced before planning rather than discovered inside it.

⚠ Row 4 adds the FIRST display, not a second control

Sketch 172 measured it: the drafted header renders the workflow's slug, so the name appears nowhere on the screen. D-15 keeps the slug untouched — so after this phase the header would still show vendor-risk-review while this row edits Vendor-risk review. Two strings, one of them invisible. Worth deciding deliberately rather than inheriting.

CLAUDE'S DISCRETION

197-CONTEXT.md leaves open “whether the surface states D-03's limit — and if so, in one line or per affected row.” Both are drawn here so the choice is made by looking.

The limit is real: answering a row writes into the draft, but the rest of the draft was built around the old answer. Changing the KB scope does not re-shape phases written for the old scope. D-03 locks that the surface must not silently discard the author's own edits; it does not lock whether the surface SAYS this.

One line, at the foot of the card

Cheap, honest, easy to miss — and it sits directly above the “nothing is committed” close, which is the same register. This is what every board on the other three tabs shows.
