Variant A — a minimal frame: the run frame, minus the run
Reasoning gets the same bordered container it has today, just without step rows or a timer. The two message shapes look like siblings — same box, same left edge, same disclosure.
The bet
One visual grammar for "the model did something before answering", whether that something was three tools or pure thought. Nothing new to learn.

Variant B — a bare line above the answer, no container at all
The calm line sits directly in the message body. On a tool-bearing message it sits above the run frame — because thinking precedes doing, and the order on screen matches the order in time.
The bet
Reasoning is not part of the run; it is what the model did before the run. Giving it its own line — never a box — makes it read as a property of the message, which is what it is on the wire (message.reasoningContent, not a tool call).
The cost
It moves the thinking control on tool-bearing messages, which is a change to a surface that isn't broken. Anyone used to finding it inside the run card has to relearn one thing.
Build consequence
ThinkingBlock comes out of RunCard and mounts in MessageItem for both shapes. Both reasoning render paths collapse into one component with one owner — the smallest surface area of the three, and the only variant where the reasoning render stops being conditional on tools by construction rather than by a second branch.

Variant C — reasoning folds into the message footer, after the answer
The answer comes first, unobstructed. Reasoning becomes a provenance affordance sitting beside the model name — the same register as "which model wrote this", because that is the same kind of fact.
The bet
Nobody opens a chat to read reasoning; they open it to read the answer. Putting thinking after the answer means the surface never delays the thing you came for, at any length — this is the only variant whose behaviour does not degrade at 33,713 characters.
The cost, and it is the deciding one
It cannot show live streaming. A footer under an answer that has not been written yet has nowhere to sit — so this variant needs a second surface for the streaming case, and a second surface is the thing the Phase 095 inventory rule exists to forbid. Check it against sketch 234's Replay the stream: whatever wins there has to live somewhere while it streams.
Build consequence
A new footer slot in MessageItem plus a retained in-run surface for the live case. Cheapest to add, and the only variant that ends with two reasoning renderers instead of one.
