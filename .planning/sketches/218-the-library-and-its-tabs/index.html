Chunking — what the agent actually searches, and why it is cut that way

The reference's screen 4, which the first pass skipped entirely. Its strongest idea is the left pane: the original text with the chunk boundaries drawn on it.

the source, with the cuts shown

The system architecture uses a service-per-domain split, with the retrieval path isolated behind a single interface so the embedding provider can be replaced without touching callers.

Each document is chunked on paragraph boundaries with an overlap, which keeps a definition and its example in the same chunk more often than a fixed window does.

Retrieval runs two arms — a vector search and a keyword search — and merges them, so an exact term still matches when the embedding does not.

The overlap is why the shading interleaves. A reader who has ever wondered "why did it find that paragraph and not this one" gets the answer from this pane alone.

how it is cut today

Chunk size1000 characters
Overlap200 characters
Split onparagraph boundaries
Applies toevery new document

Changing these re-splits and re-indexes everything. Search keeps working on the old chunks until it finishes.

⚠ CHARACTERS, NOT TOKENS — and the reference says tokens. chunk_size = 1000 / chunk_overlap = 200 are character counts. Drawing a "512 tokens" slider would be a units lie: the number would not mean what the system does with it, and a person tuning it would be tuning something else.
⚠ And these are ENV/CONFIG values today, not settings. They live in config.py, not in user_settings / app_settings — which collides with the standing rule that settings live in the Settings UI; env vars are for secrets and infra only. Chunk size is a behaviour knob, not infrastructure. Surfacing it as a control means moving it first — which is a real task, not a render.
⛔ The reference's live "Preview" with sliders is NOT drawn as shipping v1. Re-chunking on a slider drag implies a preview path that re-runs the splitter on demand; that is buildable (the splitter is pure, and the parsed text is already stored) but it is a feature, not a rendering of existing state. Drawn here as the read-only truth first — see how it is cut before you are offered a knob to change it.
