A — In the title row, opposite the seam link

proposal1 node, 1 gate

The Stop joins the row that already carries the workflow's identity and its one existing action. Cheapest possible mount: the row exists, it is already flex, and Open the chat thread is already pushed right with ml-auto.

Judge the pairing, not the button. A primary-tinted link and a destructive control sitting shoulder to shoulder is the actual question — the header's own docblock says it is “orientation, never a focal point; the only accent it spends is the seam link.” A is asking that header to spend a second accent.

B — The state row owns it

proposalgate is free

The Stop sits on the row that already says ● Running and 2m 18s since it was queued — the row whose entire job is what is true about this run right now. Stopping is a statement about the same fact, so it lives in the same sentence.

The gate comes for free, and that is the argument. This row already computes isTerminal to choose between “since it was queued” and “Ran for …”. Flip the driver to ✓ Complete: the control is simply not rendered, because the row already knew. In A and C the liveness gate has to be added and then defended — which is exactly the gate BUG-260709-01 re-opened on the panel for getting wrong.

C — On the running step

proposalcanvas vocabulary risk

The Stop is anchored to the node that is actually running, so the thing being stopped is pointed at rather than named. On a long workflow this is the only variant where the control and the work are in the same glance.

Drawn so it can be rejected with evidence, not with an opinion. The canvas has a governed glyph vocabulary (references/icon-convention.md §4), and it already spends the space beside a node on ＋ insert and ✕ remove — lane marks that mean edit this workflow. A stop control living on a node is one glance away from reading as delete this step, on a surface whose own chrome says 👁 View only. Phase 188.2 also pinned the rule that no focusable control may live inside the card — so C must mount on the lane, never in it, which is the same lane ＋/✕ own.

The guard question

Switch the Guard on the press control in the driver and press Stop on any variant tab. The three settings are this project's shipped ladder, from references/control-room-shell-and-receipts.md: irreversible + names a victim → sheet; consequential but reversible → arm-to-confirm; reversible with no victim → direct flip.

GuardWhat it claims about a StopTrue?
Direct flip “Stopping is ordinary and cheap. You can start it again.” Mostly. Nothing stored is destroyed — Phase 194 verified on seven live runs that completed phases survive and only the interrupted one is marked. But the run cannot be resumed, so re-running means paying for the completed steps again.
Arm to confirm “This is consequential. Two presses so you cannot do it by brushing past.” Defensible. The composer Stop is next to Send and gets pressed by people who mean it. A canvas Stop is a new control in a place people click to pan — the accidental-press risk is genuinely higher here than on the composer.
Naming sheet “This names a victim and needs reading before you do it.” No — and this is the one to reject deliberately. The victim-naming sheet is for operator actions against someone else's thing. Stopping your own run, which you launched and are watching, is not that. It also costs the thing the whole phase exists to buy: speed of stopping.
The asymmetry worth deciding out loud: a Stop that is too easy costs you one run. A Stop that is too hard costs you the reason the control exists — you are watching money burn and clicking through a dialog. Recommendation: direct flip everywhere, and if any mount gets a guard it is C, because C is the only one sitting in a click-to-pan region. Drive it and disagree.
