3 · A step bound to an action whose shape we do not have (D-214-07)

No fields are invented, no key/value rows, no JSON. ⚠ “Unknown” and “satisfied” must not look the same, so publish refuses this too. The way out is the shipped MCP_DISCOVER_BUTTON_LABEL, character for character — two doors onto one act must not acquire two names.

4 · A stored key the action does not accept (D-214-08)

Read out of an existing tool_args object. ⚠ Never dropped silently — the adapter already fails closed on an undeclared key (smtp_adapter.py:337), so a silent drop would hide a step that was already broken, on an outbound path, in a way the author cannot see.

· “cc” is not something this action accepts.

⭐ This example is real and it is a finding. Stitch drew Cc and Reply to rows. smtp_adapter.INPUT_SCHEMA declares exactly three properties — to, subject, body — under additionalProperties: False. A cc argument is not merely unsupported; the adapter refuses the whole send if one arrives. A sketch that drew Stitch's five fields would have specified a form the backend structurally cannot accept.
