# Sketch 177: The whole workflow surface, regenerated by Stitch

Execution of `.planning/sketches/STITCH-BRIEF.md`. Six of the seven surfaces in the brief's §4
inventory, generated breadth-first.

## ⚠ THIS IS DIRECTION. IT IS NOT AN ACCEPTANCE BAR.

Every page here is **redrawn from scratch by a generative tool**. Not one renders a shipped component.
That is precisely the failure mode that cost this project `SEED-155` — an approved sketch (163) drew a
card the shipped components structurally could not render; four complaints, three phases, one seed.

Per the brief's §2 loop, this artifact is **step 1 of 4**. Step 4 — a normal sketch that *renders* real
components — has not happened and must not be skipped.

**No decision is requested.** The operator asked to see the range (§1). Sketch 176's A/B/C question stays
open.

## What the Stitch MCP actually is

Not a text-to-image API. It is a **project → design-system → screens** CRUD API backed by Gemini 3.1
Pro, with server-side persistence. 14 tools:

| Group | Tools |
|---|---|
| Projects | `create_project` · `get_project` · `list_projects` · `delete_project` |
| Design systems | `create_design_system` · `update_design_system` · `list_design_systems` · `apply_design_system` · `upload_design_md` · `create_design_system_from_design_md` |
| Screens | `generate_screen_from_text` · `edit_screens` · `generate_variants` · `get_screen` · `list_screens` |

Findings worth keeping:

- **It takes our constraints as TYPED input, not just prose.** `colorMode`, `customColor`,
  `overridePrimary/Secondary/Tertiary/Neutral` as hex, `roundness`, three font slots — **plus a
  free-form `designMd` markdown field**, which is where the calm direction, the honesty rules and the
  three measurements went. It obeyed the hex overrides exactly: every page emits a Tailwind config
  carrying `#060A0F / #0D1117 / #212631 / #A3A5FF / #895AF6 / #21C45D / #F5A524`. **No invented hex.**
- **Fonts are a CLOSED ENUM** (~68 families). Manrope, Inter and JetBrains Mono are all in it, so we got
  our exact stack — but a future stack outside the list simply cannot be expressed.
- **`generate_variants` is the "show me the range" primitive** — `creativeRange` of `REFINE` / `EXPLORE`
  / `REIMAGINE`, 1–5 variants, and per-aspect targeting (`LAYOUT`, `COLOR_SCHEME`, `TEXT_CONTENT`…).
  **Not used in this pass** — breadth across surfaces came first. This is the obvious next lever.
- **Output is real HTML** (Tailwind + Material Symbols), downloadable, plus a 512px thumbnail. All six
  files' inline JS passes `node --check`.
- ⚠ **`generate_screen_from_text` reports a TIMEOUT and then succeeds anyway.** Seven of eight calls
  "timed out"; six had in fact completed. **Do not retry** — poll `get_project` and read
  `screenInstances`. Two calls genuinely failed with `Request contains an invalid argument` and left a
  **390×390 stub screen** (`db231025…`) that `get_screen` then refuses to read.
- ⚠ **`list_screens` is broken** — it returns `invalid argument` for a valid project id. Use
  `get_project` → `screenInstances` instead.

## The honest read, surface by surface

### 1 · The Workflows home — *answers the card question, duplicates the shell*

**Genuinely new.** The card **leads with lifecycle state, above the title** — badge first, name second,
then `Unbound · 5 PHASES · Ran 2 hours ago`. That is a real structural answer to *"the name cannot be the
differentiator"*, and it is not what 175 or 176 drew. It rendered the hard case honestly: **three cards
titled exactly "Quarterly Vendor Risk Review" adjacent**, plus two "Contract Clause Extraction" — and the
eye still separates them, because state and recency do the work. Filter chips share the card colour
vocabulary. Every colour carries its word.

⚠ **It made the reported bug worse.** Stitch layered its own app-shell convention on top of the page
header, so one viewport now carries **two search fields and three competing primary actions** — a sidebar
"New Workflow", a top-bar "Search workflows…" + "Execute Run", and the page-level "Filter by name…" +
selects + "Build workflow".

⚠ Be precise about what failed: **the page-level control row is in fact perfectly aligned** — search,
both selects and the button share one baseline and one height, which is the fix `BUG-260815-08` asked
for. What Stitch got wrong is one level up: it *duplicated the shell*. So the alignment fix survives;
the page hierarchy does not. **A generative tool still cannot be trusted with an alignment defect** —
176 proved that when its own first draft drifted 2px, invisible in a screenshot and only caught by
measurement.

**Cost to reach:** the card body is cheap. The lead-with-state ordering is a `WorkflowCard.tsx` change,
and that file is **G-5 firing with an undischarged refactor obligation** — the presentation-layer seam
named in 175's README is exactly the right place for it.

### 2 · The composing moment — *the strongest of the six*

**The user's own sentence becomes the H1.** Not a label, not a quoted echo in a grey box — the actual
hero of the page, large, at rest, with a live `00:00` mono timer, one honest line (*"Assembling workflow
from Legal — 1,284 documents"*), and a quiet Cancel. Nothing greyed out, no duplicated form, **no
percentage and no fabricated step counter** — the §3 constraint held.

Behind it, Stitch wrote a **WebGL fragment shader**: a slow indigo `#A3A5FF` breathing pulse with a
vignette. This is the one place it deliberately broke the "no decorative gradients" rule, and it may have
been right to — it is character without a claim, which is exactly what an unstreamed one-shot wait needs.

**Cost to reach:** the layout is nearly free. The shader is not — it is a new dependency of a kind
nothing in this codebase has, and it needs a `prefers-reduced-motion` answer and a no-WebGL fallback. A
CSS radial pulse gets ~80% of it for ~0%.

### 3 · The draft configuration — *closest to already-shipped*

Five decision rows, **each in one of three states, never two**: `Satisfied` (green + word), `Needs You`
(amber + word), and a real `Unknown / Not reported` row with a neutral help mark. That is the
`decisionsVocabulary.ts` contract reproduced from a prose description — including the part that matters
most, that **silence is not success**. Grounding is the **only** row claiming a publish requirement.
The workflow **name is a `contenteditable` H2 at the top** — the direct fix for *"the name appears
nowhere"* — and Publish is `disabled` **with its reason stated in words** ("Requires grounding
verification").

⚠ It put TRIGGER in the unknown state rather than showing it as an inference from the word "Monday", so
the *"this was inferred from your prose, catch it if wrong"* idea is not drawn. That idea is still open.

**Cost to reach:** low — this is the closest thing here to a re-skin of what `DecisionsList` already does.

### 4 · The two doors — *the difference is finally structural*

Describe-it owns the page: a real textarea with genuine placeholder prose, the KB selector reading
`Legal — 1,284 docs`, and one filled Compose. Build-it-yourself is **a different shape entirely** — a
compact bordered card with its own honest sentence (*"For architects who prefer to place every phase by
hand. No AI, full control…"*), not a greyed clone. Templates sit as a **quiet horizontal row with phase
counts**, positioned so they read as feeding the describe box rather than branching away.

**Cost to reach:** low, and it deletes the duplicated describe screen rather than adding anything.

### 5 · The Builder canvas + spine — *right skeleton, over-literal face*

The spine survives **a branch that splits into "High Risk" / "Standard" and rejoins** — the thing a
vertical spine usually breaks on. Grounding is a **single lock mark in the node's top-right**, present
only on grounded nodes, spending no second badge and no extra colour. Publish is gated with a worded
reason (*"Requires 2 more grounded phases"*). The name is an editable field in the left rail.

⚠ **The node-name ladder is drawn wrong in an instructive way.** It renders the *ladder rung's name*
as the node subtitle — literally the words "Author name", "Derived name", "Type description". The ladder
is supposed to be **invisible**: you see the name, not which rule produced it. A generative tool
describes the mechanism when you explain the mechanism to it.

**Cost to reach:** high. This is `WorkflowCanvas.tsx` (1301 L) + `PhaseNodeCard.tsx` and the right panel;
the graph is xyflow, so a redrawn node face is not a CSS change.

### 6 · The run surface — *the live-moment bar, met*

Finished phases **collapse to one line carrying the one fact worth keeping** — `Retrieve · 00:15 · 312
documents matched`, `Extract · 01:45 · 48 fields across 12 contracts`. The running phase is the only
dense thing on screen: live elapsed `02:12` plus plain words about what it is doing, animated by an
**opacity keyframe** — the `0% / 50% / 100%` in that file are animation stops, **not a progress bar**.
Waiting phases are dim and simply named.

Two things it got right that the shipped page does not:

- **The approval checkpoint lives INSIDE the spine**, not in a modal that hides the run — with its
  reason (*"3 contracts contain uncapped liability"*) and its two verbs, out-shouting the running phase.
- **A Stop control exists, is always visible, and states its consequence** (*"Will cleanly terminate
  current phase"*). `WorkflowRunPage.tsx` currently has **no stop control at all** (grep → 0), which the
  operator's own eye caught during Phase 194 UAT.

**Cost to reach:** medium. The spine is close to what the panel already renders; the stop control and the
in-spine checkpoint are the real work.

## What is unbuildable, and what it would cost

| Thing | Verdict |
|---|---|
| WebGL shader background | Buildable, but a new dependency class with reduced-motion + fallback obligations. A CSS radial pulse is the cheap 80%. |
| Photorealistic avatars | ⚠ **Discard.** Stitch inserted generated portrait photography ("a young professional in a softly lit studio") into three pages, against an explicit ban. Pure tool artifact. |
| Material Symbols icons | ⚠ **Discard the icon set.** Our convention is single-source: `@lobehub/icons` for provider/model, the shared `PHASE_GLYPHS` map for phase types. Read the shapes, not the font. |
| Three stacked shells per page | ⚠ **Discard.** Stitch imports its own nav/top-bar convention and stacks it on whatever you describe. Every page here has a duplicate shell. |
| `GPT-4o` as the model name | Cosmetic; our roster is registry-derived from `MODEL_CAPABILITIES`. |
| Lead-with-state card ordering | Buildable — and it lands on `WorkflowCard.tsx`, whose G-5 refactor obligation is **undischarged**. That refactor comes first. |
| The header alignment fix | **Do not take it from here.** Stitch regressed it. Fix stays with a measured sketch. |

## What was not generated

- **Surface 6 of the brief's inventory, the 8-stage publish gauntlet**, was out of scope for this pass
  (the request named six surfaces). Its Phase-127 energized pip-strip needs a coherence check against
  whatever language is chosen.
- **`generate_variants` was not used.** Every surface here is a single take. The A/B/C range that §1
  actually asks for is one `REIMAGINE` call per surface away.
