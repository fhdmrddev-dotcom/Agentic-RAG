The status vocabulary already exists — and it is not on the canvas

Found by re-running the icon-convention audit on 2026-08-05, after the first draft of this sketch had already invented a set of lane glyphs. PhaseCard.tsx:67-79 ships STATUS_META: every one of the six phase statuses already has a glyph + real text + an AA-contrast colour token, built explicitly as non-colour-alone for WCAG 1.4.1. That is the developer timeline — the exact view Phase 188's canvas is meant to be the business twin of, painted from the same stream. Inventing a second set of marks would put two vocabularies on one run. Variant C now inherits it, and flags in violet the two readings it cannot.

A second wording split, in the same place. PhaseCard labels an llm_human_input step “Needs you” (:48); the canvas badge says “Waits for you” (PhaseNode.tsx:177). Two views of one run, two words for one concept — decided independently, neither wrong, and now both visible to the same person. Phase 188 is the first phase that has to make them agree, because it is the first to put both views on the same run. Also noted while auditing, not 188's to fix: PhaseCard's own PHASE_TYPE_LABEL still carries the flat ⚙ ✎ 🤖 ⛓ ☺ glyphs that Phase 127 retired in favour of the shared 3D map — and it lists only five types, so llm_emit falls through to • “Step”.
THE COLLISION — the same four words already mean something else. "Waits for you" ships today as badge slot 2 on llm_human_input steps. It is a design-time fact: this step will pause, said before anything runs, and it is true whether or not there is a run at all. SC#1 asks for a run-time state — this step is paused right now and nothing moves until you act. Sketch 146's alignment pass already ruled that “running” and “waiting for you” may never share a word. This is the same defect one turn inward: the will-wait badge and the is-waiting state must not share one either. Every variant above draws the waiting step with both marks visible at once so you can judge whether they read as two facts or as one thing said twice.
A total function over the FULL event set (SC#3) — the fail-open this must not inherit. StreamsProvider.tsx:3337 reads DB_PHASE_STATUS[r.status] ?? "done". All five DB values are mapped today, so it is unreachable — but the fallback for an unrecognised status is “done”, which is precisely the reading SC#3 forbids. It is the same shape as the findIndex → -1 fail-open that painted an unknown blocked stage as 8/8 green in the publish gauntlet. Whichever variant wins, the unknown reading must be drawn — and it must not be “done”. Each variant's rightmost cell draws it.
