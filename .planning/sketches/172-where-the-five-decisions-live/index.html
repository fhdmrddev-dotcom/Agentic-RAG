Where the five decisions live

A freshly generated draft arrives with five decisions the AI made for you. D-07 says all five become answerable. The question this sketch asks is not what the card says — it is whether the card should own controls at all, because three of the five already have one.

⚠ The finding that reshaped this sketch, measured not assumed.

Phase 197's CONTEXT anticipates “two receipts stacked on one screen is a composition problem, and it is the sketch's problem.” That understates it. Rendering the real drafted Builder shows that rows 1 and 3 already have working controls in the header identity strip, and row 4 has no display at all — the header renders the slug, so the workflow's name appears nowhere on this screen. The composition problem is not two cards. It is a second home for two shipped controls, on a page whose own source states the rule verbatim: kbAffordance's docblock reads “A second, different answer to one question is drift.”

Everything in a SHIPPED region below is the REAL rendered component, dumped from WorkflowBuilderPage and SeedReceipt under jsdom — not redrawn. Everything marked NEW exists in no component today. 33 proposed nodes on variant A, each tagged data-s172="NEW" in the markup.

A · LITERAL D-02

The decisions card arrives as a sibling of the receipt, above the graph, carrying its own five controls. This is what the CONTEXT describes. It is also the only variant that installs a second home for the KB scope and the requirement — the header keeps its own, and the two are now two answers to one question.

A1 — spliced into the shipped 3-row grid, unchanged

The graph column ships as grid-rows-[auto_auto_minmax(0,1fr)] with the graph pinned by [&>*:last-child]:row-start-3. Add a fourth child and the pin does something worse than crowd the graph — it strands it. The card auto-places into an implicit fourth row sized to its own content, the minmax(0,1fr) third row is left with nothing to distribute, and the graph — which is last-child, so it is nailed to row 3 — collapses, rendering only its overflow on top of the card.

Measured, with the last-child pin in play, it is not shorter: it is gone.

C · THE INDEX

The card owns no control. It names each decision, shows the answer the AI chose, and hands you to the control that already exists — highlighting it in place. Rows 4 and 5, which have no home, say so plainly instead of pretending.

Press Change it on any row: the shipped control in the header is focused and ringed. Nothing is duplicated, so nothing can drift; the header stays byte-identical, so band 3 is never re-captured; and dismissal costs nothing, because the card was never the only door. This is where sketch 174 (“what dismissal costs”) folded in — on this variant the question dissolves rather than needing an answer.

⚠ Its honest weakness: rows 4 and 5 have nowhere to point. The name has no control anywhere (D-15 would add one), and the deliverable is derived from the last step rather than stored — soulDeliverable() reads a terminal llm_emit. So C is only complete if this phase also gives row 4 a home. That is a scope consequence, and it is stated here rather than discovered at plan time.
