Shared Expert Card Anatomy: Disentangled Axes (SEED-303)

Binding != Usage. Default is Union Scope (S4); tools are an additive floor (S6); access is role-gated.

Two Completely Disentangled Axes (BUS-291)

Axis 1: Knowledge Composition (scope_mode)
+ Union Scope (Default, S4): Thread folder = where user is; Expert folders = what expert brings. Both are searched together.
🔒 Strict Isolation (Opt-in, S5): Ignores chat folder; strictly reads expert folders (stated upfront at invite).
Axis 2: Access & Grants (PACK-10 / Migration 189)
Org-Wide: Everyone in the org can see and invite.
Role-Gated: Gated by role (e.g. HR group, Admin only). Users outside grant see no card (PACK-11).
Tools Semantic: Additive Floor, Never Ceiling (S6)
Expert adds domain skills, but NEVER strips execute_code, workspace_write, render_template, or ask_user. An Expert can produce real deliverables!
S8 Clone-on-Customise
System templates are read-only; clicking "Clone" copies them into an editable tenant expert pointing to client folders.

G-8 Plan Proportion & Migration 189

-- Migration 189: Presentation & Grants
ALTER TABLE public.expert_bundles
  ADD COLUMN icon text NOT NULL DEFAULT 'sparkles',
  ADD COLUMN category text NOT NULL DEFAULT 'General',
  ADD COLUMN when_to_use text NOT NULL DEFAULT '',
  ADD COLUMN example_output text NOT NULL DEFAULT '';

CREATE TABLE public.expert_grants (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  expert_id uuid REFERENCES public.expert_bundles(id) ON DELETE CASCADE,
  grantee_type text NOT NULL CHECK (grantee_type IN ('user', 'role')),
  grantee_id text NOT NULL,
  created_at timestamptz DEFAULT now()
);
Why G-8 enforces two separate phases:
  • Phase 261 (Authoring) owns Admin CRUD, AI draft generator, brainstorm upload sandbox, grant tables, and S8 clone-on-customise (~3-4 plans).
  • Phase 262 (Discovery) owns the browsable catalog, search, domain filters, modal detail view, and union scope presentation (~3 plans).
