Why the resolution has to be visible
SC#5 says a guessed-at file must land in the Library or in a named refusal, never silently in neither. The only way to make that inspectable is to show the four resolving. A silent success message is exactly the design where a file falls through and nobody notices for a month.
The reconciliation table is the SC#4 receipt
“Preview said 12 · 12 arrived · 0 unaccounted” is a claim a person can check, and it is the same arithmetic a test can assert. It is also where an optimistic bucket would be caught — by the surface, not by a bill.
One of the four resolves to “already here”
That is Tier 2 doing its job: the Google Doc exported, its sha256 matched a document already in the Library, and it was not imported or embedded again. Tier 1 could not have known this — Drive publishes no hash for native Docs. The preview said “we cannot tell” and it was right.

What it proves that A cannot
Blast radius. You see that this import touches six Library folders and that /Pricing/Rate Sheets goes 41 → 44. A per-row destination answers “where does this go”; the tree answers “what happens to my Library”.
Why it can’t be the control
SC#3 is worded at the row grain — “where each file would land”. A tree that shows six folders lighting up does not tell you where Insurance Renewal.docx goes. It is a summary of an answer, not the answer.
The dashed ghost is the reusable idea
A projected row must be visibly not a row: dashed border, no count contribution until confirmed, and a “would” verb. Same rule as the 185 canvas seal — a projection that renders like a fact is a lie with good typography.

The routing-rule button is the interesting one: evaluating a rule is a read. The rule engine answers “where would this land” without minting a folder, which is exactly what PREV-03 requires and exactly the thing a naive implementation gets wrong by creating the destination folder up front.

SC#2 stops being a promise
“The Library is exactly as it was” is normally something a user has to trust. Here it is a counter they can watch while they try to break it. Cancel prints the same zeros. That is the difference between a reassurance and a demonstration.
Is it too much chrome for the real product?
Probably, as a permanent five-counter strip. The one-line form belongs in the footer of every preview (it is already in 229 and in A above); the expanded read/write ledger belongs behind a “what has this done?” disclosure — and behind the Library’s Health tab, where the same facts have a home.
It also documents the dry-run contract
The read log is literally the phase’s architecture: the preview IS the diff pass with dry_run=True. If a future change adds a write to that path, this strip is where it becomes visible — and where a test can assert it did not.

Recommendation — A as the control, C’s ledger as its one-line footer, B deferred

  • A The receipt, then the resolution. It is the only variant that answers SC#4 and SC#5 at all: the reconciliation table is the counts-match receipt, and the four resolving rows are the “never silently in neither” guarantee made observable.
  • C The zero-line, not the full strip. 0 documents · 0 chunks · 0 jobs · 0 folders ships in the footer of every preview surface. The expanded read/write ledger is worth building once, behind a disclosure — it is the only place a future accidental write becomes visible.
  • B Deferred, not rejected. SC#3 is worded at the row grain, and 229’s rows already carry the destination and the rule chip. The tree answers a different and real question (“what happens to my Library?”) — plant it as the folder-mapping surface Phase 234 needs anyway.

What this sketch commits to

  • The confirm reads as consequences, not counts. Every row is a sentence with a verb: will be added, will be skipped, nothing will be imported, we will open these four, then decide.
  • Two-tier identity is visible in the outcome. One unknown resolves to “already here” because Tier 2 sha256 matched at splice — the honest end of a Tier 1 “we cannot tell”.
  • A refusal is named. “No text layer — image-only PDF” and “shortcut target is in a Shared Drive this connection cannot reach”. Not “2 files failed”.
  • Re-embedding is stated as a cost that is NOT paid. “nothing is embedded again” is on screen before the confirm, because the ROADMAP’s named failure mode is that the cost “is only noticed on the bill”.
  • Cancel prints the zeros. The toast on Cancel is not “Cancelled” — it is “Closed. 0 documents · 0 chunks · 0 jobs · 0 folders written.”
