⚠ SMTP takes the neutral mark, and that is a FINDING rather than a gap. logos carries no SMTP mark at all — its only mail-shaped names are vendors (google-gmail, mailgun…). Borrowing Gmail's mark for a Fastmail SMTP connection would be the ROADMAP's own named "a logo is approximated" failure.

⚠ The neutral is NAMED — never nothing, and never another service's mark. That answers SEED-206's measured ClickUp hole: an unmapped service takes the neutral, which is a decision the map makes rather than an absence the render discovers.

⚠ The ink is not a style choice — each arm exists because of a measured property of the icon body. self: Slack's four elements and Jira's three carry their own fills, so a colour utility would be inert and a fill utility would flatten four brand colours into one. stroke: lucide sets fill="none" stroke="currentColor" as presentation attributes, and a CSS rule on the same element beats a presentation attribute — so a fill utility here fills the outline into a solid blob. ⚠ And a third arm exists in the shipped module for bodies with zero fills and no currentColor, which inherit fill: black and go invisible on Deep Midnight while every test stays green.

§5 · The approval sentence, before and after

Both lines below were driven verbatim on both shapes at Phase 213's close and recorded as finding 1. This is what D-214-14 changes, and how.

today · capability row It will run "post_message" through post_message.
today · MCP row It will run "ask_question".
after · capability row It will run Post a message through Aether Slack.
after · MCP row It will run Ask the wiki through DeepWiki.
after · service unresolvable It will run Post a message.

What was actually wrong. _external_action_clause fills the service slot from config.capability — the same value it puts in the tool slot on a capability row, producing a tautology; and an MCP row carries capability = None, so the clause is omitted entirely and a GitHub, DeepWiki or Notion pause names no service at all. The service a person needs sits on the connection row and was never read.

The fix keeps the composer pure. D-214-14: the engine already holds a pool and already reads that connection to run the step, so it resolves the display name and hands it to the composer as an argument. ⚠ Rejected: storing the service name on the step config — a stored copy of a derived fact goes stale the moment the connection is renamed, and D-213-02 rejected exactly this shape for descriptors (computed never stored).

⚠ The last line is the rule that survives. An absent name still omits the service clause — "never draw a name the system cannot know" is preserved, not overridden. The action alone, and the neutral mark. Not "Unknown service".
