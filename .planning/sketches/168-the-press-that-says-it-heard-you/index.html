Today — the press is invisible

shipped at 045a83dc

All three controls are pure dispatchers — onClick={onStop} and onClick={() => void streamActions.stopThread(threadId)}. Neither awaits the promise nor holds local state, so there is nothing to render a pending style from. Press any of them below and watch what changes on screen: nothing does, until the whole stream teardown completes and the button swaps back to Send.

Then switch the driver to “The run already finished” and press the panel Stop. That is BUG-260709-01, re-opened 2026-08-16 on its own trigger — and the console line it produces states a cause that is false.

A — In place

proposal 1 local state × 4 mounts

The control keeps its slot and transforms: the filled square becomes a pending ring, the word becomes Stopping…, the button disables so it cannot be pressed twice. Nothing else on the surface moves. When the run reaches terminal the control unmounts and a terminal reading takes its place — which is also the fix for the dead control on a finished run.

The judgement here is the “never resolves” arm. Set the driver to it and press. A Stopping… that spins forever is a new lie, and it is worse than the silence it replaced, because the user now believes something is happening. Every variant on this page has to answer it; A answers it with a timeout that reverts and says so.

B — The control yields

proposal no disabled-control state to design

On press the control is replaced in its own slot by a status line: ⊘ Stopping this run…. There is no disabled button, because there is no button — which makes a double-press structurally impossible rather than defended against. When the run goes terminal the same slot holds the terminal reading.

The cost is layout: a 32px icon button and a text line are different widths, so the slot has to reserve space or the composer twitches on every stop. Watch the composer row specifically — that is where it shows.

B is the only variant where the ⊘ mark is already shipped vocabulary. Phase 174 D1/D2 use ⊘ for the quiet deliberate-stop tier (references/run-state-honesty.md). A and C introduce a spinner, which is not in any canvas or chat glyph table — see The contract tab.

C — Surface-first

proposal shared state, not per-mount

The control does the least it honestly can: it disables. The surface carries the acknowledgement — the phase spine's active step reads stopping, and the run's status sentence changes. The claim being made is “the run is stopping”, not “the button was pressed”, and only the surface is in a position to make it.

Because there is one shared reading rather than four independent button states, pressing Stop in the tray also lights the panel and the composer. Open two mounts below and press either — they agree. In A and B they cannot, because each control only knows about itself.

The cost is where it is paid. A shared optimistic reading means writing into shared streaming state before the server confirms — the exact place this project has a standing rule about (Realtime is a best-effort hint, not a source of truth — always reconcile via fetch, D-v2.5-03). C is the most honest reading and the most expensive one to make correct; it is drawn so that trade can be judged rather than argued.

Four things that bind regardless of winner

#RuleWhy
1A control that cannot stop anything must not be drawn. The panel gate is showTimeline = isHarness || phases.length > 0 and phase rows outlive the run — so a finished run renders a live-looking Stop. That is BUG-260709-01 re-opened, and Phase 194's own WR-03 / Anti-Pattern A-2. Gate on run liveness, never on the presence of phase rows.
2The warning text must not state a cause it has not established. Today one console line explains three different failures, and is wrong for two of them. StreamsProvider.tsx:2453-2459 says “the run had not finished registering … press Stop again in a moment” — on a run that finished ten minutes ago, where pressing again can never succeed.
3A pending state must have a losing arm. If the cancel does not resolve, the surface says so and returns the control. An indefinite Stopping… replaces a silent failure with a confident one. Drive the never resolves setting on each tab.
4Whatever the press looks like, all four mounts do the same thing. Phase 194 D-08 already holds the runtime half — four mounts, ONE mechanism (stopThread(threadId), never cancelRun directly). This is its display half.
