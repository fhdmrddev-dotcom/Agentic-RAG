What is wrong here is not the amount of information — it is that all of it has the same weight. Nine atoms render at one visual level, so nothing is scannable and everything must be read. With 93% of rows sharing a name, the eye lands first on the one field that cannot tell them apart.

So for most rows the headline reads “Unbound”, and the line differentiates no better than the name it replaced. Densest is not the same as most scannable.

What the data says actually separates two rows inside one family, in order of strength: updated · version · owner · lineage (forked from …) — project only earns the lead once a library is genuinely spread across projects, which this one is not. A build of this direction should lead with when + version and treat project as a chip, or the 39px row is a tidier way of telling you nothing.

The bet: rank beats compression. One line per row, leading with the differentiator stack and demoting the repeated name to context. Everything else is one click away.
The risk, now measured rather than guessed: a list reads as an inventory rather than a library, and the differentiator has to be chosen from what the data actually varies on.

The bet: colour does the first pass so reading is the second. The left edge encodes the governance tier, tags encode deliverable and provenance, and the theme's own tokens carry it — no new hue.
The risk: colour that encodes something a person has not learned yet is decoration. This has to be teachable in one glance, and it must survive a colour-blind reader — which is why the tag still says the word.

The bet: the atoms become glyphs — deliverable, tier, grounding, step count — and text appears only where a word is irreplaceable. Hover names each glyph; click opens the words.
The risk: this is the densest and the most learnable-in-theory, and the easiest to get wrong: an icon nobody decodes is worse than the sentence it replaced. It leans hardest on the shared PHASE_GLYPHS vocabulary already established in the icon convention.
