# BUG-260529-03: Free-text ask_user (no options) crashes the whole app

> **ID note:** originally drafted as BUG-260529-02, but that ID was already taken by the
> chat-tool-cards bug (`chat-tool-cards-scroll-collapse-duplicate.md`). Renumbered to
> BUG-260529-03. The fix commit `0df4b048` references the old (-02) number in its message.

## What we observed

During Phase 087 scenario-matrix testing (the previously-untested **free-text ask_user** row), the agent was prompted to call `ask_user` WITHOUT options (an open-ended question). The backend stored the pending ask with `options: null` (confirmed via `GET /threads/{tid}/ask_user/pending` → `"options": null`). The moment the workspace panel tried to render the pending card, **the entire React app blanked to a white screen** (`#root` had 0 children, `document.body.innerText.length === 0`).

Console:
```
Uncaught TypeError: Cannot read properties of null (reading 'length')
An error occurred in the <PendingAskCard> component. Consider adding an error boundary…
```

Recovery required a full page reload — and on reload, re-opening the same thread crashed again (the pending ask is restored from the GET endpoint with `options: null`), so the thread was effectively unusable until the ask expired or was answered out-of-band.

The **radio path** (ask_user WITH options) was verified working in round-1 UAT; only the **free-text path** triggers this. It has been latent since Phase 087 Plan 05 because prior UAT only exercised option-based asks.

## Why it matters

`major`: a normal, common agent behavior — asking an open-ended free-text question — crashes the whole single-page app (not just the panel), with no error boundary to contain it. Any thread with a pending free-text ask is unopenable until the ask resolves. Free-text is arguably the *default* ask_user shape (many questions have no fixed choices), so this is high-likelihood in real use.

## Hypothesized cause

**Confirmed** (not just hypothesis). `PendingAskCard.tsx` destructured `options` straight off the `PendingAsk` prop and then did `options.length > 0` at lines 180 & 207 (and `options[choiceIndex]` at line 93). The `PendingAsk` type implies `options: string[]`, but the backend serializes a no-options ask as `options: null`, so `null.length` throws during render. With no error boundary above the panel, the thrown error unmounts the entire tree.

`Agentic-RAG` — this app's frontend panel. Routable.

## Workarounds (prompt-side, code-side, or UI-side)

- Code-side (applied, commit `0df4b048`): normalize `const options = ask.options ?? []` in `PendingAskCard`. One line; radio path unaffected (arrays pass through unchanged).
- Prompt-side (pre-fix): instruct the agent to always pass at least one option to `ask_user` — avoids the null but defeats free-text.
