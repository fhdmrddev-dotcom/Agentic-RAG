# BUG-260718-02: Chat reasoning stream flickers + sources open by default

Two related response-render polish items, observed live (testing Kimi K3, a reasoning model). NOT fixed — captured for a post-v3.3 chat-response-polish phase (the fix touches the hottest chat files; see risk notes). Study performed 2026-07-18 (read-only).

## What we observed

**(A) Thinking/reasoning "flicker."** During a tool-bearing reasoning stream, the thinking block re-renders rapidly and feels janky. Compared unfavorably to Claude.ai, which shows a calm single "Thinking…" line during streaming, expandable into a timeline, then renders the final answer.

**(B) Sources open by default.** The "References · N sources" section is nicely designed but renders EXPANDED by default, which the operator finds noisy.

## Why it matters

Chat is the primary surface. The reasoning jank + always-open sources make finished answers feel busier/less polished than the Claude.ai bar the operator is aiming for. Minor (cosmetic/UX), not functional.

## Hypothesized cause (verified by read-only study)

**(A) Flicker** — the reasoning text streams raw, one token at a time, with NO batching, and every token also fires an auto-scroll:
- `frontend/src/lib/api.ts:305,654` — `onReasoningDelta` fires per token.
- `frontend/src/providers/StreamsProvider.tsx:400-408` — per-token `setMessages` (message object replaced each token; no throttle — the `throttle.ts` helper is wired only to the cache writer, not the UI path).
- `frontend/src/components/chat/MessageList.tsx:104-136` — the auto-scroll effect re-runs every token (deps include `messages`, whose identity changes per token) and calls `scrollIntoView` each time — **the primary jank driver**.
- `frontend/src/components/chat/RunCard.tsx:411-456` — reasoning renders as a flat `whitespace-pre-wrap` blob (no timeline). Already collapsed by default (`RunCard.tsx:70` `thinkingOpen=useState(false)`), so the collapse state is fine; the churn is the live-token repaint + scroll. Also: reasoning only renders on tool-bearing turns (`MessageItem.tsx:437-439`); a pure-text reply shows none.

**(B) Sources default-open** — the list itself defaults collapsed, but `MessageItem` overrides it: `frontend/src/components/chat/MessageItem.tsx:511` `defaultOpen={hasInRangeMarker(...)}` → auto-opens whenever the answer has inline `[n]` markers.

## Surface classification

`Agentic-RAG` — this app's chat response surface. Routing candidate.

## Suggested routing

- **Fold into in-flight phase:** n/a (deferred — do NOT drive-by; hot files)
- **Defer to future phase / milestone:** post-v3.3 "chat response polish" phase. Recommend `/gsd:sketch` first for the reasoning timeline (T4 below).
- **Plant as seed:** candidate if not scheduled next milestone.
- **External — note only:** no

### Options studied (not implemented)
- **Sources → collapsed (trivial, ~zero risk):** flip `MessageItem.tsx:511` `defaultOpen={false}` (or drop the prop; list already defaults collapsed). `hasInRangeMarker` becomes dead code.
- **Thinking calmer:** (T1) throttle/coalesce reasoning deltas to ~rAF cadence; (T2) show a calm "Thinking…" line during stream, reveal full text on expand/after finish (Claude.ai feel); (T3) rAF-coalesce the per-token follow-scroll (primary flicker driver); (T4) structure reasoning into a real step timeline (bigger — sketch first). Recommended combo: S1 + T2 + T3.
