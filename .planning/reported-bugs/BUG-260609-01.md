# BUG-260609-01: Harness phase timeline run-honesty (stuck "running" + vanish-on-revisit)

## What we observed

During Phase 098 live UAT (operator ran the bound "Doc Q&A (098 UAT — Weekly reports scoped)" workflow across 5 providers), two run-honesty defects on the workspace-panel phase timeline:

1. **Stuck "running":** phase 0 (`draft`) kept showing a "running" badge in the phase timeline *after the whole run completed*. Reproduced across all 5 providers (OpenAI, Anthropic, DeepSeek, Moonshot, OpenRouter).
2. **Timeline vanishes on revisit:** opening a *completed* workflow thread (Chrome, Anthropic run) rendered the final answer fine but the Workspace panel showed "No workspace activity yet" — the timeline did not reconstruct.

Ground truth (DB): every `workflow_phases` row = `completed`, `workflow_runs.status = completed`. The backend persisted correct terminal state → both are **frontend** defects.

## Why it matters

Run honesty is a first-class value for a durable automation engine: a completed multi-phase run that shows a phase "running" forever (or shows no trace of its phases on revisit) makes the user distrust whether the workflow actually finished. Provider-agnostic.

## Hypothesized cause (CONFIRMED via 4-finder + 3-verifier workflow + live Chrome)

A phase node flips running→done ONLY when its own `phase_completed` SSE is observed live (`StreamsProvider.tsx` `setPhaseStatusForThread`, matched by slug). There was **no fallback sweep**: `onRunCompleted` was an explicit no-op on phase status, and the reconcile floor returned `[]` for terminal runs — neither corrected a stranded phase in-session.

Refined during the fix: a COMPLETED harness run **clears** `threads.active_workflow_run_id` (mode flips back to "deep"), so `get_thread_workflow` had no run reference on revisit — the simplest true reason the timeline vanished.

## Resolution (2026-06-09)

Additive fix; Deep path + live `phase_completed` emit untouched; no migration; frontend `tsc` clean; backend `test_thread_workflow_endpoint` 7/7; **zero net-new test failures** (the 10 `streamsProvider.test.tsx` failures are pre-existing rot, confirmed by stash-and-rerun).

- **(A) in-session sweep** — `onRunCompleted("completed")` flips every non-terminal phase → done for the owning thread (new `finalizeAllPhasesForThread`, PANEL-09 closure-scoped). Closes stuck-running.
- **(B) terminal reconcile** — backend `get_thread_workflow` resolves the run by the active anchor ELSE the thread's latest `workflow_run` (by `thread_id`) and returns a per-phase `phases` array; `reconcilePhases` rebuilds the honest timeline from it for completed/terminal threads (DB→Phase status: `active`→running, `completed`→done). Closes vanish-on-revisit.

Files: `backend/app/models/thread.py`, `backend/app/api/threads.py`, `frontend/src/lib/api.ts`, `frontend/src/stores/streamsStore.ts`, `frontend/src/providers/StreamsProvider.tsx`.

**Verified:** (B) live in Chrome — completed Anthropic thread now shows Workflow "Phase 3/3" with draft/confirm/finalize all ✓ Complete (was "No workspace activity yet"). **(A) live re-verify 2026-06-09:** at run end, phase 0 `draft` correctly shows ✓ Complete (no permanent stuck-running) — fix (A) works.

## RESIDUAL (mid-run honesty — NOT closed by fix A)

Operator observation during the (A) re-verify: phase 0 `draft` shows **"running" for the ENTIRE run duration** and only flips to Complete **at the very end** (when `run_completed` fires the fix-(A) sweep). The honest behavior is draft → Complete the moment it finishes (when `confirm` starts). So fix (A) corrects the FINAL state but the per-phase MID-RUN state is still wrong: phase-0's `phase_completed` is not being applied live.

RESIDUAL FIXED 2026-06-09 (commit pending). Root-caused by an 8-agent workflow (6 finders + 2 adversarial verifiers, high confidence): the phase timeline flips running→done ONLY on a phase's own `phase_completed` SSE, with NO forward backstop (`onPhaseTransition` is a deliberate no-op on a normal advance; `onPhaseStarted` never touched earlier rows). A single `phase_completed(draft)` missed across the ask_user pause / consumer reattach stranded draft "running" until the run_completed sweep. Fix (frontend-only, additive, Deep untouched): new `finalizeEarlierPhasesForThread(threadId, beforeIndex)` mutator — `onPhaseStarted(index N)` now sweeps every EARLIER phase still in {running,retrying} → done BY INDEX (robust to a missed phase_completed AND a placeholder-slug mismatch). Guarded to never mask skipped/failed/pending. `finalizeAllPhasesForThread` remains the run_completed floor. tsc clean; zero net-new vitest failures (combined suite 11/44 == baseline). Files: StreamsProvider.tsx, streamsStore.ts. Live re-verify pending. Related: BUG-260609-02 (phantom Sub-task, still open), BUG-260609-03 (double-render, fixed same commit).
