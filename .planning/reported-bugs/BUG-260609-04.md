# BUG-260609-04: Phase card shows placeholder slug "phase-0" instead of the real slug

## What we observed

Running the Test-6 fixture "Read-only refusal (098 UAT)" (gpt-5.4-mini), the workspace WORKFLOW panel rendered the phase as **"PHASE 1 · Step phase-0"** — both while Running and when Complete. The DB has the REAL slug **"readonly_probe"** for that phase (`workflow_phases.slug`). So the UI showed the positional placeholder, not the real phase name. This is the "why do we show Phase 0?" the operator flagged earlier (Test A / Doc Q&A discussion). Evidence: `screenshots/Screenshot 2026-06-10 010423.png` (running, "phase-0") + `Screenshot 2026-06-10 010515.png` (complete, "phase-0"). DB: `workflow_phases` for run 852b1c66 = `[(0, 'readonly_probe', 'completed')]`.

## Why it matters

Minor run-honesty/labeling defect: the phase node shows a synthetic positional name (`phase-0`) instead of the authored step slug, so the operator can't tell which step is which. Cosmetic (no scope/correctness impact) but confusing on every workflow where it triggers.

## Hypothesized cause (high confidence; same reconcile-floor family as 01/02/03)

`reconcilePhases` (StreamsProvider.tsx ~2587) seeds a SKELETON whose non-current rows carry positional placeholder slugs `phase-${i}`, and the current row uses `current_phase_slug ?? 'phase-${i}'`. `replacePhasesForThread` OVERWRITES `phasesByThread` with that skeleton. When the reconcile fires AFTER the live `phase_started` (which had already appended the REAL slug) — e.g. a fresh kickoff in a NEW thread triggers a `[threadId]`-change reconcile — the placeholder skeleton CLOBBERS the real-slug row. If `current_phase_slug` is also null at that fetch instant (current_phase_id not yet set), even the current row seeds `phase-0`. The `appendPhaseForThread` placeholder-replacement (slug `phase-N` → real slug on a later `phase_started`) only fires if another `phase_started` arrives after the clobber; for a single-phase run none does, so `phase-0` sticks. (This is also the slug-mismatch path that makes a missed `phase_completed` strand a phase — BUG-260609-01 — though that symptom is now covered by the index-based sweep.)

## Surface classification

`Agentic-RAG` — harness/workflow panel render. Routing candidate.

## Suggested routing / fix options

- Sibling to BUG-260609-01/02/03 (098-UAT harness-UI run-honesty cluster). Fix options (additive, frontend):
  1. In `reconcilePhases`, prefer the real per-phase slug array (`wf.phases`, already added in the BUG-260609-01 fix-B) for the LIVE skeleton too — not just terminal runs — so seeded slugs are real, never `phase-N`.
  2. Make `replacePhasesForThread`/the reconcile merge NOT clobber a row whose slug is already real with a `phase-N` placeholder (preserve the live real slug).
