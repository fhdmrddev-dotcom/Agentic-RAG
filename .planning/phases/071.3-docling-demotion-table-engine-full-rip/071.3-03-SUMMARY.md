## Files Created/Modified

- `supabase/migrations/047_app_settings_table_engine_default.sql` — new migration: drop any prior CHECK constraint (idempotency), migrate `docling_tf` rows to `pdfplumber`, drop column default, add CHECK constraint `(camelot, pdfplumber)`, set new default `'camelot'`, update singleton row to `camelot`.
- `backend/app/models/user_settings.py` — `UserEffectiveSettings.extraction_table_engine_pdf` default flipped from `"pdfplumber"` to `"camelot"`; `load_app_settings()` `_str` fallback flipped likewise.

## Decisions Made

- **Live pre-test before constraint seal:** Per user request, the singleton row was flipped to `camelot` via a single UPDATE statement BEFORE applying the full migration. The user uploaded a document via the running frontend, observed extraction time/recall/resources, confirmed acceptable behavior, then applied the full migration. This validates the new adapter under real workload before the constraint-tightening migration cements the choice. Revert plan (kept in chat history): `UPDATE app_settings SET extraction_table_engine_pdf = 'pdfplumber' WHERE id = 'global';` rolls back to the prior interim default with no schema change.
- **Idempotent migration guards:** PATTERNS.md audit finding #3 recommended `DROP CONSTRAINT IF EXISTS` before `ADD CONSTRAINT` so re-runs against environments that have manually-added constraints don't fail. Adopted. The pre-migration `UPDATE ... WHERE extraction_table_engine_pdf = 'docling_tf'` protects environments that still hold docling_tf rows from a constraint-violation error when the new constraint is added.
