<objective>
**Recall and Latency Dual-Measurement Verification (RECALL-01).**

Execute the Layer 1 recall evaluation on the benchmark harness, assert that the query runs via HNSW index scan (not sequential scan), prove that the new out-of-the-box default (200) restores recall from 0.040 to 1.000 for small tenants in a large corpus, and record both recall and p95 latency deltas in `246-VERIFICATION-DATA.md`.
</objective>

<threat_model>
### Security & Reliability Invariants (ASVS L1)
1. **Measurement Honesty (ROADMAP SC#4):**
   - Invariant: Recall numbers must never be claims. The harness must run against the database under test and fail if the default regresses.
2. **Seq-Scan Blind Spot (241-VERDICT-CORRECTION-PLAN-PATH):**
   - Invariant: A recall figure measured on a sequential scan is unrepresentative of HNSW index traversal. The test must inspect the Postgres query plan and assert `idx_scan > 0`.
3. **Fail-Closed Reporting:**
   - Invariant: Database or query errors raise `RecallUnmeasurable` rather than returning synthetic or imputed metric values.
</threat_model>

<context>
- Phase 241 measured that at `ef_search = 40`, a tenant owning 0.2% of a 100k-chunk corpus scored `recall@20 = 0.040`, while `ef_search = 200` restored `1.000`.
- Phase 246 Plan 01 updated the out-of-the-box code defaults to 200 and wired dynamic server probing.
- This plan proves that an untuned request out of the box runs at 200 and achieves $\ge 0.99$ recall on the index.
</context>
