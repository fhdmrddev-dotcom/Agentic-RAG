<objective>
**Benchmark Build, Recall/Latency Dual-Measurement Verification, and Ledger Sync (RECALL-01).**

1. Build the dedicated 100,000-chunk skewed benchmark database `recall_bench` via `scripts/build-recall-bench.py`.
2. Execute the Layer 1 recall evaluation against `recall_bench` (NEVER the live `postgres` database).
3. Inspect `EXPLAIN` query plans to prove queries execute via HNSW index scan (`idx_scan > 0`), not sequential scan.
4. Verify that the new out-of-the-box default (200) restores recall from 0.040 to 1.000 for a 0.2% tenant in a 100,000-chunk corpus without any settings touched.
5. Record recall and p95 latency deltas in `246-VERIFICATION-DATA.md`.
6. Update the ledger row for `recall_eval.py` in `docs/HOT-FILE-LEDGER.md`, documenting its safe-as-is status.
</objective>

<threat_model>
### Security & Reliability Invariants (ASVS L1)
1. **Target Database Isolation (Blocker A & scripts/build-recall-bench.py safety):**
   - Invariant: Benchmark construction and execution MUST target `recall_bench`. It must NEVER issue destructive or reset commands against the live `postgres` database containing real development data (159 docs / 7,953 chunks). `assert_bench_target` in `build-recall-bench.py` enforces this.
2. **Measurement Honesty (ROADMAP SC#4):**
   - Invariant: Recall numbers must never be claims or synthetic defaults. The harness must execute against `recall_bench` and fail if the default regresses.
3. **Seq-Scan Blind Spot (241-VERDICT-CORRECTION-PLAN-PATH):**
   - Invariant: A recall figure measured on a sequential scan is unrepresentative of HNSW index traversal. The test must inspect the Postgres query plan and assert `idx_scan > 0`.
4. **Fail-Closed Reporting:**
   - Invariant: Database or query errors raise `RecallUnmeasurable` rather than returning synthetic or imputed metric values.
</threat_model>

<context>
- The live database `postgres` has 7,953 chunks with ~33% equal tenant distribution; it cannot reproduce the small-tenant cliff.
- `scripts/build-recall-bench.py` constructs a local throwaway database `recall_bench` with 100k chunks skewed at 0.002, 0.02, 0.2.
- Phase 241 measured that on this 100k bench, `ef_search = 40` produced `recall@20 = 0.040`, while `ef_search = 200` restored `1.000`.
- Phase 246 Plan 01 made `ef_search = 200` the out-of-the-box code default.
</context>
