<objective>
Implement stateful and incremental workflow execution (STATE-01, STATE-02) so that recurring and manual workflow runs can read their own previous completed deliverable output, maintain living registers, and format state deltas without starting from zero on each run.
</objective>

<threat_model>
- T-205-01 (Cross-Tenant State Leakage): Because `db/workflows.py` queries via the service-role pool, failing to filter by `user_id` / `org_id` on the prior run query would allow a workflow to read deliverables belonging to another tenant. Mitigation: Enforce strict `created_by = $2` / `org_id = $3` predicates.
- T-205-02 (JSONB String-Scalar Trap): If a prior run's `workflow_phases.output` was stored as a JSON string scalar, naive dict access or unparsed strings will crash or inject escaped literals into prompt templates. Mitigation: Implement defensive parsing (`isinstance(raw, dict)` vs `json.loads`) at the read boundary.
- T-205-03 (State Corruption from Interrupted Runs): If the query selects the latest run regardless of status, a `failed` or `cancelled` run with partial outputs would overwrite the legitimate baseline. Mitigation: Strict `status = 'completed'` predicate.
</threat_model>

  <action>
    1. In `backend/app/models/harness.py`:
       - Add `is_stateful: bool = False` to `WorkflowDefinition` model as an additive, zero-migration field with default `False`.
    2. In `backend/app/db/workflows.py`:
       - Implement `async def get_latest_completed_workflow_run(pool: asyncpg.Pool, definition_id: UUID, *, user_id: UUID, org_id: UUID | None = None) -> dict | None`.
       - Query joins `workflow_runs wr` with `threads t` (`t.user_id = $2`) and lateral join to `workflow_phases wp` (`wp.workflow_run_id = wr.id AND wp.status = 'completed' ORDER BY wp.created_at DESC LIMIT 1`).
       - Apply strict owner scoping: `wr.definition_id = $1 AND t.user_id = $2 AND ($3::uuid IS NULL OR wr.org_id = $3) AND wr.status = 'completed' ORDER BY wr.created_at DESC LIMIT 1`.
       - Defend against JSONB string-scalar trap by decoding `wp.output` into a parsed dictionary.
       - Return `{"run_id": str, "created_at": iso_str, "output": dict}` or `None` if no prior completed run exists.
    3. Update `docs/HOT-FILE-LEDGER.md` with the edit to `db/workflows.py` (G-5 compliance).
  </action>

    - `get_latest_completed_workflow_run` returns the previous completed run's output for the matching definition and owner.
    - Cold-start returns `None` without error.
  </acceptance_criteria>
</task>
