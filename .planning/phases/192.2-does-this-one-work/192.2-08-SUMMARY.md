# Phase 192.2 Plan 08: The Row-Level Run Bit — Summary

`has_any_run` — one unscoped, projection-only `EXISTS` at all four library projection sites and on
both wire models — so the card can stop saying an explicit **"Never run"** about workflows that have
run twenty times.

## 1. What shipped

**The defect, restated from the measurement rather than from the review.** `_LAST_RUN_LATERAL_SQL`
is scoped `r.user_id = $1`. That is the correct security posture and it still stands byte-identical.
But it made the run fact **caller-scoped** while every downstream artifact rendered it as a
**row-level** one — so on the world-readable shelves, every caller who is not the one user who ran a
workflow was told, explicitly, that nobody ever had.

**Measured live over real HTTP as a caller who is not the runner (§2a):** `/workflows/published`
returns **92 rows, 5 of them in the CR-01 state**; `/workflows/starters` returns **3 rows, 1 in the
CR-01 state**. Before this change every one of those six rows read "Never run".

| Artifact | What it is |
|---|---|
| `backend/app/db/workflows.py::_HAS_ANY_RUN_SQL` | `EXISTS (SELECT 1 FROM workflow_runs r2 WHERE r2.definition_id = wd.id) AS has_any_run ` — one module-level literal, appended to the SELECT list at four sites |
| `backend/app/api/workflows.py` | `has_any_run: bool | None = None` on `PublishedWorkflow` and `DraftRow`, set from `r.get("has_any_run")` at all three serializer sites |
| `backend/tests/unit/test_library_run_facts.py` | GROUP A2 (11 wire cases) + GROUP B2 (7 source fences) + GROUP C2 (4 live probes) |
| `backend/tests/unit/test_published_workflow_ownership.py` | the exact-field-set pin, with the new field **argued** rather than waved through |

## 3. Decisions honoured, and the trade written down

**DEC-08-A — the disclosure trade, recorded so a future reader can re-open it rather than
rediscover it.** The operator chose the row-level fact over rewording the arm as caller-scoped, with
the alternative presented beside it. `has_any_run` reveals that **somebody** ran a workflow the
caller **can already see**. It never reveals *who*, *when*, *how many* or *with what outcome* —
`EXISTS` only. On a world-readable starter that disclosure is arguably the point of the feature; on
a private row the caller is the only person with runs anyway, so the bit is self-evident. The budget
is written on `_HAS_ANY_RUN_SQL`'s docblock (once — a rule written twice drifts), enforced by the
fence in §2b(ii), and its **re-open trigger** is carried in three places: the constant, the model
docblock and the ownership pin — *the first workflow row visible to a caller who is not entitled to
know it has been exercised at all.*

**DEC-08-B — the owner scope is untouched.** `WHERE r.definition_id = wd.id AND r.user_id = $1 ` is
byte-identical, pinned twice (GROUP B's existing fence and a deliberate re-pin in GROUP B2, placed
where an "obvious simplification" would be attempted — the two constants sit one above the other and
ask different questions on purpose). `test_published_workflow_ownership.py` is green.

**DEC-08-C — `bool | None`, defaulting to `None`.** `r.get("has_any_run")`, never `bool(...)`. A
coercion would turn a MISSING key into `False`, i.e. into the affirmative claim *"nobody has run
this"* manufactured out of an absence — this bug one layer down. Pinned behaviourally on all three
feeds and by a source fence.

**DEC-08-D — one constant, four sites, appended to the projection.** Folding it into the lateral is
impossible: it would inherit the owner scope and answer the same question twice.

**G-7 judgement.** A closure round may never introduce a new user-facing capability. It did not: the
card **already** claims to report run truth and currently claims it **falsely** on the shelf built to
be world-readable. A correct claim in place of a false one is repair. The mechanical check agrees —
every file already existed, so `[new-capability-in-closure]` cannot fire.

**G-5 — both hot files fire, and the seams are DECLINED as a stated decision.** The change is one
constant plus one additive key on two existing models; no second concern arrives, and a closure round
is the wrong place to move an 1,800-line module. **Ledger triples re-derived with CLAUDE.md's recipe
