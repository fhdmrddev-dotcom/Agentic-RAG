```
{ kind: "ran";     outcome: "worked"|"failed"|"stopped"; when: string|null; word }
```

Resolution order, which is the contract and is not interchangeable:

## 2. The headline claim, and the shape that makes it true rather than careful

**The claim:** a frontend deployed ahead of its backend renders an explicit *unknown*, never a
fabricated time and never a green tick — and never the sentence *"Never run"* about a workflow that
has run.

**It is enforced by the TYPE, not by discipline.** `RunFact` has three arms; `unknown` and `never`
are different `kind`s carrying different words, and neither has an `outcome` or a `when` member at
all — so neither is *structurally* readable as a run, let alone a successful one. A two-armed
design, or a boolean, cannot express it, and would pass every other test in the suite. That is why
§2 of `runFacts.test.ts` asserts the difference five ways, including a **non-vacuity case proving
the two INPUTS really arrive differently on a row** — without it, the whole block would pass against
a normalizer that had already collapsed them.

### ⚠ The approved mockup itself has this bug, and that is the strongest argument for the fence

`frontend/src/dev/SketchLibraryCard.tsx`'s `runWords` — sketch 179's own code, variant C, the
operator-approved acceptance bar — carries the comment *"The run truth, in words, with its own
three-armed unknown"* above a function with **two arms and a `Never run` catch-all**. An
unrecognised status renders *Never run*. A feed with no run keys renders *Never run*.

The sketch is the acceptance bar for the LANGUAGE. It is not the acceptance bar for the RESOLUTION,
and this plan deliberately did not copy it. That divergence is now written into both files.

## 4. Deviations from Plan

### Deliberate decisions that differ from the plan's letter

**1. [Rule 2 — Missing critical] `LibraryRow`'s two members are `string | null | undefined`, not `string | undefined`**

- **The plan said:** `lastRunAt: string | undefined` and `lastRunStatus: string | undefined`.
- **What that would have done:** the sibling field one line up, `updatedAt`, is normalized with
  `row.updated_at ?? undefined` and its docblock says why — *"collapses the wire's `null` and its
  absence into ONE value, so a consumer has a single 'nothing to render' case instead of two"*.
  Typing the run fields the same way makes that collapse the only possible implementation. **And
  the collapse IS T-13**: `null` and absent would then be one value, one arm, one sentence — and
  whichever sentence was chosen would be false half the time.
- **Why the deviation is not a judgement call:** the plan's own Task 3 requires three arms with
  `unknown` distinct from `never`, and there is no input that can distinguish them once the type
  has thrown one away. The two clauses conflict; the one carrying the requirement wins. Wave 2's
  carried-forward binding #2 says the same thing independently.
- **Files:** `libraryRow.ts`, `libraryFilter.ts` (both normalizers pass the value **verbatim** — no
  `??`, no default, no normalization).

**2. [Rule 3 — Blocking] `relativeChanged.ts` was split, though it is not in `files_modified`**

- **Found during:** Task 3, before a line of `runFacts.ts` was written.
- **Issue:** the plan says *"Reuse it"* — and `relativeChanged` returns `changed 2 days ago`,
  prefix included, which is not the sentence LIB-06 renders. Calling it would have produced
  *"Worked changed 2 days ago"*. The three ways out were: re-implement the bands in `runFacts.ts`
  (**T-16 by name**, and this repository's FOURTH spelling of a relative-time formatter);
  parameterize the prefix (which puts a caller's vocabulary into the shared module's signature); or
  split the ENGINE from the SENTENCE.
- **Fix:** `relativeBand(at, now)` is the nine bands with no prefix; `relativeChanged` is now
  literally `CHANGED_PREFIX + relativeBand(…)`. **Its own suite passes UNEDITED**, which is what
  proves the split moved no band boundary — a rewritten suite would have proved nothing.
- **Commit:** `4618c148`

**3. [Rule 3 — Blocking] The normalizers are in `libraryFilter.ts`, not `libraryRow.ts`**

`files_modified` names `libraryRow.ts` for the normalization step. That file is a **types-only
leaf** that emits no runtime code at all (its own docblock: *"three exported type names, two
type-only imports, zero values"*), so it cannot contain a normalizer. `fromPublished` and
`fromDraft` live in `libraryFilter.ts:97-150`. ⚠ **This is the THIRD wrong path in this phase's
plans** — `192.2-03` named `models/harness.py`, which contains neither wire model.

**4. [Rule 2 — Missing critical] The run words went to `libraryVocabulary.ts`, not into `runFacts.ts`**

The plan implies the resolver spells its own words. 192.2-02 already met this exact question for the
state axis and recorded the answer: the DECISION moves, the VOCABULARY stays put, because a second
copy is what D-14's one-line-diff rule forbids. Five constants were added there
(`RUN_WORKED` / `RUN_FAILED` / `RUN_STOPPED` / `RUN_NEVER` / `RUN_UNKNOWN`) and `runFacts.ts` spells
none of them — asserted by a source sweep in both suites.

⚠ **They are NOT `components/workflows/runVocabulary.ts`'s words, and the reason is audience.** That
module is the CANVAS's vocabulary, keyed by `CanvasReading`, naming what ONE STEP of a run **being
watched** is doing now (`Complete` · `Running` · `Paused for your answer`). These name what a WHOLE
PAST RUN **did**, read months later off a shelf, and are past tense because that is the only honest
tense here. Its own docblock states the governing rule for exactly this case — *"one derivation, two
vocabularies … the acceptance is a grep proving zero re-derivations, NOT that the two views print
identical strings"* — and no derivation is duplicated: this plan's files hold no `CanvasReading`
mapping at all.

**5. [Rule 2 — Missing critical] `./runFacts.ts` joined `LIBRARY_SUBTREE_PATHS` in the commit that created it**

`files_modified` does not name `librarySubtree.fences.test.ts`. That array is an **explicit list,
not a glob** — an unlisted module is swept by F1, F4, F5, F6, F7 and T-192-04 **not at all**, while
all six stay green. Wave 2's carried-forward binding #7 makes this mandatory. The literal was
**observed, not predicted**: `expected [ './libraryRow.ts', …(13) ] to have a length of 13 but got
14`, and the `+5` forecast in that file's own comment held for the second consecutive addition
(123 → 128 cases).

**8. [Rule 1 — Bug] The inherited import-set fence had a blind spot, measured**

- **Commit:** `0d846456`
