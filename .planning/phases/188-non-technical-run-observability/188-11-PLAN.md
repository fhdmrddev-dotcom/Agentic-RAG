<objective>
Author the cross-provider scoreboard so it can be RUN, and so a row that did not really run cannot read
as a pass.

Purpose: CLAUDE.md's UAT scoreboard recipe binds this phase — the full native roster plus OpenRouter,
eight rows, derived rather than transcribed. RESEARCH measured the traps that make a naive board lie:
`override_provider` returns the settings **unchanged** when the target provider has no API key (so a
keyless row runs on the previous provider and looks like a pass), the per-request `model` never reaches
a harness phase, OpenRouter's `_SUB_AGENT_MODEL_DEFAULTS` entry is `""` and it is a flexible provider so
a bare id passes through unslashed, and `phase.config.model` beats everything.

Output: a script that derives the roster and reads verdicts from the database, plus the authored board
in `188-UAT.md` with every row present.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the board script → the operator's live environment | The script drives real runs against real provider keys. It must not write global settings. |
| provider routing → the recorded verdict | A silently-misrouted row is indistinguishable from a passing row unless the effective provider is read back. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-188-11-01 | Spoofing (of evidence) | `override_provider`'s silent no-op | mitigate | The board probes key availability before driving any row, and reads `runs.provider` back after. A requested-vs-effective mismatch is recorded ⛔ with the reason, never as a pass. |
| T-188-11-02 | Tampering | the operator's saved settings | mitigate | Rows are driven with a per-request `provider` on `POST /threads/{id}/messages`, which mutates no global setting. The Phase-185-proven non-mutating method is used precisely so rows cannot contaminate each other or the operator's environment. |
| T-188-11-03 | Information disclosure | API keys in script output | mitigate | The key probe reports only presence/absence per provider; it must never print a key value or a `llm_api_key` field. State that in the script's docblock and assert it by reading the output. |
| T-188-11-04 | Repudiation | a silently omitted row | mitigate | The script prints a row for every provider in the derived roster regardless of outcome, and the board vocabulary provides ⛔-with-reason. A scoreboard that lists only what passed is not a scoreboard. |
| T-188-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed; the script uses only what `backend/venv` already provides. |
