<objective>
Give a workflow run an address, so a finished run can be re-opened.

Purpose: SPEC Req 7 needs a run to be readable by id after it stops streaming. Almost everything it
needs already exists — the durable phase rows, the thread-scoped files read, the flag gate — but there
is no `GET` for a `workflow_runs` row anywhere in the tree. This plan adds exactly one read, shaped so
the run surface needs no second fetch: the run, **the definition version that actually ran**, and the
phase spine inline.

Output: `GET /workflow-runs/{workflow_run_id}`, gated both ways, with its own suite and the two
existing gate fences updated in the same commit.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet → `GET /workflow-runs/{id}` | A guessable-shaped UUID in a URL is the whole input. |
| authenticated user → another user's / another org's run | The IDOR surface: a run carries the workflow definition and the phase spine. |
| anonymous → `/openapi.json` | The schema endpoint is unconditional and unauthenticated; it is the half of non-discoverability that is easy to forget. |
