Stop the product telling two lies about run state, each proved to be a lie first.

Purpose: SPEC Req 3 named `DB_PHASE_STATUS[r.status] ?? "done"` — a fail-open that is unreachable
today. RESEARCH found a **second** one that is reachable with shipped data:
`finalizeAllPhasesForThread` sweeps every phase still in `running | retrying | **pending**` to `done`
on a successful `run_completed`, and `skip_to_phase` leaves every jumped-over phase `pending` in
`workflow_phases` forever. So on any skip-bearing workflow, the live view paints a step that **never
ran** as **Complete**, while a refresh restores **Not started**. That is SPEC failure condition #2 AND
#3 AND the Req-4 acceptance criterion, simultaneously. Both are fixed here, both observed RED first.

Output: two falsification tests with recorded RED signatures, a narrowed sweep predicate, an honest
`unknown` reading, and the compiler-forced panel entry that comes with it.
