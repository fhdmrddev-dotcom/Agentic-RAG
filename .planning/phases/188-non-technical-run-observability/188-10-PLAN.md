<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run surface → `/threads/{tid}/workspace/files*` | The run surface asks for files by a thread id it derived from the run payload. |
| downloaded bytes → the user's machine | The download helper fetches raw bytes of a server-stored artefact. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-188-10-01 | Information disclosure | thread-scoped files read with a run-derived thread id | mitigate | `GET /threads/{thread_id}/workspace/files` is gated by `_verify_thread_ownership` → 404 on a miss, with RLS on top, and it is reached only with the `thread_id` returned by the already-ownership-gated `GET /workflow-runs/{id}`. Two independent ownership checks; no new endpoint and no widened scope. |
| T-188-10-02 | Tampering / XSS | filenames and paths in the list | mitigate | Filenames render as plain React text children and as `title=` values; no `dangerouslySetInnerHTML`. The download helper receives the file id and filename as arguments, never as interpolated markup. |
| T-188-10-03 | Spoofing (of completeness) | a stale file list on a just-finished run | mitigate | The list is keyed on the RUN's thread and refetched on the run's terminal transition, so a deliverable written at the last moment is not reported as "No files yet". Asserted by the differing-thread-id fixture. |
| T-188-10-04 | Information disclosure | the "Open the run" seam on a Deep thread | mitigate | The seam is inside the existing `showTimeline` gate, so a Deep / no-run thread renders nothing new and Deep stays byte-identical. Asserted directly. |
| T-188-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed; the lucide icons and shadcn primitives used are already in tree (`188-UI-SPEC.md § Registry Safety`). |
</threat_model>
