<objective>
Add the honest verdict engine to the net-new eval runner: a thin eval-specific LLM judge that
reuses the shipped workflow judge READ-ONLY, inline grading of BOTH arms against each case's
free-text `expected_behavior`, an honest `not_measured`/`judge_error` state for arms that can't be
graded, and a with-skill run rollup — closing EVAL-03's "per-provider pass/fail verdict, never a
fabricated score."

Purpose: This is the mechanism that produces the automated "passed" Phase 136 (publish gate) and
Phase 135 (auto-re-eval) consume. Honesty is the headline (EVAL-03 SC#1) — a provider-errored arm
must read `not_measured`, and the judge must be schema-bound so a coerced/truncated verdict fails
honestly instead of faking a pass.
Output: verdict + rollup persisted inline; an additive `eval_verdict` SSE event; four new unit
tests + a Deep-byte-identical guard.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| eval answer / expected_behavior → judge | Untrusted model output + user-authored free text cross into the judge prompt; both must be DATA, never instructions |
| eval runner → judge provider | The judge is a SECOND provider call per arm on an independent model; it must route to the judge provider, not the provider-under-test |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-134-02 | Tampering | prompt injection via `expected_behavior` or the answer coercing a "pass" | mitigate | `expected_behavior` woven as clearly-delimited DATA in `EVAL_JUDGE_RUBRIC` (T-102-03-02); `overall_passed` is schema-bound via `forced_emit(schema_model=JudgeVerdict)`, not narratable/regexable (T-102-03-01) |
| T-134-03 | Repudiation / Tampering | fabricated/gamed verdict | mitigate | `forced_emit(schema_model=JudgeVerdict)` — a coerced/truncated judge yields `{"failure": ...}` → an honest `judge_error`/`not_measured`, never a silent pass; `<=3` retry only on transient no-verdict, never softens a real `overall_passed=False` |
| T-134-06 | Information Disclosure | raw judge/provider error text leaking into RLS-readable `verdict_reason` | mitigate | Truncate judge-failure reason to <=200 chars (the `_truncate_error` precedent, :150); store the summary capped at 2000 chars — never a raw traceback |
| T-134-07 | Denial of Service | judge mis-routed to the provider-under-test's SDK → uniform 401/404 verdict failures | mitigate | Pass explicit `provider=<judge provider>` to `forced_emit`; it copies the target key/base_url (:386-426). Unit-tested by `test_judge_provider_independent` (the 133 `306dd2d4` class) |
| T-134-08 | Repudiation | fabricated score on an errored/empty arm | mitigate | Gate `status == "completed" and output.strip()` before any judge call (D-04); errored arm → `not_measured` with `verdict_passed IS NULL`. Unit-tested by `test_errored_arm_not_measured` (asserts judge NOT called) |
</threat_model>
