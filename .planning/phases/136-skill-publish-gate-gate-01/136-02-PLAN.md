<objective>
Make the server the gate (D-07). Wrap the existing owner-only `toggle_global` with a server-side
publish-gate check that refuses the private→global flip (structured 409 carrying the gate) unless
the request explicitly overrides — and on override, records an owner-visible audit row with the
gate snapshot at the moment of override (D-01/D-02). Close the born-global side door in
`create_skill` (D-08). Expose a tiny `GET /skills/{id}/publish-gate` so the Plan 03 dialog renders
authoritative status before the user commits (D-05).

Purpose: There must be exactly ONE road to `is_global=true` — the gated toggle — and every road
must re-run the gate every time (D-09, no grandfathering). The client dialog is UX; the server
recomputes from `eval_runs` and never trusts a client-supplied gate payload.

Output: the three `skills.py` edits + the six enforcement tests that exercise every write path to
global.
</objective>
