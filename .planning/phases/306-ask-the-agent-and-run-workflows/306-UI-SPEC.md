# Phase 306 — UI Design Contract

> Visual and interaction contract for the user-visible part of "Ask the Agent and Run Workflows".
> The phase is mostly backend. Every surface below EXTENDS a shipped, approved surface. Nothing here
> is a new page, tab, nav entry, Settings mount or React component.
> Generated by gsd-ui-researcher; the checker validates it.

**What this file decides.** Five surfaces from the scope note, plus three adjacent places the scout
found where a 306 change would otherwise render a raw code, a crash or a false sentence:

1. **The MCP origin mark** (MCP-05, D-09, D-31): the chat history row, and every shipped origin-line
   placement (run page, evidence report, run log row, chat run line, `RunCard`).
2. **Settings → Integrations: the outside-starts limits** (GUARD-01, D-35, D-36) in 305's limits card.
3. **Admin → Spend:** MCP asks and runs in the ledger (D-18, D-34). Data only, no frontend edit.
4. **The sentences the MCP tools return** (MCP-04, MCP-06, GUARD-01, D-06, D-13, D-29, D-33).
5. **The G-4 rows of D-22**, with the UI each must see.
6. *(adjacent)* **The ask's question bubble in the app:** the question is shown without the TRUST-03
   envelope scaffolding, plus one note that the chat is read-only (D-28, D-32).
7. *(adjacent)* **Settings → API keys:** an MCP key's activity words for the new tools and refusal
   reasons, the start bar, and the draft card's ask-needs-external hint (D-19, D-29).
8. *(adjacent)* **The 301 "Waiting on you" list:** an MCP-started run reads "started by an AI tool".

**No new component.** Two new *pure* functions are needed, in one new leaf module with no React
(§Surface 6). The scope note asked to be told if anything new was unavoidable: that module is the
only addition, and it exists because otherwise the member's own question shows as
`<external_input …>` markup in their history (§Auto decisions A-6).

**It brings in no new tokens, primitives, type sizes or colours.** Where this file says "as 305", the
305 contract applies unchanged.

**Out of scope (must not be touched):** `frontend/src/pages/SettingsPage.tsx` (FIRES),
`frontend/src/components/chat/MessageItem.tsx` (FIRES ⛔), `ChatArea.tsx`, `MessageInput.tsx`,
`MessageList.tsx`, `ChatLayout.tsx`, `NavPanel.tsx`, `ThreadCommandPalette.tsx`,
`frontend/src/pages/admin/AdminSpendPage.tsx` (FIRES ⛔), `ExpertSpendCard.tsx` /
`expertSpendCopy.ts` (no edit: 305's MCP arm already renders the rows), `frontend/src/lib/api.ts`
(⛔ roadmap flag), any nav entry, any OpenAPI-public name. **No MCP tool answers a paused run**
(MCP-06): no surface in this phase offers one.

sentence sits in an inner `truncate` span. In the four shipped placements, which do not constrain
width, this renders identically to today plus a `title` attribute. In the history row (below) a long
label ends in an ellipsis and the full sentence is in `title`.

### 1a — The chat history row (`ChatHistoryColumn.renderRow`)

```
┌────────────────────────────────────────────┐
│ ▢  What changed in the Q3 pricing policy?  Today │  ← shipped title line (MessageSquare · title · meta)
│    [Bot] Started by AI tool key claude-code-l…      │  ← NEW second line, 12px muted, Bot 14px
```

- Rendered **only when `originSentence(thread.origin)` is non-null**, so every in-app thread's row

  It is part of the button's accessible name (title, then the sentence), so a screen reader hears
  "What changed in the Q3 pricing policy? Started by AI tool key claude-code-laptop".
- Shows in **both** grouping modes (date and folder). The date / folder meta stays on the title line.
- The title filter does **not** search or highlight the origin line (the shipped title-only filter).
- Selected row: the row tint and title go primary as shipped; the origin line stays muted.
- The running dot, the Stop / options actions block and its gradient scrim are unchanged; on a

- The row grows by one 16px line for MCP-origin threads only. That height difference is itself the

- **Not in this phase (recorded, A-4):** the mobile drawer's thread list (`ChatLayout.tsx`, FIRES)

## Surface 4 — The sentences the MCP tools return (copywriting contract)

House voice (293/305): plain sentences, no roadmap numbers, no raw codes, "organisation" spelled as
`mcpKeyCopy.ts` spells it. These are backend strings (each lives in one Python constant beside its
tool, never retyped in a test); they are fixed here so the G-4 rows can read them verbatim. `{N}` is
an integer number of seconds; `{link}` is `primary_frontend_origin()` + the path shown.

### ask_agent / get_answer

| Situation | Text the AI tool receives |
|---|---|
| **Answered** (within the budget, or read later) | The answer text (hygiene + outbound guard, 305), then a blank line, then **Sources ({N}):** and per cited document `[i] {title}` / `document_id: {id}` / `Open in Syrel: {link /app/library/<id>}` (305's passage shape), de-duplicated by document. Then **{Level} confidence.** plus the shipped disclaimer sentence when the run recorded one (`High` / `Medium` / `Low`, the in-app `ConfidenceBadge` words). Last line: **Open this chat in Syrel: {link /app/chat/<thread_id>}** |
| Answered with no citation | the answer text, then **Sources: none cited.**, then the confidence line only if one was recorded, then the chat link |
| **Past the wait budget** (handle) | **Still working on it. Call get_answer with handle {run_id} in a few seconds.** (structured `status: "working"`, `handle`) |
| `get_answer` while still running | the same sentence, same handle |
| **Needs a person** (iteration-cap pause, D-33; repeated by every `get_answer` while it waits) | **This question needs your input in the app before it can finish. Open it in Syrel: {link /app/chat/<thread_id>}** |
| Run failed | **The agent couldn't finish this question. Open it in Syrel to see what happened: {link}** |
| Run timed out | **The agent ran out of time on this question. Open it in Syrel: {link}** |
| Run stopped in the app | **This question was stopped in the app. Open it in Syrel: {link}** |
| Unknown, foreign or other-credential handle (identical refusal) | **No question with that handle is available to this key.** |
| Same idempotency key, same question | the first run's current read (any row above), no second run |
| Same idempotency key, different question | **This idempotency key was already used for a different question; here is the first one.** then the first run's current read |
| Same idempotency key while the first start is still being made | **This question is already being started. Send the same call again in a few seconds.** |
| Key leaves out connected-app documents (D-29) | **This key can't ask the agent: it leaves out mail and synced sources, and the agent's search can't leave them out. To ask, use a key with Include mail and synced sources ticked.** |
| Tool description disclosure (D-30) | the `ask_agent` description ends: **Answers come from the folders this key can read in its organisation. Documents not in a folder are not searched.** |

`get_answer` is listed and callable only with `ask_agent` (305 catalogue `travels_with`, unchanged).

### list_workflows / run_workflow / get_workflow_run

## Surface 6 — The ask's question bubble in the app (D-28, D-32)

The ask's user message is stored inside the TRUST-03 envelope (Pattern 2/4), because the model must
see the envelope on every later turn. In the app the member must see their **question**, not the
scaffolding.

- `outsideAskQuestion(content)` returns the inner text **only when the whole message is exactly one
  MCP ask envelope**: it starts with the opening tag `<external_input source="mcp" field="question">`
  and a newline, and ends with a newline, the closing tag, a newline and a `[SYSTEM NOTICE: …]` block
  (any notice text). Anything else, including 293's `source="api_key"` kickoff envelopes and any
  message a member typed in the app, returns `null` and renders byte-identically to today.
- The inner text is shown verbatim (React text, no un-escaping of the neutralised closing tag).
- ⛔ **One shape, two languages:** the frontend match and the backend writer are pinned by one shared
  literal fixture (a backend test writes it, a frontend test reads the same string), so a wording
  change to the notice cannot silently break the display.
- **The note** (only when `question` is non-null), after the text and after "Read more" when present:
  `mt-2 pt-2 border-t border-white/25 flex items-start gap-1 text-xs text-white`, a `Bot` 12px
  `aria-hidden` icon, then `OUTSIDE_ASK_NOTE`:
  **Asked from an AI tool. In this chat the agent only searches and reads your documents.**
  It is true for the whole thread, including a follow-up typed in the app and a Continue (D-28).
- The 7-line clamp measures the question, not the envelope, so a short question never shows
  "Read more" because of scaffolding it does not display.
- The thread title comes from the raw question (Pattern 2 step 6), never from the envelope.

## How we'd know the UI failed (G-6)

1. Any page throws on a run or thread with `origin.kind = "mcp"` (the `ICONS[kind]` crash).
2. An MCP ask is missing from history after a reload with its org active, or shows with no
   **Started by AI tool key …** line, or an in-app thread gains any second line.
3. The question bubble shows `<external_input`, `[SYSTEM NOTICE` or an empty bubble; or a message a
   member typed in the app is altered.
4. A selected row's origin line turns primary, or the mark uses `KeyRound` instead of `Bot`.
5. The limits card shows 30 / 2 / 4 / 6 before its read answers, sends a cleared field, or saves
   through anything but the shipped Save Integrations; or `SettingsPage.tsx` is edited.
6. An MCP key's activity shows a raw `admission:org`, `ask_needs_external` or `✕ pending`, or ticks
   a refused call.
7. An MCP ask or run reads "No Expert", "Deleted Expert" or "Not recorded" in the spend ledger cell.
8. A tool sentence names a raw status code, exposes the paused run's question, offers a way to
   answer it over MCP, or a link points at `/inbound/files/` for an MCP run.
