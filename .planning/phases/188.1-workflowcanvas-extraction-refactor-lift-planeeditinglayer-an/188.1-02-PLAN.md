Capture the editing affordances' rendered shape from the SHIPPED tree and commit it as a
baseline, so Plan 03's move has something to be identical *to*.

Purpose: SC#2 says the canvas "renders byte-identically before and after". The cheap wrong
way to check that is to hand-type the expected attributes — which proves only what the
author believed the geometry was. The 185-10 idiom is to CAPTURE the rendered DOM from the
tree as it ships and assert the post-move tree reproduces it. The `style` attribute is the
load-bearing part: the `translate(…px, …px)` strings encode every number `EDIT_AFFORDANCE`,
`verticalOffsetFor` and `insertPointX` contribute, so one capture fences almost the entire
moved surface. This must run BEFORE the move — a baseline taken after the move proves
nothing.

Output: an `AFFORDANCE_SHAPE` capture helper, a committed pre-move baseline array, a
determinism proof across two runs, and an extended `BASELINE` pin.
</objective>
