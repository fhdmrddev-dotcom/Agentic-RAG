### Count-gate knob contract (SC#5)

| Knob | Edit required |
|---|---|
| `TARGETS` | **None.** `TARGETS[0]` is the bare directory `src/components/workflows` (`vitest-count-gate.cjs:403`) — both new modules and any new suite are already inside it. Do not edit. |
| `BASELINE` | **EXTENSIONS ONLY, never a lowering.** `WorkflowCanvas.test.tsx` 46 → measured actual · `WorkflowCanvas.editing.test.tsx` 57 → measured actual · `PhaseNodeCard.test.tsx` 105 → measured actual. |

**⚠ Doctrine gap the plan must not walk into.** The gate script's header (`:82-86`) recognises only
**LOWERED** and **EXTENDED** pin movements. A **RELOCATION** (same test, different file) is neither
and presents as `[count-decrease]` plus a `new` file. **Recommendation: relocate no test.** Every
existing assertion reaches `PlaneEditingLayer` *through* `<WorkflowCanvas editable>` (it is not
exported today), and after the move it renders at the same JSX site — so existing suites pass
unchanged. If the plan does relocate a test anyway, it must lower the source pin and raise the
destination pin **in the same commit** keeping `BASELINE_TOTAL` constant, **and** add a third named
case to the script header.

**Rule for every pin number:** read it from the script's own printed `actual` column across **two
agreeing runs** — never from a hand count of `it(` literals (unsound under `it.each`) and never from
a planning document.
