## D-02 / D1 — `WorkflowRunPage.tsx`'s static `WorkflowCanvas` import stays static

**Decision:** do **not** convert it to `lazy()` in this phase. **This is the load-bearing deferral:
the debt is PINNED, not hidden.**

**Why deferred (D-02, `188.1-CONTEXT.md:45-53`):** the conversion needs a `<Suspense>` fallback,
and `ChatLayout.tsx` uses **no** `lazy()` anywhere today — so it would introduce a new visible
loading state on a shipped surface, which is an SC#2 (*zero user-visible change*) violation. The
premise was also declined on **evidence**, not on effort: the ROADMAP called this a *"natural
candidate to fix while the imports are already being moved"*, and research found the promised
code-split is not there to restore.

**The pin — measured at HEAD `c3e4e5c2`, 2026-08-06:**

**⚠ The `[INEFFECTIVE_DYNAMIC_IMPORT]` count is TWO, not one.** Three separate documents in this
phase asserted *"exactly one"* — `188.1-03-PLAN.md`, `188.1-04-PLAN.md` and `188.1-05-PLAN.md`'s

**⚠ A SECOND correction, new in this plan — the research claim is also false.**

**Re-open trigger:** the next phase that (a) touches `WorkflowRunPage`'s render tree for another

state acceptable on the run surface. Carry the three measured figures above as the before-state.

## D-188.1-DEF-02 — `providerLogo.tsx` is an EIGHTH prototype-key lookup — **LOGGED, NOT FIXED**

`frontend/src/lib/providerLogo.tsx:107-108`:

```typescript
  // The `?? null` mirrors fileIcon's `?? DEFAULT_SPEC` — total over any key.
  return provider ? (MARKS[provider] ?? null) : null
```

Byte-for-byte the defect `188.1-04` closed at `lib/phaseGlyph.tsx:92`, **including the same false
*"total over any key"* comment** — one file was written by copying the other. `MARKS` is a plain
object literal, so `MARKS["constructor"]` is the `Object` FUNCTION, `?? null` never fires, and the
caller reaches `createElement(Object, …)` → *"Objects are not valid as a React child"*: a hard
render crash, not a mis-paint.

**Why it was not fixed:** `phaseGlyph` was fixed as a **blocker** — sites 1 and 2's falsifications
physically could not go green while it crashed. `providerLogo` sits on **no path this phase's
falsifications drive**, and `188.1-CONTEXT.md` `<deferred>` is explicit that fixes at prototype-key
sites beyond the five SC#6 names are deferred and routed *"to the next phase touching that file
rather than widening this refactor."* `provider` is also a narrower input than `phase_type`: it comes
from the model registry, not from author-supplied definition JSONB.

**Re-open trigger:** the next phase touching `frontend/src/lib/providerLogo.tsx`, **or** any phase
that lets a user-supplied string reach `providerLogo(...)`. The fix is the same three lines
`phaseGlyph.tsx` now carries, and `fileIcon`'s `?? DEFAULT_SPEC` — which `providerLogo`'s comment
cites as its model — should be **re-measured in the same pass** rather than trusted.
