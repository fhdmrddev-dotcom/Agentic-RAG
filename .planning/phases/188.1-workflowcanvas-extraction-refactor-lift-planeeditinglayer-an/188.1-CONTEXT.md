<decisions>
## Implementation Decisions

### Module shape

- **D-01: Split into TWO modules, not one.** `editAffordance.ts` carries the `EDIT_AFFORDANCE`
  table plus `REVEAL_ON_HOVER`, `insertPointX` and `verticalOffsetFor`; `PlaneEditingLayer.tsx`
  carries the component. Rationale: eslint errors today at `WorkflowCanvas.tsx:365`
  (`react-refresh/only-export-components` on `export const EDIT_AFFORDANCE`), and that error
  follows the constant into any `.tsx` file. A `.ts` home eliminates it at zero behavioural
  cost — `eslint src/components/workflows/` must go from **2 errors to 1**. This deliberately
  reads SC#1's "their own module" as *their own module boundary*, not a literal single file;
  the widening is recorded here so it is auditable rather than silent.

### Lazy-import debt

- **D-02: Do NOT convert `WorkflowRunPage.tsx`'s static `WorkflowCanvas` import to `lazy()` in
  this phase. Defer it, and pin the current `[INEFFECTIVE_DYNAMIC_IMPORT]` warning count as a
  gate instead** so the debt stays visible and cannot get worse, with a concrete re-open
  trigger. Rationale: `ChatLayout.tsx` uses no `lazy()` anywhere, so the conversion requires a
  new `<Suspense>` fallback — a visible loading state, which violates SC#2. Research also found
  the premise is unreproducible as stated: `vite build` emits `[INEFFECTIVE_DYNAMIC_IMPORT]`,
  **no `WorkflowCanvas-*.js` chunk exists at all**, and `index-*.js` is 2,041 kB. The ROADMAP's
  "natural candidate to fix while the imports are already being moved" is therefore declined on
  evidence, not on effort.

### Claude's Discretion

- The precise shape of the Wave 0 fences (cycle fence, `AFFORDANCE_SHAPE` capture, WR-04

- Which of the five WR-04 sites need `Object.hasOwn(...) ? ... : ...` versus another own-guard

</decisions>

**Hard constraints carried from research:**

1. **The seam is provably cycle-free.** `PlaneEditingLayer` is a module-scope function component
   that closes over **nothing** — all ten inputs are props. It plus `EDIT_AFFORDANCE`,
   `REVEAL_ON_HOVER`, `insertPointX`, `verticalOffsetFor` form two contiguous regions
   (`346–413`, `486–728`, **311 lines**) whose transitive value-import closure does not contain
   `WorkflowCanvas`. SC#3 holds by construction.
2. **`FlowEdge.tsx` does NOT import `EDIT_AFFORDANCE`** — its four mentions are prose explaining
   why it deliberately doesn't. `FlowEdge.test.tsx:75` is the tree's only importer.
3. **`noUnusedLocals: true`** — exactly three imports must be dropped from `WorkflowCanvas.tsx`
   (`CANVAS_LAYOUT`, `ViewportPortal`, `useStore as useFlowStore`) and **no others**.
4. **`PhaseNodeCard.test.tsx:373` is a positive control** requiring the literal `ICON_TINT[`
   form in `PhaseNode.tsx`. The obvious WR-04 fix `own(ICON_TINT, …)` turns it **red**;
   `Object.hasOwn(…) ? … : …` keeps it green. `own()` is also **not exported** and is typed to
   `CanvasReading` — SC#6's "route through `own()`" is not a drop-in.
5. **SC#5's real hazard is not the count gate.** Eight `?raw` negative assertions across
   `WorkflowCanvas.test.tsx` and `WorkflowCanvas.composition.test.tsx` grep
   `WorkflowCanvas?raw`; after the move all eight stay **green while covering 311 fewer lines**.
   That is Phase 188's F7 lesson in a new dress and must be closed in Wave 0.
6. **Relocate no test.** The gate script recognises only LOWERED and EXTENDED pin movements —
   RELOCATION is neither and presents as `[count-decrease]` plus a `new` file. Every existing
   assertion reaches `PlaneEditingLayer` *through* `<WorkflowCanvas editable>`, so existing
   suites pass unchanged.
7. **`TARGETS` needs no edit** — `TARGETS[0]` is the bare directory `src/components/workflows`.
   `BASELINE` takes **extensions only, never a lowering**.
