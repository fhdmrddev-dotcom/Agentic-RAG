## S-A — The found-nothing pause (PendingAskCard)

**Visual anchor:** the amber `Needs you` card pinned at the top of the panel. The person's eye lands on the prompt sentence and the three stacked choice chips beneath it, the way the shipped human-step pause reads today.

### A.1 Layout (unchanged pending arm, top to bottom)

1. Amber label row: dot + `Needs you` (assertive) + countdown `m:ss` on the right — **existing**.
2. Wait line slot (one of): `NO_DEADLINE_WAITING_LINE` (armed approval, no deadline) · `PAUSED_WAITING_LINE` (window passed) — **existing strings**, see A.4.
3. `DraftBlock` — **existing**. Decided (auto): the server sends the output the step produced as `ask.draft`, so the person SEES what "Continue without sources" would keep before choosing it. Label stays the shipped `DRAFT · awaiting your review — not yet saved` (true: nothing is accepted until they answer).
4. Prompt paragraph (`text-sm`, `id={labelId}`) — server-built, rendered as a text child.
5. Choice chips (`role="radiogroup"` / `role="radio"`, roving tabindex, 44px min height) — **existing**, labels server-built.
6. **NEW — `AskFolderChoice` leaf**, rendered directly beneath the chips ONLY while the "Search another folder" chip is selected (A.3).
7. `or` divider + `Reason` free-text + `Send Answer` — **existing**. Free text stays present (pending-question D3); for an engine pause it is an optional note recorded with the answer, never read as a choice.

### A.2 Server-built prompt and choices (render verbatim; the card composes nothing)

`{folder}` = the step's bound folder name, else `the knowledge base` (the 289 `kb_label` rule). `{step}` = the step's human title (`phase.name`, else slug), in curly quotes.

| Finding | `ask.prompt` (one line, two sentences) |
|---------|----------------------------------------|
| 0 sources retrieved | `Searched {folder} and found nothing for “{step}”. How should the run continue?` |
| 0 citation markers | `“{step}” answered without citing its sources in {folder}. How should the run continue?` |
| Either finding, locked step (`escalated` / `already-set`) | the finding sentence + ` This step is set to Must prove it, so it can't continue without sources.` + ` How should the run continue?` |

`ask.options`, fixed order, exactly these labels:

| Index | Label | Offered when |
|-------|-------|--------------|
| 0 | `Search another folder` | at least one OTHER folder is permitted by D-03's bound (the already-searched folder is excluded) |
| 1 | `Continue without sources` | grounding cause is `detected` only (D-05) — absent server-side for a locked step |
| 2 | `Stop the run` | always |

Indices are positional over what is offered (an absent option is removed, not blanked). The chip set is never re-ordered by the client.

**Decided (auto) — a one-choice pause is not a pause.** If the only option left is `Stop the run` (locked step AND no other permitted folder), the engine does not pause: it fails the step with the worded finding plus `No other folder is available to search, and this step is set to Must prove it, so the run stopped.` A question with one answer is a dead-end dressed as a decision — the same rule as D-03's "a dead option is worse than a missing one". Planner: confirm against RUN-01 in research; re-open by editing this line.

**Never on this card:** `citations_required`, `0/N`, `markers`, `validator`, `gate`, any code or raw validator message, "Proceed anyway", "Abort", "Proven". (The validator strings in `validator_kinds.py:293-343` are code-prefixed and must not reach `ask.prompt`.)

### A.3 `AskFolderChoice` — the folder chooser (new leaf, reuses the shipped Select pattern)

**Reused component (named):** the shadcn `Select` pattern exactly as `components/health/MoveToFolderDialog.tsx` renders it (`SelectTrigger` + `SelectValue placeholder` + one `SelectItem` per folder). **Not reused, and why:** `MoveToFolderDialog` itself (calls `moveDocument`, fetches `listFolders()`), `DescribeKbPicker` (fetches `listFolders()`), `FolderTree` (library nav with counts/actions) and `SourceFolderPicker` (cloud sources). All four read the user's WHOLE folder list client-side, which would widen access past D-03's bound. The leaf fetches nothing: its rows come ONLY from the server's bounded list on the prompt.

| Element | Contract |
|---------|----------|
| Data | `ask.engine_pause.folders: {id, name, depth}[]` — server-bounded by `scope.resolve_run_scope_root` + the author's subtree, already-searched folder removed. The leaf renders this list and nothing else. |
| Label (visible, `htmlFor`-tied) | `Folder to search` — 12px, weight 600, uppercase, `--muted-foreground-dim` (the shipped `Reason` label's 11px is inherited and not re-specified) |
| Trigger | full width, `min-h-[44px]`, 14px text (the shipped shadcn `SelectTrigger` `text-sm`), placeholder `Choose a folder…` |
| Items | folder NAME only (never a path, never an id — the Builder's `folder_scope` rule), 14px (shipped `SelectItem` `text-sm`), indented 16px per depth level; a nameless row is dropped, never rendered blank |
| Helper line (12px, muted) | `The step runs once more, searching only this folder. The workflow itself is not changed.` |
| Selection home | the shared `askDraftStore` keyed by `tool_call_id` (282-02's one-draft rule), so the chat pointer and the panel card never disagree |
| Submit gating | `Send Answer` stays disabled until a folder is chosen while this chip is selected |
| Answer body | the existing `answerAskUser` call carries `choice_index` + optional `folder_id`; the server allow-lists both |

### A.4 States (both homes; the card reads ONE new optional field, `ask.engine_pause`)

| State | Header | Wait line slot | Controls | Source |
|-------|--------|----------------|----------|--------|
| Pending, within window | `Needs you` + `m:ss` | — | chips + (folder) + Reason + `Send Answer` | existing |
| Pending, window passed (engine pause) | `Needs you`, clock hidden | `The answer window has passed. The run is paused and still waiting for your answer.` (`PAUSED_WAITING_LINE`, verbatim) | **all controls stay live** | 289 D-13 line; 295 makes it reachable in the PANEL home |
| Armed approval (no deadline) | `Needs you`, no clock | `No deadline — the run is waiting for your answer and will not continue on its own` (`NO_DEADLINE_WAITING_LINE`) | existing | unchanged (D-18) |
| Answered — search / continue | `Answered · agent resumed` (green) | — | `You answered Search another folder — {folder name}` / `You answered Continue without sources` | existing arm, value from the leaf |
| Answered — stop | `Answered · run stopped` (green border, same arm) | — | `You answered Stop the run` | decided (auto): "agent resumed" would be false for Stop |
| Retired (run cancelled while waiting) | `Retired` | `The run was stopped, so this question no longer needs an answer` (`RUN_STOPPED_RETIREMENT_LINE`) | dead `Send Answer` | existing (D-19 reaches it) |
| Expired | **never by clock for an engine pause** — only via the server's 404/409 (`This prompt has expired — the run is no longer active` / `This run has already ended — your answer was not saved`) | — | — | existing |

**The window rule (binding, D-01).** "Window passed" is a fact about TIME (`created_at + timeout_seconds`), not about `runs.status`. If the engine flips the run to `paused` at the moment it asks, then the run page's `paused` prop and the server's `waiting_on.window_passed` must NOT be read as "window passed" for an engine pause — otherwise the card and the band would say *"The answer window has passed"* the instant the question appears. Contract: the clock shows until it reaches 0; only then does `PAUSED_WAITING_LINE` replace it, in BOTH homes; the card never retires or expires by clock while `ask.engine_pause` is present.

**Panel gap closed.** Today `PendingAskStack` passes no `paused` (289-01 named gap), so a panel card hitting 0:00 reads `No response within 5:00 — agent stopped` — false for a durable pause. `ask.engine_pause` is present on BOTH the SSE and GET payloads, so the panel card stays answerable without the stack deriving anything.

### A.5 Run band and step reading while paused (no frontend change)

- Run band: `Paused for your answer` (existing `waiting` tone) followed by the server's `WaitingOnLine` sentence — within window `Waiting on {name} (you) to answer "{prompt first line}".`, after window `Still waiting on {name} (you); the run continues as soon as they answer.` (`compose_waiting_on`, unchanged).
- The paused KB step reads `Paused for your answer` on the canvas/spine through the existing `waiting-for-you` reading — the server associates the prompt with the KB phase (`phase.pendingAsk`). No new reading, no new status, no `runVocabulary.ts` edit.

## S-B — The unsourced mark

**Visual anchor:** the bordered amber `◌ Unsourced` chip on its own line under the step's evidence sentence, so a step kept without sources never looks like a quiet completed step.

### B.1 Anatomy (one new arm on `StepEvidenceLine`, the 028 / 289 chip anatomy)

```
◌ Unsourced · continued by Fahad Murad (you)
This output was kept without sources — it does not cite your documents.
```

| Part | Contract |
|------|----------|
| Chip | `[◌ aria-hidden] + Unsourced` — `CHIP_BASE` (mono 10px, rounded-full, `px-2 py-0.5`), tone `bg-[hsl(var(--warning)/0.12)] text-[hsl(var(--warning))]` plus `border border-[hsl(var(--warning)/0.4)]` |
| Sentence | `· continued by {name}` — `text-xs leading-5 text-muted-foreground`, name in `text-foreground` at weight 400 (no 500 on new text; the shipped 289 `kb_label` keeps its inherited `font-medium`) |
| Note | `This output was kept without sources — it does not cite your documents.` — `text-xs italic text-muted-foreground`, the `step-evidence-note` register |
| Placement | on its own line directly BELOW the confidence sentence when both exist; renders alone when the step has no confidence object |
| Data | ONE optional phase-output field `unsourced: { continued_by: string; at: string } | null` (D-04, the 289 D-08 pattern). `at` is the ISO-8601 timestamp of the choice (D-04: "who chose it and when"). The line does not render it, because the step log's Time column already gives the time, but the export carries it. `continued_by` is resolved SERVER-SIDE and viewer-aware, like `compose_waiting_on`: the owner reads `{display name} (you)`; anyone else reads `the person who started this run`. The client renders it verbatim. |
| Absence | `unsourced` null/absent → the arm renders NOTHING (289 D-09 "absence is absence") |

**Glyph decided (auto): `◌` (U+25CC, dotted circle), not `○`.** `○` already means "searched, nothing matched" on the same line (`CONFIDENCE_FACE.none`), and in the 0-sources case both marks stack. One glyph for two facts is the icon-convention violation ("the same concept is byte-identical everywhere" implies different concepts differ). Record `◌` as a NET-NEW proposal against `references/icon-convention.md`, exactly as 289 recorded `○`.

**Tone decided (auto): amber, bordered.** Not red (a person's legitimate choice, not a failure); not muted (the roadmap's first failure mode is "continue without sources becomes a silent pass" — a quiet grey mark is that failure in miniature).

| Receipt / export | The evidence page IS the receipt (289); "Print / save as PDF" prints the mark; "Download JSON" carries `unsourced` on the phase object untouched, with BOTH `continued_by` and `at` | no extra UI |

**Content assertions (binding — presence assertions miss content drift):** each place's test asserts the rendered TEXT `Unsourced` AND `continued by` AND the note sentence, not a `data-testid`. The G-4 S2 drive reads the same three strings off the live DOM and the downloaded JSON.
