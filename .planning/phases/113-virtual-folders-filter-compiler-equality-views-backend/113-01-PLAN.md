<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (JWT) → /document-views save | Untrusted `filter_expr` AST crosses here — field names + values are attacker-controlled |
| compiled metadata_filter → supabase-py builder | The compiler output feeds `.contains("metadata", dict)` (param-bound) in Plan 03 — the value must remain inert data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-01 | Tampering (SQLi) | `view_filter_compiler.compile_filter` (value handling) | mitigate | Values are folded into a dict and (in Plan 03) bound as one `$1::jsonb` via `.contains()`; the compiler NEVER interpolates a value into SQL or a JSON literal string. `test_injection_value_neutralized` asserts a SQLi payload compiles to the literal value (SC#4). |
| T-113-02 | Tampering (SSTI) | `view_filter_compiler` value handling | mitigate | Values are JSON data matched by `@>`, never rendered/templated. The injection test includes a `{{7*7}}`/`${jndi:...}` payload that must survive byte-for-byte (SC#4). |
| T-113-03 | Tampering (field-name injection) | `view_filter_compiler.validate_fields` | mitigate | Field names validated against a whitelist (built-ins ∪ enabled defs, assembled in Plan 03); `_`-prefixed keys rejected at save. `test_underscore_field_excluded` + `test_unknown_field_rejected_at_save` assert. |
| T-113-04 | Tampering (unknown-op smuggling) | AST `Literal` discriminator + `OPERATOR_REGISTRY` | mitigate | Pydantic `Literal["eq"]`/`Literal["and"]` rejects an unknown op at parse; `compile_filter` raises `KeyError` on an unregistered op (fail-closed defense-in-depth). Never `eval`/`getattr`/dynamic-import. `test_unknown_op_rejected` asserts both layers. |
| T-113-05 | Information Disclosure | `_`-prefixed key as a filter dimension | mitigate | `_confidence`/`_source` excluded from the whitelist + rejected at save (D-111-9/D-112-D02). They are display-only nested keys, never filterable. |
</threat_model>
