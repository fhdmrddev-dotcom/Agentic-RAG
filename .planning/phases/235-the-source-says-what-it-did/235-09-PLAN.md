<objective>
Put the signal where a person already is — on any page, at both rail widths, and on mobile.

Purpose: SURF-03's sentence is *"a broken watch reaches a person who is not already looking at the page"*, and
`REQUIREMENTS.md` records that there is no in-app notification surface in this product — the requirement was
written to NAME that gap. D-235-01 forces the answer: a shell signal, plus the Health detail. D-235-03 forces
its shape: a general surface with exactly one tenant, so the next notification need plugs in rather than growing
a sibling surface — the two-paths-one-outcome shape this codebase has shipped five times.

⛔ **The mobile decision, taken explicitly rather than by omission.** `NavPanel.tsx:121` is `hidden md:flex`.
Closing SURF-03 against a desktop-only badge would close it against its own sentence — the same class of error
D-235-01 already rejected once for the Health tab. This plan therefore **SOLVES mobile** on the surfaces that
exist: the drawer's Library nav button carries the same badge, and the drawer-OPENING control carries a dot so a
closed drawer still signals. The residual gap (measured: `onOpenDrawer` is passed only to `ChatArea` at
`ChatLayout.tsx:738`, so a mobile user on a non-chat view has no drawer trigger at all) is a PRE-EXISTING
navigation gap this phase did not create; it is recorded with a named trigger, not glossed.

Output: a generic badge slot, a one-tenant producer registry, a popover that is a door, and a mobile home.
</objective>
