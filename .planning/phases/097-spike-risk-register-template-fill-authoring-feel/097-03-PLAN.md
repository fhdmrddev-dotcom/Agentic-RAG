from docxtpl import DocxTemplate
from jinja2.sandbox import SandboxedEnvironment
def render(template_path, context, out_path):
    doc = DocxTemplate(template_path)
    jenv = SandboxedEnvironment(autoescape=True)   # SSTI containment + XML-safe (&<>) values

Coverage oracle + integrity re-open:
```python
from docxtpl import DocxTemplate
from docx import Document
def required_keys(template_path): return DocxTemplate(template_path).get_undeclared_template_variables()
def assert_integrity(out_path, expect_min_rows):
    doc = Document(out_path)                        # raises if corrupt / won't open
    rows = sum(len(t.rows) for t in doc.tables)
    return {"opened": True, "tables": len(doc.tables), "rows": rows, "rows_ok": rows >= expect_min_rows}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Jinja .docx template → server-side render | docxtpl renders Jinja SERVER-SIDE — a malicious template is textbook SSTI→RCE (GHSA-v5gf-r78h-55q6). The spike template is trusted, but the containment pattern must be proven for Phase 101's untrusted-upload path. |
| field-map values → OOXML | Untrusted KB-derived strings (`&<>`, control chars) injected into XML can corrupt the document. |
| produced file → user | A corrupt/unopenable file must NEVER be delivered as "done". |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-097-08 | Elevation of Privilege (SSTI→RCE) | docxtpl render path (LOAD-BEARING) | mitigate | `doc.render(jinja_env=SandboxedEnvironment(autoescape=True))` — the maintained sandbox env blocks attribute/builtin access; production render also runs in the sealed network-less Docker sandbox (Phase 101); Jinja reserved for trusted library templates only (arbitrary uploads use the non-Jinja run-replace path). |
| T-097-09 | Tampering (XML corruption) | unescaped `&<>` in field values | mitigate | `autoescape=True` on the SandboxedEnvironment; the `&<>` probe row asserts the file still re-opens (Pitfall 2). |
| T-097-10 | Denial of Service / integrity | corrupt or won't-open output | mitigate | Mandatory `Document(out)` re-open gate (Pitfall 3) — a failing reparse marks the run corrupt and never delivers; previews the `output_file_valid` gate. |
| T-097-11 | Tampering (silent non-fill) | run-split / residual placeholder | mitigate | Residual-tag scan asserts no `{{`/`{%`/literal placeholder remains (Pitfall 1); docxtpl tags are run-safe by design (recorded as the rationale). |
</threat_model>
