<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| KB content → LLM context | Retrieved chunks are untrusted text; a malicious chunk could attempt indirect prompt injection (EchoLeak class) to make the model invent/exfiltrate. |
| LLM output → field-map | The model's emission is untrusted until validated by Pydantic + the deterministic coverage/citation check. |
| spike-config folder scope → retrieval | The bound `folder_ids` is the security boundary that keeps the fill inside the user's confirmed corpus. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-097-04 | Tampering (indirect prompt injection) | KB chunks in the field-map prompt | mitigate | Spotlight each chunk in `<doc id=... file=...>` delimiters (report E mode 7); the field-map phase is READ-ONLY (no outbound/exfil tool); system framing forbids inventing. |
| T-097-05 | Tampering (data integrity) | hallucinated / uncited register rows | mitigate | Deterministic coverage+citation check: every non-null value must carry a `source_chunk_id` that was actually retrieved; re-prompt once on failure (previews citations_required, Pitfall 6). |
| T-097-06 | Information Disclosure | retrieval beyond bound scope | mitigate | `search_documents(folder_ids=cfg.subtree_folder_ids)` is a bound server-side parameter, not a prompt hint (Pattern 2); RLS is the backstop at the DB layer. |
| T-097-07 | Spoofing | invented citation pointing at a non-retrieved chunk | mitigate | The check asserts each cited `source_chunk_id` was present in the retrieved set, not merely non-null. |
</threat_model>
