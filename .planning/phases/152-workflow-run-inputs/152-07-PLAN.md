<objective>
Close three frontend Warnings on the shipped Run modal + launch path, WITHOUT re-planning 152-03 (its code stays; this corrects honesty + hygiene on top).

WR-05: the Run modal's "All documents" option is DISHONEST for a bound workflow — selecting it sends `folderId: null`, which the server resolves to the AUTHOR DEFAULT (the override channel is narrow-only by design, D-06). Worse, when the author-default folder isn't in the runner's visible `folders`, the select DEFAULTS to "All documents" while the run is actually author-scoped. Fix: for a bound workflow, make the `""` option read "Workflow default" (with the folder name when known); offer a literal "All documents" ONLY on unbound workflows.

WR-03 (frontend mirror): the `overrideOptions` filter only checks membership in the whole author subtree, so the UI can still offer a folder that empties a declared phase's `folder_scope` intersection. Fix: mirror the backend A4 per-phase rule (152-06) — drop an override option unless every declared phase `folder_scope` intersects that option's subtree.

WR-04: a failed launch (422 upload or postMessage failure) strands the `createThread` shell, and every retry mints another. Fix: wrap upload+postMessage in try/catch, best-effort `deleteThread(thread.id)` before re-throwing (preserving the verbatim-422 the modal renders).

Purpose: the modal's only scope indicator is honest, never offers a scope that empties retrieval, and a failed launch leaves no orphan thread.
Output: truthful scope labelling + per-phase override filter + orphan-thread cleanup, each test-locked.

NOTE: the backend A4 authority is 152-06 (scope.py) — a DIFFERENT file. This plan is the client mirror; no file collision. WorkflowsPage.tsx is touched by BOTH WR-05 (Task 1) and WR-03-mirror (Task 2), so both live in THIS one plan (constraint #4).
</objective>
