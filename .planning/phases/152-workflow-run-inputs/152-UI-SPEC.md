## Spacing Scale

The app uses **Tailwind's 4px-based scale** (`0.25rem` unit). Core tokens (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `p-1`) | Icon-to-label gaps, chip inner padding |
| sm | 8px (`gap-2`, `px-2`) | Compact control spacing (modal action-row buttons, chip rows) |
| md | 12px (`gap-3`, `py-3`, `px-3`) | Stacked field spacing inside the modal body; sheet section gaps |
| lg | 16px (`px-4`, `py-4`) | Modal/sheet body padding, header/footer padding |
| xl | 24px | Between the Removed and Kept groups in the delete sheet |
| 2xl | 32px | (not needed at this dialog scale) |

Exceptions (inherited from the shipped surfaces this phase extends — do NOT introduce a divergent scale): Tailwind half-steps **6px (`1.5`)**, **10px (`2.5`)**, **14px (`3.5`)** are used pervasively for button padding (`px-2.5 py-1.5`), the version chip, and the file card. This phase MUST match `RunModal` / `PublishedCard` / `ActiveRunsSection` exactly, so these half-steps are the established, consistent system — not arbitrary values.

## Typography

Sizes are from the live components this phase extends; keep them so the new controls read as native.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Title | 15px (`text-[15px]`) | Semibold 600 | 1.3 | Modal header (workflow name), delete-sheet title |
| Body | 14px (`text-[14px]` / `text-sm`) | Regular 400 | 1.5 | Kickoff textarea, scope-select value, Removed/Kept sentence copy |
| Control / Label | 13px (`text-[13px]`) | Medium 500 | 1.4 | Buttons (Run, Cancel, Tweak, Delete), field labels ("What should this run work on?") |
| Meta / Caption | 12px (`text-[12px]` / `text-xs`) | Regular 400 | 1.4 | Folder chip, `input_keys` hint, **provenance note**, footer, recorded-with-your-name line |

Micro-caption 11px (`text-[11px]`) is reserved for the mono version chip and inline error text (matches `PublishedCard` v-chip + `TemplateUpload` error) — a documented meta variant, not a new role.

**Weights:** two load-bearing weights — **Regular 400** (all body/meta) and **Semibold 600** (titles, the emphasized workflow name, the danger button label). **Medium 500** is the inherited interactive-control weight (buttons + field labels) already used across `RunModal`/`PublishedCard`; keep it for byte-consistency rather than re-weighting shipped controls. Mono (JetBrains) carries counts/versions/`input_keys`/elapsed at Regular 400.

## Component Inventory & Interaction Contract

> For the planner/executor — the concrete build, keyed to the LOCKED sketch shapes. This is the visual source of truth.

### 1. RunModal scope `<select>` (WFIN-02, D-LOCK-01)
- Replace the read-only `run-folder-chip` (`WorkflowsPage.tsx:795`) with a native `<select>` styled to match `ChatArea.tsx:410` (`rounded-md border border-border bg-card ... focus:ring-primary/30`) so it reads as a native chat-scope control, NOT a heavier shadcn `Select` popover (byte-match the app's existing scope UX; keep the modal's 3-second read).
- Options, in order: `All documents` (value `""`) → `📁 {authorDefaultFolder} — workflow default` (the definition's `project_folder_id`) → then every other owner-reachable folder `📁 {name}`.
- Default selection = the workflow's author default (or "All documents" if the definition has no `project_folder_id`). A change to any other option = a per-run override; keep the "workflow default" tag on that one option so the author binding is always legible.
- Constraint reflection (RESEARCH A4 / composition landmine): if the workflow declares per-phase `folder_scope`, the `<select>` MUST only offer folders ⊆ the author `project_folder_id` (out-of-project options would silently empty the run). The planner picks the exact filter; the UI must not offer an option that produces empty retrieval.
- NOT a segmented 3-way toggle (documented SEED-112 fallback B — rejected), NOT a side panel (fallback C — rejected).

### 2. RunModal template upload (WFIN-01, D-LOCK-02)
- A quiet, self-start bordered button below the kickoff textarea: `Upload template` with a lucide `Upload` glyph (reuse the `TemplateUpload` button styling verbatim — `border-border px-2.5 py-1.5 text-[12px]`).
- States: idle → `Uploading…` (disabled) → validated file card (`{filename}` + `✓` + remove `✕`) → OR inline 422 error (`text-destructive`, `role="alert"`, server message verbatim), nothing persisted.
- Directly beneath: the 12px muted provenance note (copy above). It is honesty, not decoration — keep it quiet (muted-foreground), never a loud banner.
- The upload is a real run input, sequenced createThread → upload_template(newThread) → sendMessage (per RESEARCH); the modal orchestrates order, the server stamps `kind='template_input'`.

### 3. PublishedCard `⋯` menu (WFIN-03 entry point — NET-NEW, resolves the RESEARCH correction)
- **Research Pitfall 8 is real:** `PublishedCard` has ONLY `⑂ Tweak` + `▶ Run` today — there is NO `⋯` menu. This contract makes the delete entry point net-new UI.
- Add a lucide `MoreHorizontal` icon button to the card header, top-right, immediately left of the `published` pill. Neutral treatment: `text-muted-foreground hover:text-foreground`, `aria-label="Workflow actions"`, min 32px hit target.
- It opens `@/components/ui/dropdown-menu` (already installed — shadcn official, no registry add) anchored to the button, containing a single item: `Delete workflow…` (destructive-tinted text, lucide `Trash2` optional). The item opens the victim-naming Sheet.
- The footer `⑂ Tweak` / `▶ Run` pair is UNCHANGED — the primary card actions stay where they are.

### 4. Victim-naming delete Sheet (WFIN-03, D-LOCK-03/04/05 — 073-A / 064-B pattern)
- Reuse `@/components/ui/sheet` with `side="bottom"`, `className="mx-auto max-w-lg"` — the SAME shape as the shipped `ActiveRunsSection` Kill sheet, so the delete reads as the established operator confirm vocabulary.
- Structure: `SheetHeader`/`SheetTitle` "Delete this workflow?" → the **Removed** group (danger-tinted heading + exact counts) → the **Kept** group (neutral heading + the reassurance sentence) → the amber in-flight banner (only when a run is live) → action row (`Keep it` neutral · `Delete forever` destructive) → the `✎ Recorded with your name` footer.
- Counts come from a server preview read before commit (RESEARCH: `GET .../delete-preview` or a dry-run — planner picks the shape). Do NOT render the sheet with placeholder/guessed counts.
- Lifecycle in place (no optimistic card removal): `Delete forever` → `Deleting…` (spinner, `role="status"`) → `Deleted · recorded` (✓, `--success`) → list re-fetch. Error → "Couldn't delete the workflow" + Try again.
- NOT type-to-confirm (fallback B — rejected), NOT archive-vs-delete two-door (fallback C — rejected).

### States matrix (every net-new control declares all states)

| Surface | idle | loading | success | error | empty/absent |
|---------|------|---------|---------|-------|--------------|
| Scope `<select>` | shows author default tagged "workflow default" | n/a (folders load with the page) | override selected | folders fetch fail → "All documents" only + keep enabled | no folders → the whole control hides (matches `ChatArea` `folders.length > 0` guard) |
| Template upload | `Upload template` button | `Uploading…` disabled | file card `{name} ✓ ✕` | inline 422 `role="alert"`, verbatim | none → today's behavior (D-06) |
| `⋯` menu | neutral icon button | n/a | opens menu | n/a | always present on published cards |
| Delete sheet | Removed/Kept groups + counts | `Deleting…` `role="status"` | `Deleted · recorded` ✓ | "Couldn't delete" + Try again | 0 threads → "No chat threads to keep." |

### Accessibility (inherited bar — this milestone ships Phase 155 WCAG AA sweep)
- The Run modal's shipped focus trap + Escape-to-close + initial-focus contract (`WorkflowsPage.tsx:738-777`) MUST survive the new controls; the `<select>`, upload button, and file-remove `✕` are all in the Tab order (already covered by the existing `querySelectorAll` trap that includes `select`).
- All icon-only controls carry `aria-label` (`⋯` = "Workflow actions", remove `✕` = "Remove template").
- `role="alert"` on the upload error; `role="status"` on the delete lifecycle line; the `Sheet` brings focus-trap/restore for free.
- Meaningful text uses the panel/AA tokens (≥4.5:1) — the muted provenance note and counts must clear contrast on `--card`; do not use the dimmest global muted for load-bearing copy.
