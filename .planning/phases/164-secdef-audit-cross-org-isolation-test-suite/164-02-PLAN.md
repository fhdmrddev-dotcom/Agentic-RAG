<objective>
Close SEED-091 (TEN-06): global / org-shared resources (folders / skills / views) must null the seeding owner's `user_id` (and the scope UUID for views) for non-owner readers in EVERY list/serialize path. RLS gates rows, not columns — this is a serialize-time projection concern, applied uniformly across the three surfaces so the serialization contract cannot diverge.

Purpose: The practically cross-org-visible surface today is `is_system` platform content (the seeded skill-creator, owned by the seeding admin). Nulling on `is_global OR is_system` AND not-owner covers both the system-global leak now and the org-shared case later — no org-awareness branch needed (D-164-05).
Output: null-on-non-owner in skills / views / folders serialize paths + two model loosens + a unit-test proof.

This plan is INDEPENDENT of the SQL/migration and retrieval work (disjoint files except `kb.py`, whose serialize edit here is in an earlier wave than the grep edit in Plan 04). It self-verifies via a pure unit test (no live DB).
</objective>
