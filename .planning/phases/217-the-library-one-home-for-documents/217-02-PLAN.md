<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `GET /documents/{id}/{content,chunks,tables,images}` | untrusted `document_id` from the request crosses into four SQL reads over user data |
| document content -> response body | `document_tables.rows` and `document_chunks.content` are untrusted document text leaving the server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-217-04 | Elevation of privilege | the four new routes | mitigate | `Depends(get_user_supabase_client)` so RLS applies, PLUS `_assert_document_visible` filtering on `current_user["id"]` in app code. The `document_id` is never trusted as an authorization claim — it selects a row that the ownership filter must also match |
| T-217-05 | Information disclosure | 404-vs-empty-200 | mitigate | A document the caller cannot see is `404`, never an empty `200`. An empty 200 tells the caller the id exists. Asserted per route in task 3 |
| T-217-06 | Information disclosure | the RLS asymmetry | accept | `document_tables` / `document_images` are owner-only by migration `108:180-189`; a shared-folder document therefore returns `[]`. This is TIGHTER than the caller's other reads, so it leaks nothing. Widening it is explicitly out of scope |
| T-217-07 | Denial of service | `/content` on a large `full_markdown` | mitigate | Line-range slicing with `Query(ge=1)` bounds, and a measured worst case recorded in task 1. A caller cannot request an unbounded body without paging |
| T-217-08 | Denial of service | blocking the event loop | mitigate | every query through `await aexec(...)`; asserted by the task-3 source fence, not by review |
| T-217-09 | Injection | `document_id` in the query | mitigate | supabase-py parameterizes `.eq()`; no string interpolation into SQL anywhere in the four routes. `coerce_uid` is used for any `.or_()` filter that interpolates a user id |
| T-217-SC | Tampering | npm/pip/cargo installs | mitigate | No package installed by this plan; the Package Legitimacy Gate is inapplicable by measurement |
</threat_model>
