**A single "Built-in" pill in `SkillCard` (shown instead of "Global" for system skills) driven by a new output-only `Skill.is_system` wire field, plus a fresh component test proving the pill and the read-only owner-action reflection.**

- `Skill.is_system: boolean` added to the frontend read type — deliberately absent from `SkillCreate`/`SkillUpdate` so the client can never spoof the badge (T-137.2-02).

- Zero new authorization/guard code — the read-only protection reuses the existing `isOwner` check (T-137.2-01 reflect-not-enforce).

## Decisions Made
- **Built-in tint vs strict parity:** used the RESEARCH Example #5 tint (`text-primary bg-primary/10`) to distinguish the trust badge from the muted Global pill. The one-pill (XOR) call is the load-bearing decision; tint is CONTEXT.md discretion.
- **Owner-action assertion via lucide icon classes:** the owner-only buttons (edit/delete/share/export) carry a lucide icon and no accessible name, so the test asserts on lucide-react v0.577's stable `lucide-pencil` / `lucide-trash-2` / `lucide-globe` / `lucide-download` marker classes (each appears only inside the owner block). Verified the class-construction path in `createLucideIcon.js` before relying on it.
- **Requirements marking left to the orchestrator:** did NOT modify `REQUIREMENTS.md`/`STATE.md`/`ROADMAP.md` — CREATE-01 spans all four 137.2 plans and this is a parallel wave; the orchestrator marks it post-merge to avoid conflicts.

## Issues Encountered

**Worktree had no `node_modules` (verification-blocking, resolved).** `npx tsc`/`npx vitest` initially tried to fetch TypeScript from the network because the isolated worktree checkout has no installed dependencies (gitignored, not copied into worktrees). Resolved by confirming `frontend/package.json` is byte-identical to the main checkout, then creating a directory junction from the worktree's `frontend/node_modules` to the main checkout's already-installed, already-vetted `frontend/node_modules` (PowerShell `New-Item -ItemType Junction`). This is a worktree-local environment step — NOT a package install of a new dependency and NOT a code change; the junction is gitignored and disappears when the orchestrator force-removes the worktree. After the junction, `tsc --noEmit` and the SkillCard test suite ran clean.
