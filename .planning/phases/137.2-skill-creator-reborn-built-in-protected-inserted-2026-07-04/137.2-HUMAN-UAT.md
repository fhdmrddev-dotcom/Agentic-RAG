## Tests

### 1. Live conversational walkthrough (SC#4 / G-4)
expected: Start a fresh chat on a tool-capable provider (OpenAI, Anthropic, or Google — pick one to start; a light second-provider glance is recommended since the instructions are consumed by every provider's agent loop). Say something like "help me create a skill for summarizing project briefs" (or any real task). The agent should: (1) interview before drafting (asks about the task, inputs/outputs, "good" criteria, trigger condition) rather than jumping straight to a draft; (2) call `search_documents` at some point to ground the draft in the user's actual knowledge base; (3) call `save_skill` and confirm to the user that it saved; (4) propose 2-3 concrete eval cases as chat text and explicitly direct the user to open Skill Studio → Evals to add them (never claim to create an eval case itself via a tool); (5) at no point claim it spawned a sub-agent, used a browser, shelled out to `claude -p`, or ran a non-Python script.
result: 3 attempts total, 2 real findings, both fixed.

**Attempt 1** (thread `e08e13ca...`, DeepSeek, project-brief-summarizer skill): sub-checks 1/2/3/5 PASS. Sub-check 4 FAILED — jumped straight to "Try it out!" after saving, no eval cases, no Skill Studio mention.

**Attempt 2** (thread `832ecb69...`, DeepSeek, Executive Management Weekly Report skill, different domain): sub-checks 1/2/3/5 PASS again, even more thorough (proactively found and flagged a colliding pre-existing skill). Sub-check 4 FAILED AGAIN, same pattern — confirmed repeatable, not one-off variance. **Fixed via migration 088** (merged save+eval-proposal into one mandatory sequence, forbade offering a live test before eval cases).

**Attempt 3** (thread `134c9200...` DeepSeek + thread `7ebcc7fe...` OpenAI gpt-5.4-mini, weekly-executive-management-report skill): re-tested post-088. Sub-check 4 partially improved (ordering fixed — eval-style checks now proposed before the test offer, not after) but used "validation checks for you" phrasing instead of literal "Skill Studio → Evals" — operator judged this good enough (real, useful, just not Studio-labeled; further tightening risks over-fitting wording over behavior). **New finding surfaced independently in this round:** the agent wrote a required config file via `workspace_write` (a general scratch area) instead of an actual skill-attached file, then correctly flagged manual upload was needed — but a LATER thread (different provider) hit a real `read_skill_file` 404 because the file was genuinely never attached. Investigated the full tool registry: confirmed there is no agent-callable file-attach tool anywhere in the platform (not a skill-creator bug, not fixable by a backend restart — `load_skill` reads the DB fresh every call, no caching). **Fixed via migration 089** (skill-creator now prefers inlining small config content, and is explicit that external-file upload is a required step, not already done). The comprehensive fix (a real `attach_skill_file` tool) is deferred as SEED-104 — its own properly-scoped future phase, not squeezed into this session.

**Side finding (informational, not a gap):** operator asked whether skill-creator's interview should use the existing `ask_user` tool instead of bundling questions in one message. Investigated — `ask_user` is single-question and fully blocks the agent loop per call; per-question use would be slower than the current approach, which works well across all 3 attempts. Decision: keep as-is. A future purpose-built batched-question tool, kept fully separate from the shared `ask_user`, captured as SEED-103 (deferred, low priority).
