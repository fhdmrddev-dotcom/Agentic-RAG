<objective>
Add the backend half of the "Built-in" trust badge: expose `is_system` as an
output-only field on `SkillResponse`, pin `is_system` skills to the top of
`list_skills`, and lock in Wave 0 regression tests. This is the API contract the
seeded built-in (Plan 02) and the frontend badge (Plan 03) both depend on.

Purpose: `is_system` is a *trust signal the DB owns* — the client reads it, never
sets it. This plan makes the badge value reach the wire (Pydantic drops any field
not on the response model) and enforces the ordering (D-05) while proving the
existing owner-scoping already makes the built-in read-only/undeletable.

Output: `SkillResponse.is_system`, the `list_skills` two-column order, and three
new tests in `test_skills.py`. No new endpoint, no new authorization code.
</objective>
