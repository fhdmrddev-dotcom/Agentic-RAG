## Accomplishments
- Added `is_system: bool = False` as an OUTPUT-only field on `SkillResponse` so `GET /skills` JSON carries the "Built-in" trust badge (D-01). `SkillCreate`/`SkillUpdate` deliberately unchanged — a request body can never self-brand a skill "Built-in" (threat T-137.2-02).
- Chained `list_skills` to a two-column order — `.order("is_system", desc=True).order("name")` — pinning the built-in skill-creator to the top of the Skills list (D-05). Backend order is authoritative; no client-side re-sort introduced.
- Landed 4 Wave 0 regression tests (the plan's 3 test concepts; the non-owner concept split into both status codes) proving: badge serialization on the wire, the two-column order CALL, and the reused owner-scoped 404 (update) / 403 (toggle_enabled) protection boundary.

## Decisions Made
- **Order-chain formatted on a single line** (`.order("is_system", desc=True).order("name")`) to match the plan's literal automated verify (`grep -c '\.order("is_system", desc=True)\.order("name")'`) and its acceptance criterion ("the exact chain"), rather than the file's usual one-method-per-line style. A first pass split it across two lines and would have failed the plan's exact grep; corrected before committing Task 2.
- **Non-owner protection implemented as TWO tests, not one** — a 404 case (`update_skill` empty-result miss) and a 403 case (`toggle_enabled` empty-fetch miss). The plan's action explicitly enumerated both status codes ("`update_skill`/`delete_skill` → 404-via-empty-result; `toggle_enabled` → 403"); covering both strengthens the must-have proof that the owner-scoped boundary is unchanged. Total new tests: 4 (vs the "3 Wave 0 tests" phrasing in the plan artifact list). No behavior change — test-only.
- **`delete_skill` intentionally NOT used for the 404 test:** it fetches files then deletes unconditionally and returns 204 regardless of ownership (no `not result.data` guard), so it is not a "404-via-empty-result" route. `update_skill` (which DOES raise 404 on empty result) is the correct 404 analog.
