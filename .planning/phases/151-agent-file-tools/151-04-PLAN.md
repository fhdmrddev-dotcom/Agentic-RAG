<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM tool-call → skill write | Model-supplied `target_skill_name`/`filename`/`source args` are untrusted input crossing into an owner-scoped Storage+DB WRITE |
| workspace/KB/inline/sandbox bytes → skill_files | Bytes from four provenances land on a persistent, potentially-shareable skill |
| owned skill → is_global toggle | An owner can later make an owned skill global — a legitimate downstream data-movement path |

## STRIDE Threat Register — FILE-01 `attach_skill_file` (T-02 / T-03 / T-04)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-151-04-04 | Elevation of Privilege / Tampering | write to a global/`is_system` skill | mitigate | Resolve target with owner-only `.eq("user_id", ctx.current_user["id"])` (NOT `.or_(is_global.eq.true)`) AND reject `is_system`. Service-role has no RLS backstop — the app gate is load-bearing. Proven: attach to another user's / global / is_system skill → refuse (T-04 unit) |
| T-151-04-02 | Tampering / Elevation | untrusted upload → skill → execute_code injection | mitigate | Widened upload (Plan 03) keeps magic-byte + size gate + `kind='template_input'` provenance; Python skill files ARE executable via the execute_code skill-file injection (tool_dispatcher.py:1080) — the attach path preserves provenance and never elevates a `template_input` file to a trusted Jinja render. Owner-scope bounds who can attach |
| T-151-04-03 | Information Disclosure (legitimate, explicit) | KB doc (#4) → my skill → make skill global → other users read | mitigate | Same owner-scope gate on BOTH the doc (reused Plan 01 resolver, owner→global) and the skill (owner-only). Making a skill global is already an explicit owner action (`is_global` hard-set False on create, skills.py:240). Path is documented, not blocked — the legitimate action stays owner-driven |
| T-151-04-01 | Tampering | Storage overwrite of a colliding path outside the owner prefix | mitigate | Storage path is always `{ctx.current_user['id']}/{skill_id}/{filename}` — built from ctx user id, never model args. Proven: path assertion unit test (T-02) |
| T-151-04-05 | Elevation of Privilege | tool runs when self-improve disabled | mitigate | Hidden from get_tools() when self_improve off AND refused in-flight via `_CAPABILITY_FLAG_TOOLS` (D-11, fail-closed, provider-uniform) |
</threat_model>
