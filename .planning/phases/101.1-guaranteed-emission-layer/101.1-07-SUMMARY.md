**DeepSeek v4 forced emit no longer 400s on thinking+tool_choice, and ANY raise in the emit ladder (provider 400, render error, unexpected) is now caught into an honest receipt + ONE surfaced message + a flipped phase row — closing the silent run-crash + duplicate-message gaps UAT Test 2 found (runs 575e7345 / a7f415ad).**

## Accomplishments
- **Gap 1a (DeepSeek silent 400):** the DeepSeek thinking-enable block is gated by `force_tool_name is None` — a forced emit now sends a named `tool_choice` with thinking OFF, so DeepSeek v4 stops returning "Thinking mode does not support this tool_choice". The non-forced (Deep) path keeps thinking ON, byte-identical.
- **Gap 1b (missing D-08 layer-6 backstop — substrate half):** `forced_emit` wraps `open_stream` + `_drain` in a try/except → an honest `failure="provider_error"` result. A provider 400 / mid-stream raise no longer escapes to `threads.py` agent_runner (G-5 frozen).
- **Gap 1b (executor half):** `_exec_llm_emit`'s body is wrapped in a catch-all → `_emit_unexpected_failure` (an `emit_failed` receipt + a `render_failed` phase_substep + ONE surfaced message + a flagged honest output). A render-dispatch raise (or any unexpected error) is now auditable, not a silent run-crash.
- **Gap 1 (phase stuck "active"):** `run_workflow`'s completed-branch flips a `failure`-bearing phase output to `failed` (reusing `fail_phase`) — a graceful emit failure no longer leaves the `workflow_phases` row stranded.
- **Gap 2 (duplicate honest-failure message):** `_emit_failure_output` flags `_surfaced=True`; `_surface_final_answer` skips a second persist (and the live delta) — an honest emit failure now persists EXACTLY one assistant message.

## Decisions Made
- The DeepSeek fix is the symmetric sibling of the Anthropic thinking-OFF seam Plan 02 shipped (D-14 / TIER-FORCE-NOTHINK now covers DeepSeek too) — provider-scoped, inside the forced branch's precondition.
- The catch-all wraps the body via a Python re-indent (the inline state a-e returns sit inside the `try` and return normally; the `except` only fires on a RAISED exception) — the lowest-risk way to satisfy "wrap everything after the extraction" without restructuring the executor.
- The `provider_error` forced_emit result flows through the EXISTING `if result.get("failure"):` branch (state a) which already surfaces honestly — no new branch needed (confirmed by `test_provider_error_is_honest_state_a`, which was GREEN at RED time).
- The single-owner persist guard skips BOTH the persist and the live delta when `_surfaced` is set — the already-persisted failure row renders on the next reconcile, so nothing is lost and the live screen never double-renders.
