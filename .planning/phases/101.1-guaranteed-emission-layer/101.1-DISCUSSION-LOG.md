## Trigger

The operator asked to discuss a Phase 101 gap-closure (the live UAT produced 0 .docx — GAP-A..D), AND raised a sharp observation: *"I had a 'weekly report skill' long before workflows that searched the KB and filled a docx correctly on any provider — why is our workflow failing? Is it a different case?"* That question was treated as a root-cause signal, not an aside.

## Investigation 1 — why does the workflow fail when the old skill worked? (5 agents)

- Found the old `weekly-report-writer` skill **still live** in the dev DB (`skills` id `1161c01d`, enabled, `weekly_report_template.docx` attached). Its mechanism: markdown instructions tell the model to search the KB, then **write a python-docx script and call the universal `execute_code` tool** (template injected via `skill_files`). Robust because `execute_code` is always present and emitting CODE is every model's strongest, most uniform act.
- The v2.9 `render_template` workflow changed the model's job to **volunteering a large nested cited structured field-map** into a tool that is (a) invisible outside harness fill phases and (b) called under an **open auto-tool-choice loop**. Reasoning-natives (DeepSeek) narrate the JSON as text; the gateway's narrated-tool recovery is STRUCTURED-mode-only and reasoning-natives bypass it → silent drop → 0 docx.
- The **097 spike** proved the same field-map works when emission is **FORCED** (single isolated call, held attempt-1 on Anthropic). Production dropped that guarantee (GAP-A) and never wired the bound template (GAP-B).
- **Conclusion:** SAME job, regressed by a different mechanism. Two of four gaps (A, B) are wiring regressions from the proven spike; C (run-honesty) and D (cross-provider emission) are genuinely new surfaces.

## Investigation 2 — the forward-aligned architecture (8 agents: 4 research → 3 competing proposals → judged synthesis)

- **Provider-docs-first research** (the one probe that survived a mid-run session limit): **6 of 8 providers force natively today** (OpenAI incl. reasoning, Gemini mode=ANY, DeepSeek incl. reasoner, GLM, MiniMax, OpenRouter). Only two problem children: **Anthropic** (can't force while extended thinking is on) and **Moonshot/Kimi** (no `required`/named forcing at all). So the original "GAP-D = universally fragile" fear was over-broad; the real failure was running ALL providers in the *weakest* mode.
- Three architecture proposals argued from **different priorities** (reliability-first / capability-first / audit-first) and **independently converged** on one design: a 6th generic `llm_emit` phase type that forces a single structured emission + an `EMITTER_REGISTRY` (render_template demoted to first entry) + capability-tiered gateway forcing + NATIVE-path recovery + pinned deterministic driver downstream + honest failure + an INSERT-only audit receipt.

## Operator decision (2026-06-11)

The operator asked for the recommendation that best serves future phases/milestones, best capability, and "build ANY workflow with no risk to fail" — then said **"proceed."** This ratified:
- **(a)** ship 101.1 as the **foundational emission layer**, not a minimal patch;
- **(b)** hold **"no model-written code touches the deliverable — cited data + pinned renderer only"** as a milestone-level line.
