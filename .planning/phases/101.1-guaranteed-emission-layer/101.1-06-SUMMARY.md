## The onion — five layers found by iterating LIVE (each fix moved the failure deeper)

1. **Citation-id namespace (run a12ee906: cited=0/invented=24/coverage 0%).** The emit
   user turn was prior-phase PROSE (no `<doc id=…>` to cite → the model fabricated ids)
   AND `_retrieved_ids` only recognized `chunk_id`-shaped keys while live refs carry
   `document_id`+`chunk_index` → the gate's valid set was ALWAYS empty. Fix: 
   `_ref_spotlight_id` + `_emit_evidence` — ONE walk renders the spotlight AND yields
   the valid set (the WR-04 one-mapping discipline on ids; 097 T-097-04 productized).
2. **Dead retry wiring (run cef463f7: 28/32 cited, 4 uncited → single-shot reject).**
   The engine's `_run_phase_with_gates` retry only fires for phases that CONFIGURE
   validators — the llm_emit gate is executor-internal. Fix: bounded retry inside
   `_exec_llm_emit` (≤3 sealed attempts), feedback names the offending leaves
   (`check_coverage` now returns `uncited_leaves`/`invented_leaves`), retry only when
   evidence exists (empty set fails fast as before).
3. **No placeholder oracle (run 7fa36d2a: citations 100% but render died
   `UndefinedError: 'project_name' is undefined`).** The model was never told the
   template's keys; the old `covers_template` was circular (emitted map vs its own
   keys). Fix: `parse_docx_template_variables` — stdlib zip+regex (NO docxtpl in
   backend/app — Pitfall 4 holds; tag-stripping coalesces split runs; dotted Cited
   derefs root to scalar names) — injected into the forced shot + gated pre-render.
4. **No column oracle (run 3596174c: keys matched, render died `'dict object' has no
   attribute 'risk_id'`).** The template derefs SPECIFIC cell keys in the row loop.
   Fix: parser extracts per-collection columns (`{{ r.col.value }}` → model-emitted
   Cited cells; bare `{{ r.score }}` = driver-computed D-11, excluded); prompt names
   them; gate checks them deterministically pre-render. Live proof the retry ladder
   works: this run rejected attempts 1-2 with named feedback and CONVERGED on attempt 3.
5. **`os.join` harvest bug (run 3596174c's terminal `emit_failed`).** The sandbox render
   SUCCEEDED and the file re-opened — then the backend-side harvest crashed on
   `_os_local.join` (no such attr; `os.path.join`). Unreachable until a live run passed
