# Phase 307 — UI Design Contract

> Visual and interaction contract for "Sign in from Claude.ai and Claude Desktop" (OAUTH-04, OAUTH-07,
> and the user-visible half of OAUTH-05). OAUTH-06 has no UI of its own; it shows up only as the
> "stops on its next call" facts below.
> Generated by gsd-ui-researcher; the checker validates it.

**What this file decides.** Five surfaces:

1. **The consent page** — a standalone card at `/app/connect/<request-id>`, outside the app shell (D-10..D-14).
2. **Connected apps** — a new section in Settings → API keys, above the keys (D-25).
3. **Org admin → API keys** — the org's connected apps, a "Connected app" chip, and **Disconnect all** (D-26).
4. **The snippet tab for Claude.ai and Claude Desktop** — the `mcp-remote` bridge is retired for "add a custom connector, then sign in" (D-29).
5. **The redirect-host allowlist** — an operator card in Control Room → Controls (D-08).

**It brings in no new tokens, primitives, type sizes or colours.** Where this file says "as 304", the
304 contract applies unchanged. All new UI lives in new leaf components; every hot file gets one mount,
one prop or one data change (§G-5 mount budget).

**Out of scope and not touched:** `frontend/src/pages/SettingsPage.tsx`, `frontend/src/lib/api.ts`,
`threads.py`, `agent_loop.py`, `dispatcher.py` (D-40); any new Settings tab, org-admin tab or nav entry;
client logos; custom URI-scheme redirects; scope step-up (all deferred in CONTEXT).

**Icon convention.** No client logo is drawn anywhere in this phase — not the Claude mark, not a
fetched `logo_uri` (D-09: logos are not fetched in v1). An app's mark is chosen **only from the redirect
kind**, which the server proved: `Globe` for a web address, `Laptop` for loopback. Reason: a mark taken
from anything the client asserts would let a self-registered app wear Claude's face, which is the exact
attack the consent page exists to stop.

## Surface 1 — The consent page (OAUTH-04, D-10..D-14)

**Where it lives.** `/app/connect/<request-id>`. Backend `GET /authorize` validates the client and
redirect (D-07, D-08), stores the pending request, and sends the browser here with only the opaque id
(D-10). The page is a standalone card in the shipped `AuthCardShell` (the Iris mark, the two background
orbs, `max-w-md`), never inside the app shell: no nav rail, no org switcher, no maintenance banner.
The browser tab title is **"Connect an app · Syrel"**.

**The page title never carries the app's name.** Every state's title is fixed copy. A self-registered
app chooses its own name; a 24px title saying "Connect Claude" would hand that claim the most trusted
spot on the page. The name appears once, inside the who-well, beside the host that proves it (D-12:
"the host is the trust anchor; the name is a claim").

### 1a. Ready — top to bottom (sketch A)

`AuthCardShell` title **Connect an app** · subhead **An app wants to use Syrel as you.** Then the body,
fields separated by 16px:

**1. Who is asking** (`<ConsentWhoIsAsking>`). A well: `rounded-md border border-border bg-background/60 p-3`, a 36px square mark on the left, text on the right.

| Line | Content |
|---|---|
| Mark | `Globe` for a web redirect, `Laptop` for loopback; 36px `rounded-md bg-muted` tile, icon 20px `text-muted-foreground` |
| Name line | the client name (16px Manrope 700, `text-foreground`, plain text — never HTML, never a link, truncated with an ellipsis after 60 characters, full value in `title`). For a DCR client, followed by **calls itself** (12px muted, 4px gap) |
| Host line | the redirect host in a chip (mono 12px, `rounded border border-border bg-background px-2 py-0.5`), then its tags (§tags table) |
| Published-by line (CIMD only) | 12px muted: **Details published at {client_id host}** with the `BadgeCheck` "verified" tag |
| Why line | 12px muted, one of the four sentences below |

**Tags** — two independent facts, each a 12px rounded-full tag with a word:

| Fact | Case | Tag | Tag colour |
|---|---|---|---|
| Who named it | CIMD (the `client_id` is an https URL whose document the server fetched, D-06) | `BadgeCheck` **verified** on the published-by line | success (`bg-success/15 text-success`) |
| Who named it | DCR (the client registered itself) | **name not checked** after the host chip | warning (`bg-warning/15 text-warning`) |
| Where it returns | web host on the operator's allowlist | none (the host chip alone) | — |
| Where it returns | loopback (`localhost`, `127.0.0.1`, `[::1]`, any port, D-07) | **this computer** after the host chip | neutral (`border border-border text-muted-foreground`) |

**The host chip shows the hostname only, never the port.** A loopback port is random per sign-in and
carries no trust; the scheme is implied by the kind. `[::1]` is shown with its brackets.

**Why line** (one, chosen by the two facts; the first match wins):

| Case | Sentence |
|---|---|
| loopback | It will send you back to an app on this computer. Only allow it if you just started connecting in Claude Code or another tool yourself. |
| CIMD, web | Its details are published by {client_id host}, so this name belongs to that address. |
| DCR, web, host is the seeded `claude.ai` or `claude.com` | This app registered itself, so Syrel can't check its name. It will send you back to {host}, which this deployment allows. |
| DCR, web, any other host | This app registered itself, so Syrel can't check its name. It will send you back to {host}, which this deployment allows. Only allow it if you just started connecting from {host}. |

**2. The account line.** 14px muted: **Signing in as {email}** (the email at 700, `text-foreground`), then on
the right a text link **Use another account**. It signs out and reloads the same address, so the member
lands on the sign-in form with the same request (§1b). 16px below the who-well.

**3. Organisation** (`<ConsentOrgField>`). Label (12px/400 `text-foreground`): **Organisation**.
- **One org, switched on:** a read-only fact, 14px bold org name, no control.
- **Two or more:** a `role="radiogroup"` of radio rows (the `KeyFoldersField` radio-row shape: 14px
  name, a 14px radio dot, `rounded-md border` row, selected = primary border + ring). More than 5 rows
  scroll inside the 208px box.
- **Default:** the member's active org if it is switched on, otherwise the first switched-on org in the server's order.
- **A switched-off org stays listed** (sketch: "never hidden"): the row is `aria-disabled="true"`, 62% opacity on the name only, and a second line (12px warning, `id`-linked by `aria-describedby`) carries the 304 sentence **MCP access is switched off for this organisation by an admin.**
- **Changing the org** re-reads that org's folders (§5) and resets "Which documents" to **All folders I can see in {new org}** and unticks mail and synced sources. The reset is visible because the radio's label names the org; nothing else announces it.

**4. What it can do.** Label: **What it can do**. `<McpKeyFields variant="consent">`'s Tools row, as 304:
the four segments **Read only** (pre-selected) · **Read and ask** · **Read, ask and run workflows** ·
**Choose tools**, the grouped checklist from the server catalogue (D-11, never retyped), companions
disabled with "comes with {tool}" (D-12), ask and run unticked, and the 304 hint. This is the exact
control the key screen uses, so the member sees one vocabulary for both kinds of access.

**5. Which documents.** Label: **Which documents**. `<McpKeyFields variant="consent">`'s Folders row
(`<KeyFoldersField>`) and the **Include mail and synced sources** row, as 304: **All folders I can see
in {org}** (pre-selected) or **Only these folders** with the tree, subtree inclusion, shared and
connector-fed marks, the filter input past 12 folders, and the count. `[]` is never sent (304 D-08).

**6. The sentence you are agreeing to.** The 304 acts-as note shape: 3px primary left rule,
`bg-muted/40`, `px-3 py-2`, 14px/400 with the bold slots at 700. Built by `consentFacts.ts` from the live choices, so it changes as
they change:

> This app will **{can}** in **{where}**, as you. {cannot} It stops working if you leave {org}, and you can disconnect it any time in Settings → API keys.

| Slot | Value |
|---|---|
| {can} | Read only → search and read · Read and ask → search, read and ask the agent · Read, ask and run → search, read, ask the agent and run your published workflows · Choose tools → use {N} tool(s) |
| {where} | All folders → everything you can see in {org}; with external unticked append ", not mail or synced sources"; ticked append ", including mail and synced sources" · Only these → {N} folder(s) in {org} (same external suffix) |
| {cannot} | Read only → It can't ask the agent or run workflows. · Read and ask → It can't run workflows. · otherwise empty |

The sentence says **This app**, never the asserted name, for the same reason as the title.

**7. Actions.** Right-aligned, 8px gap: **Deny access** (outline) then **Allow access** (`gradient-primary`).
- Allow access is disabled while a condition is unmet and says why in a 12px why-line under the
  buttons, linked by `aria-describedby`. The first unmet condition shows, in this order:
  1. no switched-on org → "MCP access is switched off in every organisation you belong to. Ask an admin to switch it on."
  2. Choose tools with none ticked → "Tick at least one tool." (304 copy)
  3. Only these folders with none ticked → "Tick at least one folder, or choose All folders I can see." (304 copy)
  4. the catalogue or the folder list not loaded → "Waiting for the tool list." / "Waiting for your folders." (304 copy)
- Deny access is never disabled except while a submit is in flight.

**8. The fine print.** 12px muted, 12px above the bottom:
"Allowing sends you back to **{host}**. If this app isn't used for 90 days, it disconnects itself. Syrel never shows the app your password."
(Loopback: "Allowing sends you back to the app on this computer. …")

## Interaction and security contract

**Consent route hardening (D-35).**
- **Anti-framing on every topology:** the consent route is served with `Content-Security-Policy: frame-ancestors 'none'` **and** `X-Frame-Options: DENY` by Vercel (`vercel.json` headers), nginx (the one-box location) and the dev server (`devRouting.ts`), pinned as rows in the Phase 297 routing suite. Defence in depth in the page itself: when `window.top !== window.self`, it renders the "can't be shown here" state and **never renders Allow access**. A vitest drives that branch.
- `Referrer-Policy: no-referrer` on the consent route, so the request id never leaves in a `Referer`.
- **Navigation away only to what the server returned, and only to what the page showed.** Before `location.replace`, `consentFacts.ts` checks the returned URL parses, its scheme is `https:` (or `http:` with a loopback host), and its hostname equals the `redirect_host` the page displayed. A mismatch renders "Refused: redirect not registered" and does not navigate. `location.replace` (not `assign`) keeps a used request out of the Back history.
- **No auto-submit and no default focus on Allow.** On load, focus goes to the card title (`tabIndex={-1}`), so a screen reader reads who is asking first and a stray Enter does nothing. Enter inside a field never submits.
- The page never renders client-supplied strings as HTML, never fetches a logo, never builds a link from a client string (D-09).

**Accessibility.**
- Every refusal and every disabled reason is real DOM text linked by `aria-describedby` (Allow's why-line, a switched-off org row, disabled folder and tool rows as 304).
- The org list, preset segments and folder mode are each a `role="radiogroup"` with roving tabindex and arrow keys (the shipped 304 pattern); the folder tree stays native checkboxes in a `role="group"` (304).
- Status changes use `role="status"` (loading, submitting, receipts); failures use `role="alert"`.
- Both sheets are Radix `AlertDialog` (focus trap and restore for free); the safe button holds initial focus.
- The allowlist's armed prompt moves focus to **Keep {host}**; Esc disarms.
- Disconnect, Remove and Copy buttons carry aria-labels naming their target.
- All meaningful 12px text uses `text-muted-foreground` or stronger on `--card` (AA). Tags use the shipped AA tag pairs.
- **Motion:** only the shipped `Loader2` spin while the request loads and the 1.6s band pulse on the admin receipt. No row-leave animation (the sketch's slide-out is dropped: the row leaves on re-read, which is the honest beat).

## Lived-experience (G-4) rows, driven by Claude at verification (D-38)

1. **Claude Code signs in through loopback with no key.** Add the address in Claude Code without a header and authenticate. The consent page opens in Chrome; it shows a `Laptop` mark, the name with **calls itself** (or **verified** if Claude Code uses a metadata document), a `localhost` chip with **this computer**, and the signing-in account. Pick an org and Read only; the summary reads "This app will **search and read** in **everything you can see in {org}, not mail or synced sources**, as you. It can't ask the agent or run workflows. …". Allow; the Connected card shows "Taking you back to the app on this computer…"; Claude Code lists the three read tools and runs a search.
2. **The member disconnects it.** Settings → API keys shows Connected apps above the keys, with that app's card (`localhost`, org, Read only, All folders, last used). Disconnect opens the sheet naming org, reach and last use; confirm; the card is gone and the receipt line reads "✎ … disconnected · recorded". Claude Code's next call is refused.
3. **The org admin disconnects all.** With a second grant in the org, Org admin → API keys shows both apps with the **Connected app** chip and owners. Disconnect all opens the sheet naming **2** apps and the members; confirm; the band pulses, the receipt names the server's count, the Audit tab shows the row, and the second app's next call is refused. Keys in the list are untouched.

**I'd recognise failure here if:** the page title or the largest text on the consent card is the app's
self-chosen name; a refused redirect shows any button that leaves Syrel; the redirect host is missing
from any client state; an org with MCP off disappears from the list instead of saying why; Allow can
be pressed with an empty folder set; the consent page renders inside an iframe; a disconnected app's
card lingers or comes back on reload; Disconnect all touches a key; the Claude.ai and Desktop tab
still shows a bridge or asks for a key.
