    ```
    attempt = 0; last_output = None
    while True:
        output = await asyncio.wait_for(_execute_phase(phase, accumulated, ctx), timeout=wall_clock)   # step cap inside executor; wall-clock here
        gate = await run_gates(phase, output, ctx)
        if gate.passed:
            await write_audit(pool, run_id, "gate_passed", {"phase": phase.slug}); break
        # gate failed
        identical = (output == last_output)
        last_output = output
        await write_audit(pool, run_id, "gate_failed", {"phase": phase.slug, "attempt": attempt, "error": gate.error_message})  # D-08
        await _emit(redis, run_id, "gate_failed", phase=phase.slug, attempt=attempt, error=gate.error_message)                   # D-08 visible
        exhausted = identical or attempt >= phase_max_retries
        if not exhausted:
            attempt += 1
            ctx.retry_feedback = f"Previous output failed validation: {gate.error_message}. Fix it."   # fed into _execute_phase next loop (executor appends to prompt)
            continue
        # exhausted → on_failure routing
        action = _parse_on_failure(phase)   # fail_run | retry(=> fail_run baseline) | skip_to_phase:<slug>
        if action.kind == "skip_to_phase":
            await skip_phase(pool, phase.id); jump to the target slug (D-09); break_with_jump
        else:   # fail_run baseline OR unknown (fail-safe → fail_run, D-07)
            reason = f"Phase {phase.phase_index+1} ({phase.slug}) gate failed after {attempt+1} attempts: {gate.error_message}"
            await fail_phase(pool, phase.id, reason)
            await finish_run(pool, run_id, "failed")        # KEEP completed phases' outputs (already durable) — D-07
            await write_audit(pool, run_id, "run_failed", {"reason": reason})
            await _emit(redis, run_id, "run_failed", reason=reason)   # plain-language reason to chat — nothing silently dropped
            return   # stop cleanly, no further phases
    ```

    - `_parse_on_failure(phase)` reads the failing validator's `on_failure`; recognizes `fail_run`, `retry` (retry exhausted ⇒ fall back to fail_run baseline unless a skip_to_phase is also configured — D-09), and `skip_to_phase:<slug>` (via `parse_skip_target` from harness/reachability). UNKNOWN value ⇒ fail_run (fail-safe, T-091 mitigation).
    - skip_to_phase: validate the target slug exists in the definition (it was lint-checked at publish, but guard at runtime → unknown target ⇒ fail_run); set the loop index to the target's phase_index.
    - The wall-clock `asyncio.TimeoutError` is caught and treated like a gate failure with reason `wall_clock_timeout`, driving the SAME on_failure routing (a hanging phase fails cleanly — D-12).
    - The step cap is enforced INSIDE the executor (`max_steps` passed to run_task_sub_agent in Plan 03); this loop owns the wall-clock cap. Both are present (SC#5).
    - `ctx.retry_feedback` is consumed by `_execute_phase`/the executors (Plan 03 appends it to the phase prompt on retry) — set it here, clear it on success.
