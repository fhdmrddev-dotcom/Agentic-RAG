<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| restart → in-flight run state | Postgres is the durable truth on restart; Redis SSE/pubsub is a hint that must be rebuilt (re-subscribe). |
| 2 workers → one stranded run | Both workers' sweeps may target the same run; must be claimed exactly once. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-091-20 | DoS / integrity | resumed run double-executed across workers | mitigate | claim_run CAS (UPDATE ... WHERE status IN ('active','paused') RETURNING) — only one worker wins; rides single-producer-per-run RUN_TASKS discipline (Pitfall 7). |
| T-091-21 | Integrity | ask_user re-emit before re-subscribe (lost answer) | mitigate | resume_pending_prompt enforces subscribe → sadd → emit → block (Pitfall 2); answered prompts detected first via durable response row → never re-asked. |
| T-091-22 | Integrity | re-run double side-effects | mitigate | run_workflow skips completed/skipped phases; an active phase was never completed (output never durable) so re-running is the correct resume point; llm_agent re-run forks a fresh sub_run_id (workspace writes are versioned/append-only — Pitfall 5). |
| T-091-23 | Information Disclosure | resume reads another user's run | mitigate | find_resumable_runs joins through threads (owner FK); the engine never resumes a run_id outside the owning thread. |
</threat_model>
