# Phase 206 Plan 01: MCP Connector Client — Workflow-Scoped

## Overview
Phase 206 implements the **MCP Connector Client** enabling workflows to reach external platforms like **Atlassian (Jira + Confluence)** and **GitHub** through their official remote Model Context Protocol (MCP) servers with granular per-tool permissions and **zero per-vendor adapter code**.

---

## Must-Haves & Invariants

1. **Stable Platform Asset Model (SEED-145, SEED-146)**: Connections are modeled as platform assets. No workflow-shaped foreign key on the connection, no run-scoped credential resolution, no requirement for a `workflow_id` during resolution.
2. **Provider-Shaped Schema (D-206-01)**: `connector_connections` table stores `mcp_server_url`, `tool_grants` JSONB, and `discovered_tools` JSONB.
3. **Per-Tool Permission Enforcement (D-206-06)**: External action phases can execute an MCP tool only if that specific tool is present in `tool_grants` and marked enabled.
4. **SSRF Defense (D-206-04)**: Remote `mcp_server_url` endpoints must be HTTPS and validated against private IP ranges and loopback destinations using `app.security.egress`.
5. **Two-File Fence Retirement (D-206-07)**: `test_no_mcp_identifiers_in_backend_app` in `backend/tests/unit/test_189_no_egress.py` is retired in the same commit that adds `mcp_client.py`, and `backend/tests/unit/test_190_ssti_fence.py:475` is updated in that same commit.
6. **Zero-Hook Pin in `PhaseFormPanel.tsx`**: Must maintain 0 `useState`/`useMemo`/`useEffect` hooks in `PhaseFormPanel.tsx`.

## Tasks

### Task 1: Schema Migration & Provider-Shaped Connector Models (206-01-01)
- Create `supabase/migrations/126_mcp_connector_connections.sql`:
  ```sql
  ALTER TABLE public.connector_connections
    ADD COLUMN IF NOT EXISTS mcp_server_url text,
    ADD COLUMN IF NOT EXISTS tool_grants jsonb NOT NULL DEFAULT '{}'::jsonb,
    ADD COLUMN IF NOT EXISTS discovered_tools jsonb NOT NULL DEFAULT '[]'::jsonb;

  -- Allow capability to be optional or 'mcp_tool'
  ALTER TABLE public.connector_connections
    ALTER COLUMN capability DROP NOT NULL;
  ```
- In `backend/app/models/connector.py`:
  - Add `mcp_server_url: str | None = None`
  - Add `tool_grants: dict[str, str] = Field(default_factory=dict)`
  - Add `discovered_tools: list[dict[str, Any]] = Field(default_factory=list)`
  - Update `ConnectorConnectionResponse`, `ConnectorConnectionCreate`, `ConnectorConnectionUpdate`.
  - Validate `mcp_server_url` (must start with `https://`).
- In `backend/app/models/harness.py`:
  - Extend `ExternalActionPhaseConfig` with `tool_name: str | None = None` and `tool_args: dict[str, Any] | None = None`.

### Task 2: Backend MCP Client with SSRF Egress Defense & Fence Retirement (206-01-02)
- Create `backend/app/services/mcp_client.py`:
  - `McpClient` class providing `async def list_tools(server_url: str, secret: str | None = None) -> list[dict]`.
  - `async def call_tool(server_url: str, tool_name: str, arguments: dict, secret: str | None = None) -> dict`.
  - Uses `httpx.AsyncClient` with JSON-RPC 2.0 protocol envelope (`{"jsonrpc": "2.0", "method": "tools/list", "params": {}, "id": 1}`).
  - Validates destination host and scheme against SSRF via `app.security.egress.validate_destination`.
  - Supports authentication headers (Bearer / Basic auth tokens) parsed from decrypted `secret`.
- Concurrently retire the MCP fences:
  - In `backend/tests/unit/test_189_no_egress.py`: Replace `test_no_mcp_identifiers_in_backend_app` with a docstring explaining that Phase 206 officially introduced the MCP client with strict SSRF egress controls.
  - In `backend/tests/unit/test_190_ssti_fence.py`: Update line 475 delegation assertion.

### Task 3: Tool Discovery & Permission Grant Management (206-01-03)
- In `backend/app/services/connector_service.py`:
  - Implement `discover_connection_tools(connection_id: str, org_id: str) -> list[dict]`:
    - Resolves connection and credentials.
    - Calls `mcp_client.list_tools(mcp_server_url, secret=secret)`.
    - Persists discovered tool schemas in `connector_connections.discovered_tools`.
    - Returns updated tool list with current grant statuses.
  - Implement `update_connection_grants(connection_id: str, org_id: str, tool_grants: dict[str, str]) -> dict`.
  - Update `ResolvedConnection` dataclass to expose `mcp_server_url`, `tool_grants`, `discovered_tools`.
- In `backend/app/api/connectors.py`:
  - Register `POST /connectors/connections/{id}/discover` route.
  - Register `PATCH /connectors/connections/{id}/grants` route.

### Task 4: Workflow Engine External Action MCP Tool Dispatch (206-01-04)
- In `backend/app/services/harness/phase_types.py`:
  - In `_exec_external_action`:
    - Check if the resolved connection is an MCP provider (has `mcp_server_url` or phase config specifies `tool_name`).
    - If MCP provider:
      - Validate `tool_name` is present and permitted in `connection.tool_grants` (e.g. `connection.tool_grants.get(tool_name) == "enabled"` or `"granted"`). If not granted, fail/record with an explicit permission refusal.
      - Resolve tool arguments from phase inputs and upstream accumulated outputs.
      - Call `mcp_client.call_tool(connection.mcp_server_url, tool_name, resolved_args, secret=connection.secret)`.
      - Format output payload (`{"text": result_text, "output": result_data}`).
- Update `docs/HOT-FILE-LEDGER.md` with Phase 206 entry for `phase_types.py` and `connector_service.py`.
