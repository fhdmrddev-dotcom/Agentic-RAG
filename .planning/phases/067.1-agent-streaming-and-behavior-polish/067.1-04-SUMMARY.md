# Phase 067.1 Plan 04: Skill-Load UX Clarity Summary

Two-phase `skill_loaded` SSE follow-up surfaces the skill description on the SkillRow card so users understand WHY a skill is being loaded ("Loading skill 'docx' — Generate Word documents from structured data") instead of perceiving the bare card as out-of-order during multi-tool runs.

## What Shipped

**Backend (`threads.py:1788-1811`):**
After the existing skills DB query at the `load_skill` branch, when `row.get("description")` is truthy, emit a follow-up `skill_loaded` SSE event carrying ONLY `skill_name` and `description`. The early `_emit('skill_activated', skill_name=...)` at line 1775 is preserved verbatim — it fires BEFORE the DB query so the card appears immediately on tool_start, with the description arriving as a refinement.

row = skill_row[0] if isinstance(skill_row, list) else skill_row

**Frontend types (`types/index.ts:70-79`):** `SkillActivation.description?: string` added as optional. The `?` is critical — historical messages loaded via `loadMessages` from DB don't flow through SSE, and skills with empty `description` columns intentionally skip the emit.

**Frontend api.ts (`api.ts:180-185, 346-347`):**
- `StreamCallbacks.onSkillLoaded?: (skillName: string, description: string) => void` callback added directly after `onSkillActivated`.
- New dispatch branch `else if (t === "skill_loaded" && callbacks.onSkillLoaded)` added directly after the `skill_activated` branch. Cursor advancement at lines 410-413 is event-type-agnostic so the new event automatically participates in `lastSeenOffsetRef` cursor management.

**Frontend useMessages.ts (`useMessages.ts:208-241`):**
`onSkillLoaded` handler merges `description` into the most-recent matching `SkillActivation` entry on the streaming message:

```typescript
onSkillLoaded: (skillName, description) => {
  setMessages((prev) =>
    prev.map((m) => {
      if (m.id !== assistantId) return m
      const activations = m.activatedSkills
      if (!activations || activations.length === 0) return m
      let updated = false
      const next = activations.slice().reverse().map((act) => {
        if (!updated && act.skillName === skillName) {
          updated = true
          return { ...act, description }
        }
        return act
      }).reverse()
      if (!updated) return m
      return { ...m, activatedSkills: next }
    }),
  )
},
```

Defensive no-op when no matching activation exists. Phase 063.1 + Phase 067 invariants preserved verbatim: `lastSeenOffsetRef`=6, `reconcileInFlightRef`=5, `m.runId === run.run_id`=14, `temp-`=10 (counts unchanged from baseline).

**Frontend ToolCallPanel.tsx (`ToolCallPanel.tsx:508-525`):**
Three changes to `SkillRow`:
1. `<div className="pt-2.5 animate-toolSlideIn">` → `<div className="pt-2.5 animate-toolSlideIn" data-testid="skill-load-card">`
2. `<span ...>Using skill</span>` → `<span ...>Loading skill</span>`
3. Conditional description italic span:
   ```tsx

     <span className="ml-1.5 opacity-40 italic">— {activation.description}</span>
   )}
   ```

Three-segment row layout (Zap + middle text + CheckCircle2), `truncate`, `text-xs text-muted-foreground`, `animate-toolSlideIn`, `animate-checkPop` all preserved verbatim.
