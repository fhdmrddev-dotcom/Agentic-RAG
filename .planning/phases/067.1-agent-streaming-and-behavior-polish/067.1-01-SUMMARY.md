**Track A drain-into-queue helper neutralizes langsmith `_TracedStream.__iter__`'s `except BaseException` GeneratorExit-recording on per-call timeout, applied symmetrically to OpenAI and Anthropic branches; positive trace-closure assertion gates regression.**

## Accomplishments

- **Track A architectural fix shipped** at `backend/app/api/threads.py:155-249` — new `_drain_stream_with_close_on_cancel(stream, timeout_seconds, on_chunk_async, close_fn=None)` helper that runs the sync `for chunk in stream:` loop in a thread-pool worker and bounds queue consumption with `asyncio.timeout`. On timeout the helper closes the underlying SDK stream from the main thread BEFORE the producer's for-loop cleanup runs — `_TracedStream.__iter__` exits via the `else: self._end_trace()` clean-closure branch (no `GeneratorExit` recorded).
- **Both OpenAI and Anthropic timeout branches converted** symmetrically (PATTERNS.md parity rule). Each branch's per-chunk processing body became an inner `async def _on_chunk_*` closure that uses `nonlocal` for `tool_calls_buffer`, `_announced_tools{,_ant}`, `full_content`, `finish_reason`. The branches now end with a single `await _drain_stream_with_close_on_cancel(...)` call site each, parameterized by `close_fn=stream.close` (OpenAI) / `close_fn=_ant_gen.close` (Anthropic).
- **Positive trace-closure regression test landed** at `test_066_langsmith_clean.py::test_track_a_clean_trace_exception`. Builds `_FakeTracedStream` (verbatim mirror of langsmith run_helpers.py:1678-1685) wrapping a `_StallingIterator` (iterator-class with close()→StopIteration semantics matching openai.Stream). Captures every `_end_trace(error=...)` call and asserts `error is None or in (TimeoutError, CancelledError)` — never `GeneratorExit`.
- **Phase 061 defense-in-depth tests updated to Track A invariants** at `test_061_hard_timeout.py`. The grep guards now assert helper presence and per-branch wiring (rather than the now-defunct inline `async with asyncio.timeout(per_call_budget)` literal pair).
- **24 adjacent Phase 061 + 066 integration tests green** (incl. `test_per_call_timer.py`, `test_sse_terminal.py`, `test_terminal_classification.py`, `test_status_enum.py`, `test_consumer_cursor_race.py`, `test_runs_table.py`, `test_ttl.py`).

## Issues Encountered

- **First Track A test prototype didn't capture any `_end_trace` calls** (zero `_FakeTracedStream.end_trace_calls` entries after the timed_out path ran). Root cause: the inner stream was a Python generator; `time.sleep(5.0)` blocked the producer thread for the full 5s after timeout — when the helper's `await asyncio.wait_for(producer_fut, timeout=2.0)` gave up, the producer was still mid-sleep, and assertions ran before the `for chunk in stream:` could observe the close and exit. Fixed by replacing the bare `time.sleep(5.0)` with a fine-grained sleep loop (50ms slices) that polls `_closed` — mirrors how openai.Stream's underlying httpx response close interrupts an in-flight chunk read promptly via socket teardown. After the fix, both tests pass cleanly.
