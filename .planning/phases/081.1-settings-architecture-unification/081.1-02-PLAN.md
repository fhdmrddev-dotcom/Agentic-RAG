```python
async def _migrate_settings_override() -> None:
    """One-shot migration: settings_override.json -> app_settings DB table.

    Phase 081.1 D-01..D-05. Runs in lifespan after asyncpg pool init.
    Multi-worker safe via INSERT ... ON CONFLICT DO NOTHING (D-02).
    Idempotent: no-op if JSON file absent (D-05).
    Fail-safe: on any DB error, leaves file untouched for fallback (D-03).
    On success: renames file to .migrated (D-04).
    """
```

**2. Key routing constants** (define above the function):

```python
_DIRECT_COLUMNS: set[str] = {

}

_PROVIDER_MODEL_KEYS: set[str] = {
    "openai_models", "anthropic_models", "google_models",
    "openrouter_models", "ollama_models", "deepseek_models",
    "moonshot_models", "minimax_models", "zhipu_models",
}
```

**3. Function body:**

a. `override_file = Path(__file__).parent.parent / "settings_override.json"`
b. If not exists: `return` (D-05 idempotent no-op)
c. Try read + parse JSON. On `JSONDecodeError` / `OSError`: log error, return (D-03 leave file untouched)
d. Categorize keys:
   - `direct_updates`: keys in `_DIRECT_COLUMNS` -- collect as `{column: value}` dict
   - `api_key_updates`: keys ending in `_api_key` -- collect as `{column: value}` dict (D-19: keys stay in app_settings DB)
   - `provider_model_updates`: keys in `_PROVIDER_MODEL_KEYS` -- aggregate into `provider_model_lists` JSONB: `{"openai": ["gpt-4o", ...], "anthropic": [...]}` where each provider's value is `[m.strip() for m in str(value).split(",") if m.strip()]`
   - Unknown keys: log warning, skip

e. Merge all into one update dict. Add `provider_model_lists` as a single JSONB column value. Do NOT log API key values (security).

f. Build an `UPDATE app_settings SET col1=$1, col2=$2, ... , updated_at=now() WHERE id='global'` query with asyncpg `$N` parameterized values. Execute via `pool.execute(query, *values)`.

g. On success: rename file to `settings_override.json.migrated` using `try: override_file.rename(...) except FileNotFoundError: pass` (multi-worker race safe per RESEARCH Pitfall 3). Log `"Migrated %d keys from settings_override.json"`.

h. On any DB exception: log error with `logger.error("settings migration: DB write failed: %s", e)`, return without renaming (D-03).

**4. Wire into lifespan** -- insert AFTER the Redis ping block, BEFORE `yield`:

```python
    # Phase 081.1 D-01: one-shot settings migration (after asyncpg pool init)
    from app.dependencies import get_pg_pool
    try:
        await get_pg_pool()  # ensure pool exists before migration
        await _migrate_settings_override()
    except Exception as e:
        logger.error("Settings migration failed (app continues with file fallback): %s", e)
```

**CRITICAL:** The pool must be initialized BEFORE the migration runner. `get_pg_pool()` lazily creates the pool. The migration runner must call `await get_pg_pool()` to get the pool reference for its DB writes.

**IMPORTANT:** Do NOT log API key values in any log statement. Log only key names and counts.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| JSON file -> DB | Migration runner reads untrusted JSON file content and writes to DB |
| File system -> lifespan | File rename races between multi-worker processes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-081.1-04 | Information Disclosure | Migration runner logging | mitigate | Never log API key values; log only key names and counts. `logger.info("Migrated %d keys", len(data))` not `logger.info("Migrated: %s", data)` |
| T-081.1-05 | Tampering | JSON file content injection | accept | The JSON file is on the server filesystem, only writable by the app process or admin. Not a user-facing attack surface. |
| T-081.1-06 | Denial of Service | Migration runner DB failure blocks startup | mitigate | D-03 fail-safe: on DB error, log and continue. App starts with file-based fallback. Migration retries on next restart. |
</threat_model>
