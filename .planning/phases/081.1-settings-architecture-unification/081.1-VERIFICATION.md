### Gaps Summary

Two gaps block goal achievement:

**Gap 1: Test suite regressions** — Plan 03 deleted `_load_override`, `save_override`, `_OVERRIDE_FILE`, `_override_cache`, and related globals from `user_settings.py` as designed, but did not update two historical test files that access these symbols: `test_infrastructure.py` (3 tests) and `test_075_4_save_override_sentinel.py` (6 integration-level tests). These tests will fail with `AttributeError`/`ImportError` at runtime. The underlying behaviors they test (TTL caching, sentinel guard) are now covered by the new `test_settings_cache.py` and `test_081_1_settings_migration.py`, but the old tests need to be updated or removed to prevent CI breakage.

**Gap 2: Human verification not performed** — Plan 04 Task 2 (`checkpoint:human-verify`) was auto-approved in auto mode. The plan explicitly requires a human to restart the backend, confirm the migration log, verify the Settings UI subtitle, change+save+refresh settings, and confirm a chat uses the selected model. This verification was never performed by a human.

**Note on REVIEW findings:** REVIEW CR-01 (SQL injection via user-controlled api_key column names) was already resolved — `_API_KEY_COLUMNS` allowset is defined in `main.py` and the gate `key in _API_KEY_COLUMNS` is applied at line 132. REVIEW WR-01 (no write RLS policy on `model_capabilities_overrides`) is a design note — admin-only write via service_role is the intent for v3.1 and is acceptable for the current phase scope. REVIEW WR-02 and WR-03 are informational warnings, not blockers.
