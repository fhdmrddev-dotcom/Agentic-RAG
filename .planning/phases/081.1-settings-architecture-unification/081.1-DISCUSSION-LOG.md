## Key Routing Details

### Base URLs (embedding_base_url, ollama_base_url)

| Option | Description | Selected |
|--------|-------------|----------|
| app_settings (Recommended) | Keep them UI-writable in the DB. Not secrets — endpoint addresses admins tune. Matches "settings in DB" principle. | ✓ |
| Stay in .env | SEED-024's original call. Treat as infra like SUPABASE_URL. Requires restart to change. | |
| Both (env default, DB override) | DB row overrides .env value when present. Operators bootstrap via .env; admins tune via UI. | |

**User's choice:** app_settings (Recommended)
**Notes:** Clean alignment with the overall migration direction. SEED-024's ".env" call was conservative; user prefers full DB migration for UI-writable values.

### Provider Model Lists (9 keys)

| Option | Description | Selected |
|--------|-------------|----------|

**User's choice:** app_settings JSONB column (Recommended)
**Notes:** None — straightforward pick.

## API Contract Impact

### API Key Storage

| Option | Description | Selected |
|--------|-------------|----------|
| app_settings DB columns (Recommended) | API keys stay UI-writable via DB. Same behavior as today, different backing store. v3.1 migrates to secrets vault. | ✓ |
| Move to .env now | API keys become .env-only. Breaks Settings UI flow until v3.1. More secure but worse UX. | |
| user_settings per-user | Each user stores own API keys. Per-user credentials. Complex migration, forward-compatible with multi-tenancy. | |

**User's choice:** app_settings DB columns (Recommended)
**Notes:** Pragmatic choice — don't break the current UI flow. v3.1 will handle proper secrets management.

### Async Strategy

| Option | Description | Selected |
|--------|-------------|----------|
| Async with asyncpg (Recommended) | Phase 073 asyncpg pool available. Settings reads/writes go through asyncpg directly. Cleaner and faster. | ✓ |
| Sync supabase-py + threadpool | Keep using supabase-py for settings. Simpler but adds threadpool overhead per D-v2.5-01. | |

**User's choice:** Async with asyncpg (Recommended)
**Notes:** None — natural extension of Phase 073 work.
