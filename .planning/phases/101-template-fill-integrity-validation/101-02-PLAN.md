## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| KB chunk content → field-map values | KB-derived strings flow into the render context (untrusted reference data) |
| template provenance → engine selection | The provenance string decides docxtpl (trusted) vs run_replace (untrusted) — the security boundary |
| field-map source_chunk_id → citation check | The model-asserted citation must be verified ∈ retrieved_ids |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-101-02-01 (T-097-08) | Tampering / EoP | render_docx_template (Jinja) | mitigate | `SandboxedEnvironment(autoescape=True)` blocks attribute/builtin access (SSTI) — mandatory regardless of provenance; the untrusted upload never reaches this function (provenance routing, T-101-02-04) |
| T-101-02-02 (T-097-02) | Tampering (DoS — won't open) | render context with `& < >` KB values | mitigate | autoescape=True on the docxtpl path; python-docx `.text` setter auto-escapes on the run_replace path; assert_integrity re-open catches any residual corruption |
| T-101-02-03 (T-097-07) | Spoofing | check_coverage citation gate | mitigate | Deterministic set-membership: `source_chunk_id ∈ retrieved_ids` else uncited/invented → caller rejects before render (Plan 03 wires the reject) |
| T-101-02-04 (T-097-08) | Tampering / EoP | select_engine + run_replace_docx | mitigate | Provenance routing: `template_input` → run_replace (non-Jinja) → SSTI structurally impossible for uploads; run_replace never imports docxtpl/jinja2 |
| T-101-02-05 | Tampering | run_replace silent miss | mitigate | residual_tags_in scan after replace = the deterministic silent-miss detector (a surviving `{{` = an honest verdict line, never a silent pass) |
