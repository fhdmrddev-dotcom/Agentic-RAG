<objective>
Build the security keystone: a single router-level `require_operator` dependency that reuses
`get_current_user`, checks `operator_users` membership, and raises a byte-identical 404 on miss
(non-discoverable). Delete the `BACKPRESSURE_ADMIN_USER_IDS` allow-list + dev fail-open (D-02).
Add the audit floor (D-03) as a yield-dependency attached per-action-endpoint (so the mount probe
stays silent), a `GET /admin/me` probe, and a `GET /admin/audit` feed. Keep the four backpressure
signals unchanged; only re-gate them. `operator_service.py` houses the membership read, the audit
write (swallow-on-error), and the seed function (wired to startup in Plan 03).

Purpose: This is the access-control keystone for the whole v3.3 milestone (V4). A missing gate or
a per-endpoint gate is a full-tenant leak — the backend runs on the service-role key with NO RLS
backstop (Pitfall 1).
Output: `operator_service.py` (new), `require_operator` + `operator_audit_floor` in `dependencies.py`,
the upgraded `admin.py`, config swap, `.env.example`, and the gate regression suite.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-146-03 | Information Disclosure | 405 method-mismatch fingerprint (Allow header reveals path) | accept | Correct-method hits 404 cleanly; wrong-method 405 reveals only path existence, not data/operator-capability.
