<context>
`McpAuthDoor` encapsulates the entire connection lifecycle for MCP servers:
1. URL Input & Probing trigger (on blur or explicit action).
2. Four `kind` outcomes:
   - `'open'`: Direct connect.
   - `'oauth'`:
     - If `registration_required === false`: Direct "Sign in with {host}".
     - If `registration_required === true`: Shows Client ID / Secret fields.
     - Click handler opens blank popup synchronously, awaits `createMcpOAuthAuthorizeUrl(connection_id)`, then redirects the popup window.
   - `'token'`: Renders verbatim `detail` string and token input.
   - `'unreachable'` & 422 Refusals: Renders distinct, honest error banners.
3. Existing connection handling: Shows active connection status, tool count, Reconnect and Revoke actions.
4. Tool grant hygiene (`BUS-051`): Never write boolean `true` for discovered tools; absence inherits default posture.
</context>
