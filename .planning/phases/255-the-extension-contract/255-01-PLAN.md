<objective>
Write down the Extension Contract as binding project law in `docs/EXTENSION-CONTRACT.md` and
supply three clear, complete worked examples that a third party who has never seen engine code
can follow (Data, External Process, Sandboxed Code), explicitly articulating the architecture's
refusals and linking into `CLAUDE.md`.
</objective>

<tasks>
<task name="author_extension_contract" wave="1">
Create `docs/EXTENSION-CONTRACT.md` defining the extension philosophy:
1. The Core Law: "A plugin is DATA, an EXTERNAL PROCESS, or SANDBOXED CODE. Never engine code."
2. The Closed Core: Why the core (workflow executors, emitters, validators, programmatic functions,
   agent tools) is closed, and why third-party engine code destroys graded governance.
3. The Three Permitted Mechanisms:
   - Data: skills, workflow definitions, templates, metadata schemas.
   - External Process: Model Context Protocol (MCP) clients (`mcp_client.py`) with per-tool grants,
     discovered tools, and audit receipts.
   - Sandboxed Code: `sandbox_service.py` (`agentic-rag-sandbox`) with strict boundary.
4. Explicit Refusals:
   - Third-party executors / emitters / validators
   - Generic HTTP egress node
   - Branching / looping workflow graphs as a plugin concern
5. How a third-party developer builds on each mechanism.
</task>

<task name="author_worked_examples" wave="1">
Author three concrete, fully annotated worked examples under `docs/extensions/`:
1. `docs/extensions/skill-package-example/SKILL.md`: A complete, importable skill package.
2. `docs/extensions/workflow-definition-example.json`: A valid workflow DAG definition that imports into the engine without code.
3. `docs/extensions/mcp-server-example.md`: Complete guide for running and connecting an external MCP server to Agentic RAG.
4. `docs/extensions/sandbox-transform-example.py`: A transform script showing how user code is executed safely in the sandbox container.
5. `docs/extensions/README.md`: Index and navigation for the examples.
</task>
