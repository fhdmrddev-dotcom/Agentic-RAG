| Boundary | Description |
|----------|-------------|
| tuner winner description → rendered card | The proposed description (model-authored candidate) is displayed to the user as text |
| user click → propose/approve/reject wires | Approval is an explicit human action — the only path that writes the live description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-139-14 | Tampering (XSS) | rendering proposed_description / diff / scoreboard | mitigate | Render as React text nodes only — no `dangerouslySetInnerHTML`, reusing the ProposalCard text-node idiom (T-137-05) |
| T-139-15 | Elevation of Privilege | one-click direct live-description write (the affordance being replaced) | mitigate | D-08 removes the one-click apply; the ONLY live write is an explicit Approve through the owner-scoped route (D-06 human-in-the-loop) |
| T-139-16 | Spoofing/Repudiation | proposing a fabricated diff on a baseline-winning skill | mitigate | Gate the affordance on `isActionableWinner` (winner && !is_baseline); baseline-wins shows the honest "keeping it" path, no propose (D-02) |
| T-139-SC | Tampering | npm/pip/cargo installs | accept | No package installs — reuses first-party `lineDiff` + `ProviderScoreboard`; nothing to slopcheck |
</threat_model>
