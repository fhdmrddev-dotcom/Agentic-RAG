Create `backend/app/services/logging_sink.py` with a single public function `install_file_log_sink() -> str | None` and a `_RedactingFilter(logging.Filter)`.

1. `install_file_log_sink()`:
   - `_path = os.getenv("LOG_FILE_PATH") or os.getenv("BACKEND_LOG_FILE")`. If falsy → `return None` (opt-in; no handler — byte-identical console-only).
   - Resolve the path relative to the backend dir if relative; `os.makedirs(parent, exist_ok=True)`.
   - Idempotency guard: if the root logger already has a handler whose `getattr(h, "_gsd_093_sink", False)` is True → `return _path` (do not add a second).
   - Build a `logging.handlers.RotatingFileHandler(_path, maxBytes=10_000_000, backupCount=3, encoding="utf-8")`, set `handler._gsd_093_sink = True`, set a formatter `"%(asctime)s %(levelname)s %(name)s %(message)s"`, attach the `_RedactingFilter()`, and `logging.getLogger().addHandler(handler)`. Set the root logger level to at most INFO if it is higher (so app logger.info lines reach the file) WITHOUT lowering it below an existing explicit lower level — read the current level, set `min(current, INFO)` only if no handler-specific level is set; do NOT touch the `asyncio` logger level (main.py:21 keeps it at ERROR).
   - On Windows, set restrictive file permissions where supported (best-effort `os.chmod(_path, 0o600)` inside a try/except — Windows may ignore the POSIX bits; the gitignore is the real protection).
   - Return `_path`.

2. `_RedactingFilter(logging.Filter)`: override `filter(record)` to rewrite `record.msg` / `record.args` so the FORMATTED message has secrets removed. Build a compiled regex list ONCE at module load:
   - `re.compile(r"sk-[A-Za-z0-9_\-]{6,}")` → `"sk-***REDACTED***"`
   - `re.compile(r"(?i)(authorization|bearer)\s*[:=]?\s*[A-Za-z0-9._\-]{8,}")` → keep the keyword, redact the value
   - `re.compile(r"eyJ[A-Za-z0-9._\-]{10,}")` (JWT-shaped) → `"***REDACTED-JWT***"`
   - the literal VALUES of the provider key env vars when set (build from `os.environ` for the names listed in the interfaces block) → `"***REDACTED-KEY***"`. Guard: only redact env values with length ≥ 8 (avoid redacting empty / trivially-short values).
   Apply by formatting `record.getMessage()` first (so `%`-args are interpolated), then run the regex chain, then set `record.msg = redacted` and `record.args = ()`. Return True always (never drop a record — only redact it).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app logging calls → on-disk logfile | Log records (which may transitively contain secrets/PII) cross from in-memory logging into a persistent file |
| logfile → git repo | A committed logfile would leak secrets into version control / any clone |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-093-06-LEAK-SECRET | Information Disclosure | the RotatingFileHandler — provider API keys / Bearer tokens / service-role keys reaching the logfile in cleartext | mitigate | `_RedactingFilter` redacts `sk-…`, `Bearer/Authorization` values, JWT-shaped tokens, and the live VALUES of all provider key env vars before any record is written; unit-tested (Task 1 behavior block asserts the secret substrings are ABSENT in the file) |
| T-093-06-LEAK-PII | Information Disclosure | full prompt / document content (user PII) reaching the logfile | mitigate | The sink only MIRRORS existing `logging` calls — it adds NO new logging of request/response bodies; the app does not log full bodies today, and this plan adds none. Documented as an explicit non-goal in the action (do NOT log bodies) |
| T-093-06-COMMIT | Information Disclosure | a secret-bearing logfile committed to git | mitigate | Default path under `logs/` / `.log` is matched by the existing `.gitignore` rules (lines 44-45); Task 2 confirms coverage and the SUMMARY records it as the load-bearing mitigation |
| T-093-06-PERMS | Information Disclosure | the logfile world-readable on a multi-user host | accept | Best-effort `os.chmod(_path, 0o600)` (Windows may ignore POSIX bits); accepted because the dev host is single-user (memory: reference_local_dev_app) and the gitignore is the real protection. Production hardening (centralized log scrubbing) is out of v2.8 scope |
| T-093-06-DEFAULT-ON | Elevation (accidental enablement) | a file handler active without the operator opting in | mitigate | The sink is strictly opt-in — no `LOG_FILE_PATH` env var → `install_file_log_sink()` returns None and installs NO handler (byte-identical console-only); verified by the Task-2 opt-in assertion command + the Task-1 opt-in test |
