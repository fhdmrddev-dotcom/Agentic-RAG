calls, yet the ProblemsTray renders *"Nothing to fix — the static checks pass · checked by the
server"* and Publish stays ENABLED — for a definition the server marks `ok:false` the moment it is

because `unbound_retrieval` commonly fires on freshly-opened drafts, so the window in which the
canvas lies is now routinely non-empty. GAP A shrinks the population of unbound drafts; this plan
closes the lie itself.

Output: never-ran becomes a first-class check state with its own sentence, it fails closed at the
publish trigger, and a validate actually runs when a canvas opens on a definition with steps.

<design_decision>
**Settled here; the executor does not re-open it.**

The UAT's `missing` list names three things and offers a fork on the second (*"Either validate-on-open,
or a blockedReason branch that treats never-ran like degraded"*). **BOTH halves ship, and they ship
together, because either alone is wrong:**

- Fail-closed alone would leave every opened draft **permanently unpublishable** until the author made
  a pointless edit. A fail-closed state the user cannot escape is a new defect, not a fix.
- Validate-on-open alone leaves the ~500 ms debounce-plus-request window still lying, and leaves the
  lie standing outright whenever the first request is in flight.

**Never-ran rides the EXISTING `degraded` channel rather than a new boolean.** `useLiveValidation`'s
own docblock defines `degraded` as *"the check did not run"* — and "nobody asked yet" is a member of
that class, not a competitor to it. Routing it there fixes all three lying sites in `ProblemsTray`
with **zero new props** (`showCounts`, the resting beat and the empty paragraph already branch on
`degraded`), and costs the hot page one memo field instead of a store field, a mirror-effect branch
and a session key.

**The union is widened in `verdictModel.ts`, not in the hook.** `DegradedValidationCause` stays
exactly what the hook can emit; `verdictModel` declares `TrayCheckCause = DegradedValidationCause |
"unchecked"` and owns the third sentence beside the other two. A type that admits a member its owner
cannot produce is the drift class this phase has closed twice (WR-14); this avoids it.

**`hasEdited` is widened, not replaced, and it is gated on the canvas flag.** New rule:

```
enabled = hasEdited || (canvasEnabled && phases.length > 0)
```

- `phases.length > 0` preserves D-184-15's **stated reason** exactly — *"a brand-new zero-step draft
  is never greeted with a not-ok envelope and a full problems tray"*. The empty canvas still shows
  its invitation.
- `canvasEnabled &&` preserves **D-181-01**. Without it, a flag-off Builder opening a draft would
  issue a request it does not issue today, and "byte-identical to today" would be false. This is the
  single most important half-line in the plan and it gets its own falsification.
- D-184-15's *"Generating or opening a workflow is not something the author edited, so it must not
  start the loop"* is the sentence this plan overrides, deliberately and in the open. Its rationale
  was about an EMPTY draft; applied to a draft that already has steps it produces the fail-open the
  UAT measured. Record the override in the `hasEdited` docblock — do not silently widen a rule whose
  reasoning is written three lines above it.
</design_decision>
