<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser localStorage → API | activeOrgId is a per-device UI hint injected as X-Org-Id; the server re-validates it (Plan 01) — the client is NOT a trust boundary |
| org switch → in-flight streams | a stale subscription must not deliver the previous org's data after a switch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-166-05 | Spoofing | X-Org-Id from localStorage | accept (client not a boundary) | The header is a hint; Plan 01's get_active_org_id re-validates it against membership server-side. A forged localStorage org reaches no data (403). Documented in the OrgProvider JSDoc. |
| T-166-06 | Information Disclosure | org-switch stream teardown | mitigate | switchOrg routes through the existing 067.5 guarded clearThreadBucket + a fetch-on-reconcile; Realtime is never the isolation boundary (D-166-08). The mid-stream predicate is preserved so an in-flight send is not wiped, but the refetch reconciles to the new org (the isolation boundary is the server-validated fetch). |
| T-166-07 | Elevation | useOrgPermissionsProbe canManage | mitigate | Render-only + fail-closed; the backend require_org_manage gate is the wall. A forged canManage shows chrome but the /org/members + /org/audit reads 403. |
| T-166-SC | Tampering | npm installs | accept | No new packages — clones of shipped providers/hooks + existing supabase client. No install task. |
</threat_model>
