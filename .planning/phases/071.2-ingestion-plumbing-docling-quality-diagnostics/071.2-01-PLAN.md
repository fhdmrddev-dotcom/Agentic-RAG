## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /documents/upload | Untrusted file bytes + filename + folder_id cross into the API; auth via JWT (existing) |

| BackgroundTask → Supabase Storage / Postgres | Sync supabase-py writes from a thread-pool task |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-071.2-01-01 | I (Information Disclosure) | `_upload_pipeline` exception path | mitigate | On unhandled exception inside the BackgroundTask, log via `log.warning("upload_pipeline failed for %s: %s", document_id, exc)` and UPDATE `documents.status='failed'` + `error_message=<short user-safe summary>` — do NOT echo supabase-py internals or stacktrace into `error_message` (match 071.1 telemetry-write-swallow shape SP-5) |
| T-071.2-01-02 | S (Spoofing) / IDOR | documents INSERT in /upload, runs AFTER auth + before BackgroundTask | mitigate | The folder_id ownership SELECT (Step 1 call site 1) runs BEFORE the INSERT and rejects with 404/403 if folder_id is not owned by current_user. The INSERT carries `user_id=current_user["id"]`. BackgroundTask only receives the validated user_id. No new IDOR surface introduced. |
| T-071.2-01-03 | D (Denial of Service) | BackgroundTask queue depth | accept | Single uvicorn worker (D-v2.5-02) + 50 MB raw-bytes guard already in /upload + dedup short-circuit at 200 OK. BackgroundTasks run in Starlette's thread pool (anyio default ~40 threads). Phase 077 multi-worker harness will re-validate under load. No new DoS surface vs current foreground-extract behavior. |
| T-071.2-01-04 | T (Tampering) | Storage path construction in /upload (`f"{user_id}/{document_id}/{filename}"`) | mitigate | filename comes from `file.filename` (UploadFile attribute) which FastAPI strips of path components. The user_id segment is server-controlled. document_id is a fresh UUID4. Path traversal not possible. (Existing behavior; preserved.) |

No high-severity threats introduced. Existing threat surface (auth, ownership, size guard) unchanged.
