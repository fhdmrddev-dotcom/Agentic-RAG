<objective>
Close two operational defects:
1. `multimodal_service.extract_and_store_tables/_images` currently re-extract from `raw` bytes via pdfplumber/python-docx — silently discarding any tables/images Docling already produced AND populating `document_tables.bbox` / `document_images.bbox` with NULL even though migrations 042+ provide the columns. This is the 4-vs-1 telemetry-vs-storage mismatch (telemetry from Docling, storage from pdfplumber on the same PDF).
2. `/reextract` returns 500 (not 404) when the target document has `is_latest=False` from a prior failed cascade — `supabase-py`'s `.maybe_single()` raises on an eliminating filter rather than returning `.data=None`.

Fix both:
- Widen `extract_and_store_tables` and `extract_and_store_images` to accept `extracted_doc: ExtractedDocument | None = None`. Precedence: when present and non-empty, use it; else fall back to the existing pdfplumber/python-docx pass. Backward-compat: tests that pass `extracted_doc=None` (or omit it) keep working.
- Thread `extracted_doc=extracted_doc` through the call sites in `ingest_document` (`documents.py:1015-1032`). Remove the TODO Phase 072 comment blocks (resolved).
- Wrap the `/reextract` owner SELECT in try/except, re-raise as `HTTPException(404, "Document not found")`.

Purpose: closes D-071.2-08 + D-071.2-10. Restores SC#5 (telemetry-storage parity) and SC#6 (404 not 500). Plan 05 then builds on this — its per-aspect dispatcher writes `extracted_doc` from `extract_composable`, so multimodal_service immediately gets the right shape.

- `multimodal_service.py` — 2 functions widened (~50 LOC of additions; pdfplumber/python-docx branches preserved as `else`)
- `documents.py` — 2 call-site arg additions + 1 try/except wrap (~12 LOC); TODO blocks deleted
