<decisions>
## Implementation Decisions

### Architecture

**D-071.2-01: Per-aspect extraction dispatcher (LOCKED).** Today `extraction_service.get_extractor(engine, ...)` produces a whole `ExtractedDocument` from ONE engine. New shape: `extract_composable(raw, mime, engines={...})` with independent registries per aspect:
- `TEXT_ENGINES = {"legacy", "docling", "pymupdf"}` — produces `text` + `full_markdown`
- `TABLE_ENGINES = {"pdfplumber", "docling_tf"}` — produces `list[TableData]`
- `IMAGE_ENGINES_PDF = {"pdfplumber", "pymupdf_full", "docling_pictures"}` — produces `list[ImageData]`
- `IMAGE_ENGINES_DOCX = {"inline_shapes", "zip_xpath"}` — produces `list[ImageData]`
- `EQUATION_ENGINES = {"none", "docling_formula"}` — produces `list[EquationData]` (new field on `ExtractedDocument`)

**D-071.2-02: Aspect engine defaults (LOCKED).** Strict wins ship as new defaults; legacy stays first-class:
- `text_engine_pdf = "legacy"` (pdfplumber+pypdf — fast, structurally simple)
- `text_engine_docx = "legacy"` (python-docx)
- `text_engine_pdf_layout_heavy = "docling"` (opt-in via `app_settings` for layout-aware fallback)
- `table_engine_pdf = "docling_tf"` (strictly better recall on borderless tables)
- `table_engine_docx = "python-docx"` (DOCX tables are explicit `<w:tbl>`; trivial)
- `image_engine_pdf = "pymupdf_full"` (strictly dominates `pdfplumber.page.images` — descends Form XObjects)
- `image_engine_docx = "zip_xpath"` (strictly dominates `inline_shapes` — catches floating + VML + header/footer)
- `equation_engine = "docling_formula"` (built-in; renders math as LaTeX; off when no equations detected)

**D-071.2-03: Settings layer (LOCKED).** Per-aspect engine choice lives in `app_settings.extraction.*` (migration 043 — first migration in this phase). Per-call override via query-string hint on `/upload` and `/reextract` (`?engines=text:docling,tables:camelot`). Env vars (`EXTRACTOR_PRIMARY`) become legacy aliases — preserved for backward-compat but `app_settings` wins.

**D-071.2-04: Composable `ExtractedDocument` schema (LOCKED).** Add `equations: list[EquationData]` field. Existing consumers stay compatible — empty list when no equation engine selected.

### Plumbing

**D-071.2-05: `/upload` instant-201 + BackgroundTask (LOCKED).** Route INSERTs the `documents` row with `status='pending'` FIRST, then `BackgroundTasks.add_task(ingest_pipeline, ...)`, then returns 201 within ~1s. Extraction + chunking + multimodal-store happens in the background. Frontend Realtime sees the INSERT immediately + the lifecycle status transitions.

**D-071.2-06: `/reingest` + `/upload` threadpool sweep (LOCKED).** Same `await run_in_threadpool(extractor.extract, ...)` pattern proven for `/reextract` in 071.1. Storage `.download()` also wrapped. `/health` stays <2s during in-flight extract.

**D-071.2-07: Chunker reads `full_markdown` (LOCKED).** `docling.py:198` becomes `text = full_markdown or doc.export_to_text()`. The chunker's hierarchical separators `\n## ` / `\n### ` regain semantic alignment.

**D-071.2-08: `multimodal_service` reads `extracted_doc.tables/images` (LOCKED).** `extract_and_store_tables` and `extract_and_store_images` accept `extracted_doc: ExtractedDocument | None` and use its data when present. Fallback path (re-extract from raw bytes via pdfplumber / python-docx) preserved for `extracted_doc=None` (legacy path).

**D-071.2-09: DOCX `wp:anchor` walk absorbed from Phase 072 (LOCKED).** Port Docling's own `MsWordDocumentBackend:78-83` `.//a:blip` + `.//v:imagedata` XPath algorithm into the new `zip_xpath` DOCX image engine. Phase 072 narrows: RAG-MM-LIFT-02 closed here; 072 retains RAG-MM-LIFT-01 (vision-LLM cap lift + empty-row persistence) only.

**D-071.2-10: `/reextract` `is_latest=False` → 404 (LOCKED).** Single-line fix at `documents.py:618-626` — wrap `.maybe_single().execute()` in try/except, re-raise as 404.

**D-071.2-11: Frontend status badge (LOCKED).** Existing wiring at `useDocuments.ts:37-62` + `DocumentStatusBadge.tsx` already supports `pending|processing|completed|failed`. Plan 02 verifies the new BackgroundTask lifecycle (`pending` → `processing` → `completed`) renders correctly via Realtime; adds 2 new `ingestion_step` label cases (`extracting_tables`, `extracting_images`) only if Plan 04 introduces them; otherwise UAT-only.

### Quality gates

**D-071.2-12: Plan 04 success threshold (LOCKED).** Thesis pair re-extract under Docling per-aspect dispatch must produce: **tables ≥ 20 AND figures ≥ 10 AND chunks ≥ 200**. Below this floor → escalate to Marker GPL-fenced opt-in engine (SEED-018 promoted to phase).

**D-071.2-13: Probe-harness gate (LOCKED).** Before Plan 05 commits to the new aspect defaults, the extended probe (`backend/scripts/probe_docling_timeout.py` per RESEARCH-COMPLETENESS Part E) must run on the thesis pair and confirm: `len(full_markdown) ≥ len(text)`, `chunk_text(full_markdown).count() ≥ 3 × chunk_text(text).count()` on a representative PDF. Below → re-evaluate Plan 03 scope before Plan 05 ships.

**D-071.2-14: Docling pipeline flag enablement (LOCKED).** `do_formula_enrichment=True` enabled by default (renders math as LaTeX; ~few hundred MB on first call but already cached for thesis-style docs). `generate_table_images=True` deferred to Phase 072 / 076 (vision-LLM fallback for empty-grid tables is a separate optimization).

### Future-readiness (seeds)

**D-071.2-15: SEED-017 — PyMuPDF4LLM as opt-in text engine (PLANTED at phase close).** Re-open trigger: (a) CPU-time budget for text extraction tightens below 2s/page, OR (b) AGPL fence pattern (subprocess) becomes part of project policy.

**D-071.2-16: SEED-018 — Marker as opt-in GPU table engine (PLANTED at phase close).** Re-open trigger: (a) GPU compute provisioned for the deployment, OR (b) Plan 04 numbers come in below D-071.2-12 floor and Marker subprocess fence becomes the escalation path per Q5.

## Specific Ideas

### Test artifacts (ground-truth)
- **Thesis PDF**: `document_id = '23cc112a-92c2-440f-83c9-13aa8bf3d53d'` — 4 MB, ~400 chunks under legacy, dropped to 19 under Docling pre-fix. Used as the reference for Plan 03 (chunk-count recovery) + Plan 04 (table/image count recovery)
- **Thesis DOCX**: same content as the PDF, user has pasted-in pictures → 0 images returned under `python-docx.inline_shapes`. Used as the reference for the new `zip_xpath` engine

### Plan structure (5 plans, 2 waves)
- **Wave 1 (parallel):** Plan 01 (instant-201 BackgroundTask + threadpool sweep), Plan 03 (chunker `full_markdown` swap + extended probe harness), Plan 04 (`multimodal_service` reads `extracted_doc` + `/reextract` 404 fix), Plan 05 (per-aspect dispatcher + new engines + settings layer + migration 043)
- **Wave 2 (depends on Wave 1):** Plan 02 (frontend status badge UAT + 2 optional label cases)

### Engine adapter file structure (Plan 05 anchor points)
- `backend/app/services/extractors/aspects/__init__.py` — registries (`TEXT_ENGINES`, `TABLE_ENGINES`, `IMAGE_ENGINES_PDF`, `IMAGE_ENGINES_DOCX`, `EQUATION_ENGINES`)
- `backend/app/services/extractors/aspects/text.py` — legacy / docling / pymupdf text adapters
- `backend/app/services/extractors/aspects/tables.py` — pdfplumber / docling_tf adapters
- `backend/app/services/extractors/aspects/images_pdf.py` — pdfplumber / pymupdf_full / docling_pictures adapters
- `backend/app/services/extractors/aspects/images_docx.py` — inline_shapes (current) / zip_xpath (new) adapters
- `backend/app/services/extractors/aspects/equations.py` — docling_formula adapter (only one for now)
- `backend/app/services/extraction_service.py` — `extract_composable(raw, mime, engines)` composer + backward-compat shim that maps `get_extractor(engine=...)` → composable engines dict for legacy callers

### Settings layer (Plan 05 — migration 043)
Schema additions to `app_settings`:
```sql
extraction_text_engine_pdf text DEFAULT 'legacy',
extraction_text_engine_docx text DEFAULT 'legacy',
extraction_table_engine_pdf text DEFAULT 'docling_tf',
extraction_image_engine_pdf text DEFAULT 'pymupdf_full',
extraction_image_engine_docx text DEFAULT 'zip_xpath',
extraction_equation_engine text DEFAULT 'docling_formula',
extraction_per_call_hints_enabled boolean DEFAULT true
```

### Probe harness extension (Plan 03)
Extend `backend/scripts/probe_docling_timeout.py` to print side-by-side:
- `len(text)` vs `len(full_markdown)` from Docling
- `chunk_text(text)` vs `chunk_text(full_markdown)` count
- `fitz.Page.get_images(full=True)` count vs `pdfplumber.page.images` count
- `Document(raw).inline_shapes` count vs ZIP-walked `word/media/` count vs `lxml` `<w:drawing>` + `<v:imagedata>` count
