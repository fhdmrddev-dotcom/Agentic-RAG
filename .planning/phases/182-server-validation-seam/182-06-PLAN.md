<objective>
Close the phase-goal-fidelity gap from `182-VERIFICATION.md`. The seam's own header comment claims
"Every rule it previews is the SAME copy the publish gauntlet enforces" — true for structural lint,
business_requirement and interactive_phase, FALSE for grounding fidelity. `publish_workflow` never
calls the grounding checks, so a definition with a hallucinated tool or an inaccessible `skill_ref`
paints red in `/validate` and publishes green. This is exploitable today through the existing
non-canvas authoring API, independent of any future canvas.

OPERATOR DECISION (locked): add a grounding-fidelity stage to `publish_workflow` reusing the SAME
shared `grounding.py` collector, so there is still exactly one copy of the rule. Make the phase goal
literally true rather than narrowing the claim.

Purpose: the anti-drift promise ("the canvas can never drift from the publish gauntlet it must
ultimately pass") becomes a property of the code, not a comment.
Output: a new publish stage, corrected documentation on both sides of the seam, a falsification-tested
regression suite including a direct `/validate`-vs-publish agreement test, and an audited report of
the behavior change.
</objective>
