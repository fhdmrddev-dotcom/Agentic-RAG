## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API (`POST /validate`) | Untrusted `WorkflowDefinition` body crosses here — the ONLY net-new input surface this phase. |
| flag-off → 404 | `require_canvas()` folds an off flag (and any unauthenticated caller) into a byte-identical 404 before route existence can leak. |
| API → Supabase (owner-scoped) | grounding/bundle reads are scoped by hand on `user_id` (service-role bypasses RLS). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-182-01 | Information Disclosure | `require_canvas()` on both routes | mitigate | Both routes gate on `require_canvas()` ALONE — byte-identical 404 when off, pre-auth (D-182-05). Do NOT stack `require_visible` (raises 403 → leaks route existence, Pitfall 3). |
| T-182-02 | Tampering | `POST /validate` body parsing | mitigate | `WorkflowDefinition` with `extra="forbid"` → 422 on any malformed/injected body key (V5). Never relaxed to a lenient dict. |
| T-182-03 | Information Disclosure | grounding + bundle reads | mitigate | Owner-scoped reads by `user_id` (`fetch_visible_folders` / `_skill_registry`); the palette never widens to another user's folders/skills. |
| T-182-04 | Tampering / Elevation | client submits a definition bypassing tool whitelist / grounding | mitigate | ALL checks server-side; the bundle (not a frontend constant) is the palette source. `/validate` is READ-only advice — never persists or executes; publish remains the enforcing gate (D-182-06). |
| T-182-SC | Tampering | npm/pip/cargo installs | accept | Zero package installs this phase — reuse/route-add only; no new dependency. |
