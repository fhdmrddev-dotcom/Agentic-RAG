## ⚠ THE RULE THAT MAKES THIS FILE NECESSARY

> **A machine check that bypasses the human's task does not verify the human's task.**

Phase 192 shipped a repaired fork and verified it with a driver that located the repaired row by
`getElementById` on a known UUID. That proved the code. It could not prove the row was **findable**,
because the driver never had to find it — and the operator, who did have to find it, could not. That
is D-27, the rule 192.1 restored, and it binds every row below.

**No row in this file may locate its target that way.** Search for it. Read the words on the screen.
Point at the thing you read. Click the thing you pointed at. If at any moment you reach for a
selector, an id, a UUID, a console or DevTools' element picker **in order to find something**, that
row is not being driven — stop and record it ⛔ with the reason rather than converting it into a
check that cannot fail.

*(DevTools is sanctioned for exactly one purpose in this file — **U7**, where it BLOCKS a network
request to force a launch failure. It is used to break something, never to find something.)*

today** (D-20: hiding on unknown would silently strip the shipped WFIN-01 capability from
three-quarters of the library). **This asymmetry is a decision. Do not report it as an
inconsistency** — report it only if one of the two behaves differently from the table above.

reads **`⚡ Drafting it for you`**. That glyph asymmetry is a **consequence** of D-23's wording, not
a discretionary choice anyone made — and it is **U6's job to judge it by looking**, not to assume it.

### Residual 4 — the govern door's FIRST SCREEN changed AFTER these rows were written

first, and drive it on someone who has not seen the Builder.**

   door cards). Do not click a door.

   *"What happens if you pick the left one? The right one?"*

observation was an operator who could not name the door they were not standing in.

### U7 — A launch failure is still VISIBLE when the template block is hidden
`req:` AUTH-03 · **D-17** · the `launchError` hazard, end-to-end.

`do:`
1. Open the **Run** modal on a workflow whose template block is **hidden** — a published row that
   positively does not admit (no `· needs a template` on its card, no `Template to fill` in the
   modal).
2. Force the launch to fail. **DevTools is sanctioned here and only here**: block the run request,
   or take the backend down, so `onRun` rejects.

`see:` A visible error message appears in the modal, announced to assistive tech, on a workflow that
has no template control at all. The run does not silently do nothing.

`fail:` **Nothing appears.** The modal sits there and the user has no idea the launch failed.

A naive hide would have made every non-template launch failure silent. `193-01` wrote a
falsification for this **before** the cut and drove it RED; this row is that guard checked at the
