<!-- Source: Slack's own reference — docs.slack.dev/reference/methods/chat.postMessage -->

| Item | Value |
|---|---|
| Method / URL | `POST https://slack.com/api/chat.postMessage` — **the host is a module constant (D-02)** |
| Content-Type | `application/json` or form-encoded |
| Auth | `Authorization: Bearer xoxb-…` — a POST `token` param is also accepted; **use the header**, so the token never lands in a body that could be logged (D-08) |
| Required scope | `chat:write`. `chat:write.public` only to post to a public channel the bot has not joined; `chat:write.customize` only for username/icon overrides — **190 needs neither** |
| Required args | `channel` (channel / group / IM id) plus `text` |
| Rate limit | ~1 message per second per channel, with burst |

**⚠ THE TRAP, stated by the vendor:**
> Errors return **HTTP 200** with a JSON body `{"ok": false, "error": "<code>"}`.

**The adapter contract:** a Slack send is successful **iff `resp.status_code == 200` AND
`json()["ok"] is True`.** Anything else fails the phase (D-17 → `failed`).

Codes to surface verbatim (071-A): `channel_not_found` · `not_authed` · `invalid_auth` ·
`missing_scope` · `rate_limited` · `no_text` · `invalid_blocks` · `too_many_attachments`.
**They are rendered, not translated** — a paraphrase is a second truth-teller.

**No shared response helper with Jira.** Jira signals errors with proper HTTP status codes;
Slack does not. Flattening the difference *is* the defect (UI-SPEC §8c, RESEARCH § Anti-Patterns).

**Why the fixed host matters beyond Slack.** D-02 makes this the one destination that is
unforgeable by construction — which gives the egress suite a real negative control and reduces
the attack surface by a third for free. The surface says so out loud: the Settings row carries a
`fixed` tag and the form says *"it cannot be pointed anywhere else, by you or by a workflow."*
</interfaces>

**`send`**:
1. Build the JSON body `{channel, text}` from the resolved inputs and the non-secret `config`.
2. Call `egress.send_pinned_http` with `POST`, `SLACK_API_BASE + "chat.postMessage"`, the JSON
   body, an `Authorization: Bearer <token>` header, an explicit timeout and the size cap.
   **The token goes in the header, never in the body** (D-08).
3. Parse the JSON. Return `AdapterResult(ok=True, ...)` only when `status_code == 200` and
   `payload.get("ok") is True` — an identity check against `True`, not truthiness, because
   `"ok": "false"` is a string and truthy.
4. Otherwise return `AdapterResult(ok=False, provider_message=<the verbatim error code>,
   raw_status=<status>)`. Render, never translate. **Never retry**, including on
   `rate_limited` (D-18).

**`check`** — `auth.test` through the same binder, returning the bot/user identity for
UI-SPEC §5c's *"Authenticated as {identity}"*. It posts nothing, and the test asserts that.

| bot token → request body / logs | A token in a body is a token in a log |
