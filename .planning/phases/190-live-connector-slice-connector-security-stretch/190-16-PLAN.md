<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rendered row → the reader | A secret, ciphertext or token must never reach a rendered string, a `data-` attribute, an `aria-label` or a console line |
| hidden control → the API | UI-SPEC §2b: a hidden button the API still honours is the defect the 069-A contract exists to prevent |
| platform-wide fact → a per-row surface | Telling a platform truth on 24 rows is 24 identical amber lines |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-190-16-T7 | Information disclosure | the rendered table | mitigate | The response model carries no ciphertext (plan 190-09); this surface renders only `name`, destination, counts, verdict and state. A test asserts no secret-shaped key appears in the rendered DOM |
| T-190-16-U02 | Elevation of privilege | the Add affordance | mitigate | The button is REMOVED for a non-admin and the API gate is the real enforcement (plan 190-09, driven by an API-only test). This surface's test asserts absence from the DOM, not merely `disabled` |
| T-190-16-A11Y | Denial of service (to a screen-reader user) | the `⋯` icon-only trigger | mitigate | `aria-label="More actions for {name}"` with three distinct names asserted across three rows; no Radix default relied on. Every state carries a glyph AND a word so it reads in greyscale |
| T-190-16-BANNER | Repudiation | the `live_connectors` OFF notice | mitigate | Exactly one banner node asserted and zero per-row notices; the technical name appears once, in a `<code>`, because it is the exact string the operator must find |
| T-190-16-DESTRUCT | Denial of service | Delete / Disable | mitigate | Victim-naming sheet graded by whether a victim exists, with the victim named in the button label; Enable flips directly (restorative asymmetry). Every write lands as a receipt, never a toast |
