<!-- The docx oracle is the authoritative spec for what tags the model fills. Extracted this session. -->

The coverage oracle the model is fed at emit time — `parse_docx_template_variables`
(`backend/app/services/template_render_service.py:356-413`, docx-only):
- Scalars: `{{ root.attr }}` where `root` is the context key → the oracle reports `root`
  (e.g. `{{ project_name.value }}` → scalar key `project_name`). The model emits these as
  `FlatScalar{key:"project_name", value, source_chunk_id, source_doc, source_page}`.
- Loop rows: `{%tr for r in rows %}` (table-row repeat — grows the table; python-docx CANNOT).
- Cited cells: `{{ r.<col>.value }}` → column `<col>` of collection `rows` (the cells the MODEL emits).
- Driver-computed / inline cells: `{{ r.score }}` (bare deref, NO `.value`) → EXCLUDED from the oracle.

The EmitFieldMap shape the model targets (`template_render_service.py:160-198`):
```
EmitFieldMap { scalars: list[FlatScalar], rows: list[FlatRow] }
FlatScalar  { key:str, value:str|None, source_chunk_id:str|None, source_doc:str|None, source_page:int|None }  # extra="forbid"; value=None = honest decline
FlatRow     { collection:str, cells:list[FlatScalar] }   # each cell's key = the column name
```

The production render context builder is the SANDBOX-INLINED `build_context`
(`tool_dispatcher.py:1225-1240`) — it applies NO numeric_hook. So `{{ r.score }}` as a
bare deref would render BLANK in production. The Score MUST be computed inline in the
Jinja template expression instead (see Task 2).

docxtpl renders inside a `SandboxedEnvironment(autoescape=True)`
(`tool_dispatcher.py:1267`) — standard Jinja filters/dict-literals/`.get()` are available;
arbitrary Python is not. An inline dict-lookup + multiplication expression is supported.
</interfaces>
