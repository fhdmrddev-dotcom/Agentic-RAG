### `supabase/migrations/077_tuner_runs.sql` (migration, CRUD) — D-07/D-08 **[the only genuinely net-new artifact]**

**Migration number confirmed:** highest existing is `076_messages_origin.sql`; `077` is correct. No letter suffixes (CLAUDE.md: `007b`-style is silently skipped).

**Three composite analogs** (this table borrows one trait from each):

**Analog A — owner+global RLS template** (`017_skills.sql:25-41` for the parent + `:73-82` for a child-of-skills SELECT). The `tuner_runs` row references a skill, and a global skill's run must be readable by anyone who can see the skill, so mirror the **`skill_files` child SELECT** (the `EXISTS(... skills.is_global)` form), NOT the bare parent form:
```sql
-- Source: supabase/migrations/017_skills.sql:73-82 (skill_files SELECT — owner OR parent-skill-global)
CREATE POLICY "Users can view files on own or global skills"
  ON public.skill_files FOR SELECT
  USING (
    auth.uid() = user_id
    OR EXISTS (
      SELECT 1 FROM public.skills
      WHERE skills.id = skill_files.skill_id
        AND skills.is_global = true
    )
  );
```

**Analog B — service-role-write, SELECT-only RLS + the "durable companion to ephemeral Redis" framing** (`035_runs_table.sql:15-17,47-53`). `tuner_runs` is exactly this shape: a durable record that survives a Redis TTL, written ONLY by the service-role backend (so NO INSERT/UPDATE/DELETE policies — service-role bypasses RLS), read via a single SELECT policy:
```sql
-- Source: supabase/migrations/035_runs_table.sql:47-53
-- D-061-08: SELECT-only RLS via auth.uid() = user_id. Backend writes go
-- through service-role and bypass RLS by design.
ALTER TABLE public.runs ENABLE ROW LEVEL SECURITY;

CREATE POLICY runs_select_own
  ON public.runs FOR SELECT
  USING (auth.uid() = user_id);
```
> The header comment in `035` is itself a model for `077`'s docstring: "Companion to the ephemeral Redis Stream `run:{run_id}` (TTL …). This table is the durable record — survives Redis TTL expiry." `077` says the same about `tuner_result:{run_id}` (TTL 600s).

**Analog C — jsonb config column + UNIQUE constraint + the apply-discipline header** (`056_workflow_definitions.sql:16-33`). For the `scoreboard jsonb` payload, the `UNIQUE(skill_id)` latest-wins key, and the indexes:
```sql
-- Source: supabase/migrations/056_workflow_definitions.sql:16-33 (jsonb + UNIQUE + indexes)
CREATE TABLE public.workflow_definitions (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    ...
    definition  jsonb NOT NULL DEFAULT '{}',     -- parsed by WorkflowDefinition.model_validate()
    created_by  uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    is_global   boolean NOT NULL DEFAULT false,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT workflow_definitions_slug_version_unique UNIQUE (slug, version)
);
CREATE INDEX idx_workflow_definitions_created_by ON public.workflow_definitions(created_by);
```
And its **apply-discipline header** is the exact comment block to reproduce in `077` (CLAUDE.md mandate):
```sql
-- Source: supabase/migrations/056_workflow_definitions.sql:9-11
-- Apply via the Supabase SQL editor in order ... (never `db push`/`db reset`),
-- then `bash scripts/regenerate-full-schema.sh`. This file is authored only; Plan NN
-- applies it (autonomous:false) per CLAUDE.md.
```

**Recommended `077` skeleton** (planner finalizes columns; RESEARCH §"Pattern 1" has the full proposal). Load-bearing shape:
- `skill_id uuid NOT NULL REFERENCES public.skills(id) ON DELETE CASCADE`
- `user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE` (whoever last ran it)
- `scoreboard jsonb NOT NULL DEFAULT '{}'` (the full `TunerScoreboard`)
- `builder_model text`, `target_count int`, `case_count int` (D-12 attribution)
- `CONSTRAINT tuner_runs_skill_unique UNIQUE (skill_id)` — latest-wins upsert key
- `CREATE INDEX ... ON public.tuner_runs (user_id)`
- RLS: ENABLE + the **child-of-skills SELECT** (Analog A form). NO write policies (Analog B).

**Open product confirmation (RESEARCH A3 / OQ1):** `UNIQUE(skill_id)` (one shared latest per skill — recommended) vs `UNIQUE(skill_id, user_id)` (per-user latest on a global skill). Default to `UNIQUE(skill_id)`. Flag at plan time.

**Post-apply:** paste into Supabase SQL editor (NOT `db push`), then `bash scripts/regenerate-full-schema.sh` (no `--reset`), commit BOTH `077_*.sql` AND `supabase/full-schema.sql`. Never hand-edit `full-schema.sql`.

**Owner-scope gate to reuse (the SOLE leak gate — DO NOT reinvent)** (`:133-162`):
```python
# Source: backend/app/api/skill_tuner.py:133-162
async def _fetch_owned_or_global_skill(supabase: Client, skill_id: str, user_id: str) -> dict:
    def _read():
        return (
            supabase.table("skills")
            .select("id, name, description, user_id, is_global")
            .eq("id", skill_id)
            .or_(f"user_id.eq.{user_id},is_global.eq.true")
            .limit(1)
            .execute()
        )
    try:
        resp = await run_in_threadpool(_read)     # supabase-py is blocking (D-v2.5-01)
    except Exception:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Skill not found")  # malformed uuid → 404
    rows = list(resp.data or [])
    if not rows:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Skill not found")  # 404 never 403
    return rows[0]
```

### `backend/app/services/skill_tuner_service.py` (service, transform) — D-05

**Analog: `auto_seed_cases` itself** (`:234-268`) — currently returns bare strings `{"should_fire": [...], "should_not": [...]}`. D-05 needs **provenance** carried so the editor can distinguish `seeded` (own description / generic off-topic) from `sibling` (another skill's description). Extend it (or add a sibling fn) to return `(prompt, provenance)` pairs:
```python
# Source: backend/app/services/skill_tuner_service.py:234-268 (the seed to extend with provenance)
def auto_seed_cases(skill: dict, sibling_skills: list[dict]) -> dict[str, list[str]]:
    name = (skill.get("name") or "").strip()
    description = (skill.get("description") or "").strip()
    should_fire: list[str] = []
    if description:
        should_fire.append(description)                                  # → provenance "seeded"
        should_fire.append(f"I need to {description[0].lower() + description[1:]}" ...)  # → "seeded"
    if name:
        should_fire.append(f"Use the {name} skill.")                     # → "seeded"
    should_not: list[str] = []
    for sib in sibling_skills:
        sib_desc = (sib.get("description") or "").strip()
        if sib_desc and sib_desc != description:
            should_not.append(sib_desc)                                  # → provenance "sibling"
    should_not.extend(_GENERIC_OFF_TOPIC)                                # → "seeded" (generic)
    return {"should_fire": [...], "should_not": [...]}
```
**Leak boundary (preserve):** the sibling list MUST keep coming from the owner-scoped `fetch_owner_scoped_siblings` (`:271-293`, `.or_(user_id.eq.{id},is_global.eq.true)`) — `auto_seed_cases` never reads the DB itself, so the scope can't widen here. Do not break this when exposing provenance.

> **`held` provenance is derived, not authored** (RESEARCH Pitfall 4): the 60/40 held-out split happens at SCORING time (`split_held_out`, per-class), not seed time. Backend returns `seeded`/`sibling` only; `held` is either a client-derived display tag or dropped from the union. Decide explicitly.
