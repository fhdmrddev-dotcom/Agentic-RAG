## Decisions Made

- **`held` tag resolution (per the plan's two-option choice):** DROPPED `held` from the `EditorCase` provenance union. The backend only ever emits `seeded`/`sibling`, the author adds `you`, and the 60/40 split bar already owns the honest train/held-out display — so a per-case `held` tag would be dead/fabricated. The union is now exactly the three provenances a case can carry. (Plan acceptance criterion: "held is resolved — either derived from the 60/40 math, OR removed from the union; documented in SUMMARY.")
- **Cost-preview count source (`has_key && non-empty models`):** Followed the plan's D-12 interface note and acceptance test verbatim. The frontend `ProviderInfo.models` is a `string[]` (not the "string" the plan prose mentions), so "non-empty models" = `models.some(m => m.trim().length > 0)`. This is the frontend analog of the backend `configured_targets` presence filter (key-OR-base_url); the plan explicitly directs the `has_key`-keyed analog, and the test asserts a keyed-but-empty-models provider and a models-but-no-key provider are excluded → count `2`.
- **`previewModelCount` precedence:** running in-flight `targets.length` → persisted `latestRun.target_count` → live `configuredTargetCount`. So the preview is populated on open (pre-run), reflects the authoritative measured count after a completed run, and tracks the actual target set during a run.
