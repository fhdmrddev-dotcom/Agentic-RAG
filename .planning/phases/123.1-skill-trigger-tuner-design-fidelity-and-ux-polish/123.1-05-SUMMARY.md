## Accomplishments
- **Backend cap (Task 1, TDD):** `MAX_SEEDED_SHOULD_NOT = 8` named constant caps the sibling-sourced false-fire bait inside `auto_seed_cases` (a pure post-fetch slice of the already-leak-safe owner-scoped sibling list). The fixed generic off-topic baseline is always kept in full. `seed_cases_with_provenance` now exposes `should_not_total` (the uncapped sibling count) and `GET /tuner/cases/seeded` returns a top-level `total`. The cap applies to BOTH the run path and the editor seed so the editor shows exactly what runs. Run-time bonus: per the audit backlog §5, the uncapped seed × 3 repeats × slow coerce providers took many minutes; the cap is now load-bearing for run time, not just legibility.
- **Legible bounded CaseEditor (Task 2):** prompts bumped `text-xs → text-sm`, sub-label `text-[10px] → text-xs`, ProvenanceTag `text-[9px] → text-[10px]`; case `<ul>` bounded with `max-h-[340px] overflow-y-auto scrollbar-thin`; per-column case count in each header; amber cap banner "showing N of M seeded · capped to keep the benchmark focused" + an honest "show all N" disclosure (toggles an explanatory note, never fabricates withheld cases); columns moved to a full-width two-up grid (`grid-cols-1 md:grid-cols-2`). `SeededCasesResponse.total` is threaded from the mount effect into a new `seededNotTotal` prop.
- **Full-width layout (Task 3):** the `lg:grid-cols-[minmax(0,360px)_minmax(0,1fr)]` rail is replaced by a full-width single-column stack (description → CaseEditor → run bar). The empty-results void is gone pre-run; results render full-width below the always-mounted editor once a run produces them (or a durable latest result rehydrates on open), reusing `ProviderScoreboard` / `LiveRunCard` / `CandidateCard` untouched.
- **Red line held (Task 4):** the git diff is confined to exactly the 6 allowed tuner files + planning docs; no agent_loop / threads.py / anthropic_service / StreamsProvider / useMessages / ProviderScoreboard / CandidateCard / scoring core change.
