<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| unauth internet → /setup/* writes | Pre-auth surface with NO RLS backstop — the setup token + finalize latch are the SOLE access authority (exactly like /admin's require_operator) |
| browser → /public-config | An open endpoint that must expose ONLY the two public Supabase values |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-158-01 | Spoofing / Elevation | first-run hijack | mitigate | Every `/setup/*` write depends on `require_setup_token` (constant-time `hmac.compare_digest` in setup_store); the token is printed only to `docker compose logs backend` (host/log access = the legitimate operator). |
| T-158-02 | Tampering | config write after finalize | mitigate | `require_setup_token` asserts `not setup_finalized()` → 409 on every write; re-config is `/admin`-only (D-14). A post-finalize re-POST cannot mutate config. |
| T-158-08 | Elevation | token brute-force | mitigate | The token-verify path is rate-limited (429 on exceed) atop the 256-bit token + constant-time compare. |
| T-158-04 | Information Disclosure | secret leakage | mitigate | `/public-config` returns ONLY `supabase_url` + `supabase_anon_key` (both public); no endpoint returns the service_role key / DSN / provider key / store contents; probe reasons are sanitized (158-05). |
| T-158-03 | Information Disclosure / SSRF | /setup/validate | mitigate | Delegates to the sanitized 158-05 probes (only `type(exc).__name__` reflected); token-gated so the submitter already has host access. |
| T-158-06 | Spoofing | operator create endpoint | mitigate | GoTrue password error → 400 verbatim; duplicate → 200 already_exists; never a 500 that hides the real cause. |
| T-158-SC | Tampering | pip installs | accept | Zero new packages (fastapi/starlette already present). |
</threat_model>
