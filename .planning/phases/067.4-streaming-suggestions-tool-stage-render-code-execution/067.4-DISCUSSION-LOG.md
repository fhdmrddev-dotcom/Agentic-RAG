## Claude's recommendations + rationale (delegated decisions)

### R-3 strategy → Capture uvicorn stdout live first, branch by which Plan 04 log line fires

**Why systematic:** Plan 04 already invested in this exact instrumentation specifically for this UAT cycle. Reading what we shipped is the cheapest evidence-first move. **Why clean close:** branches the fix logic on observable evidence rather than guessing. **Why flexible:** if the captured log points to root cause (a) exception-class + `suggestion_service` LLM call, we narrow `except Exception:` AND fix the underlying exception; if (b) empty `[]` from LLM, we fix prompt or model resolution; if (c) reasoning-token starvation, we swap `_SUB_AGENT_MODEL_DEFAULTS["openai"]` from `gpt-5.4-mini` to a non-reasoning model. Each branch is a one-plan-cycle fix. **Fallback:** focused integration test that calls `generate_suggestions(...)` directly — gives a deterministic local repro for whichever branch we pick.

### R-4 scope → Surgical handler-by-handler patch + regression test

**Why systematic:** isolates the fix to specific SSE event handlers that missed Plan 03's per-thread-bucket update. **Why clean close:** the regression test guards against future refactors silently breaking it. **Why flexible:** if R-4's pattern recurs (new SSE event types added in 067.5+), THAT phase can introduce a centralized dispatcher with proper test coverage — but 067.4 itself does NOT pre-emptively refactor (which would risk a second-wave R-1 regression). Surgical = reversible and incremental; the right posture for a Plan 03 R-1 regression candidate that we just shipped two days ago.

### R-5 cadence → Line-by-line (each `\n` triggers SSE emit)

**Why systematic:** matches the existing `delta` event pattern — reuses the per-thread bucket append already validated in Plan 03 R-1 and what Plan 02 R-4 will lock down. **Why clean close:** no buffer-flush logic to forget at end-of-execution (a class of bug that bit 067.2 Plan 03's `tool_end` finalizer). **Why flexible:** if observability later shows perf issues at high stdout volumes, time-buffering is a one-line change behind the same SSE event name — backward-compatible with the frontend handler. Sandbox stdout volume is far lower than LLM token deltas, so chattier network is a non-issue.
