## R-1 Spot-Check Evidence

Vitest Test 2 (`preserves both threads' renders during cross-thread switch (R-1 protection)`) PASSES — this is an automated-test equivalent of the manual Bread/Physicists cross-thread switch protocol from 067.3 Plan 05. The test:

1. Sets viewing thread = `thread-A`, calls `sendMessage("thread-A", "hello A")`, waits for `subscribeToRun` to capture Thread A's `StreamCallbacks`.
2. Switches viewing thread to `thread-B` via `setViewingThread("thread-B")`.
3. Fires Thread A's callbacks (`onDelta("partial response from A")` + `onToolPreparing` + `onToolEnd`) while viewing Thread B — must land in Thread A's bucket.
4. Switches back to `thread-A` via `setViewingThread("thread-A")`.
5. Asserts `result.current.messages.find(m => m.role === "assistant")?.content` contains `"partial response from A"`.

This is the load-bearing R-1 invariant. Future regressions that re-introduce a single-array race (or that bind `setMessages` to a mutable ref instead of capturing `threadId` in closure) will break Test 2.

Live cross-thread Chrome MCP run NOT performed (same MCP-availability constraint). Closing UAT (Plan 05) owns this human-verification step alongside R-4 closing.
