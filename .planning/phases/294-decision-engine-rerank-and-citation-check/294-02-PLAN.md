<objective>
Freeze a held-out question set first, then build the harness that measures each engine against rerank-off on the real search path, then run it and commit the report (SC#3, D-18, D-19). SEED-020 ("a rerank stage now exists … never been benched") is folded here.

Orchestrator decision OQ1 (measurement half): the measurement uses a candidate pool of **20** (`rerank_top_n = 20 = hybrid_candidate_count`) and `retrieval_top_k = 5`, so pruning has room to act. With the local defaults (pool 5) an engine can save at most 2 chunks. The report states both numbers.

Freeze-first is enforced by order and by hash, not by intent: Task 1 commits the fixture and its sha256 sidecar before any harness or engine code runs against it, and the question writer (the executor) reads chunk text only, never an engine output. Planner choice (Claude's Discretion, D-18): the executor writes the questions at Task 1 rather than the planner, because the planner's freeze would carry the same guarantee and the executor has the DB session; the hash and the commit order are the proof.

Purpose: SC#3 must be measured, not asserted. An engine that drops the answer or costs more than it saves must say so in numbers.
Output: frozen fixture + sidecar, `decision_eval.py`, the CLI, the report (or its honest refusal), SEED-020 routed.
</objective>
