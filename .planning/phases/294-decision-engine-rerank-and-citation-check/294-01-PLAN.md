<objective>
Build the decision-engine rerank seam behind the existing `rerank()` (DEC-01 engine dispatch, DEC-02 rerank + prune + steering + fail-to-current-order), fix the two defects research found in the existing seam (failure returns the whole pool; the local model never reloads), and stop provider keys reaching LangSmith on the two traced functions this phase owns.

Purpose: every later plan builds on this package. Plan 02 measures it, plan 03 reuses `post_decisions` for the citation check, plan 04 imports the engine ids for the Settings allowlist and cards.

Orchestrator decisions recorded here:
- **Cohere and Local keep reorder + today's `top_n` cut** (D-08 answered by research: neither is a calibrated probability).
- **Research Open Question 4 (orchestrator OQ2) — no "always keep the pre-rerank top-1" protection.** D-07 stays exactly as locked. Deferred idea: "never prune the RRF best passage" (it only keeps more than D-07 and bounds an injected "everything else is irrelevant" passage); re-open if the plan 02 measurement or the planted-steering UAT row shows an injected passage pruning the answer.
- **Research Open Question 2 (orchestrator OQ3) — no OpenRouter `provider: {zdr, data_collection}` flag on Jev requests.** TypeSafe's support for it is unknown, and an unsupported flag would make every call fail and fall back. The D-05 egress notice (plan 04) covers it. Deferred idea: "send ZDR for Jev"; re-open if the operator asks for zero-data-retention routing.

- **Local first use (checker W6 / N6), one concrete approach:** the Local engine never blocks a chat search on loading the model. If the requested model is not resident, `local.rerank` starts a single-flight background load and raises `LocalModelWarming`; the dispatcher falls back to the rerank-off output until the model is resident, logging a distinct INFO line ("local rerank model <name> still loading — keeping the current order") rather than the generic engine-failure WARNING. A failed load is retried only after `LOAD_RETRY_COOLDOWN_S = 300`, so a broken model name cannot start a download per search. Each uvicorn worker (WORKER_COUNT=2) holds and loads its own copy; an out-of-process warm-up only fills the Hugging Face disk cache. `local.warm(model_name, wait=True)` is the explicit warm-up the measurement harness (plan 02) and the live drive (E1) call first. Inference itself is not time-bounded (CPU scoring of ≤ 50 pairs; its latency is measured by plan 02). The Local card copy in plan 04 says the first use downloads about 2.3 GB and that searches keep today's order until it has loaded.
- **Live forced failures (checker blocker 1 + round 2, D-22 kept as locked), Task 4:** a dev-only endpoint-base override `DECISION_ENGINE_FAULT_BASE_URL` plus `scripts/decision-fault-server.py` (stdlib, binds 127.0.0.1 only, mode switched at runtime through a loopback-only `POST /_mode/<mode>`) let the live drive force 401, slow, 429, 500, malformed, refusal and missing-answer responses through the real app with ONE base URL and ONE backend restart. The override needs an explicit local / dev / test ENVIRONMENT and a strictly validated loopback URL, which is rebuilt from its parts; when honoured, the request carries a dummy token, never the stored key. `scripts/local-provider-key-custody.py` exists only for the optional real-key swap (VALIDATION F1/F2 extra).

Output: the `rerank_engines/` package, a thin `rerank_service.py`, the `instruction` argument wired from the tool schema to the engines, one unquantised cost helper in `pricing_service.py`, the redaction on both existing traceables, and BUG-261020-03 for the four traced functions outside this phase.
</objective>
