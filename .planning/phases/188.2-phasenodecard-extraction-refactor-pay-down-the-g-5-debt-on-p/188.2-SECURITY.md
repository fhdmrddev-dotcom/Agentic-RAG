**Severity:** low exploitability, but a **measurably false coverage claim** in a declared

**Where:** `frontend/src/components/workflows/PhaseNodeCard.test.tsx:592-593`, consumed by

### FLAG-01 — `verticalOffsetFor` is a sixth, **unguarded** WR-04 sink, and this phase amplified its consequence

**Where:** `frontend/src/components/workflows/editAffordance.ts:220-224`.

**Confirmed at HEAD by reading the function:**

```ts
const live = overlay[slug]
if (live !== undefined) return live.y - laneY
return nudges?.[slug] ?? 0
```

`overlay` (`dragOverlay`) and `nudges` are plain `Record<string, …>` objects and `slug` is a
workflow-definition phase slug — author-supplied, written by the AI-seed door, with no
pattern constraint. `overlay["constructor"]` is the `Object` function: never `undefined`, so
the guard passes, `live.y` is `undefined`, and the function returns `NaN`. `"__proto__"`
behaves identically, and the `?? 0` on the `nudges` line does not fire for the same reason.
This is precisely the defect class the phase's own `ownProperty.ts` exists for.

**Why it belongs in *this* phase's record.** Three things:

1. `editAffordance.ts` is a file **this phase edited** (it is where `AFFORDANCE_Z` was added).
2. `verticalOffsetFor` feeds the `translate(…px, …px)` transform on the three elements this
   phase gave `zIndex: AFFORDANCE_Z` — verified at `PlaneEditingLayer.tsx:176-177`, `:225`,
   `:256-262`, the same style objects as `:183`, `:231`, `:269`. A `NaN` collapses the whole
   CSS declaration, so the affordance lands at the viewport origin — and **now that it carries
   z-index 1002 it lands there *above* the cards** rather than behind them. The phase's own fix
   made the failure mode more visible, not less.
3. It is **not** covered by `D-188.2-DEF-02`. That deferral names four sites
   (`lib/phaseState.ts:77`, `lib/phaseGlyph.tsx:92`, `PhaseNode.tsx:167`,
   `nodePresentation.ts:128`) which are each *already correct* — it is a de-duplication, not a
   fix. `verticalOffsetFor` is unguarded, and appears in no deferral.

Pre-existing (moved verbatim by 188.1-03), and jsdom is structurally blind to it. The fix is
one import of the zero-import leaf this phase just created — `editAffordance.ts →
ownProperty.ts` opens no cycle — falsified first by driving `PlaneEditingLayer` with
`phaseOrder: ["constructor"]` and asserting the rendered `style.transform` contains no `NaN`.

**Also still unguarded, inherited:** `frontend/src/lib/providerLogo.tsx:107-108`
(`D-188.1-DEF-02`) — byte-for-byte the defect `188.1-04` closed at `phaseGlyph.tsx:92`,
