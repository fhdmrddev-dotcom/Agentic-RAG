<decisions>
## Implementation Decisions

### What "paid down" means

- **D-01: Cut by code seams — extract real modules; the prose travels WITH its code.**
  Rejected: re-measuring G-5 on code lines and declaring the row doesn't fire (defensible, but it
  overturns a call the operator made deliberately at the 188.1-05 checkpoint). Also rejected:
  relocating prose to a companion doc — the fences grep the SOURCE, so every pinned docblock would
  break, and co-located prose is prose that actually gets read.

- **D-02: The 427-line component body MUST shrink — peripheral cuts alone are not enough.**
  The ROADMAP goal names 189's diff, and 189 writes in the body (badge slot 1 + subtitle). Cutting
  only the slot contract (147 L) and ring constants (84 L) would drop the file 797 → 566 and leave
  the body *untouched* — satisfying the ledger while missing the goal. The four absolutely-
  positioned mark blocks are therefore in scope, and so is their fence risk.

- **D-03: The acceptance bar is a body-line target carried WITH both totals.**
  Pin three measured numbers before/after: **total lines, CODE lines, and the component body.**
  The body figure is the one that answers the goal. Carrying all three is what stops a 62.5 %-prose
  file ever again reading as 797 lines of code. A named target the plan must hit — **not** 188.1's
  "measurably smaller", which is the bar that let this happen.

### Which seams to cut

- **D-04: Four modules, grouped by concern — one reason to change each.**

  | Module | ~L | Contents |
  |---|---|---|
  | `phaseNodeCardContract.ts` | 147 | `BadgeSlot`, `BadgeSlot2Tuple`, `BadgeSlots`, `NodeVerdictMark`, `NodeRunStatus`, `PhaseNodeCardProps` |
  | `NodeRunOverlay.tsx` | 104 | status ring (`RING_*` consts + SVG) + pause chip — 188's run mode |
  | `NodeCornerMarks.tsx` | 90 | verdict mark (left) + ⛨ governance seal (top-right) |
  | `NodeIconWell.tsx` | 34 | the 3D mark ⚠ carries the clip-fence prose |
  | **`PhaseNodeCard.tsx`** | **~300** | docblock + the 137-B card; body ~170 L |

  Names are indicative, not locked — planner may improve them, but the GROUPING is the decision.
  Rejected: one omnibus `NodeMarks.tsx` (five reasons to change, mixes 184/185/188 ownership);
  and leaving verdict+seal inline (smaller fence risk, but body lands ~260 L instead of ~170).

- **D-05: `own<T>()` gets ONE shared home the new modules import.**
  Its two call sites split across two destinations — `VERDICT_MARK` at `:434` → `NodeCornerMarks`,
  `RING_STROKE` at `:731` → `NodeRunOverlay`. The helper's own docblock records a prior decision
  ("one concept, two small private copies, is cheaper than one shared function with a blast
  radius") — but that decision weighed *two* copies against widening `runVocabulary`'s
  module-private, `CanvasReading`-typed `own()`, whose `?raw` fences constrain that signature.
  A small dedicated module is a third option that decision never had to consider, and it beats
  three copies. **`runVocabulary.ts` keeps its own private copy — its fences stay untouched.**

- **D-06: The two importers update; the card does NOT re-export the contract types.**
  Measured blast radius is **2 lines** (`PhaseNode.tsx:92`, `PhaseNodeCard.test.tsx:45`). A
  re-export that exists so nobody has to change two lines is a second name for the same type — free
  to be the one 189 imports by accident.

### The load-bearing prose rule

- **D-07: Adopt 188.1's subtree-source fence, verbatim, including its Wave-0 ordering.**
  A `CARD_SUBTREE_PATHS` list in `PhaseNodeCard.test.tsx` feeding `import.meta.glob('./*.{ts,tsx}',
  {query:'?raw', eager:true, import:'default'})`, **naming all four destination files BEFORE they
  exist** (a path with no file has no key and contributes `""` — it never throws). Every NEGATIVE
  fence reads the subtree source; positive assertions and per-file pins do not.
  **The fences are re-scoped and observed RED BEFORE any code moves** — this is 188.1's Wave 0, and
  its rationale is Phase 188's F7 lesson: *an invariance fence says nothing about what it no longer
  covers, and neither the count gate nor `tsc` can see the loss.*

  Carry all three of 188.1's non-vacuity controls (`WorkflowCanvas.test.tsx:591-615`):
  `toHaveLength(5)` · **each destination path named individually** (a length pin catches truncation
  but not SUBSTITUTION — measured RED under exactly that edit) · resolved module non-empty once created.

  Rejected: a whole-directory sweep (fences 60+ unrelated files; a negative assertion goes red for
  reasons unrelated to the card) and per-module fence copies (four copies of one rule set; a module
  added without them is silently unfenced).

  **Consequence, recorded so it isn't re-derived:** the `onClick=` fence at
  `PhaseNodeCard.test.tsx:214` is per-file today and would stop covering three of the four
  destinations. D-07 re-scopes it along with every other negative fence — no separate decision needed.

- **D-08: ⚠ THE MEASURED LANDMINE — the clip fence counts PROSE, and its one mention is moving.**
  `PhaseNodeCard.test.tsx:1745` asserts `phaseNodeCardSource.split(CLIP_UTILITY).length - 1 === 1` —
  deliberately pinning the prose so the *rule* can't be deleted as easily as the utility can be
  added. That single mention lives at **`PhaseNodeCard.tsx:772`, inside the 3D-mark JSX comment**,
  which D-04 moves to `NodeIconWell.tsx`. **Move it and the fence goes to 0 and RED.**
  **Decision: re-anchor the count to the subtree source** (`cardSubtreeSource.split(CLIP).length - 1
  === 1`). It stays 1 wherever the rule lives, and cannot be satisfied by shuffling prose between
  files — the exact failure mode a per-file count invites during a refactor. Rejected: moving the
  fence to `NodeIconWell?raw` (precise, but the ban covers the whole subtree, leaving the card, the
  card div and the node box unpinned) and not moving the 3D mark at all.
  Note `stripComments()` (`:1718`) must keep working over the joined subtree source.

- **D-09: Pin "a third badge is a typecheck error" with a falsification control, in Wave 0.**
  **Measured: this invariant is asserted NOWHERE.** The two-badge budget block
  (`PhaseNodeCard.test.tsx:218-267`) tests 0, 1 and 2 badges *rendering*; there is no
  `@ts-expect-error`, no reference to `BadgeSlot2Tuple`, and no type-level assertion in the suite.
  The constraint is real but exercised by no caller — so widening `BadgeSlots` to
  `readonly BadgeSlot[]` during the move would leave every test green. This is 188.1's
  vacuous-SC#4 lesson repeating on a different invariant, and CLAUDE.md + 189's D-12 both lean on it.

  ```ts
  const two: BadgeSlots = [a, b]              // legal
  // @ts-expect-error — a third badge is a typecheck error
  const three: BadgeSlots = [a, b, c]
  ```

  **Observe it RED first** against a deliberately widened union (the `@ts-expect-error` goes UNUSED
  ⇒ `tsc` errors), before the type moves.

### BUG-260806-01

- **D-10: Fixed HERE, in its own plan, as a NAMED exception to the phase's contract.**
  The phase contract splits cleanly and must be stated up front, never discovered later:
  **`PhaseNodeCard.tsx` + the four new modules → prove UNCHANGED. `PlaneEditingLayer` stacking →
  prove FIXED.** Precedent is `188.1-04`, which carried three bounded security fixes as its own
  plan for the same "sits in exactly this subtree" reason.
  Decisive argument: 188.2 will already be driving the canvas with `elementFromPoint` to prove the
  card unchanged, so this bug's reachability evidence is nearly free at that moment — whereas a
  `/gsd:fast` split (which G-3 would otherwise size it as: ≤1 file, ≤10 lines, no schema/API) needs
  its own driven verification anyway. Rejected: deferring to 189 (re-opens yesterday's routing and
  puts a major-severity user-facing defect behind a feature phase).

- **D-11: Guard it BOTH ways — one driven row plus a stacking assertion that re-runs.**
  jsdom has no layout, so **no unit test can see occlusion** (`.click()` bypasses hit-testing —
  `reference_chrome_mcp_drive_css_hover_and_hit_test`).
  - **Driven, once:** `elementFromPoint(✕ centre) === the ✕ button`, **with the card SELECTED** —
    the failing state. Deselected already passes, so a row that doesn't select proves nothing.
  - **Unit, every run:** the affordance layer's z-index **exceeds** xyflow's selected-node
    `z-index: 1000`, with both numbers NAMED rather than implied.

  A driven row alone is a one-time photograph — which is how this class survived from 184-12 to now.
