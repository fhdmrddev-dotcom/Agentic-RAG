<verified_library_facts>
Every claim below was verified against the installed `@xyflow/react@12.11.2` in
`frontend/node_modules` during planning. Treat them as given — do not re-derive them.

1. **`ReactFlowProps extends Omit<HTMLAttributes<HTMLDivElement>, 'onError'>`**
   (`node_modules/@xyflow/react/dist/esm/types/component-props.d.ts:8`), and the component
   spreads `...rest` onto its wrapper `div` BEFORE its own `onScroll`. `onKeyDown` is
   therefore a **typed, supported prop** on `<ReactFlow>` — no cast, no `@ts-expect-error`.
2. **The library's per-node `onKeyDown` does not stop propagation and does not call
   `preventDefault` on Enter/Space** (`dist/esm/index.js:2282-2310`). A handler on the
   wrapper `div` reliably receives the bubbled event.
3. **The node wrapper carries `data-id={id}` and `className="react-flow__node …"`**
   (`dist/esm/index.js:2349`), so `(e.target as HTMLElement).closest(".react-flow__node")`
   → `.dataset.id` yields the node id, which for a phase node IS `phase.slug`.
4. **`ariaLabelConfig?: Partial<AriaLabelConfig>`** is a supported `<ReactFlow>` prop
   (`component-props.d.ts:646`).
5. **The description actually rendered on THIS canvas is the `keyboardDisabled` key, not the
   `default` key.** The library's `A11yDescriptions` renders
   `disableKeyboardA11y ? 'node.a11yDescription.default' : 'node.a11yDescription.keyboardDisabled'`
   (`dist/esm/index.js:93-94`) — an inverted-looking mapping. Since this canvas leaves
   `disableKeyboardA11y` at its `false` default, the string users hear today is the LONGER one:
   *"Press enter or space to select a node. You can then use the arrow keys to move the node
   around. Press delete to remove it and escape to cancel."* **Override BOTH keys** so the fix
   is correct regardless of that mapping.
6. **The description element id is `react-flow__node-desc-{rfId}`** with `rfId` defaulting to
   `"1"` (`dist/esm/index.js:82,93`), and each node points at it via `aria-describedby`.
   Select it in tests with `container.querySelector('[id^="react-flow__node-desc"]')`.
7. **No canvas fixture uses `citation_policy: "partial"`** — `canvasFixtures.ts` contains
   exactly five `citation_policy` occurrences, all `"strict"`. The WR-01 change therefore
   must NOT alter `__snapshots__/canvasModel.fixtures.test.ts.snap`. Re-running the snapshot
   suite **without `-u`** is the proof.
8. **Hoisting the glyph lookup into a module-scope leaf component does NOT clear
   `react-hooks/static-components`** — verified experimentally during planning; the rule fires
   inside any component body. A module-scope helper that returns a `ReactNode` via
   `createElement` DOES clear it (also verified). See Task 3.
</verified_library_facts>
