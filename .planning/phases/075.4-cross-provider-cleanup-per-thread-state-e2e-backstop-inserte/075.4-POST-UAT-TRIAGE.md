## UX / observability complaints (no error, but bad signal)

### F-3 — "Thinking…" / "Synthesizing answer…" placeholder shows instead of real thinking stream
- Backend gets actual thinking tokens (Anthropic native thinking, Google's reasoning_summary, OpenAI o-series CoT)
  but UI renders a generic placeholder string.
- Surface: ChatArea/MessageItem thinking-indicator. Need an `enable_thinking` /
  `thinking_stream` SSE event hookup so the placeholder is replaced with the
  actual streaming text when the model supports it.

### F-4 — Long pauses moving to execute_code (no SSE event during the gap)
- User can't tell whether the agent is stuck, computing, or about to render.
- Suspect: harvest_output_files / sandbox_service async-vs-thread interaction
  blocks the SSE keepalive in the gap between code_executing and final output.
- Could also be re-emergence of D-v2.5-01 violation in the harvest path.

### F-5 — Sub-agent UI mixed up (Gemini 2.5 pro showing alongside other model)
- Operator saw "gemini-2.5-pro" in the chat surface when the active provider
  was set to a different model.
- Could be the title-drafter / follow-up-suggestion model field leaking into
  the main-message provenance display.

### F-6 — Resume button appearing during active code execution
- Existing report at `.planning/reported-bugs/resume-button-appears-during-active-code-execution.md` — re-confirmed during 2026-05-23 UAT.
- The recovery path (buffer_expired) is firing on plain stream-end, not just expired buffers.

### F-7 — Real-status-not-reflected-in-UI (you'd think task is done but it's still running)
- Specific to long-running pptx generation: UI quiets before backend actually
  finishes; user thinks done, then output suddenly appears later.
- Tie to F-4 (SSE-event gap) and F-6 (recovery path misfiring).

### F-8 — LangSmith fails (operator: "please check")
- Operator reports a lot of LangSmith errors during the UAT session.
- Action: tail langsmith logs / check trace ingestion. Could be missing project
