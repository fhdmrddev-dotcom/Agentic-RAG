**Part B — Fill in `test_post_returns_before_producer_first_xadd`** (currently a stub assertion in `test_063_post_contract.py` per Plan 01).

The intent of this test: prove that the POST response returns BEFORE the producer task writes its first XADD entry to Redis (Pitfall 4 invariant — frontend must be able to open the GET stream the moment POST returns; if the producer's first XADD hasn't happened yet, the consumer's replay phase reads zero entries and immediately enters live-tail mode, which is fine — but the runs row MUST be SELECT-able).

Practical implementation: this can be tested with a real Redis fixture. The simplest, most-reliable form:

```python
@pytest.mark.asyncio
@pytest.mark.timeout(15)
async def test_post_returns_before_producer_first_xadd(redis_client):
    """D-063-01 Pitfall 4: POST returns synchronously; runs row INSERT
    happens before the response, but the producer's first XADD may not
    yet have landed. The frontend's subsequent GET /runs/{rid}/stream
    must therefore tolerate an empty buffer (replay phase reads zero
    entries → falls through to live-tail). This test asserts the
    invariant by checking that the runs row is SELECT-able the moment
    POST returns, regardless of XADD progress.
    """
    # ... mock supabase + slow-mock LLM (so producer's first XADD is delayed)
    # ... post and capture run_id
    # ... assert mock_supabase.table("runs").insert.call_count >= 1 (runs row INSERT happened)
    # ... assert response received within reasonable wall-clock (< 1s typical)
    # ... optionally: assert XLEN of run:{run_id} can be 0 immediately after POST
    #     (proves response did NOT block on producer XADD)
```

Concrete approach (per 063-PATTERNS.md "test_063_post_contract.py" section + 062 redis_down test fault-injection):

1. Use the slow-mock-LLM fixture from 058 (yields chunks slowly via `time.sleep` or yield-with-delay) so the producer's first XADD is delayed by ~500ms.

3. Assert `t1 - t0 < 0.5` (response returns in &lt;500ms — well before the slow-mock-LLM's first delta).
4. Assert `await redis_client.xlen(f"run:{run_id}")` &lt;= 1 immediately after POST (the buffer is small or empty, proving the response was NOT awaiting producer progress).
5. Wait for natural completion or terminate via `redis_client.delete(f"run:{run_id}")` cleanup.

```typescript
test("F5 mid-stream: assistant message reattaches via active-runs and continues animating", async ({ page }) => {
  await signIn(page)

  // Track network calls for evidence-based assertions.
  const requestLog: Array<{ method: string; url: string; phase: "started" | "finished" }> = []
  page.on("request", (req) => {
    if (
      /\/threads\/[^/]+\/active-runs$/.test(req.url()) ||
      /\/runs\/[^/]+\/stream/.test(req.url()) ||
      /\/threads\/[^/]+\/messages$/.test(req.url())
    ) {
      requestLog.push({ method: req.method(), url: req.url(), phase: "started" })
    }
  })
  page.on("requestfinished", (req) => {
    if (/\/runs\/[^/]+\/stream/.test(req.url())) {
      requestLog.push({ method: req.method(), url: req.url(), phase: "finished" })
    }
  })

  // Step 1: send long-stream prompt; ensure stream begins.
  await sendMessageInActiveThread(page, LONG_STREAM_PROMPT)
  // Wait until some content has been rendered into the assistant bubble.
  await page.waitForTimeout(3_000)

  // Snapshot pre-reload state.
  const preReloadActiveRunsCount = requestLog.filter(
    (r) => /\/active-runs$/.test(r.url),
  ).length
  const preReloadStreamCount = requestLog.filter(
    (r) => /\/runs\/[^/]+\/stream/.test(r.url) && r.phase === "started",
  ).length

  // Step 2: F5.
  await page.reload()

  // Step 3: assert reconcile fired — active-runs called AFTER reload.
  await page.waitForRequest(
    (req) =>
      req.method() === "GET" &&
      /\/threads\/[^/]+\/active-runs$/.test(req.url()),
    { timeout: 10_000 },
  )
  const postReloadActiveRunsCount = requestLog.filter(
    (r) => /\/active-runs$/.test(r.url),
  ).length
  expect(postReloadActiveRunsCount).toBeGreaterThan(preReloadActiveRunsCount)

  // Step 4: assert reattach — a new GET /runs/{rid}/stream was opened post-reload.
  await page.waitForRequest(
    (req) =>
      req.method() === "GET" && /\/runs\/[^/]+\/stream/.test(req.url()),
    { timeout: 10_000 },
  )
  const postReloadStreamCount = requestLog.filter(
    (r) => /\/runs\/[^/]+\/stream/.test(r.url) && r.phase === "started",
  ).length
  expect(postReloadStreamCount).toBeGreaterThan(preReloadStreamCount)

  // Step 5: assert assistant bubble continues to grow (proves SSE is flowing post-reload).
  const initialContentLength = (
    await page.locator('[data-testid="assistant-message"]').last().textContent()
  )?.length ?? 0
  await page.waitForTimeout(3_000)
  const finalContentLength = (
    await page.locator('[data-testid="assistant-message"]').last().textContent()
  )?.length ?? 0
  expect(finalContentLength).toBeGreaterThanOrEqual(initialContentLength)
})
```
