## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-138-04 | Elevation of Privilege / Tampering | `reconcile_open_todos_on_run_end` → `replace_todos` | mitigate | NO new API route or external entry point — the reconciler is invoked ONLY from the run's own finalizer closure with that run's `thread_id`; `replace_todos` scopes every statement by `thread_id = $1` and validates BEFORE the DELETE (a bad payload never wipes state). A caller cannot target a thread it does not own because thread_id is the run's own, not request-supplied here. |
| T-138-05 | Tampering (concurrency / double-fire) | two finalize paths + concurrent runs on one thread | mitigate | The two call sites are mutually exclusive per run (a given run finalizes through `_shielded_finalize` XOR `spawn_continuation_run._finalize`, never both). The marker is idempotent — D-04 skip-if-already-marked means a second pass finds nothing changed and returns without emitting. `replace_todos` is one transaction (DELETE+INSERT) with last-writer-wins MVCC, and the reconciler re-SELECTs the FULL current list so it never drops rows it did not author. |
| T-138-06 | Tampering (honesty / false-terminal) | the finalizer gates (D-05) | mitigate | SITE 1 uses the TWO-clause gate `_terminal_status == "completed" and _result_sink.get("cap_disposition") != "cap_paused"` — the cap_paused clause is load-bearing (S6): `_shielded_finalize` never reads cap_disposition, so a cap-paused Deep run arrives as "completed" and would be wrongly marked without it. SITE 2's `_terminal_status` is already `cap_paused` when the cap fired (~2106-2107), so its plain `== "completed"` gate is correct. cancelled/failed/timed_out never reach `== "completed"`. |
| T-138-07 | Denial of Service (finalizer integrity) | reconciler call inside the byte-locked finalize sequence (S5) | mitigate | Each call is best-effort `try/except BaseException` (logs, never raises) and positioned in the gap AFTER step-1 persist and BEFORE step-2 finalize_run — it cannot reorder or break the S5 byte-locked sequence (persist → finalize_run → sentinel → EXPIRE → ZREM). A reconciler failure degrades to "todo not marked", never a stuck/streaming run. |
| T-138-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages — reuses `replace_todos`, asyncpg, and the module `_emit`. No install task, so the package-legitimacy gate does not fire. |
