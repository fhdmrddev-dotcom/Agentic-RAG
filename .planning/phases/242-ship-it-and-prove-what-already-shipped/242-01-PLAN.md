<objective>
Turn a bound that lives only in Python into a constraint the schema enforces — and make the CLASS
stop recurring, not just the instance.

Purpose: `app_settings.multimodal_max_vision_calls` is bounded `1..1000` at
`backend/app/api/settings.py:467` and by nothing else. The column was added by migration 044 with
`DEFAULT 100` and **no CHECK**, so any writer that is not that endpoint — a psql session, a future
endpoint, a restored dump — can store a value the API will then refuse to accept back. That is what
made the operator's local Search tab unsaveable: a stored `1001` the operator never typed.

ROADMAP SC#3 asks for the **general** fix. Constraining every bounded column is explicitly deferred
(`242-CONTEXT.md` `<deferred>` — *"a phase, not a gap"*), so the general half is delivered the only
other way it can be: **an executable fence that fails when the next Python bound arrives without a
constraint**, plus a register entry naming the three columns whose sweep is owed.

Output: migration 178 (clamp-then-CHECK, re-runnable), applied to LOCAL only; a source fence driven
RED; `full-schema.sql` regenerated with no reset; SEED-271 planted.

⚠ **This plan changes no application code.** `git diff --stat -- backend/app frontend/src` must be
EMPTY at its close.
</objective>

    Body, in this order — **the order is load-bearing**:

    ```sql
    -- 1. Bring any out-of-range row into range FIRST. A CHECK cannot be added while a row
    --    violates it. Generalised: repairs whatever is out of range in ANY environment.
    UPDATE public.app_settings
       SET multimodal_max_vision_calls = least(greatest(multimodal_max_vision_calls, 1), 1000)
     WHERE multimodal_max_vision_calls IS NOT NULL
       AND (multimodal_max_vision_calls < 1 OR multimodal_max_vision_calls > 1000);

    -- 2. The constraint. DROP IF EXISTS first so the file is re-runnable.
    ALTER TABLE public.app_settings
      DROP CONSTRAINT IF EXISTS app_settings_multimodal_max_vision_calls_bound;

    ALTER TABLE public.app_settings
      ADD CONSTRAINT app_settings_multimodal_max_vision_calls_bound
      CHECK (
        multimodal_max_vision_calls IS NULL
        OR (multimodal_max_vision_calls BETWEEN 1 AND 1000)
      );
    ```

    ⚠ **`IS NULL` is permitted deliberately** and the file says why: `_val()` falls back to the
    config default on NULL, and forbidding NULL would make a pre-044 restore unrepairable. The API
    bound still refuses a NULL write — `body.multimodal_max_vision_calls is not None` gates it.

    ⛔ **No `COMMIT`, no `BEGIN`, no `PROCEDURE`** — migrations 105/107 could not be pasted into the
