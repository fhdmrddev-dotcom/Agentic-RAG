<objective>
Fix FIX-15 / BUG-261022-01 in both copies of the Word fill code, test-first. A Word template filled from cited records shows the value for a bare `{{ name }}` (or `{{ name }}` / `{{ name.value }}` on the uploaded-template engine, in nested tables and every header/footer variant). Anything that still prints a whole record stops at the integrity check with a worded reason. `.value`, `|default` and `score` templates render byte-for-byte as before. The driver and service copies are pinned together by one parity test.

Purpose: today the user can be handed a document full of `{'value': 'Ann', 'source_chunk_id': ...}` text, or blanks where values belong, while the verdict reads clean (three defects, D-02). This plan closes all three and leaves the integrity gate able to see record text.
Output: two new test files (RED first), the fix in `render_template.py` (driver + one handler clause) and `template_render_service.py`, the D-11 golden-after and GREEN repro evidence, the ledger/CLAUDE.md rows in the same commit as the code, and `303-VALIDATION.md` with UAT rows U-1 and U-2.
