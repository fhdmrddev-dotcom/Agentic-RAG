## 7. Interaction Contracts

### 7.1 Sticky-header behavior

**Spec source**: SPEC.md R-5 + live-run-container.md D2 + CONTEXT.md D-11.

- `position: sticky; top: 0; z-index: 10` against the document scroll (the existing `MessageList` is the scroll container; no new ScrollArea introduced — D-11)
- Backdrop blur: `backdrop-blur-md` + `bg-popover/92` (sketch `hsl(220 30% 8% / 0.92)` + `backdrop-filter: blur(12px)`)
- Border-bottom: 1px `border-border`
- Padding: `px-4 py-3` (16/12 — sketch D-CSS verbatim)
- Contents (left to right): bot avatar (pulses when streaming) → title + subtitle stack → flex-grow spacer → counter chip → timer (`{N}s` in JetBrains Mono) → (when collapsed: chevron)

**A11y**: When focusable, header element gets `role="button"` (when `runStatus` is terminal AND collapsed) with `aria-expanded={expanded}` and `aria-controls={runBodyId}`. When `runStatus === 'streaming'` the header is NOT focusable (D-08 no-op).

### 7.2 Click-to-expand / collapse

**Spec source**: SPEC.md R-6 + live-run-container.md D5 + tool-call-panel.md D7 + CONTEXT.md D-05, D-08.

- Default expanded state derived once via `useState` initializer:
  - `runStatus ∈ {streaming, queued, undefined}` → `expanded = true`
  - `runStatus ∈ {completed, cancelled, failed, timed_out}` AND `tool_calls.length > 0` → `expanded = false` (auto-collapse)
  - `tool_calls.length === 0` → component not mounted
- Click on collapsed row → `setExpanded(true)`. Click on expanded header row → `setExpanded(false)` ONLY when terminal status; no-op while streaming (D-08).
- No persistence (D-06). Every fresh mount re-derives from current `runStatus`.

### 7.3 Auto-collapse trigger

**Spec source**: SPEC.md R-6 + CONTEXT.md D-05, D-07.

- Transition from streaming → terminal triggers the auto-collapse via the `useState` initializer on next mount (or via a `useEffect` listening on `runStatus` change for the SAME mounted component, depending on Plan 02 implementation choice).
- Fold uses **existing `fadeSlideUp` (0.3s)** on the summary row appearance. No new keyframes (D-07 + SPEC out-of-scope #6).
- Per-tool bodies UNMOUNT instantly when fold completes (the collapsed-row replaces them; no height transition).

### 7.4 Narration interleave

**Spec source**: live-run-container.md D6 + CONTEXT.md `<specifics>`.

- Assistant text content emitted BETWEEN tool invocations (sub-agent narration, mid-loop commentary) renders INSIDE the RunCard body, between tool cards.
- Style: italic + `text-muted-foreground`.
- The FINAL assistant answer (`message.content` post-terminal) renders OUTSIDE the RunCard — in MessageItem below — via the existing MarkdownRenderer path.

### 7.5 Result-summary `→ {summary}` row

**Spec source**: SPEC.md R-4 + live-run-container.md D3 + D-CSS `.tc-collapsed-summary`.

- Appears below the tool head row when the tool head is collapsed AND `tc.status === 'done'`.
- Text: JetBrains Mono, `text-xs`, `text-muted-foreground`, padding `px-3 py-1.5` (12/6 — sketch D-CSS verbatim).
- Border-top: 1px `border-border-soft` (`hsl(var(--border) / 0.5)`).
- Text content: `→ {SUMMARIES[tc.name](tc)}`. Per-tool summaries cite sketch live-run-container.md D3:
  - `execute_code` → last STDOUT line OR `[chart saved to X]` if a file output was produced (sketch shows `→ yoy_q3 = 30.87%, yoy_q2 = 21.71%`)
  - `search_documents` → `top match: {top_hit.title} ({top_hit.score})` for 1+ result; `0 results` for empty (sketch shows `→ top match: Q3-2026-financials.pdf (0.91)`)
  - `read_document` → `{N} chars · {first_50_chars}…` (sketch precedent `→ monthly breakdown loaded · 3 months`)
  - `ls`/`tree`/`grep`/`glob`/`web_search`/`query_documents`/`generic` — author per-Body owner per CONTEXT.md `<discretion>` "`summarize()` return-string formatting nuances (the per-Body author owns text style; sketch findings give canonical examples — follow them)"

### 7.6 Two-sticky pattern

**Spec source**: CONTEXT.md D-12 + `<specifics>`.

RunCard owns the **TOP** sticky header; MessageItem keeps the **BOTTOM** sticky indicator (BUG-260514-03 + B-260519-07 fix at MessageItem.tsx:105-121). These are independent surfaces with independent reset semantics — RunCard's `position: sticky; top: 0` and MessageItem's bottom-indicator positioning don't compete for the same screen anchor.
