### Threadpool sweep scope (D-v2.5-01 compliance for /reextract)

- **D-071.1-01:** **Sweep `/reextract` handler only.** Wrap every sync supabase-py + storage call inside the async handler at `backend/app/api/documents.py:reextract_document`. Concretely, the unwrapped calls today (post-9116c2b) are: `supabase.table("documents").select(...).execute()` at line ~556, `supabase.storage.from_("documents").download(file_path)` at line ~571, `supabase.table("document_chunks|document_tables|document_images").delete(...).execute()` at lines ~576-578, `supabase.table("documents").update(...).execute()` at line ~582, and the post-extract `supabase.table("documents").update(...).execute()` re-fetch + the `supabase.table("pdf_extraction_runs").insert(...)` writer. All become `await run_in_threadpool(...)`. **Out of scope:** `/reingest` route (same pattern, defer), full `documents.py` audit (scope creep, defer).
  - **Why narrow:** 071.1 is a gap-closure phase for SC#1. Touching `/reingest` or other handlers expands the diff and the test surface and risks slipping the SC#1 retry. Phase 077 (multi-worker / asyncpg integration) is the natural place to do the broader sweep.
  - **Surface to user during execution** if Plan 01 discovers a sync call that's load-bearing on a return value (some are sync-but-fast and may not need wrapping for correctness; we wrap all of them anyway for D-v2.5-01 letter compliance).

### Per-call `document_timeout` enforcement strategy

- **D-071.1-02:** **Defense-in-depth: per-call Docling opt + wall-clock asyncio wrapper.**
  - **Layer 1 (per-call Docling):** Inside `DoclingExtractor.extract()`, pass `document_timeout=N` per-call on the converter (exact API confirmed by gsd-phase-researcher — Docling 2.93 accepts `document_timeout` on `PdfPipelineOptions`; if per-call override needs a different surface like `convert(..., raises_on_error=False)` + custom guard, RESEARCH.md picks the exact shape).
  - **Layer 2 (wall-clock fail-safe):** Wrap the `run_in_threadpool(extractor.extract, ...)` invocation at the `/reextract` route with `asyncio.wait_for(..., timeout=N+10)`. If Docling honors its own timeout, Layer 1 fires first cleanly. If Docling is wedged in a native call (TableFormer/layout-prediction model stall — the exact failure observed in 071 UAT), Layer 2 raises `asyncio.TimeoutError` after the wall-clock budget elapses.
  - **Trade-off acknowledged:** Layer 2 raising does NOT kill the underlying thread — Python cannot kill a thread executing native code. The thread leaks until process restart. For v2.6 single-worker mode this is acceptable because: (a) the route still returns 422 to the user cleanly, (b) a leaked thread under D-v2.5-02 single-worker is one process's leak (restart in `gunicorn`/`uvicorn` reload heals it), (c) the PyMuPDF fallback (D-071.1-04) gives the user a path forward even if the leaked thread is still hung. Document this trade-off in the route docstring.
  - **Default timeout:** `EXTRACTOR_DOCLING_TIMEOUT_S=120` (matches the singleton's current default). Operator can override via env.

- **D-071.1-03:** **New env knobs (operator-tunable, default-safe).** Two new env vars introduced to `DoclingExtractor._get_converter()` + documented in `backend/.env.example`:
  - `EXTRACTOR_DOCLING_TIMEOUT_S` — int seconds. Default `120`. Read at converter instantiation; passed per-call to `convert(...)` if Docling API supports it (RESEARCH.md confirms). Also drives the wall-clock fail-safe in the route (N+10 buffer).
  - `EXTRACTOR_DOCLING_DISABLE_TABLE_STRUCTURE` — bool (any of `1/true/yes` truthy; default `false`). When truthy, sets `opts.do_table_structure = False` on the singleton. Lets operators fall back to "pdfium-only" mode on PDFs that wedge in the TableFormer. Trade-off: tables become text-only chunks instead of structured `TableData` rows.
  - `EXTRACTOR_DOCLING_IMAGES_SCALE` — float. Default `2.0` (matches today's hardcoded value). Lower values (e.g., `1.0` or `0.5`) reduce memory pressure on big PDFs by producing smaller rendered page images for figure extraction.
  - All three are read at converter-instantiation time (inside `_get_converter()`'s lock) and frozen into the singleton for the lifetime of the worker process. Change requires uvicorn restart — acceptable for v2.6 single-worker.
  - **NOT in `app_settings`** — env-only per v2.6 admin-shell-comes-later policy (matches Phase 071 D-071-12 `EXTRACTOR_PRIMARY` pattern).

### PyMuPDF fallback wiring (narrow override of D-071-11)

- **D-071.1-04:** **Auto-fallback to PyMuPDF on Docling timeout ONLY.** When `/reextract` is invoked with `engine='docling'` (default or explicit) AND Docling raises a timeout (either Layer 1's per-call timeout or Layer 2's `asyncio.TimeoutError`), the route automatically re-tries the same document in the same request lifecycle with `PyMuPDFExtractor`. Other Docling exceptions (parse errors, OOM, generic) still fail loud per D-071-11 (status='failed' + error_message).
  - **Justification for the narrow override:** Timeout is an infrastructure signal (Docling is stuck in native code), not a quality signal. The user's stated intent (D-071-11) is to avoid hiding quality regressions by silently routing to PyMuPDF when Docling produces bad output. A timeout means Docling produced NO output, so there's no quality regression to hide — only a binary "engine A failed, try engine B" choice. PyMuPDF is the documented fallback per D-PRD-07 + PRD §5 + SC#3.
  - **Telemetry:** The fallback extraction writes `pdf_extraction_runs.engine = 'pymupdf-fallback'` (NOT `'pymupdf'`) so the auto-trigger is auditable and queryable. Plain-text column per migration 039 (no CHECK constraint per T-071-01-06), so new values land without schema change. Document the convention in `backend/README.md` Troubleshooting + the route docstring.
  - **Response semantics:** 202 Accepted (same as Docling happy path) — the doc is still being ingested, just on PyMuPDF. The user sees the engine in the documents UI (which already shows `documents.extractor`).
  - **Telemetry sequence on fallback:** Two `pdf_extraction_runs` rows for the one `/reextract` call — first row `engine='docling'` with `error='docling timeout after Ns'` and partial duration; second row `engine='pymupdf-fallback'` with the actual counts + error=NULL on success. Lets the operator audit "how often is Docling timing out?" with a single SQL query.
  - **Open variant for planner:** Whether the second row's `engine` value is `'pymupdf-fallback'` (one value) or `'pymupdf' + fallback_reason='docling_timeout'` (two columns) — go with the single-value convention since adding a column is schema churn for one signal. Plan can revisit if a second fallback reason ever appears.

## Specific Ideas

- **The SC#1 retry is the binding goal anchor.** 071.1 ships when (a) friendly-fixture UAT completes cleanly, AND (b) thesis SC#1 retry shows `tables_delta ≤ 0.20 AND images_delta ≤ 0.20 AND both pdf_extraction_runs rows have error IS NULL`. - **D-071-11 narrow override is intentional and auditable.** Auto-fallback ONLY on timeout because timeout = infrastructure signal (engine produced no output). Other Docling exceptions still fail loud — the user explicitly wants quality-regression visibility per D-071-11. The two-row telemetry pattern (`engine='docling'` + `error='docling timeout'`, then `engine='pymupdf-fallback'` + success) means the auto-trigger is queryable: `SELECT count(*) FROM pdf_extraction_runs WHERE engine = 'pymupdf-fallback'` answers "how often is auto-fallback firing?" at any point in production.
- **Layer 2 wall-clock fail-safe acknowledges the thread-leak trade-off.** Python cannot kill a thread executing native code, so `asyncio.wait_for` raises but the underlying TableFormer/layout thread keeps running. Under D-v2.5-02 single-worker this is a one-process leak healed by uvicorn restart. The PyMuPDF fallback (D-071.1-04) means the user still gets a successful extract while the dead thread is stuck. This is the right trade-off for v2.6; multi-worker (Phase 077) will revisit thread-pool isolation.
- **Friendly fixture before thesis is a learned habit.** Phase 071's UAT went straight to the thesis and surfaced 3 defects in one cycle, blowing the UAT budget. A friendly real-world fixture (CC-BY arXiv paper) is a cheap pre-flight check that catches new failure modes before the binding gate runs. If the friendly fixture passes, the thesis attempt has a 10x-better chance of being a clean SC#1 close.
- **Three new env vars, all default-safe.** `EXTRACTOR_DOCLING_TIMEOUT_S=120` matches today's hardcoded value (no behavior change for default deploys); `_DISABLE_TABLE_STRUCTURE=false` matches today's default; `_IMAGES_SCALE=2.0` matches today's hardcoded value. Operators get tunability for big-PDF cases without any default-state regression — D-v2.6-01 spirit preserved (don't bump pins or change defaults silently).
- **Vibe-coder-friendly summary** (per memory `feedback_vibe_coder_communication.md`): Phase 071.1 cleans up three problems we found when we tried Docling on a real big PDF — (1) the rest of the backend froze during extract because some database calls weren't moved to the background like the extract was, (2) Docling's "give up after 2 minutes" setting wasn't actually working so we add a real timer at the route, and (3) when Docling DOES time out, we automatically retry with PyMuPDF (the backup engine) instead of just showing the user an error. Plus we add three operator knobs for tuning Docling on big PDFs, validate against a real public-domain academic paper first, then re-run the thesis test to officially close out Phase 071.
