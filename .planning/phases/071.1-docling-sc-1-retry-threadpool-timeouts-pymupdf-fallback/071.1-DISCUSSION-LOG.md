## Per-call `document_timeout` enforcement

**Question:** Plan 02 set `opts.document_timeout = 120.0` on the singleton converter at instantiation; the UAT showed it did NOT trip during the 4-min stall. Need a real timeout mechanism. Where to enforce?

| Option | Description | Selected |
|--------|-------------|----------|
| Defense-in-depth: per-call Docling opt + wall-clock wrapper (Recommended) | (a) Pass `opts.document_timeout=N` per-call inside `DoclingExtractor.extract()`. (b) Wrap `run_in_threadpool(extractor.extract, ...)` in `asyncio.wait_for(..., timeout=N+10)` at the route. Layer 1 fires first if Docling honors it; Layer 2 is the fail-safe for native-code stalls. | ✓ |
| Wall-clock wrapper only | Just `asyncio.wait_for(run_in_threadpool(...), timeout=N)` at the route. Simpler. Trade-off: thread leak if Docling is stuck in native code. | |
| Per-call Docling opt only | Trust Docling's `document_timeout` once researcher confirms the API. Trade-off: same failure mode as today if it's advisory. | |

**User's choice:** Defense-in-depth (Recommended) → captured as **D-071.1-02** + new env var `EXTRACTOR_DOCLING_TIMEOUT_S=120` in **D-071.1-03**.
**Notes:** Thread-leak trade-off acknowledged in the decision (one-process leak under D-v2.5-02 single-worker, healed by uvicorn restart; PyMuPDF fallback provides forward path).

## PyMuPDF fallback trigger policy

**Question:** D-071-11 rejected silent auto-fallback because it hides quality regressions. 071-VERIFICATION.md item 3 wants the fallback wired into /reextract "when Docling exceeds N seconds or raises" so SC#3's per-document fallback guarantee is actually exercised. How aggressive?

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-fallback on Docling timeout ONLY (Recommended) | Narrow override of D-071-11: if Docling times out (per the timeout decided above), `/reextract` automatically re-tries with PyMuPDF in the same request lifecycle. Other Docling exceptions still fail loud per D-071-11. Telemetry `engine='pymupdf-fallback'`. | ✓ |
| Auto-fallback on any Docling exception | Broader override of D-071-11. Risk: hides quality regressions; muddies telemetry. | |
| Surface-and-retry only (no auto-fallback) | Keep D-071-11 unchanged. On Docling timeout/error, return 422 with error_message naming "retry with engine=pymupdf". | |

**User's choice:** Auto-fallback on Docling timeout ONLY (Recommended) → captured as **D-071.1-04**.
**Notes:** Narrow override is auditable via `engine='pymupdf-fallback'` value — operator can query `SELECT count(*) FROM pdf_extraction_runs WHERE engine = 'pymupdf-fallback'` at any time. Two-row telemetry pattern preserves D-071-11's audit-trail intent.
