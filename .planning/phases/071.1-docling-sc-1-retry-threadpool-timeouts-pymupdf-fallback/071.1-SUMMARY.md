# Phase 071.1 — Docling SC#1 retry (threadpool, timeouts, PyMuPDF fallback)

## TL;DR

Phase 071's Docling primary path went RED on a real big PDF (the user's
thesis) because the `/reextract` async handler was choking the event loop
with sync supabase calls, Docling's own per-call timeout was never tripping
when it got wedged in PyTorch/TableFormer native code, and there was no
fallback when Docling stalled. Phase 071.1 fixed all three plus added three
operator-tunable env knobs (`EXTRACTOR_DOCLING_TIMEOUT_S` /
`_DISABLE_TABLE_STRUCTURE` / `_IMAGES_SCALE`). The thesis PDF that previously
stalled for 4+ minutes now completes in 125s. The 20% delta binding gate
itself stays RED at 89.7% / 100% — but the root cause has shifted from
"Docling stalls" to "PDF and DOCX extraction quality differ structurally"
(a deeper PDF-vs-DOCX semantic gap, NOT a Plan 01 regression). Disposition:
accept-degraded, escalate the delta gap to Phase 071.2.

## Lessons learned

- **Per-call Docling timeout did NOT exist in Docling 2.93** —
  `DocumentConverter.convert()` has no `document_timeout` kwarg.
  `RESEARCH.md` resolved this. The Layer 2 wall-clock at the route was the
  actual fix; Layer 1 (singleton-level `document_timeout`) only catches at
  batch boundaries.
- **Threadpool sweep value is enormous and immediately visible.** The same
  thesis PDF that previously froze `/healthz` for 4+ minutes now lets
  `/health` reply in 1-2s while a 125s Docling extract runs in the
  background. Single most impactful change in the patch set.
- **Friendly fixture before binding gate retry catches new failure modes
  cheaply** — exactly the pattern this phase was designed around. The
  friendly UAT exposed the persisted-vs-telemetry accounting discrepancy on
  the PDF side, which gave us the heads-up to expect the gate to fail for
  reasons OTHER than the stall before burning the budget on the thesis
  retry.
- **`/reextract`'s `is_latest=True` filter is brittle to upstream
  data-state failures.** The thesis PDF's `is_latest=False` from a prior
  failed cascade silently produces a 500 because `.maybe_single()` raises on
  empty. Worth fixing — either pre-clear `is_latest` in the reset cascade
  or handle the empty case gracefully.
- **DOCX is structurally better for extraction quality on long documents.**
  The DOCX side cleanly recovers 39 tables / 61 images via Docling in 6s;
  the PDF side recovers 1-4 tables in 125s. This isn't a bug — DOCX retains
  explicit structural markup, PDF requires layout inference. The 20% delta
  gate was a stretch goal on the PDF side; SEED-006-style multimodal lift
  and TableFormer tuning are the path forward.
- **`is_latest=False` should never silently 500.** Same lesson applies to
  any other route that filters by `is_latest=True` + `.maybe_single()`.
