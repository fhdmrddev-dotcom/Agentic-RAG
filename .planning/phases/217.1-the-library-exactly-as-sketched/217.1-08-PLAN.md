**Migration analog — copy `121_workflow_phases_timings.sql` STRUCTURALLY, six things:**
1. `BEGIN; … COMMIT;` — without it, two `ADD COLUMN`s each run in their own implicit transaction when
   pasted into the SQL editor.
2. `ADD COLUMN IF NOT EXISTS` — re-paste-safe.
3. ⭐ **No `DEFAULT`, nullable.** State the reason in the migration's own comment: a `DEFAULT now()` would
   backfill every existing row at ALTER time in Postgres 11+, destroying the "time not recorded" arm before
   it ever existed — a backfill by accident is still a backfill.
4. `COMMENT ON COLUMN` naming every write site by file and line (the four below).
5. A negative-control test asserting `is_nullable = 'YES'` and the ABSENCE of a default — a test that only
   proves the column exists cannot tell a no-backfill migration from a backfilled one.
6. An explicit "no RLS work is owed" section, CHECKED not assumed: `document_chunks` already has a live
   `authenticated` SELECT policy (`full-schema.sql:5253-5256`) that covers this new column — but per the
   `connector_connections` column-grant trap (memory), verify a `SELECT embedded_at` actually succeeds
   under the RLS-enforced test client before declaring it clear.

already re-declares it verbatim once) with `embedded_at = NULL` added to the same `USING NULL` statement
