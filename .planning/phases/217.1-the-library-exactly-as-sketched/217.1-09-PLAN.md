**BE-2 shape (a suggestion, not a lock — state your final shape in the summary):**
```
GET /library/index-summary -> {
  vectors: int | null, chunks_total: int | null, documents_without_vectors: int | null,
  last_indexed: datetime | null,          # max(embedded_at) -- BE-1
  model: str | null, dimensions: int | null, provider: str | null,
  folders: [ { folder_id: uuid|null, name: str, documents: int, chunks: int,
               vectors: int, last_indexed: datetime|null } ]
}
```
`folder_id IS NULL` is the `Uncategorized`/`Root` bucket (D-217.1-31: the app already ships `Root` on
screen — `LibraryPage.tsx:508-513` — keep it `Root`, never `Uncategorized`; that decision belongs to Plan
10's rendering, but BE-2's `name` field for the null-folder row should read `Root` at the API layer too,
for consistency).

**RLS path — the load-bearing choice, do NOT copy the neighbours:**
```python
current_user: dict = Depends(get_current_user),
```
then `get_user_pg_connection(request, current_user)` (`dependencies.py:159-177`) — an asyncpg connection
inside a transaction with `SET LOCAL ROLE authenticated` + JWT-claims GUCs applied, so RLS is enforced by
Postgres on a raw `GROUP BY`. This is `retrieval_service._call_as_user`'s substrate
(`retrieval_service.py:37-54`). ⛔ **Do NOT use a service-role client** — `knowledge_health.py`'s carve-out
exists ONLY because `audit_log` has no `authenticated` SELECT policy; `document_chunks`/`documents`/
`folders` all have one, so carrying the carve-out here would widen a classified exception for no reason.
⛔ **Do NOT copy `skill_test_cases.py`'s inline `.execute()`** — that file states its own exemption
(SEED-097); a net-new module has no such licence. Wrap every query in `aexec` (`app/utils/db.py:47-58`) if
using the PostgREST path, or rely on asyncpg's native async if using `get_user_pg_connection` (no wrap
needed there).

**Scope wider than `user_id` alone** (`documents.py:741`): `get_globally_visible_folder_ids` merges
org-shared folders into the visible set. The `GROUP BY` under the RLS path inherits this automatically —
do not hand-roll a narrower `.eq("user_id", ...)` filter that would disagree with the Documents tab's own
count.

**Where the router lives:** new `backend/app/api/library.py`, prefix `/library`, registered in
`main.py` after `documents.router` — following `document_queries.py`'s one-route-module precedent
(`main.py:786`). `documents.py` is 71 commits / 29 phases / 2531 lines with no ledger row (§G of
RESEARCH) — do not add a cross-folder aggregate to it.

**`Re-index everything`/`Re-index selected` gate — unaffected by this plan, consumed by Plan 10:** both
stay `Depends(require_visible("model_management"))`; only `GET /library/index-summary` is new and
ungated.

**BE-3 — the trap, and the fix, exact:**
```python
q = supabase.table("document_chunks").select("id, content").eq("user_id", user_id)
if org_id is not None: q = q.eq("org_id", org_id)
return q.or_(f'embedding_model.is.null,embedding_model.neq."{current}"').limit(limit).execute()
```
`reembed_service.py:158-170`. The stale predicate is **model-mismatch**, not "re-do this folder" — a
folder whose chunks are ALREADY current selects zero rows, and the job "completes" silently. Add
`folder_ids: list[str] | None = None` as an additive kwarg through `start_reembed` → `reembed_job`
(mirroring `reembed_service.py:309-331`'s existing `org_id` threading), resolved to `document_id`s once
before the loop, and `.in_("document_id", ids)` ANDed onto (never replacing) the existing `.or_(...)`
stale predicate. When the resolved scope selects zero rows, the endpoint's response must say so plainly
(`remaining: 0` plus a distinguishable reason the frontend can render as *"Already indexed with the
current model."*) rather than reporting success indistinguishably from a real re-index. For a folder with
ZERO chunks at all (the `Uncategorized` motivating case), the scope also selects zero rows — this is a
DIFFERENT case from already-current, and Plan 10's frontend must render it distinctly (no action offered,
per Open Question 1's recommendation — state that choice in Plan 10, not here).
