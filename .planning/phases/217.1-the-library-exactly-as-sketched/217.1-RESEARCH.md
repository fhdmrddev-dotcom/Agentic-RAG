## Summary

Phase 217 shipped against a generated contract that asserted **200 things about words, order and honesty and nothing about composition**. I re-ran that contract this session against the current tree:

```

  200 passed · 0 failed · 200 assertions

```

**200/200 green on the tree that does not look like the sketch.** That is the diagnosis, reproduced rather than inherited, and it is why SC#1 is task zero.

The good news for planning is that the emitter is *structurally ready* to be extended. `drive.cjs`'s `--emit` block (`:939-1026`) is a single template literal interpolating (a) `COPY.js` constants and (b) values measured from the live tree at emit time. The sketch's own markup is already block-structured with a stable class vocabulary (`.page` → `.pagehead` / `.tabslist` / `.subnav` / `.tiles` / `.card > header > h4` / `.stagecards` / `.chipgroup` / `.vgrid` / `.tfoot`), each variant wrapped in `<section class="variant" id="v-X">`. A composition emitter is a deterministic walk of that markup — no new judgement, no hand-transcription. And a fence suite that reads the emitted artifact across the repo boundary is **a shipped, green idiom in this repository**: `frontend/src/components/workflows/argumentVocabulary.test.ts:58` imports `"../../../../.planning/sketches/214-argument-form-and-its-source/BUILD-CONTRACT.generated.md?raw"` today.

The six backend items are all smaller than they look, with one exception. BE-1 is four write sites (three INSERTs, one UPDATE) plus one function edit. BE-2 wants a new `/library` router module following `document_queries.py`'s precedent, and — unlike its two nearest neighbours — it **needs no service-role carve-out**: `document_chunks`, `documents` and `folders` all carry `authenticated` SELECT policies, and the repo already has an RLS-enforced raw-SQL path (`get_user_pg_connection`) that makes a single `GROUP BY` legal. BE-3 is a filter argument, but with a trap: the re-embed worker's stale predicate is *model-mismatch*, so `Re-index selected` on an already-current folder silently no-ops. BE-4 and BE-5 are both one dict literal at `tool_dispatcher.py:796-801` — with BE-4 carrying **the single highest-consequence risk in the phase**, because `_fetch_retrieval_trend` counts *every* `search.query` row into `retrieval_count`, which is the exact series the shipped `Coverage Trend` chart plots. BE-6 is the only real build: a table, four RLS policies, an org autofill trigger, CRUD and an evaluator — and the evaluator is *feasible*, because `search_documents` reaches the RLS-enforced RPC through `get_user_pg_connection(None, {"id": user_id})`, which needs no HTTP request.

**Primary recommendation:** Ship Wave 0 as a **two-artifact** gate — extend `drive.cjs --emit` to write a machine-readable `BUILD-CONTRACT.composition.json` *beside* the existing markdown, and have the `sketch-composition` suite import that JSON, mount each tab body and assert blocks by `data-testid`; drive it RED by asserting the emitted list against the **current** four-tab tree before any wave lands. Then take BE-4 second (not sixth) — it is the one item whose wrong shape corrupts a chart that already ships.

### A.1 — BE-1: `document_chunks.embedded_at timestamptz`

**The column today** (`supabase/full-schema.sql:861-873`):

```sql
CREATE TABLE public.document_chunks (
    id uuid DEFAULT gen_random_uuid() NOT NULL,
    document_id uuid NOT NULL,
    user_id uuid NOT NULL,
    content text NOT NULL,
    chunk_index integer NOT NULL,
    embedding public.vector(1536),
    created_at timestamp with time zone DEFAULT now() NOT NULL,
    search_vector tsvector,
    embedding_model text,
    embedding_dimensions integer,
    org_id uuid NOT NULL
);
```

`created_at` is `DEFAULT now()` at **INSERT** — the chunking moment. Nothing updates it. D-217.1-13's claim is confirmed by the schema.

**Every write site of a chunk embedding — all four, measured:**

| # | Site | Kind | What it writes today |
|---|---|---|---|
| 1 | `backend/app/api/documents.py:2296-2307` | INSERT | the main text chunks (`embedding`, `embedding_model`, `embedding_dimensions`) |
| 2 | `backend/app/services/multimodal_service.py:423-432` | INSERT | table chunks (`embed_and_store_table_chunks`) |
| 3 | `backend/app/services/multimodal_service.py:896-908` | INSERT | image-description chunks |
| 4 | `backend/app/services/reembed_service.py:187-202` (`_write` closure) | UPDATE | `{embedding, embedding_model, embedding_dimensions}` — **the re-embed path** |

**All four must set `embedded_at`.** Site 2 is also reached by `backfill_document_table_chunks` (`multimodal_service.py:471-489`), which delegates to site 2 — so patching site 2 covers the backfill for free. [VERIFIED: read each site]

⚠ **A fifth thing that is not a write site but will lie if ignored.** `resize_embedding_column(new_dim)` (`supabase/migrations/073_embedding_provider_and_chunk_tags.sql:66-85`) does:

```sql
ALTER TABLE public.document_chunks ALTER COLUMN embedding TYPE vector(%s) USING NULL
```

— i.e. **it NULLs every vector**. A chunk whose vector is gone but whose `embedded_at` still reads *14 min ago* is exactly the lie BE-1 exists to prevent, for the whole duration of a dims-change re-embed. **Recommendation:** the BE-1 migration re-declares `resize_embedding_column` with `embedded_at` nulled in the same statement family. One extra line; the function is already re-declared verbatim by migration 073, so re-declaring is the established idiom.

**Backfill posture.** Do **not** backfill `embedded_at = created_at` — that reintroduces the exact lie for pre-existing chunks. Leave it `NULL` and let the read arm render `never` / `Not known yet`. This is consistent with 217's shipped honesty rules and with the `Uncategorized · – · never` requirement (D-217.1's own "the point of the tab").

**Threadpool.** Sites 1-3 are inside sync `_upload_pipeline` code already running off the loop; site 4 is already wrapped (`await run_in_threadpool(_write)`). **No new D-v2.5-01 obligation is created by BE-1.**

**FIRST, the question the brief asked me to check first — measured, and the answer is NO.**

`ReembedProgressResponse` (`backend/app/api/settings.py:548-555`) is exactly:

```python
class ReembedProgressResponse(BaseModel):
    status: str            # idle | running | partial | complete | failed
    total: int | None
    re_embedded: int | None
    remaining: int | None
    model: str | None = None

```

**It carries neither `dimensions` nor `provider`.** [VERIFIED: read `settings.py:548-555` and `reembed_service.reembed_progress` `:230-300`, whose return dict is the same six keys.] The underlying facts do exist — `document_chunks.embedding_dimensions` (schema above) and `app_settings.embedding_provider` (`SettingsPage.tsx:568,759` round-trips `embedding_provider`) — but they are not on this wire. So BE-2 must supply them.

⚠⚠ **AND THE BIGGER FINDING: `GET /settings/reembed-progress` IS OPERATOR-GATED.**

```python
@router.get("/reembed-progress", ...,
    dependencies=[Depends(require_visible("model_management"))])
```
`backend/app/api/settings.py:558-561`, and `_GOVERNED_FEATURES` (`backend/app/models/user_settings.py:1193-1197`) reads `"model_management": "operators"`. `require_visible` raises **403** for a non-operator (`dependencies.py:552-555`).

This is already recorded as **217 review Warning WR-02** (`217/deferred-items.md`): *"Non-operators get a permanent tab reading 'Could not read the indexing facts just now.'"* — with re-open trigger *"the first non-operator UAT pass, or any change to `nav-items.ts` visibility keys."* **Wave 5 modifies the Indexing tab; the trigger fires.** It also lands on the Documents tab, because the sketch's **VECTORS** tile reads the same endpoint.

**Recommendation (a HOW, inside the locked WHAT):** `GET /library/index-summary` is **ungated** and becomes the source for every *descriptive* fact (vectors, chunks indexed, documents with no vectors, last indexed, model, dimensions, provider); `POST /settings/reembed` stays `model_management`-gated and the two **buttons** (`Change model`, `Re-index everything`, `Re-index selected`) render only when `useEffectiveFeatures().features.model_management === true` — the shipped VANISH convention (`nav-items.ts:63-75`, `visibleNavItems`), never a disabled placeholder. Rationale: reading how many vectors *your own* corpus has is not model management; changing the model is. This makes the Indexing tab useful for every user and keeps the security boundary exactly where it is.

**Where the route lives.** ⭐ **A new module `backend/app/api/library.py`, prefix `/library`, registered in `main.py` after `documents.router`.** Precedent: `document_queries.py` (`main.py:786`) is a one-route module created precisely so `api/documents.py` stays uniform. `documents.py` measures **71 commits / 29 phases / 2531 lines** and has **no hot-file-ledger row at all** (§G) — adding a cross-folder aggregate to it is the wrong direction.

**RLS story — and this one gets a strictly better answer than its neighbours.**

`knowledge_health.py` and `document_queries.py` take a **service-role carve-out** because `audit_log` has *no `authenticated` SELECT policy* (mig 108) — a user-JWT client would read an empty set. **That reason does not apply here.** `document_chunks` has a live SELECT policy:

```sql
CREATE POLICY "Users can view their own chunks" ON public.document_chunks
  FOR SELECT TO authenticated
  USING ((org_id IN (SELECT public.current_user_org_ids())) AND ((auth.uid() = user_id) OR (EXISTS (...))))
```
`supabase/full-schema.sql:5253-5256`. `documents` and `folders` likewise.

> **Verdict: BE-2 may NOT use the service-role carve-out, and does not need it.** Use the RLS-enforced path. Two options, both shipped idioms:
> 1. **`get_user_supabase_client`** (PostgREST, the `documents.py:728` idiom) — simple, but PostgREST has no `GROUP BY`, so per-folder aggregation becomes a fetch-and-fold in Python, bounded by the 1000-row ceiling.
> 2. ⭐ **`get_user_pg_connection(request, current_user)`** (`dependencies.py:159-177`) — an asyncpg connection inside a transaction with `SET LOCAL ROLE authenticated` + the JWT-claims GUCs applied, so **RLS is enforced by Postgres on a raw `GROUP BY`**. This is `retrieval_service._call_as_user`'s substrate (`retrieval_service.py:37-54`) and is the recommended one: one query, no ceiling, no carve-out, no fold.

**Shape (a suggestion, not a lock):**

```
GET /library/index-summary  ->  {
  vectors: int | null,                 # chunks with a non-null embedding at the current model
  chunks_total: int | null,
  documents_without_vectors: int | null,
  last_indexed: datetime | null,       # max(embedded_at)  ← BE-1
  model: str | null, dimensions: int | null, provider: str | null,
  folders: [ { folder_id: uuid|null, name: str, documents: int,
               chunks: int, vectors: int, last_indexed: datetime|null } ]
}
```

⚠ **The `Uncategorized` row is `folder_id IS NULL`** — and the app already calls that bucket **`Root`** on screen (`LibraryPage.tsx:508-513`: `<h2>Root</h2>` / *"Documents not assigned to a folder"*). The sketch says `Uncategorized`. **Two words for one bucket is the vocabulary failure D-217.1-11 exists to prevent, arriving from the other direction.** See §H, flagged note 4.

⚠ **`documents.py:741` shows the read scope is wider than `user_id`:** `get_globally_visible_folder_ids` merges org-shared folders' documents into the list. The Folders table must use the same scope or the Documents count on a shared folder will disagree with the Documents tab. Use the RLS path (option 2) and the policy does this for you.

**Model / dimensions / provider — corpus truth, not settings truth.** Derive `model` and `dimensions` from `document_chunks` (`embedding_model`, `embedding_dimensions` — what searches actually compare against), not from `app_settings`. During a re-embed the two legitimately differ, and the card is about *the vector store*. `provider` resolves from the model id — `backend/app/services/openai_service.resolve_effective_embedding_provider(...)` already exists and is called on the retrieval error path (`tool_dispatcher.py:726-727`).

**Threadpool:** an asyncpg path is natively async — no wrap needed. A PostgREST path **must** use `aexec` (`app/utils/db.py:47`) or `run_in_threadpool` (D-v2.5-01).

### A.3 — BE-3: folder scope on `POST /settings/reembed`

**The endpoint** (`backend/app/api/settings.py:577-604`):

```python
@router.post("/reembed", response_model=ReembedProgressResponse,

async def rekick_reembed(background_tasks: BackgroundTasks, ...):
```

Takes **no body at all** today. Scope is `(user_id, org_id)` throughout `reembed_job` (`reembed_service.py:100-210`).

**Can the worker already take a filter? No — but the seam is one predicate wide.** The resumable read is:

```python
q = supabase.table("document_chunks").select("id, content").eq("user_id", user_id)
if org_id is not None: q = q.eq("org_id", org_id)
```

## Common Pitfalls

### Pitfall 1 — Writing the error-path audit row without a distinguishing key
**What goes wrong:** the shipped `Coverage Trend` chart **rises** during a provider outage, and the error row is also counted as `found nothing`.
**Root cause:** `_fetch_retrieval_trend` (`knowledge_health.py:376`) increments `retrieval_count` for every `search.query` row unconditionally, and `RetrievalTrendChart.tsx:90` plots that series.
**Avoid:** `retrieval_status: "provider_error"` in the metadata + the three-way branch in §A.4, with a characterization test proving `retrieval_count` is unchanged.
**Warning sign:** the trend endpoint's diff touches no arithmetic.

### Pitfall 2 — Using `created_at` for `Last indexed`
**What goes wrong:** after the first re-index every folder still shows its original chunking time.
**Root cause:** `document_chunks.created_at DEFAULT now()` at INSERT; nothing updates it.
**Avoid:** BE-1's `embedded_at`, written at **all four** sites, and NULLed by `resize_embedding_column`.
**Warning sign:** a plan that touches only the INSERT sites.

### Pitfall 3 — Adding a `<th>` and silently shedding the wrong three columns
**What goes wrong:** the panel opens and the wrong columns vanish.
**Root cause:** the selector lives in `LibraryPage.tsx:83-84`; the columns live in `DocumentList.tsx:347-356`; **neither file imports the other.**
**Avoid:** never change the `<th>` count; assert 7 and the 3-5 identities; run `drive.cjs` in the same turn.
**Warning sign:** any wave that adds a checkbox or an inline action column.

### Pitfall 4 — Adopting a red suite into the count gate
**What goes wrong:** every subsequent plan's gate is red for a reason it did not cause.
**Root cause:** the gate's contract is *zero failing, forever*; `TARGETS` decides what runs and `BASELINE` what is guarded, **and a suite can sit on the wrong side of exactly one**.
**Avoid:** land the fence RED and **un-adopted**, adopt in the final wave at the gate's own printed `— N new`.
**Warning sign:** a Wave 0 plan whose `files_modified` includes `scripts/vitest-count-gate.cjs`.

### Pitfall 5 — Reaching for the cap when the gate reds
**What goes wrong:** a real defect gets explained away, or a flake gets "fixed" by a knob that does not fix it.
**Root cause:** SEED-171 — five named suites flake independently of the cap; three fail with `AssertionError`, not `STACK_TRACE_ERROR`, so the signature is not a reliable tell.
**Avoid:** capture failing filenames from the gate's persisted JSON **before** re-running; check each against `git diff --numstat`; say *"provably unmodified"*, never *"fine"*.
**Warning sign:** a summary that reports a re-run before it reports a filename.

### Pitfall 6 — Gating the whole Health tab on `governance_health`
**What goes wrong:** four retrieval signals that key never governed disappear for non-greenlisted users.
**Root cause:** the tab merges two differently-governed surfaces.
**Avoid:** chip-level gating on the three Governance signals; do not call `getGov*` when the key is false.
**Warning sign:** `features.governance_health` appearing in a `return null` at the tab's top.

### Pitfall 7 — `Re-index selected` on an already-current folder
**What goes wrong:** the button appears to work; nothing happens.
**Root cause:** the stale predicate is model-mismatch, not "re-do this folder".
**Avoid:** §A.3 — an explicit already-current arm, and a decision about the zero-chunk case.
**Warning sign:** a plan that adds a folder filter and no empty-selection arm.

### Pitfall 8 — Prose that satisfies its own fence (the 187-24 trap, fired **five times** in Phase 217)
**What goes wrong:** a suite counting occurrences of a literal counts its own comment and passes while defending nothing.
**Root cause:** source fences read whole files, comments included.
**Avoid:** assemble forbidden needles at runtime; never spell a counted literal in prose. `drive.cjs:34-56` and `DocumentDetailPanel.tsx:299-312` both record having been bitten.
**Warning sign:** a docblock quoting the exact string its fence counts.
