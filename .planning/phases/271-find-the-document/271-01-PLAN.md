`resolve_filter`, reusing its fragment walk and validation (extracted, never forked), plus a closed
set of structure conditions (name, folder subtree, added by, the three file/added dates,

this core evaluates, with a content-level test, because ROADMAP's named failure is "a filter the
backend silently ignores".

the router (+1 `include_router`), four unit suites.

Decisions applied (recorded in 271-VALIDATION.md; operator may override): **P-01** default sort
`added_desc`; **P-02** relationship semantics; **P-03** Older versions = the caller's own rows;
**P-05** `has_earlier` by lineage; **P-10** "Date in the document" goes through the shipped
compiler (`date_typed`), the other three dates are structure conditions with timestamptz
day-boundary semantics.
</objective>

THE WIRE CONTRACT (271-03 types it on the frontend from THIS text — keep it exact):
Request `POST /document-search`, model `DocumentSearchRequest` (every model `ConfigDict(extra="forbid")`):
- `filter_expr: ViewFilter = ViewFilter(op="and", conditions=[])` — metadata conditions (document type, Date in the document = field `date`, custom fields)
- `name: str | None` (`max_length=200`)
- `folder: FindFolder | None` — `{folder_id: UUID | None, include_subfolders: bool = True}`
- `added_by: FindAddedBy | None` — `{kind: Literal["me","connection","others"], connection_id: UUID | None}`; `connection` requires `connection_id`, the others forbid it (model validator → 422)
- `dates: list[FindDate]` (`max_length=3`, at most one per `which`) — `{which: Literal["added","source_created","source_modified"], op: Literal["before","after","between","within_next","older_than"], value: str | int | None, value2: str | None, unit: Literal["days","weeks","months"] | None}`; before/after/between need ISO `YYYY-MM-DD` value(s); within_next/older_than need an int ≥ 0
- `relationship: FindRelationship | None` — `{verb: RelVerb, document_id: UUID}`; `RelVerb = Literal["supersedes","superseded_by","amends","amended_by","references","referenced_by","attached_to","has_attachment"]`
- `version: Literal["latest","has_earlier","older"] = "latest"`
- `sort: Literal["added_desc","added_asc","document_date_desc","source_modified_desc","source_created_desc","name_asc"] = "added_desc"` (P-01)
- `offset: int = 0` (ge 0), `limit: int = 25` (ge 1, le 100)
Response (plain dict, NO response_model — the 112 CR-01 lesson): `{"documents": [row…], "total": int, "older_matches": int, "sort": str, "offset": int, "limit": int}`. Each row is the full `documents` row (`select *`) plus `version_count: int` (visible rows in its lineage), `has_earlier: bool`, `source_connection_name: str | None`. Zero-result shape: same keys, `documents: []`, `total: 0`, `older_matches: 0`.
Sort keys → column: added_* → `created_at`; document_date_desc → `date_typed`; source_modified_desc → `source_modified_at`; source_created_desc → `source_created_at`; name_asc → `filename` (casefold).
