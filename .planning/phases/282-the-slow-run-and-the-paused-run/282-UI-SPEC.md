# Phase 282 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract.** Three surfaces, and nothing else:

1. **The chat-column pointer** that `PendingAskStack home="chat"` renders when a panel-home stack is mounted for the same thread (D-10, D-11).
2. **The option chips** inside `PendingAskCard`: a non-colour selected mark and the full radio keyboard pattern (D-13).
3. **The Model Registry Timeout field**: the inline refusal (the server's own 422 reason) and one help line (D-04, D-07).

Everything else on these surfaces (card chrome, answered/expired/retired arms, `PausedRunCue`, the rail's pulsing dot, the composer lock) ships unchanged. No new capability, no new route, no new shadcn block.

**Sources.** Layout is LOCKED by sketch 282 variant A (`.planning/sketches/282-one-answer-input/`). The card's visual language is LOCKED by sketch 006 (`references/pending-question.md`) and by the shipped `PendingAskCard.tsx`, whose classes are the design system here. Anything this document had to decide is marked **Claude's decision (operator confirmation owed at G-4)**.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Pointer button vertical padding (`py-1`); Tailwind `gap-1` inside the label |
| sm | 8px | Pointer vertical padding (`py-2`); chip mark → option text gap (`gap-2`); stacked pointers gap (`gap-2`, the stack's shipped value); registry help row bottom padding (`pb-2`) |
| md | 16px | Registry help row horizontal padding (`px-4`, same as the shipped error row) |
| lg | 24px | Not used by new elements |
| xl | 32px | Pointer button minimum height (`min-h-[32px]`) |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions:
- **12px** (`px-3`, `gap-3`): pointer horizontal padding and the gap between pointer segments; chips keep their shipped `px-3 py-2`. Multiple of 4, off the 8-point ladder, matching the card's shipped `p-3`.
- **44px** chip minimum height: shipped (`min-h-[44px]`), unchanged.
- **32px pointer button height instead of 44px.** Claude's decision (operator confirmation owed at G-4). The pointer only renders while a panel-home stack is mounted. On mobile the panel home is the sheet, which covers the chat column, so the pointer is effectively desktop-only. 32px clears WCAG 2.5.8 (24px).
- **Chip radio mark 16px** (`h-4 w-4`), inner dot **8px** (`h-2 w-2`). The sketch drew 14px; rounded to the 4-grid.
- **Focus geometry**: chip `focus-visible:ring-2 ring-offset-2` (2px), and the arrival flash `outline-2 outline-offset-4` (2px stroke, 4px offset). Ring and stroke widths are borders, not spacing.

## Color

Tokens only, never raw hex in code. Hex values are the Deep Midnight (`.dark`) resolutions, for the checker.

| Role | Token | Value (dark) | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--background` | `hsl(216 45% 4%)` ≈ `#06090F` | Chat column and panel surface behind the pointer |
| Secondary (30%) | `--card` / `bg-card` | `hsl(220 30% 7%)` ≈ `#0C1017` | Unselected chip fill (shipped), registry table surface |
| Accent (10%) | `--warning` (amber) | `hsl(38 92% 60%)` ≈ `#F7B23B` | The "needs you" signal only. See the reserved list below |
| Accent foreground | `--warning-foreground` | `hsl(240 60% 8%)` ≈ `#080821` | Text and radio mark on a selected (amber-filled) chip; ≥ 4.5:1 on amber (shipped rationale, `index.css:147`) |
| Muted meta | `--muted-foreground-dim` | `hsl(220 16% 70%)` | Pointer draft line, unselected radio-mark ring, registry help line (`text-muted-foreground`) |
| Destructive | `--destructive` | `hsl(0 72% 51%)` ≈ `#DC2828` | The registry refusal sentence only (shipped slot) |

Accent (amber) reserved for, and only for:
1. The pointer's 1px **dashed** border (`border-dashed border-[hsl(var(--warning))]`).
2. The pointer's "Needs you" label and its 8px pip (`h-2 w-2`) (static, no animation; the card's pip is already the moving one).
3. The pointer button's text and 1px solid border (`text-[hsl(var(--warning))] border-[hsl(var(--warning))]`), and its hover fill `bg-[hsl(var(--warning)/0.12)]`.
4. The selected chip fill and border (shipped), the chip hover border/fill (shipped).
5. The arrival flash outline on the panel card after `Answer in panel →` (`outline-[hsl(var(--warning))]`, 900 ms).

Amber is **not** used for the registry field, focus rings (those stay `--ring`, the indigo primary), or any new text that is not part of the paused-run signal. Amber on the pointer follows the shipped `SeamPointer` rule ("ask_user is the blocked-on-me pointer, so amber; the others are primary live"), which overrides the generic "primary = pointer" note in the sketch-findings skill.

## Surface 1 — The chat-column pointer (D-10, D-11, D-14)

### When it renders

| Panel-home stack mounted for this thread? | Chat-column `PendingAskStack` renders |
|---|---|
| Yes (desktop panel open, or mobile sheet open) | One **pointer per pending ask**, in the stack's shipped order (newest first) |
| No (panel on the rail, panel body not rendered, no thread match) | The **full `PendingAskCard`**, exactly as today |

- The chat mount's **conditions** stay byte-equivalent (D-11). Only what it renders switches. Each pointer sits in the stack's shipped per-ask wrapper (`sticky top-0 z-[4]`); no new positioning.
- **Exactly one answer input exists for one ask at any moment** across both homes (one `Send Answer`, one radiogroup, one textarea). This is the G-6 failure condition and a D-15 fence.
- When the ask is **settled** (answered, expired, or retired), the pointer renders **nothing**. The panel card carries the receipt. The pointer must never read `No answer yet` for an ask that was already answered. Mechanism (Claude's decision, operator confirmation owed at G-4): the draft store records the settle in the same write that clears the draft (D-12's "cleared on answer / on expiry"), and the pointer reads that. Planner chooses the shape.
- The row-level `PausedRunCue` is untouched and stays a marker with no button (D-14). On a Deep pause the chat therefore shows the cue on the paused row **and** the pointer at list level; this is intended.

### Layout (one line, left to right)

```
┌ - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - ┐
  ● NEEDS YOU   Which dataset should I use for the Q3 rollup?…   Draft: prod_sales_2026   [ Answer in panel → ]
└ - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - ┘
```

| Segment | Classes / behaviour |
|---|---|
| Root | `flex items-center gap-3 rounded-md border border-dashed border-[hsl(var(--warning))] px-3 py-2`, transparent background (it is a pointer, not a card). `data-testid="ask-pointer"`, `data-tool-call-id={tool_call_id}` |
| Label | `flex flex-none items-center gap-1 font-mono text-[10px] uppercase tracking-wider text-[hsl(var(--warning))]`; pip `h-2 w-2 rounded-full bg-[hsl(var(--warning))]`, `aria-hidden`, **no animation** |
| Question | `min-w-0 flex-1 truncate text-[13px] leading-5 text-foreground`; `id="ask-{tool_call_id}-pointer-q"`; `title={prompt}` so the full question is on hover. The question truncates first |
| Draft | `flex-none max-w-[12rem] truncate text-[12px] leading-5 text-[hsl(var(--muted-foreground-dim))]`; `data-testid="ask-pointer-draft"`. The **full** draft string is in the DOM (CSS truncation only, never `slice`), so a test can read the draft back exactly |
| Button | `flex-none min-h-[32px] rounded-md border border-[hsl(var(--warning))] px-3 py-1 text-[12px] font-semibold text-[hsl(var(--warning))] hover:bg-[hsl(var(--warning)/0.12)] focus:outline-none focus-visible:ring-2 focus-visible:ring-ring`; `data-testid="ask-pointer-go"`; `type="button"`; **always** has an `onClick` |

### Accessibility

- Root: `role="group"` with `aria-labelledby` pointing at the question span.
- **No live region on the pointer.** The panel card's shipped `aria-live="assertive"` "Needs you" already announces the pause; a second announcement would double-speak, and a live draft line would chatter on every keystroke.
- Button accessible name: `Answer in panel` (the `→` is wrapped `aria-hidden="true"`).

### `Answer in panel →` interaction

1. Find the panel-home card for **this** `tool_call_id`.
2. Move focus to the card's **first control**:
   - options present → the chip that holds the roving tab stop (the selected chip, else the first chip);
   - no options → the free-text `<textarea>`.
   The draft overlay button (`⤢ Review & edit full draft`) and `StepIdentity` are not the target.
3. `focus()` scrolls the card into view inside the panel (the card is already sticky at the panel top).
4. Add the arrival flash to the card root: `outline outline-2 outline-offset-4 outline-[hsl(var(--warning))]` for **900 ms**, then remove it. It is a static outline, so it is safe under `prefers-reduced-motion`.
5. If the panel card is not mounted at the moment of the click (a race with collapsing the panel), the chat stack has already switched to the full card. The handler does nothing and throws nothing.

Focus must land **inside the card**. Focus landing anywhere else is a G-6 failure.

## Surface 2 — Option chips: non-colour mark and radio keyboard (D-13)

Semantics stay as shipped: `role="radiogroup"` (labelled by the prompt) containing `<button role="radio" aria-checked>`. `aria-pressed` is **not** added.

### Visual

| State | Chip (shipped classes kept) | Radio mark (new, first child, `aria-hidden="true"`) |
|---|---|---|
| Unselected | `border-border bg-card text-foreground` | `h-4 w-4 flex-none rounded-full border-2 border-[hsl(var(--muted-foreground-dim))]`, empty |
| Unselected, hover | `hover:border-[hsl(var(--warning))] hover:bg-[hsl(var(--warning)/0.12)]` (shipped) | unchanged |
| Selected | `border-[hsl(var(--warning))] bg-[hsl(var(--warning))] font-semibold text-[hsl(var(--warning-foreground))]` (shipped) | ring `border-[hsl(var(--warning-foreground))]` + centred inner dot `h-2 w-2 rounded-full bg-[hsl(var(--warning-foreground))]` |
| Focus-visible (either) | `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background` (raised from the shipped `ring-1`, because keyboard movement is now a first-class path). Claude's decision (operator confirmation owed at G-4) | unchanged |

- Chip layout becomes `flex items-center gap-2` so the mark sits left of the option text; text stays left-aligned and wraps.
- Selection is now carried by **three** channels: fill colour, the filled dot (shape), and weight 600. Colour alone is never the only signal (SC#3).
- Answered, expired and retired arms render no chips; they are unchanged.

### Keyboard (WAI-ARIA APG radio group)

| Key | Behaviour |
|---|---|
| `Tab` / `Shift+Tab` | Enters and leaves the group at **one** stop. Roving tabindex: the selected chip has `tabIndex=0`; with nothing selected the **first** chip has `tabIndex=0`; every other chip has `tabIndex=-1` |
| `ArrowDown` / `ArrowRight` | Moves to the next chip, **wrapping**, selects it (writes the shared draft), and focuses it. `preventDefault()` so the panel/chat does not scroll |
| `ArrowUp` / `ArrowLeft` | Same, to the previous chip, wrapping |
| `Space` / `Enter` | Fires the chip's existing click handler: selects an unselected chip; **deselects the selected chip** |
| Mouse click | Unchanged: selects, or deselects when already selected (D-13) |

Deviation from APG, deliberate: in APG, `Space` on a checked radio does not uncheck it. Here it does, because D-13 keeps click-to-deselect and the keyboard needs the same path to clear a choice (for example to answer with free text only). Claude's decision (operator confirmation owed at G-4).

All of the above reads and writes the **one** draft store keyed by `tool_call_id` (D-12). A selection made by arrow keys in the panel card is what the pointer's draft line, the chat card after a panel toggle, and `WorkflowRunPage`'s direct card all read. No state is copied between renderings.

## Surface 3 — Model Registry Timeout field (D-04, D-06, D-07)

`ModelRegistryTab.tsx` FIRES under G-5. The change is limited to: the help row while the Timeout cell edits, and the refusal sentence the server sends. The `AddModelForm` seam is not taken.

### Refusal (D-07): reuse the shipped in-row slot

- `ModelRegistryTab` **already** renders `ApiError.message` (the server's `detail`) in the in-row refusal slot (`<tr data-model-error>`, `text-[11px] font-medium text-destructive`, `role="alert"`, directly under the model's row). **That path is reused unchanged.** No toast, no second error surface, no client-side text.
- The **client does not pre-block** an out-of-range timeout in `NumericCell`. It sends it, and the server's 422 sentence is what the operator reads. That guarantees the reason on screen is the server's own. The `MODEL_CAP_INT_BOUNDS` mirror is not consulted to refuse typed values; there is still only one bound per side (D-07, no third copy).
- After a refusal the cell shows the **stored** value (no optimistic write, as shipped), and the refusal stays until the next write on that row starts (shipped behaviour).
- What changes is the **server's sentence** for this one column. Today it reads `'llm_call_timeout_seconds' must be between 1 and 3600 (inclusive), or null.`, a raw engine name in an operator surface. It becomes the plain sentence in the Copywriting Contract, following the shipped refusal precedent (`test_242_stored_value_refusal.py`: name, range, what happened). The other integer columns keep their current sentence (out of scope).

### Help line (D-04)

- While the **Timeout** cell is in edit mode, a full-width row renders directly under the model's row (the same `<tr><td colSpan>` shape as the refusal slot, placed **above** it if both show):
  `<span id="timeout-help-{model_id}" data-testid="timeout-help" class="text-[11px] leading-4 text-muted-foreground">`.
- The editing `<input>` gets `aria-describedby="timeout-help-{model_id}"`, so a screen reader hears the range and the retry rule on focus.
- The row disappears when editing ends (Enter, Escape, blur). Claude's decision (operator confirmation owed at G-4): the table is `table-fixed` with a 10% Timeout column, so a permanent visible line cannot fit in the column or header; the edit moment is when the operator needs it.
- The range in the sentence is read from the **one** client mirror value (`MODEL_CAP_INT_BOUNDS.llm_call_timeout_seconds`), never typed as a literal.
- The text comes from one exported constant (`TIMEOUT_HELP_LINE` or similar, planner's name).

## Copywriting Contract

All strings are exact. `{…}` is interpolated; everything else is literal.

| Element | Copy |
|---------|------|
| Primary CTA (pointer) | `Answer in panel →` (accessible name `Answer in panel`) |
| Pointer label | `Needs you` (rendered uppercase by CSS) |
| Pointer question | `{prompt}`, verbatim, plain React text (never HTML) |
| Pointer draft: an option is selected | `Draft: {options[choiceIndex]}` |
| Pointer draft: free text only (trimmed, non-empty) | `Draft: “{freeText.trim()}”` (curly quotes U+201C / U+201D) |
| Pointer draft: nothing yet | `No answer yet` |
| Pointer draft: option **and** free text | `Draft: {options[choiceIndex]}`. The option wins, matching the card's shipped `selectedValue` |
| Card submit (unchanged) | `Send Answer` / `Preparing…` |
| Card free-text label and placeholder (unchanged) | `Reason` with options, `Type an answer` without; placeholder `Type an answer…` (the sketch's `Reason or answer…` is **not** adopted; shipped copy wins) |
| Registry help line (D-03 as written: local 0 retries, cloud 2) | `Between {min} and {max} seconds. Local models are tried once; cloud providers retry quick failures up to 2 times.` |
| Registry help line (if research sets cloud retries to 0 too) | `Between {min} and {max} seconds. Each call is tried once and is not retried.` |
| Registry refusal (server 422 `detail`, 3600 ceiling stands) | `Timeout must be between {min} and {max} seconds. {value} was not saved.` |
| Registry refusal (server 422 `detail`, D-06 found a binding bound below 3600) | `Timeout must be between {min} and {max} seconds, because {reason}. {value} was not saved.` (`{reason}` names the binding limit in plain words, e.g. `longer calls are cut off by the proxy's idle limit`; the research supplies it) |
| Run failure on per-call timeout (D-04, backend `runs.error`) | Existing prefix **kept byte-identical** (pinned by `test_066_terminal_classification.py`, and `categorizeError` matches on `timed out`), then appended: `timed_out: {N}s per-call deadline exceeded at iteration {i} (model={model}). {model} did not answer within {N} s, the timeout set for it in the Model Registry.` |
| Empty state | None new. With no pending ask, `PendingAskStack` renders nothing (shipped) in either home |
| Error state (card) | Unchanged shipped strings: `The server couldn't record your answer. It has not been saved.` · `Your answer was refused ({status}). It has not been saved.` · `Couldn't reach the server — check your connection and try again.` |
| Destructive confirmation | None. This phase adds no destructive action |

Where the run-failure sentence shows: through existing channels only (D-04, "not a new channel"). In chat the status line still reads `timed out` / `Agent reached time limit`; the full sentence is the existing `title` on the RunCard status word (`RunCard.tsx:453`). `RunCard.tsx` is not touched. **Observation for G-4 row 4:** a hover title is a quiet place for "not past the budget unannounced". If the operator wants the sentence visible, that is a follow-up on `RunCard.tsx` (FIRES), not this phase.
