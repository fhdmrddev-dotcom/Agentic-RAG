<domain>
## Phase Boundary

The run surface's **centre column** stops being a second, plainer copy of the right panel's
step list. It leads with the **deliverable** — chosen by what the run actually produced — and
each step line reports what it **yielded** rather than only restating its name.

**This is a RE-PRESENTATION of facts that already ship**, plus ONE narrow new read (per-step
citations, lazily fetched). `200.1-02` already built the four deliverable arms (file / answer /
both / neither) and three were driven live in a browser on 2026-08-21. **The selection logic is
DONE.** A plan that scopes this as new capability has misread it.

**In scope:** `WorkflowRunPage.tsx`'s deliverable region (moved + restyled as a hero),
`RunTranscript.tsx`'s row composition (yield in the phrase, expandable passages), one narrow
per-step citations read on the backend, `RunSpine.tsx` losing its count sub-line, and the
vocabulary leaves that hold the new strings.

**Out of scope:** any stored reasoning/thinking trace (that is a backend persistence phase — see
refusal R-1); per-document relevance scores (R-2); invented per-step narration (R-3); the chat
surface's own rendering of the run; branching/graph work on the canvas.

</domain>

<decisions>
## Implementation Decisions

### Where the hero lives

- **D-01:** The deliverable region **moves out of the bottom band to the TOP of the centre
  column**, above the log. It is the hero; the log beneath it is the ledger. `RunSpine`'s column
  and its pins are untouched by this move. (Today the region is a `shrink-0` `section` with
  `md:max-h-[220px]` pinned at the page's foot, below ~780px of dead column.)
- **D-02:** The hero sits **above the `[Log | Shape]` switch point**, so it renders in **both**
  the Log and the Shape (canvas) views. The deliverable is a fact about the run, not about how
  you are viewing it; and a person who clicks Shape has not stopped wanting the file. The switch
  itself stays in the page header where it ships today.
- **D-03:** **While the run is live the hero slot does not render at all** — no card, no
  placeholder, no reserved height. The log starts at the top of the column and the hero pushes in
  when the first file or answer lands. ⚠ Consequence: `COPY_NO_FILES_LIVE`
  (*"No files yet — this run hasn't written anything."*) is **retired for the live arm**. It
  carries a source fence pinning it at exactly one occurrence, so its removal is a deliberate
  edit that must be recorded (superseded-not-deleted, per this file's own convention).
- **D-04:** Centre-column order is **hero → totals strip → log**. The `RunReceipt
  variant="summary"` strip keeps its position relative to the list it summarises (its own
  docblock says that is why it moved up); reading order becomes *what you got → how long it took
  → how it got there*. The strip is NOT folded into the hero — this is `RunReceipt`'s first and
  only mount in the product and dissolving it would leave the component unmounted again.

### Step yield (SC#2)

- **D-05:** The yield goes **into the log line as part of the phrase** — `00:26  Pull support
  history — 20 sources` — and comes **OFF** `RunSpine`'s count sub-line. ⚠ **This is not a
  reversal of `200.1-03`.** That block removed the count as a *trailing atom* (*"carrying atoms
  here is what made five rows read as a table"*) while asking, in the same docblock, for the
  sheet's shape: *"the line FLOWS: gutter, then one continuous phrase."* A yield inside the
  phrase satisfies the second and does not violate the first. The spine keeps name + status +
  duration; the log keeps clock + name + yield. **Each column now carries something the other
  does not** — which is the whole point.
- **D-06:** Steps with **no `step_count`** (`llm_single`, `llm_human_input`, `external_action`)
  yield **`wrote an answer`**, derived from a non-empty per-step `deliverable_text` — a **fact,
  not a figure**. ⚠ Sketch 201 proposed `Wrote 517 characters`; that is rejected. It measures the
  string rather than the work, nobody decides anything differently at 517 vs 4,411, and it sets a
  precedent for printing any number we happen to hold. A step with neither a count nor text shows
  **nothing** — no `0`, no dash. D-07's absent arm survives intact.
  ⚠ `step_count === 0` is a REAL measurement and must still render its noun; only `null` is absent.
- **D-07:** The yield **replaces the outcome word `finished`**, and only that word. Every other
  outcome (`stopped on an error`, `never ran (skipped)`, `interrupted`, `not reached`,
  `paused, waiting on a person`, `still running`, `did not finish`, `outcome not recorded`) keeps
  its word and renders **no** yield — nothing was produced. Result: **exactly one trailing
  element per row at every state**, so 200.1-03's "one continuous phrase" holds everywhere.
  ⚠ On a fully-successful finished run today every log row reads `… finished` — five identical
  words beside a spine showing ✓ five times. That is a duplication axis nobody had measured, and
  D-07 removes it.
- **D-08:** **Step names stay in BOTH columns.** The name is the anchor that lets a log line be
  paired with a spine row; removing it from either makes the two columns un-cross-referenceable.
  With a distinct payload on each side, a repeated anchor reads as *correspondence*, not
  duplication. ⚠ **This is the proposition the RENDERED SKETCH exists to test, and SC#4 is judged
  against it on screen by a human — not by a DOM assertion.** If the sketch says the repetition
  still reads as duplication, that verdict outranks this decision.

### Citation passages (SC#3)

- **D-09:** SC#3 is **IN, but LAZY** — a **narrow new per-step read** (run + step scoped) that
  returns citations only when a person expands that step. ⚠ **The run read is POLLED**
  (`RUN_POLL_MS`, `WorkflowRunPage.tsx:1144`) while a run is live, so inlining ~38 passages ×
  N phases would repeat that payload every tick. Lazy keeps the live path small, and it leaves
  `api/workflow_runs.py`'s serializer **and its written "only `text` may reach the wire" comment
  byte-unchanged** — nothing recorded is overturned.
  ⚠ **This means the phase HAS a backend half**, and the ROADMAP's *"RESTYLE, NOT A REBUILD"*
  fence must be amended to say so rather than quietly exceeded.
- **D-10:** **`similarity` is stripped at the new endpoint** — the wire carries `document_id`,
  `filename`, `chunk_index`, `passage` and NOT the score. ⚠ **This is refusal R-2 enforced BY
  CONSTRUCTION, at the boundary where the finding lives** (`similarity_scores` held 7 entries
  against 38 citations on the same row — they do not correspond). The shipped `CitationCard` /
  `CitationPeek` render `citation.similarity.toFixed(2)` whenever it is non-null, so **reusing
  them as-is on a wire that carried the score would ship exactly the lie the refusal names.**
  With it absent, the score branch provably cannot fire and the components are reused UNCHANGED;
  chat is untouched. Assert with a **set-equality test over the real response body** (the 200.1
  pattern), not a deny-list.
- **D-11:** **Exactly one count is ever printed.** The yield keeps the executor's declared
  `_measure`; the expanded passages region states **no total**. ⚠ Nothing guarantees
  `_measure.count === len(citations)` on the same row — SEED-191 records `{count: 15}` on one run
  and 38 citations on another — so a surface printing both could contradict itself on one line.
  Printing one makes the question moot. **Do NOT reconcile the yield to `len(citations)`**:
  `_measure` is authored copy owned by the step and is the field D-07 exists to surface.
- **D-12:** **The yield IS the disclosure control.** `— 15 sources` becomes the button; passages
  expand **inline beneath that row**. No new trailing atom, so D-05/D-07's single-element rule
  holds. ⚠ `RunTranscript` rows are plain `<li>`s with **zero focusable elements today** — this
  adds the surface's first per-row focus stops, so focus order and any "zero controls" fences on
  this component must be re-checked, not assumed. Rows with no citations keep a **plain text**
  yield, so the affordance appears only where it leads somewhere.

### The 'neither' arm (SC#1)

- **D-13:** The empty hero **states the run's own terminal fact, split by outcome**. A failed run
  says it stopped and **names the step it stopped at** (durable per-row `status` — a join, not an
  invention; `OUTCOME_FAILED = "stopped on an error"` already ships). A completed-but-empty run
  says it finished without writing anything. ⚠ Today both render the SAME sentence
  (`COPY_NO_FILES_TERMINAL`), folding two different truths into one — the
  `runFacts` / `DecisionsList` / `phaseDuration` / `transcriptVocabulary` defect, caught here
  **before** it bites rather than after.
  ⚠ Naming the failing step is permitted where `deliverableOf` is not: `status` is per-row and
  durable, whereas nothing on `workflow_phases` says which step made which FILE.
- **D-14:** **The hero carries NO heading.** A file card showing a filename beside a Download
  control needs no label saying it is a file; an answer card rendering prose needs none either.
  ⚠ This **drops the D-02 authorship problem rather than re-solving it**: `COPY_DELIVERABLE_HEADING`
  (*"Files in this run's workspace"*) may not claim authorship because the list is thread-scoped,
  `COPY_ANSWER_HEADING` may, and today the files heading sits above a sentence about files **and**
  answers (SEED-191 §4, still live). Both constants are **superseded, not deleted** — each carries
  a one-occurrence source fence and `git log -S` must still find the thread through the quotation.
- **D-15:** The file arm heroes the **newest file only**; any other thread files remain a plain
  list beneath it. ⚠ The list is **thread-scoped** — measured exact for 60 of 61 file-bearing runs
  and **visibly wrong for one** — and promoting a file to an unlabelled hero implies authorship
  *more* strongly than a neutral heading did. Keeping the remainder visible makes the 1-in-61 case
  degrade to *"the wrong file is prominent"* rather than *"the only file shown is wrong"*, and
  nothing the current surface shows is hidden.
- **D-16:** The empty hero is **TOTAL over every terminal status** — completed-but-empty, failed,
  cancelled/interrupted — with an explicit fallback that **never reads as success**, matching
  `OUTCOME_UNKNOWN`'s shipped rule (*"NEVER SUCCESS BY DEFAULT"*). ⚠ Enforce exhaustiveness at the
  **type level** so a future status is a typecheck error rather than a silently wrong render — the
  `phaseStatusMeta` / `SUBSTEP_META` totality pattern. A cancelled run must not be told it
  *"finished without writing anything"*.

### Binding refusals (carried from SEED-191 / sketch 201 — a restyle must not quietly overturn them)

- **R-1 — No stored thinking process.** No substep/event/trace table exists; `reasoning_content`
  is `0` on every workflow-run message; the live substep stream is an ephemeral Redis buffer
  (`run:{run_id}`). A reasoning view of a FINISHED run would be fabrication. **That is a backend
  persistence phase, not this one.** The Stitch reference's `Query:` / `Target:` /
  `confidence threshold > 0.85` block is NOT reproduced.
- **R-2 — No fabricated relevance score.** Enforced by D-10.
- **R-3 — No invented per-step narration.** `RunTranscript` ships this refusal with a driven
  positive control. The sheet's two-line-per-step rhythm was BUILT AND WITHDRAWN on measurement:
  its two lines carry authored narration this product does not have. **D-05's yield is a stored
  fact, not narration** — that is what makes it admissible where a sentence is not.
- **R-4 — Colour is spent on STATE, never decoration.** Deep Midnight uses accent sparingly and
  Phase 185 already spent the budget (*"governance spends no colour and no third badge"*).
  **Prominence comes from weight, size, spacing and the card.** The hero is not a coloured band.

### Claude's Discretion

- Precedence when a step carries **both** a `_measure` count and non-empty `deliverable_text`:
  the **count wins** (more specific). Stated rather than asked.
- The exact typographic treatment of the hero card, the em-dash joiner in the yield phrase, and
  the expanded passage region's internal spacing — all settled by the **rendered sketch**, which
  is the acceptance bar.
- Whether the new strings live in `transcriptVocabulary.ts`, `receiptVocabulary.ts` or a new hero
  vocabulary leaf. ⚠ Note the constraint: `receiptVocabulary.ts` is a TRUE leaf and D-09's *"from
  the library vocabulary's register"* means the TONE, never the MODULE — importing across
  vocabularies **breaks a contract** rather than tripping a fence, so only that module's own suite
  can catch it.

</decisions>
