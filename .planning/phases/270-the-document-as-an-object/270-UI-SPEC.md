# Phase 270 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** two additions to shipped surfaces, with no new page and no new panel. (1) A **Download** control that names the version it fetches, in the document detail panel header and in the Library list row (FIND-04). (2) A **File** section in the document detail panel listing the file's own facts, with every date labelled for what it means (FIND-05).

> **G-2 sketch SKIPPED by recorded decision (D-11).** This spec is the visual contract in its place. OV-266-01 is the reason it is this detailed: a note that lived only in a tooltip was invisible at rest. **Every deliverable word in this spec is visible at rest. None of it lives in a tooltip, a hover, or a `title` attribute.**

Exactly 3 sizes and 2 weights are introduced or reused by the new elements. Every new element is covered by the four roles below.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Body (fact value) | 14px (`text-sm`) | 400 | 1.5 (`leading-normal`) | Every fact value, including "not recorded" |
| Label (fact label, captions, receipts, button text) | 12px (`text-xs`) | 400 | 1.5 | Fact labels; "File lives in …" reason line; "Download started" / error lines; the MIME sub-line (mono); the list-row Download text |

## Download Control: states and interaction contract

### Label (the only derivation: `downloadLabel`)

| Document state | Panel label (`viewing: true`) | Row label |
|---|---|---|
| `version_number` absent or ≤ 1 | `Download` | `Download` |
| `version_number` = N > 1, `is_latest` true | `Download vN (latest)` | `Download vN (latest)` |
| `version_number` = N, `is_latest` false | `Download vN (viewed, not latest)` | n/a (the list shows latest only) |
| No stored file (`file_path` empty) | disabled control, see below | disabled control, see below |

⚠ **Measured finding, see Open Question Q1:** today the panel can only open a **latest** row. `LibraryPage` resolves `selectedDoc` from the latest-only `documents` list (`LibraryPage.tsx:340`), and a cited non-latest doc never resolves. So the `(viewed, not latest)` label cannot be reached in the shipped product. The label function still implements it (D-07), but SC#2's "viewed" half needs a reachable path.

### States

| State | Panel (header row 2 and 3) | Row (Actions cell) |
|---|---|---|
| **Idle** | Outline button, the label | Ghost button, the label |
| **Preparing** (mint in flight) | Button disabled, `Loader2` spinning (`motion-safe:animate-spin`) replaces the icon, text `Preparing download…`, `aria-busy="true"` | Same, text `Preparing…` |
| **Started** | Button returns to idle. Row 3 shows `Download started` (12px, `--panel-status-done`, `role="status" aria-live="polite"`, `motion-safe:animate-fadeSlideUp`), auto-clears after 4 s (the shipped receipt timing) | Button returns to idle. No row receipt, because the browser's download UI is the confirmation |
| **Error** | Row 3 shows the error copy (12px, `hsl(0 80% 80%)`, `role="alert"`). It **persists** until the next click or until the panel's document changes | A 12px `role="alert"` line under the action buttons inside the same `<td>`, auto-clears after 6 s |
| **No stored file** (D-06) | Button `disabled`, **dashed** outline (`border-dashed`), text and icon at full contrast (`disabled:opacity-100 text-panel-muted-foreground cursor-not-allowed`). Row 3 **always** shows the reason sentence at rest | Button `disabled`, dashed, full-contrast `text-muted-foreground`, visible text `Not stored here`. The full sentence with the source name is in the panel |

⛔ **The disabled control must override shadcn's `disabled:opacity-50`.** At 50% opacity the words fall below 4.5:1, which would make them visible to nobody, the OV-266-01 failure in a different form. A dashed border signals "non-interactive" (the 094 locked-step vocabulary). The words stay at full contrast.

### Interaction contract (security-bearing, D-04 / D-05)

1. **No URL exists before the click.** Neither button has an `href`, and no signed URL is prefetched, cached in state, rendered into the DOM, or logged. A right-click "Save link as" has nothing to save. That is intended: the URL is a bearer token.
2. On click: set Preparing, then call the mint endpoint **for `doc.id`** (the same object the label was derived from). The server runs its user-JWT / RLS access check **before** minting (D-04). The UI does not pre-check and does not assume access.
3. On 200: **before navigating**, the client asserts that the response's `version_number` equals the version the label named, when the response carries it. On a mismatch it downloads nothing and shows the mismatch error. The request then navigates immediately with a transient `<a>` created, clicked and removed in the same tick, or `window.location.assign`. The URL is used once and dropped.
4. The saved file must carry the **original filename**. The server should mint with the storage `download` option so the response sets `Content-Disposition: attachment; filename=…`. A cross-origin `download` attribute is ignored by browsers and cannot be relied on.
5. Every click re-mints. The UI never retries a previous URL, so a 60-second lifetime can never show up as a broken second click.
6. The lifetime is **not shown** to end users. It is an operator setting (D-05), and "link valid for 60 s" means nothing to someone whose download has already started.

## Accessibility

- Both buttons have a **visible** text label, and that label is their accessible name. The row button adds the filename for screen readers: `aria-label="{label} — {filename}"` (for example "Download v3 (latest) — contract.pdf"), because twenty rows all announcing "Download" cannot be told apart. The visible text is unchanged.
- The disabled no-file control carries `aria-describedby` pointing at the visible reason line in the panel. In the row, the visible `Not stored here` is the description.
- Preparing: `aria-busy="true"` on the button. Receipt: `role="status" aria-live="polite"`. Error: `role="alert"`. These match the shipped panel's save receipts.
- Facts use `<dl>/<dt>/<dd>`. Dates use `<time dateTime>`. "not recorded" is plain text, never only an icon or a colour.
- All meaningful text uses panel-scoped AA tokens (≥ 4.5:1 in both themes). No `opacity-*` on meaningful text.
- Motion (`fadeSlideUp`, spinner) is `motion-safe:` only. The receipt still renders instantly when motion is reduced.
- Keyboard: both buttons are in natural tab order. In the panel, the order is close (focused on open, shipped) → Download → File section header → Details. Enter and Space activate.

## How we'd know the UI failed (G-6, UI half)

- Any deliverable word (the version in the label, "not recorded", the not-stored reason) is only reachable through hover, a tooltip or a `title` attribute.
- A signed URL appears in the DOM (`href`), in React state after the click resolves, or in the console.
- `updated_at` or `created_at` is rendered under a "…in the file" label.
- `0 pages`, `0 B` or an empty `<dd>` renders for any document.
- The disabled no-file control's text measures below 4.5:1 (it inherited `opacity-50`).
- Two rows in the panel carry the identical label `Author` (or `Type`) with different meanings.
- The list row's `<td>` count changes from seven, and the ≤430px column shed then hides the wrong columns.
- A new element renders at weight 500 (shadcn's `font-medium` not overridden).
