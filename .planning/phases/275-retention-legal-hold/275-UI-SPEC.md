## Color

All values are shipped tokens. The dark theme is shown. **Most tokens are theme-paired, but two text colours are not:**
- `--warning` stays `38 92% 60%` in **both** themes, so `text-warning` on a light surface fails AA.
- The lightened red `hsl(0 80% 80%)` is a dark-only literal and fails on light.

Every retention **text** use of amber or red therefore carries an explicit light shade, with the dark shade behind the `dark:` variant (Tailwind `darkMode: "class"`, the shipped `.dark` block):

| Text role | Class | Light value | Dark value |
|---|---|---|---|
| Amber text (hold chips, hold refusals, the member hold line, the stale banner, undecidable notes) | `text-[hsl(32_90%_30%)] dark:text-warning` | `hsl(32 90% 30%)`: the shipped light `--panel-status-active`, 5.15:1 on the light panel | `hsl(38 92% 60%)` |
| Red text (Delete chip, Waiting-for-you count, delete notes) | `text-[hsl(0_72%_40%)] dark:text-[hsl(0_80%_80%)]` | `hsl(0 72% 40%)` (darkened red, ≥ 6:1 on white and ≥ 4.5:1 on its 10% tint) | `hsl(0 80% 80%)` |

Tints and borders (`bg-warning/10`, `border-warning/30`, `bg-destructive/10`, `border-destructive/40`) stay the same in both themes. Violet (`--accent-violet-text`) and success are theme-paired. Primary text on light is paired but borderline (`239 84% 67%` ≈ 4.47:1 on white): 11px primary text (Review / In review chips, `Archived: included`, `+ New policy` / `+ New hold`) uses `text-[hsl(239_70%_50%)] dark:text-primary`.

| Role | Token | Value (dark) | Usage |
|------|-------|--------------|-------|
| Dominant (60%) | `--background` | `hsl(216 45% 4%)` ≈ `#06090F` | Page and tab body surface |
| Secondary (30%) | `--card` / `--muted` / `--panel-surface` | `hsl(220 30% 7%)` ≈ `#0D1017` / `hsl(220 30% 11%)` / `hsl(220 40% 8%)` | Policy/hold/batch cards, table hover, the detail panel, form inputs (`bg-muted`) |
| Accent (10%) | `--primary` | `hsl(239 100% 82%)` ≈ `#A3A5FF` | See the reserved list below |
| Destructive | `--destructive` (+ text pair `text-[hsl(0_72%_40%)] dark:text-[hsl(0_80%_80%)]`) | `hsl(0 72% 51%)` ≈ `#DC2828` | **Delete only**, listed below |

1. The active sub-tab underline (`border-b-2 border-primary`), and the active org band tab (already shipped).

3. **"+ New policy"** and **"+ New hold"** (the sketch's `.btn` indigo tint: `bg-primary/10 border-primary/30 text-primary`).
4. The **"Show"** link in the archived-hidden hint, and the **"Include archived"** chip when it is on.
5. The **Review** tag/chip ("Review", "In review"). Indigo here means "a person decides". It never means destructive.

**Posture states (Claude's discretion, needed by D-29 "the sweep ships disabled" and D-06 "ambiguous means nothing happens"):**

| State | Copy |
|-------|------|

## S2 — Policy editor (2B)

Replaces the sub-tab body in place. It is not a modal. Breadcrumb `Retention › Policies ›` + title **`New policy`** or **`Edit “{name}”`**, a ghost **`Back to policies`** button at right. It discards unsaved edits and returns to the Policies list.

Two columns at ≥ 1024px (`grid-cols-[minmax(0,1fr)_360px] gap-6`). Below that, one column: the form, then the preview.

**Form (`grid grid-cols-[150px_minmax(0,1fr)] gap-x-4 gap-y-4`, single column < 768px).** Labels are ported from 2B.

| Label | Control | Notes |
|-------|---------|-------|
| Name | `Input` | Required. Error: `Give the policy a name.` |
| Document type | `Select`: `Any type` + the org's live types with counts, e.g. `Invoice (9)` | Reads `top_document_types` (CONTEXT discretion: pick from the live distribution, never free text) |
| Folder | `Select` (`Any folder` + folder paths) + checkbox `subfolders` | D-23: a folder policy covers subfolders, and the nearest folder's policy wins. The checkbox is **on by default**. |
| Keep for | number `Input` (min 1) + unit `Select`: `days` · `months` · `years` | **Claude's discretion** (the sketch had years only). The G-4 LIFECYCLE scenario needs "archive after 1 day, delete after 2". Default unit is `years`. |
| Counted from | `Select`: `the document date` · `the day it was added to the Library` | **D-22: exactly two options, no fallback.** The sketch's third option (`the day the file was last modified`) is removed. |
| Then | `Select`: `archive it` · `delete it` · `ask a person to decide` | Ported |
| *(only when Then = archive it)* Later | checkbox `Then queue it for deletion` + number + unit `after` | **D-20 second stage. Copy is Claude's discretion.** Helper: `Counted from the same date. Deletion still waits for an org admin to confirm.` Validation: `The delete step must come after the archive step.` |

Validation, shown inline under the field, never as a toast:
- Both Document type = Any type **and** Folder = Any folder → `A policy needs a document type, a folder, or both.` (Claude's discretion: an org-wide catch-all is too easy to save by accident.)

**Action note** under the form (ported verbatim, by `Then`):
- archive → `Archived documents stop appearing in chat answers. They stay in the Library, findable with “Include archived”, and open and download as normal.`
- delete → amber: `Deletes never run on their own. Tonight's sweep lists what is due, and an org admin confirms each document by name.`
- review → `Due documents are listed for a person. Nothing is changed automatically.`

**The gate (D-02), in the form footer (`border-t pt-4 flex gap-2`):**
- `1 · Preview what this would do`: ghost button, always enabled while the form is valid.
- `2 · Save policy`: primary button. **Disabled** until a Preview has run **and** nothing has been edited since. While disabled, a visible line beside it reads `Preview first. A policy can't be saved until you've seen what it would do.` The reason is on screen, never only in a tooltip.
- Any field edit after a Preview sets the preview **stale**. Save locks again, and the amber banner above the preview reads (ported): `You changed the policy after the preview. Preview again before saving.`
- Save success returns to the Policies list. The receipt row lands in History and the band marker flashes. There is no toast (062-A).
- **Save failure:** an inline `role="alert"` line directly above the footer buttons reads `Couldn't save the policy. Nothing changed. Your preview is still here.` The preview stays on screen and **Save stays unlocked**, because nothing was edited, so the admin can retry without re-previewing. The editor does not close.

**Preview column (`RetentionPreview`)**, title `Preview · what tonight's sweep would do` (ported, 12px uppercase label):

| Bucket (expandable `<details>`, numeral 16px semibold) | Ported label | Open at rest | Tone |
|---|---|---|---|
| act | delete: `would be **queued for you to approve** deletion` · archive: `would be **archived**` · review: `would be **listed for a person to decide**` | when N > 0 | red / violet / indigo border |
| hold | `skipped — **on legal hold**` (rows: `{doc} · {hold name}`) | no | amber numeral |
| undecidable | `**can't be decided — nothing will happen to them**` (rows: `{doc} · no document date` / `{doc} · also under “{other policy}”`) | when N > 0 | amber fill |
| kept | `kept by an admin — skipped until this policy or the document changes` (rows: `{doc} · kept by {name} on {date}`) | no | neutral. **Claude's discretion**: D-11 needs kept documents to be visible, not silently missing. |
| not yet | `not due yet · next: {doc}, {date}` | no | neutral |
| already | `already archived` | no | neutral; shown only when N > 0 |

Under the undecidable bucket, amber note (ported): `Give these a document date, or count from “added to the Library” instead.` and/or `A document under two policies that disagree is never touched: change one of them.`

Before the first Preview (ported): `Nothing previewed yet.` / `A policy can't be saved until you've seen what it would do.` (dashed `border-border` empty box).

Preview loading: buckets render as `aria-busy` skeleton rows. Preview error (Claude's discretion, fail-closed): `Preview couldn't finish, so this policy can't be saved yet. Nothing was changed.` + `Try again`. **Save stays locked.**

**Remove a policy (Claude's discretion).** D-06 says a collision clears only "until one changes", and an admin needs a way to stop a policy. The editor shows a ghost `Remove policy…` button at bottom-left, edit mode only. It opens an `AlertDialog`:
- Title `Remove “{name}”?`
- Body `No documents are deleted. Documents it already archived stay archived, and anything it queued leaves “Waiting for you”.`
- Buttons `Keep policy` (cancel, focused by default) · `Remove policy` (outline, not red: it destroys no data).

This follows the 066 graded rule: the target is specific, but there is no data victim, so it gets a plain confirm plus a ✎ receipt.

**Remove failure:** the dialog stays open, and an inline `role="alert"` line above its buttons reads `Couldn't remove the policy. It is still active.`

## Interaction & accessibility contract

- **Sub-tabs:** `role="tablist"` / `role="tab"` / `aria-selected`, arrow-key roving focus. The count is part of the accessible name, e.g. `Waiting for you, 4 waiting`.
- **Type-the-count:** the visible label sits beside the input and is not a placeholder. `aria-describedby` points at `This can't be undone.` `Enter` submits only when the button is enabled.
- **Save gate:** the disabled Save uses `aria-disabled="true"`, keeps keyboard focus, and has `aria-describedby` pointing at the visible reason line.
- **Receipts:** no toasts (062-A). Every write lands as a History row and pulses the band marker (`recordingPulse`, 1.6s, `motion-safe` only). The receipt still exists with motion off.
- **Focus:**
  - Opening the editor focuses the Name field.
  - `Back to policies` and Save return focus to the triggering row or button.
  - A completed batch moves focus to the result banner.
  - Dialogs trap focus and restore it on close (Radix).
- **Dates:** `toLocaleDateString(undefined, { day: "numeric", month: "short", year: "numeric" })` (the 271 `FIND_DATE_FORMAT`). A missing date reads `not recorded` (270 rule), never a substituted date.
- **Responsive:**
  - < 1024px: the editor stacks (form, then preview).
  - < 768px: form labels sit above controls, batch tables scroll horizontally inside their card, and the detail panel is the shipped bottom sheet.
- **Contrast:** chip text uses the amber and red pairs from §Color (light shade + `dark:` shade), plus `text-accent-violet-text` and `text-primary`, on their 10% tints. The hold refusals and the member hold line use the amber pair, so they are AA in both themes. Never the global `--muted-foreground` inside the panel; use `text-panel-muted-foreground` there.
