<objective>
Build the eval runner engine: a bounded background job (modeled on `skill_tuner.py::_run_tuner_job`) that, for each owner-scoped test case, drives `run_agent_loop` twice (WITH = target-skill-only catalog, WITHOUT = empty catalog), persists an `eval_results` row the instant each arm finishes, and emits additive `eval_*` progress events over the shared `run:{run_id}` buffer.

Sequential arms over one reused ephemeral eval thread (RESEARCH Pattern 4).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| background job → provider gateway | The job drives real (paid) LLM completions; unbounded fan-out is a cost/DoS risk |
| background job → eval_results / runs writes | Service-role writes; the job is the only writer, must stamp user_id from current_user |
| inner run_agent_loop emit → shared eval buffer | The loop's terminals would corrupt the shared SSE stream if not isolated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-133-02 | Denial of Service | unbounded fan-out / cost blow-up | mitigate | Single provider/run (D-01), bounded N cases, per-call timeout (get_per_call_timeout), atomic Redis SET NX in-flight claim (one eval per skill), eval_cancel:{run_id} checkpoint at each arm |
| T-133-04 | Information Disclosure | eval_results.error / runs.error | mitigate | Truncate every error string to <=200 chars (threads.py:1561 precedent) — never raw tracebacks/key fragments |
| T-133-03 | Tampering / EoP | row ownership | mitigate | user_id stamped from current_user (never body); skill_version snapshot is owner-scoped; results inherit the verified owner |
| T-133-07 | Tampering | shared eval SSE buffer | mitigate | NO-OP emit on the inner loop so its 'done'/'error' terminals never reach run:{run_id}; only the service emits the single terminal |
| T-133-SC | Tampering | package installs | accept | No installs in this phase |
</threat_model>
