<objective>
Surgical refactor of frontend/src/hooks/useMessages.ts: replace the v2.4 Phase-057 race-prone band-aids (Realtime subs, finally-block reload, in-loadMessages ref-write) with the goal-locked architecture from 057-DEFERRAL §"Updated Recommended Approach": a `setViewingThread` callback that is the sole writer of `activeThreadIdRef`, an `AbortController`-driven `loadMessages` that reads the ref only post-await, and aggressive removal of all four Phase-057 band-aids (per-stream `channelRef`, always-on `threadChannelRef` + `subscribe/unsubscribeToThread`, `clearMessages`-internal abort, `finally`-block `loadMessages`).

Purpose: This is the foundation for STREAM-02a. Without `setViewingThread` separation + `loadAbortRef`, concurrent `loadMessages(A)` and `loadMessages(B)` calls will keep corrupting each other (the v2.5-dev failure mode documented in 057-DEFERRAL.md §"loadMessages was overwriting its own guard"). Without dropping the finally-block reload, the Bug 3 raw-JSON regression returns on every natural stream completion.

Output: A single modified file (`frontend/src/hooks/useMessages.ts`) with the new hook surface — `subscribeToThread`/`unsubscribeFromThread` removed from `UseMessages`, `setViewingThread` added.
</objective>
