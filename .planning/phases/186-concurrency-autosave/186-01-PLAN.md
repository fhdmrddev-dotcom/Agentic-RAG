<objective>
Give the draft row an optimistic concurrency token and make a stale write refuse itself
honestly.

Purpose: CONCUR-02's clobber guard, and the wire contract every other plan in this phase
builds against. Today `update_workflow_definition` is an owner-scoped, draft-only UPDATE
with no notion of "has this row moved since I read it", and its only failure signal is
`None` -> 404 — which, once a token conjunct exists, would tell an author their own draft
does not exist.

Output: `CONCURRENCY_TOKEN_SQL`, a token on the create/list/read/update responses, an
optional `If-Match` request header, and a three-way refusal (404 / 409 `already_published`
/ 409 `stale_token`) that keeps the 404-collapse closed.

**DEVIATION FROM CONTEXT.md, RECORDED IN THE OPEN.** D-186-07 says "add `AND updated_at = $N`".
That does not run. The workflows path is **asyncpg**, and asyncpg refuses to bind a `str` to
a `timestamptz` parameter — with *and* without an explicit `$N::timestamptz` cast (probed
against the live stack 2026-08-01: `DataError: expected a datetime.date or datetime.datetime
instance, got 'str'`). This plan therefore compares in **text space** via one shared SQL
constant, which is what makes "echo the string verbatim" enforceable rather than merely
requested. **The zero-migration promise is INTACT** — no column, no slot 115, head stays at
114. See `186-RESEARCH.md` §RECOMMENDATION 1, probes C/D/E/F/G/I/J.
</objective>

<wire_contract>
THE CONTRACT THIS PLAN FIXES. Plans 186-02, 186-03, 186-05 and 186-06 are written against
these exact strings — do not rename anything here without updating those plans.

| Element | Value |
|---|---|
| SQL constant | `CONCURRENCY_TOKEN_SQL` in `backend/app/db/workflows.py`, module level |
| Its expression | `to_char(updated_at AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')` |
| Response field | `token`, typed `str` (backend) / `string` (client). NEVER `datetime`. |
| Carried on | `DraftCreateResponse.token` (create + PATCH), `DraftRow.token` (drafts list) |
| Request carrier | HTTP header `If-Match`, **OPTIONAL for this release** |
| Stale refusal | HTTP **409**, `detail = {"code": "stale_token", "message": <prose>, "token": <current token>}` |
| Published refusal | HTTP **409**, `detail = {"code": "already_published", "message": "workflow is published and cannot be modified"}` |
| Missing / not-owned | HTTP **404**, `detail = "draft not found"` (string, unchanged) |
| Shape rejection | HTTP **422** (FastAPI's own), unchanged |

**Decided here, deliberately (RESEARCH "Open risks the planner must decide" #1, #2, #3):**

1. **`If-Match` header, not a wrapper body model.** `WorkflowDefinition` is `extra='forbid'`
   and the token is transport metadata, not part of the definition (D-14: no second source
   of truth). A body-shape change would break every caller and every test that PATCHes a
   bare definition.
2. **OPTIONAL for one release.** An absent `If-Match` means exactly today's unguarded
   behaviour. Required would break every browser tab open across the deploy on its next
   save. The client (186-03/186-06) always sends it, so the unguarded path is reachable only
   by a pre-deploy tab or a non-browser caller. This is a dated concession, not the end
   state — the source comment must say so.
3. **409 + machine code, not 412.** The shipped client already branches on 409 and already
   throws the body away; adding a code is strictly additive at one call site. 412 would
   split one concept across two statuses and would drag the shipped, operator-verified
   published-row sentence with it (D-186-09 protects that sentence explicitly). RFC 9110
   §15.5.10 permits 409 for "conflict with the current state of the target resource".
</wire_contract>
