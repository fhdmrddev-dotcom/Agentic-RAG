# Phase 292.1: Tool-limit Continue that always fires - Context

**Gathered:** 2026-10-24
**Status:** Ready for planning

<domain>
## Phase Boundary

When the agent reaches its tool-round limit with work still pending, the turn always ends the
Claude.ai way: a worded limit line and a Continue that resumes the SAME run, on every provider.
Tool-call markup is never shown or saved as an answer. Closes BUG-261024-03.

In scope: turning text-form tool calls (DSML, XML tags as models actually emit them) into real
calls; a provider-blind final-answer markup check; routing a typed "continue" to the existing
Continue path; operator knobs for the two round caps so UAT can hit the cap cheaply.

Out of scope: what output-file cards show (BUG-261024-04, deferred); any change to Continue
counting (`max_continues_per_run = 3` stays); rebuilding the Phase 092 limit line + Continue card.

</domain>

<decisions>
## Implementation Decisions

### Measured before discussion (scout, 2026-10-24) — these correct the ROADMAP flags
- **D-01:** The DeepSeek markup strip is gated on `active_provider_name == "deepseek"`
  (`backend/app/services/provider_gateway/openai_compat.py:352`). The failing run was
  `openrouter` · `deepseek/deepseek-v4.1-flash-1017`, so the strip never ran. Cause #1.
- **D-02:** The strip's opener literal is `<｜｜DSML｜｜` (TWO fullwidth bars,
  `openai_compat.py:167`, bytes `3c efbd9c efbd9c 44534d4c`). Production message `4226d237`
  begins `<｜DSML｜ calls>` (ONE bar then a space, bytes `3c efbd9c 44534d4c efbd9c 20`),
  read from cloud via Supabase MCP. So **native DeepSeek v4.1 would leak too**. Cause #2.
- **D-03:** ⚠ The ROADMAP flag "reuse the existing DSML/XML parsers" is FALSE. No DSML *parser*
  exists (the code only strips), and `tool_parser.parse_structured_tool_calls` reads JSON blocks
  only. No XML tool-tag parser exists. This phase writes the parser.
- **D-04:** Even when the native strip DID fire, the cap path could not see it: the cap check
  (`agent_loop.py:2849`, `if force_no_tools and tool_calls_buffer`) reads only the structured
  buffer, and the leak path appends `DSML_LEAK_ERROR_MESSAGE` and finishes `completed`.

### Text-form call at the cap
- **D-05:** On the forced-final round, a text-form tool call is **parsed into a real call and
  queued** through the existing `persist_cap_paused` (same carrier row, same
  `kind='iteration_cap_paused'`, same non-terminal `cap_paused` event). Continue runs it first,
  byte-identical to a structured cap call.
- **D-06:** The parser reads the **measured set**: every tool-call text format found in our
  production `messages` plus each provider's own docs (provider-docs-first). Minimum: DeepSeek
  DSML in both one-bar and two-bar spellings, and whatever XML tool tags OpenRouter-routed models
  actually emit. The researcher measures the set (prod read-only SQL + provider docs) before
  planning, and the opener literal is fixed from that evidence, not guessed.
- **D-07:** Markup at the cap that **cannot be parsed** (truncated, unknown tool name, broken
  arguments) is stripped and the run **still pauses `cap_paused` with Continue**, with nothing
  queued. On Continue the model resumes from its own history. The turn never ends on markup.
- **D-08:** Raw markup is **never saved in `messages.content`**. It goes to the backend log line
  and the LangSmith trace only.

### Markup before the last round (rounds 1-14)
- **D-09:** A text-form call in a non-final round is **run as a tool call** through the same
  dispatcher, known-tool check and grant checks as any call. Precedent: structured mode already
  executes calls parsed from text (`agent_loop.py:2765`). It replaces today's dead-end
  `DSML_LEAK_ERROR_MESSAGE` on the parseable path; an unparseable mid-run block is stripped and
  worded, never shown raw.
- **D-10:** The final-answer markup check is **provider-blind, at the save point, for every
  provider**. The bug happened because the guard was gated on one provider name. A clean answer
  passes through byte-identical (pinned by test).
- **D-11:** The live view **holds back** text that starts like a tool-call tag until it resolves
  as either a call (folded into tool events) or plain text (released). Reuse the Phase 273
  holdback (`backend/app/services/structured_text_holdback.py`). What streams live matches what's
  saved (I-2: live == reload).

### Typed "continue"
- **D-12:** Recognised **server-side on send**: `POST /threads/{id}/messages` checks
  (a) the thread's latest run is `cap_paused`, (b) Continues remain, and (c) the text is a continue
  word. If all three hold, it delegates to the existing continue function (`app/api/runs.py`
  `continue_run` path). ⛔ It must NOT add a second writer of `runs.status`; the rejected arm and
  its reason are recorded at `backend/app/api/threads.py:2199-2203` and stay binding.
- **D-13:** Continue words are a **short fixed list**, exact match after trimming case, whitespace
  and trailing punctuation: `continue`, `keep going`, `go on`, `carry on`, `resume`, `proceed`.
  Anything else is a new request. No model call decides intent.
- **D-14:** A typed "continue" that resumes behaves **exactly like the button**: no user message
  is saved, the composer clears, and the card shows "Continuing…". Resumed history stays
  byte-identical to a button press (Anthropic's strict tool_use/tool_result pairing).
- **D-15:** Any other text while paused **starts a new run, as today**. The paused run stays
  resumable by id (Phase 244 behaviour, `test_244_cap_paused_lock_bound.py`). No change.
- **D-16:** When Continues are exhausted (`continues_used >= max_continues_per_run`), a typed
  "continue" is an ordinary new message (falls through D-12's gate).

### Forcing a low cap for UAT
- **D-17:** The two round caps become **operator settings** in `app_settings` with a Control Room
  control (standing rule: knobs in the UI, env only for secrets/infra). Defaults stay
  **15 (general chat)** and **8 (explorer)** (`agent_loop.py:1524-1528`), pinned by test.
- **D-18:** **Two separate knobs**, each bounded (target 2-50; planner may adjust with reason).
  Read once per run at loop start. Not per-user.
- **D-19:** UAT sets the general cap to a low value **locally**, runs the board, then restores
  the default. If the knob needs a seed row, that is a seed-bearing migration: it follows the
  migration discipline (SQL editor, `regenerate-full-schema.sh`) and the deployment-artifact
  same-commit rule (`docs/OPERATOR.md` Step-3 seed list, `scripts/check-deploy-drift.sh`).

### Guardrails that bind this phase
- **D-20:** **G-5 FIRES on `backend/app/services/agent_loop.py`** (`72 / 34 / 3699`). Honour it by
  construction: the parser and sanitiser live in a **new module** (for example
  `backend/app/services/text_tool_calls.py`), and `agent_loop.py` gains call sites only.
  `threads.py` (also FIRING) gains the D-12 gate as one small delegating branch. Read both files'
  sections in `docs/HOT-FILE-LEDGER.md` before planning, and update their ledger rows in the same
  commit.
- **D-21:** **G-8:** target **3 plans** (backend parser + cap/sanitiser wiring; typed-continue +
  knobs + Control Room control; cross-provider board + G-4). Above 5 needs a written reason.
- **D-22:** **SC#10 board:** full native roster + OpenRouter (8 rows), derived from
  `MODEL_CAPABILITIES`, driven per-request with the low cap. A DeepSeek row through OpenRouter AND
  a native DeepSeek row are both mandatory (each hit a different cause, D-01/D-02). Blocked rows
  are recorded as ⛔ with a reason, never dropped.
- **D-23:** **G-4 lived UAT** (user-visible): Chrome drives (1) cap hit with a structured call →
  limit line + Continue → resumes the same run; (2) cap hit with a text-form call → same, and no
  markup on screen live or after reload; (3) typed "continue" resumes the paused run and
  `continues_used` increments.
- **D-24:** Planted-markup tests: a markup-only final turn and a markup-with-preamble final turn,
  each in DSML (both spellings) and XML, are caught and worded (SC#2). TDD RED first.

### Claude's Discretion

- Knob key names and the Control Room placement inside the existing settings surface.
