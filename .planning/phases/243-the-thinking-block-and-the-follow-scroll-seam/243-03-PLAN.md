<objective>
Stop the message list repainting once per token, and stop it dragging a reader who scrolled up back
down — in one plan, because they are one mechanism.

Purpose: `MessageList.tsx:141-176` is a single effect with `messages` in its dep array. Every
`setMessages` re-runs it; while streaming it takes the token-cadence branch and fires a smooth
`scrollIntoView` at `:171`. So the repaint cadence (CHAT-02) and the scroll behaviour (CHAT-03) are
**the same line of code**, which is exactly why `D-v4.1-02` forbids splitting them: fix one alone
and the other re-breaks.

`BUG-260823-01` names its cause precisely — a programmatic-scroll flag cleared on the next
animation frame — and **that code no longer exists**. Phase 228 replaced it with a 900 ms settle, a
second uncancellable clock gating the re-arm, gesture classification with synchronous release, and
a ref read for the pin. D-243-05 therefore makes the FIRST task a RED drive against HEAD, and names
*"nothing reproduces → CHAT-03 closes as already-fixed-by-228"* a **legitimate planned outcome**.

Output: a coalesced delta path that drops no token, a scroll fence that can actually see the
effect, and an honest verdict on CHAT-03 — fix or closure, with the bug report updated either way.

⛔ **No streaming-architecture rewrite** (D-243-08). These are surgical changes on named lines:
`StreamsProvider.tsx:412-428`, `MessageList.tsx:141-176`, `useFollowScroll.ts:196-201`.
