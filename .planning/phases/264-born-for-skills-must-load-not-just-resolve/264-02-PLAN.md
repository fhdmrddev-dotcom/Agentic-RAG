<objective>
Collapse the born-for rule back to ONE home (**D-264-01**). `app/utils/skill_visibility.py` gains an
optional keyword on both of its encodings; `expert_service.filter_visible_skill_names` stops hand-rolling a
third copy and delegates instead.

Purpose: Phase 263 added a fourth disjunct inside `expert_service.py` and argued, in a docstring,
that hoisting it would widen two consumers it had no business touching. That reasoning was correct
**for an unconditional arm**. An optional keyword cannot widen a caller that does not opt in — which
is provable by a literal `==` against the base predicate string, not by argument. So the reason is
refuted, the arm moves, and the docstring is retired deliberately with its reason rewritten
(D-264-02, the SEED-177 rule, precedent D-206-07).

⛔ This is a security change, not a refactor. The predicate it widens exists because of a real,
shipped cross-org leak (SEED-125), and the file it lives in has no RLS backstop — every read that
uses it runs on the BYPASSRLS service-role client.

Output: two widened encodings that agree, an `expert_service` that delegates, three frozen base
literals, one parametrized fixture table, and a measured count of `1`.
</objective>
