**Helper constants and functions:**
```python
USER_ID = "00000000-0000-0000-0000-000000000001"
FOLDER_ID = str(uuid4())
NOW = datetime.now(timezone.utc).isoformat()

def _folder_row(folder_id=None, name="Reports", parent_id=None, is_global=False):
    return {
        "id": folder_id or FOLDER_ID,
        "user_id": USER_ID,
        "name": name,
        "parent_id": parent_id,
        "is_global": is_global,
        "created_at": NOW,
        "updated_at": NOW,
    }
```

**Key testing patterns from conftest:**

For single-query endpoints (list, delete): set `mock_execute_result.data = [_folder_row()]` before the request.

For multi-query endpoints (create with parent validation, rename with update+select): use `mock_builder.execute.side_effect` with a list of MagicMock results, one per `.execute()` call in the endpoint.

Example for create with parent validation:
```python
parent_result = MagicMock(); parent_result.data = _folder_row(folder_id=str(parent_id))
insert_result = MagicMock(); insert_result.data = [_folder_row(parent_id=str(parent_id))]
mock_builder.execute.side_effect = [parent_result, insert_result]
```

Example for create root folder (no parent validation, single query):
```python
mock_execute_result.data = [_folder_row()]
# No side_effect needed — single .execute() call
```

**Test class structure:** Use `class TestCreateFolder`, `class TestListFolders`, `class TestRenameFolder`, `class TestDeleteFolder` groupings.

**Verify mock calls:** After each request, assert `_supabase.table.call_args_list` includes `call("folders")`. For create, verify `.insert()` was called with the expected dict. For rename, verify `.update()` was called with `{"name": "New Name"}`. For delete, verify `.delete()` was called.

Import `_supabase` from conftest to check call args: `from tests.conftest import _supabase`

**Note on the `or_` method:** The conftest builder mock does not have `.or_()` chained by default. The mock uses MagicMock which auto-creates attributes, so `.or_()` will return a new MagicMock. If `.or_().execute()` is needed, the side_effect approach should still work since the builder mock auto-chains. But if tests fail because `.or_()` breaks the chain, add `_builder.or_.return_value = _builder` in conftest's `reset_mocks` — but try without first since MagicMock auto-chains.
