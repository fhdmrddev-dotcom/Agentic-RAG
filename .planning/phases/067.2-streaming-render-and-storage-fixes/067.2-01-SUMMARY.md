# Phase 067.2 Plan 01: Streaming Render Race Fixes Summary

**useLayoutEffect-promoted setViewingThread call + synchronous handleSend ref-alignment closes both the empty-render-until-end-of-run race (D-067.2-01) and the blank-state-on-F5/navigation race (D-067.2-02) without altering useMessages.ts semantics.**

## Accomplishments

- Closed D-067.2-01: new-thread `handleSend` flow now sets `activeThreadIdRef.current = activeThread.id` synchronously before `sendMessage(...)` runs. The first `onDelta` callback after `streamingThreadIdRef.current = threadId` now passes `guardedSetMessages` at `useMessages.ts:623-628` (`streamingThreadIdRef === activeThreadIdRef`) instead of being silently dropped.
- Closed D-067.2-02: thread-id `useEffect` is split into a `useLayoutEffect` (synchronous `setViewingThread` ref-write) and a regular `useEffect` (clearMessages + loadMessages + justCreated guard). The `useLayoutEffect` runs after React commits DOM mutations but BEFORE any sibling `useEffect` for the same render — guaranteeing `activeThreadIdRef.current === thread.id` when the reconcile-trigger `useEffect` at `:163-188` invokes `reconcileRef.current(tid)`. Replay-from-offset-0 events on F5 / mid-stream navigation now land in state instead of being no-op'd at `useMessages.ts:866-871`.
- Preserved every existing behavior: `clearMessages` on null thread, `justCreatedThreadRef` skip-clear-on-just-created, `clearMessages + loadMessages` on legitimate thread switch, and (load-bearing) the deliberate omission of `abortStream()` per D-063.1-07 / Gap-003.
