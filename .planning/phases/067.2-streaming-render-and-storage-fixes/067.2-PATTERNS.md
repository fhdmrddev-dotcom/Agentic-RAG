**Auth + ownership pattern (mirror of `runs.py:331-352`):**
```python
@router.get("/{storage_path:path}")
async def get_sandbox_output(
    storage_path: str,
    current_user: dict = Depends(get_current_user),
    supabase: Client = Depends(get_supabase),
):
    # Step 1: ownership check via path-segment match.
    # storage_path layout (sandbox_service.py:103): "{user_id}/{execution_id}/{filename}"
    # First path segment MUST equal current_user["id"]. Rejecting on mismatch
    # closes cross-user IDOR (T-062-01 analog) without leaking existence.
    parts = storage_path.split("/", 2)
    if len(parts) < 3 or parts[0] != current_user["id"]:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="File not found")

    # Step 2 (defense in depth): verify a sandbox_files row exists for this
    # storage_path AND user_id. Mirrors the .eq("user_id", current_user["id"])
    # filter pattern from documents.py / skills.py / threads.py:521-527.
    file_resp = await aexec(
        supabase.table("sandbox_files")
        .select("id")
        .eq("storage_path", storage_path)
        .eq("user_id", current_user["id"])
        .maybe_single()
    )
    row = file_resp.data if file_resp is not None else None
    if not row:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="File not found")

    # Step 3: short-TTL re-sign. 60s is enough for the 302 → CDN fetch hop.
    # Per D-v2.5-01: supabase-py is sync; wrap in run_in_threadpool — but
    # create_signed_url is a thin HTTP call to Supabase, fast enough that the
    # existing harvest_output_files at sandbox_service.py:136 doesn't wrap
    # either. Match that convention; revisit if profiling shows blocking.
    from starlette.concurrency import run_in_threadpool
    signed = await run_in_threadpool(
        supabase.storage.from_("sandbox-outputs").create_signed_url,
        storage_path,
        60,
    )
    if isinstance(signed, dict):
        url = signed.get("signedURL") or signed.get("signedUrl") or signed.get("signed_url")
    else:
        url = getattr(signed, "signedURL", None) or getattr(signed, "signedUrl", None)
    if not url:
        raise HTTPException(status_code=status.HTTP_500_INTERNAL_SERVER_ERROR, detail="Failed to sign URL")

    # Step 4: 302 redirect to the signed Supabase Storage URL. Browser follows
    # the redirect and downloads from Supabase CDN directly (no proxy bytes
    # through FastAPI — keeps the backend stateless and bandwidth-light).
    return RedirectResponse(url=url, status_code=302)
```

**Why redirect instead of proxy bytes (CONTEXT § Claude's Discretion):** redirect keeps the FastAPI worker free during large-file downloads (a 50MB CSV proxied through `StreamingResponse` would block one of the 40 default threadpool workers for the duration of the download, hostile under load). Supabase signed URLs are safe to expose to the client because (a) they're scoped to the file path, (b) they're short-TTL (60s), and (c) the browser never sees them in DOM persistence — only as a transient `Location:` header. Use HTTP 302 (not 307) — the request is idempotent GET, no method-preservation requirement.

**Path-converter syntax `{storage_path:path}`:** matches arbitrary path segments including `/`, so `GET /api/sandbox-outputs/{user_id}/{execution_id}/{filename}.png` routes correctly. This is FastAPI / Starlette stock; no precedent in this codebase but no per-project gotchas.

**Pydantic response model:** none. `RedirectResponse` doesn't have a payload schema. Skip `response_model=`.

async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
    supabase: Client = Depends(get_supabase),
) -> dict:
    token = credentials.credentials
    try:
        response = supabase.auth.get_user(token)

            raise HTTPException(status_code=status.HTTP_401_UNAUTHORIZED, detail="Invalid token")
