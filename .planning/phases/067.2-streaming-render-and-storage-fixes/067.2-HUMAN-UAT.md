## New findings discovered during UAT (out-of-scope for Phase 067.2 contract, escalate to follow-on)

### N-01 — Model→provider router uses `user_settings.active_provider`, ignoring `MODEL_CAPABILITIES[model]["provider"]`
- **Where:** `backend/app/api/threads.py:949` — `_resolved_provider = _user_settings.active_provider`.
- **Repro:** With `user_settings.active_provider="openai"`, POST `/threads/{id}/messages` `{"model":"claude-sonnet-4-6"}` (no `provider` field) → backend keeps `provider="openai"`, calls OpenAI SDK with an Anthropic model id → 404 `model_not_found` from OpenAI. Evidence: run `6eab949f-78da-4ea4-ac01-f04b16c9be7d` (provider=openai, error=NotFoundError).
- **Workaround:** caller passes `body.provider="anthropic"` explicitly (the threads.py POST handler has an `override_provider` path at :945 that respects this). Plan 05's executor used this; my UAT driver was updated to match.
- **Fix shape:** at line 949, prefer `MODEL_CAPABILITIES[model]["provider"]` over `user_settings.active_provider`, falling back to `user_settings` only when the model isn't in the capability registry. ~5-line fix.
- **Severity:** HIGH — silent incorrect routing leaves the user stuck on whatever provider they last selected. Affects multi-provider scenarios broadly, not just this UAT.

### N-02 — Multi-step pipeline self-QA iteration count is high (8 of 14 tool_calls)
- **Where:** SYSTEM_PROMPT `## Multi-step intent` section (Phase 067.1 Plan 03).
- **Observation:** opus run `d6ac7f2e` did 14 tool_calls → 4 setup + **2 build + 8 self-QA** (markitdown content extract, install libreoffice, render slides, contact sheet, individual slide QA, final verification). Total wall-clock 9.25 min.
- **Not a defect:** the agent is following its instruction set correctly. Question is whether the UX/cost is acceptable.
- **Possible mitigations:** SYSTEM_PROMPT cap ("verify in at most 2 short iterations"), or a `MAX_SELF_QA_ITERATIONS` config. Defer to a UX/cost-tuning phase.
