## Side observation — suggestions emit gating

PATTERNS.md § 3 step 4 flags that the suggestions emit at `threads.py:2477`
lives in the **post-`done`-event block** (the `done` _emit fires at line 2464).
Confirmed by reading the file: the suggestion-generation `try/except`
(lines 2467-2479) runs synchronously after the `done` event but before
`stream_end` (line 2482). Therefore:

- **Successful run** → both `done` AND `suggestions` emit → frontend receives
  both. ✅
- **Failed / cancelled / timed_out run** → terminal sentinel fires from the
  producer's finally block (D-061-* contract); the success-path block at
  2467-2479 is skipped → no `suggestions` event arrives. This is **expected
  behavior** under the current code. If the user reports "no suggestions on
  a failed run", that is by design, NOT a bug. The investigation should
  distinguish.

The `confidence` emit at line 2437 fires BEFORE `done` and BEFORE
`_persist_assistant_message`, so it lands on every successful run regardless
of when the run terminates within the success path. Failed/cancelled runs
that never reach the citations/confidence block will not get a confidence
event either.

## Predicted verdict (pre-runtime, static-audit only)

**Predicted: (a) no-op closure** — the full render path is intact end-to-end,
the upstream race is closed, and CONTEXT.md's hypothesis is mechanically
sound (both `onConfidence` and `onSuggestions` callbacks route through
`guardedSetMessages` via `makeStreamCallbacks` at line 634 / line 879, so the
pre-Plan-01 no-op window WAS the silent-drop site).

**Caveats / non-no-op outcomes worth checking in Task 2:**

1. **Suggestions on failed runs** — if the user tests a synthetic-timeout or
   error-path run, suggestions will be missing by design (emit lives in the
   post-`done` success block). Distinguish "failed-run no suggestions"
   (expected) from "successful-run no suggestions" (gap).
2. **Suggestion-service availability** — `generate_suggestions` at
   `app/services/suggestion_service.py` makes an LLM call; if it fails or
   returns `[]`, the emit at line 2477 is gated by `if questions:` and won't
   fire. State will not be populated, but this is a backend / service-layer
   gap, not the render-path gap Plan 04 scopes. Would be Verdict (c).
3. **`onSendMessage` prop chain** — if `MessageList` or `ChatArea` doesn't
   thread `onSendMessage` through to `MessageItem` for some message states,
   suggestions would populate state but pills wouldn't render. Verdict (b)
   suggestions case. Confirm via DOM inspection.
4. **Race with `!isStreaming` gate on suggestions** — the SuggestionPills
   block requires `!isStreaming`. If the suggestions event fires BEFORE the
   terminal event sets `runStatus`, the rendering hook may still be in a
   "streaming" state when suggestions populate; pills will render once
   `isStreaming` flips false (immediately after `stream_end`). This is the
   intended UX, not a gap.
