# Phase 293 — UI Design Contract

> Visual and interaction contract for the API keys surfaces (START-02), the run origin line and
> the card's next-run time (START-04). REG-06 has no UI. Generated by gsd-ui-researcher; the
> checker validates it.

**What is locked and what this file decides.** The API keys tab's layout, states and copy are the
approved sketch (variant C). This file transcribes them, and only normalises pixel values to the
4px grid (listed in §Sketch-to-build normalisations). The origin line, the next-run text, the rate
limit control, the admin tab placement, the ⋯ menu item and every state the sketch did not draw
(loading, failures, no published workflows) are decided here, because D-21 sent them to UI-SPEC
rather than to the sketch.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | icon-to-text gap inside chips and tags, chip margins, gap between call-strip bars |
| sm | 8px | gap between buttons in an action row, meta-line gaps on a key card, gap inside the secret box |
| md | 16px | key card padding (all sides), form row label column gap, show-once block padding |
| lg | 24px | SectionCard header/body padding (shipped `CardHeader`/`CardContent` `p-6`), sheet padding |
| xl | 32px | empty state vertical padding |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions:
- **12px** (`gap-3`) between stacked key cards and between form rows. It is the app's shipped card-stack gap (Settings, org tabs) and a multiple of 4.
- **Call-strip bars:** visual bar 8px wide, 4px apart, 16px tall (start, refused) or 12px tall (read). Each bar sits inside a 12px wide × 24px tall `<button>` hit area so the strip is usable by touch.
- **Form label column:** 128px fixed on ≥768px (sketch 130px), stacked above the field below 768px.
- **Workflow picker list:** max-height 208px, scrolls inside its border (sketch 210px).

Accent (`--primary`) is reserved for exactly these elements:
1. Filled primary buttons: "New key", "Create key", "I've saved the secret".
2. The selected segment of the Expires control.
3. The draft card's border and 1px ring.
4. The 3px left rule of the "Runs as you" note.
5. The "From the ⋯ menu of {workflow}" hint.
6. Start bars in the call strip and the `start` verb pill.
7. Text links: run links in activity, "Show activity" / "Hide activity", "All in the audit log →", "Guide: start a workflow from outside ↗".
8. Focus rings (`--ring`), unchanged.
9. The workflow card's automation line, which is already `text-primary`; the next-run fragment inherits it (no new accent use).

The origin line is never accent coloured: it is a muted fact (`text-muted-foreground`), the same
register as the run's elapsed time.

Colour is never the only signal: every state tag carries a word, every activity result carries
"✓" or "✕ refused:", and call-strip bars differ in height (read bars are shorter) as well as hue,
with the caption legend and the tap detail spelling each call out.

## Surface 1: Settings → API keys tab (sketch C, member view)

Tab: id `"7"`, audience `everyone`, label **API keys**, last in the strip after Audit Log. It is
reached by the strip, or by the ⋯ menu item (Surface 3), which writes `settings_active_tab = "7"`
plus the pre-pick and then navigates to `settings`.

### Layout (top to bottom)

1. **Header card** (shipped `SectionCard` look: `ghost-border bg-card/60`). Left: title
   "API keys" with `KeyRound`, and the description below it. Right: the **New key** button, shown
   only when there is at least one key and no draft or show-once card is open. Under the
   description, when at least one key exists: the limits line (12px, muted).
2. **Card stack** (`grid gap-3`), in this order: the draft card (if creating) or the show-once
   card (if just created), then key cards. Order of key cards: active and refused-for-some first,
   most recently used first, never-used after them by creation date; then expired; then revoked.
   Expired and revoked keys stay listed (dimmed); there is no delete control in this phase.

### Key card anatomy (`ApiKeyCard`)

`rounded-[14px] border bg-card p-4`.
- **Top row** (`flex items-center gap-2 flex-wrap`): `KeyRound` 16px · label (16px/600) · state
  tag · key prefix `srl_live_8Hq2…` (mono 12px, dim) · spacer · right: **Revoke** (ghost danger,
  small) for an active key, or the revoke receipt for a revoked key, or nothing for an expired key.
- **Workflow chips** (12px, `rounded-md bg-muted/40 border`): one per workflow on the key. A
  workflow that is no longer published, or was deleted, is a dashed amber chip.
- **Refusal line** (12px, amber), only when a chip is dashed.
- **Meta line** (12px, dim, facts in 600): `expires {date} ({relative})` · `last used {when}` ·
  `created {date}`. The admin view prepends `owner {name}`, with ` (you)` on the admin's own keys.
- **Call strip** (active keys, or any key with calls): up to the last 20 calls, oldest left,
  newest right; caption under it; tapping a bar opens the one-line detail under the caption.
- **Show activity / Hide activity** link (only when the key has calls), which expands the activity
  table inside the card.

Dead keys (expired, revoked) render at 62% opacity. A key that was just created gets a green
border for 1.6s after "I've saved the secret", then the normal border.

### State tags

| Key state (server truth) | Tag | Style |
|---|---|---|
| active, every workflow still startable | `● active` | green |
| active, N workflows no longer startable | `⚠ 1 workflow refused` / `⚠ N workflows refused` | amber |
| expired | `expired` | dashed border, dim |
| revoked | `revoked` | dashed border, dim |
| draft (not created yet) | `draft · not created` | neutral border |
| just created | `● created` | green |

### Draft card (`ApiKeyDraftCard`)

Border `--primary` with a 1px `--primary/15` ring. Top row: `KeyRound` · the label as typed, or
"New key" in dim text while empty · tag `draft · not created`. Form rows (label column 128px):

| Row | Control | Rules |
|---|---|---|
| Label | text input, 32px tall, placeholder "e.g. n8n-prod" | required; trimmed; 1-60 characters; unique among the caller's active keys (server refusal shown inline if not) |
| Workflows | bordered checklist, max-height 208px, scrolls | lists only the caller's runnable **published** workflows; each row: checkbox · name · its declared launch field keys on the right (mono 12px) or "no inputs". A workflow whose launch form needs a file is a disabled row with its reason on the right. At least one must be picked |
| Expires | segmented control: 30 days · 90 days · 365 days · Never | default **90 days** (D-04) |

Below the rows: the **Runs as you** note (left 3px primary rule, `bg-muted/40`), then actions:
**Create key** (primary, disabled until label and one workflow are present), **Cancel** (ghost),
and the reason the button is disabled, in 12px dim text beside it.

Opened from a workflow's ⋯ menu: that workflow is already ticked, the "From the ⋯ menu of …"
hint sits above the first row, and focus goes to the Label input. Opened from **New key**: nothing
is ticked and focus goes to the Label input. Esc inside the draft card does nothing destructive;
only Cancel discards it.

### Show-once card (`ApiKeySecretOnce`)

Replaces the draft card in place (the draft becomes the key). Amber border (55%) and 4% amber
wash. Top row: `KeyRound` · label · `● created` · prefix. Workflow chips. Then:
1. The warning line (14px, amber).
2. The secret box: mono 14px on `--background`, `break-all`, with a **Copy** button.
3. Code header "Start {first workflow}" (plus "(the other N work the same way)" when the key has
   more than one) with **Copy**, then the start `curl` block. Its JSON `inputs` object lists the
   workflow's declared launch field keys in declared order, each with a placeholder value
   `"<field_key>"` (for example `"counterparty": "<counterparty>"`) that the caller replaces; a
   workflow with no inputs sends `{ "inputs": {} }`.
4. Code header "Read its status and result (poll until it finishes)" with **Copy**, then the status
   `curl` block, with `RUN_ID` as the placeholder.
5. A `<details>` "What a status read returns", closed by default, holding the sample response.
6. Actions: **I've saved the secret** (primary) and the guide link (opens
   `/docs/api/guides/start-a-workflow-from-outside` in a new tab, `rel="noopener"`).

The `curl` text uses the app's real API base URL (the same base the frontend calls), the real
secret, the real workflow id and the final endpoint paths; the sketch's `$SYREL_URL`, paths and
`srl_` prefix were placeholders (Claude's discretion at plan time). The secret exists only in
`ApiKeysTab` memory: dismissing the card, switching tab or reloading drops it, and it is never
written to storage, a URL, a log or the query cache. After **I've saved the secret** the card
becomes an ordinary key card at the top of the list.

### Activity (`ApiKeyActivity`, inside the card)

Header: "Recent calls · last used {when}" on the left; "All in the audit log →" on the right
(member: switches to the Audit Log tab, `"4"`; it may pre-filter if that tab supports it, else it
opens unfiltered). Rows, newest first, the last 30 days:

| Column | Content |
|---|---|
| Time | mono 12px dim: `10:42` today, `Yesterday 02:04`, `6 Oct 09:00` older |
| Verb | pill: `start` (primary tint) or `read` (muted) |
| Workflow | name, or `—` when the call named none; hidden below 768px |
| Run | `run 7f3a91` (first 6 characters of the run id, mono) as a link when `onOpenRun` is available; plain mono text otherwise; `no run` (dim) when the call made none |
| Result | `✓ {outcome}` in green, or `✕ refused: {reason}` in refusal red |

The call strip's tapped detail is the same row on one line:
`{time} · {verb} · {workflow} · {run} · {result}`.

### Revoke sheet (`RevokeApiKeySheet`)

shadcn `AlertDialog`, width 480px, 3px `--destructive` top border, `--destructive/45` border. Focus
starts on **Keep it**; Esc and the scrim close it. Content: title, one sub line, a three-item
fact list (bold facts), the "kept" box, then actions **Revoke {label}** (destructive filled) and
**Keep it** (ghost). While the request is in flight the destructive button reads "Revoking…" and
is disabled. On success: the sheet closes, the card turns revoked and shows the receipt line in
place of the button (re-fetch, not optimistic). On failure: the sheet stays open with a
`role="alert"` line and the key is shown as still working.

### Every state of the tab

| State | What renders |
|---|---|
| Loading | the header card with its description; in the stack, one muted line "Loading your keys…" (`role="status"`). No limits line, no New key button until the read answers |
| Load failed | the header card, then a `role="alert"` destructive-tinted line with the error copy and a **Retry** button |
| Empty | one card with the empty state: `KeyRound` 28px muted, the empty sentence, **New key** |
| No published workflows (draft open) | the checklist area shows the no-workflows sentence instead of rows; Create key stays disabled with "Pick at least one workflow." |
| Has keys | header card + limits line + key cards |
| Creating | draft card at the top of the stack; New key hidden |
| Create failed | the draft card stays, values kept; a `role="alert"` line under the actions with the server's sentence |
| Just created | show-once card at the top; New key hidden |
| Copy failed | the Copy button reads "Copy failed" for 2s and a 12px line under the block says to copy by hand |
| Revoke | the sheet over the tab |
| Revoked | dimmed card, `revoked` tag, receipt line |

## Surface 4: The origin line (four places, one component)

`RunOriginLine` renders one sentence from the run's recorded origin
`{ kind: "app" | "schedule" | "key", label: string | null, actor_name: string | null }`, as a
plain text child with the kind's icon (14px, `aria-hidden`) before it. `text-xs
text-muted-foreground`, never accent, never a link. `data-testid="run-origin"`,
`data-origin-kind={kind}`.

| Recorded origin | Sentence |
|---|---|
| app, actor name known | Started in the app by {actor_name} |
| app, no name | Started in the app |
| schedule, label recorded | Started by schedule {label} |
| schedule, no label (schedule since deleted, or a backfilled row without one) | Started by a schedule |
| key, label recorded | Started by key {label} |
| key, no label | Started by an API key |
| origin `null` or absent (every old run that was not backfilled) | **nothing**: no element, no separator, no placeholder |
| unknown `kind` value | **nothing** (fail silent, never guess "app") |

The label is the one recorded at start (the schedule's name, the key's label), so renaming or
revoking later never rewrites history. A key's label is not a secret and may show to an org
colleague on the evidence report.

| Place | Position | Live / finished |
|---|---|---|
| `WorkflowRunPage` header (live run) | status row, after `WaitingOnLine`, before the elapsed time | live and paused runs |
| `RunEvidenceReport` (finished run) | its own line directly under the "Completed in … · started … by …" sub line, above the end-reason line | finished runs; the JSON export carries the raw `origin` object, the printed report shows the sentence |
| `RunLogPanel` row | third line of the row's text column, under the detail line, 11px muted (host detail class) | every row with a recorded origin |
| Chat `RunCard` | under the model subline, `mt-0.5` | the run's assistant turn, when the message carries `run_origin` |

⛔ D-23: no surface may print "manual", "app" or any other default for a run whose origin was not
recorded.

## Surface 5: The card's next run time

The workflow card's existing automation line (`CalendarClock` + cadence words, `text-primary`,
12px) gains a fragment after the cadence and before `+N more`:

`runs every Monday · next Mon 27 Oct, 09:00`

- The cadence words are the shipped `AUTOMATION_CADENCE` / `AUTOMATION_RUNS_ITSELF` strings,
  unchanged (D-25's "Every Monday" is the shape; the card keeps its shipped wording so existing
  pins hold). A custom cron reads `runs on its own · next Mon 27 Oct, 09:00`.
- The instant is the server's `next_run_at` (the soonest active schedule, the same field
  `automationFacts` already receives). The browser only formats it, never computes it.
- Format: viewer's local time zone, `en-GB` parts: short weekday, day, short month, 24-hour
  `HH:mm`: `Mon 27 Oct, 09:00`. Add the year when it differs from the current year:
  `Mon 4 Jan 2027, 09:00`.
- If the server's instant is already in the past, the fragment reads `next was due Mon 27 Oct,
  09:00` (honest, never hidden, never recomputed).
- Separator: the shipped `ANSWER_SEPARATOR` in `text-border`, as the line already uses.
- Silent rows stay silent: no schedule, a paused schedule, or a feed that never sent the field
  renders no cadence and no next-run text (the three absences in `automationFacts.ts`).
- `title` attribute on the fragment: the full local date and time with year, for hover.

Last run stays as shipped ("Worked 4 days ago").

## Interaction and Accessibility

- **Keyboard:** New key → focus Label. Space toggles a workflow row; the Expires control is a
  `radiogroup` (arrow keys). Create key is reachable and announces its disabled reason
  (`aria-describedby` on the reason text). Copy buttons are real buttons with
  `aria-label="Copy the secret"` / `"Copy the start command"` / `"Copy the status command"`.
- **Call strip:** one tab stop (roving tabindex), Left/Right move between calls, Enter/Space opens
  the detail; each bar's accessible name is the full detail sentence. The activity table is the
  complete, non-visual alternative and is always one click away.
- **Announcements:** loading and "Revoking…" are `role="status"`; every failure line is
  `role="alert"`; "✓ Copied" is announced through a polite live region.
- **Revoke sheet:** `AlertDialog` focus trap, initial focus **Keep it**, Esc closes, focus returns
  to the card's Revoke button (or to the card's top row once it is revoked).
- **Contrast:** dim meta text uses `--muted-foreground` (AA on `--card`), never the global 3.6:1
  dim; refusal text uses the shipped `hsl(0 80% 80%)`.
- **Below 768px:** form rows stack (label above field), the activity Workflow column hides, the
  meta line wraps, the curl blocks scroll horizontally inside their box (never the page).
- **Motion:** only the fresh card's 1.6s border fade and the Copy state change; no shimmer, no
  pulse on this tab.

## How we'd know this UI failed (G-6, for the G-4 drive)

1. The secret is visible anywhere after "I've saved the secret": a re-render, the network panel of
   a later read, `localStorage`/`sessionStorage`, or the React Query cache.
2. The start `curl` copied from the show-once card, with only its placeholder values replaced,
   fails (wrong base URL, wrong path, wrong header, or field names that are not the workflow's
   declared launch keys).
3. A key with an unpublished workflow reads `● active` with no amber chip, tag or line.
4. A refused call in activity says only "refused" with no reason, or a 404 body differs by cause.
5. The admin's revoke sheet on Priya's key does not name Priya, or the band marker does not pulse.
6. An old, unbackfilled run shows any origin line at all, or a key run anywhere says "app" or
   "manual".
7. The four origin placements word the same run differently.
8. A scheduled workflow's card shows no next-run text, or shows a time that differs from the
   schedule modal's "Next:" for the same schedule.
9. The ⋯ menu item lands on the API keys tab without the workflow ticked, or lands on another tab.
10. A member sees the rate limit inputs, or the limits line shows numbers that are not the
    operator's saved values.
