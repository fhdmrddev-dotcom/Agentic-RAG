<objective>
Make the approval pause name the **service** and show the **arguments that will actually leave**.

Purpose: two facts, both measured rather than argued.

1. **`BUG-260828-01`, driven verbatim on both shapes at Phase 213's close.**
   `_external_action_clause` fills the service slot from `config.capability` — *the same value it
   puts in the tool slot* — so a capability row reads the tautology
   `It will run "post_message" through post_message.`, and an MCP row carries `capability = None` so
   the clause is omitted entirely. **The service a person needs — Slack — sits on the connection row
   and was never read.**

2. ⚠ **A defect this phase would otherwise CREATE.** Under D-214-01, `config.tool_args` holds only
   the FIXED values. Left alone, the pause would name the constants and **silently omit exactly the
   arguments that vary** — which on an approval surface is worse than showing nothing.

Output: one composer with two new parameters and its purity intact; one caller that resolves; one
suite that drives both shapes and the three-source case.
</objective>

<!-- The composer's new signature. Nothing else in grounding.py changes shape. -->

```
def _external_action_clause(phase, *, service_name: str | None = None,
                            resolved_args: Mapping[str, Any] | None = None) -> str
def _approval_sentence(phase, total_phases: int, *, service_name: str | None = None,
                       resolved_args: Mapping[str, Any] | None = None) -> str
```

Both keyword-only and both defaulting to `None`, so **every existing call site keeps its exact
current behaviour** — which is what lets the change be additive rather than a rewrite, and what keeps
the shipped character-identity assertions on the honesty rules passing unchanged.

Resolution order inside the clause, stated so it cannot drift:
- tool slot: `config.tool_name or config.capability` (unchanged).
- service slot: `service_name` **only**. ⛔ `config.capability` is no longer read for the service —
  that read IS the tautology.
- arguments: `resolved_args` when given, else `config.tool_args` (the pre-214 behaviour, preserved
  for any caller that has not been updated).
</interfaces>
