## Decisions Made
- **In-card resolvable deep-link (not a Studio navigation).** A smoke-sweep arm has `skill_id = NULL` and can never match the skill-scoped Studio readout, so the tile expands an inline detail within the card, fed by the skill-less `getEvalRunById` readout and rendered with the reused pure `RunCaseDetail` leaf (per the plan's checker-iteration-2 resolution — preserves the 060-A lock without a sketch amendment).
- **✗ only with a verbatim error.** Tile state is `healthy` (green ✓) / `failed` (red ✗ + verbatim error) / `unswept` (neutral) — a `!healthy && !error` tile is NEVER rendered red, honoring the "no engine-shaped errors, no ✗ without the error" honesty lock.
- **Judge registry source = the page's verified-models set.** Passed as a prop rather than re-fetched, keeping the picker a thin knob; writes go through `setJudgeModel` and the pair is re-read from the returned settings (server-derived, never an optimistic local truth).

## Known Limitations (transparent, not stubs)
- **Sweep-run detail prompt header.** The skill-less `getEvalRunById` readout returns `eval_run` + `eval_results` but NOT the built-in smoke fixture's `TestCase`. Because `RunCaseDetail` is a LOCKED pure leaf (must not fork), it is fed `testCase={null}` and shows its neutral prompt fallback ("this test case was removed"). The real diagnostic content — each arm's output, verdict, error, tokens, duration — IS wired and renders; an in-card `Smoke run · {provider} · {model} · {status}` header sets the context above it. This is an honest reuse limitation, not a data-hiding stub (the arm data is fully sourced from the server).
- **Sweep-arm ratings are inert.** `RunCaseDetail`'s thumbs render for completed arms, but a skill-less sweep has no skill-scoped rating endpoint, so `onRate` is a no-op in the tile detail (documented in the component).
