## Decisions Made
- **Optional matrix props on RunBar** — the launcher renders only when `onRunMatrix` is supplied, keeping the single-run contract byte-identical (its 6 existing tests pass untouched).
- **Server-truth card** — the grouped card renders from the durable list (`refreshRuns` right after kickoff, which returns running rows with server `matrix_group_id`/`feeds_gate`), so the "▣ feeds gate" chip is a label on a server flag, never a client-side gate recomputation (T-137.1-U1). No client-side row synthesis for matrix arms.
- **Separate `matrixLive` atom** — matrix per-arm progress lives in its own state keyed by run_id, leaving the lifted single-run `attach()`/`live` path (and its EvalsTab tests) completely untouched.
- **`MatrixCard` owns local collapse** — a resting-history anti-flood concern, defaulting open while any arm streams and collapsed at rest; extracted to a top-level component so its `useState` survives parent re-renders (avoids the nested-component remount trap).
