**A pure, unit-tested `eval_aggregation` module computing per-config mean±stddev/delta over accumulated eval-run history + deterministic fixed-phrasing analyst notes, exposed through an owner-scoped `GET /skills/{id}/evals/aggregate` endpoint that delegates all math and renders the shipped `EvalAggregate` wire shape verbatim.**

## Accomplishments
- **Deterministic per-config aggregation** (`aggregate_configs`): groups run history by `(provider, model)`; the mean/spread/delta count ONLY with-skill `graded` arms (inherits the shipped rollup denominator); the spread sample is a RUN, so `with_stddev` is `None` until a config has ≥2 runs (D-07 — never presents one click as if it bought N repeats).
- **Fixed-phrasing analyst notes** (`analyst_notes`): three deterministic D-08 rules — `non_discriminating` (the skill flips no case outcome), `flaky_variance` (`stddev ≥ FLAKY_STDDEV_THRESHOLD`), `time_score_tradeoff` (markedly slower than the fastest arm without a higher lift) — each a stable-tagged plain-language line, NEVER an LLM paragraph.
- **Owner-scoped aggregate endpoint**: owner-gate FIRST (404-never-403), reads only the caller's COMPLETED history (`.eq user_id`), one bounded `.in_` results read, then delegates entirely to the pure module (no inline stats in `evals.py`).
- **10 tests authored**: 7 pure-function tests (verified GREEN via direct execution with system Python) + 3 endpoint tests (route data-flow simulated against the same fake; full app-env run deferred to the post-merge gate).

## Decisions Made

Two shape-reconciliation decisions bridge the plan's internal function description and the **already-shipped** Plan-01 wire contract (`EvalConfigAgg.analyst_notes: string[]`, per-config — committed on base at `frontend/src/types/index.ts`):

1. **Per-config note attribution.** The plan's `analyst_notes(configs, cases)` is described as returning `{tag, message}` notes; the shipped wire puts `analyst_notes` as a per-config `string[]` (no group-level notes field). Each of the three D-08 rules is therefore attributed to its exact `(provider, model)` config so it maps cleanly onto the per-config array with no homeless/duplicated notes. The `non_discriminating` rule (interface phrasing: "all configs pass both arms on a case") is applied per-config as "with-skill and without-skill reach the same verdict on every graded case here" — the honest local reading of "skill adds nothing measurable", pairing arms within each run so a flipped case is correctly detected as discriminating. `cases` is used exactly for this pairing.
2. **`to_wire` + first-run marker.** Added a third pure function `to_wire(configs, notes)` so the route performs ZERO logic (pure delegation). Because the wire `with_stddev` is `number | null` with no dedicated marker field, the honest "first run — no spread yet" line (`FIRST_RUN_MARKER`, a module constant — server-authored per OQ4) is surfaced in a first-run config's `analyst_notes` while `with_stddev` stays `null` (never a fabricated 0.0).

These are design reconciliations within plan intent, not auto-fixes.
