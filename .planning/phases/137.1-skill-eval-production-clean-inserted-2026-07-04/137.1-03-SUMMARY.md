# Phase 137.1 Plan 03: Boot-Time Orphan Run Reconciler Summary

**A CAS-guarded FastAPI-lifespan boot sweep that honestly terminalizes restart-orphaned runs (eval->interrupted, chat->failed) and drops their stale Redis streams — the writer half of BUG-260702-02, mirroring `resume_stranded_workflows`.**

- **Duration:** ~40 min
- **Started:** 2026-07-04T10:55Z (approx, plan load)
- **Completed:** 2026-07-04T11:35Z
- **Tasks:** 2 (Task 1 TDD: RED + GREEN)

## Accomplishments
- New standalone `run_reconciler.py` exporting `reconcile_orphaned_runs(*, pool, redis, supabase) -> int` — a near-copy of the shipped `resume_stranded_workflows` sweep, but WRITES terminal statuses instead of re-driving.
- Closes the BUG-260702-02 restart-orphan gap (EVAL-05g): a non-terminal `eval_runs` row absent from `runs:active` flips to `interrupted`; a non-terminal companion `runs` row flips to `failed` via `finalize_run`; the stale `run:{id}` stream is dropped in both cases.
- Single-shot Redis `SET NX` guard (`run_reconcile_lock`) so `WORKER_COUNT=2` never double-sweeps; the racing sibling returns 0.
- Mounted in the lifespan as a best-effort `asyncio.create_task(_reconcile_orphans())` alongside `_resume_stranded`, after the pg pool + Redis are up — startup is never blocked.
- 4 unit tests covering: eval->interrupted, chat->failed, live-run-in-`runs:active`-skipped, and SET-NX-guard-held->returns-0.

## Files Created/Modified
- `backend/app/services/run_reconciler.py` - NEW. `reconcile_orphaned_runs` boot sweep: SET NX guard -> eval_runs `running` orphans -> `interrupted` (service-role UPDATE, `run_in_threadpool`, CAS `.eq('status','running')`) -> companion `runs` `streaming`/`cap_paused` orphans -> `finalize_run(status='failed')` -> drop `run:{id}` stream. `_is_orphan` cross-checks `runs:active`. `__all__ = ["reconcile_orphaned_runs"]`.

## Decisions Made
- **Lock TTL = 300s**: comfortably covers the multi-worker boot skew + sweep duration, then self-expires so the next restart re-runs the sweep. The reconcile task fires once per worker per boot; the guard only dedupes the near-simultaneous boot race.
- **eval UPDATE is a CAS** (`.eq('status','running')`): a row that legitimately raced to a real terminal status in the reconcile window is left untouched.
- **The eval companion `runs` row is terminalized to `failed` by the chat sweep** (the `runs` status CHECK has no `interrupted`), while the user-facing `eval_runs` row shows `interrupted` — this exactly reproduces the 2026-07-02 manual cleanup (eval->interrupted, chat->failed) and terminalizes the transport row so it never strands `streaming`.
- **`requirements-completed` left empty**: EVAL-05 is a phase-spanning requirement (137.1 has multiple plans); this plan closes only the EVAL-05g reconciler slice. The full requirement is marked complete at phase verification, not from this single plan.
