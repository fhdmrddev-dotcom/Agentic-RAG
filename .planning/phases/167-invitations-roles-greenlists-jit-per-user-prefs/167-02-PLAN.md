<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /org/invitations | Untrusted email/role/X-Org-Id; org:invite + RLS WITH CHECK are the wall; org_id is server-pinned |
| invitee → /org/invitations/accept | Any authed user; the token is the only authorization; the org/role come from the invite row, never the client |
| app → audit_log | For a 2+-org caller the mig-106 autofill (no ORDER BY) picks an arbitrary org; invitation rows must carry an explicit org_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-167-06 | Elevation | send/resend/revoke without org:invite | mitigate | require_org_invite (org:invite) + the mig-104 org_invitations RLS WITH CHECK on the user-JWT connection (default-deny 403; RLS backstop). |
| T-167-07 | Elevation | role escalation via the invite role | mitigate | Server validates role ∈ {member, org-admin}; dept-admin greyed, super-admin refused (mig 104 CHECK + app allowlist). |
| T-167-01 | Information Disclosure | token leak via API response | mitigate | No endpoint selects or returns token_hash; the raw token is only in the send `link`. Test-locked (Task 3). |
| T-167-08 | Elevation | cross-org invite (wrong org_id) | mitigate | org_id = request.state.active_org (server-validated X-Org-Id); the org_invitations_insert WITH CHECK pins org_id ∈ current_user_org_ids. |
| T-167-03 | Tampering | double-accept / expired replay | mitigate | accept goes through the Plan-01 advisory-lock + ON CONFLICT + expiry-gate; integration test proves single-membership convergence. |
| T-167-09 | Spoofing | accept without proof of invite | mitigate | accept requires a valid pending non-expired token_hash match (verify_token); email-match alone never joins (no trigger fork — Pitfall 1). |
| T-167-23 | Repudiation | invitation audit row misattributed to the wrong org | mitigate | write_audit_entry takes an explicit org_id; send/resend/revoke pass active_org and accept passes the invitation's org_id — never the ORDER-BY-less mig-106 autofill guess (correct-org accountability for a 2+-org caller). |
| T-167-SC | Tampering | npm/pip installs | accept | No new packages in this plan (resend is Plan 01, opt-in). No install task. |
