<objective>
Wire the two encryption seams into the settings substrate: encrypt-on-write in `save_app_settings` (the ONE write seam) and decrypt-on-read in `_build_settings_from_row` (the ONE read seam both sync + async loads funnel through). Decrypting onto a COPY keeps the 30s per-worker cache holding ciphertext (defense-in-depth) and makes an undecryptable column auto-fall-back to env via the EXISTING `_val` DB>env chain — D-150-04/05 fail-soft for free, zero new fallback code. Prove SC#1 with a raw-read integration test.

Purpose: SC#1 (encrypted at rest) + SC#3 (env-fallback preserved) + the fail-soft half of D-150-04/05, all landing at exactly two functions no caller bypasses. No consumer changes — `_build_providers`, `_resolve_llm`, embedding/rerank/tavily reads all get plaintext transparently.
Output: encrypt/decrypt seams in `user_settings.py`, their unit tests (save_seam, read_seam), and the SC#1 ciphertext-at-rest integration proof.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB row → settings consumers | The read seam is the last point before plaintext reaches _build_providers/_resolve_llm; ciphertext must never pass. |
| write seam → DB | Plaintext validated by the sentinel guard, then encrypted before the UPDATE crosses into storage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-01 | Information Disclosure | app_settings at rest | mitigate | Encrypt secret columns with enc:v1: on write (Task 1); Task 3 proves ciphertext-at-rest via raw read. |
| T-150-03 | Information Disclosure | ciphertext leaking to consumers | mitigate | Single decrypt seam at `_build_settings_from_row` top; decrypt on a copy so no consumer path sees ciphertext (Task 2). |
| T-150-04 | Denial of Service | decrypt failure on request path | mitigate | Undecryptable column → None → existing _val env fallback; never fail closed (D-150-05). test_failsoft_to_env locks it. |
| T-150-08 | Tampering | tampered ciphertext in DB | mitigate | Fernet is authenticated (HMAC) → InvalidToken on tamper → fail-soft to env, not silent acceptance. |
| T-150-02 | Information Disclosure | seam logging | mitigate | Decrypt-failure logs name the COLUMN only; grep confirms no value/token interpolation. |
| T-150-01b | Information Disclosure | 30s settings cache | mitigate | Decrypt on a COPY; `_load_settings_from_db` cache keeps ciphertext (defense-in-depth) — no plaintext lingers in the cross-request cache. |
</threat_model>
