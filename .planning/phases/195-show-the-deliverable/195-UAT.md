## ⚠ THE DEFECT THIS UAT FOUND — a visual regression that EVERY unit test passed

**This is the strongest G-4 evidence this project has produced, and it is recorded as a first-class
finding rather than a footnote inside U1.**

### What was measured

| Surface | `195-BASELINE.md` PRE-change | Post-conversion, measured in the browser | Δ |
|---|---|---|---|
| Run page row (`data-testid="run-deliverables"` `<button>`) | **33 px** | **40 px** | **+7** |
| Panel row (`FilesSection`, `div[role=option]`) | **38 px** | **42 px** | **+4** |

**Every shared row grew.** Both surfaces, one cause.

### The cause, located rather than guessed

`frontend/src/components/files/FileRow.tsx:223` — the icon wrapper `<span>` was a **block box**
inheriting the row's `line-height: 24px`, so a **16 px glyph sat in a 24 px line box**. Measured
directly in the browser: the wrapper's own computed height read **24** on both surfaces while the glyph
read **16**.

**Before the conversion, each surface rendered the glyph as a DIRECT child at `h-4 w-4`** — there was no
wrapper to inherit leading from. The wrapper is new; the defect arrived with it.

### ⚠ It breaks 195-03's own `must_have`

195-03's headline claim is that the three surfaces adopt the shared row *"**without any of them changing
visually**."* **They changed visually.** By 7 px and 4 px, on every row, on both live surfaces.

### ⚠ THE G-4 LESSON, REDUCED TO A SINGLE MEASUREMENT

**No unit test could have caught this, and the reason is structural rather than a gap in diligence:**

- the class names were still correct — `FileRow.test.tsx`'s 40 cases assert `classList.contains()`;
- the design tokens were still correct — `text-muted-foreground` / `text-panel-muted-foreground`, both
  asserted by CLASS NAME (`D-195-05-B`, deliberately, so the light-theme AA property is visible);
- the glyph sizes were still correct — 16×16, asserted;
- the padding was still correct — `8px` / `8px 10px`, asserted;
- **only the computed line box was wrong, and that is geometry jsdom does not resolve.**

The phase drove **75 plants RED** against production source, ran a **20-case source sweep** over four
files, held `tsc` at 33 and the count gate at `failed 0` — and **all of it was green while every row on
two live surfaces was the wrong height.** The defect was found by a human looking at a browser, in the
first five minutes of U1.

> ⚠ **This is precisely why `G-4` exists and why `CLAUDE.md` says wire format and screenshots are
> insufficient.** A screenshot would arguably have shown it; **no assertion in this repository could**.
> The next phase tempted to close on green gates alone should read this table first.

### The fix, and its re-measurement

Fixed **inline**, operator-approved as a **G-3 fast-fix** (1 file, 1 changed line + a docblock, no
schema and no API surface) — **not** a gap-closure round, so **G-7 is not in play** and Phase 195 still
has **zero** gap-closure rounds (D-19 holds).

**Commit `9c985537`** — `inline-flex items-center` on the wrapper, so the box **shrink-wraps its glyph**
and is immune to inherited leading. The reason is written into the file beside the fix, so the next
reader cannot delete it as styling.

**Re-measured LIVE after the fix:**

| Surface | Post-fix | vs baseline |
|---|---|---|
| Run page row | **33 px** | ✅ **byte-exact** |
| Panel row | **38 px** | ✅ **byte-exact** |
| Icon wrapper, both surfaces | **16 px** | ✅ shrink-wrapped |

Tokens, padding, basename-vs-full-path and activation **all unchanged**. `tsc --noEmit -p
tsconfig.app.json` → **33, unmoved**. The six affected suites → **233/233 green**. Safe against the
phase's own fences **by construction**: every token assertion uses `classList.contains()` or
`innerHTML.toContain()`, both **additive** — adding a class to a `className` cannot red either form.

deliverable actually arrives in. Covered by `fileRowUtils.test.ts` (22 cases) and `FileRow.test.tsx`
