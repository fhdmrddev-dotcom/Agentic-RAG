15 columns, `capability text NULL`, `mcp_server_url text NULL`, `tool_grants jsonb NOT NULL '{}'`,
`discovered_tools jsonb NOT NULL '[]'`. Constraints:
`connector_connections_capability_check` (`capability = ANY(ARRAY['send_email','create_ticket','post_message'])`),
`connector_connections_last_check_verdict_check`,
`connector_connections_mcp_url_is_https`,

**The create row dict** (`connector_service.create_connection`) is an explicit literal with keys
`org_id`, `created_by`, `capability`, `name`, `config`, `secret_ciphertext`, `is_enabled`,
`last_check_verdict`, `mcp_server_url`, `tool_grants`. ⭐ A column absent from THIS dict is never
written, whatever the model declares. `discovered_tools` is deliberately absent today.

**The projection chain:** `ConnectorConnectionResponse` keys → `_RESPONSE_KEYS` →
`_SELECTABLE_COLUMNS = ",".join(_RESPONSE_KEYS)` in `connector_service.py`. It is DERIVED, so a new
response field propagates on its own — which is exactly why the column GRANT is the thing that
breaks, and it breaks as a total 503.

**`_validate_connection_shape`** (`models/connector.py`, `@model_validator(mode="after")` on
`ConnectorConnectionCreate`) currently branches: `if self.mcp_server_url: <https check>; return self`
then `if not self.capability: raise ValueError("Either capability or mcp_server_url must be
provided")` then `_reject_config_capability_mismatch(...)` then the secret check. Its docblock's own
conclusion: *"branch on the SHAPE and validate each one on its own terms, never to loosen the shared
path."*
