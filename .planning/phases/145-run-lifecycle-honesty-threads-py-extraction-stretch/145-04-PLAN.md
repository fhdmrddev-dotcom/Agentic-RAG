<objective>
Make the backend correct a LYING `runs.status` (Direction B): a run whose producer
died (backend restart / broken SSE) is genuinely `status='streaming'` in Postgres
but its `run:{id}` stream stopped growing — and under D-145-02 it is now still
PRESENT in the `runs:active` mirror, so the old membership predicate is blind to it.
Replace the chat-run orphan oracle with STREAM-AGE (D-145-06), terminalize via the
Plan 02 owner (co-writing the ZREM), and run the sweep on a periodic single-flight
interval — not just at boot (D-145-06/08). The kill-timeout is the operator-ratified
generous `2400s` config default (D-145-07) so a live-but-quiet run (silent reasoning
≤900s, ask_user wait ≤1800s) is never false-killed.

Purpose: only a backend mechanism can correct a lying status — the frontend
watchdog (Plan 05) trusts runs.status. This is that mechanism.
Output: stream-age reconciler + config tunables + periodic lifespan host + tests.
</objective>
