<objective>
**WATCH-05 & WATCH-03 (Backend): Watch Loop `missing_since` Timestamp Lifecycle & Connection Health Reflection.**

Record the exact timestamp when a file vanishes at source in `connector_watch_items.missing_since` (and clear it on reappearance). Ensure `/sources/health` directly inspects the underlying connection's `is_enabled` state so a disabled connection is immediately recognized as stopped rather than waiting for an asynchronous scheduled sync tick.

Strict Boundary: `backend/app/api/connectors.py` is strictly fenced (0 lines touched).
</objective>

<threat_model>
### Security & Reliability Invariants (ASVS L1)
1. **Incomplete Listing Protection (H-5):**
   - Invariant: `missing_since` is ONLY written when `listing_complete == true`. An incomplete or paginated listing that truncated must NEVER mark items as missing or set `missing_since`.
2. **Timezone Uniformity:**
   - Invariant: `missing_since` is always formatted in UTC ISO8601 (`datetime.now(timezone.utc)`).
3. **Re-appearance Idempotency:**
   - Invariant: A file that goes missing, reappears, and goes missing again must record the latest disappearance timestamp, never the original historical timestamp.
</threat_model>

<context>
- `BUG-260909-05`: `connector_watch_items.missing_since` exists in PostgreSQL but `WatchService.sync_watch` calls `update_item_state(..., state="missing")` without passing `missing_since`.

- `backend/app/api/sources.py` serves `GET /sources/health` using `health_verdict.py`.
</context>
