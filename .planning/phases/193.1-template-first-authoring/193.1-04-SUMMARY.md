## The headline finding — `template_placeholders` alone does NOT flip the deliverable branch

Six real calls on `claude-opus-4-8` / `anthropic`. Full artifacts in `193.1-UAT.md` row U1.

| Call | `describe` says a template is attached | `template_placeholders` sent | `render_template` phase | keys in draft |
|---|---|---|---|---|
| A (control) | no | **no** | 0 | 1/8 |
| B ×3 | no | **yes** | **0 / 0 / 0** | 3–4/8 |
| C ×2 | **yes** | yes | **1 / 1** | **8/8** |

**The wire is not broken.** Proved without a provider call: `render_grounding_prompt` emits
`### Template placeholder fields (…)` followed by all eight names — all 8 present, empty case
correctly `(none)`. **RESEARCH §B's four-hop trace is accurate at the code level.**

**What fails is the inference.** Both governing strings are conditional and neither asserts a file
exists — the grounding header hedges (*"**if** the workflow must fill a template"*) and the
DELIVERABLE RULE's condition is *"…**(i.e. the user provided a .docx/.pptx/.xlsx template to
fill)**"*, closing *"reach for a template only when one is **actually provided**"*. Adding one
sentence to `describe` saying a template is attached flips it **completely and immediately**: 2/2
runs produced a `render_template` `llm_emit` phase and key coverage went **3–4/8 → 8/8**. Call C also
grew an `llm_human_input` phase on both runs — the model began asking for the fields it now knew it
had to fill.

### Why it matters

**The phase as planned would attach a template, send the placeholders, and still produce a draft that
does not fill it** — the exact defect AUTH-03 was re-opened to remove, arriving through a different
door and passing every wire-level test on the way. **SC#2 is not satisfiable by the currently-planned
change set.** Recorded as **D-26** in `193.1-CONTEXT.md`.

### It corrects D-19 in one direction and confirms it in the other — both stated

- ✅ **CONFIRMED:** the rule is real and the control obeys it (Call A ended in plain-text `llm_single`).
- ❌ **CORRECTED:** D-19 says *"names present ⇒ `llm_emit`/`render_template`"*. Measured, **names
  present ⇒ nothing, 3/3.** The trigger is the **assertion of provision**, not the names.
- ⚠ **D-19's derived hazard is currently UNREACHABLE, and the guard must NOT be removed for that
  reason.** The wire alone produces no `render_template` phase, so the `no_template_bound` terminal
  failure cannot occur today — **but the wire-and-bind indivisibility rule still stands**: the moment
  the provision fix lands, the branch fires and the hazard becomes live and immediate.
