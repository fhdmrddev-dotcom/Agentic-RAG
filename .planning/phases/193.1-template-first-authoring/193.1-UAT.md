### ⚠ THE CAUSE, ISOLATED AND REPRODUCED — this is the finding

**`template_placeholders` alone does not flip the deliverable branch. The model also needs to be told
a template file was actually PROVIDED.**

The mechanical wire is **not** broken — proved directly, without a provider call:
`render_grounding_prompt` emits `### Template placeholder fields (if the workflow must fill a
template)` followed by all eight names, and **all 8 are present in the rendered prompt** (the empty
case correctly renders `(none)`). RESEARCH §B's trace is accurate at the code level.

What fails is the **inference**. Both governing strings are written conditionally, and neither states
that a file exists:

- the grounding header hedges — *"**if** the workflow must fill a template"*;
- the DELIVERABLE RULE's own condition is *"ONLY when the grounding explicitly lists template
  placeholders **(i.e. the user provided a .docx/.pptx/.xlsx template to fill)**"*, and it closes
  with *"reach for a template only when one is **actually provided**"*.

Nothing in the payload asserts provision. **Adding one sentence to the `describe` that says a
template is attached flips it immediately and completely: 2/2 runs produced a `render_template`
`llm_emit` phase, and key coverage jumped from 3–4/8 to 8/8 on both.** Call C also grew an
`llm_human_input` phase on both runs — the model started asking for the fields it now knew it had to
fill.

### Why this matters more than a failed row

**Shipping the phase as planned would attach a template, send the placeholders, and still produce a
draft that does not fill it** — the exact defect AUTH-03 was re-opened to remove, arriving through a
different door. It would pass a wire-level test and fail the user.

It also **corrects D-19 in one direction while confirming it in the other**, and both halves are
stated rather than smoothed:

- ✅ **CONFIRMED:** the rule is real, the branch exists, and the control (Call A) obeys it.
- ❌ **CORRECTED:** D-19 says *"names present ⇒ `llm_emit`/`render_template`"*. **Measured, names
  present ⇒ nothing, 3 times out of 3.** The trigger is not the names; it is the *assertion of
  provision*. D-19's derived warning — that shipping the wire without the bind yields an unbound
  `render_template` draft that is terminal at run — therefore **does not materialize as predicted**:
  the wire alone produces **no** `render_template` phase at all. The risk D-19 named is real in
  principle but is currently unreachable, because the branch never fires.

### The consequence line Plan 09 asked for

**On a template-aware draft as the phase currently plans to build it, the three-bucket name check
still resolves to `produced 0 · run-input 0 · named-nowhere ALL`** — `inputs[]` was `null` on every
run, and only 2 of 8 keys reached a slug/name. **D-20's degenerate-first design stands and must not
be softened.** ⚠ **But if the provision fix below ships, this changes materially**: Call C reached
**8/8** key coverage and grew a `llm_human_input` phase, which is exactly the shape that would begin
populating the *run input* bucket. **Plan 09 must therefore build for the degenerate case AND must
not hard-code the assumption that the non-degenerate case is unreachable.**

## 167-C copy ruling

**Ruling: `reword-both`** — recorded by the assistant under the operator's standing delegation to
proceed unattended, on the **D-21 precedent the operator set on this same phase, on the same day, for
the same reason**. It is cheaply reversible: both strings are unshipped, ungoverned and carry no
byte-exact pin, and nothing in the codebase renders either today.

### The measurement that forced the question

Sketch 167-C's `reconcile.heading` — *"This draft was written before the template arrived"* —
**asserts an ORDER OF EVENTS the definition cannot carry.** Measured over the live corpus (223
`workflow_definitions`): `EmitPhaseConfig.emitter` **defaults** to `"render_template"`
(`backend/app/models/harness.py:156`), every live `llm_emit` phase names it explicitly
(`render_template` **78** · `render_docx` **1** · absent **0**), and on the **74** template-binding
definitions it is `render_template` **73**. **There is no field distinguishing a draft written before
the template from one written to it.** Under D-19 this phase starts producing template-first drafts —
on which the heading would be flatly false. That is the class of dishonesty D-10 calls a red line,
one screen earlier than `SEED-159`.

`reconcile.action` — *"Reconcile the steps with this template"* — **names an act variant C does not
perform.** 167-B (ask the model to reconcile) was rejected on SIZE and no seed was planted. In C the
check is a pure client-side name comparison with **no model call and no write** (D-12), so the label
promises a reconciliation that never happens.

### The exact replacement strings — Plan 06 puts these in `templateFirstVocabulary.ts` VERBATIM, Plan 09 renders them. Neither plan may invent copy.

| id | approved-sketch string (superseded) | **the string that ships** |
|---|---|---|
| `reconcile.heading` | This draft was written before the template arrived | **`What this template asks for, next to what these steps name`** |
| `reconcile.action` | Reconcile the steps with this template | **`Check the names against this template`** |

**Why these two.** The heading now states only what the panel actually puts side by side — a
comparison — and claims nothing about when either was authored, which is the fact the app does not
have. The action names the operation the code truly performs, a **name check**, matching D-10's
own vocabulary (*"a three-bucket NAME check"*) and D-12's rule that the reconcile is an explicit act
that never rewrites the draft.

### What survives this ruling unchanged, and is not open

- **`reconcile.disclaim` ships VERBATIM.** D-10 calls it *"the single most important string on the
  surface"*: without it C asserts a coverage verdict it **cannot compute**. Measured — at attach time
  the app has placeholder keys, phase slugs and `inputs[].key`, a **heuristic**; only at run time does
  `check_coverage` (`template_render_service.py:416-460`) produce `covered_keys` / `covers_template` /
  `null_leaf_count`, a **verdict**. The copy may say *"nothing in the steps **names** these"*. It may
  **NEVER** say the template is uncovered.
- **Three buckets, never two** (D-10's red line).
- **An empty bucket renders no claim** (D-20 / 193's D-15 rule one surface later).

### ⚠ The residual this ruling does NOT remove — routed to row U2, not left to be discovered

Sketch 165's build contract makes `ctrl.button` **deliberately** the shipped `TEMPLATE_ATTACH_LABEL`,
*"Attach a template"* — character for character, so that two doors onto one act do not acquire two
names. **That string contains the word *template*** and will render on the Builder's describe screen
roughly two inches from the shipped `STARTER_DOOR_LINE` (*"Not sure where to start? Start from a
template."*). **D-21 removed the collision from the LABEL; it does not remove it from the BUTTON.**
Row **U2** is the instrument for what is left, and it is the reason U2 must be driven by a person who
has not read this file.
