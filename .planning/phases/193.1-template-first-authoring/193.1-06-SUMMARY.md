### 2. ⚠ THE PLAN'S TASK-1 ACCEPTANCE FOR `doorVocabulary.test.ts` IS NOT ACHIEVABLE AS WRITTEN — AND THE REASON IS A SECOND ACCEPTANCE BAR NOBODY HAD COUNTED

The plan says to *"move `GOVERNED_ID_COUNT` 21 → 22 and add the new id to every whole-table
case … Do not weaken any case."* Measured, those two instructions **conflict** on one case, and
the conflict is not cosmetic:

`doorVocabulary.test.ts`'s contract-agreement case re-parses
`./__contracts__/doors-copy.generated.md` at test time and asserts
`Object.keys(parsed)).toHaveLength(GOVERNED_ID_COUNT)` **and** `parsed).toEqual(COLUMN_D)`. That
file is **sketch 164's generated artifact and contains exactly 21 rows**. `DESCRIBE_ATTACH_PROMPT`
comes from a **different acceptance bar** — sketch 165's `ctrl.label` slot, reworded by D-21/D-28
— so the generated contract has no row for it and never will. Setting the shared constant to 22
reds the case; leaving it at 21 fails the export-set case.

⚠ **The plan's own pointer is slightly off here too, and it matters:** `<interfaces>` describes
this as *"re-parses `165/BUILD-CONTRACT.generated.md`-class contracts"*. It parses the **164**
doors-copy contract — a different sketch. That is why the 22nd id is genuinely outside it rather
than merely missing from it.

**Resolved by RE-SCOPING across the seam, never by weakening** (the standing instruction):

- `GOVERNED_ID_COUNT` → **22** (the whole table) and a new `CONTRACT_ID_COUNT` → **21** (what the
  generated bar governs).
- `COLUMN_D` keeps its 21; `POST_CONTRACT_COPY` holds the 22nd; `ALL_GOVERNED_COPY` is their
  union, and the export-set case asserts the union **equals** the module's exports **and** that
  the two sets are **disjoint** (so a spread cannot shadow a contract row and take a governed
  word out of the generated bar's reach while every count still read 22).
- The exact-match loop runs over the **union**, so the 22nd id gets a real byte-exact case.
- **A NEW case asserts every post-contract id is genuinely ABSENT from the contract**, in both
  the parsed table and the raw source, with non-vacuity on both. Without it `POST_CONTRACT_COPY`
  would be a place to quietly park any id someone would rather the generator did not check.

Every property the file had is intact; the file gained one. **The rejected alternative is named:
widening the parse until it "found" 22 would have made this phase's anti-drift instrument report
on a row its own source file does not contain — a fence measuring nothing.**
