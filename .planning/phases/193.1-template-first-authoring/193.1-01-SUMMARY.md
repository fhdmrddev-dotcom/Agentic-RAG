## Deviations from Plan

### Auto-fixed / judgement calls (no rule 4 territory)

**1. [Rule 2 — missing coverage] The captures include the KB picker, not an empty one.**
- **Found during:** Task 1 design.
- **Issue:** The analog (`WorkflowDoorSwitch.baseline.test.tsx`) stubs `listFolders` to `[]`. The
  Builder's picker is gated on `folderOptions.length > 0` (`:1558`), so an empty stub would have
  captured six screens **with no `project-folder-picker` node at all** — and the row this phase adds
  mounts *under the knowledge-base picker* (CONTEXT §specifics). A baseline blind to the picker
  cannot see a re-parenting at the exact seam the phase is about.
- **Fix:** `listFolders` returns two fixed folders in all six rows. Order is preserved verbatim by
  the page (`folders.map(...)`, `:1208`), so it stays deterministic; both option labels are asserted
  present in every capture.
- **Cost:** none — no extra rows, same six keys the plan specifies.

**2. [Rule 3 — blocking] Every api stub is a plain function, including the ones the analog spies on.**
- **Issue:** The plan's acceptance criterion is `grep -c "vi.fn()" <file>` **== 0**, but the analog
  and `describe.test.tsx` both build the whole `@/lib/api` seam out of `vi.fn()`.
- **Fix:** the seam is a `vi.hoisted` object of plain functions with an explicitly-reset `WIRE.state`.
  Task 2's call recording is an array push rather than a spy's `mock.calls`. Measured: 0.
- **⚠ It also forced a prose edit.** The docblock EXPLAINING the rule contained the literal
  `vi.fn()` and broke the raw grep — the same property the D-24(a) copy fence has. Reworded to
  `vi.fn` and the reason is recorded in the file itself.

**3. [commit hygiene] The single new file was committed in two commits, one per task.**
- Task 1's commit contains the file without the Task-2 section; Task 2's commit appends it. Both
  were verified green independently (13/13 then 16/16). This is what sequential authoring would have
  produced; it is noted because the file's own title docblock (written once) mentions the key set in
  both commits.
