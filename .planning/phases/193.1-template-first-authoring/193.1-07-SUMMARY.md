## The test that proves a THROWING bind cannot fail the save

**`useDraftPersistence.test.tsx` → `useDraftPersistence — 193.1-07: a misbehaving onDraftCreated`
→ `"THE GUARD — the shipped composition (async + internally caught + void-ed) is CLEAN"`.**

It installs *exactly* the composition the page ships, with the inner throw made **synchronous** —
the harder case, because `async` is the thing that converts it into a rejection:

```ts
const bind = async (id: string) => {
  try { throw new Error(`the bind threw for ${id}`) } catch (e) { failures.push(String(e)) }
}
const h = await createWith((id) => { setDraftIdOnThePage(id); void bind(id) })

expect(setDraftIdOnThePage).toHaveBeenCalledWith("new-draft")          // (a) id installed
expect(h.view.result.current.draftId).toBe("new-draft")
expect(stateOf(h.view)).toEqual({ kind: "saved", at: expect.any(Number) })   // (b) NOT an error
expect(h.markSaved).toHaveBeenCalledTimes(1)
h.edit(); await advance(AUTOSAVE_DEBOUNCE_MS); await flush()
expect(mockedUpdate).toHaveBeenCalledTimes(1)                          // (c) loop NOT halted
```

**Its control is the case immediately above it** — `"THE HAZARD, CHARACTERIZED"` — which drives a
bare synchronous throw at the same seam and measures `{ kind: "error", sentence: SAVE_FAILED_SENTENCE }`.
The two cases are each other's positive control: the guard's green is only meaningful because the
unguarded shape is red on the same harness, on the same commit.

At the hook's own level the property is asserted on the **returned promise**, not on the state —
`useTemplateFirstDraft.test.tsx` → `"NEVER REJECTS — a synchronously-throwing upload resolves,
which is what makes void safe"` — because a `void`-ed rejection has nowhere to be caught.

## ⚠ Measured contradictions — stated beside the claimed value, never silently fixed

This phase has already measured a dozen inherited claims false, including its own central
assumption. Five more, each with the correction and the evidence.

### 1. The plan's sixth read arm (`notWord`) is UNBUILDABLE against the shipped row

**Claimed** (Task 1 `<action>`): *"Derive `notWord` HERE rather than in the component, so the union
is the whole answer and the row stays purely presentational."*

**Measured:** the row is not purely presentational and this plan cannot make it so.
`DescribeTemplateRow.tsx:153` already derives `notWord` itself, from `none` plus the held filename,
gated on **emptiness** rather than on the extension alone; its `state` prop is typed on the shared
five-arm `TemplatePlaceholdersState`; and its own docblock requires that union *"imported rather
than re-declared: one wire shape for both doors means the two surfaces cannot derive different arms
from the same server answer."* `DescribeTemplateRow.tsx` is **not** in this plan's `files_modified`,
and Plan 08's Task 1 feeds it `state` + `filename` straight from this hook — so a sixth arm would be
a value the shipped component cannot accept.

**Taken:** the union stays five and is **imported**, not re-declared; the hook exposes `templateFile`
so the row's existing predicate keeps its single home. The behaviour the plan wanted is asserted
(`"an EMPTY ok read on a .pptx is ALSO none, and the held name is what separates them"`), and the
case carries the correction in its own comment so a future reader meets it at the code.

### 2. The two key-set literals must NOT move — and that is the feature working

**Claimed** (Task 2 `<action>`): *"MOVE Plan 01's two key-set literals to their new values … That
movement is this phase's mechanical evidence that the wire changed."*

**Measured:** both cases drive the page with **no document supplied**, and this screen has no way to
supply one until **Plan 08** mounts the control (which Plan 08 declares in its own `files_modified`).
`template_placeholders` is sent on the `fields` arm alone, so those two journeys send exactly what
they sent before. Moving the literals would have recorded a change that did not happen and would
have redded on the first run.

**Taken:** the literals stand, and six cases were **added** pinning the other half of the same claim
— the two key sets re-asserted *after* the wire shipped, the CTA proved not disabled with no
document held, a source fence proving the page derives no key of its own, and two on the failure
line. The declaration is dated in the file and repeated at the count-gate pin, which is where the
now-corrected *"their whole value is that they must MOVE"* comment lives.

### 3. A synchronous throw does NOT trip `haltedRef` on the common path

**Claimed** — by the plan, by CONTEXT's amendment and by PATTERNS §9 alike: *"a SYNCHRONOUS throw
out of `onDraftCreated` … can freeze autosave for the session."*

**Measured:** `refusalOf` sets the halt flag only for `WorkflowStaleTokenError` (→ `conflict`) or an
error passing `isTerminalRefusal`; an **ordinary `Error` falls through to the generic arm** and the
loop is not halted. The `"THE HAZARD, CHARACTERIZED"` case proves it: after the throw a subsequent
edit still issues a `PATCH` against the created id.

**Consequence:** the hazard is **real and smaller than stated on the common path** — a false
save-error for a row that exists, rather than a frozen session. The guard is unchanged: a false
save-error is already a lie, and the freeze remains reachable for a terminal-shaped throw. Both facts
are pinned so neither can later be quoted as the other.

### 4. `bindFailed` ships with ONE field, not two

**Claimed:** *"a two-field `bindFailed` object that structurally cannot hold server prose, a status
code or an id (the `useWorkflowFork.ts:205` posture)."*

**Measured:** the analog's second field (`conflict`) exists because it **selects a branch in that
module's sentence**. `templateBindFailedMessage(filename)` — shipped by Plan 06, unedited here —
takes a filename only. A second field would be data with no reader.

**Taken:** one field. The property the rule is *for* — cannot carry prose, a status or an id — is
satisfied strictly more, and is asserted as an exact key list rather than trusted.

### 7. `?raw` sources carry CRLF, and a multi-line source fence must be `\r`-tolerant

matches nothing and reports as an **empty extraction**, which looks exactly like a fence that
passed. Mine did, on the first run. This is why the non-vacuity floor is asserted before any claim
about the contents, and the reason is now recorded at the fence.
