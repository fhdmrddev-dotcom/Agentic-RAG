## Task 1 — what changed, and what deliberately did not

`render_grounding_prompt` previously emitted ONE hedged heading serving BOTH meanings:

```
### Template placeholder fields (if the workflow must fill a template)
<names> | (none)
```

It now branches on `bundle.placeholders` into two arms that each state which world the call is in.
The names still follow the heading on the very next line, comma-joined exactly as before — that is
load-bearing, because the per-name membership fences parse the line immediately after the heading.

**Present arm:** *"the user HAS attached a template document to this workflow; the final deliverable
MUST therefore be an `llm_emit` phase with `emitter: 'render_template'` that fills EXACTLY the fields
named on the next line"*.

**Absent arm:** *"NO template document was provided with this workflow; the final deliverable MUST
therefore be PLAIN TEXT / markdown, and a `render_template` emit phase is FORBIDDEN because it would
fail at run time"* — **stronger than the string it replaces, never weaker.** Call A proved the
no-template path already behaved correctly, and SC#4 plus D-08 rest on it; an unbound
`render_template` phase is terminal at run (`no_template_bound`, `phase_types.py:1271`).
