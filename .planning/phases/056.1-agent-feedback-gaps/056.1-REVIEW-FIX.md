## Fixes Applied

### WR-01 — Duplicate-named tool calls lose second `preparing` entry
**File:** `frontend/src/hooks/useMessages.ts`
**Fix:** Changed deduplication in `onToolPreparing` from name+status match to `tc.id === preparingId` where `preparingId = "preparing-${index}"`. Same-named parallel tool calls now each get their own preparing placeholder.
**Commit:** 71c2f89

---

### WR-02 — `onToolStart` fallback entry missing `id` field
**File:** `frontend/src/hooks/useMessages.ts`
**Fix:** Fallback append path in `onToolStart` now includes `id: \`running-${Date.now()}\`` so downstream `tool_end` matching has a consistent entry.
**Commit:** 71c2f89

---

### WR-03 — `finally` block marks tools on ALL assistant messages as interrupted
**File:** `frontend/src/hooks/useMessages.ts`
**Fix:** Changed guard from `m.role !== "assistant"` to `m.id !== assistantId` so only the currently-streaming message's tools are marked interrupted.
**Commit:** 45ff663

---

### WR-04 — Anthropic path lacks `_announced_tools` guard
**File:** `backend/app/api/threads.py`
**Fix:** Added `_announced_tools_ant: set[int] = set()` before the Anthropic event loop with the same `if _idx not in _announced_tools_ant` guard that the OpenAI path uses. Prevents duplicate `tool_preparing` emission on retry/replay.
**Commit:** 09f5a1d

---

### WR-05 — `preparing` entries sort to epoch-0, jumping to top of tool list
**File:** `frontend/src/components/chat/ToolCallPanel.tsx`
**Fix:** Changed sort key from `tc.startedAt ?? 0` to `tc.status === "preparing" ? Infinity : (tc.startedAt ?? Date.now())`. Preparing entries now sort to the end (appended order) rather than the top.
**Commit:** b79089f

---

### WR-06 — Structured-mode `tool_preparing` emitted without async gap
**File:** `backend/app/api/threads.py`
**Fix:** Added `await asyncio.sleep(0)` after the batch of `tool_preparing` yields in the structured (XML) path. Forces an event-loop yield so the SSE chunk reaches the browser before tool execution begins, making the `preparing` state visible.
**Commit:** 9e2dd75

---

### WR-07 — `onDone` called twice when stream ends without `stream_end`
**File:** `frontend/src/lib/api.ts`
**Fix:** Added `let doneFired = false` guard. The `done` event handler and the fallback at end-of-function both check and set `doneFired` — `onDone` is now called exactly once regardless of how the stream terminates.
**Commit:** ae6daa7
