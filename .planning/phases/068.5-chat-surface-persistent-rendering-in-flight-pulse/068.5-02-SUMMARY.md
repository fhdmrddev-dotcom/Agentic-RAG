## Decisions Made

- **Template-literal className** in `MessageItem.tsx` (not `cn()`): matches the existing bare-string convention in the file; `cn()` is not currently imported here and adding it would be a one-off inconsistency.
- **Banner thread-predicate `reconcileError.threadId === thread?.id`** in `ChatArea.tsx`: prevents the banner from rendering on a different thread than the one that failed. Acceptable degradation: if the user switches back, the banner reappears.
- **Inner `tryFetch(attempt: number)` recursion** (not `for` loop): keeps the L-068.5-02 MERGE 3-clause filter body byte-identical inside the wrapper. A grep over the entire file finds the predicate at the same point.
- **Defensive AbortError check (both `DOMException` and `name === "AbortError"` shape)**: matches the safety net the original `loadMessages` body had (`err instanceof Error && err.name === "AbortError"`), with an added duck-type fallback for fake errors thrown in tests.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Test bug] Retry-banner tests needed an auto-reconcile baseline before queueing failures**
- **Found during:** Task 3 (post-implementation iteration on the retry-banner tests)
- **Issue:** `setViewingThread("T1")` fires `reconcile("T1")` which internally calls `loadMessages("T1")` → calls `getMessages`. The original test sequence `mockReset()` + `mockRejectedValueOnce(...)` + `mockResolvedValueOnce([])` was consumed by the auto-reconcile path BEFORE the explicit `loadMessages` call fired. Then the explicit call hit the now-exhausted mock, returning `undefined`, and `data.filter(...)` threw `TypeError`. The test was failing for the wrong reason (mock-exhaustion TypeError, not a retry-banner-flow bug).
- **Fix:** Restructured the 3 retry-banner tests (Test 1, Test 2, AbortError test) to do `mockResolvedValue([])` baseline BEFORE `setViewingThread`, let the auto-reconcile consume that, then `mockReset()` + queue the failure-sequence + `mockResolvedValue([])` safety net BEFORE the explicit `loadMessages("T1")` call. Also added `await vi.advanceTimersByTimeAsync(0)` after `setViewingThread` to drain any pending microtasks from the auto-reconcile path.
- **Files modified:** `frontend/src/__tests__/providers/streamsProvider.test.tsx` (3 tests in the Plan 02 retry-banner describe blocks).
- **Verification:** All 5 retry-banner tests now GREEN. The tests exercise the actual retry-wrap behavior, not a degenerate mock-exhaustion path.
- **Committed in:** `6ee6f65` (part of Task 3 commit).
