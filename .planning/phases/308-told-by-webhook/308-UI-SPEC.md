# Phase 308 — UI Design Contract

> Visual and interaction contract for "Told by Webhook" (HOOK-01, HOOK-02's visible half, HOOK-04,
> HOOK-05's save-time refusal, HOOK-06). HOOK-03 has no UI of its own; it shows up only as "exactly one
> row per event" in the delivery log.
> Generated by gsd-ui-researcher; the checker validates it.

**What this file decides.** Four surfaces:

1. **Settings → Webhooks** — a new member tab: the endpoint list (each endpoint a card that expands in place to its actions and its own delivery log), the add and edit form, the secret shown once, Send test, Roll secret, Turn off / Turn on, Delete, Resend (D-28, D-29).
2. **Org admin → API keys → Webhooks** — one new section listing every endpoint in the org, with Turn off, Turn on (admin-off only) and Delete (D-30).
3. **"Waiting on you"** — a new row kind for an endpoint Syrel turned off, which opens the Webhooks tab on that endpoint (D-19).
4. **Audit words** — plain labels for the nine new `webhook.*` literals in the org and operator audit tabs (D-31).

**It brings in no new tokens, primitives, type sizes or colours.** Where this file says "as 304" or
"as 307", that contract applies unchanged. All new UI lives in new leaf files; every hot file gets one
mount, one registry entry or one data change (§G-5 mount budget).

**Out of scope and not touched:** `frontend/src/lib/api.ts` (the new client is `lib/api/webhooks.ts`),
`OrgAdminShell.tsx` (no new org-admin tab, D-30), any operator or org kill switch for webhooks, email
for an auto-disabled endpoint, revealing a secret after creation, folder or workflow filters on events,
custom headers, replay (all deferred in CONTEXT).

## Spacing Scale

As 304 and 307. All values are multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | icon-to-text gap, chip gaps, the gap between an event chip row's chips |
| sm | 8px | gap between action buttons, meta-line gaps, the gap under each form label, sheet button gap |
| md | 16px | endpoint card padding (`p-4`, the `ApiKeyCard` value), form card padding, gap between form fields (`gap-4`), the gap above "Deliveries" |
| lg | 24px | header card padding (`p-6`, shipped), sheet body padding (shipped `AlertDialogContent`) |
| xl | 32px | empty-state vertical padding (`py-8`, shipped) |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions (all inherited, all multiples of 4 except the shipped chip and table padding noted):
- **12px** (`gap-3`) between stacked cards (the shipped tab grid), between an expanded card's header and its detail (`mt-3 pt-3`), and `px-3` inside log table cells and notice boxes. This is the shipped card-stack value.
- **Log table cells:** `px-3 py-1.5` (12px / 6px), the shipped `ApiKeyActivity` table. 6px is inherited, not introduced.
- **Chip padding (shipped classes):** `py-0.5` (2px), `px-1.5` (6px), `px-2` (8px) on status tags, event chips and the admin "you" mark. Inherited from the 304 key card; none is introduced here.
- **Touch targets:** every button, checkbox row and the card's expand toggle is at least 44px tall below 640px (`min-h-[44px] sm:min-h-0`, the 304 precedent).
- **Narrowest supported width: 320px.** The log table and the admin table scroll horizontally inside their bordered boxes (`overflow-x-auto`); the page itself never scrolls sideways. The action row wraps.
- **Settings column:** the shipped 880px Settings content width (sketch 308's measure). Nothing here widens it.

**Accepted density exception (orchestrator decision, 2026-11-04, UI-check revision 1):** the 2px
(`py-0.5`), 6px (`px-1.5`, `py-1.5`) and 12px (`gap-3`, `px-3`) values above are **accepted, not
re-gridded**. They are the shipped classes of `ApiKeyCard` / `ApiKeyActivity` (Phase 304) that the 307
UI-SPEC already carried under the same exception (307-UI-SPEC §Spacing, "Chip padding … inherited from
the 304 key card"). Re-gridding them here would make the Webhooks tab visibly denser or looser than the
API keys tab beside it, which is the drift the sketch was asked to avoid. **No new off-grid value is
introduced by this phase**; any value not listed here must be on the 4/8 scale.

Accent (`--primary`) is reserved for exactly these elements in this phase:
1. **Add endpoint** (`gradient-primary`) in the tab header and in the empty card.
2. **Save endpoint** / **Save changes** (`gradient-primary`) in the form.
3. **I've saved the secret** (`gradient-primary`) on the secret-once card (the 304 button).
4. **Roll secret** confirm button (default primary) and the Roll sheet's 3px top rule (the "calm" sheet).
5. Text links: the log's "About" links, **Show older**, **Switch to {org}**.
6. Checked event checkboxes and focus rings (`--ring`), unchanged.

**At most one filled `gradient-primary` button is on screen at a time:** the header's Add endpoint hides
while the form or a secret-once card is open; the form's Save and the secret card's done button never
co-exist. Turn on, Send test, Roll secret (the opener), Edit and Resend are **outline**, never filled:
they are routine, and a failing endpoint's next step is said in its notice, not shouted by a colour.

**Status colour is never red for a state.** Red is spent on destructive actions and on failure text; an
endpoint that is off is amber (it can be turned back on), as 304's `⏸ switched off` tag. Colour is never
the only signal: every tag carries words; every disabled control carries its reason as DOM text.

## Surface 1 — Settings → Webhooks (HOOK-01, HOOK-02, HOOK-04, HOOK-05; D-27..D-29)

The tab is self-contained on the `ApiKeysTab` / `RetentionTab` shape: its own reads, an `alive` ref on
every setState, the last-known list kept on a failed re-read, and a re-read when the active org changes
(endpoints belong to one org, D-04). Layout is the shipped `grid gap-3` stack.

**Focal point.** With no endpoints, the header's **Add endpoint** (the only filled button) is the
focal point. With endpoints, the focal point is the **open card's status tag and delivery log** — the
evidence of whether the receiver works. When the secret-once card is showing, it is the focal element
and the only filled button on screen is **I've saved the secret**.

### 1a. Header card

`ghost-border rounded-xl bg-card/60 p-6 shadow-sm` (shipped).
- Title (16px Manrope 600): `Webhook` icon (16px) · **Webhooks** · count **{N} of 10** (12px mono muted) once loaded.
- Description (14px muted): "Syrel tells your own systems when a run finishes, a run waits on you, or a document is ingested. Each message is signed and carries ids, a status and a link — never document text."
- Scope line (12px muted): "Endpoints in **{org}**. Each one gets events from {org} only." ({org} at 600 `text-foreground/80`.)
- Right side: **Add endpoint** (`gradient-primary`) when the list is loaded, has at least one endpoint, has fewer than 10, and no form or secret-once card is open.
- **At the cap (10):** Add endpoint is shown **disabled** with a 12px muted why-line under the description, linked by `aria-describedby`: "You have 10 endpoints in {org}, the most allowed. Delete one to add another."

### 1b. The endpoint card (sketch A: one card per endpoint, opens in place)

The shipped `ApiKeyCard` shape: `rounded-[14px] border border-border bg-card p-4`, stacked 12px apart,
newest first. **One card is open at a time**; opening another closes the first.

**Collapsed (the header is a `<button>`** with `aria-expanded` and `aria-controls` naming the detail

## Interaction and security contract

- **Never optimistic.** Every write (create, edit, turn on/off, roll, delete, resend, admin writes) changes the screen only from the server's answer. A failure keeps the screen as it was and says so in the server's words.
- **The address refusal is the server's.** The client checks form (parseable, no userinfo, no fragment); reachability is decided only by the server at save and again at every send (D-23). The refusal sentence is fixed; no reason code, resolved IP or internal detail is ever shown.
- **Untrusted text is text.** Description, address and owner names render as React text only; nothing builds a link from an endpoint's address (the address is never an `<a href>` anywhere in the UI).
- **Query strings.** Member view masks query values; admin view and audit never receive them.
- **One card open, one secret alive.** Opening a card closes the other; a roll's secret-once panel lives only in that card and leaves with "I've saved the secret", the card closing, or unmount.
- **Keyboard.** The card header is a button (Enter / Space toggle). The log table is a real `<table>` with `scope="col"` headers. Sheets are Radix `AlertDialog` (focus trap and restore); the safe button holds initial focus. After Delete, focus moves to the header title. After a direct flip, focus stays on the flipped button's replacement (Turn off ↔ Turn on swap in place).

**Accessibility.**
- Every disabled control's reason is real DOM text linked by `aria-describedby` (Add endpoint at the cap, Send test when off, Turn on when admin-off, Save without an address or event).
- Status changes use `role="status"` (loading, saving, verdicts, receipts, resend outcome); failures use `role="alert"`.
- The event checkboxes sit in a `role="group"` labelled "Events"; each checkbox's accessible name is its type and sentence.
- All 12px text uses `text-muted-foreground` or stronger on `--card` (AA). Tags use the shipped AA tag pairs.
- **Motion:** the chevron's 150ms rotation, the shipped 1.6s band pulse on admin receipts. No row-leave animation, no auto-scroll except the single `scrollIntoView` on arrival from "Waiting on you". Both respect `prefers-reduced-motion` (rotation becomes instant).

## Lived-experience (G-4) rows, driven by Claude at verification (D-39)

1. **Add, test, verify.** Settings → Webhooks → Add endpoint with a public receiver's https address and the default events → Save endpoint → the secret-once card shows `whsec_…`; Send test reads "Delivered — your receiver answered 2xx in … ms. It is in this endpoint's log."; the receiver's request verifies with `standardwebhooks` and the copied secret; after "I've saved the secret" the card lists the endpoint **On** with one `webhook.test` row, Sent.
2. **Exactly one delivery each.** Finish a workflow run and ingest a document; the open card's log shows exactly one `run.finished` and one `document.ingested` row, Sent, with **run …** and **document …** links that open the run and the document in the app.
3. **Failing → off → told.** Point an endpoint at a receiver answering 500; the log shows Retrying rows with "next …", tries climbing and HTTP 500; after 5 failed deliveries the tag reads **Off — kept failing**, the notice explains, and "Waiting on you" shows a `Webhook` row "… · webhook turned off · kept failing · turned off …" that opens this tab on that endpoint.
4. **The refusal.** Save `http://169.254.169.254/` and an internal host name: each shows exactly "That address can't be reached from the internet, so Syrel won't send to it." under the address, keeps the typed value, and saves nothing.
5. **Admin turn-off.** As an org admin, Org admin → API keys → Webhooks lists the member's endpoint (host + path, no query); Turn off → the band pulses and the receipt names owner and host; the member's card reads **Off — turned off by an org admin** with Turn on disabled and "Only an org admin can turn this back on."

**I'd recognise failure here if:** the log shows any part of a request or response body; an address
refusal shows a code, an IP or any other sentence; a secret appears anywhere after "I've saved the secret"
or after a reload; the admin table shows a query string; a member can turn on an admin-off endpoint; a
disabled button gives its reason only in a tooltip; a delivery row appears for an item the member cannot
open; the Settings strip label is longer than one word; an endpoint's address renders as a link.
