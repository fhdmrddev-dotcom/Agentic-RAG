## UAT recipe

1. Navigate to **Settings → AI Model**.
2. Find the **Google** provider's "Models" comma-separated input. Append `, gemini-99-flash` to the existing list (after `gemini-3.5-flash` or whatever the last entry currently is).
3. Click **Save** (the AI Model section save button). Confirm the page persists the change (toast "Saved" or similar).
4. **Reload** `/settings` (Cmd-R / F5, or programmatically via Chrome MCP `Page.reload`).
5. **Assertion 1 (badge inline in pill row):** In the **Active Model** section, the "Available from active provider" pill row now shows `gemini-99-flash` with an inline amber `unverified` chip. Other registered models (`gemini-2.5-pro`, `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-3-flash-preview`, `gemini-3.1-pro-preview`, `gemini-3.5-flash`) have NO chip.
6. Click the `gemini-99-flash` pill to set it as the active LLM model. Click **Save Model** (or whichever save button persists the AI Model section).
7. **Assertion 2 (badge on selected-label):** Reload `/settings`. The `<TextInput value={llmModel}>` shows `gemini-99-flash` AND the inline amber `unverified` chip appears next to it (per the `<FieldRow label="Model">` block).
8. **Assertion 3 (tooltip text):** Hover the `unverified` chip (either on the pill OR the selected-label). The tooltip reads exactly:

   ```
   This model isn't in our verified registry. Using inferred provider: google. Safe defaults applied (max_tokens=8192, timeout=90s).
   ```

9. **Assertion 4 (content streams):** Navigate to the chat surface. Open a **NEW** chat (fresh thread). Send the prompt `hi`. Confirm the assistant streams a non-empty reply (typically "Hi! How can I help you today?" or similar).
10. **Assertion 5 (warn-once log fires once):** Tail the backend uvicorn stdout. Find the line matching the regex `model_capability_unknown.*model_id=gemini-99-flash.*inferred_provider=google.*safe_defaults_applied=True`. Assert EXACTLY ONE such line appears in the post-restart window.
11. **Assertion 6 (warn-once dedup holds across prompts):** Send a SECOND `hi` prompt (in the same chat OR a new chat — same process). Tail logs again. The `model_capability_unknown` line for `gemini-99-flash` does NOT re-fire (still exactly 1 match).
12. **Assertion 7 (warn re-fires after uvicorn restart):** Stop and restart uvicorn (the process-restart resets `_WARNED_UNKNOWN_MODEL_IDS`). Send `hi` again. The warn line fires ONCE more (proves dedup is process-scoped, not persistent).

**Cleanup after UAT:** Remove `gemini-99-flash` from the Google provider's `models` list so it doesn't pollute the default state for the next phase. Confirm the chip disappears + the model is no longer selectable from the dropdown.
