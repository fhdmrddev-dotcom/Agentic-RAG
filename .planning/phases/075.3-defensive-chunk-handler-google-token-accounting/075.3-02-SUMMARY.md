## Final shape of `get_model_capability` + `_INFERRED_DEFAULTS`

The rewritten capability lookup at `backend/app/config.py:get_model_capability` (lines 200-260 region) is a two-branch dispatcher:

```python
def get_model_capability(model_id: str) -> ModelCapability:
    if model_id in MODEL_CAPABILITIES:
        return MODEL_CAPABILITIES[model_id]   # capability_source="registry" (tagged on every entry)
    if not model_id or not str(model_id).strip():
        return _build_inferred_defaults(model_id or "", _INFERENCE_FALLBACK_PROVIDER)
    return _build_inferred_defaults(model_id, _infer_provider_for(model_id))
```

`_infer_provider_for` walks the 5-bucket table; `_build_inferred_defaults` builds the safe-default dict and triggers warn-once. The 5-bucket table (config.py:177-184):

| Pattern (`re.IGNORECASE` except slash) | Provider     | Example matches                                 |
| -------------------------------------- | ------------ | ----------------------------------------------- |
| `^gpt-`                                | `openai`     | `gpt-99`, `gpt-future-mini`, `GPT-4o-future`    |
| `^o[1-9](-\|$)`                        | `openai`     | `o5`, `o3-mini-future` (note: `o10` → ollama)   |
| `^claude-`                             | `anthropic`  | `claude-future-5`, `Claude-future`              |
| `^gemini-`                             | `google`     | `gemini-99-flash`, `gemini-3-future-flash`      |
| `^[^/\s]+/[^/\s]+`                     | `openrouter` | `vendor/model`, `vendor/model:free`             |
| (else)                                 | `ollama`     | `unknown-no-prefix`, `""`, `None`, garbage      |

Safe-default matrix per bucket (config.py:190-198):

| Provider     | max_output_tokens | timeout_s | native_tools |
| ------------ | ----------------- | --------- | ------------ |
| openai       | 8192              | 90        | True         |
| anthropic    | 8192              | 90        | True         |
| google       | 8192              | 90        | True         |
| openrouter   | 4096              | 90        | False        |
| ollama       | 8192              | 90        | False        |

Warn-once dedup (`_WARNED_UNKNOWN_MODEL_IDS: set[str]`, config.py:201) fires `logger.warning("model_capability_unknown model_id=%s inferred_provider=%s safe_defaults_applied=True", model_id, provider)` exactly once per process per model_id. Parameterized formatter (NOT f-string) — T-075.3-02-02 log-injection mitigation.

## `capability_source`-guarded active-provider fallback

`backend/app/api/threads.py:1205-1230` is the ONE consumer that needed updating — the routing decision for the run's resolved provider when `body.provider` is unset:

```python
if body.provider:
    _resolved_provider = _user_settings.active_provider
else:
    _capability = get_model_capability(_resolved_model) or {}
    _capability_provider = _capability.get("provider", "unknown")
    _capability_source = _capability.get("capability_source", "registry")
    if _capability_provider != "unknown" and _capability_source == "registry":
        _resolved_provider = _capability_provider
        _user_settings = override_provider(_user_settings, _resolved_provider)
    else:
        _resolved_provider = _user_settings.active_provider
```

The added `_capability_source == "registry"` clause preserves D-067.3-N01-02 verbatim: when the user types `random-garbage` (falls into the ollama bucket), routing stays on their explicit `active_provider` instead of yanking to Ollama. Only verified registry hits override the active provider.

## `ModelPillRow` + selected-label badge

`frontend/src/components/settings/ModelPillRow.tsx` (75 lines, new) owns the dropdown pill row + inline badge. Component contract per D-075.3-10/11/12:

- Each pill renders `{model}` text; if `!verifiedModels.has(model)`, appends an inline amber `<span class="ml-1.5 text-[9px] font-medium text-amber-600 bg-amber-500/10 px-1.5 py-0.5 rounded-full ghost-border">unverified</span>` with the locked tooltip on the `title` attribute.
- Selected-label render (inside `<FieldRow label="Model">` in SettingsPage.tsx:540-625) adds a slightly looser variant (`ml-2 text-[10px] ... px-2 py-0.5`) next to the `<TextInput value={llmModel}>` when the model is not in `verifiedModels`.

Tooltip text is built by a pure helper:

```typescript
function _tooltipFor(model, inferredProviderFor) {
  const provider = inferredProviderFor[model] ?? "ollama"
  const maxTokens = provider === "openrouter" ? 4096 : 8192
  return `This model isn't in our verified registry. Using inferred provider: ${provider}. Safe defaults applied (max_tokens=${maxTokens}, timeout=90s).`
}
```

Mirrors the backend safe-default table verbatim. XSS-safe: React JSX auto-escapes `{m}` interpolation + `title=` attribute (T-075.3-02-03 mitigation).

## Deviations from the planned shape

### Auto-fixed Issues

**1. [Rule 1 - Bug] Restored 4 MODEL_CAPABILITIES entries silently dropped by the first-pass capability_source tagging**

- **Found during:** Task 2 (Wave 1) — surfaced when full backend unit suite reported 4 MODEL_CAPABILITIES rows missing post-commit `a117de9`.
- **Issue:** First-pass regex used to append `, "capability_source": "registry"` to every MODEL_CAPABILITIES entry was `\r\n`-naive — on Windows CRLF lines, it ate the closing `}` + the next `{` on multi-entry-per-block sections, dropping `gpt-5.4-mini`, `gpt-5.4-nano`, `gpt-5.5`, `claude-opus-4-6`.
- **Fix:** Reverted MODEL_CAPABILITIES to the pre-`a117de9` shape from git, re-tagged via strict per-line regex requiring single physical line: `^(\s*"[^"]+":\s*\{[^}]+)\}(,?)$` → `\1, "capability_source": "registry"\}\2`. Confirmed all 33 entries present + tagged.
- **Files modified:** `backend/app/config.py`
- **Verification:** `grep -cE "\"capability_source\":\s*\"registry\"" backend/app/config.py` → 33 (matches `len(MODEL_CAPABILITIES) == 33`); 21/21 inference tests + 7/7 chunk-handler tests green post-fix.
- **Committed in:** `40a6cde`

### Mid-UAT Operator Recovery (not a Plan 02 defect)

**2. [Orchestrator UI-bypass mistake] KEY_PLACEHOLDER sentinel confusion clobbered all 5 provider api_keys mid-UAT**

- **Found during:** Wave 4 UAT (between adding `gemini-99-flash` and sending the first `hi` prompt)
- **Issue:** Orchestrator's direct `PUT /settings` call used the wrong sentinel `__KEEP__` instead of `***` (which is `KEY_PLACEHOLDER` per `frontend/src/pages/SettingsPage.tsx:14`). The settings backend treated `__KEEP__` as a literal new key, overwriting all 5 provider api_keys in `backend/settings_override.json`.
- **Fix:** Stripped the bad `*_api_key` keys from `settings_override.json` (env fallbacks restored from `backend/.env` automatically). Backend integrity restored before Assertions 4-7 captured.
- **Why not a Plan 02 defect:** Plan 02 did NOT touch the settings PUT path or the KEY_PLACEHOLDER sentinel. The orchestrator should have used the Settings UI (which uses `***` correctly via the SettingsPage form), not bypassed it with direct API calls. Documented in `075.3-02-UAT.md` "Mid-UAT recovery note (operator)" for the next orchestrator iteration.
- **Future hardening (deferred):** Backend could reject `__KEEP__` / any value matching `^_+[A-Z_]+_+$` as a foot-gun guard. Out of scope for Plan 02; should be a SEED if it reproduces.

### Assertion 4 PARTIAL — Recipe-Author Contradiction

**3. [Documented PARTIAL, not a deviation per se] Assertion 4 upstream-streaming sub-requirement structurally unsatisfiable**

- **Found during:** Wave 4 UAT Assertion 4
- **Issue:** The UAT recipe note (c) (lines 21 of 075.3-02-UAT.md) explicitly chose `gemini-99-flash` because it's `obviously synthetic model_id so no risk of accidental production billing`. But Assertion 4 demands the assistant streams a non-empty reply — which requires a real upstream that accepts the model_id. Google's API correctly 404'd: `models/gemini-99-flash is not found for API version v1main`.
- **What was satisfied:** Plan 02's local-path contract is fully verified — the request reached the Google upstream (proves provider inference + active-provider fallback + safe-defaults application all worked), `runs` row created, `_accumulate_chunk_usage` ran via the `provider="google"` branch (proves Plan 01 + Plan 02 integration). The chip rendered, the warn fired once, dedup held, restart reset the dedup. **6/7 STRICT PASS** captures the actual Plan 02 contract closure.
- **What was NOT satisfied:** End-to-end content stream — the upstream rejection means the user does not see assistant text. NOT a Plan 02 code defect; it's a recipe-author contradiction.
- **Recommended future re-UAT:** Use a real-but-unregistered model_id (e.g., a freshly-released Gemini variant before MODEL_CAPABILITIES catches up — the actual production scenario this plan is designed for). A pinned reproduction harness with a vendor-mocked endpoint would close the strict criterion without depending on vendor release timing.

**Total deviations:** 1 auto-fixed (Rule 1 — Bug, regex tagging error) + 1 operator recovery (orchestrator UI-bypass, NOT Plan 02 defect) + 1 documented PARTIAL (recipe-author contradiction, NOT Plan 02 defect)
