<domain>
## Phase Boundary

Two-plan bundle:

- **Plan 01 — Defensive chunk handler + Google token accounting.** Stop dropping content chunks when `chunk.usage` is populated in `_on_chunk_openai` at `backend/app/api/threads.py:1806-1816`. Add a provider-aware usage accumulator (Google = overwrite-last-wins for cumulative per-chunk usage; OpenAI / OpenRouter = `+=` for final-chunk-only emission). Revert the Path A `stream_options.include_usage` gate at `backend/app/services/openai_service.py:886-893` so Google runs repopulate non-NULL `runs.input_tokens` / `runs.output_tokens`.

- **Plan 02 — Unknown-model graceful degradation.** `get_model_capability(unknown_id)` in `backend/app/config.py:157-159` returns a pattern-inferred provider + safe defaults instead of `{"provider": "unknown"}`. Emits a `model_capability_unknown` warning log. The Settings UI shows an "unverified — using safe defaults" badge next to unregistered model_ids in the main LLM model selector.

<decisions>
## Implementation Decisions

### Plan 01 — Google accumulator strategy
- **D-075.3-01:** Lock the Google cumulative-vs-delta accumulator strategy via a **live repro probe** before planning. Researcher / planner script: one-shot dev call to `gemini-2.5-flash` with prompt `"count to five"`, log `chunk[i].usage` raw (`prompt_tokens`, `completion_tokens`) for every chunk. Pin the result (cumulative running totals OR per-chunk deltas) in `075.3-01-PLAN.md` before any code change. Wrong assumption silently corrupts `runs.input_tokens` / `runs.output_tokens` for every Google run.
- **D-075.3-02:** Default expectation is `overwrite-last-wins` (community consensus is Google's OpenAI-compat emits cumulative running totals on every chunk). The probe either confirms or flips this; planner pins whichever wins.

### Plan 01 — Handler shape
- **D-075.3-03:** `_on_chunk_openai` takes an explicit `provider: str` argument (or closure-captured `active_provider_name`). Branch: `if provider == "google": overwrite-last-wins else: +=`. Readable, single source of truth, unit-testable. No shape-detection magic.
- **D-075.3-04:** Remove the unconditional `return` at `threads.py:1816` after the usage accumulation block. Chunks carrying both `usage` AND `delta.content` / `delta.tool_calls` must continue through the existing `delta.content` / `delta.tool_calls` processing.
- **D-075.3-05:** Revert the Path A gate at `openai_service.py:886-893` — `stream_options = {"include_usage": True}` enabled for all providers including Google. Path A's purpose (restore Google content delivery at the cost of NULL token rows) is superseded by the defensive handler. Restore non-NULL Google token rows is SC#3.

### Plan 02 — Unknown-model inference
- **D-075.3-06:** Inference patterns locked per ROADMAP SC#4 — `gpt-*` / `o1` through `o9` → `openai`; `claude-*` → `anthropic`; `gemini-*` → `google`; any slash-bearing `*/*` → `openrouter`; everything else → `ollama`. Case-insensitive prefix match. Implementation: ordered list of `(regex, provider)` tuples in `config.py` adjacent to `MODEL_CAPABILITIES`.
- **D-075.3-07:** Safe-default table per inferred provider, locked per ROADMAP SC#4 — `max_output_tokens`: 8192 (openai / anthropic / google) or 4096 (openrouter); 8192 for ollama (consistent with Big-3); `llm_call_timeout_seconds`: 90 (all); `native_tools`: True (openai / anthropic / google), False (openrouter / ollama).
- **D-075.3-08:** `get_model_capability` becomes: registry hit → return verified caps; registry miss → compute inferred provider + safe defaults, emit `model_capability_unknown` warning (subject to D-075.3-09), return the inferred dict.

### Plan 02 — Warning log
- **D-075.3-09:** `model_capability_unknown` warning fires **once per process per model_id**. Implementation: module-level `set[str] _WARNED_UNKNOWN_MODEL_IDS` populated at first lookup. Subsequent lookups stay silent until process restart. Log format: `logger.warning("model_capability_unknown model_id=%s inferred_provider=%s safe_defaults_applied=True", model_id, provider)`.

### Plan 02 — Settings UI badge
- **D-075.3-10:** Badge placement: **inline next to each item in the main LLM model dropdown** in `SettingsPage.tsx` AI Model section (around lines 530-609). Badge also appears next to the currently-selected `llmModel` label. Renders only for model_ids that hit the inference fallback path (i.e., not in `MODEL_CAPABILITIES`).
- **D-075.3-11:** Badge scope: **main LLM model selector only**. Sub-agent model picker (`subAgentModel`) and per-provider model-list inputs (`providerStates[*].models` comma-separated free text) stay unbadged in this phase. Sub-agent badging is a candidate follow-up if the unverified surface broadens.
- **D-075.3-12:** Badge text: `"unverified"` chip (short label). Hover / tooltip: `"This model isn't in our verified registry. Using inferred provider: {provider}. Safe defaults applied (max_tokens={n}, timeout=90s)."` Visual style: muted/yellow `ghost-border`-style chip consistent with the existing AI Model section visual language.
- **D-075.3-13:** Backend exposure: extend the `GET /api/settings` response (or `/api/models` endpoint, whichever currently serves the dropdown) to include a per-model `verified: bool` flag (or equivalent `capability_source: "registry" | "inferred"`). Frontend reads the flag and decorates the option element. No new endpoint required if the existing settings payload can carry the flag.

### Plan ordering
- **D-075.3-14:** Plans 01 and 02 are **independent** — no execution dependency between them. They can ship in either order or in parallel waves. Plan 01 alone restores Google token-accounting end-to-end. Plan 02 alone unblocks unregistered model_ids end-to-end. Recommend Plan 01 first because it closes the user-visible bug (already mitigated by Path A) and reverts the temporary gate.

### Tests
- **D-075.3-15:** Pytest layered across both plans + Chrome MCP UAT per SC#7 (NOT lean / NOT pytest-only).
- **D-075.3-16:** Plan 01 unit tests in new file `backend/tests/unit/test_chunk_handler_provider_aware.py`:
  - Google-shape stream (every chunk has `usage` AND `content`) → no content dropped; final token counts match the cumulative-mode contract pinned by D-075.3-01 probe.
  - OpenAI/OpenRouter-shape stream (final-chunk-only `usage`, empty `choices=[]`) → token counts accumulate correctly via `+=`; no content path regression.
  - Mixed shape: chunk with `usage` only (no choices) → tokens read, no `delta` processing crash.
- **D-075.3-17:** Plan 02 unit tests in new file `backend/tests/unit/test_get_model_capability_inference.py`:
  - All 5 inference branches: representative ID per bucket (`gpt-99`, `o5`, `claude-future-5`, `gemini-99-flash`, `nodelta/some-model`, `unknown-no-slash-no-prefix`).
  - Boundary cases: `None` / empty string / case variations / whitespace-only model_id (must NOT crash; degrade to ollama bucket or raise a clear ValueError — locked at planner level).
  - `warn-once` dedup: invoke `get_model_capability("gemini-99-flash")` three times in a row → assert `logger.warning` called once. Reset dedup via module-state fixture between tests.
  - Registered model_ids (`gpt-4o`, `claude-sonnet-4-6`) still return verified caps unchanged (regression).
- **D-075.3-18:** Frontend badge test in new file `frontend/src/__tests__/components/SettingsModelBadge.test.tsx` (or extend `SettingsPage.test.tsx` if it already exists): render dropdown with mixed registered + unregistered model list → assert `unverified` chip appears only on unregistered items + on the currently-selected label when it's unregistered.
- **D-075.3-19:** Chrome MCP UAT per SC#7: 5 Gemini models (`gemini-2.5-pro`, `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemini-3-flash-preview`, `gemini-3.1-pro-preview` — `gemini-3.5-flash` is the 6th since recent add) — assert content streams + `runs.input_tokens` / `runs.output_tokens` non-NULL post-completion. <specifics>
## Specific Ideas

- "Live repro probe first" wins because we can't afford a silently-wrong cumulative-vs-delta guess — the symptom is wrong token counts in production DB, hard to notice from the UI.
- The defensive handler should look like the explicit `if provider == "google":` branch — vibe-coder readability matters more than future-proofing for hypothetical new compat layers.
- Once-per-process warn dedup is the "clean operator triage" path — operator sees one row per session per unknown model, not 12+ rows per agent run.
- "Inline in dropdown" badge wins because the user wants to see status BEFORE they save the change, not after. Banners only fire after commit.
- Bug routing reconfirmed: BUG-260522-01 stays in 082.5 surface; BUG-260522-02 is a separate data-layer fix surface that should NOT bundle into 075.3 even though it touches the same `threads.py` file.

</specifics>
