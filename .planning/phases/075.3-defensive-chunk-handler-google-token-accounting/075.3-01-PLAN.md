**Why CUMULATIVE is locked despite inconclusive probe:**

1. **260522-gdg evidence is decisive on the multi-chunk question.** The original bug captured Gemini splitting `"hi"` across 2 chunks BOTH with `has_usage=True`:
   ```
   chunk[1]: delta.content='Hello', finish_reason=None, has_usage=True
   chunk[2]: delta.content='! How can I help you today?\n', finish_reason='stop', has_usage=True
   ```
   Multi-chunk usage emission DOES occur — the probe just can't reliably reproduce it (Google batches small responses; chunking is non-deterministic).

2. **Community consensus** (RESEARCH.md §"Sources, Secondary (MEDIUM confidence)" lines 928-932): Google OpenAI-compat layer is widely understood to emit cumulative running totals on every streaming chunk. LiteLLM Issue #25389 + llama_index Issue #18096 + ai.google.dev forum thread #92785 all consistent with cumulative semantics.

3. **Asymmetric risk profile** (Plan 01 threat model T-075.3-01-01):
   - If `+=` is locked AND Google emits cumulative: silent over-counting (`runs.completion_tokens` reads 2-3× actual usage). Inflates token spend, breaks per-user accounting fidelity.
   - If overwrite-last-wins is locked AND Google emits delta: under-counting (last delta only). Equally broken accounting fidelity.
   - Both wrong directions are bad, but cumulative-over-counting matches the **observed compat-layer behavior** per (1)+(2).

4. **Defensive future-proofing** locked via test `test_google_cumulative_accumulator_matches_probe_shape` (D-075.3-16): asserts that a synthetic Google-shape chunk sequence `[(p=5,c=3), (p=5,c=8), (p=5,c=12)]` produces `(input=5, output=12)` — i.e., overwrite-last-wins behavior. If Google ever flips to delta semantics, this test will fail loudly during the next CI run.

**Implementation lock (D-075.3-03):**
- `_accumulate_chunk_usage(chunk, provider, input_total, output_total)`:
  - Google branch: `return _i, _o` (overwrite-last-wins; ignores previous totals)
  - OpenAI/OpenRouter branch: `return (input_total or 0) + _i, (output_total or 0) + _o` (`+=` accumulate)
