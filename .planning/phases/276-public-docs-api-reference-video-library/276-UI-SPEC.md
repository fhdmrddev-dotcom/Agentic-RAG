## Typography

Four sizes, two weights. [S-B normalised to the checker's 4-size / 2-weight rule]

| Role | Size | Weight | Line Height | Font | Used for |
|------|------|--------|-------------|------|----------|
| Label | 14px | 400 (600 for pills, button text, crumb current) | 1.5 | Inter | Nav links, breadcrumbs, card blurbs, article meta pills, honesty badges, captions, table cells, inline + block code (JetBrains Mono), search results meta, footer |
| Body | 16px | 400 (600 for card titles, release titles, H3, `<strong>`) | 1.7 prose / 1.5 UI | Inter (Manrope for card + release titles and H3) | Article prose, lead paragraphs (colour `muted`), hero sub-copy, list rows, search result titles |
| Heading | 24px | 600 | 1.25 | Manrope | Article H2, home section titles ("Start with a guide"), big bento card title |
| Display | 40px | 600 | 1.15 | Manrope | Every page H1 at every width — **including the docs-home hero H1** — article, stub, section index, changelog, API reference intro, docs 404 |

Exceptions: **none.** The docs entry renders text at exactly 14 / 16 / 24 / 40 px and weights 400 / 600. No other size or weight appears on any docs page.

- The docs-home hero H1 uses the 40px Display size at all widths (with `letter-spacing: -0.02em` and the gradient second line). Sketch B drew it at 64px. **Source correction:** the landing's 64px is **not** in `landing.css`. It is an inline `fontSize: 64` (weight 800) on the landing hero headline in `frontend/src/landing/components/HeroSection.tsx:69`. `landing.css` only carries the mobile override `.h1 { font-size: 40px !important }` at ~line 794. The docs reuse neither that headline nor the `.h1` class. Hierarchy on the home hero comes from the gradient line, the glow and the 880px video below it, not from size. [S-B normalised][CD]
- Eyebrows ("Docs", "Changelog", "Chapter 2") render at **14px** / 600 / JetBrains Mono / uppercase / 0.08em via the docs.css override of `.eyebrow` (below).
- The `/` keyboard hint (`.d-kbd`) renders at **14px** / 400 / JetBrains Mono (Label), `padding: 0 4px`, 1px border, radius 4.

**Reused landing classes are pinned.** `docs.css` re-declares the size (and, where needed, the weight) of every landing class the docs entry reuses, so the landing's off-scale values (13 / 15 / 12 / 11 / 10 / 9 px; weights 500 / 700 / 800) cannot leak into a docs page. The docs entry reuses **only** these landing classes and components:

| Reused from landing | Landing value | Pinned in docs.css (scoped under `.docs-root`) |
|---|---|---|
| `.wrap` | no type | unchanged (layout only) |
| `.btn` | 14px / **500**, height 40 | 14px / **600**, height 40 (36 where this spec says 36) |
| `.btn-primary` | 14px / 600 | 14px / 600 (restated) |
| `.btn-outline` | 14px / 500 | 14px / **600** |
| `.btn-lg` | **15px**, height 44 | **not used by docs** (see the drawer button) |
| `.eyebrow` | **12px** / 600 mono | **14px** / 600 mono |
| `.hl` | family only | Manrope; size always set by role (16 / 24 / 40) |
| `.mono` | family only | JetBrains Mono; size always set by role (14) |
| `.grid3` | no type | unchanged (layout only) |
| `Navigation` component | links 14px inline; brand text 16 / 700 | links stay 14; the brand text is **replaced by the SVG lockup** (D-14), so no 16 / 700 text remains |
| `LandingFooter` component | **13px** inline | changed to **14px** inline in the logo-pass commit (landing and docs share it) |

Any other landing class (`.h1`, `.h2`, `.cmp`, `.tab`, `.pip*`, `.facts`, scene classes …) is **not** used in `src/docs/`. A docs component that needs a look writes a `d-` class on the scale instead. The landing page keeps its own sizes: the pins are scoped under `.docs-root` (the docs entry's root element) and never change the landing.

Rules:
- One H1 per page. Article H3 = Body size at 600 in Manrope; no H4+ in authored Markdown (the build warns). [CD]
- Body text colour in prose: `hsl(226 30% 86%)` (`#D3D9E8`, sketch `.prose`); headings `fg`. [S-B]
- Gradient text (`primary → violet-text`) is used on exactly two strings: the second line of the docs-home hero H1 and "not promised." in the changelog H1. [S-B]
- Lead paragraph under an article H1: 16px, colour `muted`, `margin-bottom: 24px`. (Sketch used 19px; normalised to Body to hold four sizes.) [CD]

**Accent `#A3A5FF` is reserved for exactly:**
1. Text links in prose and "→" links ("Full changelog →").
2. The "Book a demo" primary button (inherited `.btn-primary`).
3. The search box focus ring (`0 0 0 4px hsl(239 100% 82% / .12)` + border `/.55`) and the global `:focus-visible` outline.
4. The active item in the TOC pill (text + 2 px left border).
5. `.eyebrow` labels (pinned in docs.css).
6. Version numbers in the changelog (mono).
7. The play-button disc (gradient primary → violet) on every video poster.
8. Hover border on link cards (`hsl(239 100% 82% / .45)`), the selected chapter chip, the highlighted search result row background (`/.10`).

**`dim` `hsl(220 14% 45%)` (3.9:1 on bg) is NEVER used for text** — the sketch used it for crumbs, dates and meta; all of those move to `muted`. `dim` may only be used for decorative strokes (e.g. a divider). [CD — WCAG 1.4.3]

## Accessibility contract

- **Landmarks**: `header` (banner), `nav aria-label="Main navigation"`, `nav aria-label="Breadcrumb"`, `main id="content"`, `footer`. `lang="en"` on `docs.html`.
- **Headings**: exactly one H1 per page; H2 → H3 order; TOC lists H2 only.
- **Keyboard**: everything reachable by Tab in visual order; drawer and search dialog trap focus and restore it on close; Esc closes drawer / dialog / dropdown / TOC; `/` shortcut ignored while typing in a field.
- **Focus visibility**: global `:focus-visible` rule (above); the search box keeps its 4px ring as well.
- **Contrast**: text uses only `fg`, `#D3D9E8` prose, `muted` (≥ 7:1), `primary` (8.9:1), amber, green on the dark background. `dim` is never text.
- **Motion**: `prefers-reduced-motion: reduce` disables promo autoplay, hover translate/scale, smooth scrolling, drawer slide and loading pulses. User-started videos still play.
- **Auto-moving media**: the promo always shows Pause; it is muted until the user unmutes; it pauses off-screen and in hidden tabs.
- **Media alternatives**: Remotion narrated slots carry "Read the transcript" where a VO script exists; YouTube slots rely on YouTube captions (NotebookLM audio) — recorded as a known limit, not hidden.
- **Touch**: 44px minimum hit areas on phone for the controls listed under Spacing exceptions.
- **Live regions**: search result counts (`polite`), loading lines (`role="status"`), load errors (`role="alert"`).
- **Images**: posters `alt=""` (the button carries the label); screenshots carry a descriptive `alt` written in the Markdown; the logo lockup link has `aria-label="Syrel home"` and the SVG is `aria-hidden`.

## How we'd know this UI failed (G-6, design side)

- Any docs page at 390 px has horizontal scroll, a clipped table/code block, or a TOC pill that hides the pager.
- A video frame, "coming soon" box or broken embed appears for a slot with no video.
- A YouTube, `i.ytimg.com` or Remotion request appears in the network panel before the reader presses play (docs) or scrolls (landing).
- The promo moves without a visible Pause, plays with sound before the user unmutes, or autoplays under reduced motion.
- A stub is reachable only by URL (missing from its section index, the drawer section path, or search).
- A v4.5 feature page lacks the badge or the callout, or any page says Word/PDF can be previewed in-app.
- The docs look like a different product from the landing (different header, fonts, colours, or logo).
