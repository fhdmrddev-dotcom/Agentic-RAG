# Phase 071.4 Plan 04: `/reingest` accumulation fix — BUG-260516-04 closed, SEED-022 mitigation unmasked

**The Reingest button no longer triples your `document_tables` and `document_images` rows on every click. The 4-line fix also unmasked a 4.4x precision-floor win that was hidden under the accumulation noise.**

## Performance

- **Started:** 2026-05-16 mid-Plan-01-verification (when accumulation pattern became obvious)
- **Completed:** 2026-05-16 after operator verification reingest matched predictions ±0%
- **Tasks:** 4/4
- **Files modified:** 4 (2 code, 2 docs)
- **Duration:** ~45 min total

## Accomplishments

1. **Fixed `/reingest` endpoint** at `backend/app/api/documents.py:688-697`. Two `run_in_threadpool` delete calls now run between the storage download and the status update, mirroring `/reextract`'s cascade. Commit `7c0d189`.

2. **Added regression test** `test_reingest_deletes_prior_tables_and_images` at `backend/tests/integration/test_documents.py`. Asserts `.delete().call_count` increases by ≥2 across the endpoint body AND `supabase.table('document_tables') / supabase.table('document_images')` both appear in the call history. Pre-fix the test would have failed (0 delete calls); post-fix it passes. Existing `test_reingest_wraps_extract_in_threadpool` updated to account for the 4-entry side_effects list (was 2). Commit `4ac8378`.

3. **Operator-confirmed verification reingest** on the user's thesis PDF + DOCX after SQL cleanup. Counts landed at:

   | | Predicted | Actual |
   |---|---|---|
   | PDF: tables / images / chunks | ~48 / ~20 / ~441 | **48 / 20 / 441** |
   | DOCX: tables / images / chunks | ~39 / ~20 / ~402 | **39 / 20 / 402** |

   All within ±0% of predictions. The /reingest delete cascade works.

4. **Unmasked the SEED-022 precision-floor magnitude.** With the accumulation gone, the fresh-per-extract PDF count is **48** — down from 214 pre-floor. That's a **4.4x reduction (78%)**, much better than the predicted 80-120 range. Only ~9 false positives remain that have ≥2×2 shape and survive the floor — likely formula blocks or multi-row aligned text. SEED-022 updated to reflect the new magnitude and to downgrade the Phase 076 prerequisite from "must address" to "nice-to-have."

## Decisions Made

- **Insert Plan 04 mid-phase, not defer.** When the +48-per-click pattern surfaced during Plan 01 Task 3, the choice was: (a) capture as a bug and continue with the original 3 plans, or (b) fold a fourth plan into 071.4 right now. Chose (b) because the bug actively corrupts data on every operator click — leaving it for a future phase means users continue to pollute their library while waiting. Plan 04 added with operator approval (chat record 2026-05-16).
- **Chunks NOT added to /reingest delete cascade.** `_upload_pipeline` already cleans chunks downstream before re-insert (proven by chunks staying stable at 441 across the polluted reingests). Adding a redundant chunks delete would be correct-but-wasteful. /reextract's chunks delete remains because /reextract takes an explicit engine override and needs the cleanup upstream of the BackgroundTask.
- **No documentation changes to D-v2.6-04 in PROJECT.md.** The Phase 071 decision said /reextract deletes chunks + tables + images. /reingest should have always mirrored that contract; this fix corrects an oversight in the Phase 071.2 D-071.2-06 port rather than changing the documented behavior.

**None — plan executed as written.** The 4-LOC fix landed where predicted; the regression test asserts the predicted behavior; the operator verification matched ±0%.

## Issues Encountered

- The existing `test_reingest_wraps_extract_in_threadpool` test broke under my fix because its mocked side_effects list expected only 2 supabase `.execute()` calls (owner SELECT + UPDATE). With the new delete cascade, the test needed 4 entries (SELECT + DELETE tables + DELETE images + UPDATE). Updated the list inline; documented the order in a comment for future maintainability.
- My first regression-test version asserted `mock_builder.table.call_args_list` but that's an empty list because `.table()` is called on the supabase mock (`_supabase`), not on the builder (`_builder`). Fixed by importing `_supabase` from conftest and inspecting `_supabase.table.call_args_list`.
