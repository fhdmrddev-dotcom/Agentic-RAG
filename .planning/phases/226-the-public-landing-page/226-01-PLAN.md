<threat_model>
ASVS L1 Threat Assessment:
- Threat: Information disclosure or credential leakage via marketing page bundle (e.g. Supabase anon key, auth session handlers, internal API routes bundled on a public marketing surface).
  Mitigation: Strict architectural separation via separate Vite HTML entry point (`landing.html`). Zero imports from `@/lib/api`, `@supabase/*`, or auth providers into `src/landing/`. Enforced by automated static analysis test `landingBundleFence.test.ts`.
- Threat: Open redirect or path confusion on root routing (`/` vs `/app`).
  Mitigation: Vercel rewrite explicitly isolates `/` to `landing.html` while preserving wildcard SPA fallback to `index.html`. Application navigation explicitly uses `/app` or `/login`.
- Threat: Uncontrolled external redirects from CTAs.
  Mitigation: `VITE_DEMO_URL` and `VITE_APP_URL` are sanitized string environment variables; when unset, `VITE_DEMO_URL` falls back to internal anchor `#start` and `VITE_APP_URL` falls back to relative `/login`.
</threat_model>
