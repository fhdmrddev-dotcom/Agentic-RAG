- Cumulative file count badge in RunCard header from `tc.result` JSON parsing of `output_files` arrays

## Decisions Made
- runError is only available for live-streamed runs because the backend messages response does not yet include runs.error. Historical/reloaded runs show generic "failed" -- this is intentional graceful degradation, not a bug. A future phase can add runs.error to the threads.py messages query (requires threads.py change, deferred per G-5).
- Text dedup uses exact paragraph match only (no fuzzy matching) with >20 char threshold to avoid collapsing separators or short repeated tokens. This is conservative by design per D-07.
- File count checks both "done" and "running" tool status values because tool calls may have output_files in their result while still being processed.
