<decisions>
## Implementation Decisions

### Auto-scroll Strategy
- **D-01:** Auto-scroll to active tool panel ONLY when user is already at or near the bottom of the chat (within ~100px threshold). If the user has manually scrolled up to read earlier content, do NOT move them. This matches Claude.ai and ChatGPT behavior — scroll follows new content only when the user is "following along."
- **D-02:** `scrollIntoView` targets the tool panel body element (the `ToolCallPanel` or `ExecuteCodeEditorInset` wrapper) for the active tool. This puts the streaming code preview in the viewport center. Use `{ behavior: 'smooth', block: 'nearest' }` to avoid jarring jumps.

### Sticky Timer Placement
- **D-03:** Sticky elapsed timer renders as a compact bar **above the input box** during active runs. Content: `⏱ {elapsed} · Step {N} · {fileCount} files · {currentActivity}`. Auto-hides when run completes. Does NOT cover message content — sits between the message list and the input area. Proposed layout from the master findings document (Section 4, Stuck Moment #4).

### DeepSeek API Integration
- **D-04:** Reuse the existing provider tab pattern in Settings UI — same component structure as OpenAI/Anthropic/Google tabs. Same API key field pattern, same model list component. Minimal new frontend code.
- **D-05:** Hardcoded model list in MODEL_CAPABILITIES: `deepseek-v4-pro` (flagship, timeout 900s, max_output 65536), `deepseek-chat` (fast/cheap, sub-agent default), `deepseek-reasoner` (reasoning model). Users can type custom model IDs for unlisted models. Same discovery pattern as OpenAI/Anthropic.
- **D-05b:** `_PROVIDER_BASE_URLS["deepseek"] = "https://api.deepseek.com/v1"`. `DEEPSEEK_API_KEY` env var. `_SUB_AGENT_MODEL_DEFAULTS["deepseek"] = "deepseek-chat"`. Routing: `MODEL_CAPABILITIES[model]["provider"] == "deepseek"` → direct API; no `provider` match → OpenRouter fallback unchanged.

### Error Categorization
- **D-06:** Frontend pattern matching for error categorization — a utility function that maps common substrings in `runs.error` to user-friendly labels. No backend schema changes. Patterns: `timeout` / `timed out` → "Timed out", `exceeded` / `truncat` → "Output limit reached", `code` / `execution` / `sandbox` / `error` → "Code execution failed", `cancelled` → "Cancelled", fallback → "Run failed". Displayed as tooltip on the failure badge or inline in the RunCard collapsed header.

### Text Dedup Algorithm
- **D-07:** Render-time dedup at the paragraph level. Before displaying `message.content` in MessageItem, split by `\n\n`, detect consecutive identical paragraphs (exact string match after trimming whitespace), collapse to single occurrence. Raw data in StreamsProvider preserved unchanged. Minimum paragraph length threshold: >20 characters (avoids collapsing short repeated tokens like "---" or blank lines).

### Status Labels
- **D-08:** `execute_code` tool cards show "Generating code" with a code-streaming icon during `preparing` state, and "Executing code" with a play/run icon during `running` state. Other tool types keep existing labels ("Preparing {toolName}..." during `preparing`, tool-specific during `running`).
- **D-09:** Replace "queued" suffix in RunCard footer (RunCard.tsx:273-284) with an elapsed counter when delta events are arriving (LLM is active). Format: "{Ns}" counting up. When no deltas arriving (genuine inter-iteration wait), show "waiting..." instead of "queued".

### Google Atomic Args
- **D-10:** For providers with atomic tool arg delivery (Google), the `preparing` state shows "Waiting for model..." with a visible elapsed counter (same as D-09 pattern). No byte-count badge and no empty code panel. Detection: if `tc.argsBytesStreamed` is null/0 AND `tc.status === "preparing"` for >2s, switch to "Waiting for model..." label.

### Claude's Discretion
- Text dedup edge cases (near-duplicates, partial matches) — exact-match-only is fine for v1
- Sticky timer animation/transition on appear/disappear
- Auto-scroll `scrollIntoView` options (`block: 'nearest'` vs `'center'` vs `'start'`)
- Whether to show cumulative file count in the sticky timer bar or only in the RunCard header

</decisions>
