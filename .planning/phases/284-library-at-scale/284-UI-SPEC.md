# Phase 284 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**What this contract does.** Phase 284 changes where the Library's numbers and rows come from. It does
not change what the screen looks like. The pager, stat tiles, folder tree, detail panel and picker
dialogs are all shipped layouts. CONTEXT D-26 skipped the G-2 sketch because of that. This contract therefore
**locks the shipped visual system** and specifies **only the new or changed states**:

1. Loading and load-failed states for the Library list, the IngestionTab lists and every number (D-12, SEED-248 Library half).
2. Header, folder, root and tile numbers become server totals. The "may be larger" arm is deleted (D-07, D-09).
3. The pager runs in `exact` mode for browse, saved views, ad-hoc filters and ingestion lists (D-09, D-10, D-13).
4. The Chunks section loads the next page when its bounded region is scrolled to the end. There is no button (D-17, the Phase 283 rule).
5. Tables, Images and Versions show "N of M" when they do not show everything (D-17).
6. Picker typeahead runs on the server in CreateLinkDialog, LegalHoldDialog and StructurePopovers' RelationshipEditor. Takeoff's spreadsheet list is a bounded read (D-15, R-05).

**Out of scope here (not specified, not to be built):** bulk actions, folder-tree search, new filters,
virtualisation, any new layout, any new colour, any new component family (CONTEXT `<deferred>`, SEED-352).

**The one rule every state below obeys:** *zero is a claim about an answer, so it is only made once
there is an answer.* No surface may render "0", "No documents…", "Nothing…" or an empty list while
its request is in flight or after it failed. (Precedent: `DocumentsFindBody.tsx` `isZero`, Phase 271 S7.
Seed: SEED-248 "populated ≠ empty ≠ loading ≠ error".)

## Typography

This phase introduces **no new type role**. All new copy (loading, error, "N of M", picker status
lines) uses only the two smallest shipped roles. Larger roles are inherited and not edited.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Body | 14px (`text-sm`) | 400 | 1.5 (Tailwind `text-sm` 20px) | alert sentences, empty copy, the list's skeleton status text |
| Label | 12px (`text-xs`) | 400 (600 for an emphasised count, e.g. FindMetaLine's total) | 1.33 (16px) | pager line, picker status lines, "N of M" lines, "Try again" links, header pill |
| Heading | 18px (`text-lg`) | 600 | 1.2 (`leading-tight`) | IngestionTab section headings: inherited, not edited |
| Display | 24px (`text-2xl`, `font-mono` on tiles) | inherited 700 | 1.2 | stat-tile number and page `h1`: inherited, not edited |

Weights used by new copy: **400 and 600 only.** The tile number and `h1` ship at 700. This phase only
changes the value they render, not their class.

Inherited micro-sizes in the detail panel stay byte-identical: chunk body `text-[0.7rem]` mono,
model chip `text-[0.65rem]`, tile label `text-[11px]` uppercase, Takeoff `text-[11px]`. New lines inside
the detail panel use `text-xs`, the Conversation section's shipped "showing the first N" line.

Numbers: every count of 1,000 or more renders with grouping separators (`10,000`, never `10000`).
To get this, pass `n.toLocaleString()` into `AnimatedNumber`. `LibraryStatTiles` CHUNKS already does this.
Counts keep `tabular-nums`.

## Loading vocabulary (the one set every surface uses)

| State | Treatment | Shipped source reused |
|-------|-----------|-----------------------|
| **Cold load** (no rows for this list yet) | `role="status" aria-live="polite"` wrapper, `sr-only` sentence, N skeleton bars `h-10 w-full animate-pulse rounded-md bg-border/30` (`aria-hidden`), `gap-2` | `DocumentChunksSection.tsx` loading arm |
| **Warm, user-initiated reload** (page change, rows-per-page change, sort) | rows stay; wrapper `aria-busy="true"` + `transition-opacity opacity-60` until the answer lands | `DocumentsFindBody.tsx` `find-results` wrapper |
| **Background reload** (a Realtime-triggered refetch, D-08) | **silent**: no dim, no `aria-busy`, no skeleton. Rows and numbers swap when the answer lands. `AnimatedNumber` does not re-animate an equal value (D-v2.5-03) | `AnimatedNumber.tsx` |
| **Unknown number while loading** | `…` | `LibraryStatTiles.tsx` VECTORS arm |
| **Unknown number after a failure** | `Not known yet` (number slot), `—` (description slot) | `LibraryStatTiles.tsx` `UNKNOWN` |
| **Count slot with no answer** | omitted (`count={undefined}`), never `0` | `NavRow.tsx` "pass undefined to omit" |
| **Inline "Searching…"** | `text-xs` muted, `role="status"` | `FindMetaLine.tsx` |

Why background reloads are silent: ingestion emits an UPDATE per step. If every debounced refetch dimmed
the list, the Library would flicker for the whole length of an upload. The content on screen stays
readable and current enough. The dim is only for waits the person caused.

A folder or view **switch** is a cold load, not a warm one: the previous rows belong to a different
list, so they must not stay on screen under the new folder's header. A **page** change within the same
list is warm.

## State Matrix — Library surfaces (D-07, D-09, D-10, D-12, D-13)

`summary` = `GET /library/summary` (R-03). `page` = `GET /documents` envelope `{documents,total,offset,limit}` (D-01).

### S1. Documents list (Root, a folder, a saved view, an ad-hoc filter)
Component: `LibraryPage.tsx` `documentSurface` → `DocumentList.tsx` (7-column order untouched) + `DocumentsPager.tsx`.

| State | What renders |
|-------|--------------|
| Cold loading | Inside `data-testid="documents-doclist"`: the cold-load block with **6** bars and `sr-only` "Loading documents". No `DocumentList`, no empty copy, no pager, no ArchivedHiddenLine. |
| Populated | `DocumentList` with the server page in server order (no client slice: `pagedDocuments` slicing is removed) + pager (S2). |
| Warm loading | Previous page rows dimmed (`opacity-60`, `aria-busy`), pager still shown with the previous total. |
| Empty (success, `total === 0`, nothing archived-hidden) | Shipped `DocumentList` copy, verbatim: Root → "No root documents yet." · folder → "No documents in this folder" · second line "Upload files above to add them here." A saved view or filter keeps its shipped zero copy. |
| Empty but archived hidden (success, `total === 0`, archived > 0) | Shipped 275-05 rule: no list, only `ArchivedHiddenLine` (count from `summary`). |
| Error, cold (no rows) | Page-level alert in place of the list: **"Couldn't load documents. This is a loading error, not an empty folder."** + **"Try again"**. No empty copy, no pager. |
| Error, warm (rows on screen) | Rows stay (Find rule S7: an error never swaps the list). Above the list, a page-level alert: **"Couldn't refresh this list. The rows shown may be out of date."** + **"Try again"**. |

A saved view or ad-hoc filter that fails cold uses the same alert with "not an empty view" in place of
"not an empty folder": **"Couldn't load documents. This is a loading error, not an empty view."**

### S2. Pager (browse, views, filters): exact mode
Component: `DocumentsPager.tsx`.
- Browse, view and filter callers pass `exact` and the server `total`.
- **The `ROW_CAP = 1000` arm is deleted** (D-09): the `capped` flag, the `+` suffix, and the line
  "The list may be larger than shown — the library has N+ rows." No caller can produce it any more, and
  that string must not exist in `frontend/src` after the phase.
- Line format (unchanged shape): `Rows per page: [25] · 1–25 of 10,000 · ‹ Previous  Next ›`. Numbers are grouped.
- Rows-per-page options stay `10 / 25 / 50 / 100`, default 25 (D-02's server max of 200 is not offered in the UI).
- Changing rows-per-page resets to offset 0 (shipped). A page change is a warm reload of S1.
- Hidden while S1 is cold-loading or errored-cold, and when `total === 0` (shipped `return null`).
- Last page: `Next` is disabled once `offset + limit >= total` (shipped). G-4 B checks that the last row is the folder's oldest document.

### S3. Header pill (`LibraryHeaderBar.tsx`)
| State | Copy |
|-------|------|
| In flight > 0 (from `summary.status.pending + processing`, R-04) | shipped: `Loader2` + "Reading N file(s)", sky style |
| Idle, summary loaded | shipped: "N document(s)" (`summary.total`, grouped) |
| Summary loading | **"Counting…"** (idle pill style, no spinner) |
| Summary failed | **"Count not known yet"** (idle pill style) |

The pill never shows "0 documents" or "Nothing reading" before the summary has answered.

### S4. Folder tree counts (`FolderTree` → `NavRow.tsx`) and Root count
- Loaded: `summary.folders[id].count` / `summary.root.count`, grouped.
- Loading or failed: `count={undefined}`, so the slot is omitted (shipped arm). Never `0`.

### S5. Folder detail band (`FolderDetail.tsx`)
Props change from `documents: Document[]` to numbers (`count: number | null`, `sizeBytes: number | null`, plus a load state). The layout is unchanged.
- Loaded: shipped "N document(s)" + formatted size.
- Loading: each of the two number slots renders `…`.
- Failed: the document-count and size spans are replaced by one span, **"Count not known yet"**. The shared badge, subfolder count and Created date stay, because they come from the folder and not the summary.

### S6. Stat tiles (`LibraryStatTiles.tsx`)
Props change to numbers (`chunks`, `documents`, plus a load state).
- CHUNKS value: `summary.chunks.toLocaleString()`. Description: "across N document(s)" with `summary.total`.
- Loading: value `…`, description `…` (the VECTORS arm).
- Failed: value **"Not known yet"**, description `—` (the shipped `UNKNOWN` arm).
- VECTORS and FOUND BY A SEARCH: unchanged (own endpoints; `getReembedProgress().total` is uncapped, RESEARCH fact 7).

### S7. IngestionTab (`IngestionTab.tsx`): layout unchanged (D-13)
- **Stage cards and sub-tab counts** come from `summary` (`status`, `steps`, `rate_limited_in_flight`). Loading: each card number renders `…` and sub-tab count badges are omitted. Failed: numbers render `—`, and one page-level alert sits above the cards: **"Couldn't load ingestion counts."** + **"Try again"**.
- **The queue heading** "(N files)" uses the summary's in-flight total, never the page length.
- **Queue, Needs attention, History lists** read `GET /documents?status=…` pages.
  - Cold loading: the cold-load block with **3** bars and `sr-only` "Loading files".
  - Empty (success only), with the shipped copy verbatim: "Nothing is being read right now." · "Nothing needs attention." · "Nothing has been ingested yet."
  - Error: page-level alert **"Couldn't load this list. This is a loading error, not an empty list."** + **"Try again"**.
  - Paging: the shipped `PaginationControls` (25 per page) with the server total, shown when total > 25. It is applied to all three lists. Queue and Needs attention were unpaged before.
  - History order stays `updated_at` newest first (R-08 `order=updated_desc`). The visible order is unchanged.

### S8. Opening a document that is not on the current page (D-11)
- While `GET /documents/{id}` is in flight, the panel does not open and nothing changes in the list column (no empty panel shell).
- Success: the panel opens as shipped.
- 404: the panel stays closed. This is today's behaviour for an unresolvable id. Copy is uniform, so it cannot confirm whether a document exists.
- Network or 5xx failure: the panel stays closed. A page-level alert above the list reads **"Couldn't open that document."** + **"Try again"**.

## State Matrix — Detail panel per-document lists (D-17)

### S9. Chunks section (`DocumentChunksSection.tsx`): scroll-to-end paging, no button
The bounded region from Phase 283 stays: `role="region"`, `tabIndex={0}`, `max-h-96 overflow-y-auto`,
one Tab stop, no nested scrollers, no per-chunk height cap (283-REVIEW CR-01).

- **Section header count** (`PanelSection` `count`) = the server's exact `total`, not the loaded length. A 2,500-chunk document reads 2,500, not 1,000.
- **First page:** 200 chunks (RESEARCH route inventory, default 200, max 500). Loading, error and empty arms: shipped, verbatim ("Loading chunks" sr-only + 2 bars · "Couldn't load this document's chunks" + Try again · "This document has no indexed chunks").
- **Next page:** a non-focusable sentinel element sits after the last chunk inside the region. When it scrolls into view (IntersectionObserver, `root` = the region) and `loaded < total`, the next 200 load and are appended. Wheel, trackpad, touch, and keyboard scrolling of the focused region (Arrow/PageDown/End) all reach it the same way.
- **While the next page loads:** one skeleton bar (`h-10 animate-pulse rounded-md bg-border/30`, `aria-hidden`) at the end of the list, plus `role="status"` `sr-only` "Loading more chunks". Loaded chunks stay readable.
- **Next page failed:** at the end of the list, `role="alert"` **"Couldn't load more chunks"** in the panel error colour + the shipped panel **"Try again"** button. Loaded chunks stay. "Try again" is the only focusable element added inside the region, and only in this state.
- **All loaded:** no end marker; the header count is the claim.
- **Region accessible name:** `Chunk list, {total} chunks` when everything is loaded, otherwise `Chunk list, {total} chunks, {loaded} loaded`.
- ⛔ There is **no "Show all" button and no "Load more" button** (the Phase 283 rule; CONTEXT D-17).

### S10. Tables, Images, Versions: "N of M" when not all are shown
Each list reads one bounded page with the exact total. Planner-set defaults, taken from RESEARCH as
working values: tables 50, images 100, versions 50. The planner may change these numbers but not the copy.

| Surface | Header count | "N of M" line (only when N < M) | Placement |
|---------|-------------|----------------------------------|-----------|
| `DocumentTablesSection.tsx` | `PanelSection` count = M | **"{M} tables in this document, showing the first {N}"** | top of the section body, `text-xs text-panel-muted-foreground`. The shipped Conversation section line is the precedent. |
| `DocumentImagesSection.tsx` | `PanelSection` count = M | **"{M} image descriptions in this document, showing the first {N}"** | same |
| `DocumentRow.tsx` `VersionHistoryPanel` | n/a | **"{M} versions, showing {N}"** | below the version table, `text-xs text-muted-foreground` |

When N = M, no line renders and the sections are byte-identical to today. Loading, error and empty arms
stay as shipped ("Couldn't load this document's tables" · "Couldn't load this document's image
descriptions" · "Could not load version history." · each section's shipped empty copy). There is no
paging control here: D-17 asks only for the honest line.

## State Matrix — Pickers on server search (D-15, R-05)

Common contract for every typeahead picker:
- **Source:** `POST /document-search` with `version: "latest"`, `include_archived: true` (keeps today's candidate set; RESEARCH A6), `limit: 20`, `name: <query>`.
- **Debounce:** 250 ms after the last keystroke. Only the latest request's answer is applied; stale answers are dropped (the `useDocumentFind` pattern).
- **Empty query:** shows the **20 most recent** documents (newest first).
- **No client re-filter in server mode:** the server's name match is the answer (RESEARCH Pitfall 10). Client exclusion of self or already-picked ids still applies.
- **The chosen document is retained as an object.** It stays chosen, and stays shown in any preview line, even when a later search no longer returns it.

| State | What renders |
|-------|--------------|
| Searching, no rows yet for this query | no listbox options and no "No matching documents"; a `<p role="status">` line after the list: **"Searching…"** |
| Searching, previous rows on screen | previous options stay, the listbox gets `aria-busy` + `opacity-60`, and the status line reads **"Searching…"** |
| Results | options (`role="option"`), server order |
| More matches than shown (server `total` > rows shown) | status line after the list: **"More documents match. Type more of the name to narrow."** |
| No match (completed search, 0 rows) | the shipped "No matching documents" item, only after the answer |
| Failed | `<p role="alert">` after the list: **"Couldn't search documents."** + **"Try again"** (`text-xs text-primary hover:underline`). Previous options stay. |

The status and alert lines sit **after** the `role="listbox"` element, never inside it, so they add no
non-option children to the listbox. Style: `mt-1 text-xs`, `text-panel-muted-foreground` inside panels and dialogs.

### S11. CreateLinkDialog (`CreateLinkDialog.tsx` + `LinkTargetCombobox.tsx`)
- `LinkTargetCombobox` gains server mode: an optional `onQueryChange` plus `loading`, `error`, `hasMore` and `onRetry` inputs. The APG roles, keyboard walk and `aria-controls` rule (WR-04) are unchanged.
- The dialog shell, type-first chips, preview line, per-type "N already linked with this type — hidden…" note, disabled-until-chosen confirm and 422 copy are all shipped and unchanged.
- The open-time "Could not load documents." line is replaced by the common picker failure line.
- The listbox keeps `max-h-44 overflow-y-auto` (20 rows scroll inside it).

### S12. StructurePopovers RelationshipEditor (`StructurePopovers.tsx`)
- Same server-mode `LinkTargetCombobox`. `maxVisible={8}` stays (271 UI-SPEC S6). "More documents match…" renders whenever the server total is above the number shown.
- The `documents` prop is no longer the candidate source.
- The **Added by** and **Document type** editors read `summary.connections` and `summary.document_types` (R-03). Their layout is unchanged. While the summary loads, each shows the common "Searching…"-style status as **"Loading…"**. On failure: **"Couldn't load this list."** + **"Try again"**.

### S13. LegalHoldDialog (`LegalHoldDialog.tsx`)
- The Documents `Input`, its `role="listbox"` of button options and the picked-chip row stay as shipped.
- The whole-library `listDocuments()` read and the `getDocumentStates` loop over the library are removed. The active-org check runs over the ≤ 20 returned ids only (R-05).
- Empty query: the 20 most recent appear in the suggestion list. The list takes the folder list's shipped bound `max-h-48 overflow-y-auto rounded-md border border-border`, so 20 rows do not stretch the dialog.
- States follow the common table. The failure line uses `AMBER_TEXT_CLASS`, the dialog's shipped refusal colour. The previous code silently offered nothing on failure; that is replaced.
- "More documents match. Type more of the name to narrow." carries no number here, because the active-org filter runs after the server count. A number would be wrong (it would include another org's documents).

### S14. TakeoffSection rate-sheet select (`TakeoffSection.tsx`), the R-05 exception
Not a typeahead. The read is a bounded `GET /documents?kind=spreadsheet` page of **50**, newest first.

| State | What renders in the shipped `<select>` |
|-------|----------------------------------------|
| Loading | disabled, one option **"Loading rate sheets…"** |
| Loaded, 0 | disabled, shipped option verbatim: "No Excel rate sheets found in Library", but only after success |
| Loaded | options; the first is auto-selected (shipped) |
| Loaded, total > 50 | below the select row, `text-[11px] text-muted-foreground`: **"Showing the 50 most recent of {M} spreadsheets."** |
| Failed | disabled, one option **"Couldn't load rate sheets"**. Below the row, a **"Try again"** text button (`text-[11px] text-primary hover:underline`). |

## Interaction and accessibility contract

- `role="status" aria-live="polite"` on every loading line and on the picker "Searching…"/"More documents match" line. `role="alert"` on every failure line (shipped 112/117 pattern).
- `aria-busy="true"` only on a warm, user-initiated reload wrapper and on a picker listbox showing previous options. Never on a background refetch.
- The Chunks region stays one Tab stop. The sentinel is not focusable. The only focusable child ever added is the failure state's "Try again".
- Focus is not moved by any state change: a refetch landing, a page loading, or a failure appearing leaves focus where it was. "Try again" keeps focus on itself while it retries.
- Debounce 250 ms on picker input (D-15). Realtime refetch debounce ~500 ms (D-08). The Find tab keeps its shipped 300 ms.
- The upload optimistic row stays on page 1 until the refetch reconciles it (D-08). Totals (pill, Root/folder count, tiles, pager) change when the summary refetch lands, not optimistically. G-4 D checks that the totals go up by one without a reload.
- Mobile (<768px): no layout change. The skeleton and alerts take the list column's full width. The detail bottom-sheet carries S9/S10 unchanged.
- Reduced motion: `animate-pulse` and `AnimatedNumber` keep their shipped reduced-motion behaviour (AnimatedNumber renders immediately under `prefers-reduced-motion`).

## How we'd know this failed (UI-observable, feeds G-4 A-E)

- A Library open shows "0 documents", "No root documents yet." or an empty tree count for any frame before the first answer arrives (G-4 A).
- Any folder count, Root count, tile or header total equals a page length (25/50) or reads 1,000 when the database holds more (SC#3).
- The pager shows `+` or "may be larger" anywhere, or the 10,000-document folder's last page does not end at its oldest document (G-4 B).
- A load failure renders any empty-state sentence, or swaps on-screen rows for an empty list.
- The Library list dims or shows a skeleton every time ingestion progresses (background refetch not silent).
- The Chunks section shows a "Show all" or "Load more" button, a second Tab stop, or a header count of 1,000 for a larger document.
- A picker shows "No matching documents" while still searching, re-filters server results in the client, or drops the chosen document when the list changes. Or the network log shows a whole-library request when a dialog opens (G-4 C).
- Takeoff shows "No Excel rate sheets found in Library" after a failed read.
