Close UAT Test 10 (severity: major). Backend kickoff refusals are correct (the
disabled-skill gate returns a descriptive 400 and fail-closes before any
workflow_run insert — DB-verified), but the frontend send path SWALLOWS every
non-409 HTTP error: `api.ts` discards the response body's `detail`,
`StreamsProvider`'s catch surfaces only 409s (everything else is `console.error`
+ a `runStatus:'failed'` placeholder that renders as a bare avatar), and
reconcile then wipes the orphaned temps → a dead blank "New Chat" thread with the
user's prompt lost. Reproduced 3× across providers (glm / minimax / gpt-5.4-mini).

This plan makes a kickoff refusal VISIBLE: the server's actionable `detail`
message appears in the thread's error banner, both optimistic bubbles roll back,
and the typed prompt lands back in the composer. Deep sends gain the same banner
on any HTTP refusal — the intended improvement; nothing else about Deep changes.

dead thread (same failure family as BUG-260603-01 / SEED-055).

the success path, the 409 branch semantics, SSE/chunk handling, and ALL backend
files are untouched.
