## What I checked and found sound

- **Reachability fence (plan 01/05).** I broke the `experts` branch (`activeView === ("expertz" as string)`), and `activeViewReachability.test.ts` went RED on 2 cases. Reverted. The fence is AST-based and bites on the real files.
- **Entry action.** I deleted the `experts` NAV_ITEMS entry, and `nav-items.test.ts` + `NavPanel.test.tsx` went to 5 failed / 20 passed. Reverted.
- **PACK-12 honest-folder rule.** I planted `.filter((f) => f.known)` into the modal, and `ExpertDetailModal.test.tsx` case (3) went RED. Reverted.
- **PACK-11 vanish and positive control.** I planted a filter that drops `visibility: "granted"` rows, and `ExpertCatalogPage.test.tsx` failed 5 cases. Reverted. The page makes one `listExperts()` call with default arguments.
- **`startScopedChat` ordering and PATCH-failure handling.** Cases 1–8 cover the order, identity of the selected row, PATCH rejection without navigation, discard-then-rethrow of the original error, and a failed discard. Run: experts dir 7 files / 72 passed.
- **Management arm.** `for_management=true` without `experts:manage` returns 403, and the unfiltered service call is never awaited. The test asserts this, and the code at experts.py:416-421 matches.
- **Retired hardcodes / XSS.** `example_output` renders as escaped text inside `<pre>`. The new catalog files contain no `dangerouslySetInnerHTML`.
- **Migration 190.** Every column is nullable with no default, and the CHECK vocabularies are closed. It adds columns to an existing table that already has RLS (read-all to authenticated, per its header). Locally, all 6 columns exist and no rows set `max_tools`, `reasoning_off` or `api_surface`. I checked this with a read-only asyncpg SELECT. `full-schema.sql` carries them too.
- **`/v1/responses` routing.** `resolve_api_surface` accepts only the closed vocabulary. It returns None when the operator's `native_tools` is explicitly False, and also when the resolved provider is not `openai`. The dispatcher raises on an unknown surface instead of falling back. The adapter handles `response.failed` and `error`. The 262 backend tests passed: pin, provider-hint, responses adapter and reasoning-first routing, 86 in total.
- **tsc.** None of the 70 app-config errors are in files 262 created.
