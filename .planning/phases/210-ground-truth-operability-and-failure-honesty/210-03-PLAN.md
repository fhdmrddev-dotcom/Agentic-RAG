<objective>
Implement embedding and retrieval failure honesty (RAG-09), closing BUG-260815-05 so that provider outages (429 quota exhaustion, auth errors) are never reported as "nothing was retrieved (0 sources)".
</objective>

<threat_model>
- T-210-06 (Conflation of Provider Outage with Empty KB): When embedding generation fails (429 insufficient quota, connection failure), `_vector_search` fails. If this exception is caught and converted to `[]`, the `citations_required` gate reports *"nothing was retrieved (0 sources) — this step reads your documents and must show where its answer came from"*. Authors waste hours modifying document text/prompts when the problem is billing or network. Mitigation: Propagate `retrieval_status: "provider_error"` and detailed `retrieval_error` into `ToolResult` and output citations; update gate to explicitly name provider failure.
- T-210-07 (False Positive Provider Errors on Honest Zero Matches): If empty matches are accidentally flagged as provider errors, legitimate zero-source searches would produce false alarms. Mitigation: Strictly separate the exception-catching path from the successful vector/hybrid search return `([], 0.0)`.
</threat_model>
