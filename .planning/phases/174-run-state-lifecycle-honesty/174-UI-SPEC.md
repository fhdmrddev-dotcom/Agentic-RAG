## Terminal-State Vocabulary (129-C) — the load-bearing contract

The chat surface reads a non-clean run ending as one of **three tiers, loudness earned by severity** ("quiet & calm, red for real failure — the louder the frame, the more it's earned"). Every marker derives from persisted state, so it survives nav **and** a full cold reload (STATE-02).

| Tier | State | Trigger (authoritative source) | Frame | Glyph + word | Target seam |
|------|-------|-------------------------------|-------|--------------|-------------|
| **1 · Dim** | Response stopped (with partial content) | `runs.status='cancelled' && content` OR `runs.status='timed_out'` | none — thin inline line | `Square` ⊘/■ + "Response stopped" / "Agent reached time limit" | `MessageItem.tsx:670` (EXISTS — verify) |
| **1 · Dim** | Cancelled — no output yet | `runs.status='cancelled'` && empty content | none — quiet dashed body | ⊘ + "cancelled — no output yet" | `MessageItem.tsx:627` (EXISTS — verify) |
| **2 · Amber** | Blocked — disabled by the administrator | workflow kill-switch **403** (`ApiError.status===403`; no run persisted) | 1px amber border + amber wash | ⊘ + server `ApiError.message` | `StreamsProvider.tsx` catch (`~:2069`) → amber notice render (BUILD) |
| **3 · Red** | Run failed | `runs.status='failed'` + `error` | 1px red border + red wash | ✕ + reason + provenance | vocabulary-defined; deep failure-card taxonomy is `run-honesty.md`'s (panel), OUT of 174 build — **174 must never downgrade a genuine failure below this tier** |

**The tier ladder is verifiable:** frame weight strictly escalates none → amber-border → red-border, and a state may never render louder than its severity earns (a deliberate Stopped must NOT be framed like a failure; an administrative block must NOT read red).

## Live Pre-Answer Instrument (130-C) — one surface, STATE-03 + STATE-04

The **run-card header owns the pre-first-token honesty** — no separate banner. It carries a live activity pill, a `started_at`-anchored timer, and exactly one avatar. STATE-03 (activity) and STATE-04 (timer + avatar) are ONE instrument.

| Element | Contract | Target seam |
|---------|----------|-------------|
| Activity pill | In the pre-first-token window, shows the model's real work: **"Reasoning…"** when `reasoningContent` is streaming (OpenAI-compat reasoning providers) — replacing the static "Setting up agent…". | `toolMeta.ts:outerBannerLabel()` + `MessageItem.tsx:620` (BUILD) |
| Calm fallback | Anthropic / Google (never emit `reasoning_delta`) keep the calm **"Setting up agent…"** — by design, not a failure. Harness variant: "Starting workflow…". | `toolMeta.ts` default branch (byte-identical) |
| Anchored timer | Elapsed derives from the run's `started_at`/`created_at`, **never component mount** — a nav-back into a multi-minute run keeps climbing (mirrors Phase 095.1). | `StreamsProvider.tsx:1859-1865` kickoff stamp + `RunCard.tsx:122` (BUILD) |
| Single avatar | Exactly ONE assistant avatar per run at all times — including the pre-runId double-mount / nav-back remount window. | `dedupMessages.ts` + `MessageList.tsx` reconcile seam (BUILD) |

## Color

Aether Deep Midnight tokens only (`frontend/src/index.css :.dark`). 60 / 30 / 10 split preserved; this surface adds **no new hue** — it reuses the amber, danger, and primary tokens already in the palette.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `hsl(216 45% 4%)` / `--color-surface` `hsl(220 30% 7%)` | transcript background, message column |
| Secondary (30%) | `--color-muted` / `--color-text-muted` `hsl(220 16% 65%)` / `--color-text-dim` `hsl(220 16% 45%)` | **dim tier** markers (Stopped / Cancelled) — muted foreground, no color |
| Accent (10%) | `--color-primary` `hsl(239 100% 82%)` (soft indigo) | **live activity pill only** — `--color-primary-dim` bg + `--color-primary-glow` border + primary label; timer.anchored = primary mono. Primary = "working now," nothing else. |
| Warning (amber) | `border-amber-400/30 bg-amber-400/10 text-amber-400/90` | **amber tier** — administrative block (kill-switch 403). Reuse the `model-fallback-notice` primitive verbatim (D-06). |
| Destructive (red) | `--color-danger` `hsl(0 72% 51%)` / `--color-danger-dim` | **red tier only** — a genuine `runs.status='failed'`. Never for a user-chosen stop or an administrative block. |

**Accent reserved for:** the live pre-answer/streaming activity pill + the anchored run timer (the "working now" instrument) — never for terminal markers, never for the amber/red tiers, never as a generic interactive-element color.

**Amber reserved for:** the administrative-block tier (kill-switch 403) — *not* an error, *not* a primary action. **Red reserved for:** a genuine failure (`runs.status='failed'`) — the loudest tier, earned by severity.

**Color-never-alone (WCAG 1.4.1, load-bearing):** every tier pairs a glyph + a word with its color — dim = `Square` + "Response stopped"; amber = ⊘ + "disabled by the administrator"; red = ✕ + "Run failed". Color is reinforcement, never the sole signal.

## Design Assertions (6 pillars — checker-verifiable)

Each assertion is anchored to its sketch (129-C / 130-C) and target component. `A#` IDs are stable handles for the checker.

### Pillar 1 — Layout & Hierarchy

- **A1 (129-C):** Terminal markers attach **inside the assistant message column** (`msg-col`), directly below the answer body — never as a separate chat row and never on the user bubble. `MessageItem.tsx`.
- **A2 (129-C):** Frame weight **strictly escalates by severity**: dim tier = no frame (inline line / dashed body); amber tier = 1px amber border + wash; red tier = 1px red border + wash. A deliberate Stopped is never framed as loudly as a failure.
- **A3 (130-C):** The pre-answer activity pill, anchored timer, and single avatar live in **one instrument** — the run-card header — not as three separate pieces of chrome. `RunCard.tsx` / `RunStatusStrip.tsx`.
- **A4 (house rule + D-14):** No new chrome on the calm transcript beyond what the sketches show. Single-column conversation, no dedicated execution rail, no bordered chat box; **only the run-card is framed**; tool cards stay click-to-expand. Deep Mode byte-identical.
- **A5 (130-C):** The activity pill sits **right-aligned** in the header (`margin-left:auto`), the timer trailing it; the avatar + model/turn meta lead. Reasoning-before-any-tool renders at `MessageItem.tsx:620`; the moment a tool appears, hierarchy hands off to the existing `RunStatusStrip` (no duplicate activity home).

### Pillar 2 — Color & Theming

- **A6 (129-C):** Dim tier uses **muted foreground only** (`--color-text-muted` / `--color-text-dim`) — no accent, no color.
- **A7 (129-C / D-06):** Amber tier reuses the exact `model-fallback-notice` classes — `border-amber-400/30 bg-amber-400/10 text-amber-400/90` — no bespoke amber CSS.
- **A8 (129-C):** Red tier (`--color-danger`) renders **only** for `runs.status='failed'`; a stopped/cancelled/blocked run never renders red.
- **A9 (130-C):** Primary (soft indigo) is used **only** for the live activity pill + anchored timer — the "working now" signal — never for terminal markers or as a generic interactive color.
- **A10 (WCAG 1.4.1):** Every tier carries a glyph + word alongside color; no state is distinguishable by color alone.

### Pillar 3 — Typography

- **A11:** Status/identifier/timer text is **JetBrains Mono** (`--font-mono`); notice titles and the activity label are sans (Inter). No serif, no new family.
- **A12:** Notice title = `text-sm` weight 600; markers/meta/timer/provenance = `text-xs` (12px) mono weight 400; activity label = 12px weight 500. Exactly 3 sizes (12/14/16), 2 core weights (400/600, with 500 as the existing app medium).
- **A13:** Body/marker line-height ≥ 1.5; no dense sub-1.4 line-height on multi-line notice reason copy.

### Pillar 4 — Spacing & Rhythm

- **A14:** All new spacing is a multiple of 4 — the amber notice reuses `mt-2 px-3 py-2` (8/12/8) verbatim; the dim marker keeps `mt-1` (4). No off-grid value ships (sketch odd-px are illustrative).
- **A15 (D-14):** Inter-message transcript rhythm (`--space-6` / 24px) is **unchanged** — the phase adds markers *inside* existing columns, never new vertical gaps between messages.

### Pillar 5 — Interaction & State

- **A16 (129-C / STATE-02):** Every terminal marker is **derived from persisted `runs.status`** (via the `threads.py:346-353` zip → `api.ts:_mapRow` → `message.runStatus`), so it renders identically **live, after nav-away-and-back, AND after a full cold browser reload**. No live-only badge.
- **A17 (129-C / STATE-01b):** On an `ApiError.status===403`, the `sendMessage` catch **replaces the empty assistant placeholder with the amber notice** (carrying `ApiError.message`) **and clears the workflow-lock** so the composer is never left locked. The existing 400 (disabled-skill) and 409 (workflow-lock) rollback-banner paths stay **byte-identical** (D-05).
- **A18 (130-C / STATE-03):** The activity pill is **live**, streaming the real sub-state from already-emitted events (`reasoning_delta` → `message.reasoningContent`). It shows "Reasoning…" only while reasoning streams and content is still empty; default (no reasoning) returns "Setting up agent…" byte-identical. No new backend event.
- **A19 (130-C / STATE-04):** The timer **climbs continuously from `started_at`** and never resets on nav-back / remount; it freezes only on a TRUE terminal. **Exactly one** assistant avatar renders at every moment, including the pre-runId double-mount window.
- **A20 (cross-provider):** "Reasoning…" appears on OpenAI-compat reasoning providers (DeepSeek / Moonshot-Kimi / GLM-zhipu / MiniMax / OpenAI-reasoning); Anthropic & Google keep the calm "Setting up agent…" fallback (by design — asserting "Reasoning…" on `claude-*`/`gemini-*` is a false expectation, not a bug).
- **A21 (motion):** Restrained motion only — `brandPulse` on the active avatar, `progressShimmer` on the active run, `pulseGlow` on the activity pill dot. No new/decorative animation; `prefers-reduced-motion` respected.

### Pillar 6 — Responsive & A11y

- **A22 (mobile):** At <768px the run-header remains legible — the activity pill/timer wrap rather than overflow; the message column is `min-width:0` so long provenance/model strings never blow out the layout. Terminal markers stack cleanly.
- **A23 (XSS, V5):** The amber/red notice renders `ApiError.message` (and any server reason) as **React text children only — never `dangerouslySetInnerHTML`** — inheriting the established safe-render pattern (`RunStatusStrip`, the `reconcileErrors` banner).
- **A24 (a11y):** The live activity pill/timer expose `role="status"` (aria-live polite) so assistive tech announces the working state; icon-only glyphs (`Square`) carry an accessible label ("Response stopped"); meaningful copy uses the panel-scoped AA token (≥4.5:1), never the global 3.59–3.64:1 dim.
- **A25 (per-thread isolation):** All lock/timer/marker state is per-thread keyed (`workflowLockByThread`, `reconcileErrors`) — the STATE-01b `clearWorkflowLockForThread(threadId)` uses the OWNING thread closure, so a parallel Thread B never has its composer unlocked or its avatar/timer bled by Thread A.
