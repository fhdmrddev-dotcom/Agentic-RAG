## Deviations from Plan

**One auto-fix (Rule 1 — schema-drift / function ambiguity), no architectural changes.**

**1. [Rule 1 - Bug] Migration 073 left a stale 6-arg `match_document_chunks` overload after apply.**
- **Found during:** Task 1 read-back (the live signature query returned TWO rows — the old 6-arg function AND the new 7-arg one).
- **Issue:** `CREATE OR REPLACE FUNCTION` matches an EXACT signature only. Adding the trailing `p_embedding_model` param created a NEW overload instead of replacing the prior function, leaving two live `match_document_chunks` definitions — a latent `function is not unique` ambiguity for any caller omitting the new param, and a duplicate in the regenerated `full-schema.sql`. Plan 01's stated intent ("existing callers stay compatible") was a SINGLE backward-compatible function, not two overloads.
- **Fix:** Added `DROP FUNCTION IF EXISTS public.match_document_chunks(public.vector, uuid, integer, double precision, jsonb, uuid[])` before the `CREATE OR REPLACE` in the migration file (the migration-016 precedent — DROP before re-create on a shape change). Re-applied (idempotent); verified live: exactly 1 overload remains. `full-schema.sql` now carries a single definition.
- **Files modified:** `supabase/migrations/073_embedding_provider_and_chunk_tags.sql`, `supabase/full-schema.sql`.
- **Commit:** `8c4adece`.

The cross-embedder roundtrip fallback (cred-parity boundary assertion instead of a full second-embedder roundtrip) is per the operator authorization + the plan's own Task-2 instruction ("if only OpenAI keys are available, assert the cred-resolution parity at the client-build boundary; the full second-embedder roundtrip is the manual UAT axis") — planned behavior, not a deviation.
