# Phase 111.1 Plan 02: D-09 Data-Egress Routing Fixes Summary

**Three backend routing fixes that close BUG-260616-01 — extraction now routes by a stored explicit provider (not a slashed model name), forced_emit resolves a local provider's base_url + dummy key, and the OpenRouter :exacto/response-healing mangling fires only when the resolved provider is openrouter — so a pinned local model stays local instead of silently shipping document text to OpenRouter's cloud.**

## Performance

- **Completed:** 2026-06-16
- **Tasks:** 3
- **Files modified:** 4 source + 3 new test files (+ 1 deferred-items log)

## Accomplishments

- **D-09 #1 (data-egress, HIGH):** `documents.py` extraction routing now reads `app_settings.extraction_provider` first; a slashed local id (`google/gemma-3-4b`) can no longer be name-inferred to `openrouter` once the operator pins a local provider. Name-inference stays as the legacy fallback only (D-08 back-compat — confirmed `google/gemma-3-4b` still infers `openrouter` when the provider is unset).
- **D-09 #2 (data-egress, HIGH):** `forced_emit` gained a local-provider branch BEFORE the cloud branch — a forced shot targeting `lmstudio`/`ollama` injects the local dummy key (`lm-studio`/`ollama`) + the local base_url (ollama appends `/v1`, lmstudio AS-IS, no double-append), mirroring `resolve_llm_provider`. The cloud branch is byte-identical inside an `else`.
- **D-09 #3 (DoS/tampering):** the OpenRouter quality mangling (`:exacto` + `response-healing` plugin) is gated on `provider == "openrouter"` instead of `"/" in effective_model` — local `org/model` ids are left untouched (they 500'd LM Studio/Ollama) while OpenRouter keeps the quality strategy.
- 15 new real-assertion unit tests all GREEN; each of the 3 fixes proven load-bearing (the tests fail against un-patched source).

- **Defensive consumption of `extraction_provider`:** Plan 02 runs in parallel (Wave 1) with Plan 01, which owns the `extraction_provider` schema/field. The `getattr(app_settings, "extraction_provider", "")` read means my code works whether or not Plan 01's field has merged yet — falling back to inference if absent, taking the stored provider once present. This is the exact pattern the plan's action specified.
- **Authored the three `test_111_1_*` files as real-assertion tests directly** rather than "un-marking" Plan 01 scaffolds, because those scaffolds live in Plan 01's parallel worktree and are not present in this worktree's base (see Deviations). They are real behavior tests (not source-greps): they drive the actual `forced_emit` / `create_adaptive_streaming_chat` code paths via captured boundaries and fail against un-patched source.
- **`config.py` change is documentation-only** — the shared `resolve_llm_provider` mapping body is byte-untouched, preserving the cross-provider shared path (CLAUDE.md never-break-shared-path rule).
