# Phase 111.1 Plan 05 Summary — EMBED-05 re-embed lifecycle

A batched, RLS-scoped, resumable, NON-DESTRUCTIVE background re-embed job (`reembed_service.reembed_job`) now re-embeds a user's existing chunks from their PRESERVED `content` whenever the embedding model/dimensions change — wired to kick off via `background_tasks` on a confirmed settings save, with a reconcile-on-fetch progress record and a manual "Re-embed now" re-kick — so a model/dimension switch recovers search at full recall without ever losing the corpus or comparing across vector spaces. Every supabase-py call + `embed_texts` goes through `run_in_threadpool` (never blocks the loop), every read+write is `eq(user_id)`-scoped (the service-role client bypasses RLS), the stale predicate (`embedding_model IS DISTINCT FROM current`) makes the loop resumable, and `resize_embedding_column` is gated on a true dims change only.

**1. [Rule 3 - Blocking] Added a `batch_size` param to `reembed_job`.**

- **Files modified:** `reembed_service.py`, `test_111_1_reembed_resume.py`.
- **Commit:** `ff661417`.

**2. [Rule 3 - Blocking] The live tests use an asyncpg-backed supabase-py adapter (not the literal production client object) inside a rollback txn.**
- **Found during:** Task 1 RED design — `reembed_job` uses the supabase-py service-role client (auto-commit), which cannot participate in the asyncpg rollback transaction that keeps the 30-doc corpus untouched (the resize-test / match-filter-test discipline).
- **Fix:** `_reembed_adapter.py` implements the exact `.table().select().eq().neq().limit().execute()` / `.update().eq().execute()` / `.rpc().execute()` surface the job calls, routing real parameterized SQL through the rollback-txn asyncpg connection (`.execute()` is sync — wrapped by the job in `run_in_threadpool` — and schedules the coroutine back onto the test loop via `run_coroutine_threadsafe`). The REAL job logic + REAL SQL (the RLS `eq(user_id)` WHERE clause, the stale `IS DISTINCT FROM` predicate) run against :54322 against real two-user rows. This satisfies the threat-register intent ("proven live, not mocked") — the RLS scope is a real WHERE clause, not a MagicMock call-shape assertion. Only `embed_texts` is a deterministic local stub (no API key — the live cross-embedder round-trip is the manual UAT axis per the plan's own verification note).
- **Files created:** `_reembed_adapter.py`.
- **Commit:** `352bb494` (RED).
