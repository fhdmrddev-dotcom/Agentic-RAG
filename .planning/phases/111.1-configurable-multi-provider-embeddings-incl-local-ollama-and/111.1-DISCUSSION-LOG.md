## Pre-discussion: "why use the strongest/most expensive models?"

Operator paused before gray-area selection to ask why the strongest/most expensive models
would be used "only to do a summary and metadata extraction," suggesting a decent model per
provider instead.

**Clarification given:** disentangled the THREE model roles — (1) the **embedding model**
(this phase; turns text→vector; tiny/cheap/free-when-local; "strongest/expensive" doesn't
apply), (2) the **extraction LLM** (Phase 111; the summary+metadata job; bounded structured
task — a capable mid/strong model, not necessarily the frontier), (3) the chat LLM (separate).

**Operator correction:** "we want also accuracy, we will **not compromise on quality**; the
purpose is to **open the choices** to the **most decent embedding models**." → reframed the
selection principle from cost-first to **quality-first** (D-01). Noted the consequence: quality-
first **rejects** down-truncating to a single 1024 dimension and makes the re-embed lifecycle
the load-bearing piece.

## Area 1 — Re-embed lifecycle & UX

| Option | Description | Selected |
|--------|-------------|----------|
| Trigger: confirm-on-save | Save in Settings → serious destructive confirmation → background job | ✓ |
| Trigger: silent auto | Re-embed silently on change | |
| Search during run: Option A graceful-dip | Background batched; not-yet-done chunks skipped; search up at reduced recall, recovers | ✓ |
| Search during run: Option B zero-downtime shadow-build | Build new vectors in 2nd column, atomic swap; no dip; more engineering | (deferred) |
| Failure: resumable + non-destructive | Stale-predicate resume; old vectors kept until replaced; manual "Re-embed now" | ✓ |

**User's choice:** Option A graceful-dip, confirm-on-save, background + resumable.
**Notes:** Operator emphasized the confirmation must be a **serious, attention-demanding gate**
("this is a serious step that should be handled carefully to get the attention of the user
about the consequences") → captured as hard design contract D-03.
