<objective>
Give an `external_action` step a way to say *this step calls a tool on an MCP server*. Today
`ExternalActionSection` offers exactly the three members of `EXTERNAL_ACTION_CAPABILITIES` and there
is no way to express the MCP shape at all — which is why the picker is always handed a capability,
and why wave 2's MCP branch has no caller yet.

**Purpose:** this is the authoring half of SEED-200. Wave 2 made the picker able to see MCP rows;
this plan is what lets a person ask it to.

**And it authors something no shipped code in the frontend has ever done:** a config write that
CLEARS keys. `patchPhaseConfig` is a pure spread merge, `set(key)` is single-key, and nothing
normalises — so today, choosing `create_ticket` on a step that carried `tool_name: "ask_question"`
produces a config with BOTH, which the server accepts and which **runs as MCP**. The clear is the
plan's most dangerous omission and its direction is asymmetric: a stranded `capability` is inert, a
stranded `tool_name` silently changes what the step does.

**Output:** a two-position segmented control that lives BESIDE the capability radiogroup and never
inside it, a multi-key write seam that exists in exactly one place, three keys cleared in each
direction, and one permanently-false readiness row that stops appearing.
</objective>
