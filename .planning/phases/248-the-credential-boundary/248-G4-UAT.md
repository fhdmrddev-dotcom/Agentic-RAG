# Phase 248 — G-4 lived-experience UAT

⚠ **This obligation was not in the ROADMAP flags.** Phase 248's flags waived **G-2** explicitly
(*"no G-2 — refusal copy is a sentence, not a surface"*) and said nothing about **G-4**, which fires
on any phase touching user-visible UI. CRED-01 shipped a visible refusal on two doors, so G-4 was
live and simply unmentioned — raised at review (`BUS-243`), driven here.

⭐ **Why it could not be skipped:** every other piece of evidence for CRED-01 is jsdom, pytest and
psycopg2. **None of them can see whether a person who pastes a secret understands what happened.**
The requirement's own wording is that the refusal *names which field takes a secret* — a legibility
claim, and this project has measured twice that a green fence coexists with a shipped legibility
defect.

---

## S1 — the original incident, reproduced ✅ PASS

**Driven:** Settings → Connections → Microsoft 365 → *Advanced: Custom OAuth App Credentials* →
pasted an Entra-secret-**shaped** string into **Custom Client ID**.

⚠ **A fake was used, never a real credential:** `abc8Q~FakeNotARealSecret1234567890abcdef`. It
carries the `<prefix>~<body>` shape that `BUG-260907-02` reported and nothing else.

**Observed, on screen:**

- The input border turns **destructive red the moment the value lands** — no blur, no save needed.
- The grey hint is **replaced** by: *"This looks like an Entra client secret containing '~', not a
  Client ID. Enter the Application (client) ID (GUID). Put the secret into Custom Client Secret."*
- ⭐ **The field it names — Custom Client Secret — is rendered directly beneath it, empty.** The
  instruction and its destination are visible in the same glance.
- *Connect with Microsoft 365* is disabled while the error stands.

**Operator verdict: APPROVED.**

⚠ **ONE OBSERVATION THAT ONLY A DRIVEN RUN COULD PRODUCE, recorded and NOT raised as a blocker
because the operator approved S1.** *Connect with Microsoft 365* is genuinely disabled
(`ConnectionFormPanel.tsx:1746`) but still renders **solid purple, exactly as if pressable**. The
refusal works; the button does not *look* refused. ⛔ **No fence in this repository can see that** —
a test asserting `disabled` passes on a button that reads as enabled. Re-open trigger: any report of
a person clicking Connect and nothing happening.

## S3 — the false-positive check ✅ PASS · ⭐ the one that would have broken real users

**Driven:** cleared the field, typed `bD78Ksp3xBJew1kL` — the RFC 7591 dynamically-registered client
id from `McpAuthDoor.byo.test.tsx:161`.

**Observed:** **accepted.** Red border clears, message disappears, the grey hint returns, and
*Connect with Microsoft 365* re-enables. The state flips cleanly in both directions in one field.

⭐ **This is the scenario that justifies `D-248-01`'s negative-rule choice.** An entropy- or
length-tuned rule would refuse a 16-character mixed-case opaque id and silently break the Phase 222
BYO door for anyone using a self-registering MCP server — with no error anywhere but the form.

## S2 — the second door ⛔ OWED, and stated rather than worked around

**Intended:** the same Entra-shaped paste into `McpAuthDoor`'s Custom Client ID.

⛔ **NOT REACHED.** That field renders only on the bring-your-own-OAuth path — a server advertising
OAuth *without* dynamic registration. The live Notion connection is already OAuth-connected, so the
field is not shown, and forcing it would mean disconnecting a working connection.

✅ **What IS established:** code-level parity. `McpAuthDoor.tsx` imports and calls the **same**
`customClientIdError` at `:145`, `:362`, `:365`, `:367` and `:398` — border, message and a disabled
submit, mirroring the panel.

⛔ **What is NOT established, and the distinction is the point:** *"both doors import the same
function"* is not the same claim as *"a person sees the same refusal."* S2 is recorded as OWED with
that note, by operator decision, rather than marked passed on an inference.

**Re-open trigger:** the next phase that touches `McpAuthDoor.tsx`, or the first BYO-OAuth MCP
server connected against a real endpoint.
