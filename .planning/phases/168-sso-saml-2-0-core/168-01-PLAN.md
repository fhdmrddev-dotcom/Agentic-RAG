<objective>
Ship migration 113 — the load-bearing schema foundation the entire SSO phase stands on. Migration 104 shipped a deliberately-thin `sso_configs` table AND the `sso_configs` RLS write policies, but granted `sso:manage` to `super-admin` ONLY (mig 104:414-425), so no org-admin can self-serve SSO today. This migration flips that grant live, adds the D-168-05 approval-gate columns, enforces domain uniqueness, and adds the encrypted `app_settings.supabase_management_token` column that Plan 02's provider-CRUD service decrypts at call time.

Purpose: Without the `('org-admin','sso:manage')` grant every org-admin write 403s (RESEARCH Pitfall 1) — D-168-01's whole premise fails. Without the `status` column and domain uniqueness, an unapproved or hijacked domain routes logins immediately (D-168-05).
Output: `supabase/migrations/113_sso_configs_firming.sql` applied live + regenerated `supabase/full-schema.sql`.
</objective>
