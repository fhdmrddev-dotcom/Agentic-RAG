# Phase 168 — UI Design Contract

> Visual and interaction contract for SSO — SAML 2.0 (CORE). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase introduces NO new visual language.** It reuses the locked Aether Deep Midnight design system and the Phase-166 org-admin shell verbatim (CONTEXT: "reusing 166's design system"). Two surfaces are built: (1) the **SSO tab** — the Phase-166 `LockedTab` "SSO" flips LIVE inside `OrgAdminShell` (indigo org zone), styled as a sibling of `OrgSettingsTab` / `InvitationsTab`; (2) the **identifier-first login** — a rework of the existing `SignInForm.tsx` that routes email→SSO or reveals the password box. JIT provisioning is backend/silent (the user lands in the Phase-166 org switcher). 0 new frontend deps (`supabase-js` ships `signInWithSSO`).

## Spacing Scale

Tailwind default 4px grid (source of truth = `sketch-findings` "4px grid `--space-1`..`--space-16`"). **This phase snaps every spacing value to the grid** — the 166/167 sibling tabs ship a few off-grid half-steps (`py-0.5`/`px-3.5`/`gap-2.5`), but the SSO tab uses the canonical token instead (see the intentional-deviation note below) so it passes the grid gate.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon↔label gaps (`gap-1`), chip vertical padding (`py-1`), tab-strip icon gap |
| sm | 8px | Compact stacks (`space-y-2` between Label + Input), inline gaps (`gap-2`), tab-strip button padding (`py-2`) |
| md | 16px | Default element/field spacing (`space-y-4` in forms), list-row horizontal padding (`px-4`) |
| lg | 24px | Tab-body padding (`px-6 py-6` on the section shell) |
| xl | 32px | Between major sections inside a tab |
| 2xl | 48px | (unused this phase) |
| 3xl | 64px | (unused this phase) |

**Non-spacing values (exempt from the 4px grid — listed here so they aren't mistaken for spacing):**
- **Corner radius:** `--radius` = 0.625rem (10px) via `rounded-lg` — the section-card + chip radius. This is a radius token, not spacing.
- **Fixed icon/avatar sizing:** heading icon `h-[18px] w-[18px]`; row avatar/status dot `h-9 w-9` (36px, itself a multiple of 4). These are fixed component dimensions, not layout spacing.

**Intentional-deviation note (for the executor):** where a sibling tab uses an off-grid value — `InvitationsTab` chips at `py-0.5` (2px), rows at `px-3.5` (14px), heading gap `gap-2.5` (10px) — the SSO tab deliberately uses the grid token (`py-1`, `px-4`, `gap-2`) to satisfy the spacing gate. Do NOT "fix" these back to match the sibling's odd values; the small rhythm difference is an accepted, gate-required deviation.

## Typography

Inherited from the locked Aether system (`index.css`), constrained to **exactly two weights for this phase's surfaces: 400 (regular) + 700 (bold)**. Distinction that the sibling tabs draw with a 500/600 weight is carried here by **size + `uppercase tracking-wide` + color** instead of a third/fourth weight.

| Role | Size | Weight | Line Height | Font / Notes |
|------|------|--------|-------------|--------------|
| Section heading | 16px (`text-base`) | 700 (`font-bold`) | 1.2 | Manrope (`font-headline`) — tab title, e.g. "Single sign-on" |
| Prose emphasis | 14px (`text-sm`) | 700 (`font-bold`) | 1.5 | Inter — empty-state heading + the org/domain name in the remove-confirm sheet |
| Body / input | 14px (`text-sm`) | 400 | 1.5 | Inter — field values, helper prose, button labels |
| Helper / caption | 12px (`text-xs`) | 400 | 1.5 | Inter — under-field guidance, honesty notes |
| Micro-label / chip | 11px (`text-[11px]`) | 400 | 1.4 | Inter — uppercase field labels (`uppercase tracking-wide`) + status/role chips; distinction is size + uppercase + tone, NOT weight |
| Identifier / URL | 11–14px | 400 | 1.5 | JetBrains Mono (`font-mono`) — SP metadata URLs (Entity ID, ACS URL), `provider_id`, the copyable metadata-URL echo |

**Two-weight set = 400 + 700.** The reserved-warning amber tint is never used for text in this indigo zone.

**Intentional-deviation note (for the executor):** `InvitationsTab`/`OrgSettingsTab` render micro-labels and chips at `font-medium` (500). The SSO tab intentionally drops that to **400 + `uppercase tracking-wide`** to stay within the 2-weight contract — do NOT bump the SSO chip/label back to 500 to match the sibling.

## Color

60/30/10 on the Deep Midnight (dark, default) theme. Values are the canonical HSL tokens — the hex is the resolved dark-theme approximation; the executor reads the token, never the hex.

| Role | Token (dark) | Hex ≈ | Usage |
|------|--------------|-------|-------|
| Dominant (60%) | `--background` `216 45% 4%` | `#060a0f` | Page/auth-screen background, input field fill (`bg-background`) |
| Secondary (30%) | `--card` `220 30% 7%` / `--muted` `220 30% 11%` | `#0c1017` / `#131a24` | Tab section cards (`bg-card`), row wells, dividers, inactive-tab hover |
| Accent (10%) | `--primary` `239 100% 82%` | `#a3a5ff` | See reserved list below |
| Positive | `--success` `142 71% 45%` | `#21c45d` | The "Active" connection status chip ONLY (positive terminal — mirrors InvitationsTab "Accepted") |
| Destructive | `--destructive` `0 72% 51%` | `#dc2828` | Remove-connection action + its victim-naming confirm ONLY |

**Accent (indigo `--primary`) reserved for:** the active tab (`bg-primary/10 text-primary`), the primary CTA button ("Add SSO connection" / login "Continue" / "Sign In"), the focus ring (`--ring`), text links ("Sign in with SSO" escape hatch), the copyable SP-metadata mono values, and the "Pending approval" status chip (`primary` tone — the in-your-zone attention state, matching InvitationsTab "Pending"). NOT for every interactive element — inactive tabs, secondary buttons, and rows stay `text-muted-foreground` / `border-border`.

**Status chip vocabulary (166 chip tones — reuse `CHIP_TONE_CLASS`, do NOT invent):**
- `Pending approval` → **primary** (`border-primary/30 bg-primary/10 text-primary`)
- `Active` → **success** (`border-success/30 bg-success/10 text-success`)
- `Disabled` → **muted** (`border-border bg-muted/40 text-muted-foreground`)

**Reserved-tint rule (load-bearing, from `OrgAdminShell`):** the operator zone's **warning/amber** tint stays reserved for `/admin` — it must NOT appear anywhere in this org-indigo SSO surface, including for the `pending_approval` waiting state (use the indigo/primary chip instead).

**Contrast:** meaningful text uses `text-muted-foreground` (dark `220 16% 65%` ≈ 7.7:1) — never `--muted-foreground-dim` for anything the user must read (the ~3.6:1 trap). Mono identifiers and copy meet ≥4.5:1 on `bg-card`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — SSO tab | **Add SSO connection** |
| Primary CTA — login (identifier step) | **Continue** (routes email → SSO-or-password) |
| Primary CTA — login (password revealed) | **Sign In** (unchanged from today's form) |
| SSO escape-hatch link | **Sign in with SSO** (small secondary link under the form — for IdP-initiated / no-domain-match edge cases) |
| Empty state heading — SSO tab | **No SSO connection yet** |
| Empty state body — SSO tab | Add your identity provider's metadata URL to let your team sign in with single sign-on. Email and password sign-in stays available. |
| Pending-approval status note | Waiting for operator approval before this connection can route sign-ins. |
| SP-metadata block label | Give these to your identity provider (helper: Entity ID · ACS URL · NameID format — each with a **Copy** / **Copied** affordance, reusing InvitationsTab's copy pattern) |
| Error — metadata URL unreachable | We couldn't reach that metadata URL. Check the link from your identity provider and try again. |
| Error — duplicate domain | That domain is already configured for SSO. |
| Error — public/personal domain rejected | Public email domains can't be used for SSO. Enter your organization's own domain. |
| Error — SAML not available (plan/env) | SSO isn't enabled for this deployment. (Cloud: requires the Pro plan · self-hosted: set `GOTRUE_SAML_ENABLED`.) |
| Error — login SSO redirect failed | We couldn't start SSO sign-in. Try again, or sign in with your password. |
| Destructive confirmation — remove connection | **Remove SSO for {domain}?** Members who sign in with **{domain}** will fall back to email and password. → confirm **Remove connection** |
| Save receipt | SSO connection saved. (a quiet inline confirm — no toast; mirrors the 166 receipt discipline) |

**Honesty rules (from the sketch-findings / 166 patterns):**
- Never a lying disabled button — the "Add SSO connection" affordance is **honest-absent** for a non-`sso:manage` user (render-only `can_manage_sso` gate; the server is the wall). T-166-09 precedent.
- Status is **server truth** — the chip renders the real `sso_configs.status`, never a client guess. A `pending_approval` connection must visibly read as not-yet-routing.
- Removal is **re-fetch, not optimistic** (D-117-9 lineage) — brief `↻ updating` (`role="status"`) then the fresh state; NO undo (removal deletes the GoTrue provider — irreversible).
- The management token / `provider_id` internals never render to the user beyond the opaque `provider_id` mono chip; no secret substring ever appears in UI or copy.

## Interaction Contracts (phase surfaces)

### 1. SSO tab (`SsoTab.tsx`) — inside `OrgAdminShell`, indigo zone
- **Primary visual anchor:** before a connection exists, the anchor is the **"Add SSO connection" primary CTA**; once a connection exists, the anchor shifts to the **connection row + its status chip** (the one element that answers "is SSO live?" at a glance). Everything else (SP-metadata well, helper prose) is secondary.
- **Layout:** sibling of `OrgSettingsTab` — `mx-auto max-w-2xl px-6 py-6` → `section` `rounded-lg border border-border bg-card px-6 py-6` (24px `lg` — snapped from the sibling's `px-5 py-5`/20px to a declared token); heading = lucide icon `h-[18px] w-[18px] text-primary` + `font-headline text-base font-bold`. Tab flips from `LockedTab` → live in the `OrgAdminShell` TABS switch (render-gated on `can_manage_sso`; server `sso:manage` is the wall).
- **Connection create form:** two fields — **Metadata URL** (`Input type=url`, mono value, placeholder `https://idp.example.com/saml/metadata`) + **Email domain** (`Input`, lowercased, placeholder `example.com`). Domain blocklist rejects public domains inline (422 → the public-domain error copy) BEFORE any provider call. Primary CTA "Add SSO connection". No XML upload — metadata URL only (D-168-01).
- **SP-metadata display:** a read-only well showing Entity ID (`{SUPABASE_URL}/auth/v1/sso/saml/metadata`), ACS URL (`{SUPABASE_URL}/auth/v1/sso/saml/acs`), NameID format (`emailAddress`) as mono values, each Copy-able. Static per deployment — no API call to obtain.
- **Connection state:** once created, the form collapses to a connection row = domain + `provider_id` (opaque mono chip) + the status chip (Pending approval / Active / Disabled) + a **Remove connection** destructive action (victim-naming confirm sheet — graded-guard rule: target-specific destructive → name the victim domain).
- **Approval gate:** a `pending_approval` connection shows the waiting note; only `status='active'` routes logins (server-enforced). Operator approval flips it (operator surface out of this tab's authorship, but the tab must render the pending → active transition honestly).
- **States to cover (Dimension 2):** loading · empty (no connection) · pending-approval · active · disabled · create-error (each of the 4 error copies) · removing (`↻ updating`) · non-manager (honest-absent CTA).

### 2. Identifier-first login (rework `SignInForm.tsx`)
- **Primary visual anchor:** the **single email field + "Continue" CTA** — the resting form is a 3-second read (one input, one button). The password field and the "Sign in with SSO" link are secondary and appear only when the flow calls for them.
- **Resting state:** ONE email field + **Continue** button (the password field is hidden). Preserves the existing `space-y-4` form rhythm, `Label` + `Input` pattern, `Button className="w-full"`.
- **On Continue:** look the domain up (`GET /org/sso/route?domain=`). **Match** → `signInWithSSO({ domain })` → manual `window.location.href = data.url` redirect to the IdP. **No match** → reveal the password field with `animate-fadeSlideUp` (the established 0.3s reveal), CTA relabels to **Sign In** (today's `signInWithPassword` path, unchanged). RETAINED password fallback — nobody is locked out (D-168-02, SC#3).
- **Escape hatch:** a small secondary **Sign in with SSO** link (indigo, `text-sm underline`) under the form for IdP-initiated / no-domain edge cases (`{ providerId }` fallback).
- **Error:** the redirect-failed copy renders in the existing `text-sm text-destructive` slot; never blanks the form.
- **JIT landing:** provisioning is silent/backend; on `SIGNED_IN` for an SSO session the app calls the JIT seam then re-probes `/org/me` — the user lands in the Phase-166 org switcher (join-additive; both orgs visible). No net-new UI beyond a brief neutral "Setting up your access…" state if the re-probe is not instant.
