<objective>
Build the two backend primitives Plan 04's endpoints consume: the `require_sso_manage` authz guard and the domain-gated JIT `provision_sso_membership`. The JIT is the sibling of the Phase-167 token-gated `accept_invitation` — same advisory-lock + `ON CONFLICT DO NOTHING` convergence skeleton, but the org resolves from the authenticated SSO provider (never a token), and the role is HARDCODED `member` (never derived from a SAML attribute — the D-168-03 escalation footgun).

Purpose: The SSO first-login has no invitation token and the user is not yet a member, so the user-JWT RLS insert is denied — the same authorized service-role/BYPASSRLS path as the 167 accept. Getting the idempotency + duplicate-email-tolerance right here is the load-bearing correctness of the whole JIT.
Output: `require_sso_manage`, `provision_sso_membership`, and an integration test modeled on `test_167_jit_race.py`.
