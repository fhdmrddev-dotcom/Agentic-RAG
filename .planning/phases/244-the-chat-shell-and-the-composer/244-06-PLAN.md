**⛔ THE "UNSET DESTINATION ⇒ REFUSE" RULING — a REQUIRED field, not a hand-rolled branch.**

**mechanical**:

- ✅ A **required** field (`folder_id: str`, no default) on a new `_StrictBase` request model.
  FastAPI + `extra="forbid"` then returns a **422 before the handler runs**, so the refusal cannot
  be forgotten in a branch a future edit adds.

  inside a handler that already has two `except` arms and a 502 catch-all, and it is exactly the kind
  of guard that survives as prose after a refactor. If you take it anyway, it needs its own driven
  RED case and the SUMMARY must say why the model-level refusal was not usable.

  field, no shape change, no migration"*. A new **request** model is additive and stays in that
  spirit — ⛔ do not add a field to an existing model.
