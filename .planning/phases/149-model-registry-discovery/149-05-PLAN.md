| Boundary | Description |

| service-role DB access | No RLS backstop on the admin write path — the router gate + allowlist are the authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-149-10 | Elevation of Privilege (SC#4) | GET/PATCH /admin/models | mitigate | Router-level `Depends(require_operator)` → byte-identical 404 for non-operators (no RLS backstop; the gate is load-bearing — tested in test_149_model_gate.py) |
| T-149-11 | Tampering (SQL injection) | PATCH field names | mitigate | `_MODEL_CAP_COLUMNS` allowlist rejects unknown keys with 422 BEFORE any SQL; upsert is parameterized asyncpg — no client field name reaches a SET clause (Pattern 2) |
| T-149-12 | Repudiation | capability writes | mitigate | Every write stamps a ✎ `model.capability.set` receipt via operator_audit_floor; a failed persist stamps `write_failed` (honest, no false success) |
| T-149-13 | Tampering (routing integrity) | invalidate on write | mitigate | `invalidate_model_overrides_cache()` on every write so an edit takes effect on the next request (≤30s cross-worker, the accepted 147 SC#1 semantics) |
| T-149-SC | Tampering | package installs | accept | Zero new packages |
