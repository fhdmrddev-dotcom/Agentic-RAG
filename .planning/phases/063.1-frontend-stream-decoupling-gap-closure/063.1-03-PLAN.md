<objective>
Make in-flight SSE consumers survive thread switches (Gap-003 fix). When the user navigates away from a streaming thread, the SSE keeps reading deltas in the background; per-event `setMessages` calls become no-ops via a guardedSetMessages wrapper. When the user navigates back, state updates resume because activeThreadIdRef matches streamingThreadIdRef again, and the still-live subscription means reconcile's narrowed short-circuit (Plan 02) skips opening a duplicate consumer.

Purpose: Phase 063 incorrectly aborted the SSE consumer on every thread switch via `abortStream()` in ChatArea's thread-change effect. Removing that call + guarding sendMessage's per-event updates fixes the blank window, the wasted Redis bandwidth, and the duplicate `GET /runs/{rid}/stream?since=0` request.

Output: One-line deletion in ChatArea.tsx + guardedSetMessages wrapping in sendMessage's makeStreamCallbacks call site + grep-verified hook unmount audit comment.
</objective>
