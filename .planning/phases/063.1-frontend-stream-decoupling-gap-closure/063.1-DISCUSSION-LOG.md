## Offset-cursor storage (Gap-004 input)

| Option | Description | Selected |
|--------|-------------|----------|
| Hook-local useRef | `lastSeenOffsetRef.current = Map<run_id, ms_id>` inside useMessages. Survives tab/reconcile cycles within a page lifetime; F5 wipes it. Gap-001 solved separately by run_id-based dedup. | ✓ |
| sessionStorage-backed | Persisted across F5; directly kills Gap-001 by avoiding replay. Adds setItem cost per delta and stale-cleanup concerns. | |
| Hybrid (ref + flush on terminal/visibility-hide) | Ref hot path; persist on lifecycle events. Survives F5. More moving parts. | |

**User's choice:** Hook-local useRef
**Notes:** Trade-off accepted — Gap-001 (refresh duplicate-bubble) is solved by D-063.1-04 (runId-match dedup) rather than by persisted offset, keeping the change scope inside useMessages and avoiding a coupling to browser storage semantics.

## Concurrent-reconcile race fix (Gap-005)

| Option | Description | Selected |
|--------|-------------|----------|
| In-flight guard + MERGE loadMessages | `reconcileInFlightRef.current` boolean (skip while true). `loadMessages` MERGE preserves temp-${run_id} placeholders whose run_id is not yet in DB. Belt-and-braces. | ✓ |
| In-flight guard only | Just the boolean ref. loadMessages stays REPLACE. Risk: any future caller of loadMessages running concurrent with a placeholder insert wipes it. | |
| Debounce reconcile triggers (50ms trailing) | Wrap reconcileRef in debouncer. Coalesces visibilitychange+focus. Fragile against pageshow latency, adds latency to single triggers, doesn't address non-listener call paths. | |
| All three (guard + merge + debounce) | Maximum defense. Adds debounce complexity for marginal gain. | |

**User's choice:** In-flight guard + MERGE loadMessages
**Notes:** Debounce explicitly deferred. Merge protection covers the terminal-time refetch (line 698) and `buffer_expired` fallback (line 493) paths in addition to the reconcile race itself.

## Resume button data flow (Gap-002 fix)

| Option | Description | Selected |
|--------|-------------|----------|
| LEFT JOIN runs in GET /threads/{tid}/messages | Modify existing endpoint. Single round-trip; no flicker. RLS piggy-backs on existing messages SELECT. Pre-run-backed messages get null. | ✓ |
| Separate GET /threads/{tid}/recent-failed-runs endpoint | Frontend merges in parallel with active-runs + loadMessages. Three round-trips; potential render flicker before merge. | |
| Single GET /threads/{tid}/recent-runs (replaces getActiveRuns) | Broaden active-runs to streaming + failed + recent completed. Bumps Phase 062's locked API contract. | |

**User's choice:** LEFT JOIN runs in GET /threads/{tid}/messages
**Notes:** This decision feeds D-063.1-04 (refresh dedup) — the JOIN supplies `runId` on DB-loaded assistant rows, which is what the runId-match short-circuit needs. RLS verification (cross-user JOIN leak guard) is a required test.
