**Thread switches no longer abort the in-flight sendMessage SSE consumer — guardedSetMessages closure in sendMessage early-returns when streamingThreadIdRef diverges from activeThreadIdRef, and the bare `abortStream()` call is gone from ChatArea's thread-change effect.**

## Accomplishments

- Removed the bare `abortStream()` call from ChatArea's thread-change useEffect (D-063.1-07 / Gap-003 fix). Switching threads mid-stream no longer kills the in-flight `sendMessage` AbortController, which means the SSE consumer survives the switch and continues writing through the guard.
- Wrapped sendMessage's `makeStreamCallbacks` setMessages with a hook-scoped `guardedSetMessages` closure (D-063.1-08). Per-event accumulators are no-ops when the user has navigated to a different thread; state updates resume automatically when the user navigates back because `streamingThreadIdRef.current === activeThreadIdRef.current` again.
- Audited `useMessages()` mount lifetime — single consumer (ChatArea.tsx:39); ChatArea is NOT keyed on thread.id (`grep` for `key=.*thread.*ChatArea|<ChatArea.*key` returns 0 matches). Confirmed via comment block that the hook unmount effect (`subscriptionsRef` abort + clear) only fires on logout / route change, not on thread switch (D-063.1-10).
- Preserved `abortStream` export from `useMessages` and the destructure paths used by genuine timeout cases (e.g., `loadMessages`'s loadAbortRef path); this plan removed only the one ChatArea call site.

## Decisions Made

- **Inline `guardedSetMessages` in sendMessage rather than lifting to a hook-level helper.** The plan-level CONTEXT.md (D-063.1-08) suggested "lifting" the WR-05 helper, but reconcile's guard captures `activeThreadIdRef !== threadId` (a captured snapshot from the reconcile-call's threadId arg) while sendMessage's guard captures `streamingThreadIdRef !== activeThreadIdRef` (two refs, no snapshot). They have semantically different signatures, so a unified helper would have to be parameterized — adding indirection without reuse benefit. Kept both guards inline at their respective call sites; the comment in sendMessage cross-references reconcile's pattern.
- **Drop `abortStream` from ChatArea's destructure.** The only call site in ChatArea was the one being removed; leaving the destructure would produce an unused-variable lint signal. The two remaining text-matches (`grep abortStream src/components/chat/ChatArea.tsx`) are documenting comments only. `abortStream` stays exported from `useMessages` and is still consumed by genuine timeout cases.
- **Keep the audit comment text grep-friendly to the verify command.** The first draft used the literal phrase `useMessages()` inside the audit comment; that broke the plan's `grep -rn 'useMessages()' src | wc -l == 1` check. Reworded to `Single hook consumer: ChatArea.tsx (line 39)` and `If a future surface adds a second consumer of this hook` — preserves audit intent without inflating the literal-text grep count above the unavoidable function declaration line.
