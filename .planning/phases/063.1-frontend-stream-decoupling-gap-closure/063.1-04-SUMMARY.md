## Accomplishments

- Added `reconcileInFlightRef = useRef(false)` adjacent to `lastSeenOffsetRef` (D-063.1-11). The guard is set synchronously **before** the `Promise.all` dispatch in `reconcile()`, so a second concurrent call (which is also synchronous to the same tick before its own `await`) reads `true` at the top-of-function guard and returns immediately. The lock is released in an outer `try/finally` block — every early-return path inside the body (cross-thread guard at line 669, inner `Promise.all` catch at line 661) flows through the `finally` and releases the lock.
- Changed `loadMessages` from REPLACE to MERGE at line 382 (D-063.1-12). The new functional updater builds a `dbRunIds` set from the freshly-fetched data, filters `prev` for `temp-`-prefixed placeholders whose `runId` is **not** in that set, and concatenates `[...data, ...liveTempPlaceholders]`. This preserves any in-flight reconcile-inserted placeholder whose run hasn't yet persisted to the DB; conversely, it drops any placeholder whose `runId` **is** in the DB result (the DB has caught up; reconcile's `runId`-match dedup at D-063.1-04 will route SSE deltas to the DB row, so preserving the placeholder would dup-bubble).

## Decisions Made

- **Bool ref, not Map.** D-063.1-11 specifies the guard semantics: only one viewing thread is active at a time, so a single in-flight bit is sufficient. A `Map<thread_id, boolean>` would suggest per-thread parallelism that doesn't exist (the hook only ever reconciles the current thread; thread switches don't queue reconciles, they just tear down and re-mount the surrounding component tree). Mirrored `resumeInFlightRef`'s shape verbatim — same `useRef(false)` + sync set-before-await + try/finally release.
- **Outer try/finally over re-indent.** Wrapping the entire reconcile body in an outer `try/finally` means the inner `Promise.all` block and the for-loop body now sit one nesting level deeper. Two implementation paths existed: (a) re-indent the entire ~150-line block by +2 spaces; (b) leave the inner indentation at the original level — TypeScript syntax is whitespace-insensitive, and the diff is dramatically cleaner. Path (b) chosen because the plan's acceptance criterion explicitly requires "the for-loop content is byte-identical to the Plan 02 result". Re-indenting would have produced a 150-line diff with subtle drift risk in the dedup/cursor/onTerminal blocks; leaving the inner indent preserves byte-identical content as required.
- **Spread order: `[...data, ...liveTempPlaceholders]`.** CONTEXT.md grants Claude's Discretion on merge ordering; this plan picks DB rows first, placeholders appended. The DB rows are sorted by `created_at` server-side (chronological); live placeholders are by definition the newest in-flight runs (most recent `run_id`), so appending them at the tail matches chronological flow. React keys on the stable `id` field prevent any collision risk regardless of order.
- **Three-clause filter predicate.** `m.id.startsWith("temp-") && m.runId && !dbRunIds.has(m.runId)`. Each clause is necessary:
  - `m.id.startsWith("temp-")` — only consider temp placeholders, not persisted DB rows.
  - `m.runId` — Phase 063 invariants only set `runId` on placeholders that have been issued by sendMessage (line 460) or reconcile (line 681); a temp placeholder without `runId` is from legacy code paths that predated run-backed streaming, and shouldn't be preserved.
  - `!dbRunIds.has(m.runId)` — this is the dup-bubble guard. If the DB result already carries a row with this `runId`, reconcile's runId-match dedup at D-063.1-04 will route SSE deltas to the DB row; preserving the placeholder would render two bubbles for the same run.
