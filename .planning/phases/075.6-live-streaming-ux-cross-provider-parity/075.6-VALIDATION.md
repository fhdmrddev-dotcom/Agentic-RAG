### Orchestrator deviation findings (non-blocking)

1. **Backend `--reload` watcher missed Plan 01 commits.** Initial UAT-1A run had 3 `tool_args_progress` events at 5KB boundaries but `has_code_so_far=false` because uvicorn worker PID 15820 (started 7:03 PM, system Python) was running stale code — `anthropic_service.py` modified at 10:22 PM but the `--reload` watcher didn't fire. Diagnosed via process start time vs file mtime comparison, killed PIDs 11300+11984, restarted uvicorn from project venv without `--reload`. After restart, all 4 cross-provider UATs verified GREEN. **Implication:** `--reload` on Windows + watchfiles can silently fail for cross-process edits. Document under v2.6 carry-forward seeds OR add a startup banner that logs the loaded source-tree mtime so future cycles catch this immediately.

2. **React state timing during preparing window.** Mid-stream React state inspection on Tab A showed `argsCodeText_len=0` even with backend confirmed sending 2 events (len 4769→9459 on the wire). Backend SSE wire format proven correct via direct fetch of `/runs/{id}/stream`. Plan 02 SSE-parser-to-reducer wiring is statically correct per inline source review (`api.ts:405` forwards `parsed.code_so_far`, `StreamsProvider.tsx:317` applies longer-string-wins). Most likely explanation: measurement window was post-`onToolStart` which intentionally clears `argsCodeText: undefined` (line 352) per CONTEXT.md Claude's Discretion. Inconclusive on whether there's a genuine forwarding bug; vitest tests assert correctness in isolation. Re-open trigger if a real user reports the panel never showing during long preparing windows on production.
