## Decisions Made

- **Working badge visibility predicate uses three inputs (NOT two).** `(activeTool || isPlanning) && !allToolsDone` — the `isPlanning` arm catches the brief window between user submission and the first tool's `tool_preparing` event when no tool is yet active. Without `isPlanning`, the user would see a 1-3s blank turn before the badge appears. With it, the badge becomes the canonical "agent is thinking/working" signal end-to-end.
- **`<WorkingBadge>` renders UNCONDITIONALLY at MessageItem.tsx (not gated outside the JSX).** The outer wrapper DOM node is preserved across visible transitions — that's the Pitfall 5 mitigation working in tandem with the component-internal React.memo. The `visible` prop drives the inner content gate. Gating outside (e.g., `{visible && <WorkingBadge .../>}`) would cause remount/unmount churn and break the `animate-brandPulse` keyframe continuity.
- **Step-list collapse default-collapsed-when-shouldCollapse, expand on chevron click.** `useState(true)` for `stepsCollapsed` — when N≥3, the user sees the compact 3-row view by default and can opt in to the full chain. Lower friction; the active step + iteration divider are still always visible.
- **Summary row carries `data-iteration-min` (NOT max).** Pitfall 6 mitigation. The D-067-03 iteration divider above the FIRST-non-collapsed item must fire for the iter-(min-of-collapsed) → iter-(active) boundary in expanded view, NOT the iter-(max) boundary. Min preserves the topmost iteration boundary inside the collapsed group when expanded.
- **Bug-report frontmatter changes use Edit (not Write) tool.** Task 6 explicitly mandates Edit over Write to preserve body content. Acceptance criterion grep counts lines to confirm.
- **Task 8 UAT-CHECKPOINT closed orchestrator-driven, not operator-driven.** Phase 063 precedent + operator's stated preference. Orchestrator drove Chrome DevTools MCP + Redis stream inspection across 4 providers + multi-tool + parallel-thread; operator approved at the project level after reviewing the 8/10 GREEN evidence bundle.
- **UAT-4 (long-message) and UAT-5 (sub-agent kind) deferred with re_open_triggers.** UAT-4 required Supabase Studio SQL editor INSERT of 50 prior messages — orchestrator session had `docker exec` denied. UAT-5 needed a non-`analyze_document` sub-agent trigger which wasn't enumerated in production yet. Both deferred with concrete re-open triggers; vitest virtualization tests in `streamsProvider.test.tsx` + the static Req #9 audit cover the per-thread bucket invariant + sub-agent gate-drop correctness respectively, so the deferred axes are NOT blind spots.

- **Found during:** Task 8 UAT-1A initial run.
- **Symptom:** First UAT-1A run produced 3 `tool_args_progress` events at 5KB boundaries BUT with `has_code_so_far=false` — backend was emitting the pre-Plan-01 wire format despite the source code being on the post-Plan-01 commit.
- **Diagnosis:** Process inspection showed uvicorn worker PID 15820 started 7:03 PM (system Python interpreter) while `backend/app/services/anthropic_service.py` was last modified at 10:22 PM. The `--reload` flag's watchfiles backend silently failed to fire on the cross-process edits.
- **Fix:** Killed PIDs 11300 + 11984; restarted uvicorn from the project venv (`backend/.venv/Scripts/python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000`) WITHOUT `--reload`. After restart, UAT-1A → UAT-1D all verified GREEN with the post-Plan-01 wire format.
- **Implication:** `--reload` on Windows + watchfiles can silently fail for cross-process source-tree edits. Logged as a v2.6 carry-forward seed candidate (consider adding a startup banner that logs the loaded source-tree mtime so future cycles catch this immediately) — orthogonal to Plan 03's surface but worth carrying forward.
- **Documented in:** `075.6-VALIDATION.md` §Orchestrator deviation findings #1.

**2. [Inconclusive — React state-timing window] Mid-stream React state inspection showed `argsCodeText_len=0` while backend SSE wire confirmed 2 events on the wire.**

Vitest reducer tests (Plan 02's 4 `argsCodeText` it() blocks) assert correctness in isolation — they would have failed if the reducer was actually broken. Logged as a re-open trigger if a real user reports the panel never showing during long preparing windows on production.
- **Documented in:** `075.6-VALIDATION.md` §Orchestrator deviation findings #2.
