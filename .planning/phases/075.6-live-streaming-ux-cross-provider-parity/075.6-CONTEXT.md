## Phase Boundary

During every `tool_preparing → tool_start` window for `execute_code` exceeding the 5 KB cadence threshold, the assistant turn renders a live code panel that shows the LLM-generated code text growing monotonically — on all four LLM providers (Anthropic, Google, OpenAI, OpenRouter) using one provider-agnostic frontend component fed by one normalized SSE event vocabulary.

Goal verbatim from SPEC.md §Goal. ~80% of substrate is already in place (Phases 068 / 068.5 / 075 / 075.1). Gap is narrow: one new field on an existing event (provider-uniform across 4 adapters), one new frontend collapsible component, and three small frontend rendering improvements that surface already-accumulated state.

<decisions>
## Implementation Decisions

### A. Plan split & wave shape

- **D-075.6-A1:** **3-plan split** — Plan 01 = backend cross-provider emit (SPEC Reqs 1-3, all 4 adapters + `code_so_far` field). Plan 02 = frontend live panel + reducer (SPEC Reqs 4-5). Plan 03 = frontend UX bundle (SPEC Reqs 6-8 sub-agent gate drop + step-list collapse + Working badge; Req 9 invariant audited across all plans).
- **D-075.6-A2:** **Wave shape** — Wave 1 = Plan 01 (backend emits the new field across all 4 adapters); Wave 2 = Plan 02 + Plan 03 in parallel (independent frontend surfaces, no merge conflicts). Mirrors Phase 075.1 wave shape (backend root cause first, frontend parallel after) per [[project_phase075_1_shipped]].

### B. Component file placement

- **D-075.6-B1:** **Flat under `frontend/src/components/chat/`** — `ToolArgsLivePanel.tsx` + `WorkingBadge.tsx` live alongside existing chat components (ExecuteCodeBlock, OutputFileCard, ToolCallPanel, MessageItem). Matches the established pattern. Zero refactor risk. Reusability for future per-token signals (extended thinking summary, eval pane streaming — per ROADMAP forward-reference) comes via **component API** (props-driven content/title/state), NOT folder structure.
- **D-075.6-B2:** Promotion to a `components/streaming/` subfolder is **deferred** to a future phase that introduces ≥3 streaming components needing co-location. If v2.7 thinking-models phase adds an extended-thinking summary component, that's the natural trigger to extract — not 075.6.

### C. UAT execution order + 4-axis bandwidth (mandatory per CLAUDE.md SC#10)

- **D-075.6-C1:** **Axis sequence** — (1) cross-provider FIRST; (2) multi-tool; (3) parallel-thread; (4) long-message.
- **D-075.6-C2:** **Cross-provider order** — Anthropic → Google → OpenAI → OpenRouter. Anthropic is the known-good baseline (existing `tool_args_progress` emit + commit `0a5a2db` byte counter); confirming panel UX renders correctly there first means the riskier OpenAI + OpenRouter runs (new emit paths from Plan 01) test ONLY the backend, not the panel.
- **D-075.6-C3:** **Composed axes** — multi-tool exercises `search_documents` + `execute_code` in one prompt, run on Anthropic only (provider-uniform invariant means cross-provider parity is already covered by axis-1). Parallel-thread uses **two browser tabs, same user** (`fhdmrd@gmail.com` per [[reference_local_dev_app]]); Thread A streaming while Thread B accepts a new prompt asserts Phase 075.4 D-075.4-A1 per-thread state invariant still holds with the new panel state. Long-message uses **Supabase SQL editor pre-seed** of ≥50 prior message pairs into a thread (matches the `apply_migrations_via_sql_editor` workflow per [[feedback_apply_migrations_via_sql_editor]]).

### E. Sub-agent visual indicator

- **D-075.6-E1:** **No sub-agent badge in 075.6.** After SPEC Req #6's narrow-gate drop, sub-agent text streams visibly inline within the parent tool row. The turn-level Working badge (Req #8) covers the parent's silent windows. Adding a sub-agent-scoped badge would be redundant noise inside a row that already has streaming text as the activity signal.

### Claude's Discretion

- **Aggregation buffer shape (OpenAI/OpenRouter, Plan 01):** maintain a **separate string accumulator per `tool_index`** rather than reusing the existing byte-count buffer. Reason: the byte counter today is a running `int`; the underlying chunk text would need to be re-accumulated regardless. Separate slot allows clearing on `tool_start` without touching the byte-count path. OpenAI keys off `chat.completions.chunk.choices[0].delta.tool_calls[N].function.arguments`; OpenRouter keys off the upstream OpenAI-shaped equivalent per locked D-075.6-SPEC OpenRouter normalization.
- **Reducer behavior on `tool_start` (Plan 02):** clear `argsCodeText` to `undefined` so post-start renders read from the source-of-truth `tc.args.code` (per SPEC Req #5 "cleared on tool_start transition"). Forces panel to collapse + drop the cached streaming text; final args parsed by `tool_start` win. Avoids stale-cache risk if `tc.args.code` diverges from the last `code_so_far`.
- **Test fixture extension:** add the new `argsCodeText` reducer assertions to the existing `frontend/src/__tests__/providers/streamsProvider.test.tsx` (or its closest sibling), NOT a new file. Add the Phase 067.5 Branch D-3 regression assertion to the existing `streamsProvider_067_5_regression.test.tsx` (already exists; co-locate the new regression case with the existing invariant tests).
- **Working badge styling:** reuse Phase 068.5 brand pulse animation if present; otherwise add a 1.5s CSS keyframe in `frontend/src/index.css` matching the pink-orange brand accent. Position **inline at top of MessageItem** (above MarkdownRenderer), NOT absolute-positioned — avoids layout shift on appear/disappear.
- **Vitest test file naming:** follow existing `frontend/src/__tests__/providers/*.test.tsx` pattern.
- **Plan-internal commit cadence:** atomic commit per task per D-PRD-15 (no batching).
- **Code-review depth:** Standard (matches Phase 075.1 + 075.4 cluster precedent — touches frontend reducer, streaming UI surface, and 4 backend service adapters).
