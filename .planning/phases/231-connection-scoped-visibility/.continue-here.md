# BLOCKING CONSTRAINTS — Read Before Anything Else

> Each was discovered through actual failure this session, not predicted.

- [ ] **CONSTRAINT: A `str.replace` anchored to a LINE PAIR will match the first of several classes
      that share it.** It happened TWICE. In `connector.py` the field landed twice in `Create` and
      never in `Response` (23 new test failures); in `connector_service.py` an 8-space pattern
      matched inside an already-edited 12-space line and duplicated a keyword argument.
      **Mitigation is structural: anchor every edit to a class or function BODY** (find the class
      line, bound it at the next `class `, insert inside), and assert `s.count(old) == 1` before
      replacing — never just `assert old in s`.
- [ ] **CONSTRAINT: Do not reconstruct SQL from a filtered grep.** Rebuilding
      `match_document_chunks` / `keyword_search_chunks` from grep output was **wrong in five ways**
      (plpgsql not sql · an invented `filename, metadata` return pair · `0.3` not `0.0` ·
      `plainto_tsquery`/`ts_rank_cd` not `websearch`/`ts_rank` · volatility). The invented return
      type alone would have made `CREATE OR REPLACE` fail. **Mitigation: dump
      `pg_get_functiondef` and add exactly one line to the verbatim body.**
- [ ] **CONSTRAINT: A green gate proves nothing about behaviour.** Phase 230 shipped 30/30 green
      tests over a `progress` column that was corrupt in the database, because every test passed a
      dict in directly and never round-tripped through Postgres. **Mitigation: for any column the
      code READS BACK, assert the round-tripped TYPE (`isinstance(x, dict)`) after a real DB read,
      not just the value.**

**Do not proceed until all boxes are checked.**
