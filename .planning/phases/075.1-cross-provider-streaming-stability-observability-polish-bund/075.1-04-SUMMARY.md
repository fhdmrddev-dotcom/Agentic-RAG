## Decisions Made

- **@traceable fallback for Anthropic LangSmith wrap** because `wrap_anthropic` is NOT in the installed langsmith version. Verified at plan-time: `python -c "from langsmith.wrappers import wrap_anthropic"` raises `ImportError`. The `@traceable(name="ChatAnthropic", run_type="llm")` decorator path handles generator functions per langsmith docs and provides equivalent trace coverage. ImportError guard around the decorator import keeps the module resilient if langsmith is ever missing in prod (unlikely but graceful).
- **Per-provider `chat_name` uses `f"Chat{provider.title()}"`** — yields `ChatOpenai`, `ChatAnthropic`, `ChatOpenrouter`, `ChatOllama`, `ChatGoogle`. Verified the installed `wrap_openai` signature accepts the kwarg: `(client: 'C', *, tracing_extra: ..., chat_name: 'str' = 'ChatOpenAI', completions_name: 'str' = 'OpenAI')`. Older langsmith versions without the kwarg fall back to bare `wrap_openai` via `TypeError` handler.
- **Sandbox custom image is OPT-IN via `SANDBOX_IMAGE` env var, not mandatory.** Building `Dockerfile.sandbox` costs ~2 minutes the first time. Gating on env var means local dev that hasn't built it falls back to `llm_sandbox`'s default image without behavior change. Recommended for staging/prod via `SANDBOX_IMAGE=agentic-rag-sandbox:075.1` in env config.
- **`harvest_output_files` signature extension is a breaking type change** (was `list[dict]`, now `tuple[list[dict], set[str]]`). Adapted Plan 02 regression tests to the new shape — they still verify the loop-responsiveness invariant + per-entry contract. There is exactly one production caller (`threads.py` agent loop), updated atomically with the signature change. The breaking change is OK because the only external caller is in-repo.
- **Atom C (stdout styling) shipped as a regression test only.** The existing wire (StreamsProvider routes `onCodeStdout` → `kind:'stdout'`, `onCodeStderr` → `kind:'stderr'`; `ExecuteCodeBlock` renders `text-emerald-400` for `kind === "stdout"`, `text-red-400` otherwise) is already correct. No source change required — the test pins the contract so a future refactor can't silently regress. B-260519-07's stdout-portion symptom may have been an observation against a separate visual ambiguity (emerald is sometimes perceived as the "warning" color in low-light themes); functionally the code is correct.
- **Atom F (Settings dropdown) shipped as a regression test only.** `SettingsPage.tsx` already ships the sub-agent override dropdown (line ~843-865) with "Auto (cheapest)" mapping to empty string. Plan 04 test source-greps the file to lock the surface so future Settings refactors don't accidentally remove it.
- **Atom B dedup preserves first-occurrence ordering** (sequential scan + `Set<string>` of seen ids) so the existing `displayItems` timestamp sort behaves identically; only duplicate-suffix entries get dropped. Stable id key resolution: `tc.id || ${tc.name}-${tc.startedAt ?? ''}`.
