## How every row is driven — the cheapest honest method

**Proven in Phase 185 and re-recommended by RESEARCH.** Drive each row as a **real run** with a
**per-request `model` + `provider`** on:

```
POST /threads/{id}/messages     body: { ..., "model": "<id>", "provider": "<provider>" }
```

then press Stop on the row's assigned mount, then read the verdict from the database:

| Table | What to read |
|---|---|
| `workflow_runs` | `status` — must be `cancelled`, never left `active` |
| `threads` | `active_workflow_run_id` — must be `NULL` after the stop |
| `workflow_phases` | the interrupted row `= 'cancelled'`; **completed rows UNTOUCHED** (D-07) |
| `runs` | the producer row `status = 'cancelled'` |
| `harness_audit` | the recorded outcome verb — ⚠ a `"zombie_healed"` outcome renders **"recovered a stuck run"**, **NEVER "killed"** (064-B / D-11) |

### ⚠ WHY PER-REQUEST AND NOT A SETTINGS CHANGE — this is a mitigation, not a convenience

Threat **T-194-01-02** (Tampering): switching the global model/provider in Settings between rows
would (a) mutate the operator's own environment and (b) let rows contaminate each other, so a later
row could inherit an earlier row's configuration and a failure could not be attributed. **A
per-request override mutates NO global setting**, so the operator's environment is untouched and
each row is independently attributable.
