<objective>
Wire the entire self-improvement loop into ONE home — a thin proposal card inside `SkillEvalSection`
under the eval readout (D-08): "Propose improvement" (enabled once the run has results, D-01) -> render
the proposer's edit as a unified line diff (D-09, via Plan-06 `lineDiff.ts`) with the rationale +
which-evidence-drove-it -> approve/reject only (D-10). On approve, reattach the existing eval live
readout to the re-eval run (`re_eval_run_id`, Pattern 3), then show the terminal verdict WITH the honest
case-matched counts (`proposal.gate`, D-13): promoted (counts + "promoted to the live skill") /
not-promoted (counts + failing evidence + force-promote, D-06) / interrupted (with re-run, D-14). State
always re-fetched from the DB — never optimistic.

Purpose: the user experiences the loop as results -> propose -> review diff -> approve -> re-eval ->
promoted/not-promoted, all on the skill's eval surface, with honest counts on every terminal verdict.
Output: the proposal card + handlers in `SkillEvalSection.tsx`.

Stays thin/undesigned — the designed Skill Evals panel is Phase 137 (D-08 / 137 fence); no design-system
chrome, matching the file's existing `--skip-ui` header. Honors D-06, D-08, D-09, D-10, D-13, D-14.
