<objective>
Fix the one load-bearing architectural gap (RESEARCH Pitfall #1): `_handle_load_skill`
(`tool_dispatcher.py:656`) resolves a skill's instructions from the LIVE `skills` table by name, so a
re-eval of a DRAFT version whose instructions differ from the live skill would silently measure the
OLD instructions — making the auto re-eval gate a no-op. Thread an **additive, default-off**
`skill_instructions_override: dict[str,str] | None = None` seam through `RunContext` -> `ToolContext` ->
`_handle_load_skill`, and add one additive optional param to `run_eval_job` to carry it into the
WITH-arm build.

The RunContext field is unpacked inside `run_agent_loop` (at `agent_loop.py:1105`, right beside
`skill_catalog_override = ctx.skill_catalog_override`) and passed into BOTH ToolContext build sites:
the primary `tool_ctx = ToolContext(` at `:2279` AND the resume `_resume_ctx = ToolContext(` at `:1501`
(a resumed run must keep measuring the DRAFT, not silently revert to the live skill). The sub-agent
(task-tool) ToolContext in `task_service.py:585-636` also copies the field from `parent_ctx` — otherwise
a re-eval case that invokes the `task` tool would measure the LIVE instructions inside the sub-agent.

Purpose: Make the D-05 draft-version-first re-eval actually measure the draft's instructions WITHOUT
touching the live skill — the correctness precondition for the entire promotion gate.
Output: the override seam end-to-end (RunContext + both ToolContext builds + sub-agent ctx +
_handle_load_skill + run_eval_job) + its guard test.

**Red-line note (pre-empts a checker false-flag):** this is an ADDITIVE, default-off extension exactly
matching the shipped `skill_catalog_override` / `phase_whitelist` / `skill_snapshot` / `workflow_run_id`
precedents — `None` on every existing caller ⇒ Deep Mode byte-identical. It does NOT fork the shared
path; the both-arms/judge/SSE/heartbeat/terminal logic in `run_eval_job` is untouched. Only the WITH
arm's instructions SOURCE is overridden. This satisfies D-16 ("consume agent_loop READ-ONLY") in the
same sanctioned way Phase 133 added `skill_catalog_override`.
</objective>
