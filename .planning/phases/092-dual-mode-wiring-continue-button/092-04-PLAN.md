<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → composer | The grayed toggle is a UX courtesy ONLY — the authoritative lock enforcement is the server-side 409 (plan 02) |
| client → continueRun / getThreadWorkflow | Auth headers carried on every request; backend enforces ownership + the 3-cap |
| SSE → store | cap_paused / lock events are best-effort hints; the mount-time GET reconcile is the source of truth (D-v2.5-03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-092-14 | Tampering / client-trust | grayed toggle bypass | mitigate | The disabled toggle is courtesy only; a user who re-enables it client-side still hits the server-side 409 (plan 02 T-092-06) — the frontend never carries the enforcement |
| T-092-15 | Denial of Service (self) | global-boolean lock regression | mitigate | Per-thread keyed Map + owning-thread-id derivation (SC#3) — a background workflow thread cannot lock an unrelated thread's composer; the binding gate is the parallel-thread Chrome MCP UAT |
| T-092-16 | Spoofing | SSE hint trusted as truth | mitigate | D-v2.5-03: the mount-time GET /threads/{id}/workflow reconcile is the source of truth; a forged/stale SSE hint is corrected on reconcile (lock_is_stale heals a dangling lock) |
| T-092-17 | Information Disclosure | published-workflow picker | accept | The picker only lists what the backend's owner-scoped list endpoint returns (plan 02 T-092-07) — the frontend cannot widen the scope |
</threat_model>
