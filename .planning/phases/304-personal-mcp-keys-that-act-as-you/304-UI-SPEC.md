# Phase 304 — UI Design Contract

> Visual and interaction contract for personal MCP keys (KEY-01, KEY-03, KEY-04, KEY-05, KEY-06).
> KEY-02 has no UI of its own; it shows up only as the "acts as you in {org}" facts below.
> Generated by gsd-ui-researcher; the checker validates it.

**What this file decides.** Phase 293's API keys surfaces already have an approved contract
(`293-UI-SPEC.md`). This phase adds a **second kind of key** to those surfaces and adds **two
switches**. It brings in no new tokens, primitives, type sizes or colours. Everything below either
reuses a 293 element as it is, or adds a leaf component built from the same parts. Where this file
says "as 293", the 293 contract applies unchanged.

**No new places.** No Settings tab, no org-admin tab, no nav entry (D-01, D-02).
`SettingsPage.tsx` is not edited.

**Icon convention (sketch-findings §Icon Convention).** No client logos (Claude, Cursor, VS Code)
are drawn on the snippet tabs. The tabs are words only. Reason: `@lobehub/icons` covers model
providers, not editors, and the convention forbids hand-drawn or per-surface marks.

## Spacing Scale

As 293. All values are multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | chip gaps, icon-to-text gap in kind tiles and tags, gap between a tool name and its plain label |
| sm | 8px | gap between buttons, meta-line gaps, gap inside the secret box, gap between preset segments and the checklist |
| md | 16px | key card and draft card padding, form label-column gap, kind tile padding, tree indent per depth level |
| lg | 24px | header card padding (`p-6`, shipped), org Settings section padding |
| xl | 32px | empty-state vertical padding |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions (all inherited from 293 or the shipped grid, all multiples of 4):
- **12px** (`gap-3`) between stacked cards and between form rows. This is the shipped card-stack gap.
- **Form label column:** 128px on screens ≥768px, stacked above the field below 768px (as 293).
- **Scrolling lists:** the folder tree and the tool checklist each scroll inside a bordered box with max-height **208px** (as the 293 workflow picker).
- **Tree indent:** 16px per depth level. Indent stops growing after depth 4; deeper rows keep the depth-4 indent and show their path in the row's `title`.
- **Touch targets:** every checkbox row, kind tile and segment is at least 44px tall below 640px (`min-h-[44px] sm:min-h-0`, the `ScopePicker` precedent).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` hsl(216 45% 4%), about #060A0F | page behind Settings, the org-admin shell and the Control Room; snippet and secret wells |
| Secondary (30%) | `--card` hsl(220 30% 7%), about #0C1017; `--muted` hsl(220 30% 11%) for nested wells | header card, key cards, draft card, kind tiles at rest, folder tree and tool checklist boxes, org Settings section |
| Accent (10%) | `--primary` hsl(239 100% 82%), about #A3A5FF; `gradient-primary` for filled CTAs | the reserved list below |
| Destructive | `--destructive` hsl(0 72% 51%), about #DC2828; refusal text `hsl(0 80% 80%)` | Revoke on a key card, the revoke sheet (unchanged), the armed OFF state of both MCP switches (065-A) |
| Warning (semantic) | `--warning` hsl(38 92% 60%), about #F7B23B | show-once card (unchanged), the Claude.ai warning box, the "Workaround" chip on the Claude Desktop tab, the `⏸ switched off` tag and its line on a key card |
| Success (semantic) | `--success` hsl(142 71% 45%) | `● active` / `● created` tags, `✓ Copied`, the 1.6s fresh border (all as 293) |
| Org indigo | the shipped `OrgBand` tint | admin list and org switch only, inherited from `OrgAdminShell` (080-A: amber stays operator-only) |

Accent (`--primary`) is reserved for exactly these elements:
1. Filled primary buttons: "New key", "Create key", "I've saved the secret" (as 293).
2. The selected segment of the Expires control and of the Tools preset control.
3. The selected kind tile's border and 1px ring.
4. The draft card's border and ring (as 293).
5. The 3px left rule of the "acts as you" note.
6. Text links: "How to connect" / "Hide how to connect" on an MCP card, "Show activity" (293), the guide link.
7. The active snippet tab's underline (shadcn `TabsTrigger` active state).
8. The ON track of a switch (`bg-primary/70`, shipped `CapabilitySwitch`).
9. Focus rings (`--ring`), unchanged.

Accent is never used for kind chips, tool names, folder rows or the org name. Those are facts and
use `text-muted-foreground`, or `text-foreground` when bold.

Colour is never the only signal. The switched-off tag carries `⏸` and words. The Workaround chip
carries the word. Disabled folder and tool rows carry a right-hand reason in words. An armed switch
carries "off for {scope}" and an impact sentence.

## Surface 1 — Settings → API keys (member)

### 1a. Header card (as 293, reworded)

Title "API keys" with `KeyRound`, as shipped. The description is reworded so it covers both kinds
(§Copywriting). The limits line renders only when the member has at least one **workflow** key,
because MCP keys have no per-key limits in 304. When MCP is switched off for the org or the
deployment, `<McpOffNotice>` renders as one 12px warning line under the description. MCP keys stay
listed (D-19: the switch states its scope and does not hide anything).

### 1b. Draft card, step one: the kind choice (D-01)

"New key" opens the draft card (primary border, as 293). The card's first row, above Label, is
`<ApiKeyKindChoice>`. It has two tiles side by side (≥640px) or stacked (below 640px). Each tile is
a `role="radio"` button inside a `role="radiogroup"` labelled "What is this key for?".

| Tile | Icon | Title (14px/400) | Sub line (12px muted) |
|---|---|---|---|
| `mcp` | `Bot` | For an AI tool (MCP) | Claude Code, Cursor or VS Code searches and reads your knowledge as you. |
| `workflow` | `Workflow` | For a workflow integration | n8n, a script or a scheduler starts the published workflows you pick. |

- **At rest nothing is selected** when the draft is opened from "New key". Below the tiles, only
  "Discard draft" shows, with the why-line "Choose what the key is for." Label and the other rows
  appear after a choice. Focus starts on the first tile.
- **⋯-menu pre-pick** (293's "New API key…" on a workflow card): `workflow` is pre-selected and the
  293 behaviour follows unchanged ("From the ⋯ menu of {workflow}…").
- **Selected tile:** primary border plus 1px primary ring, `bg-primary/5`. Unselected: `border-border bg-card`, hover `bg-muted/40`.
- **Keyboard:** arrow keys move and select, the roving-tabindex pattern of the shipped Expires
  control. Choosing a tile moves focus to the Label input.
- **Switching kind after typing** keeps the Label. It also keeps each kind's own choices in memory
  until the draft is discarded, so switching back loses nothing.
- **MCP switched off for the org:** the MCP tile is `aria-disabled="true"`, dimmed to 62% opacity
  (the dead-card value), and its sub line is replaced by the org sentence (`McpOffNotice`, org).
  The workflow tile works as normal.
- **MCP switched off for the deployment, or not available on this deployment** (D-30): the MCP tile
  **is not rendered**. The draft opens straight into today's workflow form, with no choice row,
  byte-identical to 293.

### 1c. Draft card, MCP rows (`kind="mcp"`)

Same 128px label column and 12px row gap as 293. Rows in this order:

1. **Label.** As 293, with placeholder `e.g. claude-code-laptop`.
2. **Organisation.** A read-only fact: the active org's name, bold 14px. Hint (12px):
   "The key acts as you in this organisation only. To use another organisation, switch to it and make a key there."
3. **Tools** (`<McpKeyFields>`):
   - A segmented `role="radiogroup"` (the Expires control's shape) with four segments:
     **Read only** (pre-selected) · **Read and ask** · **Read, ask and run workflows** · **Choose tools**.
     Below 640px the segments wrap onto two lines. They do not scroll.
   - Under it, a bordered checklist (max-height 208px) in three groups, each with a 12px group heading:
     **Read**, **Ask the agent**, **Run workflows**. Each row has a checkbox, the tool name (mono
     12px) and its plain label (12px muted) from the server catalogue.
   - Picking a preset sets the ticks. Changing any tick by hand moves the segment to **Choose tools**.
     Picking a preset again overwrites the hand ticks.
   - **Companion tools (D-12)** render as disabled checkboxes that mirror their lead tool. The right
     side reads "comes with ask_agent" (on `get_answer`) or "comes with run_workflow" (on
     `list_workflows` and `get_workflow_run`). They are never ticked or unticked on their own.
   - **Ask and run start unticked** (KEY-04). The hint under the checklist always reads:
     "Read only is the safe default. Ask lets the tool put questions to the agent as you. Run lets it start your published workflows as you."
   - Tool names and plain labels come **only** from the server catalogue (D-11: never retyped).
     The client spells only the three group headings and the four preset names.
4. **Folders** (`<KeyFoldersField>`):
   - A two-option `role="radiogroup"` of radio rows (not segments, because the second option opens a
     tree): **All folders I can see in {org}** (pre-selected) and **Only these folders**.
   - With "All folders" selected, the hint reads: "Includes folders shared with the whole organisation. Mail and synced sources are left out unless you include them below."
   - With "Only these folders" selected, an indented checkbox tree opens under the option. It has a
     bordered box, max-height 208px, `Folder` icon per row, and 16px indent per depth. A **Filter
     folders** input (`h-8`) sits above the tree when the member can see more than 12 folders.
     - **Ticking a folder includes its subtree.** Descendant rows render checked and disabled, with
       right text "included". The hint reads: "Subfolders are included, also ones made later."
     - **Shared folders** (org-shared or platform-global) carry a right-side 12px chip "shared with the org". They start unticked (D-22).
     - **Connector-fed folders** (mailbox root, watched or synced sources) carry a right-side chip
       "mail" or "synced". They are **disabled until "Include mail and synced sources" is ticked**.
       The disabled reason reads "tick Include mail and synced sources first". Unticking that box
       also unticks any connector-fed rows (D-23: excluded unless ticked; one control owns it).
     - The count reads under the tree: "{N} folder(s) ticked".
5. **Include mail and synced sources.** One checkbox row, unticked by default, shown in both folder
   modes. Sub line: "Documents that arrived from a mailbox or a synced source. Left out unless you tick this."
6. **Expires.** The 293 segmented control **without "Never"**: 30 days · **90 days** (pre-selected) · 365 days (D-07).
   Hint: "AI tool keys always expire. You can revoke it any time before then."
7. **The acts-as note** (the 293 "Runs as you" note shape: 3px primary left rule, `bg-muted/40`, 12px):
   "This key **acts as you** in {org}. It sees what you see there, never more, and only within the folders and tools above. Anyone holding the key can do the same, so keep it in an environment variable, never in a file you share."
8. **Actions.** "Create key" (gradient-primary) · "Discard draft" (ghost) · the why-line.
   Create key stays disabled and says why (`aria-describedby`, as 293). The first unmet condition is shown, in this order:
   1. no label → "Add a label."
   2. no tool ticked (only reachable under Choose tools) → "Tick at least one tool."
   3. "Only these folders" with none ticked → "Tick at least one folder, or choose All folders I can see." (D-08; this is G-4 row 2)
   4. catalogue or folder list not loaded → "Waiting for the tool list." / "Waiting for your folders."

   A server refusal (422) renders through the shipped `draft.createFailed` template with the
   server's own sentence, and keeps every value the person chose (as 293).

### 1d. Show-once card, MCP (D-19 as 293, plus snippets)

The 293 card shape is unchanged. It has the warning border and wash, `● created`, the
`srl_mcp_…` prefix, the "Copy the secret now" warning, the secret box with Copy, and

  1. "Put the secret in an environment variable named `SYREL_MCP_KEY`." Then a one-line `<pre>`

     client reads. The default is the sentence only, with no secret in any block.
  2. "{client-specific placement sentence}". Then the snippet `<pre>` with a Copy button in its
     header row. This is the shipped `pre` class: mono 12px, line height 1.6, `bg-background`,
     bordered, horizontal scroll.
  3. "{client-specific reload sentence}".

  Snippet text and the placement and reload sentences come from `mcpSnippets.ts`. Their **exact

  "A developer workaround until Claude Desktop connects with sign-in. It needs Node.js and runs a small bridge on your computer."

- **The Claude.ai warning (D-29)** sits below the tabs and shows on every tab. It is a box with a
  warning border at 55% and a 4% wash, `role="note"`, 14px:
  "⚠ Don't paste this key into Claude.ai's organisation connector settings. Everyone in that Claude organisation would act as you. Claude.ai and Claude Desktop will connect with sign-in instead."
- **No address yet:** if the server returns no MCP URL (`BACKEND_PUBLIC_URL` unset, D-28), the tab
  bodies are replaced by one 14px line: "This deployment's public address isn't set, so the connection address can't be shown yet. Ask your operator to set it." The Claude.ai warning still shows.
- Copy buttons are the shipped `CopyButton` (`✓ Copied` / `Copy failed` for 2s, the copy-by-hand
  line on failure, the polite live region). Each has an aria-label of the form "Copy the {client} setup".

**The secret rule is unchanged (T-293-21).** The secret lives only in `ApiKeysTab` state and only in
the secret box. `McpConnectSnippets` has no prop that could carry it.

### 1e. Key card, MCP (KEY-05)

The 293 card is unchanged in shape. The differences:

- **Header row:** `KeyRound` · label · **kind chip** · state tag · `srl_mcp_…` · spacer · Revoke.
  - Kind chip: bordered 12px chip, `border-border text-muted-foreground`, reading
    **AI tool · MCP**, or **Workflow** on a workflow key. Workflow keys gain only this chip.
  - State tags: as 293 (`● active`, `expired`, `revoked`), plus the new **`⏸ switched off`** tag
    (warning border at 50%, warning text) whenever the org or deployment switch is off and the key
    is otherwise active.
- **Chips row** (scope chips, 12px, `border-border bg-muted/40`):
  - Tools: the preset name ("Read only", "Read and ask", "Read, ask and run workflows") when the
    tool set equals a preset, otherwise "{N} tools". `title` lists the tool names.
  - Folders: "All folders" when not narrowed, otherwise one chip per ticked folder name. After 4
    chips the rest collapse into "+{N} more", with names in `title`.
  - "mail & synced sources" chip only when included.
- **Switched-off line** (12px warning) under the chips, from `McpOffNotice`:
  - org: "MCP access is switched off for this organisation by an admin. This key works again when they switch it back on."
  - deployment: "MCP access is switched off for this deployment by the operator. This key works again when they switch it back on."
  - Deployment wins when both are off. This is G-4 row 3.
- **Meta line:** "acts in **{org}**" · "expires **{date}** ({relative})" · last use · "created {date}".
  The last-use atom reads **"Not used yet"** when `last_used_at` is null (D-26). Otherwise it reads
  "last used **{time}**" (as 293).
- **No call strip and no "Show activity" for MCP keys in 304.** Per-call records for MCP keys
  arrive with KEY-07. Showing an empty strip would claim "no calls" when calls are not recorded at all.
- **"How to connect"** (primary text link, 12px) toggles `<McpConnectSnippets>` inline under the
  meta line, labelled "Hide how to connect" when open. The snippets need no secret, so they stay
  available after the show-once card is gone. Shown only on active keys.
- **Fresh border** (1.6s success) after "I've saved the secret": as 293.
