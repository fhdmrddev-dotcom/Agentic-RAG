## The standing lesson this file exists to obey

**A fence that cannot fire is worse than no fence.** Phases 190, 192.1 and 193.1 each registered
fences later found to be sweeping the empty string, asserting the absence of a *field* where a *set
member* had been added, or scoped to a renamed module. In 193.1 **four** such fences were caught —
every one of them by *planting*, none by reading.

⇒ **Every fence in this phase carries a named plant, and the plant must be observed RED before the
fix lands.** A plan that reports a green fence without having seen it red has not validated anything.

## Manual-Only Verifications

### The three operator-driven G-4 rows

Per CLAUDE.md **G-4**, these are operator-defined at scope time and driven by the operator at
verification. Wire format and screenshots are **insufficient**.

| # | Row | Drive | Named failure shape | Requirement |
|---|---|---|---|---|
| 1 | **Press** | Stop in the composer on a live run | *fails if the button sits inert or the row twitches* | R1, R2 |
| 2 | **Canvas** | launch via `▶ Run workflow`, stop from the run surface **without navigating** | *fails if there is no control, or the control persists after the run is terminal* | R3 |
| 3 | **Return** | stop, navigate away, come back | *fails if the thread ends at the original prompt* | R4 |

⚠ **Row 2 requires `visual_workflow_canvas` ON.** It ships **off** (`models/user_settings.py:1197-1203`)
— confirm the local flag before driving, or the row measures the gate rather than the feature.

### The cross-provider axis — a stated decision, not a silent omission

Per CLAUDE.md's UAT scoreboard recipe, a phase touching streaming or UI state owes the 4-axis
bandwidth. **This phase does not re-drive the 8-row native roster, and that is a decision:** it adds
**no provider-facing behaviour** — no prompt, no tool call, no emission path, no model routing — and
the durable half it renders was already scored on **seven live runs** in Phase 194. The parallel-thread
and multi-tool axes are likewise unmoved.
**Re-open trigger:** any plan that ends up touching a provider service, `MODEL_CAPABILITIES`, or the
emission path owes the full roster before this phase closes.

### The L-01 boundary — owed as a STATEMENT, never as a fix

At the shipped `WORKER_COUNT=2`, roughly **half of all stops end with the run reporting `completed`**
(Phase 194 SC#2, FAILED; `RUN_TASKS` is per-process and `finish_run` carries no terminal guard,
`db/workflows.py:1458-1463`). **This phase's honest UI makes that lie MORE visible, not less** — the
surface will truthfully show `⊘ Stopping this run…` and then land on `✓ Complete`.

⚠ **That is not a defect in 194.1's work, and NO plan may "fix" it by suppressing the terminal
reading.** A fence exists in the fence set specifically to red against that well-meaning suppression.
**RUN-01 stays UNTICKED until the inserted L-01 phase ships.**
