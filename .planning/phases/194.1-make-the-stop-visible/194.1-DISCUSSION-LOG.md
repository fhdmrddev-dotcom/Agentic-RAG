## Where the stopping state lives (R1 + R2)

| Option | Description | Selected |
|--------|-------------|----------|
| Store slice in StreamsProvider | `stopThread` sets `stoppingThreads[threadId]`; one 8s timer per thread in the store; four mounts render a shared `<StopControl threadId>` that only READS a selector. Zero new state ownership in any mount file. Survives unmount. | ✓ |
| Shared `<StopControl>` owns its own state | Smaller diff, no store change — but two mounts of the same thread each get their own state, and the pending state dies on unmount. | |
| Store slice, component-owned timer | State shared, timer local — four mounts of one thread run four timers that can disagree about when the climb-down fires. | |

**User's choice:** Store slice in StreamsProvider.
**Notes:** The discriminating argument, recorded in CONTEXT D-06 so it is not re-litigated: the
composer Stop and the panel Stop can be mounted for the **same thread at once**, so component-local
state leaves the second control pressable — and R1's acceptance is that a second press is impossible
**by construction**. This choice is also what keeps the G-5 by-construction claim true.
