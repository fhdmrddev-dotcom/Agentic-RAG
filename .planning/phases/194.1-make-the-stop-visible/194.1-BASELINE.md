harvests double-quoted string literals finds (a) and (c) and reports *"two of the three shipped
sentences"* — which reads like a **missing sentence** rather than a missing regex, and would send the

```
// NaN/0 and flip straight to "No response within 0:00 — agent stopped", i.e.
```

That is this project's recurring lesson landing in a new place: **a raw sweep reds on the PROSE
DOCUMENTING the thing it sweeps for.** It is the same shape as `192-05`'s `title=` fence — which had to
be AST-parsed *"because the raw form reds on the prose documenting it"* — and as 193's D-24(a) copy
fence, which was deliberately kept RAW for the opposite reason. **The honest form strips comment lines
first and then asserts on code**, and the shipped fence also asserts the comment mention is PRESENT, so
nobody later reads the strip as covering for an absence.

⚠ **A later plan must NOT "fix" a red here by deleting that comment.** It documents a real NaN/0 guard.
The fence is what is mis-scoped in that scenario, never the documentation.

**Trap 3 — (a) and (c) share the prefix `This prompt`, and that is NOT a violation.** The distinctness
rule is about **complete sentences**, not shared prefixes (the 193.2 lesson: a fence asserting only
`a !== b` passed a real plant that swapped one arm's second sentence for the other's, so the
shared-complete-sentence clause is the one that fires). The shipped fence asserts the shared prefix
**explicitly and positively**, so a later plan cannot "fix" a non-problem by rewording shipped copy
nobody asked it to touch.
