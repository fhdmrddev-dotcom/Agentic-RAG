<objective>
Widen the shipped, **ungated** `GET /threads/{id}/workflow` with three additive-optional fields —
`last_run_status`, `last_run_created_at`, `last_run_updated_at` — keyed to the **already-resolved**
`phases_source_run_id`.

Purpose: R4 needs "was this thread's workflow stopped, how far did it get, how long did it run" on a
surface (chat) that is **not** canvas-gated. CONTEXT **D-09 as originally written** proposed a new
route on `backend/app/api/workflow_runs.py` — that router is canvas-gated
(`middleware/canvas_gate.py:85-93`, `workflow_runs.py:169`) and `visual_workflow_canvas` ships **off**
(`models/user_settings.py:1197-1203`), so a chat receipt fed from it would be **invisible at the
shipped default**. D-09 is AMENDED by operator decision (2026-08-16) and this plan implements the
amendment. The original decision is not deleted; it stands in CONTEXT with the correction beside it.

Output: three fields on one existing response model, populated on **both** arms of a resolution the
route already performs, with the ownership gate it already has and **zero** additional queries.

⚠ **R6 needs nothing from this plan.** `last_workflow_run_id` already ships (Phase 188 CR-03,
`models/thread.py:101-115`) and `DELETE /runs/{id}` already accepts a `workflow_runs.id`
(`api/runs.py:1211-1253`). That chain is complete end to end — D-09b. This plan must not touch it.
</objective>
