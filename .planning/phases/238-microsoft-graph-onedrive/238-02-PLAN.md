# 238-02 — The contract leaks, and the fence that could not have caught them

**Goal (SC#4, plus the SEED-253 fold):** remove the three provider branches that already sit
above `adapters/`, replace the boundary fence that was written to exempt the one that exists,
and stop fabricating a `path` fact on the watch→ingest path.

⚠ **These leaks are the phase's FINDING against Phase 232's contract.** They are fixed here and
recorded in `238-VERIFICATION.md`; they are not tidied away silently.

## Tasks

### T1 — `sources/base.py`: delete `_ensure_registered`

`SourceRegistry._ensure_registered` branches on `"google" in service_id` / `"mock" in
service_id` **inside the contract module**, while `sources/__init__.py` already imports every
adapter eagerly. It is dead weight whose only function is to be branched, and it is the reason
"add a family" was *almost* a code change.

- Delete the method and both call sites.
- Keep the `google_workspace` → `google` **alias** resolution? ⛔ **No.** Register the alias
  where aliases belong — `@SourceRegistry.register("google_workspace")` already exists on the
  adapter. Delete the `if "google" in service_id` fallback in `get_adapter` and
  `is_source_supported` too; an unregistered id returns `None`, which is the honest answer.
- ⚠ Check for callers relying on substring matching (`grep -rn "is_source_supported\|get_adapter" backend/app`).
  A connection stored as `google` resolves by exact key; one stored as something else was
  already unresolvable.

### T2 — `watch_service.py`: delete the Drive fallback, write the real `path`

- **Lines ~238-243:** delete
  ```python
  if not adapter:
      service_id = conn.get("service_id", "")
      if "google" in str(service_id).lower():
          adapter = SourceRegistry.get_adapter("google")
  ```
  A Graph connection whose adapter failed to register would otherwise be **silently read by the
  Drive adapter**. The `NotImplementedError` two lines below is the correct answer.
- **`metadata.source` (~line 318-325):** add `"path": item.path` alongside `system` /
  `external_id` / `version`. Today the key is absent, so `ingest_enrich`'s path arm is dead.
  ⚠ Write `None` as `None`, not `""` — an absent path and an empty path are different facts.

### T3 — `api/connectors.py:679`: the cosmetic provider literal

`host="googleapis.com" if (service_id or "") == "google" else ""` puts a vendor literal in a
display field above `adapters/`. Replace with a value the adapter owns: read
`SourceHealth.details.get("host")` where the check produced one, else `""`. If that costs more
than it is worth, drop the field to `""` for every OAuth-shaped connection and say so — the
field is decorative and no test asserts a hostname for it (verify with
`grep -rn "host" backend/tests/unit | grep -i connectorcheck`).

### T4 — SEED-253: stop fabricating a path on the watch→ingest path

⚠ **CORRECTION TO SEED-253, MEASURED 2026-09-07 AND RECORDED RATHER THAN INHERITED.** The seed
says production *always* substitutes `/<filename>`. That is **true of the watch→ingest path and
NOT of the preview path**: `preview_service.py:333-334` builds a real breadcrumb during the
recursive walk (`f.path = f"{current_path}/{f.name}"`), seeded from `folder_name`. So the live
defect is narrower than the seed states, and narrower is the version that gets fixed.

- `ingest_enrich.py:537-541` — delete the `or (f"/{filename}" if filename else None)`
  fabrication. `src_path = source_info.get("path")`. When it is `None`, `path` and
  `source_path` are simply **not set** in `eval_facts`, and a folder-shaped rule does not
  match. ⭐ **That is strictly better than matching a fabricated filename**, which is what makes
  a dead rule look live.
- `mock_source.py` — give every `SourceFile` a real `path` (`/Engineering/architecture.pdf`
  etc.) so the conformance suite can assert the field is populated by an adapter rather than
  by a caller.
- `preview_service.py:583-584` — leave the behaviour alone (the walk sets `f.path` first);
  **update the stale comment** to cite this correction instead of claiming no adapter
  populates `path`.

### T5 — The boundary fence, rewritten and DRIVEN RED

`test_boundary_fence.py` today refuses the literals `onedrive|sharepoint|dropbox|box` in
`base.py` **and explicitly permits `google`** — it would have caught the *second* offender
while the *first* sat three lines away in the same file. Replace it:

- Scan `sources/base.py`, `sources/preview_service.py`, `sources/import_service.py` and
  `services/watch_service.py` with `ast`.
- Refuse **any** provider literal — `google`, `google_workspace`, `microsoft`,
  `microsoft_graph`, `onedrive`, `sharepoint`, `drive`, `dropbox`, `box`, `gdrive` — appearing
  in a `Compare` **or** as an argument to `str.__contains__`/`in` on a `service_id`-shaped
  name. An **allow-list of permitted literals** (e.g. `"folder"`, `"drive"` as a `SourceNode.kind`)
  is declared explicitly at the top with its reason, so a future exemption is a visible edit
  rather than a silent gap.
- ⚠ **Exempt `preview_service.GOOGLE_NATIVE_PREFIX` / `GOOGLE_EXPORTABLE` by name and say
  why**: those are **MIME type constants**, not provider routing — deleting them would break
  Docs export. Name them in the allow-list; do not widen the rule to "anything containing
  google".

**DRIVE IT RED (mandatory, and recorded):**
1. Plant `if "google" in service_id: pass` in `sources/base.py`.
2. Run the fence — it MUST fail, naming the file and the literal.
3. `git checkout -- backend/app/services/sources/base.py`; verify `git status --short` is clean
   for that file (**byte-identical restore**).
4. Re-run — green.
Record the RED output verbatim in the plan's SUMMARY. **A guard nobody has seen fire is not a
guard.**

### T6 — `test_238_source_path_honesty.py`

- A `SourceFile` with `path=None` reaching `ingest_enrich` sets **neither** `path` nor
  `source_path` in `eval_facts` (drive the real function, not a stub).
- A `SourceFile` with `path="/Finance/Q3.pdf"` sets both, verbatim.
- `watch_service`'s `metadata.source` carries the `path` key (present, possibly `None`).
- The conformance suite asserts every adapter's `list_files` returns `SourceFile`s whose
  `path` is either `None` or an absolute string — never a bare filename.

## How we'd know this failed

- The fence passes with a planted `"google"` branch (it did, until this plan).
- `is_source_supported("google-something")` still resolves by substring after T1, so the
  branching moved rather than left.
- A rule that used to match now matches something *else* rather than nothing — T4 must remove
  a fabricated match, not introduce a different one.
- The Drive export path broke because the fence's allow-list swallowed `GOOGLE_NATIVE_PREFIX`.
