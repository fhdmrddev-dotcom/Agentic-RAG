<objective>
Make the armed wait HONEST end to end: it must not announce a failure, it must survive a worker restart
without orphaning the prompt the person is looking at, and the card must not tell them it expired.

Purpose: three defects that only appear once the wait is indefinite.

1. **The pre-gate emits `gate_failed` before it can pause** (L-5). `harness_engine.py:697-704` writes a
   `gate_failed` audit row and emits a `gate_failed` SSE event *before* calling
   `_resolve_failure_with_ask_user`. An armed step that is merely waiting would announce a failure to
   chat and canvas, and the frontend's existing handler renders it as a problem. The audit ledger's own
   vocabulary rule ("consequence ≠ receipt") makes this correctness, not cosmetics.
2. **The boot-time resume sweep will not re-subscribe an armed pre-gate** (L-7).
   `resume_stranded_workflows:1778` gates the re-subscribe branch on `_is_llm_human_input(active)`
   (`:1866-1880`), which is False for an armed `llm_agent` — its stored config type is `llm_agent` and
   its output was never persisted. The run IS re-driven and IS re-asked, so it is fail-closed, but with a
   NEW `tool_call_id` and a NEW prompt row, while the OLD row is never expired on the graceful-shutdown
   path. `/pending` can then serve a dead, unanswerable card — G-4 scenario 3's exact named failure.
3. **The shipped card counts a null/zero deadline down to expired** (found this session).
   `PendingAskCard.tsx:184-197` seeds `remaining` from `timeout_seconds` and flips to the `expired` state
   when it reaches 0, rendering *"No response within 0:00 — agent stopped"*. Plan 185-04 sends `None`;
   without this task the armed prompt renders as expired the instant it appears.

Output: a truthful `action_risk_pending` event, an armed branch in the resume sweep that preserves the
`tool_call_id`, and a card that renders "no deadline" as an open-ended wait.
</objective>
