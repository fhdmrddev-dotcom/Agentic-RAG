<objective>
Make the armed action-risk checkpoint actually park, and make this failure class unrepeatable.

GOVERN-03's entire deliverable does not work. An armed step never pauses — it kills the run. Measured
on `workflow_runs.id = 80c8823d` (definition `sc10-armed-f77e72`, `gpt-5.5`): `retrieve` completed,
`emit` reached its `timing:"pre"` approval gate, and the run then died with

  failed: ValueError: write_audit event_type must be one of the 22 harness_audit kinds
  (059 + 069 + 070), got 'action_risk_pending'

leaving a phase permanently `active` under a run marked `failed`, and no audit row explaining any of
it. Nobody is ever asked.

**The irony is the diagnosis.** Plan `185-05` introduced `action_risk_pending` *for honesty* — the
comment at `harness_engine.py:700-711` argues that announcing `gate_failed` on an armed pause "would
tell the ledger and the frontend that something went wrong when nothing did". That reasoning is
right. But the new word was never registered at either layer that admits an audit kind, so the
**dishonest `else` branch works and the honest branch crashes**.

Two layers, both required: the Python allow-list `_AUDIT_EVENT_TYPES` (`db/workflows.py:56-80`) raises
before the INSERT, and the Postgres `harness_audit_event_type_check` CHECK carries the same 22
literals. Registering only the Python literal converts a `ValueError` into a Postgres `23514` mid-run.

Operator decision, taken 2026-07-31: **ship migration 114 and amend the zero-migration contract**,
rather than have the armed pause reuse an already-registered kind — that alternative works today but
re-introduces exactly the dishonesty `185-05` existed to remove.

Output: migration 114, the Python registration, two structural guards, an amended contract, and an
operator-verified armed run that PARKS.
</objective>
