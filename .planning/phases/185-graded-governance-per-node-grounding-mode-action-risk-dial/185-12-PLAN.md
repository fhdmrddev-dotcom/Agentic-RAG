<objective>
Close BUG-260730-01: make the citation requirement legible to the model that has to satisfy it.

The gate is correct and should stay strict. What is broken is that nothing tells the producer what
the gate wants. A detected grounded step retrieves correctly, writes prose without `[1]` markers,
fails half (b), retries twice against feedback that repeats the deficit without naming the format,
and the run dies. Measured on the operator's publish golden run
(`workflow_runs.id = ded89703-44c4-4e40-b5fe-9af35a44a54d`, model `deepseek-v4-flash`):

  Phase 1 (retrieve) gate failed after 3 attempt(s): citations_required: 0/1 citation markers in the answer

Half (a) — the `"nothing was retrieved (0 sources)"` branch — did NOT fire, which is the proof that
retrieval succeeded and the failure is purely the missing marker.

This is not provider-specific. Nothing tells ANY model the format: not the step prompt, not the
attachment seam (`grounding.py:935-947` appends a ValidatorSpec and no prose), and not the retry
feedback (`harness_engine.py:804`). A grep for marker guidance across the harness services and
`app/prompts/` finds the pattern literal only inside `validator_kinds.py`, as the thing being checked.

Purpose: GOVERN-01's promise is that a grounded step's gate is attached AUTOMATICALLY and is not
author-loosenable-away. As shipped it is attached automatically and then usually fails, because
satisfying it silently depends on marker instructions the author would have had to hand-write —
exactly the burden the auto-attachment exists to remove. Publish is blocked for grounded workflows,
including the shipped `Compliance Gap Report` starter.

Output: one shared marker-format constant, a remedy clause on the failure message, an additive
prompt suffix on both agent paths, and the tests that pin all three together.

This plan changes NO frontend source and NO migration.
</objective>
