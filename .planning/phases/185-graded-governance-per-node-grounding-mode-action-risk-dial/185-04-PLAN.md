<objective>
Make the armed action-risk checkpoint fail closed: the wait is indefinite, the decline choice actually
declines, and a graceful restart does not destroy the run.

Purpose: SPEC Req 9. `_exec_llm_human_input` clamps to `min(phase.config.timeout_seconds,
settings.ask_user_max_timeout_seconds)` and on timeout sets `answer = ""` and **returns normally** — a
normal return advances the run. In the canonical example the next step sends the email. GOVERN-03 reuses
the `llm_human_input` SUBSTRATE (durable prompt row, `tool_call_id`, `/pending` replay, the Phase 094
frame) but MUST NOT inherit its timeout disposition. Scope is **armed checkpoints only**: a plain
`llm_human_input` step keeps its current disposition, byte-identical, because changing it would break
D-14 for existing human-input steps.

Three concrete fail-open / fail-destructive defects the research pass found, each fixed here:
- `_is_abort_choice` matches only `("abort","cancel","stop","")`, so `"Do not run it"` falls through to
  the **Proceed** branch and runs the risky step (L-4).
- `subscribe_for_response`'s `timeout_seconds` is a required `float`; the two live call sites hard-cast
  with `float()`, so `None` would `TypeError` before it could wait forever (A1).
- A `{"kind": "shutdown"}` payload computes `choice = ""`, `_is_abort_choice("")` is True, and the run
  is FAILED on a routine deploy (L-6).

Output: an indefinite-capable subscribe, an explicit decline mapping, a verbatim armed prompt, and a
shutdown branch copied from the shipped `_exec_llm_human_input` precedent.
</objective>
