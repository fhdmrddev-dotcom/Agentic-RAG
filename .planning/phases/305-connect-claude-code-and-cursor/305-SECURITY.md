## Trust Boundaries

| Boundary | Description | Data crossing |
|----------|-------------|---------------|
| AI tool (untrusted network caller) → `POST /mcp` | Bearer key, Host, Origin, method and body are all attacker-controlled | `srl_mcp_` secret, JSON-RPC body |
| McpEdge → resolver core | The presented string goes to the one key lookup (service-role pool) | secret → digest |
| MCP handler → Postgres | Only after a principal exists. Refused requests never reach member SQL | principal (user, org, scope) |
| MCP caller → tool arguments | query, folder_id, document_id and cursors are attacker-controlled | arguments |
| retrieved document content → caller's model | Document text is untrusted and may carry instructions or exfiltration URLs | passages, read chunks |
| Syrel documents → MCP caller's tool | The last point before personal data leaves the deployment | redacted / withheld results |
| MCP path → `audit_log` / `mcp_usage` | The service-role pool writes for the caller, with the org stated explicitly | audit + spend rows |
| org admin browser → `PUT /org/api-keys/pii-redaction` | Only an org admin of the ACTIVE org may change what leaves | switch boolean |
| operator deploy config → mount decision | `BACKEND_PUBLIC_URL` / `ENVIRONMENT` decide whether `/mcp` exists | public base |
| PyPI → backend venv / image | New third-party code enters the venv and the built image | `mcp`, `httpx2`, `sse-starlette` |
