Reading for 306:
  1. Effective default on Claude Code 2.1.312: a silent tool call is aborted at ~60 s
     ("The operation timed out."). A member who has not set MCP_TOOL_TIMEOUT gets ~60 s, not 28 h.
  2. With MCP_TOOL_TIMEOUT raised, the documented 5-min idle ceiling holds exactly (300 s, worded,
     naming a per-server "timeout" setting in the MCP config as the escape hatch).
  3. No backgrounding was observed in `claude -p` (the 150 s call answered in the foreground with the
     knob raised); the 2-min auto-background is an interactive-session behaviour, not measured here.
  4. So any 306 tool that can run past ~60 s must answer quickly and let the caller poll (or send
     progress), never hold one silent JSON response open.
