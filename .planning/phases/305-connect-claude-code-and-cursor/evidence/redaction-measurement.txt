Phase 305-04 — PII redactor measurement (D-38), local corpus, read-only
=========================================================================

Script: backend/venv/Scripts/python scripts/measure-redaction.py  (SELECT-only; default_transaction_read_only)
Corpus: 10,279 search units (document_chunks.content — what a search passage carries)
      +    872 read units  (latest documents.full_markdown cut into 8,000-char read_document chunks,
                            each scanned with its 128-char overlap window — what a read carries)
      = 13,161,950 characters. Measured 2026-10-31 on the operator's local database.

AGGREGATES ONLY. No matched value is recorded here. The labelled samples were written as SHAPES
(letters -> a/A, digits -> 9, context digits scrubbed and other matches masked) to a scratch file
outside the repository, labelled TP/FP there, and never committed (T-305-34).

Labelling rule: a hit is TP when the masked text really is that class of data (an email address,
a phone number, an IBAN, a credential); FP otherwise. A JWT is a bearer token and is TP wherever it
sits, links included. Up to 30 hits per recognizer were sampled, from the search units.

Residuals, stated rather than hidden:
  * Names are NOT covered (GUARD-03) — no pattern recognizer can find them.
  * The entropy recognizer now ignores tokens inside links. A credential pasted as a bare link
    parameter of an unknown format would pass; known key prefixes and JWTs are still caught in
    links because their recognizers run first.
  * A value split across two INGEST chunks in a search passage leaks only partial digits, which fail
    Luhn and mod-97 (Pitfall 8); read chunks are covered by the 128-char overlap window.
  * Card and secret-prefix recognizers had no real hits to label on this corpus; their precision
    rests on the fixture (positive + negative cases per brand/prefix) and on the validators.
