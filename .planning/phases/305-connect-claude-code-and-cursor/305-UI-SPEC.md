# Phase 305 — UI Design Contract

> Visual and interaction contract for the user-visible part of "Connect Claude Code and Cursor".
> The phase is mostly backend. Every surface below EXTENDS a shipped, approved surface; nothing here
> is a new page, tab, nav entry or Settings mount.
> Generated by gsd-ui-researcher; the checker validates it.

**What this file decides.** Five surfaces, plus one adjacent field the research already put on a
screen (§Surface 6), so that no user-visible word in 305 ships without a contract:

1. **Org admin → Settings: the PII redaction card** (GUARD-03, D-36/D-37/D-56).
2. **Admin → Spend: the key in the ledger's attribution cell** (GUARD-02, D-55).
3. **Settings → API keys: an MCP key's activity** (KEY-07, D-53).

6. *(adjacent)* **The operator's per-key limits card gains the searches knob** (KEY-07, D-54, R-19).

**It brings in no new tokens, primitives, type sizes or colours.** Where this file says "as 304",
the 304 contract applies unchanged.

**Out of scope (and must not be touched):** `frontend/src/pages/admin/AdminSpendPage.tsx` (FIRES,
"extraction FIRST next" ⛔), `frontend/src/pages/SettingsPage.tsx`, `OrgAdminShell.tsx`'s tab

Accent (`--primary`) is reserved for exactly these elements in this phase:
1. The ON track of the redaction switch (`bg-primary/70`, the shipped switch look).
2. The "Show activity" / "Hide activity" text link on an MCP key card (shipped 293 link).
3. The "All in the audit log →" link in the activity header (shipped).
4. Focus rings (`--ring`), unchanged.

Accent is **not** used for the ledger MCP pill, tool names, the redaction tag, or the document
notice. **The Expert violet is not reused for an MCP row**: violet means "an Expert ran this", and an
MCP call has no Expert.

**One deliberate difference from the MCP switch (A-3):** the redaction switch's OFF track is
**neutral** (`bg-muted-foreground/40`), not `bg-destructive/70`, and OFF is **not armed**. The MCP
switch's OFF is a kill (065-A); redaction OFF is the default, everyday state of every org, and
painting it red would make every org's Settings read as alarmed.

Colour is never the only signal: the ON tag carries words, every activity result carries `✓`/`✕`
plus words, and the call strip keeps its bar-height difference (shipped).

## Surface 1 — Org admin → Settings: the PII redaction card (GUARD-03)

`<OrgPiiRedactionCard>` sits inside `OrgSettingsTab`'s section, **directly under**
`<OrgMcpSwitchCard>` and above the three-homes paragraph. It is the same bordered well
(`mt-3 rounded-md border px-4 py-3`). It is a copy of `OrgMcpSwitchCard`'s shape and behaviour;
the differences are listed, everything else is "as 304 Surface 3".

### Layout (top to bottom)

```
┌────────────────────────────────────────────────────────────────────────┐
│ Remove personal data from AI tool results  [ON FOR ACME]          (●─) │  ← title 14/600 · tag (only when ON) · switch right
│ When on, search results and documents sent to members' AI tools in      │  ← sub 1, 12px muted
│ Acme have email addresses, phone numbers, card numbers, IBANs and       │
│ secrets such as API keys replaced with a short note, like               │
│ [email removed].                                                        │
│ Names are not covered. If a result can't be checked, it is withheld     │  ← sub 2, 12px muted, mt-1
│ rather than sent. Document ids, citations and Open in Syrel links are   │
│ never changed.                                                          │
└────────────────────────────────────────────────────────────────────────┘
```

- **Both sub lines render in every state** (on, off, loading, failed), because they are what the
  setting *is*. The admin reads what is covered, what is not, and the fail-closed rule before
  touching the switch.
- **Default OFF** (D-36). OFF is calm: well `border-border bg-background`, no tag, neutral track.
- **ON:** the well stays `border-border bg-background`; a tag `on for {org}` renders after the
  title in the shipped tag shape (`rounded-md border px-1.5 py-0.5 text-[10px] font-semibold
  uppercase tracking-wide`) in the success hue (`border-success/40 bg-success/10 text-success`).
  Track `bg-primary/70`.
- **Direct flip, no confirm, either direction** (066: reversible, no single victim). Turning it OFF
  is not armed and has no impact line (A-3).
- **Never optimistic** (as 304): the switch shows the server's answer. While the PUT is in flight
  the switch is `disabled` at 60% opacity. On failure it stays where it was and one line shows,
  `role="status"`, 12px destructive: **Couldn't change it. Try again.**
- **Recorded:** after a successful write the leaf calls `onRecorded()`, so the org band's "every
  action recorded" marker pulses for 1.6s (062-A). No toast. The audit row is `settings.update` +
  `metadata.event = "pii_redaction"` (D-36) and reads in Org admin → Audit as
  **Turned personal data removal for AI tools on for the organisation** / **… off for the
  organisation** (the stored `enabled` picks the word; one event read in `OrgAuditTab.tsx`).
- **Load states (as 304):** while the GET is pending, "Loading…" (12px muted) and **no switch**.
  On a failed GET, "Couldn't load this setting." plus **Retry** (outline, sm) and **no switch** — a
  switch must never show a guessed value. There is no separate "unknown" rendering: a failed read
  *is* the unknown state, and it shows words, not a switch.
- **Org switch:** the shell already keys `OrgSettingsTab` on the active org (304), so switching org
  re-reads this card. Nothing extra.
- **Wall:** `require_org_manage` on `GET`/`PUT /org/api-keys/pii-redaction` (D-56). The card only
  sits inside the admin-only shell; it adds no client-side role check of its own.
- **Accessibility:** `role="switch"`, `aria-checked`, `aria-label` = the title; the two sub lines
  are tied to the switch with `aria-describedby` so a screen reader hears what it covers before
  flipping it. `data-testid="org-pii-redaction"`, `data-on="true|false"`.

### What the caller's AI tool sees (backend words, fixed here so the card's example is true)

The card's example `[email removed]` must be the real mask. The redactor (D-33/D-56) replaces each
match with exactly one of these, which cannot collide with the passage delimiters (R-21):

| Recognizer | Mask |
|---|---|
| Email | `[email removed]` |
| Phone | `[phone removed]` |
| Card number | `[card number removed]` |
| IBAN | `[IBAN removed]` |
| Secret / token (key prefixes, JWT, high-entropy) | `[secret removed]` |

The withheld tool error is D-35's sentence, verbatim: **This result was withheld because it could
not be checked for personal data.**

### The MCP arm of `LedgerExpertCell`

Checked **first**, before the existing `expertAttributed` / `expertId` / deleted arms, so an MCP row
can never read "No Expert", "Deleted Expert" or "Not recorded".

| Case | Renders |

| `source === "mcp"` and `apiKeyLabel` present | pill `LEDGER_PILL` + `border border-border bg-muted/40 text-foreground`, `KeyRound` 12px, then **MCP · {label}** — "MCP ·" fixed, the label `truncate max-w-[16ch]` (the Expert-name width). `title` = **AI tool key {label} · {tool}** (or **AI tool key {label}** when `mcpTool` is null) |

### The rest of an MCP row (shipped page cells, data only — stated so the auditor knows what is right)

| Column | An MCP row reads |
|---|---|

## Surface 3 — Settings → API keys: an MCP key's activity (KEY-07)

304 rendered **no** call strip and **no** activity on MCP keys, because per-call records did not
exist (304-UI-SPEC A-5). 305 writes one audit row per `tools/call` (D-26/D-53), so MCP keys now get
the 293 strip and the "Show activity" table — with words that can never read a blocked call as OK.

### Wire (fixed by D-53 / Pitfall 7, stated so the words below are reachable)

- `ApiKeyCall.ok` is false for an `api_key.refused` row **and** for an `api_key.read` row whose
  `metadata.kind = "mcp"` and whose `outcome` is anything but `ok` / null (the one-expression
  readback change in `api_keys._call_from_audit`).
- `ApiKeyCall.tool` (new, optional): `metadata.tool`, or null when the call was refused before a
  tool was known (a credential refusal).
- Over-limit and not-granted calls arrive as `api_key.refused` with `reason`
  `rate_limited:<bucket>` (bucket `read` = list/read, `expensive` = search) or `tool_not_granted`,
  and `detail.limit` (the per-minute figure) on an over-limit row.

### Result words (`mcpCallWords`, every string from `mcpKeyCopy.ts`)

| Row | `ok` | Result cell |
|---|---|---|
| `api_key.read`, outcome `ok` or null | true | **✓ answered** |
| `api_key.read`, outcome `redaction_blocked` | false | **✕ withheld: it couldn't be checked for personal data** |
| `api_key.read`, outcome `error` | false | **✕ failed: the tool couldn't finish** |
| `api_key.read`, outcome `limited` or `refused` (defensive: D-26's older vocabulary) | false | as the matching refusal row below |
| `api_key.read`, any other outcome `X` | false | **✕ {X}** — an unknown outcome shows its raw code, never a tick (293 rule) |
| refused, `rate_limited:expensive` | false | **✕ refused: over the limit: {N} searches a minute** |
| refused, `rate_limited:<any other bucket>` | false | **✕ refused: over the limit: {N} reads a minute** |
| either over-limit row with no figure known | false | **✕ refused: over the limit** (shipped `overBare`) |
| refused, `tool_not_granted` | false | **✕ refused: this key isn't allowed to use {tool}**; with no tool name, **✕ refused: this key isn't allowed to use that tool** |
| refused, any reason the 293/304 table already words (`revoked`, `expired`, `not_member`, `banned`, `wrong_kind`, `mcp_off_org`, `mcp_off_deployment`, `limiter_unavailable`, …) | false | the shipped words, unchanged |
| refused, unknown reason `X` | false | **✕ refused: {X}** (shipped default) |

`{N}` comes from `detail.limit`, else from the list's `limits.searches_per_minute` /
`limits.reads_per_minute`, else the bare form. Colour: `text-success` for `ok`, the shipped refusal
red for everything else (`ApiKeyActivity`'s existing class).

### Activity table (an MCP key)

- **Three columns: Time · Tool · Result.** The Workflow and Run columns are not rendered for an MCP
  key (an MCP read has neither; showing "— · no run" on every row is noise). The visually-hidden
  header row reads **Time**, **Tool**, **Result**.
- **Tool cell:** the tool name in the shipped read pill (`rounded px-1.5 py-0.5 font-mono bg-muted
  text-muted-foreground`), e.g. `search_knowledge_base`; **—** when `tool` is null. Tool names come
  from the server row, never retyped (D-20).
- Header line as shipped: **Recent calls · last used {when}** plus "All in the audit log →" when the
  viewer can open it.
- **Empty (MCP key, never called in the window):** **No calls yet. The first search or read will
  show here.** Revoked with no calls: the shipped "Revoked before any calls in the last 30 days."
- **No query text anywhere** (R-18: none is recorded, so none can be shown).

### Call strip (an MCP key)

- Bars as shipped: an `ok` call is a short muted **read** bar; every non-`ok` call is a tall
  destructive bar. There are no start bars on an MCP key.
- Caption for an MCP key: **last {N} call(s) · ■ answered ■ not answered · tap one** — the legend
  names only the two kinds that can occur ("refused" alone would be untrue for a withheld or failed
  call).
- The tapped bar's detail line, and each bar's accessible name: **{time} · {tool or —} · {result
  words}**, e.g. `10:42 · search_knowledge_base · ✕ refused: over the limit: 30 searches a minute`.

### Card placement

Unchanged order: header → chips → switched-off line → meta (with "Not used yet" / "last used") →
"How to connect" → **call strip** → **Show activity**. The strip and the toggle render exactly where
they render on a workflow key. "Last used" moves on any authenticated call, refused or not (the
resolver touches `last_used_at`, 304) — G-4 row 3 reads it.

| **Anyone else** — not a member of its org, the document deleted, superseded, archived, or never existed | the Library view with **one in-page notice** (below) and the panel closed. Missing and forbidden render the **same DOM** (the server's uniform 404); nothing on screen names a title, an org or an owner |
| **The server could not answer** (5xx, network) | the shipped S8 alert, unchanged: **Couldn't open that document.** + **Retry**. An outage is never worded as "can't be opened" (T-299-25) |
| **A malformed id** (`/app/library/not-a-uuid`, a partial UUID, a dotted segment) | the shipped 297 page **This address doesn't open anything** / "It may be mistyped or out of date." + "Go to Chat" (the route table's `not-found`; strict-UUID rule, never throws) |

### The in-page notice `<DocumentCantBeOpened>`

Rendered in the Library's S8 alert slot (top of the documents column, above the list), the one mount
`LibraryPage.tsx` takes.

- A `<section aria-labelledby>` card: `rounded-xl border border-border bg-card p-4`, left-aligned.
- Heading (16px Manrope 600): **This document can't be opened** — `CANT_BE_OPENED_COPY.heading("document")`, imported, not retyped.
- Body (14px muted, `mt-2`): **If someone sent you this link, ask them to check it.** — `CANT_BE_OPENED_COPY.body`.
- One action (`mt-4`): **Dismiss** (`Button variant="outline" size="sm"`). It clears the refused
  state and replaces the address with `/app/library` (a replace, not a push). The list behind was
  never hidden or made inert — the person can use the Library at once.
- Focus moves to the heading once on arrival (`tabIndex={-1}`, no ring — the 299 UI-D6 rule).
- No Copy address button (A-7): the person already holds the link in their AI tool.
- `data-testid="document-cant-be-opened"`.

### Address behaviour

- `/app/library/<uuid>` is a 299-style entity variant (strict lowercase UUID). It never throws.
- While the panel shows that document the address stays as opened, so a reload reopens it. Closing
  the panel or picking another row does **not** write a new address in 305 (in-app selection has no
  per-document address yet; A-6).
- A member of several orgs opening a document from an org other than the active one gets the panel
  without an org switch or a prompt (A-5) — the same as a chat citation today.
- The same notice applies to **any** by-id open that answers 404, including a chat citation to a
  document the member can no longer see (A-4): one rule, and it replaces a silent nothing with a
  sentence.
