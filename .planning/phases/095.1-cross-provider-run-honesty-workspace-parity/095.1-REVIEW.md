## Summary

Reviewed the 14 changed files against the phase-095.1 diff (`b9b204bb..HEAD`),
focused on the project's three critical lenses: cross-provider safety, security/RLS,
and correctness (timer math + error-classification ordering + null handling in the
derived-panel selector).

The changes are clean and well-reasoned. The three highest-risk surfaces all check out:

1. **Cross-provider safety (PROVIDER-ERR classifier, `errors.py` + `agent_loop.py`)** — The
   429→`rate_limit` ordering is correctly enforced ahead of any billing classification
   in every branch (Google `.code`, typed SDK isinstance, numeric `.status_code` fallback).
   Billing is only ever claimed via the structural `insufficient_quota` signal, never the
   word "quota" in a message string — which is the exact BUG-260606-01 root cause being
   closed. The classifier is a pure consumer-side helper imported from the gateway package;
   it does NOT touch the byte-identical adapter generators, preserving the 092.5 Deep
   invariant. `_resolved_provider` is confirmed in scope (set at `agent_loop.py:961`,
   consumed at `:2271` within the same `run_agent_loop` body). The SDK import guards
   degrade safely to the numeric-status fallback when an SDK is absent.

2. **Security / RLS (`threads.py` additive SELECT)** — The `.select(...)` gains 4 read-only
   columns (`model, provider, started_at, completed_at`) but the WHERE clause
   (`.eq("thread_id") + .eq("user_id")` under RLS `runs_select_own`) is UNCHANGED — no
   widened row set, no IDOR. No new write, no migration. The new strings flow through
   `message.py` → `api.ts` → `RunCard.tsx`/`TodosSection.tsx` and render as React text
   children only — no `dangerouslySetInnerHTML` anywhere. `message_for_kind` bounds the raw

   leak).

3. **Correctness (timer + derived panel)** — The reload-timer honesty rule is implemented
   correctly: a terminal run with no persisted `completedAt` and no same-session
   `frozenEnd` shows NO duration rather than the fabricated `Date.now() − created_at` lie

   null-safe throughout (`dedupToolCalls` guards null/undefined; `inferLabel` guards

## Warnings

### WR-01: Timer can show `created_at`-anchored duration for a finished run whose `startedAt` is absent but `completedAt` is present

**File:** `frontend/src/components/chat/RunCard.tsx:121-167`
**Issue:** `runStartMs` falls back to `Date.parse(message.created_at)` when `message.startedAt`
is absent. For a terminal run that has a persisted `completedAt` but NO `startedAt` (possible
for a legacy/partially-enriched run row where `completed_at` was written but the additive
enrich returned a null `started_at`, or any future path where only one of the pair is
populated), the "true duration" branch computes `completedMs − runStartMs` using
`created_at` as the start anchor. `created_at` is the message-row creation time, which can
differ from `runs.started_at` — reintroducing a smaller version of the inflation the D-05
rule is meant to eliminate. The honesty rule ("a finished run's duration is `completedAt −
startedAt`") is only fully honest when both timestamps come from the run row.
**Fix:** Gate the true-duration branch on a real persisted start, mirroring how the branch
already gates on `hasTrueEnd`:
```ts
// derive a run-row start separate from the created_at live-tick fallback
const runStartMsTrue = message.startedAt ? Date.parse(message.startedAt) : NaN
const hasTrueStart = Number.isFinite(runStartMsTrue)
// ...
} else if (hasTrueEnd && hasTrueStart) {
  elapsedMs = completedMs - runStartMsTrue   // both from the run row → honest
}
```
Keep the `created_at` fallback only for the live streaming tick (where it correctly
reinforces the 083 fix). Low likelihood in practice (the enrich populates both columns
together from one join), so this is a warning, not critical.

### WR-02: `producedDeliverables` Resume gate comment claims "execute_code only" but the live-stream path counts any emitted final output file

**File:** `frontend/src/components/chat/MessageItem.tsx:224-228`
**Issue:** The gate is `(message.finalOutputFiles?.length ?? 0) > 0`, with a comment asserting
deliverables are "execute_code output files specifically; we do NOT count workspace_write
files here." That precision holds for the RELOAD path (`api.ts:138` reconstructs
`finalOutputFiles` strictly from `tc.name === "execute_code"`), but the LIVE path
(`StreamsProvider.tsx:728-733 onFinalOutputFiles`) stamps whatever the backend
`final_output_files` SSE event carries, unfiltered. If that event ever includes
non-`execute_code` outputs, a live run could suppress Resume on a non-deliverable file —
diverging from the documented contract. The behavior is sound today; the risk is the comment
overstating an invariant that only one of the two code paths enforces.
**Fix:** Either (a) tighten the comment to "any final output file" to match the live path, or
(b) if execute_code-only is the real intent, filter the live `onFinalOutputFiles` payload the
same way the reload path does, so both paths enforce the same definition of "deliverable."

## Info

### IN-01: Index-as-key in the derived-panel row map

**File:** `frontend/src/components/panel/TodosSection.tsx:163` (`{derived.map((item, i) => <DerivedRow key={i} item={item} />)}`)
**Issue:** Uses the array index as the React key. The derived list is recomputed
deterministically from `tool_calls` on each activity change; when items are inserted/reordered
between renders, index keys can cause React to reuse the wrong DOM node (status/label
mismatch flashes). `DerivedRow` is purely presentational with no local state, so the impact is
cosmetic at most.
**Fix:** Prefer a content-derived key, e.g. `key={`${i}-${item.label}`}` or include the source
tool key when available, so reorders re-key correctly.

### IN-02: `variant` prop and `is_hero` flag are now inert / written-but-unread

**File:** `frontend/src/components/chat/OutputFileCard.tsx:54-62, 77` and the `is_hero` field
**Issue:** After reversing the hero/working split, `variant` no longer changes the rendered
shape (it only feeds `data-variant`), and `is_hero` is carried through `api.ts`/types but never
read. This is intentional and documented for back-compat / forward-compatibility, so it is not
a defect — but it is dead-ish surface that a future reader may mistake for live behavior.
**Fix:** No action required now. Optionally add a `@deprecated` JSDoc tag to `variant` so
tooling flags new call sites that try to use it, and leave a tracking note to drop both once
the persisted payloads no longer carry `is_hero`.

### IN-03: `inferLabel` leading-comment branch lower-cases the entire label tail

**File:** `frontend/src/lib/workspacePanel.ts:119` (`text.charAt(0).toUpperCase() + text.slice(1).toLowerCase()`)
**Issue:** Porting Python's `.capitalize()` verbatim lower-cases everything after the first
char, so a header comment like `# Build PDF Report for Q3` renders as "Build pdf report for
q3" — acronyms (PDF, CSV, Q3) and proper nouns get flattened. This is faithful to the spike
but produces slightly degraded labels for the common all-caps-acronym case. Purely a display
nicety; not a correctness issue and never an XSS vector (rendered as text).
**Fix:** Optional — drop the trailing `.toLowerCase()` and only upper-case the first char
(`text.charAt(0).toUpperCase() + text.slice(1)`), preserving author casing for the rest.
