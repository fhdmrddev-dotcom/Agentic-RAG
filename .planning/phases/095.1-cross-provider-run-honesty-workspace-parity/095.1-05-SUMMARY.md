# Phase 095.1 Plan 05: MessageItem Honesty (Flat Generated-files + Deliverable-aware Resume) Summary

**Two MessageItem honesty fixes shipped together: output files now render as one flat equal "Generated files" list (no "★ Your file" hero crown, D-06), and a failed/timed_out run that already produced its deliverables no longer falsely offers Resume (D-07, closes BUG-260518-01).**

## Accomplishments

- **D-095.1-06 (flat list):** `FinalOutputsPanel` collapsed from the hero/working split into ONE flat `space-y-1.5` map of equal `OutputFileCard` rows. Removed the `useState(workingOpen)`, the `heroes`/`working` `is_hero` filters, the hero block, and the collapsible "Working files (N)" group. The "Generated files" eyebrow and `data-testid="final-outputs-panel"` are preserved. The frontend no longer reads `is_hero` anywhere (it stays written-but-unread — no backend change).
- **D-095.1-06 (OutputFileCard):** Removed the entire hero presentation path — the glow/gradient/48px-icon/prominent-Download styling and the "★ Your file" caption (both the live branch and the url-less dead-state branch). The icon is now a uniform 30px. The `variant` prop is kept optional + inert for call-site back-compat. The url-less "Download unavailable" dead-state affordance is KEPT verbatim (orthogonal honesty fix).
- **D-095.1-07 (deliverable-aware Resume):** Added a `producedDeliverables = (message.finalOutputFiles?.length ?? 0) > 0` predicate and `&& !producedDeliverables` to the Resume gate. A failed/timed_out run that already produced execute_code output files no longer offers Resume; a failed/timed_out run with NO deliverables still resumes; completed/cancelled/streaming and the Continue card (`capPaused`) branch are unchanged.
