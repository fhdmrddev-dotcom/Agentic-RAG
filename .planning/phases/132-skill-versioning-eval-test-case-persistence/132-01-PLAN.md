<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API (service-role) → Postgres | Backend writes to `skills` via the service-role client, which BYPASSES RLS. The version trigger runs in this context (auth.uid() is NULL). |
| Cross-user data | Version history is the author's private authoring artifact — never visible to consumers of a global skill (D-12). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-132-01 | Information disclosure | skill_versions cross-owner read via global skill | mitigate | Owner-only RLS (no is_global branch, D-12) + app-code owner filter in Plan 02; defense-in-depth even though service-role bypasses RLS. |
| T-132-02 | Tampering | version-history mutation | mitigate | `BEFORE UPDATE` append-only block trigger (067 pattern); raises 23514 on any UPDATE. |
| T-132-03 | Tampering | NULL/forged user_id on version rows | mitigate | Trigger sources user_id from `NEW.user_id` (the authenticated owner of the skill row), never auth.uid() (NULL under service-role); NOT NULL FK to auth.users. |
| T-132-04 | Denial of service | version_number race → duplicate/lost version | mitigate | `UNIQUE(skill_id, version_number)` turns a concurrent max+1 collision into a benign retryable 23505 rather than silent loss. |
| T-132-05 | Elevation of privilege | SECURITY DEFINER trigger search_path hijack | mitigate | `SET search_path = public, pg_temp` on the definer function (standard hardening). |
</threat_model>
