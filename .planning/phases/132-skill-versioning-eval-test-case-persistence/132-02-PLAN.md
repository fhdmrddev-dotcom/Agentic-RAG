## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → API | Authenticated user requests carry a bearer token resolved by get_current_user; the user_id path/param can be forged → must be ignored in favor of current_user["id"]. |
| API (service-role) → Postgres | Service-role client BYPASSES RLS; app-code owner filter is the sole runtime gate. |

|-----------|----------|-----------|-------------|-----------------|
| T-132-06 | Information disclosure / Tampering | IDOR on /test-cases/{case_id} and /skills/{id}/versions | mitigate | Every query includes `.eq("user_id", current_user["id"])`; PATCH/DELETE WHERE matches id AND user_id; non-owner → 404. Verified per-route in plan-check (RESEARCH primary control). |
