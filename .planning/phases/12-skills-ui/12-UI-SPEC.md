## Spacing Scale

Declared values (multiples of 4 — standard 8-point scale):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), tight inline padding |
| sm | 8px | Compact row padding (`p-2`), button icon gaps (`gap-2`) |
| md | 16px | Default card body padding (`p-4`), form field gaps |
| lg | 24px | Section gaps (`gap-6`), card row spacing |
| xl | 32px | Page-level top padding (`p-8` = 32px) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Global badge pill: `px-2 py-1` (8px / 4px) — matches existing FolderNode global pill pattern (RESEARCH.md Pattern 7, source: PROGRESS.md)
- Disabled skill opacity: `opacity-50` — applied at wrapper level, not spacing
- Touch targets for icon-only action buttons: minimum 32px (`h-8 w-8`) per Button `size="icon"` default

## Color

All values use CSS variables. Both light and dark modes are declared in `index.css`.

| Role | Light Mode | Dark Mode | Tailwind Token | Usage |
|------|-----------|-----------|----------------|-------|
| Dominant (60%) | `hsl(220 20% 97%)` soft blue-grey | `hsl(216 45% 4%)` deep navy | `bg-background` | Page background |
| Secondary (30%) | `hsl(0 0% 100%)` white | `hsl(220 30% 7%)` dark navy | `bg-card` | Skill cards, dialogs |
| Sidebar / nav strip | `hsl(220 15% 95%)` off-white | `hsl(220 40% 5%)` darker navy | `bg-sidebar` | Left nav panel |
| Muted surface | `hsl(220 14% 94%)` light grey | `hsl(220 30% 11%)` charcoal | `bg-muted` | Global badge background |
| Accent (10%) | `hsl(239 84% 67%)` indigo | `hsl(239 100% 82%)` bright indigo | `text-primary` / `bg-primary` | Reserved list below |
| Destructive | `hsl(0 84% 60%)` red | `hsl(0 72% 51%)` red | `text-destructive` / `bg-destructive` | Delete action only |
| Success | `hsl(142 71% 45%)` green | same | `text-success` | Enabled-state indicator (if used) |
| Border | `hsl(220 13% 89%)` silver | `hsl(220 20% 16%)` dark border | `border-border` | All borders |

**Accent (`primary`) reserved for:**
1. Active Sidebar nav button background (`variant="secondary"`) and label (`text-primary font-semibold`)
2. The "New Skill" primary CTA button background
3. The send/confirm button in dialogs
4. The `skill_activated` inline badge text color
5. The `gradient-primary` gradient on the Zap icon in Skills tab nav (matches existing sidebar pattern)

**Never use accent for:** card borders, description text, global badges, disabled states, form labels.

Source: PROGRESS.md Color Palette Reference + index.css CSS variable definitions.

## Layout Contract

### SkillsPage — Single-panel layout (no folder tree)

```
┌─────────────────────────────────────────────────────────────┐
│  [Zap icon] Skills                   [+ New Skill button]   │  ← header row, mb-6
│  Define reusable AI behaviors that the agent loads on demand.│  ← description, text-sm muted
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐           │
│  │ SkillCard   │ │ SkillCard   │ │ SkillCard   │           │  ← grid-cols-1 sm:grid-cols-2
│  │ [dimmed if  │ │ [Global]    │ │             │           │     lg:grid-cols-3, gap-4
│  │  disabled]  │ │   badge     │ │             │           │
│  └─────────────┘ └─────────────┘ └─────────────┘           │
│                                                             │
│  [Empty state if no skills]                                 │
└─────────────────────────────────────────────────────────────┘
```

Page container: `flex flex-col h-full overflow-y-auto p-8` — identical to IngestionPage.

### SkillCard — anatomy

```
┌─────────────────────────────────────────────────────────────┐
│  [Zap icon 16px]  Skill Name              [Global] [badge]  │  ← header row, items-start
│                                                             │
│  Description text (2 lines max, line-clamp-2)              │  ← text-sm text-muted-foreground
│                                                             │
│  ─────────────────────────────────────────────────────────  │  ← border-t border-border/50
│  [Try in Chat]         [👁] [✏] [🌐] [🗑]                  │  ← footer row, justify-between
└─────────────────────────────────────────────────────────────┘
```

Card container: `rounded-xl bg-card ghost-border p-4 transition-all` with `opacity-50` when `!is_enabled`.

Owner-only actions (pencil, globe toggle, trash): hidden when `skill.user_id !== currentUserId`.
Non-owner global skills: show "Global" badge, "Try in Chat" button, and eye icon only — no edit/delete/toggle-global.
Global skills owned by seed account (`00000000-0000-0000-0000-000000000001`): toggle-enabled also hidden (single is_enabled row affects all users).

### SkillFormDialog — anatomy

Dialog title: "New Skill" (create mode) / "Edit Skill" (edit mode)

Fields:
1. **Name** — `Input` — required — placeholder: "e.g. SQL Writer"
2. **Description** — `Textarea` — optional — 2 rows — placeholder: "One sentence describing what this skill does"
3. **Instructions** — `Textarea` — optional — 8 rows — `font-mono text-sm` — placeholder: "Step-by-step instructions the agent follows when this skill is loaded..."

Footer: `[Discard Changes]` (ghost) + `[Save Skill]` / `[Update Skill]` (primary)

### skill_activated indicator — anatomy

Rendered inside `MessageItem.tsx` below the ToolCallPanel (when `message.activatedSkill` is set):

```tsx
<div className="flex items-center gap-1.5 mt-2 text-xs text-primary">
  <Zap className="h-3 w-3" />
  <span>Skill activated: {message.activatedSkill}</span>
</div>
```

This is an inline badge, not a toast. It appears per-message and persists in the conversation history.

## Interaction Contract

### Navigation

| Interaction | Behavior |
|-------------|----------|
| Click "Skills" in sidebar | Sets `activeView = "skills"`, renders `SkillsPage` in main content area |
| Active state | `variant="secondary"` + `text-primary font-semibold` on sidebar button |
| Inactive state | `variant="ghost"` + `text-muted-foreground hover:text-sidebar-foreground` |

### Skill CRUD

| Interaction | Behavior |
|-------------|----------|
| Click "+ New Skill" | Opens `SkillFormDialog` in create mode |
| Click pencil icon | Opens `SkillFormDialog` in edit mode, pre-populated |
| Click "Save Skill" | POST `/skills` → optimistic prepend to skills list → dialog closes |
| Click "Update Skill" | PATCH `/skills/{id}` → optimistic update in place → dialog closes |
| Click trash icon | Inline confirmation replaces the card footer (no separate modal) — shows "Delete skill?" + [Keep Skill] [Delete Skill] buttons |
| Confirm delete | DELETE `/skills/{id}` → optimistic removal from list |
| Cancel delete | Restores normal card footer |

### Skill Toggles

| Interaction | Behavior |
|-------------|----------|
| Click eye icon (enabled) | PATCH `/skills/{id}/toggle-enabled` → optimistic `is_enabled` flip → `opacity-50` applied/removed |
| Click eye-off icon (disabled) | Same — toggles back |
| Click globe icon (private) | PATCH `/skills/{id}/toggle-global` → optimistic `is_global` flip → "Global" badge appears/disappears |
| Click globe icon (global) | Same — badge disappears |

### "Try in Chat" navigation

| Interaction | Behavior |
|-------------|----------|
| Click "Try in Chat" | Sets `prefillMessage = "Use the [Skill Name] skill"` in App.tsx state, sets `activeView = "chat"` |
| MessageInput mounts with prefill | Displays pre-populated text in input field |
| User sends or types new content | `prefillMessage` cleared after first send or first keystroke |

### Loading and error states

| State | Rendering |
|-------|-----------|
| Skills loading (initial fetch) | Skeleton cards: 3 gray `rounded-xl bg-muted animate-pulse` placeholders, same dimensions as real cards |
| Empty state (no skills) | Centered illustration area — Zap icon 48px `text-muted-foreground/30`, heading, body copy, "+ New Skill" CTA (see Copywriting) |
| API error on create/update | Inline error below dialog footer: `text-sm text-destructive` — no toast |
| API error on delete | Inline error on card: `text-sm text-destructive mt-1` — restores normal UI on dismiss |
| API error on toggle | Optimistic update reverted; `text-xs text-destructive` shown below card actions for 3 seconds |

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Icon-only buttons | All icon-only action buttons must have `<Tooltip>` with readable label (established pattern from FolderNode.tsx) |
| Dialog focus trap | shadcn Dialog provides focus trap automatically via Radix |
| Dialog close on Escape | shadcn Dialog handles — no custom logic needed |
| Disabled skill visual | `opacity-50` on card; does NOT use `disabled` attribute (card is not interactive as a whole) |
| Color contrast | All text uses semantic tokens with sufficient contrast in both light and dark mode (verified from Aether Design System) |
| Delete confirmation | Inline in-card confirmation (not browser `confirm()`) — keyboard-accessible via Button components |

## What NOT to Build (Out of Scope for Phase 12)

The following are defined in REQUIREMENTS.md as out of scope or deferred:

- Skill file upload/management UI — FILE-01 through FILE-06 are backend-complete; the UI for file attachment is not required in Phase 12
- ZIP import/export UI — Phase 13 (OPEN-01 through OPEN-06)
- Per-user skill enable state — schema stores single `is_enabled` per skill row; per-user enable table is a Phase 13+ schema change
- Toast notifications — no toast library installed; inline states are used
- Admin moderation UI — out of scope project-wide (REQUIREMENTS.md Out of Scope table)
- Skill versioning/history — out of scope (REQUIREMENTS.md Out of Scope table)
