## Phase Boundary

**The identity of a library ROW** — how a person tells one workflow from another when many share a
name, whose a row is, what it was copied from, and which one changed most recently. Requirement
LIB-05.

**In scope:**
1. A computed **identity line** on the library card (161-A placement, 160-B content).
2. The **lineage / recency / ownership** data that line needs — a derived-at-render lineage
   resolver, plus one additive `updated_at` projection on three feeds and two TS types.
3. A **name prompt at the fork** (162-B) so new copies arrive differentiated instead of adding to
   the 43.
4. The **G-5 extraction** that the fork prompt makes due — see D-01.

**Out of scope (named, not implied):**
- The shelves/toolbar/chips/search frame — **Phase 192 shipped it and this phase consumes it
  unchanged.**
- `WorkflowSoul` — the five card atoms are consumed unchanged, exactly as 192 did.
- The consequence sentence (`FORK_CONSEQUENCE` / `FORK_CONSEQUENCE_EXISTING`) — **imported, never
  retyped, never reworded.** This phase adds a line; it does not spend the sentence slot again.
- A **sort control** or a change to the server's `ORDER BY name`. 160-C (recency ordering) LOST.
  SC#3 is met by the `changed <rel>` segment on the line, not by re-ordering the list.
- A **human-readable owner name.** Needs a users join; nobody asked; `Yours` / `Shared` is the
  honest ceiling (D-09).
- The authoring doors (193), the run surface (194+), the canvas, the publish gauntlet.
- **The double-encoded `definition` finding** (83 of 104 rows are `jsonb_typeof = string`). Real,
  recorded as `SEED-154`, and **not this phase** — see `## Known carried defects`.

**G-2 is SATISFIED.** Sketches 160/161/162 were built and driven 2026-08-12; the operator picked
**160-B · 161-A · 162-B**, and 163 assembled them into one surface with a machine-generated build

### The identity axis — 160-B (disambiguate on collision)

- **D-03: The line's CONTENT is computed per row from what actually differs among its namesakes.**
  Not a fixed subtitle (160-A), not re-ordering (160-C). Grammar, verbatim from the generated
  contract:

  ```
  [own pill] [computed seg] · [computed seg] [1 of N] · changed <rel>
  ```

- **D-04: SEGMENT PRIORITY when the name COLLIDES — first two that VARY across the namesake set
  win:** `lineage → project → state → version`. **Max 2 computed segments, always.** `1 of N`
  appears **only** on a colliding name. These are driven assertions in `163/drive.cjs`, not
  guidelines; the build's suite reproduces them against the real component.

- **D-05: `N` is counted over the FULL merged library, BEFORE search / chip / project filtering.**
  This matches the sketch (`identity(r, allRows())`) and it is the honest reading: the discriminators
  answer *what tells this row apart from its namesakes*, which is a property of the library. A count
  that shrank as you typed would both flicker and misdescribe the library.

- **D-06: THE SINGLETON EDGE — operator decision 2026-08-12: `quiet`.** This is the one edge
  160-B and 161-A disagreed about (B: no strip at all on unique names; A: a line on every card), and
  it is now recorded rather than left to an executor:

  > **Every card carries the identity LINE** (A's consistent placement), **and a unique-name row
  > carries NO discriminator segments** (B's restraint) — lineage only if the row is actually a
  > fork, plus the owner pill and `changed <rel>`.

  | Row | Identity line |
  |---|---|
  | Colliding name | `Yours · Copy of Compliance Gap Report starter · [1 of 43] · changed 2 months ago` |
  | Unique name, is a fork | `Yours · Copy of Access Review Attestation · changed just now` |
  | Unique name, not a fork | `Shared · changed 5 months ago` |

- **D-07: `1 of N` ships VERBATIM as the sketch renders it — `"1 of " + n` — and the concern it
  raises is routed to UAT rather than fixed by an unrecorded rewrite.** Every colliding row reads
  `1 of 43`; the leading `1` is a constant, not an index, and it *can* be misread as one. The
  operator-approved mockup is the acceptance bar and changing a bar string at plan time is the drift
  sketch 163 exists to prevent — so it ships as approved, **and a named UAT row asks a human whether
  it reads as an index.** If it does, that is a one-line change in one file (D-14), by construction.

### Lineage — derived, and honest about what it cannot derive

- **D-12: Lineage is derived at render from the SLUG RULES the fork handlers already own. Zero wire
  cost.** Two shapes:
  - **version fork** — same `slug`, a lower `version` present in the merged list → `v3 of v2`
  - **copy fork** — `slug` matches `^(.*)-[a-z0-9]{6}$` AND the base slug is present in the list →
    `Copy of <parent name>`, suffixed ` starter` when the parent is a starter

- **D-13: THREE lineage states, not two — and the third is SILENCE. Measured, and the measurement
  is why this decision exists.** Run against the live local DB 2026-08-12 (222 rows / 201 distinct
  slugs):

  | | count |
  |---|---|
  | slugs matching the copy-suffix shape | **69** |
  | …of which the parent slug **exists** | **57** |
  | …**orphans** — shape says copy, parent absent | **12** |

  The orphans are not deleted parents; most are **false positives**, and the sketch's generated
  fixture could not surface them because its slugs were minted by the fork rules themselves.
  `pm-weekly-status-report` matches the regex because `report` is six lowercase alphanumerics.
  `ephemeral-template-fill-101uat` and `risk-register-fill-101uat` match on `101uat`. **The charset
  cannot be narrowed to rescue this** — `freshHash()` (`WorkflowsPage.tsx:141`) is
  `Math.random().toString(36)`, i.e. genuinely `[a-z0-9]{6}`, so `report` is a legal hash.

  Therefore the parent-exists guard is **load-bearing**, and the fallback must be silence:

  | Case | Renders |
  |---|---|
  | parent resolves | `Copy of X` / `vN of vM` |
  | slug shape is not a fork shape | `Original` |
  | **slug shape matches, parent ABSENT** | **no lineage segment at all** |

  The sketch's `lineagePhrase` returns `Original` in that third case. **On real data that would be a
  fabricated claim** — a genuine copy whose parent was deleted or is invisible to this user would be
  labelled an original. The measured trade is stated plainly: **57 resolve · 12 go quiet · 0 lie.**

- **D-14: Every string this phase renders lands in `libraryVocabulary.ts` and is IMPORTED.** Port the
  sketch's single `COPY` object (`163/index.html:228-250`), whose shape was deliberately built to
  mirror this module. `FORK_VERB` (`:78`) and `FORK_CONSEQUENCE` (`:91`) already live there and are
  **read, never re-typed** — the sketch itself reads them from the fixture, which is the proof the
  mechanism works. A copy change must be a one-line diff in one file.

### Recency — the one net-new wire field

- **D-15: `updated_at` ships as an ADDITIVE projection on three feeds and two TS types — the exact
  shape Phase 192 used for `is_mine` (its D-04). No migration, no predicate change, no new column.**
  The column already exists (`full-schema.sql:1941`) and is maintained by
  `workflow_definitions_set_updated_at` (`:3771`). Measured: **0 of 222 rows are NULL**, spread over
  **21 distinct days**.

  | Touch point | Change |
  |---|---|
  | `db/workflows.py` `list_published_workflows` (`:231`) | add `updated_at` to both `SELECT` lists — projection only, predicate untouched |
  | `db/workflows.py` `list_starter_workflows` (`:309`) | same |
  | `db/workflows.py` `list_draft_workflows` (`:502`) | same |
  | `api/workflows.py` `list_drafts` (`:1072`) + the published/starter response builders | serialize the new field |
  | `api.ts` `PublishedWorkflow` (`:1364`) / `WorkflowDraftRow` (`:3328`) | one optional field each |
  | `libraryRow.ts` (`:52`) | one field on `LibraryRow` |

- **D-16: ⚠ NEVER READ `token` AS A TIMESTAMP. It is already `updated_at` in disguise and it is a
  trap.** `CONCURRENCY_TOKEN_SQL` (`db/workflows.py:93-95`) is
  `to_char(updated_at AT TIME ZONE 'UTC', …)`, and `api.ts:3334-3345` forbids parsing it: Postgres
  keeps microseconds, a JS date keeps milliseconds, and a parsed-and-re-rendered token matches **zero
  rows** — every later save then refuses as stale (probed against the live database 2026-08-01).
  **Project a separate field. This is a fence, not advice.**

- **D-17: `changed <rel>` for a PUBLISHED row means "when it was published", and that is honest, not
  a bug.** `workflow_definitions_block_published` (`full-schema.sql:3764`) makes a published row
  immutable, so its `updated_at` is frozen at the publish flip — which *is* the last time it changed.
  Do not add a second field to "fix" this.

- **D-18: ONE relative-time formatter, in the library subtree, with the sketch's exact bands.** No
  date dependency (`frontend/package.json` carries none — verified) and no reach into
  `UsersAndAccess.tsx:87`'s private `relativeTime`, which is COMPACT (`4mo ago`) for an operator
  audience while this surface is long-form. The bands, from `library-fixture-192-1.js:352-365`:
  `just now` (≤ 1 min) · `N min ago` · `N hour(s) ago` · `yesterday` · `N days ago` · `last week` ·
  `N weeks ago` · `last month` · `N months ago`. Prefixed by `CHANGED_PREFIX = "changed "`.

### The fork asks for a name — 162-B

- **D-19: 162-B REOPENS 192's D-15, and D-15 IS AMENDED IN THE SAME COMMIT — never left silently
  contradicted.** 192's D-15 made the fork a **direct flip** on a recorded argument, spelled out in
  the card's own docblock (`WorkflowCard.tsx:79-87`): a confirm on a non-destructive, reversible
  action *spends the guard vocabulary the delete relies on*.

  **The rationale that makes this prompt legal, and it is mechanical rather than asserted: it
  collects something the system cannot know, so it is an INPUT, not a guard — and inputs do not
  spend guard vocabulary.** The design carries that claim in its own shape, and each clause is a
  test:
  - it asks for a **name**, never for a confirmation;
  - it wears **no destructive styling** — no `DESTRUCTIVE_ITEM_CLASSES`, no red, no victim naming;
  - its primary button is **`Create my copy`**, and asserting *"the primary button is not
    `Confirm`"* is what makes the distinction mechanical;
  - it **warns and never blocks** on a colliding name (D-20).

  The graded-guard ladder (146-148) is untouched: sheet for the live delete, arm-to-confirm for the
  draft delete, and the fork remains outside the ladder entirely — it is now an input step, not a
  lighter guard.

- **D-20: The name prompt WARNS, NEVER BLOCKS, on a colliding name.** A name you chose is a name you
  are allowed to have; blocking would make the library's problem the user's fault. The only hard gate
  is **emptiness** (`FORK_HINT_EMPTY = "Give it a name."`). The collision hint is
  `FORK_HINT_CLASH`; the clear state is `FORK_HINT_FREE`.

- **D-21: The pre-flight collision check is CLIENT-SIDE, over the caller's OWN rows in the merged
  feed — free, because the page already holds it.** It checks the **display name**, which is what the
  human sees. It is not, and must not be presented as, a slug check.

- **D-22: WR-08 IS NOT RETIRED IN THIS PHASE, and that is recorded rather than half-done.** Sketch
  163 floats the name field as a natural home for the 409. It is not: the 409 is a
  `UNIQUE(slug, version)` violation and the pre-flight check reads names. The two residual failing
  rows are `published + published` slugs with no draft (`meridian-risk-summary-good-07aedc33`,
  `readonly_refusal_098uat` — named in `WorkflowsPage.tsx`), and no name field prevents that.
  `isForkConflict` (`WorkflowsPage.tsx:165`) therefore **moves with the extraction and keeps its
  substring test**, docblock intact.

  **WR-08's re-open trigger is restated verbatim so it survives this phase:** *the next phase that
  touches `createWorkflowDraft`'s throw site replaces this substring test with the typed error's own
  discriminator, in the same commit.* This phase does **not** touch that throw site — it is an
  `api.ts` change with callers outside this page (notably `useDraftPersistence`).

- **D-23: 192-14's open-the-existing-draft branch SURVIVES the prompt.** On a published row the
  caller has already forked, the verb still **opens** the existing draft and creates nothing — so **no
  name prompt appears on that path**, because nothing is being named. The card's sentence already
  says so (`FORK_CONSEQUENCE_EXISTING`, selected by `hasExistingFork`). Regressing this re-opens the
  U5 blocker.

- **D-24: `onUseStarter`'s single 409 retry is PRESERVED**, and stays pinned from the inside at
  **exactly two `createWorkflowDraft` calls** (T-192-42), so it cannot be deleted under cover of the
  refactor.
