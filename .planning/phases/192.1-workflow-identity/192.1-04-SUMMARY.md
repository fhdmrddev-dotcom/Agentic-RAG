## Deviations from Plan

### 1. [Rule 1 — Bug] The plan's `30 days → last month` is arithmetically impossible

- **Found during:** Task 2, writing the band table.
- **Issue:** the `<behavior>` block says *"30 days → `changed last month`"*. Under the algorithm
  the same plan instructs be ported **verbatim**, `wks = round(30 / 7) = 4`, which is `< 5`, so
  the weeks band answers first: **`4 weeks ago`**. The two halves of the plan contradict each
  other.
- **Fix:** the ALGORITHM wins — `<action>` and the acceptance criteria both say *"port the nine
  bands verbatim"*, and the sketch is the acceptance bar. The real threshold was measured and is
  now pinned **on both sides**: 31 days is the last `weeks` day, 32 days the first `last month`
  day. The correction is stated in the test file's own header so it is not silently re-broken.
- **Commit:** `17696a63`.

### 2. [Rule 2 — Correctness] A STRICT tier with no emit phase is UNREACHABLE

- **Found during:** Task 3, mapping the sketch's `tierId` onto real definitions.
- **Issue:** the sketch carries a free-standing `tierId` string. The app has none —
  `tierForDefinition` (`soulData.ts:111`) reads the strictest `citation_policy` across the
  definition's `llm_emit` phases. With **no** emit phase the policy defaults to `draft`, and
  `deriveTier` can lift that to MIDDLE at most. The sketch's *Offboarding Access Sweep* is
  `STRICT` + `answer`, i.e. **a tier the product cannot produce**.
- **Fix:** it is MIDDLE in the fixture, reached the way the product reaches it — a
  `structure_check` validator. Recorded in the `SINGLETONS` docblock. A fixture that carried an
  unreachable tier would let a *Strict* chip assertion pass against data that cannot exist.

### 3. [Rule 2 — Correctness] A starter must carry NO project

- **Found during:** Task 3.
- **Issue:** the sketch's `makeSource` picks a random project for starters too. Production does
  not: `094_starter_workflows.sql` sets none on any of the three seeded rows — which is the exact
  fact `PROJECT_STARTERS_NOTE` states out loud ("Starters aren't tied to a project."). A fixture
  contradicting the note would make D-17's UAT row (U6) unprovable.
- **Fix:** starters get `projectId: null`, with the reason at the call site. The `BUILD-CONTRACT`
  rendered line for the starter (`Shared` · `No project` · …) independently agrees.

### 4. [Rule 2 — Correctness] `isMine` follows the shipped normalizer, not the sketch

- **Found during:** Task 3.
- **Issue:** the sketch sets `isMine: true` on every fork. `fromDraft` (`libraryFilter.ts:97`)
  deliberately leaves it **`undefined`** — `/workflows/drafts` is already scoped to
  `created_by = $1`, so the feed-derived fallback answers correctly without the row asserting a
  bit no payload carried. A fixture setting `true` on every draft hides that fallback path
  entirely, and the fallback is D-04's whole point.
- **Fix:** drafts emit `undefined`. Measured spread: **58 true / 6 false / 42 undefined** — all
  three readings present, so the *Yours* predicate is exercised on every branch.

### 5. [Rule 2 — Correctness] `grep -c "Math.random"` cannot be 0 — the 187-24 trap, 5th instance

- **Found during:** Task 3's acceptance criteria.
- **Issue:** the criterion requires `grep -c "Math.random"` to equal **0**, but the module must
  record that `freshHash()` really is `Math.random().toString(36)` — that is *why* `report` is a
  legal six-character hash and *why* the D-13 orphans exist. A whole-file needle reds on the prose
  documenting the rule it enforces.
- **Fix:** verified over **non-comment CODE lines**, this repository's own recorded resolution
  (F1 became AST-parsed for it; the `HighlightTitle` fence was observed RED against a comment;
  `libraryFilter.test.ts:461-468` scopes its `token` fence the same way; 192.1-03 hit it on three
  greps at once). **Measured: raw 3, CODE 0.** The measurement and the trap are recorded in the
  fixture's header. `setInterval`, `fetch(` and I/O: raw 0 / CODE 0.

### 6. [Rule 3 — Blocking] The `third`-admission fence was case-sensitive

- **Found during:** Task 2's GREEN step (1 failure of 37).
- **Issue:** `expect(source).toMatch(/\bthird\b/)` reddened on a docblock that says **THIRD** —
  this file's house voice puts load-bearing words in caps. The fence reddened on prose that
  satisfies its own intent, which trains a reader to reword the prose.
- **Fix:** `/\bthird\b/i`, plus a **non-vacuity control** so the anchored needle is not merely
  looser. The claim the fence makes is unchanged; only its blindness to case is.

### 7. [Measurement] Family multiplicities below the top four, and the singleton count

D-30 pins the four named families, the duplicated-name count and the total; the tail is not
measured anywhere. Reaching **106** with **14** duplicated names and a usable singleton control
forced a choice, and it is stated rather than left implicit: the ten tail families are
`3 · 3 · 2 × 8 = 22`, and there are **11 singletons** plus **2 appended orphans**
(`71 + 22 + 11 + 2 = 106`). The alternative — 13 singletons — forces every tail family to exactly
2 and flattens the multiplicity gradient. Two of the sketch's 13 singletons were dropped; one of
them (*Policy Translation (DE)*) also carried an F5 word in its purpose, so dropping it is
doubly cheap even though the fixture sits outside the sweep.
