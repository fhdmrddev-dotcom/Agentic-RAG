## Deviations from Plan

### 1. [Rule 2 — Correctness] The project axis can RANK but cannot SPEAK, and D-14 is why

- **Found during:** Task 1, writing the axis table.
- **Issue:** the plan says the project extractor is *"`row.def?.project_folder_id`'s resolved name,
  or `NO_PROJECT`"*. **There is no resolved name available.** `LibraryRow` carries a UUID; the
  folder list lives on the page, and the fixed `<interfaces>` contract is
  `buildIdentityIndex(rows)` — rows and nothing else, which D-05 independently requires. Rendering
  the UUID would be exactly the technical discriminator D-31 forbids, and D-14 requires every
  rendered string to come from `libraryVocabulary.ts`.
- **Fix:** the axis contributes its folder id to the **histogram** (a row in Legal is genuinely
  narrowed against one in Finance) but the only segment it can **render** is `NO_PROJECT`. A row
  inside a named project falls through to the next axis — a MISSING segment, not a wrong one,
  which is the posture the plan already prescribes for P-7. **A second, independent reason makes
  this the right answer rather than a workaround:** the card already paints the project one node
  BELOW this line (the folder chip, `WorkflowCard.tsx:383-387`, which D-08 places immediately
  after the identity line), so a segment naming it would spend one of two slots on something the
  reader can already see. The chip renders nothing when a row is unbound — so the absence is
  precisely the case the chip cannot show. Recorded in the module's own header.
- **Consequence to inherit:** the fixture's starter row renders
  `Shared · Shared starter · No project · 1 of 43 · changed 5 months ago` — the same two computed
  segments as `BUILD-CONTRACT.generated.md`, in **narrowing order rather than D-04 order**. That
  swap is D-31 working as decided, not drift.

### 2. [Rule 1 — Bug] The sketch's copy-parent lookup is FEED-ORDER DEPENDENT

- **Found during:** Task 1's RED, as `expected { kind: 'copy', …(2) } to match object { kind: 'copy', …(2) }`.
- **Issue:** `lineageOf` picks the parent with `rows.forEach(o => { if (o.slug === m[1]) parent = o })`
  — **last write wins**. On `compliance-gap-report`, which carries a v1 **starter** and a v2
  **draft**, that flips ` starter` on or off depending on which feed answered first. The 40
  children would say *"Copy of Compliance Gap Report"* or *"Copy of Compliance Gap Report starter"*
  by accident of `Promise.allSettled` ordering.
- **Fix:** the parent is the **origin of the parent slug** — its lowest version, ties to first
  seen. Deterministic, and it is the row a person means by "what it came from".

### 3. [Rule 2 — Correctness] `versionLabel()` had to be authored, not copied (D-14)

- **Issue:** `BUILD-CONTRACT.generated.md` declares **no key** for the bare version segment,

- **Fix:** `versionLabel(n)` added to `libraryVocabulary.ts` beside `lineageVersionOf`, so the two
