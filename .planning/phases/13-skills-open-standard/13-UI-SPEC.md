# Phase 13 — UI Design Contract

> Visual and interaction contract for Phase 13: Skills Open Standard.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

## Scope Note

Phase 13 adds two UI touch-points to the already-built Skills UI from Phase 12:

1. **Export button** on `SkillCard` — owner-only icon button, triggers ZIP download
2. **Import button + hidden file input** on `SkillsPage` — triggers `.zip` file picker, shows result toast

All tokens, layout, typography, and color are inherited from the established "Aether Intelligence" design system. This document records the contract for the two new elements and confirms all inherited values so the executor has a single source of truth.

## Interaction States

### Export flow

1. User clicks Export icon button on a SkillCard they own.
2. Button immediately shows disabled + `Loader2` spin (replaces `Download` icon).
3. `exportSkill(id, name)` is called — fetches ZIP blob, triggers `<a download>`.
4. On success: button returns to normal state. No toast needed (browser download bar is feedback).
5. On error: button returns to normal state. Inline `text-xs text-destructive` appears below card footer: "Export failed. Try again."

### Import flow

1. User clicks "Import Skill" button in SkillsPage header.
2. OS file picker opens filtered to `.zip`.
3. User selects a file — `onChange` fires immediately.
4. Import button shows disabled + `Loader2` spin.
5. On full success (all skills created): toast "Skill imported" / "{N} skills imported".
6. On partial success: toast "{N} skill imported, {M} failed — check your ZIP."
7. On total failure (no SKILL.md, bad ZIP, parse error): toast "Import failed — {api error message}."
8. Skills list refreshes (re-fetch) after import regardless of partial/full success.
9. File input value is reset so the same file can be re-imported after a fix.
