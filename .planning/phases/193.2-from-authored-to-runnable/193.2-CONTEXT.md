## Phase Boundary

Everything between *"the AI wrote my workflow"* and *"I can run it and find it again."*

Three findings, **all observed by the operator in ONE sitting** on Phase 193.1's own headline
path, immediately after `AUTH-03` was proven working. They are one phase and not three fixes
because they share **one root: the authoring path makes decisions the author is never shown, and
does not know what the publish gate requires.**

| Item | What happens today |
|---|---|
| `SEED-163` | The AI authors five phases from the describe text, then leaves `business_requirement` blank — the author restates the same intent by hand before publish is possible |
| **`BUG-260815-01`** (blocking) | The draft grows an `llm_human_input` step the synchronous publish gate categorically refuses; the operator deleted it on the canvas to proceed |
| **`BUG-260815-02`** (blocking) | A just-published workflow is unfindable — the AI names it, the library sorts `ORDER BY name` at three call sites with no recency ordering anywhere, and *"Quarterly Business Review…"* landed at position **129 of 146** |

**IN SCOPE:** the proposed business requirement; suppression + honest refusal of the unwanted
interactive step; recency ordering of the library feeds; measuring two shipped surfaces that
should already have covered half of this and apparently did not.

**OUT OF SCOPE, ruled explicitly:**
- **Letting the author name or rename the workflow** → 197 / AUTH-02 (D-16).
- **Card density / list-vs-card layout** → G-2 fires; needs `/gsd:sketch` first, bound by
  `SEED-155`. **Sorting is a defect and ships regardless of any layout decision.**
- **A workflow that DELIBERATELY pauses for a person and can still be published** → `SEED-164`.
  ⚠ **This phase SUPPRESSES the unwanted interactive step; it does NOT deliver that capability.**
  Nothing shipped here may imply otherwise (D-11).
- **Removing or weakening the publish gate.** An unsubscribed `ask_user` can wedge a publish
  indefinitely. The gate is deliberate and stays.

### The proposed business requirement (`SEED-163`)

- **D-06 — THE FIELD ARRIVES PRE-FILLED AND VISIBLY MARKED AS AN AI PROPOSAL.** Populated,
  editable, and carrying a visible mark that the AI wrote it. Rejected: a silent pre-fill
  indistinguishable from typed text — that repeats this phase's own root failure in miniature (a
  decision the author is never shown), and the project already judged that shape wrong once.
  Rejected: an empty field with a click-to-accept proposal — still one extra act before publish,
  which is the friction `SEED-163` exists to remove.

  **Reuse the shipped provenance pattern, do not invent one.** Phase 187 / D-187-03 stamps
  `name_seeded_by_ai` in `backend/app/services/workflow_authoring.py:353-375`, and its edit rule
  (D-187-07) already clears a GENERATOR-seeded value and never a hand-typed one. ⚠ **That precedent
  also carries a rule worth honouring verbatim:** a value that trims empty was not seeded and must
  not be stamped as such — *"provenance for a name that does not exist would make that rule read a
  lie."* The same applies here.

- **D-07 — THE PROPOSAL IS A DURABLE REQUIREMENT, NEVER A COPY OF THE DESCRIBE TEXT.** `SEED-163`
  is explicit and this is not re-litigable: `describe` is a task instruction (*"produce a QBR for
  Northwind covering Q3"*), the requirement is what the workflow must deliver for **any** run
  (*"produce a client-ready QBR for a named account from our own records"*). A verbatim copy bakes
  one run's parameters into the workflow's definition of done, and the publish gauntlet's later
  stages read this field. The prompt must ask for the durable form.

- **D-08 — WHEN THE MODEL EMITS NOTHING, FALL BACK TO TODAY'S EXACT BEHAVIOUR.** Blank field plus
  the shipped `REQUIREMENT_INVITATION` (`frontend/src/pages/WorkflowBuilderPage.tsx:383` — *"What
  must this workflow deliver? · required to publish"*). No new failure mode, no new string, no lie.
  Rejected: a second derive call (a new provider call and a new failure surface on every miss) and
  making the field schema-required (a hard-required field can fail an otherwise-valid emit, and the
  change ripples to every other emit path).

  ⚠ **This makes the fix explicitly non-deterministic, and the phase may only claim a measured
  reduction in frequency — never absence.** Any success criterion or test written as "the field is
  always populated" is wrong.

- **D-09 — THE PUBLISH GATE IS NOT CHANGED. Pressing Publish IS the consent.** Stage 1's predicate
  `business_requirement_missing` (`backend/app/services/harness/grounding.py:1007`) only checks the
  field is non-empty, so an AI-seeded value passes it untouched — **and that is accepted.** The
  author still presses Publish, which `SEED-163` names as the human checkpoint, and D-06's visible
  mark means they can see and overrule it. Rejected: a gate that distinguishes seeded from
  author-confirmed — that would add a genuine second concern to `publish_service.py` and void D-01
  for that file.

  ⚠ **The emit tool ALREADY advertises this field.** `WF_SCHEMA = WorkflowDefinition.model_json_schema()`
  (`workflow_authoring.py:151`), and `business_requirement` is on `WorkflowDefinition`
  (`backend/app/models/harness.py:538`). **No schema change is needed** — the prompt simply never
  instructs the model to set it. `grep -c business_requirement` over the authoring module returns
  **0**, and that is the whole defect.

### The interactive step (`BUG-260815-01`)

- **D-10 — WAVE 1 MEASURES WHY THE SHIPPED AUTHOR-TIME GATE DID NOT FIRE, BEFORE ANYTHING IS
  BUILT. This is a first-class deliverable, not a preamble.**

  ⚠ **Two facts were measured during discussion and they do not add up with what the operator
  experienced:**
  1. `/validate` **already** mints an `interactive_phase` verdict on every canvas edit —
     `backend/app/api/workflows.py:895-903` calls `publish_service._interactive_phase_failures(body)`.
  2. That verdict **already** greys the Publish control and shows the server's message **verbatim**
     — `interactive_phase` is registered in BOTH `_ROUTE_ASSIGNED_CODES` (`:686`) and
     `_INCOMPLETE_CODES` (`:700`), `blockedReason` renders the first verdict's message unmodified
     (`frontend/src/pages/WorkflowBuilderPage.tsx:1341`), and there is a **pinned test**:
     *"187-28 — a route-assigned verdict GATES the Publish control"* in
     `frontend/src/pages/WorkflowBuilderPage.canvas.test.tsx`.

  **If the control was greyed, the operator could not have clicked Publish and received a 400.**
  One of those two facts is false on the live path and the phase must establish which. Candidate
  causes to test rather than assume: `blockedReason` returns `null` unless
  `canvasEnabled && builderPhase === "drafted"`; the describe-door hand-off may reach publish
  before `/validate` has run; `isCheckOutstanding` may resolve differently on a freshly-generated
  draft.

  **The precedent for sequencing it first is measured, not stylistic:** 193.1's Wave 1 was
  sequenced exactly this way and found that phase's CENTRAL assumption FALSE (`template_placeholders`
  alone did not flip the deliverable branch — 0 of 3). At the gate that would have cost the phase.
  ⚠ **If the gate is silently not firing, that is the real defect and rewriting the string fixes
  nothing.**

- **D-11 — SUPPRESSION IS A PROMPT CLAUSE ONLY, IN THE DELIVERABLE RULE'S OWN VOICE.**
  `AUTHORING_SYSTEM_PROMPT` already carries a rule labelled *"CRITICAL — a wrong choice makes the
  workflow unpublishable"* (`workflow_authoring.py:82-91`); the interactive case joins that same
  rule. **Symmetric with the D-26 fix that caused this.**

  ⚠ **Rejected: a server-side strip of the emitted phase.** Deterministic, and wrong here — it
  silently deletes a step the model judged necessary, which is the exact *"decisions the author is
  never shown"* root this phase exists to fix, and it forecloses `SEED-164`'s capability at the
  wrong layer. Rejected: emitting it pre-flagged on the canvas — a new canvas affordance, new UI
  surface, and G-5 on the canvas files.

  ⚠ **LENGTH IS A CONSTRAINT ON THIS PROMPT, not a style note.** The module's own comment records
  it (`:70-74`): the six shipped phase-type bullets have a median of 83.5 characters, and an
  over-long bullet is a nudge that skews composition toward the type it describes. A clause about
  `llm_human_input` that is three times the length of the `llm_human_input` bullet is itself a
  hazard.

  ⚠ **The gate STAYS.** Prompt-level mitigation reduces frequency and cannot guarantee absence.

- **D-12 — ONE MESSAGE STRING, REWRITTEN ONCE, FEEDS BOTH SURFACES.** The literal composed in
  `publish_service._interactive_phase_failures` (`:502-540`) is consumed verbatim by the publish
  refusal AND by `/validate` → `blockedReason` → the canvas. **Rewrite it in one place; both
  change.** Any plan that writes a second string for the canvas is wrong.

- **D-13 — THE REFUSAL NAMES THE STEP BY ITS VISIBLE LABEL AND OFFERS TO REMOVE IT.** Today it
  names two internal phase-type identifiers (`llm_human_input` / `ask_user`) at a person who chose
  neither and can see neither word on the canvas — **the same failure class as `BUG-260809-02`,
  whose message named an internal snake_case field.** The rewritten message names the offending
  step by the plain-language `name` a non-coder reads on the canvas, and offers removal as an
  action.

  ⚠ **The label is available and the current message throws it away.** `_interactive_phase_failures`
  already carries `phase` (the slug) per finding, and the phase's human-readable `name` is on the
  definition it is iterating — the authoring prompt mandates *"a short, specific, plain-language
  `name` … what a non-coder reads on the canvas"* (`workflow_authoring.py:99-104`).

  ⚠ **Guard against a slug leaking into the copy** where a name is empty or missing — an empty
  label must degrade to something honest, never to a bare slug, which would reintroduce the exact
  defect being fixed.

- **D-14 — THE MESSAGE MUST NOT PROMISE THE CAPABILITY.** It may not say a deliberate human-pause
  workflow is *"planned"*, *"coming"*, or *"deferred"*. `SEED-164` exists **because** a docblock
  calling something *"the DEFERRED Phase-103 rework"* made unscheduled work read like a plan for a
  year — and Phase 103 shipped long ago. **Repeating that in shipped user-facing copy is the same
  error with a wider audience.** State what is true now; name nothing that is not on the roadmap.

### Findability (`BUG-260815-02`)

- **D-15 — ORDER BY `updated_at DESC`.** Already on the wire and already consumed: Phase 192.1
  ships `relativeChanged`'s nine bands off this exact column (`libraryFilter.ts:86` and `:112`), so
  the card's *"changed 2 minutes ago"* text and the list order **agree by construction** rather than
  by discipline. Rejected `created_at DESC`: strictly the publish moment, but it would have the card
  reading one column while the list orders by another — the quiet disagreement this project keeps
  finding.

- **D-16 — PUBLISHED AND DRAFTS GET RECENCY; STARTERS STAY ALPHABETICAL.**
  `list_published_workflows` (`backend/app/db/workflows.py:316`) and `list_draft_workflows` (`:553`)
  change; `list_starter_workflows` (`:352`) does not. Starters are a **curated catalogue the author
  did not write** — *"most recently updated starter"* is meaningless to someone browsing, and
  alphabetical is genuinely right for a catalogue. **The two feeds holding the author's own work get
  recency.**

  ⚠ **`BUG-260815-02` warns "change them together or the feeds disagree", and this decision
  deliberately does not.** That is accepted with eyes open **on condition that the divergence is
  written into the `db/workflows.py` ledger row (D-03) and into the code**, so the next reader finds
  a recorded decision rather than an inconsistency. Rejected: an explicit curated-order column for
  starters — a schema change and a genuine second concern in `db/workflows.py`, which would void
  D-01 on the file that fires G-5 hardest.

- **D-17 — SERVER `ORDER BY` IS THE SOLE AUTHORITY; NO CLIENT SORT IS ADDED.** Verified, not
  assumed: a shipped positive-controlled fence pins it —
  `frontend/src/components/workflows/library/rowIdentity.test.ts:167`, *"T-7 / P-4 — the ROW LIST is
  never re-ordered, and every sort says what it sorts"*, which fails any `rows.sort(` /
  `family.sort(` / `list.sort(` in the module and additionally requires ≥ 2 `NEVER THE ROW LIST`
  annotations in the prose. **The three-call-site SQL change is therefore sufficient AND that fence
  must stay green** — any plan adding a client-side ordering breaks it.

  ⚠ **Open for research, not decided here:** the three feeds are merged client-side and the fence
  forbids re-ordering the merged list, so the merged order is concatenation order. Research must
  establish where a freshly-published row actually lands in the RENDERED list — recency inside the
  published block is only useful if that block is reachable. **SC#3 is about the rendered position,
  not the SQL.**

- **D-18 — FIXED DEFAULT, NO SORT CONTROL.** Changing the default is a **defect fix and ships
  regardless of any layout decision.** A sort dropdown on `LibraryToolbar` is a UI addition to the
  library surface — the half where G-2 fires and where card-density / list-view is already routed to
  `/gsd:sketch`. **Building a control the pending sketch may relocate or redesign is building it
  twice.** The control goes to the sketch alongside layout (see `<deferred>`).

- **D-19 — THE POST-PUBLISH CTA IS MEASURED BEFORE ANYTHING IS BUILT BESIDE IT — same discipline as
  D-10.** It already exists and already names the workflow:
  `frontend/src/pages/WorkflowsPage.tsx:897-908` renders *"Published **{name}** v{version}. Ready to
  run it."* with a Run button, set on gauntlet PASS (`runCta`, `:282`; sketch 023-A), and WR-04
  already fixed one way it silently dropped (a hardcoded `"workflow"` slug literal finding nothing).

  **So "the product never told me the name" is at least partly already closed, and the operator was
  still lost.** Research establishes whether the CTA fired at all on their path. Two honest outcomes,
  both acceptable: it fires reliably and **SC#3 is met by the sort alone**, or it does not and that
  is a named defect this phase fixes. ⚠ **Do not build a second hand-off surface beside a shipped one
  without knowing why the shipped one failed** — `WorkflowsPage.tsx` carries an inherited G-5
  obligation and a navigate-to-row behaviour would be a genuine second concern.

  ⚠ **Note the CTA depends on the row existing in `rows`** (`:861-864` — `rows.find(...)` by slug,
  excluding drafts), so it is coupled to the published re-fetch landing. That coupling is a concrete
  thing for research to test.

### Verification shape

- **D-20 — NO FULL 8-ROW CROSS-PROVIDER ROSTER; TEST THE RESOLVABLE AUTHORING MODELS ONLY.** The
  roster rule exists because chat routes through any provider. **Authoring cannot.**
  `resolve_authoring_model` (`workflow_authoring.py:109-133`) returns
  `settings.harness_authoring_model`, else the first of `("claude-opus-4-8", "gpt-5.5")` whose
  registry entry has a truthy `forced_emission` — **it is explicitly NOT the composer's selected
  model.** Scoring eight providers on a path six of them can never take would measure a
  configuration that does not ship, which is the exact error the roster rule itself warns about
  (an id that resolves `capability_source=inferred` measures a weaker configuration than the one
  that ships).

  ⚠ **The other six are recorded as N/A WITH THE REASON, never dropped.** *"A scoreboard that lists
  only what passed is not a scoreboard"* — and one that silently omits rows is worse. The
  scoreboard states the roster rule, states why it is narrowed here, and names the two rows driven.

- **D-21 — SC#4 IS ONE REAL OPERATOR-DRIVEN END-TO-END RUN AT PHASE CLOSE.** Re-run the Phase 193.1
  UAT kit (`C:\Users\fhdmr\Desktop\uat-193.1-qbr\`, scoring rule: 8+ planted facts), same shape as
  193.1's U5 — *the row no test could stand in for*. ⚠ **It is also the ONLY row that exercises all
  three fixes together**, in the order a person meets them: describe → pre-filled requirement →
  publish **without deleting a step on the canvas** → find it at the top of the library. Rejected:
  automated regression alone — 193.1 measured that a 3,600-case suite could not see the assumption
  that mattered, and a `render_template` pin does not prove a template gets FILLED.
