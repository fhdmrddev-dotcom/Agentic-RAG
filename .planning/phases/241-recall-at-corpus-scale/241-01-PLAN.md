<objective>
Replace the Phase 230 recall harness with a measurement that can report a failure.

Purpose: 241-CONTEXT F-1 measured the shipped harness and found it structurally incapable of
failing — `scripts/measure-recall.py` never touches the vector path (it runs `content ILIKE`),
scores every un-found target `rank = 1` under the comment *"Standard ground truth baseline"*, and
on a connection failure prints a hardcoded `mock_ranks` list and **returns 0**. Run live against
the real 159-document corpus it prints `MRR 1.000`. ROADMAP failure mode #1 is *"'Recall is fine'
is asserted from spot checks, with no number anyone can reproduce"* — the live state is worse:
there IS a reproducible number, it is perfect, and it is meaningless. Every other plan in this
phase measures with this tool, so it is built first and its honesty is pinned by a test that has
been seen to fail.

Output: a rewritten `recall_eval.py` (one home for the probes, both layers, an explicit refusal),
a rewritten `measure-recall.py` CLI driven by `--dsn`, a retired `tests/eval` baseline test, and a
new honesty guard in `backend/tests/unit/`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell → `measure-recall.py` | A DSN carrying a password crosses on `argv` |
| `measure-recall.py` → Postgres | Filter shapes and a synthesized JWT-claims payload cross into a `SECURITY DEFINER` body |
| harness → `--json-out` report / SUMMARY | Real corpus content and a real user id cross into a file that gets committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-241-01 | Information disclosure | `--dsn` on argv, and the DSN echoed into reports/exception messages | mitigate | Parse the DSN and emit only host + database in every printed line, every `RecallUnmeasurable` message and every JSON field. Never write the password to the report, to stdout or to the SUMMARY. Add a unit assertion that the refusal message does not contain the password substring. |
| T-241-02 | Tampering (SQL injection) | `FILTER_SHAPES` values reaching `match_document_chunks` | mitigate | Every filter value is an asyncpg **bind parameter** (`$5` jsonb, `$6` uuid[]) — never string-interpolated. The `jsonb` argument is passed as a Python object and json-encoded once by the driver; a pre-encoded string would double-encode (the recorded jsonb string-scalar trap). No f-string ever builds a `WHERE` clause. |
| T-241-03 | Elevation of privilege | The synthesized `request.jwt.claims` GUC | accept | The harness deliberately impersonates a real user id so `auth.uid()` resolves inside the DEFINER body — that is the only way to measure what the product actually returns. It runs from an operator shell that already holds the DSN, so it grants nothing the caller did not already have. ⛔ The idiom is copied from `dependencies.py:145-155`; it must never be re-derived. |
| T-241-04 | Denial of service | The exact arm's forced sequential scan over a large corpus | mitigate | The planner GUCs are set with `SET LOCAL` inside the measuring transaction only, so they revert at COMMIT and cannot leak to another connection. Bound the Layer-1 query-vector sample (`--query-vectors`) and state the measured wall time in the report so a full-scale run is sized, not discovered. |
| T-241-05 | Information disclosure | Chunk `content` in the JSON report | mitigate | The report stores chunk **ids**, document **ids** and filenames — never `content`. Recall is computed on id sets; no corpus text needs to leave the database. |
| T-241-06 | Repudiation | A number quoted with no provenance | mitigate | Every report carries the label, the ISO timestamp, the server's pgvector and PostgreSQL versions, the live `hnsw.*` values, the corpus counts and the sample seed. A number without its configuration is the anecdote this phase exists to replace. |
| T-241-SC | Tampering | npm/pip/cargo installs | mitigate | **No package is installed by this plan.** `asyncpg`, `psycopg2-binary` and the app's own modules are already declared dependencies (ROADMAP: ⛔ no new Python package). If any task believes it needs one, it STOPS and reports rather than installing — a legitimacy checkpoint is required first and none is authorised here. |
