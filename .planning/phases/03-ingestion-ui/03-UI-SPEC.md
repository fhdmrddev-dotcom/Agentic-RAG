## Layout

The IngestionPage currently renders a centered single-column layout (`max-w-3xl mx-auto`). Phase 3 splits this into a **two-panel layout**:

| Panel | Width | Content |
|-------|-------|---------|
| Left: Folder Tree | 260px fixed | Folder hierarchy with CRUD controls |
| Right: Document Panel | flex-1 | Upload target area + document list filtered to selected folder |

The two panels sit inside the existing `flex flex-col h-full overflow-y-auto p-8` page shell. The split itself uses `flex flex-row gap-6` replacing the current `space-y-8` column. Both panels are independently scrollable via `overflow-y-auto`.

**Source:** Inferred from requirements UI-01–UI-04, roadmap Phase 3 goal. Layout follows existing `w-64 border-r bg-sidebar` sidebar pattern from `Sidebar.tsx`.

## Spacing Scale

Standard 8-point scale. Project already uses Tailwind spacing which maps 1 unit = 4px.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (p-1) | Icon-only button padding, tree indent per depth level |
| sm | 8px (p-2) | Tree node row padding (py-2 px-2) |
| md | 16px (p-4) | Panel inner padding, table cell padding |
| lg | 24px (p-6) | Panel header bottom margin |
| xl | 32px (p-8) | Page outer padding (existing) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

**Exception:** Tree indent step per nesting depth = 12px (pl-3 per level). This is sub-8 but matches the tight sidebar tree aesthetic established in `Sidebar.tsx` (uses `px-3 py-2`).

**Exception:** Touch targets for tree row action buttons (rename, delete icons) = 28px height minimum (h-7 w-7) matching the existing `DocumentList.tsx` delete button pattern.

## Color

CSS variable tokens from `src/index.css`. Light mode values:

| Role | CSS Variable | HSL (light) | Usage |
|------|-------------|-------------|-------|
| Dominant (60%) | `--background` | `0 0% 100%` (white) | Page background, document panel background |
| Secondary (30%) | `--sidebar` | `220 14% 96%` (light blue-gray) | Folder tree panel background, table header `bg-muted/50` |
| Accent (10%) | `--accent` / `--primary` | accent: `210 40% 96.1%`, primary: `222.2 47.4% 11.2%` | See accent list below |
| Destructive | `--destructive` | `0 84.2% 60.2%` (red) | Delete folder confirmation, delete document button hover |

**Accent reserved for (explicit list):**
1. Selected folder node background (`bg-accent`)
2. Folder node hover state (`hover:bg-accent`)
3. "Add subfolder" and "Upload here" primary action button (`bg-primary text-primary-foreground`)
4. Ingestion status spinner border (`border-primary`)
5. Document topic pill background (`bg-primary/10 text-primary`)

**Global vs. per-user folder distinction (UI-02):**
- Global folders: render a `Globe` lucide icon (16px) alongside the folder icon, tinted `text-muted-foreground`
- Per-user folders: render standard `Folder` lucide icon only
- No color change on the node itself — icon is the sole differentiator (avoids color overload)

**Source:** `index.css` CSS variables, `DocumentList.tsx` topic pill pattern, `Sidebar.tsx` hover/selected pattern.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — upload | **"Upload to [Folder Name]"** (dynamic; falls back to "Upload to Root" when no folder selected) |
| Primary CTA — create folder | **"New Folder"** |
| Folder tree panel heading | **"Folders"** |
| Empty state — no folders | Heading: "No folders yet" / Body: "Create a folder to organize your documents." |
| Empty state — no documents in folder | Heading: "No documents in this folder" / Body: "Upload files above to add them here." |
| Empty state — root with no documents | (existing) "No documents uploaded yet." |
| Error state — folder create failed | "Could not create folder. Check your connection and try again." |
| Error state — folder rename failed | "Could not save name. Check your connection and try again." |
| Error state — folder delete failed | "Could not delete folder. Try again or refresh the page." |
| Error state — upload failed (existing) | (existing error pattern in DocumentUpload — unchanged) |
| Destructive: delete folder | Confirmation inline below the tree node (not modal): "Delete [Folder Name] and all its contents? This cannot be undone." with **"Delete"** (destructive) and **"Cancel"** buttons |
| Destructive: delete document | No confirmation dialog — icon button tap triggers delete immediately (matches existing pattern in `DocumentList.tsx`) |
| Rename folder | Inline edit: click pencil icon → folder name becomes an `<input>` inline, commit on Enter/blur, cancel on Escape |

**Source:** REQUIREMENTS.md UI-01–UI-04, roadmap Phase 3 success criteria, inferred from existing `Sidebar.tsx` rename pattern (same inline-edit UX).

## Interaction Contract

### Folder Tree (UI-01, UI-02, UI-03)

| Interaction | Trigger | Behavior |
|-------------|---------|---------|
| Select folder | Click node label | Highlights node (bg-accent), filters document list to that folder, sets upload target |
| Deselect (root) | Click "Root" node at top | Clears folder selection, shows all documents, upload targets root |
| Expand/collapse | Click chevron icon | Toggles children visibility. Starts collapsed for depth > 1 |
| Create folder | Click "+" button in tree header or context action | Opens inline `<input>` appended as child of selected node (or root if none selected) |
| Rename folder | Click pencil icon on hover | Inline edit (same pattern as Sidebar thread rename) |
| Delete folder | Click trash icon on hover | Show inline confirmation row below node before executing |
| Real-time sync (UI-05 roadmap) | Supabase Realtime subscription | Tree re-renders on remote changes without page reload |

### Upload Panel (UI-04)

| Interaction | Trigger | Behavior |
|-------------|---------|---------|
| Upload files | Drop or click in drop zone | Calls upload with `folder_id` of selected folder (null = root) |
| Upload feedback | During upload | Existing spinner + "Uploading N files…" label (unchanged) |
| Post-upload feedback | After upload | Existing "N uploaded · N already up to date" label (unchanged) |

### Folder CRUD — State Transitions

```
Idle → [click +] → Inline input (name entry) → [Enter] → API call → Success: node appears → Idle
                                                           → [Escape] → Idle
                                                           → API error → Inline error message → Idle

Idle → [click pencil] → Inline input (name edit) → [Enter/blur] → API call → Success: name updates → Idle
                                                                  → [Escape] → Idle

Idle → [click trash] → Inline confirmation row → [click Delete] → API call → Success: node removed → Idle
                                                                 → [click Cancel] → Idle
```
