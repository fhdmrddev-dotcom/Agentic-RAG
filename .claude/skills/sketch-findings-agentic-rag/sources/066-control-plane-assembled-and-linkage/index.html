Consistency rules (the whole-surface guards)

  • One receipt vocabulary (062-A). Every write → a ✎ row in Activity + Audit and a "every action recorded" band flash. No per-surface bespoke confirmation styling.
  • Graded action guards — by shape, consistently. Target-specific destructive actions use a confirm sheet that names the target (Kill run #12). Global state switches use inline arm-to-confirm (Maintenance #14). Reversible per-user capability switches (#13) flip directly. Same rule everywhere a future action of that shape appears.
  • Consequence ≠ receipt. Maintenance ON raises a persistent present-tense banner ("read-only right now") that is distinct from the past-tense ledger receipt ("Turned ON maintenance mode"). Two truths, two elements.
  • Plain-language default, ⌥ technical reveal (#10). Every technical term (parameter names, action codes) is plain by default; the reveal is Control-Room-wide and display-only. Extends the Phase-124 two-door pattern; ratified app-wide in Phase 154.
  • Honest locks. Future tabs stay visible, dimmed, with a calm refusal naming the arriving phase — never hidden, never a broken 404 inside the shell.
  • Non-discoverable (146 red line). The whole surface is probe-gated: a non-operator can't see the shield and gets a 404 on every /admin route. Enforced in application code (no RLS backstop on the service-role client).
  • Read-only monitoring, not surveillance. The operator sees others' run metadata (user / model / elapsed / current tool) but cannot open another user's thread contents from here. "Sign in as user" / thread inspection is a Phase-148 named-trigger decision, not implied by Kill.

Open IA decision → discuss-phase 147

Does "Overview" survive, or become "Control Plane"?

Phase 146 shipped an Overview tab (health posture + a controls preview + ledger) alongside a locked Control Plane slot. At 147 the live surface holds all of that plus active runs + real controls. Keeping both would split health across two tabs.

Recommendation: promote — the 146 "Overview" tab becomes the live "Control Plane" (one landing, no duplication); the 061-B locked slot is fulfilled by promotion, not by a parallel tab. Designed that way here.

Alternative (if kept): "Overview" stays a thin home (welcome + top-line posture + shortcuts) and "Control Plane" is the cockpit — accept some health duplication. Ratify at discuss-phase as D-147-IA.
