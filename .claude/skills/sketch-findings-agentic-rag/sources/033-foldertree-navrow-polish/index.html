One row, two peers

Folders and Views are built from the same row — both show a count, both have a reachable menu. The only differences: the icon (folder vs funnel) and which actions appear.

What changed

  • ✓ Every row shows a count — folders too, not just Views. No more guessing how much is in a folder.
  • ✓ Views are flat — a saved filter never nests, so it never inherits the tree's indentation.
  • ✓ One soft indent guide replaces the hand-drawn branch lines that read as noise.
  • ✓ The “G” has a tooltip — hover it: “Global — shared with everyone.” Same labeled pill on global Views.
  • ✓ Actions are always faintly visible and keyboard-reachable — not hidden until hover.
  • ✓ A small filter box appears once you have many folders/views.

Folders

The problems (verified in code)

  • ✗ No count on subfolders — only “Root” shows one; you can't tell what's inside.
  • ✗ Unbounded nesting — 16px per level with no cap; deep folders truncate the name to nothing.
  • ✗ Dense hand-drawn guide lines — two 1px branch lines per child read as visual noise.
  • ✗ Tiny hover-only actions — ~24px, invisible until hover, unreachable by touch/keyboard.
  • ✗ Opaque “G” pill — a bare letter with no explanation.
  • ✗ Adding a “Views” group as-is would clone every one of these flaws and look inconsistent beside Folders.

Capped indent + path

Beyond ~3 levels, stop indenting and show the remaining path inline, so a deep folder never crushes its own name. Selecting a deep folder still shows a breadcrumb above the list.
⌕
Folders
Views

The over-nesting answer

  • ✓ Indent caps at level 3; deeper folders align there with a small path prefix (e.g. …/Q1/).
  • ✓ The existing breadcrumb carries deep location, so the tree stays shallow and scannable.
  • ✓ Everything else is the same unified NavRow from variant A.
  • Trade-off: a tiny bit less literal hierarchy on screen, in exchange for never truncating names.
