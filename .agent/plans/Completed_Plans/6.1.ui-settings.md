## Complexity: ⚠️ Medium

## Overview

Module 6.1 makes the Settings page fully interactive. Users can:
1. **Add LLM provider profiles** (OpenRouter, OpenAI, Ollama, custom) — each with base URL, API key, and a list of models
2. **Set the active provider** — drives which models appear in the chat model dropdown
3. **Configure embedding** — model, base URL, API key, dimensions (with re-ingestion warning)
4. **Configure reranking** — enable/disable, provider (API/local), model, API key, top-N
5. **Configure retrieval** — top-K, match threshold, hybrid on/off, weights, candidate count

The backend services (LLM, embedding, reranking, retrieval) all read from user settings at request time instead of global env. Env vars remain the fallback default for any unset user preference.

## Architecture

### LLM Provider storage
Stored as a JSONB array in `user_settings.llm_providers`:
```json
[
  {
    "id": "uuid-v4",
    "name": "OpenRouter",
    "base_url": "https://openrouter.ai/api/v1",
    "api_key": "sk-or-...",
    "models": ["openai/gpt-4o", "anthropic/claude-3.5-sonnet"],
    "is_active": true
  },
  {
    "id": "uuid-v4",
    "name": "Ollama (local)",
    "base_url": "http://localhost:11434/v1",
    "api_key": "ollama",
    "models": ["llama3.1", "mistral"],
    "is_active": false
  }
]
```
Only one provider has `is_active: true` at a time. Switching active provider updates all models in the chat dropdown.

### Per-request effective settings
A `UserEffectiveSettings` Pydantic model merges user DB settings with env defaults. Built once per request in the chat endpoint, passed through to all services.

```python
class UserEffectiveSettings(BaseModel):
    # LLM
    llm_api_key: str
    llm_base_url: str
    llm_model: str
    available_models: list[str]
    # Embedding
    embedding_api_key: str
    embedding_base_url: str
    embedding_model: str
    embedding_dimensions: int
    # Reranking
    rerank_enabled: bool
    rerank_provider: str
    rerank_api_key: str
    rerank_model: str
    rerank_top_n: int
    # Retrieval
    retrieval_top_k: int
    retrieval_match_threshold: float
    hybrid_search_enabled: bool
    hybrid_candidate_count: int
    vector_search_weight: float
    keyword_search_weight: float
    rrf_k: int
```

Merge logic: `user_value if user_value is not None else env_default`

### API key masking
API keys are masked in GET responses: `sk-or-abc123...xyz` → `sk-or-...xyz` (last 4 chars visible). Full key is only sent to backend on save. Frontend never re-displays a saved key in full.

### Task 2: Backend — UserEffectiveSettings model + settings loader

**File:** `backend/app/models/user_settings.py` (new)

- `LLMProvider` model: `id, name, base_url, api_key, models: list[str], is_active: bool`
- `UserEffectiveSettings` model (all fields above)
- `load_user_settings(user_id, supabase) -> UserEffectiveSettings` function:
  - Fetches `user_settings` row for user
  - Merges each field: user value if not None, else env default

  - Returns fully resolved `UserEffectiveSettings`

### Task 3: Backend — Extend settings.py API

**File:** `backend/app/api/settings.py`

New endpoints:

```
GET  /settings                  → full settings response (all sections, keys masked)
PUT  /settings/providers        → upsert a provider (add or update by id)
DELETE /settings/providers/{id} → remove a provider
PATCH /settings/providers/{id}/activate → set as active provider
PUT  /settings/embedding        → update embedding config
PUT  /settings/reranking        → update reranking config
PUT  /settings/retrieval        → update retrieval config
```

**GET /settings response** (`FullSettingsResponse`):
```python
class FullSettingsResponse(BaseModel):
    llm_providers: list[LLMProviderResponse]   # api_key masked
    # active provider details (derived)
    llm_model: str
    available_models: list[str]
    # embedding
    embedding_model: str
    embedding_model_locked: bool
    embedding_base_url: str
    embedding_dimensions: int
    embedding_has_api_key: bool                # bool only, never send key back
    # reranking
    rerank_enabled: bool
    rerank_provider: str
    rerank_model: str
    rerank_top_n: int
    rerank_has_api_key: bool                   # bool only
    # retrieval
    retrieval_top_k: int
    retrieval_match_threshold: float
    hybrid_search_enabled: bool
    hybrid_candidate_count: int
    vector_search_weight: float
    keyword_search_weight: float
    rrf_k: int
```

**API key handling:** Keys are write-only — GET responses never include raw keys. Use `has_api_key: bool` flag instead. On PUT, if the user sends an empty string `""`, keep the existing key (no-op). Only replace if a non-empty value is provided.

**Validation:** Backend starts without errors. GET /settings returns defaults. PUT provider round-trips.

### Task 4: Backend — Propagate user settings through services

Make services accept `UserEffectiveSettings` instead of reading from global `settings`.

**File:** `backend/app/services/openai_service.py`
- `get_llm_client(user_settings: UserEffectiveSettings | None = None)` — if provided, use user's api_key/base_url; else fall back to env
- `embed_texts(texts, user_settings: UserEffectiveSettings | None = None)` — same pattern

**File:** `backend/app/services/retrieval_service.py`
- `search_documents(..., user_settings: UserEffectiveSettings | None = None)` — use user settings for hybrid/retrieval config; fall back to global settings if None

**File:** `backend/app/services/rerank_service.py`
- `rerank(..., user_settings: UserEffectiveSettings | None = None)` — use user's rerank config; fall back to global settings if None

**File:** `backend/app/api/threads.py`
- At top of `event_stream()`: call `load_user_settings(user_id, supabase)` → get `UserEffectiveSettings`
- Pass to `get_llm_client()`, `embed_texts()`, `search_documents()`, `rerank()`
- Model title generation also uses user's LLM client

**Validation:** Change a setting via API → next chat request uses the new setting (visible in LangSmith trace).

## Security Notes

- API keys stored in Supabase `user_settings` — protected by RLS (users only see their own row)
- Keys never returned in GET responses — `has_api_key: bool` flag only
- Empty string on PUT = keep existing key (no accidental key deletion)
- All settings endpoints require auth via `get_current_user` dependency

## Open Decisions (deferred)

- **Admin vs per-user settings**: Currently all per-user. Admin role and global overrides deferred to a future module.
- **Encryption at rest for API keys**: Supabase RLS provides row-level isolation; column-level encryption is a future hardening step.
- **`resize_embedding_column` automation**: Currently manual. UI shows the SQL to run; automating it requires a DB-level function call from backend which has side effects — keep manual for now.
