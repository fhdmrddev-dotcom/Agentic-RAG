# Module 2: BYO Retrieval + Memory

🔴 **Complex** — Full-stack architectural replacement + new ingestion pipeline. Execute task groups in order; do not attempt all in one pass.

---

## Context

Module 1 used OpenAI's Responses API (stateful, managed memory, managed file_search). Module 2 replaces this with the Chat Completions API so the app is provider-agnostic and we own the full retrieval stack. The goal is for OpenAI, OpenRouter, Ollama, and LM Studio to all work via env config alone — no code changes to switch providers.

---

## Provider Abstraction Design

**Key insight:** OpenRouter, Ollama, and LM Studio all expose an OpenAI-compatible Chat Completions API. The OpenAI Python SDK accepts `api_key` + `base_url` at construction time — one client pattern covers all providers.

### Two clients from config

| Config var | OpenAI | OpenRouter | Ollama | LM Studio |
|---|---|---|---|---|
| `LLM_BASE_URL` | *(empty)* | `https://openrouter.ai/api/v1` | `http://localhost:11434/v1` | `http://localhost:1234/v1` |
| `LLM_API_KEY` | `sk-...` | `sk-or-...` | `ollama` | `lmstudio` |
| `LLM_MODEL` | `gpt-4o` | `anthropic/claude-3.5-sonnet` | `llama3.2` | `llama-3.2-3b-instruct` |
| `EMBEDDING_BASE_URL` | *(empty)* | *(usually empty — stay on OpenAI)* | `http://localhost:11434/v1` | *(usually empty)* |
| `EMBEDDING_API_KEY` | `sk-...` | *(falls back to LLM key)* | `ollama` | *(falls back to LLM key)* |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | — | `nomic-embed-text` | — |

**Client factory pattern** in `openai_service.py`:
```python
def get_llm_client() -> OpenAI:
    kwargs = {"api_key": settings.llm_api_key}
    if settings.llm_base_url:
        kwargs["base_url"] = settings.llm_base_url
    return OpenAI(**kwargs)

def get_embedding_client() -> OpenAI:
    api_key = settings.embedding_api_key or settings.llm_api_key
    kwargs = {"api_key": api_key}
    if settings.embedding_base_url:
        kwargs["base_url"] = settings.embedding_base_url
    return OpenAI(**kwargs)
```

No provider-specific branching anywhere in service logic. Provider selection is purely config.

## Architecture Changes (Module 1 → 2)

| Aspect | Module 1 (Responses API) | Module 2 (Chat Completions) |
|---|---|---|
| Memory | OpenAI manages via `previous_response_id` | App loads full history from Supabase, sends on every request |
| Retrieval | OpenAI `file_search` (black box) | Custom pgvector search via tool calling |
| Vector store | OpenAI-hosted | `document_chunks` table with HNSW index |
| Streaming events | `response.output_text.delta` | `choices[0].delta.content` |
| Provider lock | OpenAI only | Any OpenAI-compatible endpoint |

**Option A chosen** (per PRD video): Remove all Responses API code. No dual-mode support.

## Database Schema Changes

New migration: `backend/supabase/migrations/002_module2_byo_retrieval.sql`

```sql
-- Remove Responses API column
ALTER TABLE public.threads DROP COLUMN IF EXISTS openai_thread_id;

-- Documents table (file metadata)
CREATE TABLE public.documents (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  filename text NOT NULL,
  file_path text NOT NULL,           -- Supabase Storage path
  file_size integer NOT NULL,
  mime_type text NOT NULL,
  status text NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'processing', 'completed', 'failed')),
  error_message text,
  chunk_count integer,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

-- document_chunks table (embedded text segments)
CREATE TABLE public.document_chunks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id uuid NOT NULL REFERENCES public.documents(id) ON DELETE CASCADE,
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  content text NOT NULL,
  chunk_index integer NOT NULL,
  embedding vector(1536),            -- text-embedding-3-small dimension
  created_at timestamptz NOT NULL DEFAULT now()
);

-- HNSW index for cosine similarity search
CREATE INDEX document_chunks_embedding_idx ON public.document_chunks
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);

-- RLS policies on both tables (select/insert/update/delete)
-- match_document_chunks RPC function (pgvector cosine search, see below)
-- Enable Realtime: ALTER PUBLICATION supabase_realtime ADD TABLE public.documents;
```

Retrieval RPC function:
```sql
CREATE OR REPLACE FUNCTION match_document_chunks(
  query_embedding vector(1536),
  match_user_id uuid,
  match_count integer DEFAULT 5,
  match_threshold float DEFAULT 0.3
)
RETURNS TABLE (id uuid, document_id uuid, content text, similarity float)
LANGUAGE plpgsql SECURITY DEFINER AS $$
BEGIN
  RETURN QUERY
  SELECT dc.id, dc.document_id, dc.content,
         1 - (dc.embedding <=> query_embedding) as similarity
  FROM document_chunks dc
  WHERE dc.user_id = match_user_id
    AND 1 - (dc.embedding <=> query_embedding) > match_threshold
  ORDER BY dc.embedding <=> query_embedding
  LIMIT match_count;
END;
$$;
```

### Phase 4 — Documents API + Threads Refactor *(parallel within phase, depends on Phase 3)*

**4.1 — Documents API** *(needs 1.1 schema + 3.1 embedding + 1.4 model)*
- Create `backend/app/api/documents.py`
- `POST /documents/upload` (multipart): validate mime type (text/plain, text/markdown, text/html), decode as UTF-8, insert document row (`status='pending'`), upload file to Supabase Storage bucket `documents` at path `{user_id}/{document_id}/{filename}`, kick off `BackgroundTasks` ingestion, return `DocumentResponse` immediately
- `GET /documents`: list user's documents ordered by `created_at desc`
- `DELETE /documents/{id}`: verify ownership, delete row (cascades to chunks), delete from Storage
- Background function `ingest_document(document_id, text, user_id)`:
  1. Update status → `'processing'`
  2. `chunk_text()` the content
  3. `embed_chunks()` all chunks
  4. Bulk insert to `document_chunks`
  5. Update status → `'completed'`, set `chunk_count`
  6. On exception: status → `'failed'`, set `error_message`
- ✅ Verify: Upload a `.txt` file — response is immediate with `status:'pending'`, then transitions to `completed`. `document_chunks` rows exist with non-null embeddings.

**4.2 — Threads API: stateless history + tool calling** *(parallel with 4.1, needs 2.1 + 2.2 + 3.2)*
- Modify `backend/app/api/threads.py`:
  - Remove all `openai_thread_id` logic from thread insert and update
  - In `send_message`: load full message history from Supabase ordered by `created_at`, build `messages` array with system prompt prepended, append new user message
  - Call `create_streaming_chat(messages)` — stream deltas as SSE `{"type":"delta","content":"..."}`
  - Detect `finish_reason == "tool_calls"`: accumulate streamed tool call arguments (streamed in pieces), run `retrieval_service.search_documents()`, append tool result message, make second streaming call with `tool_choice="none"` to prevent recursion
  - Insert assistant message to Supabase on completion
- System prompt guides model to use `search_documents` tool when answering from documents
- ✅ Verify: Send a chat message — response streams correctly. Both user + assistant messages appear in Supabase. LangSmith trace shows the call.
