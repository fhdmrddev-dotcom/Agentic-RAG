# Module 1: App Shell + Observability

**Complexity: 🔴 Complex** — Multiple integrated systems (Supabase, OpenAI Responses API, SSE streaming, LangSmith), greenfield scaffold. Execute in sequential phases.

## Context

Module 1 establishes the foundation: authentication, chat UI, and a "managed RAG" integration using OpenAI's Responses API (which handles threads, memory, and file search as a black box). LangSmith observability is wired in from day one. The entire backend will be rebuilt in Module 2 — Module 1 is intentionally simple, teaching RAG concepts before diving into custom retrieval.

## Key Design Decisions

**Auth flow:** Frontend authenticates via Supabase Auth directly → gets JWT → passes as `Authorization: Bearer <token>` to FastAPI → backend calls `supabase.auth.get_user(token)` to verify.

**OpenAI Responses API threading:** Uses `previous_response_id` to chain turns. The `threads` table stores the latest `response.id` (updated after each turn). A separate `messages` table stores message content in Supabase so history survives page refresh (important since Module 2 replaces the Responses API entirely).

**SSE streaming:** Uses `fetch` + `ReadableStream` (not `EventSource`) because the endpoint is POST. A `streamMessage()` utility in `api.ts` handles parsing and exposes `onDelta` / `onDone` callbacks.

**LangSmith:** The `@traceable` decorator from the `langsmith` SDK wraps OpenAI calls. No LangChain required — just set `LANGSMITH_TRACING=true`.

## Phase 0: Infrastructure & Scaffold

### Task 0.1 — Supabase Schema
**Files:** `backend/supabase/migrations/001_initial_schema.sql`

Tables:
- `profiles` — extends `auth.users` (id, display_name, avatar_url, timestamps). Auto-created on signup via trigger.
- `threads` — (id, user_id, openai_thread_id, title, timestamps). `openai_thread_id` starts empty, updated to latest response ID after first message.
- `messages` — (id, thread_id, user_id, role, content, timestamps). Stores all messages locally for history retrieval.

RLS policies on all three tables: users can only SELECT/INSERT/UPDATE/DELETE their own rows (`auth.uid() = user_id` or `auth.uid() = id`).

**Validation:** Supabase Table Editor shows all 3 tables with RLS enabled. Policies tab shows correct policies for each.

### Task 2.2 — OpenAI Service with LangSmith
**File:** `backend/app/services/openai_service.py`

```python
from langsmith import traceable

@traceable(name="openai-responses-chat", run_type="llm")
def create_streaming_response(message: str, previous_response_id: str | None, vector_store_id: str):
    kwargs = {
        "model": "gpt-4o",
        "input": message,
        "store": True,
        "stream": True,
    }
    if vector_store_id:
        kwargs["tools"] = [{"type": "file_search", "vector_store_ids": [vector_store_id]}]
    if previous_response_id:
        kwargs["previous_response_id"] = previous_response_id
    return client.responses.create(**kwargs)
```

**Validation:** `backend/scripts/test_openai.py` — calls `create_streaming_response("Hello", None, "")`, prints streamed events. Check LangSmith dashboard for trace.

### Task 2.3 — Threads & Messages Router
**File:** `backend/app/api/threads.py`

Endpoints:
- `GET /threads` — list user's threads, ordered by `updated_at desc`
- `POST /threads` — create thread in DB (no OpenAI call yet; `openai_thread_id` = `""`)
- `GET /threads/{thread_id}/messages` — return messages from the local `messages` table
- `POST /threads/{thread_id}/messages` — send message, stream SSE response

SSE generator for `POST /threads/{thread_id}/messages`:
1. Insert user message into `messages` table
2. Fetch thread's current `openai_thread_id` (use as `previous_response_id`, or `None` if first message)
3. Call `create_streaming_response(...)`
4. Yield `data: {"type": "delta", "content": "..."}` for each `response.output_text.delta` event
5. On `response.completed`: update `threads.openai_thread_id = new_response.id`; insert assistant message into `messages` table
6. Yield `data: [DONE]`

Return `StreamingResponse(..., media_type="text/event-stream")`.

**Validation:** `curl -X POST http://localhost:8000/threads -H "Authorization: Bearer <jwt>" -d '{}'` → returns thread JSON with UUID.

## Phase 3: Chat UI (Frontend)

### Task 3.1 — API Client & SSE Utility
**File:** `frontend/src/lib/api.ts`

`getAuthHeaders()` — always calls `supabase.auth.getSession()` to get fresh token (handles auto-refresh).

`streamMessage(threadId, content, onDelta, onDone)` — uses `fetch` + `ReadableStream` to parse SSE from POST endpoint. Parses `data:` lines, calls `onDelta(text)` and `onDone(responseId)`.

REST methods: `listThreads()`, `createThread(title?)`, `getMessages(threadId)`.

1. Append optimistic user message to local state
