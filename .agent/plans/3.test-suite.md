# Plan: Test Suite

⚠️ **Medium** - Covers multiple layers (unit, integration, frontend, E2E). Each layer is straightforward but total scope is large.

---

## Overview

Implement a comprehensive test suite covering backend unit tests, backend integration tests, frontend unit tests, and Playwright E2E tests. All external dependencies (Supabase, OpenAI) are mocked in unit/integration tests. E2E tests require live services.

## Task Breakdown

### 1. Backend Fixtures (`conftest.py`)
- Create pytest fixtures for TestClient, mock user, auth headers
- Override `get_current_user` and `get_supabase` dependencies
- Mock supabase supports method chaining via MagicMock

**Validation:** `pytest backend/tests/ --collect-only` finds all test functions

### 2. Unit: `test_embedding_service.py`
- `chunk_text("")` → `[]`
- `chunk_text("short")` → `["short"]`
- Long text exceeding `chunk_size` → multiple chunks returned
- Overlap: consecutive chunks share characters
- Sentence boundary: chunk ends at `.` within overlap window

**Validation:** All 5+ tests pass with `pytest backend/tests/unit/test_embedding_service.py`

### 3. Unit: `test_retrieval_service.py`
- Mock `embed_texts` to return `[[0.1, 0.2, ...]]`
- Mock supabase RPC to return chunk rows
- Mock documents table `.select().in_()` to return doc rows
- Assert formatted return structure matches expected

**Validation:** All tests pass without touching real Supabase

### 4. Unit: `test_openai_service.py`
- Mock `settings` to control `llm_base_url`, `embedding_api_key`
- Assert `get_llm_client()` creates OpenAI with/without base_url
- Assert `get_embedding_client()` falls back to `llm_api_key`

**Validation:** All tests pass with mocked settings

### 5. Integration: `test_health.py`
- GET /health → 200 `{"status": "ok"}`
- GET /models → 200, keys `models` and `default` present
- No auth required for either

**Validation:** Both tests pass

### 6. Integration: `test_threads.py`
- 401 on unauthenticated requests
- Mocked supabase returns correct data shapes
- POST /threads uses "New Chat" default title
- SSE stream yields `data: {...}\n\n` lines ending with `data: [DONE]`

**Validation:** All 9+ tests pass

### 7. Integration: `test_documents.py`
- 401 on unauthenticated requests
- Upload valid TXT returns 201 with `status: "pending"`
- Upload empty file → 422
- Upload invalid MIME → 422
- Delete returns 204

**Validation:** All 8+ tests pass

### 8. Frontend: `api.test.ts`
- `vi.stubGlobal('fetch', vi.fn())` pattern
- Assert each API function calls the correct URL/method

**Validation:** `npm test` in `frontend/` passes

### 9. Frontend: `useDocuments.test.ts`
- Mock `@/lib/api` and `@/lib/supabase`
- renderHook + waitFor pattern

**Validation:** All hook state transition tests pass

### 10. Frontend: Component tests
- `DocumentStatusBadge`: renders correct text for all 4 statuses
- `MessageItem`: user = justify-end, assistant = justify-start, content visible

**Validation:** All component tests pass

### 11. E2E: Playwright setup
- `playwright.config.ts` targeting localhost:5173
- 4 spec files with `test.describe` grouping
- Tests skip gracefully when live services unavailable

**Validation:** `npx playwright test --list` enumerates all tests

## Acceptance Criteria

**Backend Unit Tests PASS when:**
- `chunk_text` handles empty, short, long, overlap, sentence-boundary inputs
- `search_documents` calls embed_texts and supabase RPC with correct args
- Client factory respects `llm_base_url` and `embedding_api_key` settings

**Backend Integration Tests PASS when:**
- All endpoints return correct HTTP status codes
- Unauthenticated requests return 401
- CRUD responses match Pydantic model schemas
- SSE stream contains parseable `data: {...}` lines and `data: [DONE]`

**Frontend Unit Tests PASS when:**
- API functions call correct endpoints with correct HTTP methods
- Components render correct output for all prop variants
- Hook state transitions are correct

**E2E Tests PASS when (with live services):**
- Auth flow: sign in / sign out works
- Thread creation and message streaming works
- Document upload status transitions work
- RAG retrieval returns document-grounded responses
