# v1.0 — Knowledge Base Explorer

> **Shipped:** 2026-03-29 · **Phases:** 1–8 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v1.0 gave Syrel a real folder system for documents and taught the AI agent to explore that library the way a developer explores a codebase: list, tree, grep, glob and read.

## Why this milestone existed

Before v1.0, Syrel's knowledge base was a flat pile of uploaded files that the agent could reach only through similarity search. The milestone's stated core value was: *"The agent can explore the knowledge base the same way Claude Code explores codebases."* Two things were missing for that:

- **Structure.** Users had no way to organise documents into nested folders, and nothing let one person's folders be shared with everyone else.
- **Deterministic navigation.** Vector search finds passages that *sound* related. It cannot answer "what is in the /reports folder?", "which files mention invoice 4471?" or "show me lines 10–30 of that contract". Filesystem-style tools can.

The plan was to build the folder foundation first, then the tools, then a dedicated "Explorer" agent mode that uses only those tools.

## What shipped

- **Nested folders.** Users can create folders at any depth, rename them, move them, and delete them. Deleting a folder also deletes everything inside it.
- **Global and private folders.** A folder can be private (only its owner sees it) or global (every signed-in user sees it). Documents inside a global folder are readable by everyone.
- **Folder-targeted uploads.** Uploading a file while a folder is selected puts the document in that folder. Files and whole folders can be moved later.
- **Full document text stored.** Every ingested document keeps its full extracted markdown alongside its search chunks, so it can be grepped and read line by line.
- **Folder tree in the ingestion page.** A two-panel layout with the folder tree on the left (global folders visually distinct), inline create/rename/delete, and the document list on the right.
- **Folder info bar.** Selecting a folder shows document count, total size, a global badge, subfolder count and creation date.
- **Five knowledge-base tools for the agent.** `ls`, `tree` (with depth limits and truncation markers), `grep` (regex over document text), `glob` (filename patterns including `**`) and `read` (whole document or a line range, with line numbers).
- **Explorer mode.** A General/Explorer selector in the chat toolbar. Explorer mode gives the agent only the knowledge-base tools plus the existing document-analysis sub-agent, and tells it to answer in synthesised prose rather than raw tool output.
- **Folder-scoped chats.** A new chat can be scoped to one folder. Search then covers that folder and all of its subfolders, and the scope shows as a badge in the sidebar and chat header.

## How it works

**Data model.** A `folders` table uses an adjacency list (`id`, `user_id`, `name`, `parent_id`, `is_global`, timestamps), with cascade deletes and Row-Level Security. The `documents` table gained a nullable `folder_id` and a nullable `full_markdown` column. Existing documents stayed at the root with no stored markdown until they were re-ingested. Chat threads gained a `folder_id` for scoping.

**Migrations.** The phase records cite `013_folders.sql`, `014_document_folder_integration.sql`, `015_global_folder_document_rls.sql` and `016_thread_folder_scope.sql`. Those were written under the legacy `backend/supabase/migrations/` folder, now `backend/supabase/migrations.archive/`. In today's canonical sequence, the files are `supabase/migrations/014_folders.sql`, `015_global_folder_document_rls.sql` and `016_thread_folder_scope.sql`. `documents.full_markdown` was later back-ported in `supabase/migrations/029_storage_buckets.sql`, whose header says it was "added in backend/014 but never in supabase/migrations/".

**Visibility rules.** Migration 015 replaced the document SELECT policy so that a document is visible if the user owns it *or* it sits in a folder with `is_global = true`. Only the owner can toggle a folder's global flag. Anyone else gets HTTP 403.

**Tools.** Each tool was built as a FastAPI endpoint and as an OpenAI-style tool definition dispatched from `backend/app/api/threads.py`. Path resolution happens in memory over the user's visible folder set. `grep` runs a regex over `full_markdown`, `glob` matches filenames and folder paths, and `read` slices `full_markdown` by line. Every tool sees only global folders plus the caller's own private folders.

**Explorer mode.** `MessageCreate` gained `agent_mode` (`"default"` or `"explorer"`). In explorer mode, `send_message` swapped in `EXPLORER_SYSTEM_PROMPT` and `get_explorer_tools()`, which returns exactly `ls`, `tree`, `grep`, `glob`, `read_document` and `analyze_document`. It also raised the tool-loop limit from 5 to 8 iterations. Default mode was unchanged.

**Scoped retrieval.** When a thread has a `folder_id`, the backend resolves the folder's whole subtree with a recursive helper and passes `folder_ids` to the vector-search RPC. Migration 016 added the `d.folder_id = ANY(p_folder_ids)` filter. At this point keyword search was not scoped yet; v2.1 fixed that.

**Frontend.** `buildFolderTree`, the `useFolders` hook, and the `FolderNode`, `FolderTree` and `FolderCreateInput` components, plus the reworked ingestion page. `ToolCallPanel` gained a renderer for `read` results.

## Key decisions

- **Adjacency list for folders**, not a path string or nested sets. Folder hierarchy is resolved in application code.
- **Store full markdown, don't re-extract.** Grep and read work over a stored `full_markdown` column. Only extracted markdown is searchable; raw files are not.
- **Two visibility levels only.** Global (everyone) or private (owner). Team sharing and per-folder permissions were explicitly out of scope.
- **Explorer is a mode, not a separate agent service.** It reuses the main chat loop with a different prompt and tool list.
- **A thread's scope is fixed at creation.** v1.0 has no endpoint or UI to change a thread's folder afterwards.
- **No extractor switch.** The existing pypdf + python-docx pipeline was kept, and Docling was explicitly ruled out.

## Post-v1.0 Enhancements (2026-03-29)

Shipped alongside the v1.0 close. These were visual changes with no functional effect, plus one bug fix.

- **Aether Intelligence design system.** A full CSS-variable token set for dark and light mode, a Sun/Moon theme toggle backed by a `useTheme` hook (stored in localStorage, respects `prefers-color-scheme`, with a no-flash script in `index.html`), Inter and Manrope fonts, and `fadeSlideUp` / `pulseGlow` animations.
- **Restyled chat.** Glassmorphism chat input, gradient user bubbles, animated thinking dots, colour-coded tool-call icons and a gradient send button. The auth page got gradient orbs and a glass card.
- **Bug fix.** `maybe_single().execute()` in `folders.py` can return `None` when no row exists. The create and rename endpoints now guard against that instead of crashing with `AttributeError`.

## Gaps and deferred work

- **Deferred to "v2":** drag-and-drop folder ordering, folder templates, bulk move and copy, `head`/`tail` tools, content previews in `ls`, cached Explorer state, folder-tree search and keyboard navigation, and automatic import from a local folder.
- **Out of scope:** team-based sharing, per-folder permissions, real-time collaboration, and searching raw (unextracted) files.
- **Record inconsistencies in the archived roadmap.** The v1.0 progress table still shows Phase 7 as "1/2 — In Progress", but the v2.0 roadmap and the milestone record list it as complete (2026-03-22). The v1.0 requirements traceability table lists Phase 8's five requirements as "Not Started", while their checkboxes are ticked and `08-VERIFICATION.md` reads `passed` (11/11). Phases 3 and 7 have no VERIFICATION.md file.
- **Keyword search ignored folder scope.** Only vector search was scoped in Phase 8. v2.1 Phase 21 closed this.
