# v3.5 — UX Consolidation & Chat Polish

> **Shipped:** 2026-07-23 · **Phases:** 174–177 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

A short cleanup milestone that made Syrel's chat tell the truth about what a run is doing, stream
cleanly across newer reasoning models and non-OpenAI providers, render every message exactly once,
and gave the brand-new organisation screens one calm, consistent look.

## Why this milestone existed

By the end of v3.4 a backlog of user-reported chat bugs had piled up — empty bubbles after a cancel,
a "Response stopped" marker that vanished on reload, a dead "Setting up agent…" label while a model
was visibly reasoning, duplicate user bubbles, answers that only appeared after a page refresh, and
`execute_code` quietly failing to install libraries. Newer OpenAI reasoning models were also
returning request errors when tools were attached, and DeepSeek could leak raw tool-call markup into
the visible answer.

At the same time, v3.4 had just shipped a set of organisation surfaces (admin shell, switcher,
invitations, SSO) built quickly across three phases, each with its own chip colours and error
styles. The planning records describe v3.5 as a deliberately **medium cleanup milestone** — mostly
bug-fix and polish, no large new build — kept separate from the big visual Workflow Studio that
followed in v3.6.

## What shipped

- **Honest run states.** A run cancelled before any output shows "cancelled — no output yet" instead
  of an empty bubble; "Response stopped" survives navigation and a full reload; reasoning-heavy models
  show "Reasoning…" instead of "Setting up agent…"; workflow timers keep climbing after you navigate
  away and back, with exactly one avatar.
- **An honest "disabled by the administrator" message.** If an operator has switched workflows off,
  launching one shows an amber in-chat notice with the server's reason, and the composer stays usable.
- **Reasoning models with tools stop erroring.** gpt-5.6-class models were routed so that tool use
  no longer triggered a request error, and the specific provider error got its own plain, actionable
  message.
- **No DeepSeek markup leaks.** The existing DeepSeek sanitizer was hardened so trailing text is not
  lost, and if raw tool markup is still detected the user sees one honest error rather than garbage.
- **Real chat titles from reasoning models.** Title generation turns reasoning off where the provider
  supports it, so titles are real 4–6 word summaries; a stale cross-provider helper model no longer
  triggers a false "fallback" banner.
- **Each message renders once, and answers un-fold live.** No duplicate user bubble; a run finishing
  in a background thread shows its final answer without a reload.
- **No silent send-drops.** A submitted message either sends or shows a recoverable failure with
  the draft preserved.
- **Live skill version updates.** Approving a skill description proposal updates the Skill Studio
  header version and the "LIVE" badge immediately.
- **`execute_code` installs what it is asked to.** Declared libraries install into the same Python
  that runs the code, and a missing-module error triggers one bounded install-and-retry, with an
  honest `install_failed` note if that still fails.
- **One look for organisation screens.** Shared status chips, role badge and avatar, and one honest
  notice component across the org band, profile menu, members, invitations, SSO, the invite landing
  page and sign-in. Recoverable invite dead-ends became calm rather than alarming red.

## How it works

- **Run-state honesty (Phase 174)** is almost entirely frontend. The "Reasoning…" label is derived
  from the already-streamed `reasoningContent` on the message; stop/cancel affordances render from
  `message.runStatus`, which the reload path rebuilds from persisted `runs.status`; the kickoff
  placeholder carries a stable `startedAt`; and `frontend/src/lib/dedupMessages.ts`
  (`dedupMessagesByRunId`) collapses a double-mounted twin to one avatar. No backend change.
- **Cross-provider fidelity (Phase 175)** stays at the provider boundary. Two capability markers were
  added to `MODEL_CAPABILITIES` in `backend/app/config.py`: `reasoning_first` (models that reject
  tools + reasoning together on chat completions) and `reasoning_off` (how to disable reasoning for a
  given model). `resolve_calling_mode` in `backend/app/services/openai_service.py` routed
  `reasoning_first` models to structured (XML-injected) tool calling. A dedicated
  `reasoning_tools_unsupported` error kind lives in `backend/app/services/provider_gateway/errors.py`.
  `provider_safe_utility_model` (`backend/app/services/sub_agent_models.py`) drops a helper model that
  belongs to a different provider before title/suggestion calls.
- **Render correctness (Phase 176)** — two additive reconcile fixes in the streams provider (drop the
  optimistic row when the persisted one arrives; reconcile content at terminal for background runs),
  a `refreshVersions` refetch for the Skill Studio, and a stash-and-hint path when the send guard
  declines to dispatch.
- **`execute_code` reliability** lives entirely in `backend/app/services/tool_dispatcher.py`:
  `python -m pip` into the running interpreter, one retry, and a run-scoped auto-heal on
  `ModuleNotFoundError`, provider-uniform.
- **Org-surface polish (Phase 177)** extracted shared primitives —
  `frontend/src/components/org/StatusChip.tsx`, `frontend/src/components/org/OrgIdentity.tsx`
  (`RoleBadge`, `OrgAvatar`), `frontend/src/components/auth/HonestNotice.tsx` and
  `frontend/src/components/auth/AuthCardShell.tsx` — and rewired the v3.4 org components onto them.
  Authorisation, routing and invite-accept logic were left untouched by design.

## Key decisions

- **Keep cleanup separate from the big build.** v3.5 was scoped as a medium polish milestone so the
  v3.6 visual Workflow Studio would start on a clean chat surface.
- **Fix at the provider boundary, never the shared path.** Every provider-specific fix (routing,
  sanitizer, title params) was keyed on model capability data and left Deep Mode behaviour unchanged
  for every other model.
- **Capability-keyed, not ID lists.** `reasoning_first` and `reasoning_off` are registry fields, so a
  new model is handled by adding data rather than editing an ID list.
- **Prefer verify-and-lock where something already worked.** The cancelled and stop affordances
  already existed from earlier work; Phase 174 locked them under tests instead of rebuilding them.
- **Polish must not widen authorisation.** Phase 177 changed presentation only; the secured v3.4
  authz paths were kept byte-identical.
- **Defer all STRETCH work** (178–180) in favour of starting the visual Workflow Studio.
