# v2.4 — Stability, Polish & UX Fixes

> **Shipped:** 2026-04-30 · **Phases:** 44–57 (55 and 57 deferred; no Phase 50) · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v2.4 made Syrel's agent dependable across AI providers — tools that work on every model, Claude through Anthropic's own SDK, a model fallback when one is unavailable, and live progress so the agent never goes silent — while fixing the everyday rough edges in chats, documents, settings and Library Health.

## Why this milestone existed

After v2.3's feature push, real use exposed production bugs and friction: the Stop button did not always stop, deleted chats left "ghost" content on screen, models from non-OpenAI providers silently failed to call tools, Anthropic responses were cut short by a blanket token reduction, sub-agents were hard-wired to OpenAI defaults, and long tool calls produced 30–120 seconds of silence. The roadmap summarised it as fixing "critical production bugs (SSE disconnects, ghost chats, model routing failures)" and polishing "key UX gaps across document management, settings, navigation, and the agentic feedback loop."

## What shipped

- **Tool calling that works across providers.** A model-capability registry decides whether a model uses the provider's native tool API or a structured JSON-in-prompt mode, with a deterministic parser for models that cannot call tools natively.
- **Claude through Anthropic's own SDK.** Anthropic models run through a native adapter with prompt caching, instead of an OpenAI-compatible shim.
- **Full-length answers.** A legacy 20% token reduction and tool-result caps that were truncating responses were removed.
- **Answers vs. file generation disambiguated.** The agent only switches into "generate a file" mode on explicit creation verbs (create / generate / build / make), so plain questions no longer trigger code execution.
- **You choose every model role.** Users control the main, sub-agent and helper models; if a chosen model is unavailable (404), the run falls back and the UI shows a banner saying so.
- **Smarter sub-agents.** Generation-heavy sub-agent tasks were escalated to a more capable model; analysis tasks stayed on the cheaper one. Output ceilings became configurable, and the model picker gained info cards (context size, output size, cost tier).
- **The agent never goes quiet.** A "preparing tool" signal fires the moment a tool call starts forming, running tools show a live elapsed timer, multi-step runs show "Step N", and document uploads show which ingestion step they are on.
- **Stop that stops.** Stopping a stream ends it promptly and keeps the partial answer.
- **Safer chats.** Deleting a thread asks for confirmation, leaves no ghost content behind, and new chats can start inside a chosen folder.
- **Version-aware document deletion.** Delete one version (the next one is promoted) or all versions, with chunks, storage and history cleaned up.
- **Clearer uploads and library.** Root-folder documents are clearly visible, and uploads over 50 MB fail with a specific message.
- **Web search on/off.** A Settings toggle controls whether the agent may search the web.
- **Library Health at scale.** Health lists became paginated tabs with an explanation of what "low confidence" means and actionable empty states.

## How it works

**Provider routing and tool calling (Phases 52–54).** `MODEL_CAPABILITIES` in `backend/app/config.py` became the registry that routes each model. `create_adaptive_streaming_chat()` (today in `backend/app/services/openai_service.py`) chooses native or structured calling; `backend/app/services/tool_parser.py` extracts tool calls from model text for structured mode. An `openrouter_tool_strategy` user setting (quality / native / xml) controls OpenRouter behaviour. `backend/app/services/anthropic_service.py` converts messages to Anthropic's format and applies `cache_control` prompt caching. On a model 404 the backend falls back and emits a `fallback_model` SSE event; `resolved_sub_agent_model` is reported back to Settings.

**Context and sub-agents (Phase 51).** Sub-agent routing classified tasks by keyword (generation vs analysis) and raised the generation ceiling to 32k output tokens; OpenAI token estimation moved to `tiktoken` (`cl100k_base`); `sub_agent_max_output_tokens` became a user setting.

**Live feedback (Phases 56, 56.1).** New SSE events: `iteration_start` (Step N) and `tool_preparing`, fired exactly once per tool index across OpenAI, Anthropic and structured paths. Migration `supabase/migrations/032_phase56_realtime.sql` added an `ingestion_step` column to documents. The frontend `ElapsedTimer` ticks every 250 ms and cleans up on unmount.

**Stop and reconnect (Phases 44, 55, 57).** Stop used `GeneratorExit` handling plus a stop event, with `asyncio.shield` protecting the partial-answer save. Attempts to recover a stream after refresh or tab-switch via Supabase Realtime were shipped as code but not verified, and were deferred (see Gaps) — this is what v2.5 rebuilt.

**Documents and settings (Phases 46–49).** `DELETE /documents/{id}?scope=version|all` handles version promotion and cascade cleanup; the frontend dialog offers Cancel / Delete vN / Delete All Versions. Upload enforces `MAX_FILE_SIZE = 50 * 1024 * 1024` in `backend/app/api/documents.py`. `web_search_enabled` threads through the settings stack and gates the web-search tool. The health API gained offset/limit pagination with totals.

## Key decisions

- **Two tool-calling modes:** native for models proven to support it, structured JSON-in-prompt for everything else.
- **OpenRouter strategy is user-controllable** (quality / native / xml).
- **Generation mode only on explicit creation verbs**, to stop Q&A prompts running code.
- **`tool_preparing` fires exactly once per tool**, guarded by an announced-tools set.
- **Stop via `GeneratorExit`** was judged good enough for v2.4 without a dedicated cancel endpoint — accepting that an in-flight LLM call finishes in the background (known issue KI-001).
- **Smart skill dispatch was cut** from scope and moved to the later Skill Studio work, due to schema-migration risk.

## Gaps and deferred work

- **STREAM-02 (recover after refresh / tab switch) — partial.** Five fix attempts around a Supabase Realtime insert race failed; the final browser check was never confirmed. Carried into v2.5, which replaced the approach entirely.
- **KI-001** — after a disconnect, an in-flight LLM call or tool runs to completion and wastes tokens. Addressed by v2.5 Phase 059.
- **SKILL-01/02 (relevance-based skill filtering)** deferred to the Skill Studio milestone.
- **Unconfirmed browser checks** — 14 human UAT items across Phases 45, 46 and 48; Phases 44, 47, 52 and 56 had no formal verification report.
- **15 backend test-mock failures** from a side phase were carried forward.
- **Sources disagree on the score.** The requirements archive reports 34 complete, 1 partial, 2 deferred; the milestone audit scores requirements 22/27. The audit also notes the requirements file defined MDL-01..05 twice and left most checkboxes unticked, so the two counts are not comparable.
