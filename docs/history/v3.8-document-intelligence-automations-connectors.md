# v3.8 — Document Intelligence, Automations & Connectors

> **Shipped:** 2026-08-26 · **Phases:** 201–209 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v3.8 made ingestion understand tables and email, let workflows run themselves on a schedule under a hard spend cap, let a workflow remember its previous run, and — for the first time — let Syrel reach outside itself through other vendors' official MCP servers with per-tool consent.

## Why this milestone existed

At the end of v3.7 the workflow product was usable, but only by a person sitting in front of it, working only on prose documents, and only inside Syrel. Three carry-forwards from v3.7's close named the gaps: ingestion and document quality (spreadsheets and Outlook `.msg` files were stranded), automations (no unattended runs, no memory between runs, no spend brake), and outbound connectors. v3.8 addressed all three in three days and closed 11 of 11 requirements — three of them only partially wired, as recorded below.

## What shipped

- **Spreadsheets and CSVs become queryable tables.** A CSV or spreadsheet upload is extracted into structured tables the agent can query directly.
- **Facts inside tables become searchable.** Table contents are also written as searchable text chunks, so semantic search can find a fact that only exists in a table cell (for newly ingested documents).
- **Email is a document type.** Outlook `.msg` and standard `.eml` files parse on upload; From, To, Cc, Date and Subject become metadata, quoted replies are stripped, and attachments are stored as their own documents linked to the parent email.
- **Workflows run on a schedule, with nobody watching.** An author or admin sets a cron or interval schedule on a published workflow and it runs unattended in the background.
- **Hard spend and duration caps that actually stop a run.** An unattended run that exceeds its time or token budget is cancelled through the same path as a person's Stop, and an audit entry records the trip.
- **The library says what runs itself.** A scheduled workflow's card reads, for example, `runs every Monday` on the status line, and a paused schedule stays silent.
- **A workflow can read its own previous run.** `{{prior_run.output}}` lets a prompt build on the last deliverable — living registers and weekly "what changed" reports, with `[NEW]` / `[UPDATED]` / `[RESOLVED]` framing.
- **Reach outside through official MCP servers.** A person creates an MCP connection in Settings → Connections, binds it to a workflow step, discovers the server's tools, grants them one by one, runs and publishes — with no per-vendor adapter code.
- **A step says what it actually does.** On the canvas, a step names the bound service and tool instead of a generic "Reach outside", and a read-only tool no longer claims to change something outside.

## How it works

- **Tables.** `backend/app/services/multimodal_service.py` extracts CSV/XLSX into `document_tables` rows (CSV dialect sniffed across `,;\t|`, 50 rows per chunk) and injects markdown representations into `document_chunks`. The agent tool is registered as `query_tables` in `backend/app/services/tool_dispatcher.py` (planning records call it `query_table`).
- **Email.** `backend/app/services/email_extraction_service.py` parses `.eml` with the standard library (RFC 2047 header decoding, HTML-to-text fallback) and `.msg` with `extract-msg`; attachments are linked with `rel_type='attached_to'`. Wired through `backend/app/api/documents.py`.
- **Scheduler.** Migration `124_workflow_schedules.sql` adds `workflow_schedules`; `backend/app/services/scheduler_service.py` claims due rows with `FOR UPDATE SKIP LOCKED` plus an in-transaction advance of `next_run_at`, so exactly one worker claims each due run (driven: 10 trials × 3 concurrent claimers → exactly 1 claim each time).
- **Circuit breaker.** Migration `125_circuit_breaker_trip.sql`; `backend/app/services/circuit_breaker.py` reads the budget written by `arm_run_budget` / `load_run_budget` in `backend/app/db/workflows.py`, and on a trip calls `cancel_workflow_run_internals` — the same cancellation path as the manual Stop — which broadcasts to the producer so the work stops on any worker (`run_lifecycle.py`, `run_producer.py`, `harness_engine.py`). Scheduled runs are mirrored into the Control Room's active-run list so an operator can see and kill them.
- **Stateful workflows.** `_interpolate_prior_run_variables` in `backend/app/services/harness/phase_types.py` resolves the previous completed run by the workflow's stable slug (not its definition id, so a republish does not reset the register) and unwraps step output stored as a JSON string.
- **MCP connectors.** Migration `126_mcp_connector_connections.sql` adds `mcp_server_url`, `tool_grants` and `discovered_tools` to the connection row. `backend/app/services/mcp_client.py` is an async JSON-RPC 2.0 client; `backend/app/security/egress.py`'s `validate_mcp_destination` blocks loopback, private (RFC 1918) and cloud-metadata addresses. `/discover` and `/grants` endpoints live in `backend/app/api/connectors.py`; external-action steps dispatch MCP tools from the harness.
- **Frontend API split (maintainability).** `frontend/src/lib/api.ts` went from 6,815 lines to a re-export barrel over domain modules in `frontend/src/lib/api/`, with all 325 exports preserved.

## Key decisions

- **CONN-02 re-scoped to MCP (2026-08-24).** The original "first-party Jira + Email/SMTP connectors" became "Atlassian and GitHub through their official MCP servers, reads and writes, no per-vendor adapter code"; generic SMTP/IMAP moved to the Connections milestone (v3.9). This follows the MCP-first verdict in `docs/CONNECTOR-ARCHITECTURE.md`.
- **Per-tool grants from day one.** A per-connector on/off toggle cannot say "search freely, but confirm before creating an issue", and retrofitting that grain later would be a migration — so the connection was made provider-shaped with per-tool grants in Phase 206.
- **OAuth deferred.** MCP servers carry their own auth; Google/Microsoft OAuth was explicitly left to v3.9.
- **Breaker reuses the Stop path.** The spend cap composes the manual cancellation path rather than a second one, so a cap that trips actually stops provider calls.
- **Stateful scope keyed on slug, not definition id**, so republishing a workflow does not reset its living register.
- **Read-ness from the server's annotations, never from the tool name.** A first draft guessed "read-only" from names like `get_…`, which labelled a tool that deleted records as read-only; the shipped version follows the MCP spec (an unannotated tool is treated as potentially destructive).

## Gaps and deferred work

- **Spend cap was broken when the phase first "passed".** One parallel plan wrote the caps to `workflow_runs.inputs`, another read them from `workflow_runs.metadata`; the read failed open, so a run went 3m20s against a 120s cap while 106 tests stayed green. Fixed before close by `arm_run_budget` and an integration test that mocks neither side; afterwards a 60s cap tripped a real run at 61.06s.
- **Email thread half of EML-02 was unwired at close.** Thread headers were parsed and stored but read by nothing, so the same `.msg` uploaded twice created two documents (partly addressed in v4.0).
- **TAB-02 covers newly ingested documents only** — no backfill was run.
- **Stateful variables reach 3 of 7 executors**, missing `llm_emit` (the step that produces typed deliverables); there the literal `{{prior_run.output}}` is sent to the model.
- **Seven of twelve phases had no verification report** at close; they were backfilled during the milestone audit. Phase 209's final fix was authored by the reviewer and had no independent review; 207 and 208 ran without independent verification.
- **A Settings "Check" button crashed on MCP rows** (HTTP 500) — found by the audit and fixed at both ends (`69ae998b`).
- **The publish judge passed a run whose deliverable refused the work**, at score 100 (`SEED-203`, still planted).
- **Schedule dialog never had live user testing**, and exactly-once claiming was proven with three connections in one process rather than two real server workers.
- **Two ingestion bugs closed on local-only evidence** await cloud verification.
