# v3.2 — Skill Eval Studio + Self-Improving

> **Shipped:** 2026-07-10 · **Phases:** 132–145 (144 deferred to v3.3) · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v3.2 turned Syrel's Skill Trigger Tuner into a full Skill Eval Studio: authors can save test cases, run each case with and without a skill across providers, read honest pass/fail verdicts, rate outputs, and approve system-proposed improvements. Publishing a skill now requires a passing eval, every user gets a built-in skill-creator, and a starter library of workflows is available.

## Why this milestone existed

v3.1's Trigger Tuner measured whether a skill was picked at the right time, but nothing measured whether a skill made the answer better. The milestone goal was to give users "a real iterative environment to test, compare, and improve their skills": see how a change to a skill affects real outputs across providers, and let the system suggest improvements, with a human always deciding.

A rule applied to every phase: evals reuse the existing agent loop and provider gateway (with the skill and without it, on the same provider). No separate eval runtime was built, and the normal chat path was not changed.

## What shipped

- **Test cases and versions.** Each skill has a persistent, editable set of eval test cases. Every save of a skill's instructions creates an immutable version, so results always trace back to the exact wording that produced them.
- **With-skill vs without-skill eval runs.** Each case runs twice (with the skill and without it), progress streams live, and results are still there after reload. An LLM judge scores both versions of the answer.
- **Honest verdicts and ratings.** Results show a per-provider PASS, FAIL or "not measured" verdict, never a guessed one. A side-by-side view compares the two answers, and thumbs up/down ratings capture human preference.
- **Evals stay out of chat.** The threads that eval runs need are hidden from the chat sidebar.
- **Human-approved self-improvement.** From eval results and Tuner signals, the system proposes an edit to a skill's instructions (or, in a lighter mode, to its description only). A person reviews the diff and approves it. Approval creates a new version, which is re-evaluated automatically before promotion. Nothing is ever applied automatically.
- **Publish gate.** A skill cannot be published until at least one eval has run and passed. The rule applies to future publishes only.
- **Skill Evals panel.** The Skill Studio gained Evals, Triggering and Versions tabs: a case editor, run history, run detail, inline ratings and version comparison.
- **Production-ready evals.** An automated smoke sweep across providers, one-click matrix runs over several providers in parallel with mean ± spread and "skill lift" summaries, determinate progress bars, advisory judge feedback per case, timing for each version of the answer, and a Settings option for the judge model.
- **Built-in skill-creator.** Every user, locally and in the cloud, gets a read-only, undeletable skill-creator marked "Built-in". It walks through the full loop: interview, research, save the skill, write eval cases, evaluate, propose improvements, publish.
- **Honest run endings.** Files that existed before a run started no longer appear as dead "Download unavailable" cards, and runs that end with open todos say so.
- **Smarter skill dispatch.** Only plausibly relevant skills are shown to the model for a given question, within a configurable token budget.
- **Run-scoped templates.** A template uploaded in one run cannot be seen from another.
- **Non-Python script honesty.** If a skill bundles a script Syrel cannot run, the agent says so instead of failing silently or describing the code as if it had run.
- **Reliable Stop / running state.** The chat's "running" indicator and Stop button now reflect the true run state, in both directions.
- **Starter Workflow Library.** A Starters shelf on the Workflows page offers curated workflows (Risk Register, Weekly Status Report, Compliance Gap Report) that a user forks into a personal draft.

## How it works

- **Schema.** Migrations `079_skill_versions_and_test_cases.sql` through `094_starter_workflows.sql`: versions and test cases (079), eval runs and results (080), verdicts and ratings (081), a hidden-eval-thread flag `threads.is_eval` (082), skill proposals (083, 090), publish overrides (084), matrix/duration/feedback columns (085), judge-model setting (086), built-in skill-creator seed and updates (087–089, 093), `skill_embeddings` + `match_skills` (091), workspace-file run claims (092), and the three starter workflows (094).
- **Eval engine.** `backend/app/services/eval_runner_service.py` runs both arms through the normal agent loop; `backend/app/services/eval_aggregation.py` builds matrix summaries. Routes: `backend/app/api/evals.py`, `backend/app/api/skill_test_cases.py`.
- **Proposals and gate.** `backend/app/services/skill_proposer_service.py` drafts diffs; `backend/app/services/publish_gate_service.py` computes the gate, which `backend/app/api/skills.py` enforces with a `publish_gate_unmet` refusal.
- **UI.** `frontend/src/pages/SkillStudioPage.tsx` with `frontend/src/components/skills/studio/` (`EvalsTab.tsx`, `TriggeringTab.tsx`, `VersionsTab.tsx`, `LifecycleStepper.tsx`, `RunBar.tsx`, `RunHistory.tsx`, `RunCaseDetail.tsx`, `ProposalCard.tsx`, `DescriptionProposalCard.tsx`) and `frontend/src/components/skills/PublishGateDialog.tsx`.
- **Smart dispatch.** `backend/app/services/agent_loop.py` calls the `match_skills` RPC over `skill_embeddings` to filter the skill catalog before it is shown to the model.
- **Run lifecycle.** `backend/app/services/run_lifecycle.py` keeps Postgres `runs.status` authoritative and updates a Redis `runs:active` mirror in the same calls. The frontend reconciles by fetching again on reconnect. This logic was moved out of the large `backend/app/api/threads.py` route file.
- **Starters.** `frontend/src/pages/WorkflowsPage.tsx` loads a Starters shelf; forking creates a new slug and a v1 draft.

## Key decisions

- **No separate eval runtime.** Evals use the same agent loop and providers that chat uses, so a result reflects real behaviour.
- **A human approves every change.** The system proposes; it never applies a change to a skill by itself.
- **Honest "not measured".** A provider that could not run a case is shown as not measured, not as a pass or a fail.
- **The gate looks forward only.** Skills published before the gate existed were not retroactively blocked.
- **The built-in skill-creator only claims what the platform can do.** Its instructions were written against the platform's actual capabilities.
- **Starters are trusted seed content** with strict citation gates. In a live end-to-end test, a forked starter passed the publish gauntlet and produced a `.docx` with 17 real citations; the gate rejected an uncited version.
