# v3.3 — Operator UX

> **Shipped:** 2026-07-18 · **Phases:** 146–159 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v3.3 let a non-developer operator run Syrel from the browser: a hidden admin Control Room for health, running work, kill switches, maintenance mode, audit history, users and feature visibility; a live model registry; encrypted API keys; file tools for agents and workflows; per-claim citations; plain-language labels; an accessibility sweep; and a first-run install wizard.

## Why this milestone existed

Until v3.3, running Syrel meant editing environment files, reading logs and touching the database directly. The milestone goal was to "make the platform operable and configurable by a non-developer admin from the UI". It also had to close the workflow and skill file-input gaps deferred from v3.2, and bring everyday UX closer to the simple, accurate, plain-language standard set by enterprise search products.

## What shipped

- **A hidden, gated admin area.** Designated operators get an `/admin` Control Room. To anyone else it does not exist: every admin route returns the same "not found" response, and the nav entry only appears for operators. Every operator action is written to an append-only audit ledger.
- **Control Plane.** Live dependency health (database, Redis, sandbox), a cross-user list of running work with a Kill button that names whose run will stop, kill switches that fail closed for web search, the code sandbox and self-improvement, and a maintenance / read-only mode with a banner shown to every user.
- **Governance.** An audit browser over two ledgers (operator actions and platform activity) with filters and a recorded CSV export, a user roster with last-active times and access control, and feature visibility that hides advanced features per audience. The visibility rule is enforced by the API, not only hidden in the UI.
- **Live model registry.** Operators can edit model capabilities, deprecate or disable models, and lock an org default without restarting the server. Provider discovery proposes new models but never enables one automatically or guesses its capabilities. A model can also be added by ID, and a default-on filter hides utility models (embeddings, audio and so on) during discovery. If a model is disabled mid-conversation, the next message falls back to the org default with a visible notice naming both models.
- **API keys encrypted at rest.** Provider keys saved in the database are encrypted, existing deployments keep working, and the Control Room shows whether encryption is active.
- **File tools for the agent.** `fetch_document_file` copies a knowledge-base document's original bytes into the sandbox so the agent can convert or edit it. `attach_skill_file` lets the agent save files it creates, or a template the user hands it, onto a skill the user owns.
- **Better workflow runs.** The Run dialog accepts an uploaded template and a per-run knowledge-folder scope. Workflows can be deleted safely: a confirmation shows exactly what will be removed and what is kept, and stops live runs first.
- **Inline citations.** Answers carry numbered `[n]` markers tied to what the agent actually retrieved in that run. Hovering a marker previews the passage; clicking pins it and highlights the matching row in a References footer. Claims without a marker read as general knowledge.
- **Plain language by default.** Labels use everyday words, and a single "Show technical names" switch, available to every user in Settings, reveals the underlying terms.
- **Accessibility.** A WCAG 2.1 AA sweep: lint rules enforced in CI, every icon-only button labelled, and low-contrast text fixed app-wide.
- **Everyday navigation.** A permanent icon rail with New Chat always visible, a dedicated chat history column with date grouping and filtering, a ⌘K / Ctrl+K chat finder, and search in the mobile drawer.
- **Deployment and first-run setup.** A production `docker-compose.prod.yml`, a one-box environment preset, an `OPERATOR.md` runbook, and a browser install wizard at `/setup` (environment check, preset, database/Redis connection, operator account, provider key, smoke test) that locks itself once setup is finished.

## How it works

- **Operator access.** Migration `095_operator_foundation.sql` added `operator_users` and `operator_audit_log` with deny-all RLS. Isolation is enforced in the application layer: a router-level `require_operator` dependency in `backend/app/api/admin.py`, seeded at startup from `operator_emails` in `backend/app/config.py`. Migration `096_org_id_stub_sweep.sql` added forward-compatible `org_id` columns for the later multi-tenancy milestone.
- **Flags and visibility.** `097_operator_flags.sql` (`self_improve_enabled`, `workflows_enabled`, `maintenance_mode`) and `098_feature_visibility.sql`, read through the 30-second settings cache. Kill switches work in two layers: the tool is removed from the model's schema and refused at dispatch.
- **Control Room UI.** `frontend/src/components/admin/` (`ControlRoomPage.tsx`, `OperatorBand.tsx`, `HealthSignals.tsx`, `ActiveRunsSection.tsx`, `CapabilityGrid.tsx`, `MaintenancePanel.tsx`, `AuditTab.tsx`, `UsersAndAccess.tsx`, `FeatureVisibility.tsx`, `ModelRegistryTab.tsx`, `ModelDiscoveryPanel.tsx`).
- **Model registry.** `099_model_registry_deprecated.sql` and `103_model_discovery_filter.sql`; `backend/app/services/model_registry.py` and `model_discovery_service.py` (fan-out to provider `/models` endpoints, with destinations checked against an SSRF allowlist).
- **Secrets.** `backend/app/security/secret_cipher.py` wraps MultiFernet with an `enc:v1:` envelope. `100_secret_key_columns.sql` added the missing key columns. Startup refuses a malformed `SECRETS_ENCRYPTION_KEY`, warns and runs in plaintext when it is missing, and encrypts existing plaintext keys once the key is set.
- **File tools.** Handlers in `backend/app/services/tool_dispatcher.py` (`_handle_fetch_document_file`, `_handle_attach_skill_file`). `101_skill_files_unique_index.sql` makes overwrite-in-place race-safe.
- **Workflow inputs and delete.** Run scope resolution in `backend/app/services/workflow_kickoff.py`; `/delete-preview` and `/cascade` routes in `backend/app/api/workflows.py`.
- **Citations.** `backend/app/services/citation_markers.py` removes out-of-range markers and aligns the rest to the final retrieval footer; the UI uses `frontend/src/components/chat/CitedMarkdown.tsx` and `CitationPeek.tsx`.
- **Plain language.** `frontend/src/providers/TechnicalNamesProvider.tsx` and `frontend/src/lib/termMap.ts`.
- **Accessibility and navigation.** `eslint-plugin-jsx-a11y` in `frontend/eslint.config.js` plus a `lint:a11y` script; `frontend/src/components/layout/ChatHistoryColumn.tsx` and `ThreadCommandPalette.tsx`.
- **Setup.** `102_setup_complete.sql`; `backend/app/services/setup_service.py` and `setup_store.py`; `backend/app/api/setup.py`; `frontend/src/pages/SetupWizard.tsx` with `frontend/src/components/setup/`. `scripts/check-deploy-drift.sh` fails CI when the deployment artifacts drift apart.

## Key decisions

- **Admin is invisible, not just locked.** Non-operators get the same "not found" response on every admin route, and the frontend never shows a locked admin badge.
- **The operator gate is an application-layer wall.** The operator tables deny all row-level access, and the backend gate is the only authority. The schema was shaped so that the v3.4 multi-tenancy rewrite would not have to undo it.
- **Discovery proposes; operators decide.** Discovery never auto-enables a model and never guesses a capability the provider did not report ("unknown — you set it").
- **Kill switches fail closed and treat every provider the same.** When a flag is on, the gate does nothing at all, so normal chat behaviour is unchanged.
- **Citation truth comes from the backend.** The server decides which markers are valid, based on the run's real retrieval set.
- **One-box is the primary deployment path.** The managed and on-prem variants are documented alongside it.

## Gaps and deferred work

- **Cloud parity owed at close.** Production needed migrations 099–103 and `SECRETS_ENCRYPTION_KEY` at the next push. The milestone summary records this as owed; this document does not verify when it was applied.
- **Open chat-surface bugs** (six reports) rolled forward to a planned chat-polish phase.
- **One accepted limitation:** the per-run folder-scope requirement (WFIN-02) carries an operator-accepted OpenRouter cross-provider limitation tied to an external bug report.
- 44 open items were acknowledged at close: dormant seeds, stale quick-task references, and already-passed or human-tested items.
- Every phase that touched a trust boundary (146–150, 153, 154, 158, 159) recorded a security review with no open threats.

**Sources disagree on deployment presets.** `v3.3-REQUIREMENTS.md` (DEPLOY-01) and the milestone summary describe "Solo/Team/Enterprise" preset bundles. Phase 157's decisions and its shipped files show one fully built preset (`deploy/onebox.env.example`, the "one-box" home), with managed and on-prem as documented variants. Phase 158's wizard lets you select those variants, but they only pre-fill different defaults. There are no separate Solo/Team/Enterprise files.
