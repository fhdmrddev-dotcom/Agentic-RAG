# v2.3 — Memory, Multimodal & Experience

> **Shipped:** 2026-04-19 · **Phases:** 33–43 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v2.3 made Syrel remember you across conversations, read the tables and images inside your documents, tell you how healthy your library is, take your feedback on answers, and look like a finished product on desktop and phone.

## Why this milestone existed

By v2.2 the agent could search a knowledge base, run code and use skills, but every conversation started from zero, documents were read as plain text only (tables flattened, images ignored), and there was no way to see which documents were actually useful to the agent. The interface was also functional rather than polished. The roadmap framed the goal as: "Deepen the agent intelligence with persistent memory and richer document understanding, then elevate the product feel with the Deep Midnight UI redesign across chat, citations, skills, and mobile."

## What shipped

- **Cross-thread memory.** The agent can `remember` a fact or preference in one chat and `recall` it in another; the most recent memories are injected automatically at the start of each general-mode turn.
- **Memory you control.** A Memory section in Settings lists every stored memory with inline edit and delete-with-confirmation, plus an empty state explaining what memory is.
- **Tables inside documents are understood.** Tables in PDFs and Word files are extracted during ingestion and stored as structured rows; a `query_tables` tool lets the agent query them by document and column.
- **Images inside documents are searchable.** Embedded images (above 50x50 px) are described by a vision model, and those descriptions are embedded so ordinary document search can find them.
- **Extraction never blocks ingestion.** If table or image extraction fails, the document still ingests normally.
- **Library Health.** A dashboard of four signals — most-retrieved, never-retrieved, low-confidence and stale documents — with Delete, Re-ingest and Move-to-folder actions on each row.
- **Thumbs up / down on answers.** Every completed assistant message can be rated; a thumbs-down opens a reason picker (Wrong answer / Not from my documents / Incomplete / Other). Ratings are immutable and never interrupt the conversation.
- **Feedback stats.** Overall positive rate and the most-downvoted documents over the last 30 days, shown in Library Health.
- **Deep Midnight redesign.** Frosted-glass tool-call panels, gradient-bordered citation cards with file-type icons, and a floating "pill" message composer.
- **New layout shell.** Navigation moved into a dedicated rail, the Skills page became a three-pane layout, and toggles and settings cards got a consistent tonal treatment.
- **Mobile and responsive.** A collapsible navigation panel, a frosted overlay drawer for the thread list on small screens, and a five-tab Settings page.

## How it works

**Memory (Phases 33–34).** Migration `supabase/migrations/026_user_memory.sql` creates `user_memory` with a `UNIQUE(user_id, key)` constraint so writes are upsert-by-key, and Row-Level Security limits rows to their owner. The `remember` / `recall` tools are dispatched today from `backend/app/services/tool_dispatcher.py` (handler map entries `"remember"` and `"recall"`). Writes were designed fire-and-forget (`asyncio.create_task`) so they never delay the streamed reply. The top 10 most-recently-updated entries are injected as a capped (~500 token) block in general mode only; Explorer mode gets no memory block. The Settings UI is `frontend/src/components/settings/MemorySection.tsx`, which reads the same table under the same RLS policies.

**Multimodal extraction (Phases 35–36).** During ingestion, `pdfplumber` (PDF) and `python-docx` (DOCX) pulled tables into `document_tables` (document, page, table index, headers, rows as JSON); images went to `document_images` with a vision-LLM description. The phase plans cite migrations 018/019 for these tables; in today's `supabase/migrations/` folder both are created by `030_missing_tables.sql` (the sources do not explain the renumbering). `backend/app/services/multimodal_service.py` implements `query_tables` and embeds image descriptions as searchable chunks. A notable fix (035-04) was reading PDF image stream bytes via `PDFStream.get_data()`. The document list gained "Tables: N, Images: N" badges and the detail view a tables panel and image lightbox.

**Library Health (Phases 37–38).** `backend/app/api/knowledge_health.py` (router prefix `/knowledge-health`) derived all four signals from the existing `audit_log` table, with Python-side JSONB aggregation, target response time under 2 s for libraries up to 10,000 documents. A new `POST /documents/{id}/reingest` endpoint backed the Re-ingest action.

**Feedback (Phases 39–40).** Migration `supabase/migrations/028_message_feedback.sql` creates `message_feedback` (one rating per message per user, INSERT-only). `backend/app/api/feedback.py` exposes `POST /feedback` and `GET /feedback/stats`; feedback events also land in the audit log as `message_feedback`. Frontend: `frontend/src/components/chat/MessageFeedback.tsx` wired into `MessageItem.tsx`, and `frontend/src/components/health/FeedbackStatsPanel.tsx`.

**UI redesign (Phases 41–43).** Strictly additive CSS/Tailwind — no changes to SSE parsing or state management. Phase 42 extracted an `AppDock` rail; Phase 43 then replaced the AppDock + Sidebar pair with a single collapsible `NavPanel` (`frontend/src/components/layout/NavPanel.tsx`), installed shadcn Tabs, and rebuilt Settings as five tabs. That refactor also fixed a bug where one tab's save could write placeholder API-key values from another tab.

## Key decisions

- **Memory is upsert-by-key** (`UNIQUE(user_id, key)` + `ON CONFLICT`), so restating a preference updates it rather than duplicating it.
- **Memory writes are non-blocking** — the chat reply is never held for a memory write.
- **Memory is general-mode only** — Explorer mode stays a clean document-navigation context.
- **Multimodal extraction is non-fatal** — a broken table or image must never fail an upload.
- **Image descriptions become ordinary searchable chunks**, so no separate image search path was needed.
- **Health metrics come from the audit log**, reusing data the product already recorded rather than adding new tracking.
- **Feedback ratings are immutable** (INSERT-only, no update or delete).
- **The redesign was additive styling only**, to avoid regressing streaming behaviour.
- **One collapsible NavPanel replaced the AppDock + Sidebar pair** within the same milestone.

## Gaps and deferred work

- **Human visual checks outstanding at close.** The v2.3 audit (2026-04-22) rated the milestone `tech_debt`: Phases 38–42 were verified as `human_needed` (automated checks passed, browser confirmation pending) and Phase 43 had no formal verification report.
- **Requirement count disagreement.** The audit headline says 28/28 requirements satisfied, but its own coverage table lists 24 requirement rows. All listed rows were marked satisfied.
- **Metadata normalisation** beyond document type and language (carried from v2.1) was deferred.
- **Library Health at scale** — fixed top-10 lists did not scale; pagination followed in v2.4 Phase 49.
