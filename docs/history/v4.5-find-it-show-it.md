# v4.5 — Find It, Show It

> **Shipped:** in progress (started 2026-09-29) · **Phases:** 270–275 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** IN PROGRESS — DRAFT generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v4.5 lets people find a document by what it is (type, owner, dates, folder, relationships, version) and get the original file back out. It makes the agent respect a named period or dimension instead of answering from the nearest wrong document, and lets the agent answer with live, interactive charts, tables and metrics instead of static images and prose.

## Why this milestone existed

By v4.4 Syrel could answer questions about a knowledge base, but it was weak at the basic job of a document system:

- **You could not find a document you knew existed** unless you remembered a phrase inside it. Every search was an answer search (RAG), which returns passages, not documents.
- **You could not get the file back out.** There was no download of the original file, and the detail panel did not say what the file was: pages, size, author, or the date the file itself was created as opposed to the date it was uploaded.
- **"Close" answers were wrong answers.** Asked about October revenue, the agent could cite a March report, because a date in the question was just text and never became a filter.
- **Charts were dead images.** Asked for a chart, the agent wrote matplotlib code and returned a PNG. You could not hover it, toggle a series, or say "make it a bar chart" without re-running everything.
- **Chat attachments and retention** (keeping what is dropped into a chat inside that chat; policies, legal hold, scheduled disposal) were also in scope for this milestone but are not started yet.

Two rules apply to every phase. A success criterion is met only by a live run as a real user in a real org, with the evidence recorded. And a metadata filter may **never** decide who can see a document; access stays with the existing org and row-level security rules.

## What shipped

(So far on the development branch. None of it is in production yet; see Status today.)

- **Download the original file.** Download it from the Library list, the detail panel or the version history. The button says whether it fetches the latest version or the one you are viewing, and fetches exactly that one. The downloaded bytes match the stored hash. Someone in another org gets a refusal and no link. Links expire after a short, configurable lifetime (60 seconds by default).
- **File facts on the detail panel.** Created, modified, pages, size, type and uploader. "Created in the source file" and "added to Syrel" are labelled as different facts. Older documents show "not recorded" rather than a wrong date or "0 pages".
- **Find documents, beside Ask.** The Library Documents tab has a `Find documents | Ask` switch. Find combines type, owner, date range, custom fields, folder (with subfolders), relationships in both directions ("supersedes X", "referenced by X") and version state (latest / has earlier versions / superseded). It returns one row per document, sorted by a stated field, and never calls the AI ranking. Ask hands the question to chat in a new thread without sending it.
- **Classification became "Filing rules."** It moved off the main navigation rail and into the Library as a header link. Every existing rule still loads and still applies to new uploads. An older version opened from search shows a read-only notice.
- **The agent filters by period and dimension.** When a question names a period or a field value, the agent's search carries a structured filter, and every cited source falls inside it. The search tool card shows a plain line such as "Filtered: document date 1–31 Oct 2025". When nothing matches, the agent says so, cites nothing, and is blocked from quietly retrying without the filter.
- **Live artifacts in chat.** The agent can answer with an interactive chart (hover for values, click the legend to hide a series), a table or a metric card, drawn from a closed set of three components. A follow-up like "make it a bar chart" or "only Q3" redraws from the rows already attached, with no new search or code run. Artifacts reload identically. A malformed or unknown spec shows a short notice, never raw JSON.

## How it works

- **Download and file facts (270).** Migration `199_document_file_facts.sql` adds four nullable file-fact columns, a positive page-count check, and the link-lifetime setting (clamped 10–900 seconds). It does not backfill old documents. `backend/app/services/file_facts.py` reads the facts at ingest, with one best-effort write in `ingest_splice.py`: a failed facts write is logged and never fails the ingest. `POST /documents/{id}/download-url` in `backend/app/api/documents.py` first checks visibility as the user (through row-level security), and only then signs the stored path with the service role. It returns 404 for a document the user cannot see and sends no-store caching headers. Frontend: `DocumentDownloadButton`, `DocumentFileFacts`, mounted in `DocumentDetailPanel.tsx` and `DocumentRow.tsx`.
- **Find (271).** `backend/app/services/document_search_service.py` behind `POST /document-search` (`backend/app/api/document_search.py`). It reuses the shipped saved-view filter compiler, adds folder-subtree, two-direction relationship and version-state filters, and does server-side sort, paging and an exact total. A test pins that it imports no embedding or retrieval code. Frontend: `frontend/src/components/library/find/*`, the `useDocumentFind` hook, `LibraryPage.tsx`. A two-org fence runs through real login tokens against the row-level security path.
- **Filtered retrieval (272).** The retrieval service was first split into `retrieval_rpc.py`, `retrieval_rank.py`, `retrieval_documents.py` and `retrieval_scope.py`. Default predicates live in `retrieval_scope.py` as data, so the archive exclusion planned for Phase 275 can ride on them. The `search_documents` tool gains a `filters` argument with Find's condition shape (handler in `search_documents_tool.py`), validated against a vocabulary built for each request. Unknown fields are refused, with the valid ones listed. Migrations `200_filtered_retrieval_document_scope.sql` and `201_retrieval_rpcs_force_custom_plan.sql` give both retrieval arms (vector and keyword) the same document set, with an exact search branch for small filtered sets. A recall test at 100,000 chunks measured recall@20 = 1.000 at every filtered size. Today's date now goes into the system prompt. One audit writer records filters and result kind on each `search.query` row.
- **Artifacts (273).** A new agent tool, `show_artifact` (`backend/app/services/show_artifact_tool.py`), is the only way to emit an artifact. Pydantic validates the spec as a closed union of `chart` / `table` / `metric`, with a 500-row cap. Each artifact is immutable and stored in `message_artifacts` (migration `202_message_artifacts.sql`), whose row-level security mirrors messages and allows no client writes. A follow-up calls `show_artifact(from_artifact=<id>, …)` to re-encode by reference. The server writes the provenance caption. Messages are re-attached on reload through `GET /messages` and `/snapshot`. On models without native tool calling, tool-call text is held back from the streamed answer. Frontend: `frontend/src/components/chat/artifacts/*`, with the closed map in `artifactRegistry.ts` and a lazily loaded recharts chart. The tool is chat-only and excluded from workflows and sub-agents.

## Key decisions

- **Link lifetime is a setting, not hardcoded** (default 60 seconds), and the org check always happens before any URL is signed (270 D-05).
- **Old documents are not backfilled.** They honestly show "not recorded".
- **Find is a mode on the Documents tab, not a new tab** (271 D-01). Ask leaves the Library for chat. The two result lists are never merged or re-ranked together (D-02).
- **The default version view is "Latest versions".** "Superseded" (version lineage) and the `supersedes` relationship are labelled as separate facts (D-06/D-07).
- **"Filing rules"** is the new name for Classification (D-08).
- **The model decides when to filter, over a closed field list built for each request** (272 D-01/D-02). Undated documents are excluded under a date filter and counted (D-06). After a zero-match filtered search, a retry that drops the filter is refused (D-09).
- **Widening `search_documents` instead of adding a tool** kept the tool count at 29 in 272. **Phase 273 then deliberately added `show_artifact`**, taking the closed tool registry from 29 to 30. This change was recorded at discussion, as the milestone's rule requires.
- **Artifacts are immutable, carry a server-written caption, and cap rows at 500** (273 D-04/D-08/D-09).
- **Google's filter behaviour accepted as unmet.** The operator closed 272's cross-provider criterion with Google recorded as unmet (6 of 8 providers met), and stated that this is a decision, not a pass.

## Gaps and deferred work

- **Nothing from this milestone is in production.** Production still runs the v4.4 deploy. The deploy order recorded for 272 is strict: migration 200 step 1 (a concurrent index build) alone, then step 2, then 201 immediately, then verify. Migration 200 without 201 was measured to make searches take about 1.6 seconds.
- **Operator sign-offs owed:** 271's six browser scenarios and two product choices (default sort "newest added"; "Older versions" shows only the caller's own rows). 272's three logic rules changed after the last live run and need a live re-run.
- **Provider gaps:** Google never emitted the filter argument in 272 (model behaviour, investigated). MiniMax once answered with out-of-filter figures before the retry lock existed. In 273, DeepSeek failed the by-reference redraw (the refusal message did not say where `chart` belongs), so 7 of 8 providers passed that check. All 8 emitted and reloaded charts.
- **273 still owes:** a live check that tool-call text never leaks into the answer on a model without native tool calling (no model on the current roster uses that path; the local model tried timed out), plus two notice cases not driven live.
- **Known product rough edges:** Re-ingest on an older version row is a silent no-op (271 F-2). Find and saved views share a filter-compiler hole that 272 fixed only for the agent. A thread's first open can be blank for up to 7 seconds (not artifact-specific).
- **Out of scope by decision:** permissions derived from metadata (`SEED-211`), the full five-tab document-space redesign, image generation, and the branch/compare half of data threads. Artifacts are not linkable because the app has no URL router.
- **Records disagree:** the brief for this document described the milestone as phases ~269–273. The roadmap defines v4.5 as 270–275, with 269 belonging to v4.4. The ROADMAP checklist still shows 270 and 271 unticked, and its progress table reads "0/TBD · Not started" for 270, although both have verification reports. `STATE.md` frontmatter reports 13 total phases, which does not match the six-phase roadmap.
