# v4.2 — The Connected Knowledge You Can Actually Run

> **Shipped:** 2026-09-18 · **Phases:** 247–254 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v4.2 made v4.0's connected-knowledge features dependable enough to live on: watched sources describe themselves accurately, credentials can't come to rest anywhere readable, the model you actually run registers from the UI, and runs stop claiming things that didn't happen.

## Why this milestone existed

v4.0 built connected sources and v4.1 deployed them. v4.2 was the first milestone in three to open on code that was already in production, and using that code surfaced a list of defects. The goal was:

> The capability v4.0 built and v4.1 deployed becomes the surface you can **live on** — the watch loop tells the truth, a credential cannot land in a readable column, and the model you want to run registers itself.

The milestone was scoped at five phases (247–251). After all five closed, a cross-phase audit found four blockers and nine warnings. Each one sat at a seam between two pieces that were correct on their own. Three more phases (252–254) closed those findings, which is why v4.2 ran to eight phases.

## What shipped

- **A watched source describes itself accurately.** Paths from Google Drive and OneDrive are stored in full and used by classification rules. A watch card reports the health of the connection it rides on, not just its last run. A missing file says when it went missing. Every action label matches what the button does.
- **"Sync now" answers where you pressed it.** The result appears in place and reports what the sync actually did.
- **A pasted secret is refused, not stored.** Paste a credential into a field that isn't a secret field and Syrel refuses it, names the field that does take secrets, and keeps the credential out of the backend log.
- **Dynamic client registration was brought inside the credential boundary.** A writer that bypassed the credential check (OAuth dynamic client registration, RFC 7591) now goes through the same validated path. A malformed `client_id` can no longer break a connection.
- **Locked-down database functions.** All 13 `SECURITY DEFINER` functions in the exposed API schema were reviewed, and the default public execute grant was revoked.
- **New installs get the same database privileges.** A database created from the single-file bootstrap now has the same privileges as one built by replaying every migration, for tables as well as functions.
- **Add the model you actually run from the UI.** Local and self-hosted models (Ollama, LM Studio, vLLM or any OpenAI-compatible endpoint) can be added in the Model Registry with no code edit or deploy.
- **A warning when you pick an unregistered model.** If a model isn't in the capability registry, the composer says so when you pick it. Measurement found 13 of the operator's configured models were silently losing tool calling.
- **Failed settings writes say so.** A save the database refuses now reports failure, and each eval engine either reports healthy or names its own problem.
- **Runs stop overclaiming.** Context trimming never drops your own question. A reasoning model that produces no text explains what happened instead of reporting an empty response. The workspace panel stops calling a live run finished, and a finished task leaves no false to-do items.

## How it works

- **Watch truthfulness (Phase 247).** Source paths travel in `metadata.source.path` from the adapters in `backend/app/services/sources/adapters/`. Connection-level health is computed in `backend/app/services/sources/health_verdict.py` and worded for people in `frontend/src/components/sources/sourceHealthVocabulary.ts`.
- **Credential boundary (Phases 248, 252).** Validation lives in the connector models (`backend/app/models/connector.py`). For example, `custom_client_secret` is refused in a field that is not a secret field. The log redaction for that refusal lives in `backend/app/services/logging_sink.py`. Dynamic client registration is handled in `backend/app/services/connector_service.py` and `backend/app/api/connectors.py`.
- **Function lockdown.** Migration `supabase/migrations/181_revoke_public_secdef_functions.sql` revokes `EXECUTE` from `PUBLIC`, not just from `anon`. Postgres grants function execute to `PUBLIC` by default, so a revoke from `anon` alone changes nothing.
- **Bootstrap parity (Phase 253).** `pg_dump --no-privileges` cannot carry grants, so the bootstrap file `supabase/full-schema.sql` was shipping functions wide open. The revokes are mirrored in `scripts/full-schema-supplement.sql` (78 `REVOKE` lines today). `scripts/check-schema-acl-parity.cjs` compares them with the migrations, and it was shown to fail against a real scratch database before anyone relied on it.
- **Model registry (Phase 249).** The add-model endpoint used to check providers against the security allowlist used for model *discovery* (8 cloud providers). It now checks against the routing roster (11 providers). The UI is in `frontend/src/components/admin/ModelRegistryTab.tsx`, and the pick-time warning is in `frontend/src/components/chat/MessageInput.tsx`. Cross-worker propagation was already built (`broadcast_settings_change`, `SettingsCacheSubscriber`) and was verified, not rebuilt.
- **Run honesty (Phase 250).** `backend/app/services/context_window.py` trims context in four ordered passes and protects the user's latest question. The empty-reasoning explanation is in `agent_loop.py` and `provider_gateway/openai_compat.py`. Todo reconciliation is in `frontend/src/components/panel/todoRunHonesty.ts` and `TodosSection.tsx`.
- **Planning-register integrity (Phase 251).** This internal work keeps the team's records of deferred ideas reliable. Duplicate seed ids were resolved, `.planning/seeds/TEMPLATE.md` defines the record format, and `scripts/check-seeds-register.cjs` sweeps the register automatically.

## Key decisions

- **Refuse, don't store.** A credential in the wrong field is rejected with a message naming the right field. It is never quietly accepted.
- **Revoke from `PUBLIC`, then grant back what's needed.** Revoking from `anon` alone was measured to change nothing.
- **Validate model providers against the routing roster, not the discovery allowlist.** The discovery allowlist is a security control for outbound probing. It was never meant to define which models a user may register.
- **Measure before building.** Two of the six model requirements were already satisfied in code and a third defect no longer reproduced. All three were closed in writing, not rebuilt.

## Gaps and deferred work

- **Independent review (`DEBT-06`) was the only unmet requirement (25 of 26).** At close, 8 of 14 phase records showed neither a completed independent review nor a written refusal. The accepted risk was that the builder had verified its own work.
- **Some checks were owed, not passed.** Migration 181 wasn't yet in cloud. Self-hosted models weren't tested end to end in chat because no live self-hosted endpoint was available. Multi-worker propagation wasn't observed live. The live BYO-OAuth scenario for Phase 248 wasn't run, and the CI job for schema privilege parity wasn't confirmed.
- **Four small record-keeping issues were found at the audit.** These were an unparseable verification header, duplicate ids in the reported-bugs folder, one fixed bug not marked closed, and one stale verification status.
- **41 deferred items** were carried forward at close.
- **Sources disagree about when the watch loop first reached production.** The v4.2 roadmap says v4.0's watch loop reached production "for the first time on 2026-09-13". The v4.1 roadmap records the v4.0 production push on 2026-09-10. Today the background watch process still ships disabled by default (`WATCH_PROCESS_ENABLED=false` in `deploy/onebox.env.example`).
