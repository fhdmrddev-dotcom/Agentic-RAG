# v3.1 — Workflow & Skill Studio — Trust, Clarity & Triggers

> **Shipped:** 2026-06-28 · **Phases:** 120–129 (shipped: 120, 121, 122, 123, 123.1, 124, 127, 128, 129) · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v3.1 made Syrel's skills and workflows trustworthy and easy to read on every AI provider: it fixed a real bug where a workflow's output leaked into a later skill run, gave workflows one obvious place to launch from, made structured output recover or fail honestly on every provider, added a Skill Trigger Tuner, and made the Workflow Studio and the chat tool card easier to read.

## Why this milestone existed

By the end of v3.0, Syrel had a workflow engine (the "harness"), a Workflow Studio and reusable skills, but testing exposed four trust problems:

- **A confirmed collision bug.** When a skill ran in a thread that had previously run a workflow, the skill's run could pick up the workflow's leftover files ("two files instead of one"), and a later chat turn could replay the workflow's history.
- **Two ways in.** Workflows could be started both from the chat composer (a "Harness" pill and an in-chat picker) and from the Workflows page, which confused people about what they were running.
- **Uneven provider honesty.** Structured output was reliable on OpenAI but not on every provider, and step labels were vague on some providers.
- **Skills that did not trigger.** There was no way to measure whether a skill's description actually made the agent pick it at the right time.

The milestone goal was to fix the collision, bring cross-provider honesty up to OpenAI's level, add a trigger tuner, and make each workflow's purpose obvious.

## What shipped

- **No more cross-run collisions.** A skill run now only collects files it created itself, and chat turns and workflow runs no longer replay each other's history.
- **One front door for workflows.** Workflows launch from the Workflows page only. The chat composer was simplified to two modes, General and Explorer.
- **Honest structured output on every provider.** When a provider cannot produce strict structured output, Syrel steps down through fallbacks and either recovers or fails with an honest message, instead of returning something broken.
- **Concrete step labels everywhere.** Task and step labels are specific on all providers, not just OpenAI.
- **Skill Trigger Tuner.** A skill author can benchmark a skill's description against "should trigger" and "should not trigger" prompts on held-out cases, see results per provider on a scoreboard, and accept improved candidate descriptions. Results survive refresh and restart.
- **Description lint at save time.** Weak skill descriptions get a warning when saved. The warning never blocks the save.
- **Loaded skills stay in context.** Once the agent loads a skill's instructions, they are kept when long conversations are trimmed.
- **Workflow "soul".** Every workflow shows the same summary (purpose, inputs, a glyph phase spine, one tier chip, output) at three sizes: library card, run header and publish summary.
- **Two authoring doors.** "Describe & run" for quick use and "Author & govern" for full control. No control was removed; advanced settings sit one click away.
- **Calmer publish gauntlet and run steps.** The publish check reads as a pip strip with a worded verdict and raw detail on demand. Idle steps stay visually quiet.
- **Unified chat tool card.** The tool card is now the single place for live run information, shows the real provider's logo, and streams the tool's description before the tool starts. The redundant sticky timer above the composer was removed, and long user prompts collapse behind "Read more".
- **Provider robustness fixes.** Malformed tool arguments from MiniMax get one bounded re-ask at the adapter boundary, and OpenRouter requests ask only for upstreams that support the required parameters.

## How it works

- **Collision fix.** The sandbox output harvest now starts from a per-run baseline snapshot (`snapshot_output_baseline` / `harvest_output_files` in `backend/app/services/sandbox_service.py`). Migration `supabase/migrations/076_messages_origin.sql` added a `messages.origin` column; `backend/app/services/agent_loop.py` filters history so chat runs skip `origin = 'harness'` rows.
- **Emission ladder.** `backend/app/services/forced_emit.py` tries force-strict, then non-strict, then coerce, then fails honestly, and records which step succeeded. Each model's tier is stored as an explicit `emit_tier` field in `backend/app/config.py`. The tiers were checked against each provider's documentation (55 models at the time), and a per-provider scoreboard has to approve any change of tier.
- **Trigger Tuner.** `backend/app/services/skill_tuner_service.py` generates candidates and runs a 60/40 held-out benchmark with three repeats as a background job, streaming progress over the existing run buffer and SSE (`backend/app/api/skill_tuner.py`). Migration `077_tuner_runs.sql` stores the latest result; `078_app_settings_skill_builder_model.sql` lets admins pick the builder model. The UI is `frontend/src/pages/SkillTunerPage.tsx` with `frontend/src/components/skills/tuner/` (`ProviderScoreboard.tsx`, `CandidateCard.tsx`, `CaseEditor.tsx`).
- **Lint and trim-pin.** `backend/app/services/skill_lint.py` (`lint_description`, called from `backend/app/api/skills.py`). `backend/app/services/context_window.py` treats `load_skill` results as a protected class when trimming.
- **Workflow soul.** `frontend/src/components/workflows/soulData.ts` is the single source for tier derivation, phase glyphs and soul fields. `WorkflowSoul.tsx` renders it at three sizes, and `WorkflowDoorSwitch.tsx` is the two-door fork.
- **Chat surface.** `frontend/src/lib/providerLogo.tsx` is the shared `@lobehub/icons` logo map used by `frontend/src/components/chat/RunCard.tsx`. Long-prompt clamping lives in `UserMessageBubble.tsx`.
- **Provider boundary.** All provider fixes were made at the gateway/adapter layer; the shared chat path was left unchanged. OpenRouter `require_parameters` is set in `backend/app/services/openai_service.py` (around line 2383).

## Key decisions

- **Provider fixes stay at the boundary.** Every provider-specific fix lives in the gateway or adapter, and the shared agent path is unchanged. No new runtime was added.
- **Icon convention.** Provider and model logos come from one `@lobehub/icons` source; workflow phase types use one shared 3D glyph map.
- **The tuner warns but never blocks.** Description lint is advice; authors stay in control.
- **Nothing removed, only reorganized.** Both the two-door Studio and the two-pill composer kept every existing capability reachable.
- **Per-phase testing instead of a milestone audit.** Every phase that touched streaming, providers or the agent loop ran a live cross-provider scoreboard.
