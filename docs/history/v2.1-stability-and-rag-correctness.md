# v2.1 — Stability & RAG Correctness

> **Shipped:** 2026-04-11 · **Phases:** 18–25 · **Product:** Syrel (formerly Agentic RAG) · **Doc status:** DRAFT — generated 2026-10-04 from planning records; verify before publishing

## In one sentence

v2.1 was a hardening release: Syrel stopped producing blank or silently failed answers, kept long conversations inside the model's context window, and fixed retrieval bugs that returned the wrong or unscoped results.

## Why this milestone existed

The milestone goal was stated in one line: *"Eliminate silent failures, blank responses, and correctness bugs found in post-v2.0 review."* With skills, sandboxed code and multi-step tool loops added in v2.0, conversations grew longer and tool results got bigger. That exposed failures users could not see or diagnose:

- Long threads could overflow the model's context window. The provider rejected the call, and the user saw a blank reply.
- A run could end on an empty final message, or be cut off mid-tool-call, with nothing shown.
- In a folder-scoped chat, keyword search still searched *everything*, while vector search respected the scope.
- Metadata filters were case-sensitive, so filtering for "PDF" missed documents stored as "pdf".
- The agent had no instruction to hedge on weak matches or to cite sources consistently.

## What shipped

- **Long conversations keep working.** Before every model call, older history is trimmed to a token budget. A tool call is never separated from its result.
- **No more blank replies.** If the final step returns nothing, the user gets a fallback message. If the model hits its output limit while building a tool call, the user sees an error instead of silence.
- **Readable "conversation too long" errors.** Provider context-length errors are shown in chat as a clear message.
- **Large documents don't break analysis.** Content sent to the document-analysis sub-agent is capped before the call is made.
- **Folder scope applies to keyword search too.** A folder-scoped chat now limits both keyword and vector search to that folder subtree.
- **Bounded document reads.** `read_document` results are capped at 3,000 characters, with a note telling the agent to read the rest by line range.
- **Case-insensitive metadata filters.** Document type and language are lowercased at ingest, and filter values are lowercased at search.
- **More honest answers.** The system prompt now tells the agent to hedge when search similarity is below 0.4 and to cite sources by document name and section.
- **Cheaper, model-aware sub-agents.** The analysis sub-agent automatically picks the cheapest capable model for the active provider (Haiku, a "nano" OpenAI model, or Gemini Flash), and the main agent's context budget depends on the provider.
- **Fewer bad chunk splits.** The chunker no longer splits sentences on abbreviations or decimals such as "e.g." or "3.14".

## How it works

**Context trimming (Phases 18, 25).** Token estimates (`estimate_tokens`, `estimate_messages_tokens`) drive two trim points in the chat loop: once before the loop starts, and again between iterations. Removal is atomic per request/response pair, and the most recent messages are protected. Phase 25 added `resolve_context_budget()`, with per-provider defaults of Anthropic 120k, OpenAI 200k, Google 180k, OpenRouter 100k and Ollama 80k. It also changed JSON tool-call estimation from chars/4 to chars/3, because JSON punctuation is token-dense.

**Error and blank-response guards (Phases 19, 20).** Context-overflow `APIError` detection matches "context", "maximum" or "too long" and emits a user-readable SSE error. The final iteration, which runs with tools disabled, yields a fallback message if its content is empty. `finish_reason == "length"` while a tool call is still buffered emits an error and discards the partial call. The `load_skill`/`save_skill` handlers return an informative tool result instead of raising when no row is found. The phase notes say Phase 18's trimmer and Phase 19's sub-agent cap already existed in code. Those phases mostly confirmed, logged and tested them, adding the "maximum" keyword.

**Retrieval fixes (Phases 21, 22).** `_keyword_search` and the `keyword_search_chunks` RPC gained a `folder_ids` parameter, shipped as migration `020_keyword_search_folder_scope.sql`, which is now `supabase/migrations/020_keyword_search_folder_scope.sql`. Read caps use a 3,000-character default limit. Ingest lowercases `document_type` and `language`, and `retrieval_service.py` lowercases all filter strings.

**Prompt and infrastructure (Phases 23, 24).** New `SYSTEM_PROMPT` sections cover hedging and citation format, appended after the tool table. The settings override file read by `_load_override()` got a 5-second TTL cache, invalidated on save. `chunk_text` now treats `.`/`!`/`?` as a sentence end only when a space or the end of the text follows.

**Sub-agent model selection (Phase 25).** A `_SUB_AGENT_MODEL_DEFAULTS` map in `backend/app/services/sub_agent_service.py` resolves through four levels: user override, environment override, provider default, then the orchestrator model.

## Key decisions

- **Character heuristics, not exact token counting.** Tiktoken was ruled out because the estimate is fast and accurate enough for trimming decisions.
- **Hard-coded budgets for now.** Dynamic per-model context mapping was explicitly out of scope. It arrived later; see Status today.
- **Trim whole pairs.** A tool call and its result are always kept or dropped together, so the model never sees an orphaned tool result.
- **Fail visibly.** Every terminal state must produce either output or a readable error.
- **Prompt-level citation guidance, not enforced structure.** Pydantic-enforced citations were deferred because they needed an API contract change.

## Gaps and deferred work

- **The milestone closed with its audit reading `gaps_found`.** `v2.1-MILESTONE-AUDIT.md` scored 11/14 requirements as satisfied. The audit called the gaps "process/documentation, not functional": seven of eight phases had no verification report, two cited test files (`test_blank_response_guards.py`, `test_rag_correctness.py`) were not on disk, and no phase had a validation file.
- **Partial normalisation.** Only `document_type` and `language` are lowercased at ingest. Other metadata strings, such as author, are stored as-is but filtered lowercase.
- **Owed human check.** Phase 25's verification is `human_needed`: a live trace confirming the sub-agent really calls the cheap model was outstanding.
- **Sources disagree on requirement IDs.** The audit says CTX-06/07/08 "do not exist in REQUIREMENTS.md" and pairs CTX-06 with provider-aware budgets. The archived `v2.1-REQUIREMENTS.md` *does* list them, apparently added afterwards, with CTX-06 as sub-agent model selection and CTX-07 as provider budgets. The roadmap's Phase 25 criteria name "GPT-4o-mini/nano" for OpenAI, while the requirement and verification say "GPT-5.4-nano".
- **Deferred:** document-level deduplication of RAG results (picked up by Phase 32.5, which the v2.2 roadmap lists but which completed on 2026-04-18, after v2.2 shipped) and structured citation enforcement. Real-time settings reload was out of scope.
